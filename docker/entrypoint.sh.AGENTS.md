# entrypoint.sh — index

Runs `seed-auth.js`, seeds spawnStrategy into config.json first-run-only, starts tmux server, enrolls zrok v2 headless when `ZROK_TOKEN` set + not already enrolled (`zrok2 enable "$ZROK_TOKEN" --headless`, idempotent via `~/.zrok2/environment.json`), runs pi-dashboard with env→flag mapping (`DASHBOARD_PORT`→`--port`, `PI_GATEWAY_PORT`→`--pi-port`, `TUNNEL_ENABLED=0`→`--no-tunnel`), then SUPERVISES the detached daemon via `supervise-daemon.sh` instead of `exec`ing it: `pi-dashboard start` returns as soon as the server detaches, so PID 1 exited and the container cycled every ~30s under `restart: unless-stopped` (invisible in E2E, which runs `test-entrypoint.sh` and supervises itself). `PI_ENTRYPOINT_NO_SUPERVISE=1` restores the old exec-and-return for a wrapping caller. See change: docker-packaging, support-zrok-v2, add-pi-gateway-transport-identity.

Step 0 (`# >>> credential-data-key` block): exports `PI_DASHBOARD_DATA_KEY_FILE=/home/pi/.pi-key/data-key` when unset; only at THAT default path (a preset custom path is never overridden or generated, G9), only when the file is absent AND neither `~/.pi/agent/plugin-credentials.json` nor `~/.pi/dashboard/vault.json` starts with `pi-dashboard-encrypted:` (`head -c 23 | grep -q`), it generates 32 random bytes as base64 under `umask 077` by redirect from `/dev/urandom` (no key in argv/env/log). Envelope present + no key → prints `REFUSING to generate…` with the restore remedy and starts anyway (server reports `key_file_missing`). Warns when `/home/pi/.pi-key` is not a mountpoint or is an anonymous volume (`/proc/self/mountinfo`). `test-entrypoint.sh`/`peer-entrypoint.sh` reach this only through this script. Contract + executed-block test: `packages/shared/src/__tests__/docker-credential-key-contract.test.ts` (E84, E86). See change: encrypt-credentials-at-rest.
