# verify-lockfile-versions.mjs — index

Sanity gate after `pnpm install --lockfile-only` in `publish.yml` (`tag-and-push`) + `_electron-build.yml`. Line-parses `pnpm-lock.yaml`'s `importers:` map (fixed 2/4/6/8-space shape, no YAML lib), walks every `packages/<workspace>` importer's dep sections, asserts each WORKSPACE-MEMBER cross-ref specifier equals `^<root.version>`; tracks `checkedCount` to guard a vacuous pass. Prints `file → name: spec (expected ^X.Y.Z)` per mismatch + exits 1. Catches lockfile-version drift before commit lands on tag. See changes: fix-release-lockfile-drift, adopt-pnpm-for-dev-ci.

**Internal = workspace membership, NOT name scope.** Builds `workspaceNames` from `packages/*/package.json` `name` fields; exits 1 if that set is empty (wrong cwd). The org publishes packages outside this repo — `@blackbelt-technology/pi-anthropic-messages` is an ordinary external dep of `flows-anthropic-bridge-plugin` pinned `>=0.3.4`. The former `name.startsWith("@blackbelt-technology/")` prefix test flagged it as drift and failed EVERY `tag-and-push` + `_electron-build` run after the peerDep landed in #428 (post-v0.7.0); first observed via a manual `ci-electron.yml` dispatch, all 6 legs red. `scripts/sync-versions.js` always had it right (`if (!(depName in versionMap)) continue;`) — keep the two aligned. Locked by `packages/shared/src/__tests__/verify-lockfile-versions.test.ts` (4 fixture cases + a real-repo case, incl. a drift case proving the gate keeps its teeth).
