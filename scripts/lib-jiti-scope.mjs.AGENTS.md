# lib-jiti-scope.mjs — index

Discovery rule + AST detector behind the `jiti-cjs-transpile-safety` gate. Scope is a DERIVED RULE — "first-party source jiti evaluates at runtime" — so a new workspace is covered with no edit here; criterion is *evaluated by jiti*, NOT *executed from source* (raw-`.ts` `bin` entries carry `#!/usr/bin/env node`, run under native type-stripping as ESM, no CJS wrapper → out of scope). Three seeds, all manifest-derived: `pi.extensions` `.ts` entries; a workspace whose `main` is `.ts` (`packages/server` — `bin` is the `.mjs` wrapper, so a `bin`-keyed limb cannot find it, and its whole `src/**` is jiti-evaluated by the `--import <jiti-url>` re-exec); `pi-dashboard-plugin` `server`/`bridge` entries (loaded by dynamic `import()` over glob paths, so no static specifier exists to walk). Transitive walk follows ESM `import` AND CJS `require()`, stops at `node_modules`. Detection is AST-level (`acorn` → `MetaProperty`), never textual. Exports `discoverSeeds`, `discoverJitiLoadedFiles`, `isExcludedPath`, `specifiersOf`, `workspaceIndex`, `transformToCjs`, `hasCodePositionImportMeta`, `checkFile`, `repoRoot`. See change: fix-jiti-cjs-transpile-safety.

`discoverSeeds` adds `tagged` [{kind: piExtension|serverMain|pluginServer|pluginBridge, entry}] — pure relabel of the three lists. Plugin manifest via exported `pluginManifestOf` (adjacent `dashboard-plugin.json` wins, runtime precedence). Exports `resolveFirstParty`, `filesUnder` for `check-loader-neutral-source.mjs`. Seed-2 rationale: server src stays in jiti scope because the `PI_DASHBOARD_TS_LOADER=jiti` fallback can evaluate it. See change: fix-appimage-cold-boot-latency.
