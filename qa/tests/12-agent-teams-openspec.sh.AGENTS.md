# 12-agent-teams-openspec.sh — index

L2 process-level smoke for the OpenSpec team profiles (add-agent-teams-openspec, test-plan V1/V2/V3). Run green (all three sections) in the docker harness container against a second hermetic server (`QA_BIN_DIR=/usr/local/bin QA_REPO_ROOT=/app TMPDIR=<exec dir>`; container /tmp is noexec so the `post-checkout` hook needs another TMPDIR). Hermetic: own prefix (HOME), own port (default 18980), faux provider staged + made default model (`settings.json` provider/model split, `config.json` defaultModel). Sections via `QA_OPENSPEC_SECTIONS` (default `v1 v2 v3`). SKIPs (exit 0) without `pi`/`git`/faux fixtures. Number 12 is shared with the `12-*.ps1` scripts (duplicates already exist, e.g. 09, 10, 15).

- `v1` (#V1): `GET …/templates?cwd=` of a trusted repo ⇒ `openspec-group` + `openspec-apply`, source `bundled`, no `judo-modules`; start in a repo recorded untrusted in `trust.json` ⇒ `project_untrusted` for both; no team, no `.worktrees/`.
- `v2` (#V2): (A) group start ⇒ launcher worktree at `<repo>/.worktrees/os-<change>` on `os/<change>` via loopback inject; sidecar failures typed (`worktree_path_unexpected` for a symlink in the way, route/git token for a branch checked out elsewhere). (B) apply start ⇒ scripted implementer completes task 1 ⇒ only that checkbox ticked in `tasks.md`, byte-identical otherwise, `synced[task]=true`.
- `v3` (#V3): 3 changes, parallel 2, scripted ship (`agent-teams-openspec-ship-<taskId>`). `post-checkout` hook (`sleep 4`) holds the `launching` record; SIGKILL at first record; restart ⇒ `launch_failed launch_interrupted`, ONE lead notice across two restarts, no worktree with two sessions, relaunch route ⇒ ships, 3/3 completed, sidecar valid JSON.

Repos commit a hook-free `.pi/settings.json` (else the server auto-seeds an untrusted `worktreeInit` ⇒ `init_untrusted`). V3 kills via sidecar-file polling (a `pi-dashboard api` call takes ~1 s) and waits for the other teammates to register before the 2nd restart (a restart during an unresolved spawn fails it by design). Mechanics: REST via `pi-dashboard api` (mints local proof); node programs written to `$SCRATCH` (`os-lib.cjs` shared). Leads are faux pi RPC processes started in the repo (`/agent-team start <template> <goal>`); members are spawned by the server. Sidecar `<dataDir>/openspec/<teamId>.json` is found by walking `$HOME/.pi`. Needs scenarios `agent-teams-openspec-ship-N` / `-complete-N` from `qa/fixtures/faux-scenarios.ts`.
