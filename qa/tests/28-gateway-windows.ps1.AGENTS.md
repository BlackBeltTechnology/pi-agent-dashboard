# 28-gateway-windows.ps1 — index

Windows gateway transport + identity (tasks 5.1/5.5/5.7/12.53; verify-windows-credential-acls tasks 1.3). Four sections in falling order of certainty: `/api/health` advertises a NUMERIC loopback port with no `gateway-*.sock` artifact anywhere and a real listener on it; a bridge connects, is `terminate()`d like a sleeping laptop, and reconnects as exactly ONE session; the live `instanceId` is readable for identity checks; and a second STANDARD OS user (`New-LocalUser`, asserted NOT in Administrators) attempts to read all THREE credential files in the REAL profile — inheritance is the mechanism under test, so a temp HOME would measure the wrong ACL.

§4 target list = `local/token`, `identity.key`, `paired-devices.json`. Each file gets its OWN DACL inspection and its OWN read verdict; one file's ACL is not evidence for its neighbours'. Absent files are minted through the PRODUCT's own writers (`ensureLocalToken`, `ensureServerIdentity`, `PairedDeviceRegistry`), never `Set-Content` — `paired-devices.json` is net-zero (QA row added then revoked, operator devices untouched). One impersonated run covers all three, emitting JSON parsed back into a per-file verdict map, so a surprise on the first file cannot leave the other two unexamined. A broad-principal DACL is reported per file.

**A successful read is a PER-FILE finding.** `local/token` sits in a `local` subdirectory while the other two sit directly under `.pi\dashboard`, so they do not inherit from the same parent, and any file may carry explicit ACEs. Remediation scope = the leaked paths only; a shared credential-directory ACL fix needs per-file DACL evidence of a common cause first.

**Only an access-denied exception counts as `READ-DENIED`.** The probe catches `UnauthorizedAccessException` / `SecurityException` as `READ-DENIED`, and EVERYTHING else (`IOException`, sharing violation, locked or missing file) as `READ-ERROR`. A `READ-ERROR` is NOT a permission decision, so it counts as UNANSWERED and fails the arm — otherwise a locked file could manufacture a green. Answered means exactly `READ-DENIED`.

**A missing verdict is a hard FAIL** (`verify-windows-credential-acls` task 2.1) — no more NOTE-and-pass. `windows-latest` demonstrably yields a verdict (OBSERVED `READ-DENIED`/`UnauthorizedAccessException` for all three, owner `BUILTIN\Administrators`, run 34823022229), so a silent pass could only hide a broken harness. The failure text is worded as an EVIDENCE failure, never a leak, and names what to check (`seclogon`, `New-LocalUser`, probe-dir READ+WRITE).

§4 probe harness: probe script + verdict file live in `C:\ProgramData\qa-acl-$PID` with `(M)` for the second user, removed in `Cleanup`. NOT the session owner's `%TEMP%` — a standard user cannot traverse another user's profile at all, so the previous `%TEMP%` + `(RX)` arrangement made even a SUCCESSFUL impersonation produce no output. That bug is what the parent change misread as "a hosted runner gives a standard user no usable logon" and reported as `infeasible`; the blanket `icacls $env:TEMP /grant` loosening is gone.

Run by `.github/workflows/ci-gateway-platform.yml` (`windows` job, triggers on this file's path).
