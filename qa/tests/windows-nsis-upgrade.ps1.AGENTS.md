# windows-nsis-upgrade.ps1 — index

NSIS upgrade-from-previous-release test (slim-windows-install-file-count, X4). Params: `-Setup <new Setup.exe>`, `-PreviousSetup` (default: latest release x64 `Setup.exe` via `gh release download`, needs `GH_TOKEN`/`GH_REPO`; none published → SKIP exit 0; a failed `gh` lookup/download or no x64 asset → FAIL), `-RegisterTimeoutSec` (90). Flow: install previous (`windows-nsis-install.ps1`) → start/stop app → seed `...\resources\server\packages\extension` into `~/.pi/agent/settings.json` if the previous app cannot register headlessly → install new over it → assert `resources\server\packages\` holds no dir but `dist`, no stale `packages\extension`, node_modules extension `package.json` present → start new app once, poll `settings.json` for the node_modules path and no `packages\extension` entry (FAIL otherwise; `/api/health` informational). Wired as the last step of the win32-x64 leg in `_electron-build.yml`.
