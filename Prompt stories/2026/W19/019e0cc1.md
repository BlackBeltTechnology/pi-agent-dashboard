## 1. Goal (the ask)

The operator pasted a raw block of CI TypeScript errors and nothing else:

> `Error: packages/client/src/__tests__/use-message-handler-pending-prompt.test.ts(39,9): error TS2741: Property 'setOpenspecGroupsMap' is missing… / FolderOpenSpecSection.tsx(354,28): error TS2345… / SettingsPanel.tsx(548,34): error TS2339: Property 'modelProxy' does not exist on type 'Config'…`

The real objective: **make the failing CI `tsc`/lint pass by fixing every reported error, without over-reaching into unrelated changes, then commit only the relevant files.** The single follow-up prompt ("Commit changes") confirmed the scope ended at a clean, targeted commit.

## 2. TL;DR playbook

1. Paste the full CI error block as prompt 1 — no extra instructions needed.
2. Ask the AI to **triage errors into buckets by root cause** before touching code (10 errors collapsed into 5 buckets here).
3. For each bucket, have it trace provenance with `git log`/`git show` on the archived feature commit that introduced the surface (`git show <sha> --stat`) — the missing types were already defined in a sibling test file.
4. Apply mechanical fixes bucket-by-bucket with `edit`; keep each edit surgical.
5. Verify per-package: `npx tsc --noEmit -p packages/<pkg>` then `npm run lint`.
6. Re-run the narrow test that exercises the changed code: `npx vitest run <path>` (add `HOME=$(mktemp -d)` if localStorage/HOME pollutes the run).
7. Explicitly note any *pre-existing* error not in the original report (here: `@honcho-ai/sdk` missing) so it isn't conflated with your fix.
8. `git add` **only** the touched files; leave unrelated proposals + `package-lock.json` unstaged; commit.

## 3. How the collaboration unfolded

**Phase 1 — Triage (read-only).** The AI ran `git status`/`git log`, then grouped the 10 errors into 5 buckets (A: missing OpenSpec-group request/response types in `rest-api.ts`; B: `Config.modelProxy` absent on the client-local interface; C: `streamer.ts` calling `streamCompletion` with the wrong arity; D: header-cast typing; E: a `.map` callback mismatch + a test mock missing a setter). *Why it worked:* bucketing turns a scary 10-error wall into 5 independent, mechanical fixes and prevents thrashing.

**Phase 2 — Provenance.** For Bucket A it traced the archived feature commit `61fe3516` and found the 8 request/response types were fully defined inside `openspec-groups-types.test.ts` but never added to `rest-api.ts`. *Decision point:* copy the shapes verbatim from the test rather than re-designing them.

**Phase 3 — Fix bucket-by-bucket.** 7 `edit`s across shared/client/server. Bucket C required reading the real `pi-ai` `.d.ts` under `~/.pi-dashboard/node_modules/@mariozechner/pi-ai` to confirm the `(model, context, options)` signature and `system` → `systemPrompt` rename, then updating the streamer tests to match.

**Phase 4 — Verify.** `tsc -p` per package, `npm run lint`, and `npx vitest run` on the streamer test. The AI flagged the one leftover lint error (`@honcho-ai/sdk`) as out-of-scope.

**Phase 5 — Commit.** On the "Commit changes" turn it staged exactly the 7 files (+57/-22), committed `effac0c6`, and deliberately left openspec proposals and `package-lock.json` unstaged.

## 4. Prompts that worked

- **Goal prompt — paste the raw error block.** Effective because the compiler output already contains file, line, error code, and message. No prose needed; the AI can triage directly. A future user should paste the *complete* `tsc`/CI output, not a summary.
- **High-leverage follow-up — "Commit changes."** Two words unlocked a scoped commit because the AI had already tracked which files it touched vs. what was pre-existing. Works only when the earlier turn kept changes surgical.

Stronger kickoff to reuse: *"Here's the CI tsc output. Triage into root-cause buckets first, fix each with minimal edits, verify with `tsc -p` + the narrow vitest, and flag anything not in this report."*

## 7. Pitfalls & dead ends

- **vitest picking up polluted HOME/localStorage.** The streamer test was re-run with `HOME=$(mktemp -d) NODE_OPTIONS="--localstorage-file=$(mktemp)"` to isolate it — do this if a test behaves differently under your real HOME.
- **Chasing the `pi-ai` signature in the wrong tree.** The real `.d.ts` lives under `~/.pi-dashboard/node_modules/@mariozechner/pi-ai`, not the project `node_modules` — search both when confirming an external API's shape.
- **The `@honcho-ai/sdk` lint error is a red herring** for this task — a separate uninstalled dep, not caused by the fix. Don't try to "fix" it inside this commit.
