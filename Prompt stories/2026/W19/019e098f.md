# How we did it: Untangle a messy working tree into clean per-proposal commits — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The first prompt was: *"Which proposals have uncommitted changes? You can use pi-dashboard sessions to try to figure it [out]"*. On the surface a read-only question — but the steering turns made the real objective clear: the working tree had accumulated a **big, tangled pile of uncommitted work** (multiple OpenSpec archives, new proposals, a v0.5 plugin, ~36 stray TypeScript build artifacts, and a few orphan files), and the operator wanted to **triage it and land it as clean, intention-scoped commits — one logical group at a time** — without accidentally committing build noise or per-user runtime state. The session is a git-hygiene / release-prep exercise, not a feature build.

## 2. TL;DR playbook

1. **Get the raw truth first.** `git status --porcelain | wc -l` then bucket it: `awk '{print substr($0,1,2)}' | sort | uniq -c` to see how many staged/modified/renamed/untracked entries you're dealing with.
2. **Classify by OpenSpec intent, not by directory.** Split entries into *active proposals* (`openspec/changes/<name>/`), *archive moves* (`openspec/changes/archive/…` renames), *main-spec syncs* (`openspec/specs/`), *proposal-only* (docs, no code), and *orphans* (build artifacts, per-user state).
3. **Ask the AI to draft a per-group commit plan** ("Group A/B/C…") so the human can approve granular, ordered commits.
4. **Interrogate suspicious bulk changes before committing.** For any large lump of `.js`/`.d.ts`/`.js.map`, prove they're build output (no matching `.tsx` source change; HEAD doesn't have them; package exports point at `.tsx` via jiti) → **unstage + gitignore**, don't commit.
5. **Commit group-by-group on the human's go-ahead** ("commit E1 and E2", "commit A and B"): archive moves as `openspec(archive): …`, build-artifact cleanups as `chore(plugins): gitignore …`.
6. **Handle orphans deliberately.** Per-user runtime JSON → `git rm --cached` + `.gitignore`. A missed config edit → its own small commit. A standalone style tweak → its own `ui(...)` commit.
7. **Re-run `git status --porcelain` after every group** and report the shrinking remainder until only intentional, still-open proposals are left.

## 3. How the collaboration unfolded

**Phase 1 — Discovery (what's dirty?).** The AI first tried to reach the dashboard's `/api/sessions` endpoint to map sessions→proposals, but every HTTP attempt failed (`curl`, `wget`, `node fetch`). It pivoted to pure git: `git status --porcelain` filtered by `openspec/changes/`. *Why it worked:* git is the ground truth; the API detour was unnecessary. The human's *"recheck"* forced a second pass that corrected the first read (a proposal had been committed in between).

**Phase 2 — Classification.** On *"check the other — not proposal-only changes"* and *"check group E"*, the AI produced a labelled **Group A–E** breakdown separating archive renames, spec syncs, new proposals, and the plugin. *Why it worked:* naming the groups gave the human addressable units to approve one at a time.

**Phase 3 — Forensics on the build-artifact lump (the key decision point).** Group E was ~36 `.js`/`.d.ts`/`.js.map` files under `packages/jj-plugin` + `packages/flows-anthropic-bridge-plugin`. The AI *didn't* commit them — it proved they were noise: no sibling `.tsx` change, HEAD lacks them, manifests publish `src/` and point exports at `.tsx` (jiti runtime), and a dangling commit `9d8e015a` showed a prior failed attempt to lump them in. Verdict: **unstage + gitignore**.

**Phase 4 — Ordered commits.** On short go-aheads (*"commit E1 and E2"*, *"commit A and B"*), the AI landed each group with an intention-scoped message and reported the shrinking remainder.

**Phase 5 — Orphan sweep (next day).** After a ~13h gap the human re-asked *"what is the status?"* then *"commit orphans"*. The AI landed three: `git rm --cached` + gitignore for a per-user `openspec/groups/groups.json` (it even contained a junk test group "sdasdasd"), a missed `vitest.config.ts` workspace registration, and a standalone `AgentCardShell` style blend — each as its own commit.

## 4. Prompts that worked

- **The goal prompt** — *"Which proposals have uncommitted changes?"* Good because it scoped the question to a unit the AI could enumerate deterministically. Stronger version: *"Bucket every uncommitted entry by OpenSpec intent (active proposal / archive move / spec sync / proposal-only / orphan) and propose a per-group commit plan; don't commit yet."*
- **High-leverage follow-ups:**
  - *"recheck"* / *"what is the status?"* — cheap re-syncs that caught state drift between passes. Repeat these liberally; the tree changes under you.
  - *"check group E, because there maybe committed other fixes a little bit different intention"* — explicitly told the AI to look for *hidden different intent* inside a lump, triggering the forensic pass instead of a blind commit.
  - *"commit E1 and E2"*, *"commit A and B"*, *"commit orphans"* — one-line approvals over pre-labelled groups. The upfront grouping is what made these terse commands unambiguous.

The workflow is clearly repeatable, so **a `triage-dirty-tree` project skill should be created**, capturing: (1) porcelain bucketing by OpenSpec intent, (2) the build-artifact proof recipe (no sibling `.tsx`; HEAD lacks it; exports point at `.tsx` via jiti → unstage + gitignore), (3) the group-then-approve commit loop with `openspec(archive):` / `chore(plugins):` / `ui(...)` message conventions, and (4) the orphan rules (`git rm --cached` per-user JSON; split missed config + style tweaks into their own commits). That removes the per-session re-derivation of "is this lump safe to commit?" — the single most time-consuming judgment here.

## 7. Pitfalls & dead ends

- **The `/api/sessions` endpoint was unreachable** (`curl`/`wget`/`node fetch` all failed). Don't burn turns on it for git questions — go straight to `git status`.
- **Stale reads:** the tree changed between the first and second check (a proposal got committed elsewhere). If you cache a status summary, it's already wrong — `recheck` before acting.
- **Build-artifact trap:** `tsc` + `git add .` re-stages ~36 `.js/.d.ts/.js.map` files that look like real changes. A prior dangling commit (`9d8e015a`, plus ~5 abandoned siblings) shows this exact mistake was made before. Verify, unstage, gitignore.
- **Fake orphan:** `vitest.config.ts` looked orphaned (registered `packages/honcho-plugin` which appeared absent), but the plugin was **already on develop** (`2d42e006`) — the line was just a missed config edit, not dead code. Confirm against `develop`/HEAD before deleting a "reference to nothing".
- **Junk in per-user state:** `openspec/groups/groups.json` held a typo group "sdasdasd" — another reason it's per-user runtime data to gitignore, not commit.

## 8. Reproduce it faster — checklist

- [ ] `git status --porcelain | wc -l` and `… | awk '{print substr($0,1,2)}' | sort | uniq -c` to size the mess.
- [ ] Bucket entries: active proposals / archive moves / spec syncs / proposal-only / orphans (scan the *whole* tree, not just `openspec/`).
- [ ] For each `.js/.d.ts/.js.map` lump: confirm no sibling `.tsx` change + HEAD lacks it + exports point at `.tsx` → `git restore --staged …` + append to package `.gitignore`.
- [ ] Draft a Group A/B/C… commit plan; get one-line human approval per group.
- [ ] Commit group-by-group with intention-scoped messages (`openspec(archive):`, `chore(plugins):`, `test(...)`, `ui(...)`).
- [ ] Orphans: `git rm --cached` + gitignore per-user JSON; split missed config edits and style tweaks into their own commits.
- [ ] `git status --porcelain` after every group; stop when only still-open proposals remain.
