# How we did it: Fix macOS first-run unblocking docs — an AI collaboration guideline

## 1. Goal (the ask)

The session opened as a support question, not a task:

> `xattr: /Applications/PI-Dashboard.app: No such xattr: com.apple.quarantine?`

The user pasted a confusing terminal message from following the app's own
first-run instructions. The AI correctly diagnosed it as *harmless* (nothing to
remove, not an error). But the real objective surfaced one prompt later: **the
install docs were giving users a command that produces a scary-looking message,
so fix the docs everywhere** — README, the release changelog, and the Astro
marketing site — to use an idempotent command and pre-empt the confusion.

## 2. TL;DR playbook

1. **Answer the literal question first.** Explain that `No such xattr:
   com.apple.quarantine` means the quarantine flag was already absent — safe to
   ignore.
2. **Recommend the better command:** `sudo xattr -cr /Applications/PI-Dashboard.app`
   (idempotent + recursive) over `xattr -d com.apple.quarantine …`.
3. **Grep for every copy of the stale instruction** across README, CHANGELOG,
   `docs/`, and `site/src/` — install text is duplicated in multiple surfaces.
4. **Fix the app-name typo too:** `PI Dashboard.app` → `PI-Dashboard.app` (verify
   against `forge.config.ts` `productName`).
5. **Edit all three surfaces** with matching wording: README first-run section,
   `InstallTabs.tsx`, and a `CHANGELOG.md` Unreleased → Changed entry.
6. **Verify with a final grep** that no `xattr -d`/`quarantine` remnants survive.
7. **Commit and push** with a `docs:` message that names both fixes and the
   rationale.

## 7. Pitfalls & dead ends

- **`xattr -d com.apple.quarantine` is a bad instruction to ship** — it errors
  (`No such xattr`) whenever the flag is already absent, confusing users. Ship
  `sudo xattr -cr <app>` instead: idempotent (never errors on a missing attr) and
  recursive (clears every file in the bundle).
- **A special glyph broke naive edits.** The README line held the Apple `` menu
  character and was truncated in normal reads; three `edit` attempts failed until
  the exact bytes were recovered with `sed -n '63p' | od -c` and a `python3` read.
  If an edit won't match, dump the raw bytes with `od -c` first.
- **App-name typo:** `PI Dashboard.app` (space) vs `PI-Dashboard.app` (hyphen) —
  verify against `forge.config.ts` `productName` before writing paths.
