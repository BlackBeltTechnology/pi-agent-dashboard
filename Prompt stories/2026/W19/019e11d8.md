# How we did it: Light-mode pill contrast across core + plugin badges — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The user opened with a screenshot and a plain complaint:

> "Some visual fix needed, because in light mode there is hard to read stuffz
> presented: For example Workspace labels, openspec status."

The real objective, once the steering turns landed: **make every session-card pill
legible in light mode** — not just the core `SessionSubcard` section labels
(`OPENSPEC`/`WORKSPACE`/`FLOWS`) and the OpenSpec `StatePill`, but also the
third-party **jj** and **honcho** plugin badges, which render their own washed-out
palettes. Plus one feature ask folded in: give the `jj:<workspace>` pill an icon.
End state: darker theme-aware text on light, dark mode untouched, tests green,
docs updated, committed.

## 2. TL;DR playbook

1. **Reproduce the contrast bug from the screenshot** — identify which CSS token each
   unreadable pill uses (`--text-muted` ≈ `#aaa` on `#f0f0f0` light bg = fails).
2. **Fix the core pills first**: swap section labels to `--text-tertiary` + `font-semibold`;
   add `[data-theme="light"] [data-testid="state-pill"]` per-state overrides in `index.css`
   (700-shade text + stronger tint) for the OpenSpec status pill.
3. **State scope up front for plugins**: the `running` / `jj:default` pills live in
   `packages/jj-plugin` and `packages/honcho-plugin` — flag them as separate targets.
4. **Add a shared theme hook** each plugin uses: a `MutationObserver` on
   `<html data-theme>` (`useIsLightTheme`) driving a `STATE_STYLE_DARK` / `STATE_STYLE_LIGHT`
   split. Put the hook **before any early return** (rules-of-hooks).
5. **Add the jj icon** with `mdiSourceFork` from `@mdi/js`.
6. **Run plugin + client tests** with `HOME=$(mktemp -d) npx vitest run <pkg>` (isolated HOME).
7. **Rebuild + restart**: `npm run build` then `pi-dashboard restart` (or POST `/api/restart`),
   then **hard-refresh** (⌘⇧R) to bust the cached `index-*.js`.
8. **If a plugin edit "doesn't take"**: delete stale precompiled `*.js / *.d.ts / *.js.map`
   under the plugin `src/` — Vite resolves those over your `.tsx` (see Pitfalls).
9. **Doc + proposal gate**: visual-only fixes need **no OpenSpec proposal**; update the
   file-index rows via a subagent, then commit.

## 3. How the collaboration unfolded

**Phase A — Locate the offending tokens (Discovery).**
The AI `rg`-searched `packages/client/src` for the label strings and CSS custom props,
traced the section pills to `--text-muted` and the `StatePill` states, and named the
exact contrast failure (`#aaa` on `#f0f0f0`). *Why it worked:* it grounded the fix in
concrete token values from the screenshot instead of guessing colors.

**Phase B — Fix core, then verify (Design → Verify).**
Edited `SessionSubcard.tsx` (→ `--text-tertiary` + `font-semibold`) and added
light-theme `state-pill` overrides to `index.css`, ran the `SessionSubcard` test,
built. It explicitly called the jj/honcho pills **out of scope** and asked whether
to extend — the human immediately said yes.

**Phase C — Extend into the plugins (Scope expansion).**
Steering turn "Fix jj and honcho too. Add icon for jj workspace pill" unlocked the
bulk of the work. The AI introduced a shared `useIsLightTheme` MutationObserver hook,
split each plugin's `STATE_STYLE` into dark/light palettes, added `mdiSourceFork` to
the jj badge, and moved the hook above the early return to satisfy rules-of-hooks.
128/128 plugin tests passed.

**Phase D — The "I still don't see it" loop (Debug).**
The user reported the icon and jj color still weren't showing. The AI chased the
restart/serve path, then found the real cause: stale gitignored `*.js` build artifacts
in `jj-plugin/src/` that Vite resolved instead of the edited `.tsx`. Deleting them and
rebuilding put the icon + palette into the bundle (verified by grepping the built
`index-*.js`).

**Phase E — Governance close-out (Document → Commit).**
"update proposal if required" → the AI correctly judged **no proposal needed** (visual
fix, no contracts/behavior/specs) and delegated file-index row updates to a
`general-purpose` subagent in caveman style, annotated `See change: light-mode-pill-contrast`.
"commit changes" → committed `aff51952` on `develop`, 6 files, +102/-13, leaving the
user's other unstaged work untouched.

## 6. Skills, tools & memory created — and why they're effective

No skill or memory was persisted this session, but two reusable patterns emerged and
**should** be captured:

- **`useIsLightTheme` MutationObserver hook** (dark/light `STATE_STYLE` split) — the
  reusable answer to "a plugin badge must react to the dashboard theme." It removes the
  need for each plugin to re-implement theme detection and makes light-mode palettes
  reproducible. Invoke it whenever a new plugin badge is added. *Rules-of-hooks caveat:
  place it before any early return.*
- **Stale-plugin-artifact cleanup** — the fix "delete `*.js / *.d.ts / *.js.map` under a
  plugin `src/`, then rebuild" is worth a project memory; it explains a whole class of
  "my edit didn't take effect" confusion. (A `switch-extension-source` / build-artifact
  skill would be the natural home.)

The `general-purpose` subagent was used well: file-index row updates delegated in caveman
style with a `See change:` annotation, keeping the doc protocol out of the main context.

## 7. Pitfalls & dead ends

- **Vite resolves stale precompiled `.js` over your `.tsx`.** `jj-plugin/src/client/index.tsx`
  imports siblings as `./X.js` (gitignored build artifacts). If they exist on disk, edits to
  the `.tsx` never reach the bundle. **Fix:** `rm` all `*.js *.d.ts *.js.map` under the plugin
  `src/`, rebuild, and grep `packages/client/dist/assets/index-*.js` to confirm. (honcho-plugin
  had no precompiled `.js`, so it "just worked" — the asymmetry is the tell.)
- **`/api/restart` via curl failed repeatedly** (blocked by a hook / connection). Fallbacks:
  `pi-dashboard restart`, or a small `node /tmp/restart.mjs` `fetch` shim. Don't loop on curl.
- **vitest needs an isolated HOME** here — run `HOME=$(mktemp -d) npx vitest run <pkg>` to avoid
  the user-home interference that made the first plain `npx vitest` run flaky.
- **"Restarted, status 200" is not "the user sees it."** The prod build is static; a browser
  hard-refresh is mandatory to bust the cached `index-*.js`.
- **Don't over-govern:** a visual contrast fix does **not** warrant an OpenSpec proposal —
  just update the file-index rows.
