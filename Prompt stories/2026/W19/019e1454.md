# How we did it: Hide the empty FLOWS subcard in SessionCard — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The kickoff prompt was terse and precise:

> "In session card when a card is empty do not render it. (Like workspace)"

The *real* objective, once the AI located the code: the `FLOWS` subcard inside
`SessionCard.tsx` was rendering an empty titled box even when there were no flows.
The user pointed at the existing **workspace** subcard as the reference pattern —
"do it the way workspace already does it." So this was not an invention task; it was
a *match-the-established-pattern* task. The later two prompts were pure commit
hygiene: land only the relevant change, then triage and commit the unrelated staged
work that was already sitting in the tree.

## 2. TL;DR playbook

1. **Point at the reference pattern in the ask.** "Like workspace" told the AI where
   the correct implementation already lives — no design decision needed.
2. Let the AI **locate the empty-render bug**: `SessionSubcard` checks children at the
   React-node level, but `<SessionFlowActions />` is *always* a non-null element even
   when it internally `return null`s → empty titled box.
3. **Fix at the call site, not inside the child.** Gate the subcard on
   `(flows.length > 0 || hasFlowsNew)` — mirroring how `WorkspaceSubcard` computes its
   gate before rendering.
4. **Verify with `npm run build`** (typecheck + bundle). Note: vitest may die on an
   unrelated `os.userInfo()` ENOENT env error — don't chase it.
5. **Update the docs row** (`docs/file-index-client.md`) per the Documentation Update
   Protocol before committing.
6. **Commit ONLY your change** when the tree has unrelated staged work: `git stash push
   --staged`, `git add` your two files, commit, restore the stash.
7. For leftover uncommitted work: **categorize into coherent groups**, one commit per
   group with an explanatory message.

## 3. How the collaboration unfolded

**Phase 1 — Locate (bash greps + reads).** The AI grepped for `SessionCard`,
`SessionFlowActions`, `SessionSubcard`, and `WorkspaceSubcard` to find both the buggy
call site and the reference pattern. The first grep failed (wrong `src/client/...`
path — the repo uses `packages/client/src/...`), and it self-corrected with a `find`.

**Phase 2 — Diagnose.** It articulated the root cause precisely: the null-check happens
one level too late (on the rendered element, not on the data). Workspace avoids this by
computing the emptiness gate at the call site. The decision point — *fix the child vs.
gate the call site* — was resolved by the "like workspace" instruction: match the
existing pattern.

**Phase 3 — Implement + verify.** One `edit` to `SessionCard.tsx` gating the FLOWS
subcard. `npm run build` passed; vitest hit an unrelated environment error, correctly
flagged as out-of-scope. Docs row updated via a `general-purpose` subagent.

**Phase 4 — Commit hygiene (steering #1 & #2).** The working tree had a large
pre-existing staged changeset. The AI stashed the unrelated staged work, committed
*only* SessionCard.tsx + the docs row (`1b3d7b72`), then restored the stash untouched.
On the next prompt it triaged the remaining uncommitted work into three coherent
groups (Phase-3 pi-flows split-out, electron-auto-update proposal, Explore agent) and
made one commit per group.

## 4. Prompts that worked

- **The goal prompt** — "In session card when a card is empty do not render it. (Like
  workspace)". Effective because it names *both* the symptom (empty card renders) and
  the reference implementation (workspace). Naming an existing correct pattern removes
  all design ambiguity.
- **"commit changes"** — trusted the AI to scope the commit; it correctly isolated only
  the files it had touched rather than sweeping the dirty tree.
- **"There are uncommitted changes. Categorize and binmd to proposal. Commit them"** —
  a high-leverage cleanup prompt: "categorize" unlocked a triage-into-coherent-groups
  behavior and one-commit-per-concern discipline.

Stronger rewrite of the goal for a future user: *"The FLOWS subcard in SessionCard
renders an empty titled box when there are no flows. Gate it at the call site the same
way WorkspaceSubcard does, then build and update the docs row."*

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Guess the source path (`src/client/...`) | Implicitly — AI self-corrected via `find` | State the monorepo layout: code lives under `packages/client/src/` |
| Commit everything in a dirty tree | "commit changes" (AI scoped it to its own files) | State up front: "commit ONLY the files you changed; stash unrelated staged work" |
| Leave unrelated staged work loose | "Categorize … Commit them" | Ask for grouped, one-commit-per-concern triage explicitly |

The user imposed one implicit quality bar throughout: **surgical scope** — touch only
the FLOWS gate, don't refactor adjacent code, and keep commits coherent.

## 7. Pitfalls & dead ends

- **Wrong source path** — `src/client/components/...` does not exist; the client code is
  at `packages/client/src/components/...`. If a grep returns nothing, `find` the file.
- **Vitest env crash** — `os.userInfo()` ENOENT fires before tests run in some
  environments. It is unrelated to the change; verify with `npm run build` instead of
  chasing it. (A `HOME=$(mktemp -d) NODE_OPTIONS=--localstorage-file=...` workaround was
  attempted but the build is the reliable gate.)
- **Dirty working tree** — never `git add -A` when unrelated staged work is present.
  Use `git stash push --staged`, commit your files, then restore.
