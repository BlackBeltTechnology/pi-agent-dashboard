# How we did it: Status-tinted rail on the session-card gutter — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

## 1. Goal (the ask)

The user opened in **explore mode** (`openspec-explore`) with a stance prompt: *"Enter explore mode. Think deeply. Visualize freely."* The real objective, which surfaced over the next few turns, was concrete: the session card's **left drag-handle gutter** (`SessionCard.tsx:455`, ~14px wide, holding only the source icon) reads as dead space. Make it carry **visual weight AND encode session status** — without breaking its role as the drag target. The end product: a status-tinted vertical rail plus an icon chip, shipped through the full OpenSpec loop (proposal → apply → visual verify → archive → commit).

## 2. TL;DR playbook

1. **Explore first, don't code.** Kick off with `openspec-explore`; enumerate 3 design flavors (color-blocked rail / segmented dots / diagonal shards) with ASCII sketches before touching a file.
2. **Generate visual options with nano-banana** (`npx @the-focus-ai/nano-banana`) so the human picks a direction from real mockups, not prose.
3. **Write the OpenSpec change**: `openspec new change add-session-card-status-mosaic-rail` → proposal.md + tasks.md + `specs/session-card-status/spec.md`. `openspec validate` clean.
4. **Apply with `openspec-apply-change`**: add a `deriveRailBgColor(session, flags, isSelected)` helper in `session-status-visuals.ts`, wire the gutter in `SessionCard.tsx`, write unit + component tests.
5. **Use Tailwind literals, not interpolated class strings** — JIT can't see `bg-${x}-500`. Hard-code every status × selected combo.
6. **Verify in the real browser** (`browser` skill / direct navigation to `:8000`) after **rebuilding** — the local server serves the prod build, so HMR won't reflect changes until `npm run build`.
7. **Iterate on the human's image references** — expect 4–5 visual redirects (mosaic → solid → slim line → capsule + chip → add gap). Update helper + tests + spec each round.
8. **Sync specs + archive**: `openspec-sync-specs` then `openspec-archive-change`. Then commit only the rail files, splitting out unrelated working-copy noise.

## 3. How the collaboration unfolded

**Phase 1 — Explore & diverge (01:06–01:16).** The AI stayed in explore mode, mapped the current gutter, and offered flavors A/B/C with ASCII diagrams. The human answered a 4-question batch tersely (*"1. no fragmented / 2. keep current / 3. static / 4. always"*) then said **"Show me with nano banana."** That decision point — *stop describing, start rendering* — was the highest-leverage move of the session. Three mockups let the human pick "Mosaic" with a precise refinement: a **transparent grayscale asset tinted by status color**.

**Phase 2 — Spec the change (01:20–01:24).** With the direction locked, the AI wrote the OpenSpec proposal/tasks/spec-delta targeting the existing `session-card-status` capability, validated clean, and — correctly — refused to implement while still in explore mode until the human ran `openspec-apply-change`.

**Phase 3 — Implement (01:24–01:34).** `deriveRailBgColor` helper + gutter wiring + unit/component tests. Full suite green (**521 files / 5313 tests**). Build succeeded; no server was running to restart. The AI flagged visual verification as the human's job.

**Phase 4 — The visual-feedback loop (01:36–02:05).** This dominated the session. Five image-driven redirects, each round = restructure component + update tests + update spec + rebuild + re-inspect in browser:
- mosaic → **solid + more transparent**
- full-width tint → **slim 2px line, icon clear of it**
- → **match reference: circular icon chip + capsule bar**
- → **more space between chip and rail** (`top-7`)

**Phase 5 — Land it (02:21–02:38).** Sync spec delta into main spec, archive the change. Then a jj/git detour: commit only the rail files, invoke a `jj-workspace-fold-back` skill (which the AI correctly judged *did not fit*), pull the commit back to the working copy as unstaged, and finally `git commit` two clean commits. The human then asked *"Who own uncommitted changes?"* → the AI ran `git log`/blame provenance on the two leftover files.

## 4. Prompts that worked

- **Goal / explore kickoff** — entering `openspec-explore` kept the AI from coding prematurely and forced a design-options phase. Good pattern for any UI change with an unclear target.
- **"Show me with nano banana"** — the single most effective follow-up. Converts an abstract "more stunning + fragmented" ask into pickable renders. Reach for image generation *before* writing CSS.
- **"Mosaic. But it's a transparent grayscale image… the tint represents the status"** — a precise, implementation-shaped instruction. It named the asset (grayscale mask), the mechanism (tint), and the semantics (status) in one line.
- **Terse numbered replies** to a batched question (*"1. no fragmented 2. keep current…"*) — efficient when the AI asks a well-structured multiple-choice batch.
- **Image + one-line correction** ("Keep colors, just made the left side like in the image") — pairing a reference screenshot with a scoped instruction removed all guesswork.

Weak-prompt rewrite: instead of *"More stunning + more fragmented"* (ambiguous), open with *"Show me 3 rendered options for the gutter, then I'll pick"* — skips a round of prose.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Over-engineer the first design (mosaic SVG mask) | "No mosaic, be solid and be more transparent" | Start with the simplest tint (solid + low alpha); only add texture if asked |
| Render the tint full-gutter-width behind the icon | "The status icon have no clear background, because the line presented under" | Separate the status rail from the icon's own backdrop from the start |
| Verify against a stale prod build | "Use browser for inspect" (repeatedly) | **Rebuild before every browser check** — local server serves `dist`, not HMR |
| Interpolate Tailwind class strings | (caught internally) JIT can't detect them | Always write full literal class names per branch |

Quality bars the human imposed: the rail must read as a *tint not a block*, the icon must stay legible, spacing must match a reference image to the pixel, and commits must be clean (rail files only, unrelated working-copy files left untouched).

## 6. Skills, tools & memory created — and why they're effective

**`.pi/skills/jj-uncommit-to-working-copy/SKILL.md`** (created this session). Captures the exact inverse of `jj-workspace-fold-back`: take a described jj commit and fold its diff **back into the working copy as unstaged git changes**.
- **What it removes:** the fiddly `jj squash --from <target> --into @` + `jj describe -m ''` dance, plus the safety rails (refuse if not jj-colocated / conflicts exist / git index dirty; capture `PRE_OP` for `jj op restore` recovery; never run `git commit`/`git reset`/`git stash`).
- **Why effective:** symmetric with the existing fold-back skill (fold-back ships work *outward* to origin; this pulls work *inward* to `@`). Default target `@-` = "undo my last commit".
- **When to invoke:** "uncommit", "put changes back as unstaged", "undo last jj commit", "move commit into working copy".

**nano-banana** (`npx @the-focus-ai/nano-banana`) — the design-divergence engine. Turned a vague aesthetic ask into three concrete renders the human could choose from. Reuse whenever the target look is undecided.

**Recommended memory to save:** *"pi-dashboard local server serves the prod build from `dist`; rebuild (`npm run build`) before any browser visual check — HMR is only active in `--dev` mode."* This tripped the loop twice.

## 7. Pitfalls & dead ends

- **ImageMagick alpha-mask fumbling** — ~8 failed `magick` invocations trying to turn a grayscale strip into an alpha mask. If you go the mask route, expect trial-and-error; the whole approach was later dropped for solid+alpha anyway. Prefer solid tint first.
- **`curl` to `/api/restart` failed repeatedly** — the AI fell back to a Node `fetch` script (`/tmp/restart-and-check.mjs`). If curl restart hangs, script it in Node.
- **HMR didn't reflect changes** — the running server wasn't in `--dev`; it served the prod build. Every "why don't I see it?" was a missing `npm run build`.
- **Tailwind interpolated classes silently produce no style** — JIT purges them. Use literals.
- **`jj-workspace-fold-back` mis-fit** — its preconditions require a `.shadow/<name>/` agent workspace and a trunk bookmark; default workspace + conflicted `develop` bookmark = don't run it. Read skill preconditions first.
- **The change name outlived the design** — `add-session-card-status-mosaic-rail` shipped a *capsule rail*, not a mosaic. Renaming a change dir breaks history; the AI left it and noted the mismatch.
