# How we did it: Recovering an orphaned settings toggle — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The user opened with a pure discoverability question:

> *"Where can I set Keep tool groups collapsed in global settings page?"*

On its face this looks like "point me to the toggle." But the steering turns
revealed the **real** objective: the toggle *isn't findable because it isn't
there*. The global "Chat display" settings block — including **"Keep tool groups
collapsed by default"** (`toolGroupDefaultCollapsed`) — lived in a `DisplayPrefsSection`
component that was **defined but never mounted** in the JSX. So the true goal
became: *diagnose why the setting is unreachable, then wire the orphaned section
back into the Settings → General page, and ship it live.*

## 2. TL;DR playbook

1. **Locate the toggle by string, not by memory.** `rg -n "Keep tool groups collapsed|toolGroupDefaultCollapsed"` across `packages/client/src/components/`.
2. **Confirm the component that owns it** (`DisplayPrefsSection` in `SettingsPanel.tsx`) — then grep for its *render site*, not just its definition: `rg -n "<DisplayPrefsSection"`.
3. **When the render grep returns nothing → the component is orphaned.** That's the root cause, not a UX/discoverability issue.
4. **Find the fallback path** for the user in the meantime — the per-session **View** popover (`ChatViewMenu.tsx`) toggles the same key as a session override.
5. **Mount the orphaned section** in the tab its draft source already registers for (`page: "general"`), right after the existing Interface `</Section>`.
6. **Type-check the touched file only:** `npx tsc --noEmit -p packages/client/tsconfig.json 2>&1 | grep -i SettingsPanel` — ignore unrelated pre-existing `rootDir` fixture errors.
7. **Client change → build + restart:** `npm run build` then `curl -X POST http://localhost:8000/api/restart`, verify `/api/health` mode+uptime.

## 3. How the collaboration unfolded

**Phase 1 — Discovery (answer as asked).** The AI first answered the literal
question: Settings → General → "Chat display", key `toolGroupDefaultCollapsed`,
file/line pointer. Confident, specific, *and wrong about reachability.* Lesson:
a precise-sounding answer can still be wrong if it's read off source without
confirming the code path actually renders.

**Phase 2 — Steering forces a real investigation.** The user pushed back with a
screenshot: *"I haven't found [image]."* This is the pivotal turn. The AI stopped
asserting and started verifying — grepping for `<DisplayPrefsSection />` usage and
discovering it is **defined but never rendered**. It also found the Developer tab
has a *different, smaller* "Chat Display" section (only `<DebugToolsToggle />`),
which explains the confusion. Root cause: orphaned component.

**Phase 3 — Diagnosis + honest framing.** The AI reframed the whole thing:
*"You can't find it because it's not there."* It gave the user a working stopgap
(the per-session View popover) and proposed the surgical fix, but deferred the
edit pending confirmation of the intended page (General vs Developer).

**Phase 4 — Generate (the one-line fix).** On `edit`, the AI mounted
`<DisplayPrefsSection />` in the General tab immediately after the Interface
`</Section>` and before `<SettingsSectionSlot tab="general" />`. Because the
draft source was already registered for `page: "general"`, save/reset/dirty
tracking needed no further wiring.

**Phase 5 — Verify + ship.** Scoped type-check (ignoring a pre-existing
unrelated fixture `rootDir` error), then `npm run build` + `POST /api/restart`,
confirming production mode and a fresh ~30s uptime.

## 4. Prompts that worked

- **Goal prompt** (`"Where can I set Keep tool groups collapsed…"`) — good because it
  named the *exact UI string*, which made it greppable. A stronger version would
  add intent: *"…and if it's not on the settings page, tell me why and where it
  actually lives."* — that invites the reachability check up front.
- **High-leverage follow-up: a screenshot + "I haven't found."** Four words plus an
  image flipped the AI from asserting to verifying. When an answer doesn't match
  reality, *show* the AI the reality — it's faster than describing it.
- **"edit"** — a one-word go-ahead once the fix was proposed and scoped. Effective
  because the AI had already narrowed the change to a single safe line.
- **"rebuild and restart"** — trailing the project's exact build/restart doctrine,
  no explanation needed.

## 6. Skills, tools & memory created — and why they're effective

No skill or memory was created this session, but the workflow is textbook-repeatable
and worth capturing. **Recommended skill: "diagnose-orphaned-ui-component"** —
*when a UI element the user expects is missing, grep for its render site (not its
definition); if none, it's orphaned — mount it in the tab its draft source registers
for, then build + restart.* This removes the reflex of blaming discoverability and
turns a 5-minute detective loop into a two-command check.

The session did lean on existing project doctrine effectively: the **build/restart
matrix** (client change → `npm run build` + `POST /api/restart`) and scoped
`tsc --noEmit -p packages/client/tsconfig.json` verification.

## 7. Pitfalls & dead ends

- **Confident-but-wrong first answer.** The AI's initial "it's in Settings → General"
  was read off the source definition and was reachability-wrong. *If your pointer
  doesn't match the running UI, grep the render site before doubling down.*
- **Two "Chat Display" sections.** The Developer tab has its own smaller one
  (`<DebugToolsToggle />` only). Don't assume the first grep hit is the one the
  user means — enumerate all matches.
- **Failed restart command (1 of 8).** The inline `curl … | jq` one-liner failed;
  the retry wrote responses to `/tmp/*.json` first, then `cat`+`jq`'d them. *For
  restart+health checks, capture to a file before piping to jq.*
- **Pre-existing `rootDir` tsc error** in a test fixture — unrelated to the change.
  Filter type-check output to the touched file (`grep -i SettingsPanel`) so noise
  doesn't read as a regression.
- **Left a known redundancy** (two Chat-Display sections) flagged but unfixed —
  intentional scope discipline, surfaced to the user rather than silently merged.

## 8. Reproduce it faster — checklist

**Inputs to have ready:** the exact UI label string; a running dashboard on
`localhost:8000`; the client workspace (`packages/client/`).

1. `rg -n "<exact UI label>|<prefKey>" packages/client/src/components/`
2. Identify the owning component; `rg -n "<ComponentName" packages/client/` — **look for the `<ComponentName />` render site.**
3. No render site → orphaned. Mount it in the tab its draft source registers for, adjacent to the existing sibling section.
4. `npx tsc --noEmit -p packages/client/tsconfig.json 2>&1 | grep -i <ComponentFile>` (ignore unrelated fixture errors).
5. `npm run build` → `curl -s -o /tmp/restart.json -X POST http://localhost:8000/api/restart; cat /tmp/restart.json`
6. `sleep 4; curl -s http://localhost:8000/api/health | jq '{mode, uptime}'` — expect `production` + low uptime.
