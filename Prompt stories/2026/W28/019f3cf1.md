# How we did it: Condense the collapsed folder header — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore` skill) — a thinking-partner
stance, no implementation allowed. The real objective, which surfaced once the operator
started grounding the exploration: *a collapsed workspace-folder group in the dashboard
sidebar still renders every header slot* — git branch bar, `FolderActionBar`
(Terminals/Editor/Zed/⚙), plugin sections (Goals/Automation/KB), the `FolderOpenSpecSection`
proposal-state row, spawn buttons — so a "collapsed" folder still costs ~5 rows and two of
them eat ~340px for what is really one line of info. The goal: **make a collapsed folder
show only the essential signal (name + count + attention state), hide the heavy slots, and
keep it draggable** — then take it all the way from idea to a live, deployed, archived
OpenSpec change.

## 2. TL;DR playbook

1. **Explore first, code never.** Enter `openspec-explore`; ground the idea in the real
   components (`SessionList.tsx`, `FolderActionBar`, `FolderOpenSpecSection`) *before*
   sketching. Find the exact `{!isCollapsed && …}` seam.
2. **Mock with real tokens.** Build a throwaway HTML mockup (`/tmp/folder-collapse-mockup/`)
   using the *actual* dashboard dark-theme CSS tokens, `serve_mockup` + screenshot it so the
   operator judges real density, not a wireframe.
3. **Offer discrete variants (A–E), let the human pick.** Present a comparison table of
   trade-offs; the operator answered `2` → iterate, then `B, and keep the collapsed folder
   card draggable`.
4. **Ground the implementation before touching code.** Read the status model
   (`SessionStatus`) and reuse existing DRY primitives (`deriveStatusShape`,
   `countNeedsYou`) instead of inventing logic.
5. **TDD, surgically.** Write the helper + component tests first; add
   `countStatusRollup`, a new `FolderStatusRollup.tsx`, wrap the slot block in
   `{!isCollapsed && …}`, render the rollup in the head row. Keep `FolderDragGutter`
   OUTSIDE the wrapped block so drag survives.
6. **Update the ONE test that encoded the old behavior** (spawn buttons visible while
   collapsed) — and flag the behavioral reversal explicitly.
7. **Formalize as an OpenSpec change** (operator answered `3`): proposal + tasks (marked
   done) + `collapsible-groups` spec delta; `openspec validate --strict`.
8. **Stage ONLY your files** in a dirty tree; run biome/tsc/full client suite scoped to
   them (not `quality:changed`, which would sweep unrelated changes); commit; run advisory
   CodeRabbit on just that commit.
9. **Full build & deploy** (`full build and deploy`): `npm run build` → `POST /api/restart
   {dev:false}` → `npm run reload`; then live-verify by driving the browser to collapse a
   folder.
10. **Archive + sync** (`archive, sync proposal`): `openspec archive <change> -y`; fix any
    pre-existing malformed main spec it trips over; commit the archive move + spec sync
    separately.

## 3. How the collaboration unfolded

**Phase 1 — Discovery (explore mode).** The AI refused to sketch until it had opened the
real code: `grep`/`find` across `packages/client/src/components` to locate the folder-group
header and its slots, read `SessionList.tsx`, and identified that the header renders *every*
slot unconditionally while only child cards respect collapse. **Why it worked:** grounding
first meant the eventual seam (`{!isCollapsed && ( …slots… )}`) was known before any design,
so the design was implementable by construction.

**Phase 2 — Design via real-token mockup.** The AI grabbed the actual dashboard theme tokens
and built a live HTML mockup showing the verbose current state next to condensed variants,
served via `serve_mockup` + screenshot. When the operator picked "iterate" (`2`), it
*appended* two more concepts (D gutter-status, E hover-reveal) to the same page rather than
starting over. **Decision point:** operator chose `B` (inline status rollup) and added a hard
constraint — *keep the collapsed card draggable*.

**Phase 3 — Grounded TDD implementation.** Before code, the AI read the status model and found
the DRY primitives (`deriveStatusShape`, `statusShapeIcon`, `countNeedsYou`). It wrote tests
first: `countStatusRollup` helper spec, then `FolderStatusRollup` component spec, then wired
into `SessionList.tsx`. It discovered no `jest-dom` and switched to `.textContent` assertions.
**4 files, surgical.** It kept `FolderDragGutter` outside the collapse-wrapped block so the
drag suites (`session-drag-reorder`, `workspace-drag-reorder`, `expanded-pinned-drag`) stayed
green — honoring the operator's draggable constraint structurally.

**Phase 4 — Formalize + gate (operator: `3`).** Scaffolded an OpenSpec change matching an
existing UI change's format, wrote a `collapsible-groups` spec delta, `openspec validate
--strict` → valid. In a dirty working tree it **staged only its 6 files**, committed, ran the
advisory CodeRabbit gate scoped to that one commit (no findings).

**Phase 5 — Deploy + live-verify (operator: `full build and deploy`).** `npm run build` →
restart in production mode → reload 6 bridges → drove the browser to collapse the live
`pi-agent-dashboard` folder and confirmed the condensed header (`name (459) ●2 ⇅`) with slots
hidden and drag handle present.

**Phase 6 — Archive + sync (operator: `archive, sync proposal`).** `openspec archive` tripped
on a **pre-existing** malformed main spec (`## ADDED Requirements` at top instead of
`## Purpose` + `## Requirements`); the AI repaired it, re-archived, validated, and committed the
archive move + spec sync as a separate commit — again leaving unrelated dirty files untouched.

## 4. Prompts that worked

- **The goal prompt** — entering `openspec-explore` set a *stance* (think, don't build) that
  forced grounding before design. Effective kickoff for any "should we change this UI?" idea:
  it prevents premature code and produces a proposal you can commit.
- **High-leverage one-word follow-ups.** The steering was almost entirely single tokens:
  `2` (iterate on options), `B, and keep the collapsed folder card draggable` (pick + hard
  constraint), `3` (formalize as OpenSpec), `full build and deploy`, `archive, sync proposal`,
  `commit`. These worked *because the AI had structured each decision as a small menu with
  labeled options* — the human could steer with a letter/number instead of a paragraph.
- **Rewrite of a weak prompt.** `Ive pulled the branc` (truncated, ambiguous) → better:
  *"I pulled `develop` on another machine and don't see this change — did it push?"* States the
  observation + the question so the AI can diagnose (here: commits were local-only, never pushed).

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Present a single design and run with it | `2` (iterate) then `B, …draggable` | Always offer 3–5 labeled variants in a trade-off table before implementing UI |
| Risk breaking drag when hiding slots | Explicit constraint "keep the collapsed folder card draggable" | Structurally place drag handle OUTSIDE the collapse-conditional block; assert drag suites stay green |
| Want to run `quality:changed` on a dirty tree | (implicit) scope gates to only staged files | In a dirty tree, stage only your files and run biome/tsc/suite scoped to them, not repo-wide gates |
| Consider committing all dirty files | AI self-stopped and asked before sweeping | State "surgical changes only — commit only files this task touched" up front |
| Assume commits were pushed | `Ive pulled the branc` surfaced the gap | Check `git status -sb` (ahead/behind) before claiming a change is live elsewhere |

The operator never had to correct *quality* — the AI volunteered the guardrails (surgical
commits, flag the behavioral reversal that spawn buttons now hide when collapsed). The steering
was purely **direction** (which variant, how far to take it), which is the ideal division of labor.

## 7. Pitfalls & dead ends

- **`jest-dom` not available** → don't reach for `toHaveTextContent`; assert on `.textContent`
  directly in component tests.
- **A pre-existing test encoded the old behavior** (spawn buttons visible while collapsed).
  Variant B intentionally hides them — update the test AND flag the reversal in the commit/proposal;
  don't silently "fix" it.
- **`quality:changed` on a dirty working tree is poisoned** — `biome --changed` + full `npm test`
  with `--error-on-warnings` sweeps in unrelated changes. Stage only your files and run scoped
  biome/tsc/suite instead.
- **`openspec archive` can abort on a malformed *main* spec** — here the main
  `collapsible-groups/spec.md` had `## ADDED Requirements` (a delta header) at the top, making its
  requirements invisible to `validate`. Repair to `## Purpose` + `## Requirements` before re-archiving.
- **The live dashboard runs production mode (serves `dist/`)** — source edits aren't visible until
  `npm run build` + restart. Don't expect hot changes; use the deploy sequence.
- **Local-only commits look "done" but aren't shared** — `develop` was 3 ahead of origin, never
  pushed. Check ahead/behind before claiming a change reached another checkout.
- **Nested collapse toggle** — clicking a double-nested toggle fires twice (net no-op); re-snapshot
  and click the folder-name header once.
