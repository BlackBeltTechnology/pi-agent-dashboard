# How we did it: hunting a black-screen crash to a one-line reducer bug — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) — a "think, don't
implement" stance — with a symptom, not a task: loading one specific dashboard
session (`019f4456…`) turned the entire dashboard into a **black screen**, unmounting
the whole React root instead of showing the app's red *"Chat view encountered an
error"* fallback card. The real objective, once steering clarified it, was: **find
the exact uncaught crash that escapes React's error boundary, prove the mechanism,
capture it as an OpenSpec change, then fix it under TDD and deploy.** The decisive
clue arrived in prompt 2 — the actual console stack: `TypeError: Cannot read
properties of undefined (reading 'toLowerCase')` inside a `useState` initializer.

## 2. TL;DR playbook

1. **Lead with the deduction, not the code.** A *black* screen (not the red error
   card) means React's `ErrorBoundary` did **not** catch it → the throw happens
   *above* the boundary, or isn't a catchable render error. State that asymmetry
   first; it eliminates whole families of causes.
2. **Profile the offending record's *shape*, not its bytes.** The session file was
   1.7 MB / 308 lines but one line was 226 KB — two `browser`-tool screenshots as
   inline base64. Use `awk`/`grep`/`ctx_execute_file` to inspect record shapes
   without pulling megabytes into context.
3. **Get the real stack trace early.** Ask the user to paste the console error
   (prompt 2 did this). `qr … at Object.useState` pinned it to a reducer running in
   a lazy `useState` initializer — a render-time `TypeError`, not OOM/async.
4. **De-minify against the *deployed* bundle.** `awk 'NR==431' index-BzY2mtXh.js`
   at the crash column mapped minified `qr` → `event-reducer.ts`, and `.toLowerCase()`
   → `data.toolName as string` on the `tool_execution_start` path.
5. **Reproduce empirically before trusting a theory.** A tsx script replayed the real
   session through `state-replay` + `event-reducer` — it came back **clean** (153
   starts, 0 undefined). That falsified the "JSONL is the source" theory and pointed
   at the **IndexedDB replay cache** (`pi-dashboard-replay-cache`), which stores raw
   *live* event shapes where `toolName` can be `undefined`.
6. **Capture the finding as one OpenSpec change** (`fix-reducer-crash-undefined-toolname`)
   with two delta specs (`event-reducer` + `session-replay-persistence`) — one
   proposal, multiple capabilities.
7. **Fix under TDD:** write red tests reproducing `undefined.toLowerCase()` and the
   poisoned-cache black-screen, then coalesce `toolName` to `"unknown"` and wrap the
   rehydrate re-reduce in try/catch (poisoned entry → discard → full replay).
8. **Gate → build → restart → commit only your files.** `quality:changed`, tsc,
   full suite, CodeRabbit; rebuild client, graceful production restart; stage only
   the fix's files, leaving pre-existing dirty files untouched.

## 3. How the collaboration unfolded

**Discovery (deduce the mechanism).** Before reading any code the AI framed the core
asymmetry: the app *has* an `ErrorBoundary` that renders a red card + Reload button,
so a **black** screen means the boundary didn't fire. It mapped the client (lives in
`packages/client`, not `packages/web`), found `ChatView` is virtualized
(`@tanstack/react-virtual`) — reframing "large session" away from "render 303 rows at
once" — and drew a 4-branch decision tree (OOM / stack overflow / infinite loop /
throw-outside-React).

**Get the stack (human unblocks).** Prompt 2 pasted the real console error; prompt 3
named the exact reproducing session. This collapsed the tree instantly: a synchronous
`.toLowerCase()` on `undefined` in a `useState` initializer.

**Pin the line (de-minify + trace).** `awk` on the deployed bundle at the crash column
tied `qr` → the event-reducer's `tool_execution_start` handler:
`data.toolName as string` (the cast lies) → `.toLowerCase()` unguarded.

**Falsify the obvious source (empirical repro).** A throwaway tsx script replayed the
real session cleanly — `state-replay` normalizes `toolCall.name`, so the JSONL path
never produces `undefined`. `dashboard.db` had **zero** events for the session. The
crash therefore came from the **cold-load rehydrate path**, re-reducing raw *live*
events cached in IndexedDB, where the live bridge forwards pi-core
`tool_execution_start` verbatim (no `toolName` default).

**Capture (explore-mode artifact).** Scaffolded `fix-reducer-crash-undefined-toolname`
— proposal, design, two delta specs, TDD tasks. Prompts 4–5 steered scope: create a
proposal, and keep both capabilities in **one** proposal (not split).

**Fix + verify (apply-change, TDD).** Red tests first (reducer `undefined`/non-string;
rehydrate poisoned `data: null`), then a single coalescing point at the top of the
start handler (also protects downstream `useInflightBashTools.ts:45`), plus a
try/catch around the rehydrate re-reduce returning `null` → full replay. 469 tests
green, tsc clean, biome ratchet satisfied (0 new warnings), CodeRabbit no findings.
Built the client, graceful production restart, committed only the fix's files.

## 4. Prompts that worked

- **Goal prompt (`openspec-explore` + the symptom):** Effective because it kept the
  AI in *think/prove* mode — it deduced the boundary asymmetry and built a decision
  tree instead of jumping to a speculative patch. Reproduce this by pairing an
  explore stance with a concrete symptom.
- **Prompt 2 — pasting the raw console stack.** The single highest-leverage move: one
  stack trace collapsed a 4-branch hypothesis tree to a single line. *Always paste the
  exact error text early*, not a paraphrase.
- **Prompt 3 — naming the reproducing session id.** Gave the AI a concrete artifact to
  profile and replay, enabling the empirical falsification step.
- **Prompt 5 — "be in same proposal".** A 4-word steer that locked the OpenSpec shape
  (one change, two capabilities). Stronger version: *"keep both capabilities in one
  proposal with two delta specs."*

## 6. Skills, tools & memory created — and why they're effective

- **Memory saved (failure · tool-quirk):** `npm test`'s full parallel run
  intermittently fails two *server*-package tests (`doctor-route` probeServer,
  `recovery-offer` cold-start) due to port/timing contention — **pre-existing flakes,
  not your change**. *Why effective:* future runs won't waste time chasing these two
  red tests after a client-only change; re-run them in isolation to confirm green.
  (The note the AI tried to add hit a full memory store mid-session; the persisted
  entry captures the same fact.)
- **No skill was created, but one is warranted:** *"de-minify a production stack to
  source"* — `awk 'NR==<line>' dist/assets/index-*.js | cut -c<col>` to map a minified
  frame back to a source symbol, then grep the source. This turned an opaque `qr` frame
  into `event-reducer.ts` in one step and is reusable for any prod crash report.

## 7. Pitfalls & dead ends

- **Wrong package first.** Early `grep` assumed `packages/web/src`; the client is
  `packages/client/src`. If a path 404s, `ls packages/` before theorizing.
- **The clean-replay red herring.** Replaying the JSONL through `state-replay` came
  back with 0 undefined — tempting to conclude "no bug." It only proved the JSONL path
  is clean; the real source was the **IndexedDB live-event cache**. *If a repro is
  clean, check the other ingestion path (cache / live stream) before doubting the bug.*
- **`biome --changed` finds nothing for new files.** New test files are untracked, so
  `--changed` (diffs vs VCS base) skips them. Run biome directly on the touched paths.
- **Test-isolation guard.** Vitest runs needed an ephemeral `HOME=$(mktemp -d)` to
  avoid the isolation guard; the first bare `npx vitest run` failed on it.
- **Fake-indexeddb serialization gotcha.** A getter-trick poisoned-cache test "passed"
  for the wrong reason (serialized oddly). Use a genuinely un-reducible event
  (`data: null` on `tool_execution_start`) so the test truly exercises fault isolation.
