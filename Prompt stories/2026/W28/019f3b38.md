# How we did it: Root-cause a stuck first-launch modal and capture it as an OpenSpec bug-fix — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The user entered **explore mode** (`openspec-explore`) with a concrete bug: the
first-launch chat-display preset modal ("How much should the chat view show?")
gets **permanently stuck on mobile** — tapping Skip/Continue never dismisses it.
The literal kickoff was the explore-mode skill banner (a *stance*, not a task), so
the real objective only crystallised through steering: **diagnose the true root
cause of the stuck modal, prove it against the code, and capture a validated
OpenSpec bug-fix proposal — without writing any application code.** Explore mode
is thinking-only; the deliverable is spec artifacts, not a patch.

## 2. TL;DR playbook

1. Enter explore mode (`/skill:openspec-explore`) and paste the bug symptom.
2. `grep` the literal UI string ("how much") to locate the component
   (`FirstLaunchDisplayModal.tsx`), then trace **what unmounts it**, not what
   renders it.
3. Steer with a bare **`dig`** whenever the model reaches a plausible-but-shallow
   conclusion — force it past the first hypothesis into competing hypotheses.
4. Follow the close mechanism to the WebSocket layer; compare the modal's pref
   against its sibling prefs on the **connect handshake** (the asymmetry is the bug).
5. Say **`capture`** to scaffold the OpenSpec change (`openspec new change …`) and
   write proposal / design / spec-delta / tasks; `openspec validate --strict`.
6. Say **`make doubt review`** to run the `doubt-driven-review` cycle: same-model
   adversarial reviewer first, then a **cross-model** reviewer (probe reachability,
   pick a non-Anthropic family), reconcile every finding into the artifacts.
7. Let the review expand scope when it surfaces an adjacent bug (desktop never
   renders the modal); fold it in, re-validate `--strict`.
8. Say **`commit`**; stage **only** the change artifacts, commit as an explore-mode
   capture (no application code touched).

## 3. How the collaboration unfolded

**Phase 1 — Locate (grep the symptom).** The AI grepped the visible string, found
`FirstLaunchDisplayModal.tsx`, and — crucially — asked *"what makes this unmount?"*
rather than *"what renders this?"*. That reframing pointed straight at the state
that gates the modal (`displayPrefsLoaded && displayPrefs === undefined`).

**Phase 2 — Dig past the first answer.** The model's first read ("both buttons call
`seed()`→PATCH→`onClose()`, so they should close it") was plausible and wrong. Two
bare **`dig`** steers forced it to trace the *actual* close path: dismissal depends
on the `display_prefs_updated` **WebSocket broadcast**, and `onClose` is a no-op.
Digging surfaced **three** compounding faults instead of one.

**Phase 3 — Find the load-bearing asymmetry.** The decisive move: compare
display-prefs against every sibling preference on `wss.on("connection")`. Sessions,
pinned-dirs, favorite-models, workspaces, openspec, terminals are **all re-sent on
every (re)connect** — display-prefs is the **only** one with no connect-time
snapshot. A dropped mobile socket can never recover the pref. That one-line
diagnosis anchored the whole proposal.

**Phase 4 — Capture (`capture`).** The AI checked for a duplicate active change
(none), confirmed the archived `configurable-chat-display` as the correct target,
read an existing proposal for format, then wrote all four artifacts and passed
`openspec validate --strict`.

**Phase 5 — Doubt review (`make doubt review`).** Ran the full doubt cycle:
CLAIM → EXTRACT (artifact + contract, reasoning stripped) → DOUBT with a
fresh-context reviewer given **only the artifact + contract, never the claim** →
RECONCILE → STOP. Same-model first, then a cross-model reviewer
(`openai-codex/gpt-5.5`, probed reachable first). Both found *material* bugs in the
proposed fix — not theater.

**Phase 6 — Scope expansion + commit (`commit`).** The cross-model reviewer proved
the modal renders **only** inside the `if (isMobile)` branch — desktop never mounts
it. The AI folded desktop render-parity into the same change, re-validated, then
staged **only** its 5 artifacts and committed as an explore-mode capture.

## 4. Prompts that worked

- **Goal prompt (`openspec-explore` + the symptom).** Entering explore mode set the
  right guardrail up front: *think and capture, never implement*. A stronger kickoff
  states the symptom **and** the platform delta explicitly: "On mobile, tapping
  Skip/Continue on the first-launch chat-display modal never dismisses it; on
  desktop it never appears. Explore the root cause and capture a fix proposal."
- **`dig` (used twice).** A one-word, high-leverage steer that refuses the first
  plausible answer and forces competing hypotheses. This is what turned a
  single-cause guess into the fully-evidenced three-cause chain.
- **`capture`.** Converts finished thinking into OpenSpec artifacts in one word —
  works because explore mode already had the diagnosis loaded.
- **`make doubt review`.** Invokes the adversarial cycle; short, but unlocked two
  rounds of real bug-finding in the AI's own proposed fix.
- **`commit`.** Trusted the AI to stage surgically — it correctly staged only its
  own 5 files and left unrelated working-tree changes untouched.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Stop at the first plausible root cause ("both buttons call `onClose`, should close") | Bare **`dig`** (×2) to force competing hypotheses | Prompt "give me 2–3 competing hypotheses and the decisive check for each" before concluding |
| Treat the diagnosis as done once it read well | **`make doubt review`** — mandatory adversarial pass | Always run `doubt-driven-review` on an irreversible/spec artifact; never skip the cross-model leg |
| Frame RC1/RC2/RC3 as co-equal causes | Reviewers proved RC2 is *the* fix, RC1 is polish | Rank root causes by "does fixing this alone dismiss the modal?" |
| Gate the modal on the wrong flag (`displayPrefsSeedless`-only) — would have broken every close path | Cross-model reviewer proved the gate must stay **coupled** to `displayPrefs` | State the invariant: "every path that closes the modal must set the same state the render-gate reads" |
| Scope to "mobile" as reported | Cross-model reviewer proved desktop **never** renders the modal | Verify the render site (`if (isMobile)` branch) before trusting the platform in the bug report |

## 6. Skills, tools & memory created — and why they're effective

- **`doubt-driven-review` (invoked, not created).** The MVP of this session. It ran
  CLAIM→EXTRACT→DOUBT→RECONCILE→STOP with a fresh-context reviewer that saw only the
  **artifact + contract, never the claim** — so it couldn't rubber-stamp the author's
  reasoning. The **cross-model** leg (non-Anthropic `gpt-5.5`, probed reachable
  first) caught a critical bug the same-model pass missed. Invoke it on every spec /
  irreversible artifact before committing.
- **Project memory attempted (1 write).** The AI tried to persist two durable
  codebase facts (display-prefs is the only pref with no connect snapshot; the modal
  renders only in the mobile branch) but the project store was **at capacity**, so it
  skipped — the facts live in the change artifacts instead. *Recommended follow-up:*
  run `consolidate-pi-memory-store` so high-value architecture facts like these can
  be persisted next time.
- **Recommended skill to create:** a "diagnose-lost-websocket-preference" note —
  the reusable pattern here (a preference that has no connect-time snapshot cannot
  self-heal after a dropped socket) will recur for any new browser preference.

## 7. Pitfalls & dead ends

- **Trusting the first close-path read.** "Both buttons call `onClose`" looked
  correct; `onClose` was a no-op. *If a UI element won't dismiss, trace what state
  actually unmounts it, not what the click handler claims to do.*
- **`openspec change new` failed; `openspec new change` is correct.** The AI probed
  `openspec --help` after the first form failed. *Use `openspec new change <name>`.*
- **Stray field in an `edit`/Agent call (×2 retries).** A leftover key broke the
  call; the AI removed it and retried. *Keep edit payloads minimal.*
- **`curl /api/models` failed (REST unavailable).** Fallback: write to a temp file
  and parse with `node -e`. *Don't assume the local server is up; have a fallback.*
- **Project memory at capacity.** The `memory add` silently no-op'd. *Consolidate the
  store before a session that needs to persist durable facts.*
- **Gating on the wrong flag.** The AI's own reconciled RC3 fix (`displayPrefsSeedless`
  only) would have broken RC2. *The render-gate flag and every close-path write must
  be the same state.*
