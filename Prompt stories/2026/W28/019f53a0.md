# How we did it: Diagnose the empty-clipboard table copy bug and turn it into an OpenSpec proposal — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore` skill) — a thinking stance,
not an implementation task. The first prompt loaded the explore-mode framing verbatim:
*"Enter explore mode. Think deeply. … you must NEVER write code or implement features …
You MAY create OpenSpec artifacts."* The real objective, once the two steering turns
landed, was concrete: **root-cause why the chat view's table "Copy as Markdown" / "Copy
as TSV" buttons copy an empty string, then capture that finding as a validated OpenSpec
change proposal — without writing the fix.** Explore → understand → propose, all in one
9-minute pass.

## 2. TL;DR playbook

1. Stay in explore mode: investigate, don't patch. Grep for the copy call sites
   (`grep -rniE "clipboard|writeText|copy"` across `packages/web/src` + `packages/client/src`).
2. Read the offending component (`MarkdownContent.tsx` → `TableWrapper` → `CopyButton`)
   and the co-located test to confirm expected behavior.
3. Nail the root cause in one sentence: `text={copyMarkdown()}` is computed **during
   render**, but the reader does `ref.current?.querySelector("table")` — and React
   populates refs at **commit**, after render, so under `React.memo` the ref is `null`
   on the only render → empty string.
4. Widen the blast radius before proposing: grep **every** `CopyButton` call site;
   discover `ChatView.MessageBubble`'s "Copy as plain text" has the same latent bug
   (degrades to raw markdown instead of empty).
5. On `create proposal`: scaffold with `openspec new change <name>`, read the existing
   `content-copy` spec first, then write all four artifacts (proposal, design,
   specs delta, tasks) — the fix framed as an eager `text: string` → lazy
   `getText: () => string` contract resolved at click time.
6. Include the project-mandated `## Discipline Skills` line in `proposal.md`.
7. `openspec validate <name> --strict` until clean.
8. On `commit`: `git status` first — check whether a concurrent session already swept
   some files into an unrelated commit; commit only the stragglers, and **flag the
   muddy boundary rather than rewriting shared history.**

## 3. How the collaboration unfolded

**Phase 1 — Discovery (grep the copy path).** The AI ran targeted `grep -rniE` across
both `packages/web/src` and `packages/client/src`, filtering out tests/`.AGENTS`, to
land on `MarkdownContent.tsx`. *Why it worked:* it searched by behavior ("clipboard",
"writeText", "copy" ∩ "table") rather than by guessed filenames, so it found the real
renderer in a couple of calls.

**Phase 2 — Root-cause (read component + test + confirm memoization).** It read
`TableWrapper`, `CopyButton`, and the test, then explicitly checked whether
`MarkdownContent` is wrapped in `React.memo` — because memoization is what makes the
bug deterministic (one render only, ref never re-read). It drew an ASCII render-vs-commit
diagram. *Decision point:* the AI paused to verify the ref-timing hypothesis against the
test's expected behavior before declaring the cause.

**Phase 3 — Widen scope (every call site).** Before proposing a fix, it grepped all
`<CopyButton` usages and found `ChatView.MessageBubble`'s plain-text copy shares the
class of bug. *Why it worked:* this turned a one-button patch into a single
contract-level fix covering every ref-derived copy site — captured in the proposal's
impact list.

**Phase 4 — Generate artifacts (`create proposal`).** It scaffolded via
`openspec new change` (after probing `--help` to find the right subcommand), read the
existing `content-copy` spec for header format, then wrote proposal + design (with the
diagram and a call-site migration table) + spec delta + tasks (TDD ordering). Then
`openspec validate --strict` → clean.

**Phase 5 — Commit (`commit`).** `git status` revealed three of five files were already
committed by a **concurrent session's** `git add -A` under an unrelated
*"archive reduce-chat-render-cpu-umbrella"* commit. *Decision point:* the AI committed
only the two remaining files and chose **not** to rewrite the shared commit, flagging the
messy boundary to the human instead.

## 4. Prompts that worked

- **The goal prompt (explore-mode skill load).** Strong because it set a hard guardrail
  up front — *investigate, never implement, but artifacts allowed* — which kept the AI
  from jumping to a code patch and instead producing a diagnosis + proposal.
- **`create proposal`** — a 2-word high-leverage follow-up. It worked only because the
  root cause was already nailed; the AI had everything it needed to write four coherent
  artifacts unattended.
- **`commit`** — one word that triggered the right defensive behavior (status-check-first,
  don't rewrite shared history).

Rewrite tip: pair the goal with the acceptance bar next time —
*"explore the empty-clipboard table copy bug, find the root cause, and if you're
confident, draft the OpenSpec proposal covering every affected copy site."* That folds
the scope-widening (§3 Phase 3) into the kickoff.

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was created. Skills *used*: `openspec-explore` (the stance) and
the OpenSpec change scaffold (`openspec new change` + strict validate).

Recommended skill to create: **"eager-render-ref-read" bug pattern** — a short note that
`text={getter()}` props which dereference a `ref.current` are empty/stale under
`React.memo` because refs populate at commit, not render; the fix is a lazy
`getText: () => string` resolved at event time. It's effective because this class recurs
across any ref-derived copy/export button and the diagnosis is otherwise re-derived from
scratch each time.

## 7. Pitfalls & dead ends

- **Guessing the OpenSpec subcommand.** `openspec change new` failed; the AI had to probe
  `openspec --help` / `openspec change --help` to find `openspec new change`. → Check
  `--help` first when a CLI verb is uncertain.
- **Concurrent-session commit contamination.** A parallel session's `git add -A` swept
  `proposal.md`, `.openspec.yaml`, and the spec delta into an unrelated archive commit
  before this session committed. → Always `git status` before committing; commit only your
  stragglers; **don't** rebase/rewrite shared history to "clean" it — flag it.
- **One `git status --untracked-files=all` invocation errored** (exit non-zero on the
  path filter) — a harmless probe; re-ran with a plain `git status <path>`.
