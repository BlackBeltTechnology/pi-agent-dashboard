## 1. Goal (the ask)

The user opened with a terse three-word directive: **"remove pi (core agent — legacy fork)"**. No context, no file, no scope. The *real* objective — clarified once a screenshot arrived — was: **understand what the `pi (core agent — legacy fork)` row in the dashboard's Pi Ecosystem → CORE package section actually is, and produce a plan (no code changes) for removing it.** It turned out to be the deprecated `@mariozechner/pi-coding-agent` package, renamed to `@earendil-works/pi-coding-agent` at pi v0.74, that the dashboard surfaces on purpose so operators can clean it up.

## 2. TL;DR playbook

1. When an ask is a bare UI label with no file path, **ask for a screenshot first** rather than guessing. One `ask_user` call resolves the ambiguity.
2. From the screenshot, name the exact target: the `@mariozechner/pi-coding-agent` row, badge `local`, in Pi Ecosystem → CORE.
3. `grep` the docs first (`docs/faq.md`, `README.md`) for `legacy fork|mariozechner|pi.?ecosystem|core agent` — the FAQ already documents the row (`docs/faq.md:1818`).
4. Trace the row's source: `grep installSource|scope` in `packages/server/src/pi-core-checker.ts` (server generates the row) and the client renderers (`UnifiedPackagesSection.tsx`, `PackageRow.tsx`).
5. Split "remove" into two readings: **Plan A** uninstall the package from this machine (no code), **Plan B** rip out dashboard support for the legacy fork (cross-cutting code change).
6. Recommend Plan A; write the full analysis to `docs/plans/remove-legacy-pi-fork.md` per project doc conventions.
7. Do NOT touch code — this was scoped as a plan-only deliverable.

## 3. How the collaboration unfolded

**Phase 1 — Disambiguation.** The AI recognized the opening prompt was a behavioral directive with no actionable context. It checked session memory (`ctx_search`), found nothing, and instead of speculating, used `ask_user` to request a screenshot. This was the pivotal correct move: the ask referenced a UI label, not a file.

**Phase 2 — Target identification.** With the screenshot, the AI pinned the row to `@mariozechner/pi-coding-agent` in the CORE section with a `local` badge. It then investigated *how the row is produced* rather than assuming.

**Phase 3 — Source tracing.** Three `bash` greps walked the stack: docs (`faq.md`/`README.md`) → server generator (`pi-core-checker.ts`, where `installSource === "managed"` drives the `local` badge) → client renderers. This established that the row is generated deliberately from a managed install at `~/.pi-dashboard/node_modules/@mariozechner/pi-coding-agent`.

**Phase 4 — Two-plan synthesis.** The AI framed "remove" as two distinct operations — uninstall the machine copy (Plan A, no code) vs. remove dashboard support (Plan B, cross-cutting) — recommended A, and wrote it all to `docs/plans/remove-legacy-pi-fork.md`. The decision point (plan-only, don't edit code) was honored throughout.

## 4. Prompts that worked

- **The goal prompt** — "remove pi (core agent — legacy fork)". Weak as written (no scope, no file). A stronger version: *"In the dashboard's package section there's a row `pi (core agent — legacy fork)`. Figure out what package it is and write me a plan (no code changes) to remove it."*
- **High-leverage follow-up** — "sreenshot [image]". A single image collapsed all the ambiguity. Attaching a screenshot when the target is a UI element is worth more than a paragraph of description.
