# How we did it: Migrate the two git-only first-party extensions to npm — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened as a *question*, not a task:

> "Is there any mandatory dashboard package which git managed? Because it can cause
> problems on windows when git is not installed. What is it about?"

The real objective only crystallized after two steering turns: **remove git as a hard
runtime dependency of the dashboard by publishing the two first-party extensions
(`pi-anthropic-messages`, `pi-flows`) to npm**, switch the dashboard's recommended-
extension manifest from `git+https` sources to `npm:` sources, keep Electron's offline
bundling working, and then bring the docs and an OpenSpec change into line with the new
reality. The trigger was a Windows footgun: the *only* `required` bundled extension was
git-clone-only, so a Windows box without git silently degraded Anthropic tool calls.

## 2. TL;DR playbook

1. **Ask the diagnostic question first.** "Which mandatory dashboard package is git-
   managed, and why is that a Windows problem?" Let the AI map `BUNDLED_EXTENSION_IDS`
   in `packages/shared/src/recommended-extensions.ts` and the install path.
2. **Inventory npm vs git.** Have it build a table of every recommended extension:
   source kind, on-npm status (`npm view <name>`), required-vs-recommended. This exposes
   which ones actually block the goal.
3. **Fix the publish blockers per package.** For each git-only repo: rename to the owned
   scope (`@blackbelt-technology/*`), bump the patch version, add
   `publishConfig.access: public` + `repository`, and set a tight `files:` allowlist so
   the tarball ships only `extensions/`, `agents/`, README, CHANGELOG, LICENSE.
4. **Dry-run then publish.** `npm publish --dry-run` on each; treat a publish `E404` as
   "not authenticated" (confirm with `npm whoami` → 401), not "missing package".
5. **Flip the manifest sources** to `npm:@blackbelt-technology/...` and — critically —
   add a `bundleSource?: string` field carrying the git URL, because Electron's
   `bundle-recommended-extensions.mjs` rejects `npm:` sources.
6. **Teach both consumers to prefer `bundleSource ?? source`** — the bundle script and
   `installBundledExtensions` — and make `recommended-routes.ts` match installed/active
   against *either* form.
7. **Run the full suite, fix only your own failures.** Separate pre-existing red suites
   from the 3 `recommended-routes.test.ts` failures your change caused; fix those.
8. **Retro-document.** Create a retrospective OpenSpec change, delegate all `docs/`
   prose to a subagent, and downgrade the "git required" docs to "git recommended" once
   you confirm the boot gate never actually existed in code.

## 3. How the collaboration unfolded

**Phase A — Discovery (what is git-managed and why).** The AI grepped docs + the shared
manifest, and reported that `pi-anthropic-messages` (the sole `required` bundled
extension) and `pi-flows` were git-clone-only, so a Windows box without git broke
Anthropic-messages providers. *Why it worked:* it grounded the answer in the actual
`BUNDLED_EXTENSION_IDS` source, not the architecture doc's claims.

**Phase B — Inventory (npm vs git).** On the second prompt it produced a per-extension
table via `npm view`, revealing the 4 recommended extensions were already on npm and
only the 2 first-party ones weren't. This scoped the whole job to two repos.

**Phase C — Publish prep.** The AI discovered the docs were *wrong about the blockers*:
both repos already had MIT LICENSE files; the real issue was `pi-anthropic-messages`
being named under the un-owned `@pi/` scope. It renamed both to `@blackbelt-technology/*`,
bumped versions, added `publishConfig`/`repository`/`files`, committed locally, and dry-
ran cleanly. Actual publish returned `E404` — correctly diagnosed as *auth*, not a
missing package. The human then logged in out-of-band and published.

**Phase D — Decouple bundle vs runtime source.** After "both released to npmjs", the AI
hit the real design problem: the Electron bundle script only accepts git sources. Rather
than fork the manifest, it introduced one field — `bundleSource` (git URL for offline
bundling) alongside `source` (`npm:` for runtime install) — and updated the bundle
script, `installBundledExtensions`, and `recommended-routes.ts` to use the effective
source. *Decision point:* one optional field beat two parallel source lists.

**Phase E — Test triage.** It ran the full suite in the background, distinguished pre-
existing failures (unrelated `client-utils` import + lint on untouched files) from its
own 3 `recommended-routes.test.ts` regressions, fixed only those, and re-ran the 3
affected suites green.

**Phase F — Retro-document.** It scaffolded a retrospective OpenSpec change (proposal +
design + spec delta + tasks), delegated the `docs/` rewrites to a `general-purpose`
subagent (per AGENTS.md), and — on "downgrade git requirement" — verified the
`git-gate.ts` / `git-required.html` boot gate described in `architecture.md` **never
existed in code**, so the "downgrade" became a doc-correction from a 106-line "required"
section to a 21-line "recommended" one.

## 7. Pitfalls & dead ends

- **`npm publish` → `E404` is an auth error, not a missing package.** Confirm with
  `npm whoami` (401 = logged out). All edits/commits can be prepared first; the human
  just runs `npm login` and re-runs publish.
- **Switching `source` to `npm:` silently breaks Electron bundling.** The bundle script
  rejects `npm:` sources (it needs a clonable git URL). Add `bundleSource` (git URL) and
  read `bundleSource ?? source` everywhere, or CI bundling-required builds fail.
- **Don't chase pre-existing red suites.** The full run showed SessionHeader / "0 test" /
  `no-direct-*` failures from unrelated `client-utils` import resolution + lint on
  untouched files. Only the 3 `recommended-routes.test.ts` failures were caused by the
  change — fix those, list the rest as pre-existing.
- **The architecture doc lied about the git gate.** `git-gate.ts`, `git-required.html`,
  `openGitRequiredWindow`, `evaluateGitGate`, `system-toolchain-installer.ts` were
  aspirational — never in code. Grep before you "downgrade" a feature; the fix was a doc
  correction, not a code change.
- **Watch the npm scope.** `pi-anthropic-messages` was named `@pi/anthropic-messages` —
  a scope you can't publish under. Rename to the owned `@blackbelt-technology/*` scope
  first; the npm name is permanent once published.
