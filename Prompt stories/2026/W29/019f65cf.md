# How we did it: Collapse the diff file-tree by default — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The operator entered **explore mode** (`openspec-explore`) to think through a UI complaint:
the editor-pane's `Changes (N)` file tree "takes too much space." The first prompt was the
skill's stance boilerplate — *think, visualize, don't implement* — so the real objective only
crystallized through steering: **decide how the diff file-tree should behave by default so it
stops burying the workspace tree below it, and capture that decision as an OpenSpec proposal**
(no code). The end state: a validated `collapse-diff-file-tree` change proposing a one-line
default flip, committed.

## 2. TL;DR playbook

1. **Ground before sketching.** Ask the AI to find the real component (`ChangesRailSection`,
   `DiffFileTree`, `buildFileTree`/`collapseTree` in `diff-tree.ts`) and map the composition
   *before* proposing anything.
2. **Quantify the complaint.** Build an interactive mockup that renders each design option
   against the *exact* real change set (24 files) and prints honest **row counts** — turn
   "takes too much space" into numbers.
3. **Run a UX review on the numbers**, not vibes: rows, clicks-to-file, files-visible-on-open.
4. **Coherence-check against shipping code before recommending.** This is where the session
   was saved: "compact folders" *already ships*, so the 47-row baseline was a strawman; the
   true baseline is ~39 rows. Re-frame.
5. **Let the human pick the philosophy** (keep-all-visible vs hide-and-drill). Here they chose
   **Option A** — collapse the whole section to just the `▸ Changes (N)` header by default.
6. **Verify the spec, not just the code.** Read `change-summary-table/spec.md`; confirm the
   flip is spec-compatible and add a scenario making collapsed-by-default explicit.
7. **Scaffold the proposal** (`proposal.md`, `specs/.../spec.md` delta, `tasks.md`, mockup),
   `npx openspec validate <change> --strict`.
8. **Commit only your artifacts** — use a `-F message-file` to dodge apostrophe/heredoc
   quoting breakage; leave unrelated working-tree churn (`groups.json`) out.

## 3. How the collaboration unfolded

**Phase 1 — Discovery / grounding.** The AI resisted sketching and instead grepped the client
for the diff-tree components, then drew an ASCII map of the editor rail (two stacked trees:
`ChangesRailSection → DiffFileTree` over `EditorFileTree`). *Why it worked:* it separated the
**two independent space costs** — section-open (45% max-height) vs tree-shape (one row per
single-child dir) — so "collapse it" had a precise fork instead of a vague direction.

**Phase 2 — Quantify.** It captured the theme tokens, built an interactive mockup of 5 options
against the real 24-file change, served it, screenshotted it, and produced a scored table
(rows / clicks / files-visible). *Why it worked:* real row counts replaced hand-waving.

**Phase 3 — The coherence check (the turning point).** Before recommending "compact folders,"
the AI checked the option against shipping code and found `collapseTree` **already merges
single-child chains**. Its own "Current = 47 rows" column was a strawman; the true baseline is
~39. It openly retracted, re-framed the design space (you can't drop below 24 rows = 24 files
without hiding files), and flipped its recommendation. *Decision point:* the human, seeing the
honest math, steered toward hiding — first Option B (dirs collapsed), then narrowed to Option A.

**Phase 4 — Narrow & spec.** The operator clarified "when collapsed only the header be shown" —
i.e. Option A. The AI confirmed the change is essentially one line (`useState(true)` →
`useState(false)` in `ChangesRailSection`), read the spec to confirm `openChanges()` only needs
to *reveal* (not mount-expand), and added a collapsed-by-default scenario.

**Phase 5 — Capture & commit.** Wrote the four artifacts, validated strict, then committed only
the change folder (`e414c7c51`), deliberately excluding unrelated `groups.json` churn.

## 4. Prompts that worked

- **The goal prompt** was the `openspec-explore` stance — good because it kept the AI in
  *think/propose, never implement* mode, which is exactly right for a design decision. A
  stronger kickoff for a future operator: *"Explore mode. The `Changes` diff tree takes too
  much space — ground it in the real components, quantify each option against a real change set,
  and recommend a default. Don't implement."*
- **High-leverage follow-up:** `"when collapsed only the [header] be shown"` — a terse, one-line
  redirect that collapsed the entire option space onto Option A. Short prompts that name the
  *observable end state* ("only the header shows") are worth more than long ones.
- **`commit`** — one word, but it landed cleanly because the AI already knew to isolate its own
  artifacts from unrelated churn.

## 6. Skills, tools & memory created — and why they're effective

No skill or memory was created this session. But the workflow is a repeatable **"design a UI
default as an OpenSpec proposal"** pattern worth codifying:

- **The quantified-mockup move** — build a throwaway HTML mockup that renders every option
  against the *real* data and prints a hard metric (row count). Removes subjective
  "feels cramped" debates. Invoke whenever a UI complaint is about *space/density*.
- **The coherence check** — before recommending any change, verify it isn't already shipping.
  This single step converted a no-op recommendation into a correct one. This is exactly what
  the `doubt-driven-review` discipline exists for; invoke it before any "just flip X" proposal.

## 7. Pitfalls & dead ends

- **Strawman baseline.** The AI's first analysis compared options against a fully-uncollapsed
  tree that never renders. *If you're benchmarking a UI option, benchmark against what actually
  ships (read the render path), not the theoretical worst case.*
- **`ctx_batch_execute` errored 3/3 times** — grounding fell back to plain `bash` greps. Don't
  block on the batch tool; grep works.
- **Shell quoting broke the commit twice.** An apostrophe in `"today's"` broke inline `-m`
  quoting; a heredoc then parse-errored so *nothing ran*. *Fix:* write the message to a file and
  `git commit -F /tmp/msg.txt`. Verify with `git log --oneline -1` — a failed commit is silent.
- **Unrelated working-tree churn.** `openspec/groups/groups.json` was dirty independently;
  staging `git add <change-dir>/` (not `git add -A`) kept it out.
