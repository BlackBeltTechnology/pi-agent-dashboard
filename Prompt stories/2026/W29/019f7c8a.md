# How we did it: Unblock a contributor's stale PR without stealing credit — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was

## 1. Goal (the ask)

The session opened in **openspec-explore mode** — "think, don't implement" — pointed at
an external contributor's pull request (**PR #286**, a fork branch fixing a real Pi-TUI
bug where `ask_user({method:"confirm"})` dropped its `message` arg). The literal first
prompt was the explore-mode preamble; the *real* objective, once steering clarified it,
was: **verify the PR's bug claim is true, figure out why the PR is un-mergeable, and
unblock it — while keeping the original contributor (juicetin / Justin Ting) as the
author. Do not "take over" their work.** The finished result: PR #286 flipped from
`CONFLICTING/DIRTY` to `MERGEABLE`, contributor's commit preserved as first parent.

## 2. TL;DR playbook

1. **Investigate before touching anything.** `gh pr view 286 --json title,body,files,author,headRefName` + `gh pr diff 286`. Read the actual diff, not just the description.
2. **Verify the bug claim independently** against the current `develop`: grep pi's type defs (`node_modules/@earendil-works/pi-coding-agent/**/*.d.ts`) to confirm the real signature (`confirm(title, message, opts?)`), and confirm the target code still exists verbatim on develop.
3. **Diagnose the conflict, not the symptom.** `gh pr view 286 --json mergeable,mergeStateStatus`; fetch develop + the PR head and dry-merge to reveal *which files* conflict. Here: the PR was stale vs the `AGENTS.md → *.ts.AGENTS.md` sidecar split.
4. **Establish the authorship guarantee up front:** a squash-merge credits the *PR author*, so resolving conflicts on their branch keeps credit — re-implementing it as a fresh commit is what "takes over." State this before choosing an approach.
5. **Offer explicit options** (`ask_user`): A = hands-off (ask contributor to rebase), B = you resolve the trivial conflict on their branch. Let the human pick.
6. **Stash unrelated local dirt** (`git stash push -u openspec/groups/groups.json`) so your working tree is clean before the merge.
7. **Merge develop into the PR branch, resolve doctrine-correctly:** take develop's block, slot the one new import alphabetically; move the long doc row into a new `*.ts.AGENTS.md` sidecar (>200-char rows belong in sidecars).
8. **Run the PR's targeted tests with the project's ephemeral-HOME convention** (`HOME=$(mktemp -d) npx vitest run …`) — match the contributor's reported pass count (76 tests).
9. **Confirm before pushing to someone else's fork** (the one write outside your control), then `git push <fork-remote> HEAD:<branch>`. Verify `mergeable` + the author commit is preserved as first parent.
10. **Restore the pre-task state exactly:** unstash, unstage, delete scratch branch + temp remote.

## 3. How the collaboration unfolded

**Phase 1 — Discovery (explore mode).** The AI read the PR title/body/diff and the
current `bridge.ts` on develop. It did NOT trust the PR description; it went to pi's own
`.d.ts` files to confirm `confirm(title: string, message: string, opts?)` and that pi's
TUI renders that second arg. *Why it worked:* independently reproducing the bug chain
(ask_user → patched confirm stores `metadata.message` → TUI adapter passes `""` →
message dropped) turned "the PR claims X" into "X is verified true."

**Phase 2 — Root-cause the un-mergeability.** `mergeable` was `DIRTY` even though the
target `bridge.ts` block was untouched on develop. A dry-merge showed the real cause:
the PR branch predated the `split-large-agents` migration that broke `AGENTS.md` into
per-file `*.ts.AGENTS.md` sidecars. The conflict was **docs churn, not code.**

**Phase 3 — The authorship reframe (human steering).** The human said *"keep the
contributor as contributor, I don't wanna take over."* The AI's earlier instinct
(re-apply the fix fresh) was exactly the wrong move; it corrected itself and surfaced
the decisive fact: **squash-merge attributes to the PR author regardless of who resolves
conflicts.** It then offered A/B options via `ask_user`.

**Phase 4 — Resolve (Option B).** Stash unrelated dirt → merge develop into the PR
branch → two conflicts surfaced: `bridge.ts` (unexpected: import block re-alphabetized —
resolved by taking develop's block + one new import in its alphabetical slot) and
`AGENTS.md` (expected: 287-char row → moved to a new sidecar per the >200-char rule).

**Phase 5 — Verify & hand back.** Ran the PR's targeted tests with the ephemeral-HOME
convention (76 pass), committed the merge, confirmed juicetin's `727c362b8` survived as
first parent with author intact, **confirmed with the human before pushing to the fork**,
pushed, verified `MERGEABLE`, then restored the operator's exact pre-task state.

## 6. Skills, tools & memory created — and why they're effective

No skill or memory was created this session. **A skill *should* exist** for this recurring
task — call it `unblock-contributor-pr`: (1) `gh pr view --json mergeable,maintainerCanModify`,
(2) verify the bug claim against current `develop`, (3) dry-merge to locate the real
conflict, (4) the squash-merge-preserves-author rule, (5) resolve on the fork branch with

It removes the two things that made this slow: re-deriving the authorship rule and
re-discovering the ephemeral-HOME test convention.

## 7. Pitfalls & dead ends

- **"Re-implement it fresh" is a trap** — it discards contributor credit. Resolve on the
  branch and squash-merge instead.
- **The conflict was NOT where the fix lives.** The `bridge.ts` target block merged clean;
  the churn was in `AGENTS.md` (sidecar migration) *and* a re-alphabetized import block.
  Don't assume the conflict is in the changed code.
- **The `>200-char AGENTS.md row` rule:** a 287-char inline row must move to a
  `*.ts.AGENTS.md` sidecar to match develop's doctrine — pasting it inline re-introduces
  the over-threshold problem.
- **Tests need an ephemeral HOME.** A bare `npx vitest run …` failed; the project
  convention is `HOME=$(mktemp -d) npx vitest run …`.
- **HTTPS push to the fork needs auth wiring:** first push failed; `gh auth setup-git`
  then retry.
