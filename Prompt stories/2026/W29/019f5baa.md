# How we did it: Fix the "Pairing expired in ~5s" QR bug — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (not with a bug ticket) to think through why the
QR device-pairing code — spec'd to live ~60s — was showing "Pairing expired" only ~5s
after the QR rendered. The real objective, once steering clarified it: **root-cause the
premature-expiry bug, fix it end-to-end (server + operator UI), guard it with TDD tests,
pass the code-review gate, update the spec to match, and redeploy.** The operator drove
this in six terse steering turns rather than one big prompt — each turn unlocked the next
phase only after the previous was verified green.

## 2. TL;DR playbook

1. **Explore first, don't fix.** Enter `openspec-explore`, trace the whole pairing flow
   (`pairing.ts` → `PairLanding.tsx` → `GatewayPairQR.tsx`) and name the root cause in
   plain terms *before* touching code.
2. **Pin the root cause to one line.** Here: the one-time code's `expiresAt` is anchored at
   QR *mint* (`createPayload`) and never re-anchored — so the single 60s budget must cover
   scan + human read + type + Approve.
3. **Green-light with a single letter.** Operator said `A` to pick the fix option → switch to
   implement mode, TDD.
4. **Server fix, TDD:** write a failing test (late scan → full window), then the minimal fix
   in `redeem()`: `entry.expiresAt = this.now() + CODE_TTL_MS` (keep the expiry gate *before*
   it, preserving anti-replay). Run with `HOME=$(mktemp -d) npx vitest run …`.
5. **Steer to the operator side** (`address operator side`): remove the mint-anchored
   countdown gating in `GatewayPairQR.tsx` — countdown becomes advisory text only; server is
   sole authority. Add a regression test (`act`-flush the async load under fake timers).
6. **Run the review gate** (`code-review`): `coderabbit review --agent -t uncommitted`, triage
   **only your files**. It surfaced a real Major (`approve()` never checked expiry) — fix TDD,
   then re-review *scoped* (`--dir packages/server`) to dodge the unrelated-diff timeout.
7. **Commit scoped** (`commit`): `git add` exactly your 4 files, leave in-flight unrelated
   changes unstaged.
8. **Update the spec** (`update specs if needed`): edit `openspec/specs/qr-device-pairing/spec.md`
   to reflect the two changed `SHALL`s, `openspec validate … --type spec`, commit separately.
9. **Full redeploy** (`full build and redeploy`): `npm run build` → `POST /api/restart`
   (preserve mode) → `npm run reload`.

## 3. How the collaboration unfolded

**Phase 1 — Discovery (explore mode).** The AI read the server TTL logic and both UI sides,
then produced a clock-timeline diagram showing the 60s budget starts at mint and is never
reset by `redeem()`. **Why it worked:** naming the flow with a code-annotated timeline turned
a "mysterious 5s expiry" into an obvious design defect the operator could green-light in one
keystroke. **Decision point:** the operator typed `A` to accept the fix option.

**Phase 2 — Server fix (TDD).** Red test first (scan at t+55s, approve at t+85s → was
`"unknown"`/swept), then the one-line re-anchor in `redeem()` + a JSDoc update. All 12 tests
passed. **Why it worked:** the fix kept the expiry gate ahead of the re-anchor, so a genuinely
stale code still returns `"expired"` — the window just moves to when the device presents itself.

**Phase 3 — Operator side.** On `address operator side`, the AI removed the countdown-based
disabling of the Approve button (kept `expired` only for advisory header text, so no orphan
prop), and added a regression test proving Approve stays enabled after the countdown lapses.
**Decision point:** the human explicitly expanded scope from server-only to the self-blocking UI.

**Phase 4 — Review gate.** `code-review` ran CodeRabbit on the uncommitted diff. The AI noticed
the working tree had **pre-existing unrelated changes** and scoped triage to its own 4 files —
finding exactly one real Major: `approve()` had no expiry check, making the AI's own "server is
sole authority" comment untrue. It fixed it TDD (test → guard), then re-reviewed *scoped to
`packages/server`* to avoid the 300s timeout the huge unrelated openspec diff caused.

**Phase 5 — Commit + spec + redeploy.** Two clean scoped commits (`795344f40` fix,
`0384570fa` spec), `openspec validate` green, then the canonical full-rebuild sequence.

## 4. Prompts that worked

- **Goal prompt (explore-mode skill invocation).** Starting in *explore, don't implement*
  mode was the high-leverage move: it forced a full root-cause trace and a shared mental model
  before any edit, so the eventual fix was one line, not a guess.
- **`A`** — a single letter accepting the diagnosed option. Effective *only because* the AI had
  laid out labeled options (A/B) with tradeoffs first. Lesson: make the AI enumerate options so
  the unlock can be one keystroke.
- **`address operator side`** — three words that expanded scope to the matching client
  self-block. Short, but it landed because the AI had already flagged the client countdown as an
  open question at the end of the server fix.
- **`code-review`, `commit`, `update specs if needed`, `full build and redeploy`** — each maps
  to a known project workflow/skill; terse works when the skills exist. A future operator can
  chain these verbatim.

Rewrite for a colder start (no prior AI flag): instead of bare `address operator side`, say
*"also fix any client-side countdown that disables Approve — server should be the sole
authority."*

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Stop at the server root cause and only *flag* the matching client self-block | `address operator side` | State up front: "fix both the server TTL and any UI that gates Approve on a local timer." |
| Consider the fix done before the review gate | `code-review` | Make the review gate a non-skippable step in the plan, not an afterthought. |
| Leave the shipped code and the normative spec out of sync | `update specs if needed` | Add "update `openspec/specs/**` for any changed SHALL" to the definition-of-done. |
| Commit and stop short of deploying to the running instance | `full build and redeploy` | Include build→restart→reload as the last checklist item. |

Quality bars the operator implicitly imposed: **TDD (red before green) on every change**,
**scope discipline** (commit only the 4 relevant files amid unrelated in-flight work), and
**server-is-authority** as the design principle the UI change had to respect.

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was created — the session leaned on existing project skills
(`openspec-explore`, the CodeRabbit `code-review` gate, the full-rebuild workflow). That mix
worked, so no new asset was warranted.

**Reusable pattern worth remembering** (candidate for a future skill): *"expiry/TTL anchored at
mint instead of at the action that consumes it"* is a recurring class of bug. The effective
recipe — trace the clock, re-anchor the TTL at redemption, keep the stale-check *before* the
re-anchor to preserve anti-replay, and make the server the single authority (UI timers advisory
only) — generalizes to any one-time-code / token-redemption flow.

## 7. Pitfalls & dead ends

- **Vitest needs an ephemeral HOME.** A bare `npx vitest run …` failed; the harness requires
  `HOME=$(mktemp -d) npx vitest run …`. Use that form from the start.
- **`grep -c` flips exit code to 1 on zero matches**, which made a clean `tsc` *look* failed.
  Don't trust a piped grep's exit status — check `tsc`'s own exit with `npx tsc --noEmit; echo $?`.
- **Pre-existing type errors are noise.** The touched packages had unrelated errors
  (`auth.ts`, `npm-search-proxy.ts`, a `qa/` rootDir issue). Filter to your files; confirm with
  root `tsc --noEmit` reporting zero errors *in your touched files*.
- **CodeRabbit times out on a big unrelated diff.** The 300s review died on the in-flight
  openspec changes. Re-run **scoped** (`--dir packages/server`) to review just your area.
- **Fake timers + async load.** The client test needed an `act`-flush of the async load before
  advancing fake timers, or the component never rendered its post-load state.
