# How we did it: Planning `detect-tool-created-files` in explore mode — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal:
> take a vague "the changed-file list misses files" hunch and land a fully-reconciled,
> doubt-reviewed OpenSpec planning artifact — proposal, design, spec delta, tasks,
> test-plan, and a themed UI mockup — without writing a line of production code.

---

## 1. Goal (the ask)

The session opened in **explore mode** (the `openspec-explore` skill preamble was the
first prompt — "*Enter explore mode. Think deeply… you must NEVER write code or
implement features… You MAY create OpenSpec artifacts*"). The real objective, which
crystallized as the steering turns landed, was: **prove that the dashboard's
changed-file list silently drops files produced by anything other than `Write`/`Edit`
(converters, image-gen, scripts — all run through Bash), then capture a reconciled
design for detecting and attributing them as a complete OpenSpec change** — grounded in
the actual `session-diff.ts` extraction code, stress-tested by two independent
adversarial reviewers, and coherence-checked against the two sibling changes
(`auto-canvas`, `add-eml-preview`) it brushes up against.

## 2. TL;DR playbook

1. **Enter explore mode** (`openspec-explore`) so the AI investigates and drafts specs
   but never implements. State the hunch as a question, not a task.
2. **Ground before framing.** Have the AI `grep`/read the real extraction code
   (`extractFileChanges` in `packages/server/src/session-diff.ts`,
   `WRITE_EDIT_TOOLS`) and confirm exactly *how* files are detected today — before any
   proposal text exists.
3. **Force the feasibility check early.** Ask "are converter/imagegen tools actual pi
   tools or Bash-invoked scripts?" — the answer (they're **Bash**, no structured
   tool-result) inverts the whole design and must be found before scaffolding.
4. **Scaffold the change** with `openspec new change <name>`, then author
   proposal → spec delta → tasks against a real house-format exemplar.
5. **Run doubt-driven-review with a fresh-context reviewer AND a cross-model second
   opinion** (`@propose-review-1` = a different model family). Feed it ARTIFACT +
   CONTRACT only — no reasoning, no claim. Fold every actionable finding.
6. **Gate on missing numbers.** When scenario-design needs concrete boundaries you
   can't invent (size cap, file-count cap), STOP and `ask_user` — don't guess BVA values.
7. **Mock the UI against real tokens.** Load `frontend-mockup-loop-dashboard`, read the
   actual Files-panel component + theme CSS vars, build the mockup with exact classes,
   verify both themes/breakpoints in the browser.
8. **Coherence-sweep the neighbors.** Diff the new change's files/types against sibling
   in-flight changes; resolve overlaps with reciprocal cross-reference notes, not scope
   creep. Commit each fold scoped to only its files.

## 3. How the collaboration unfolded

**Phase 1 — Discovery & grounding (explore mode).** The AI refused to design from
memory: it ran `openspec list`, `git status`, and grepped for
`session-diff|extractChanges|tool_execution_start`, then read the existing
`session-diff-extraction` spec and the `extractFileChanges` implementation. *Why it
worked:* it produced an ASCII trace of the real event stream (Write/Edit captured,
Bash/converter/imagegen **ignored**) so the problem statement was a verified fact, not a
guess.

**Phase 2 — The load-bearing feasibility inversion.** The AI initially claimed
structured tools like document-converter emit clean output paths — then **caught its own
error**: converters and nano-banana are *Bash-invoked CLI programs*, not registered pi
tools, so there is no structured payload to read. This relocated the design: git-status
becomes the reliable **detector**, Bash-token scanning (`>`, `-o`, `--output`, `tee`)
becomes a best-effort **attributor**. *Decision point:* human answers had picked
"approach A (git-status union)" but also demanded attribution + out-of-cwd + non-git
support — which A alone can't satisfy — so the AI surfaced the contradiction and
reconciled to **hybrid C** before writing anything.

**Phase 3 — Author + two-model doubt review.** Scaffolded via `openspec new change`,
authored against the `add-eml-preview` exemplar, validated. Then spawned an `Explore`
subagent as a fresh-context adversarial reviewer, and — because the author was Claude —
a **cross-model** review on `@propose-review-1` (glm-5.2, different family). Both
converged on real bugs: porcelain paths are C-quoted / have rename `R old -> new` lines
(dedup breaks unless routed through the same `normalizePath`), a generated PNG rendered
as a synthetic utf-8 diff = corrupt blob, `producedBy` leaks secrets, out-of-cwd
`existsSync` is an unanchored probe oracle. All folded in.

**Phase 4 — Scenario-design hard gate.** At design stage the AI hit a HARD gate: two
scenarios (synthetic-diff **size cap**, **file-count cap**) needed concrete BVA numbers
it couldn't invent, so it **stopped and asked** rather than fabricate (got 256 KB / 200).

**Phase 5 — Themed UI mockup.** Loaded `frontend-mockup-loop-dashboard`, read the real
`DiffFileTree` component + theme tokens, built a faithful `files-panel.html`
(violet `◆` + `TOOL` pill reusing the existing `summed`-badge pattern), and verified
both themes + a ~300px breakpoint in the browser (Playwright headless shell was absent →
fell back to the `browser` tool).

**Phase 6 — Steering-driven scope folds + coherence sweep.** Three follow-up questions
each became a folded design layer: session-ownership gating (git status is
*cwd*-scoped not *session*-scoped), the absolute-under-cwd → relative-key contract, and
a coherence reconciliation with `auto-canvas` (zero file overlap; reciprocal
cross-reference notes added). Each fold was committed scoped to only its change's files.

## 4. Prompts that worked

- **Goal prompt (the explore-mode skill preamble).** *Why effective:* it set the stance —
  investigate and draft specs, never implement — so the AI grounded everything in real
  code and produced artifacts instead of a half-built feature. For a future run, kick off
  with: *"Explore mode. The changed-file list seems to miss files not made by Write/Edit —
  verify against `session-diff.ts` before proposing anything."*
- **"Maybe that detect tool have some regression, or features which is help for
  auto-canvas."** A short, high-leverage nudge that triggered the entire coherence sweep
  against sibling changes — catching a STALE rationale in `auto-canvas`.
- **"Is it possible to filter out git changes owned by other sessions?"** One question
  that surfaced the cwd-vs-session ownership problem and became a whole design decision.
- **"yes" / "apply".** Terminal unlock prompts — they worked *because* the AI had already
  laid out the tradeoff and the plan, so a one-word confirm was unambiguous.

Weak-prompt rewrite: "*create mockup for proposal and ux review*" → stronger:
*"Mock the Files-panel badge using the real `DiffFileTree` classes and theme CSS vars;
verify both themes and a narrow breakpoint before committing."*

## 6. Skills, tools & memory created — and why they're effective

No persistent skill or memory was *created* this session, but four existing skills did
the heavy lifting and are worth invoking together as a pattern:

- **`openspec-explore`** — keeps the AI in think/draft mode. *Effective because* it
  prevents premature implementation and forces artifact capture instead.
- **`plan-proposal` + `doubt-driven-review`** — the fresh-context + cross-model
  adversarial review is the single highest-value move: it caught a likely-fatal dedup bug
  and a binary-diff corruption bug that the author would have shipped. *Invoke* whenever a
  proposal has non-trivial parsing/normalization logic; always add a cross-model pass when
  the author model would otherwise review its own work.
- **`scenario-design`** — its HARD gate ("can't fill the input·trigger·observable triple
  → ask") is what stopped the AI from inventing cap numbers.
- **`frontend-mockup-loop-dashboard`** — grounds the mockup in real component classes +
  theme tokens so the design is faithful, not invented.

Recommended memory to save: *"`git status` in this repo is cwd-scoped, not
session-scoped — `packages/shared/src/types.ts` says sessions sharing a cwd share one
working tree; `active-sessions-in-cwd.ts` exists for this."* It's load-bearing and was
rediscovered mid-session.

## 7. Pitfalls & dead ends

- **OpenSpec requirement parser reads only the first physical line as the SHALL text** —
  a wrapped `SHALL` on line 2 fails validation. Keep the requirement statement on one line.
- **`openspec change new <name>` failed; the working command was `openspec new change
  <name>`.** Check `openspec new --help` when a subcommand errors.
- **Multi-pair edits (`oldText2`) aren't supported** — only the first old/new pair
  applies. Do separate edits.
- **Playwright's headless shell wasn't installed** → `score_mockup` couldn't run; fall
  back to the `browser` tool for screenshots.
- **agent-browser tab staleness** — a screenshot captured the live dashboard tab instead
  of the mockup. Re-`open` the mockup URL explicitly and re-snapshot before trusting a shot.
- **`existsSync` outside cwd is an unanchored probe oracle** — bound any file-existence
  probe to paths this session's own Bash events named, and anchor to cwd.
