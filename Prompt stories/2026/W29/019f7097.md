# How we did it: 2D images → free 3D model → proxy-safe Three.js viewer — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened cold with an unrelated trivia question ("Mikor volt a muhi csata?"
— when was the Battle of Muhi) and a throwaway image request. The **real objective**
only crystallized through steering: *take 2D reference images of an aircraft (Airbus
A320) and produce a good 3D model from them, then display it interactively in a
Three.js viewer — using only free, no-subscription tooling — and finally capture the
whole pipeline as a reusable global skill.* The last prompt makes the intent explicit:
"Készitsel ujrafelhasznalhato SKILL-t ebbol… ha megadok kepeket, akkor csinalja meg a
3d modellt es jelenitse meg threejs-ben" — *build a reusable skill so that given images,
it produces the 3D model and shows it in Three.js*.

## 2. TL;DR playbook

1. **Gather clean reference images** — pull free/PD/CC photos from the Wikimedia Commons
   API (multiple views: side profile, front, planform, rear), download ~1600px sizes.
2. **Prefer a clean single side-profile view** for image-to-3D (multi-view Spaces expect
   the *same* object precisely aligned; mismatched real photos degrade quality).
3. **Call a free Hugging Face Space via `gradio_client`** — try **Hunyuan3D-2**
   (`/shape_generation`, token-free, best free quality) with **TripoSR** as fallback.
   Grab the returned GLB.
4. **Build a self-contained Three.js viewer** — CDN import map, `OrbitControls`,
   wireframe/blueprint toggle. No build step.
5. **Embed the GLB as base64 directly in the HTML** and use `GLTFLoader.parse()` —
   this is the critical proxy-safe move (see §5/§7).
6. **Verify in the browser** (screenshot) *before* putting it on the canvas.
7. **Capture the pipeline as a global skill** at `~/.pi/agent/skills/<name>/` with a
   standalone script, then **test the script end-to-end** on a fresh run before declaring done.

## 3. How the collaboration unfolded

**Phase 0 — Warm-up / misdirection.** Trivia answer + a `nano-banana` image of a sulky
boy. The first `pi-nano-banana` command failed; the model recovered with
`npx @the-focus-ai/nano-banana`. Not part of the real goal, but it surfaced the
image-gen tooling.

**Phase 1 — Blueprint web page (Design).** Generated a top-down technical blueprint of
an airliner with **nano-banana pro** (`gemini-3-pro-image`), then built an interactive
`index.html`: the generated image as background with SVG hotspot regions that highlight
(cyan glow) on hover, plus a two-way info panel. Verified hotspot alignment via browser
screenshots. The human hit `stop` here to park it.

**Phase 2 — Procedural 3D (Generate + Verify).** Built `repulo-3d.html` — a fully
procedural Three.js airliner from blueprint proportions (fuselage 39.5 m, span 35.8 m).
First attempt had disordered geometry; the AI **rewrote the whole build with a clean,
verified coordinate system** (X = long axis, nose +X; Z = span; Y = up) and a DRY shared
surface-builder for wings/stabilizers. The human caught a real defect — *"farokresz el
van csuszva a torzstol"* (tail cone detached) — fixed by parenting the cone to a Group
whose pivot sits exactly at the fuselage end so only the narrow tail sweeps up.

**Phase 3 — Real image-to-3D research + gather.** The human asked which models are SOTA
for 2D→3D, then: "use one that needs no subscription, and scrape A320 images from several
views." The AI queried the **Wikimedia Commons API**, downloaded 8 free reference images,
and evaluated free **Hugging Face Spaces** through `gradio_client`.

**Phase 4 — Free generation bake-off.** **TripoSR** ran fast but produced a blobby mesh
(thin wings melted, back "hallucinated"). **Hunyuan3D-2** ran free (token-free) and its
`/shape_generation` endpoint gave a clean, proportional A320 from a single side view —
the clear winner. (Its textured `/generation_all` endpoint hit a server-side NameError;
geometry-only was reliable.) A single side-profile beat the planform (planform models
stood "on their tail").

**Phase 5 — Proxy fix.** The canvas showed "Failed to fetch": the dashboard canvas proxy
put the page on a different origin, so the relative GLB fetch failed while the external
three.js CDN loaded fine. Fix: **embed the GLB as base64 in the HTML and
`GLTFLoader.parse()` it** → zero localhost network requests, proxy-safe. Two memories saved.

**Phase 6 — Skillify.** Located the canonical global skill dir (`~/.pi/agent/skills/`),
wrote `image_to_3d.py` (images → Hunyuan3D-2 GLB with TripoSR fallback → embedded viewer)
and `SKILL.md`, then **ran the script end-to-end on a fresh A320 image** to prove the
packaged script — not just the ad-hoc code — works.

## 4. Prompts that worked

- **The scoping follow-up** — *"Ha van olyan, amihez nem kell elofizetes hasznald azt.
  Szedjel le kepeket airbus A320-rol kulonbozo nezetekben, hogy legyen input a
  modellezonek"* — this was the high-leverage prompt: it pinned a hard constraint
  (no subscription), a concrete subject (A320), and a sub-task (gather multi-view input).
  It turned an open research question into a buildable pipeline.
- **The defect report with an image** — *"farokresz el van csuszva a torzstol [image]"* —
  a precise, visual bug report. Attaching the screenshot let the AI localize the exact
  geometry error instead of guessing.
- **The proxy hint** — *"nem tolti be. Lehet a proxy nem ok [image]"* — the user's own
  hypothesis ("maybe the proxy isn't ok") pointed the AI straight at the origin/fetch
  issue. A good pattern: state your suspicion, don't just say "it's broken".
- **The skillify prompt** — *"Keszitsel ujrafelhasznalhato SKILL-t ebbol… ahogy most is
  csinaltad"* — "make a reusable skill out of this, the way you just did it" — asking to
  crystallize a *just-proven* workflow is the ideal moment to create a skill.

**Rewrite of the weak kickoff:** instead of drifting in from trivia, a future operator
should open with the whole goal: *"Given reference photos of an object, produce a 3D
model using only free/no-login tooling and show it in an interactive Three.js viewer;

## 6. Skills, tools & memory created — and why they're effective

- **Global skill `image-to-3d-threejs`** (`~/.pi/agent/skills/image-to-3d-threejs/`,
  `SKILL.md` + `scripts/image_to_3d.py`). Captures the whole pipeline: images →
  Hunyuan3D-2 GLB (free, token-free, TripoSR fallback) → self-contained Three.js viewer
  with the GLB **embedded base64** (proxy-safe). *Effective because* it removes the
  bake-off, the API-shape discovery, and the proxy trap — one command produces a rendered
  viewer. **Invoke it** whenever someone supplies reference images and wants a 3D model shown.
- **Two memories saved** during the proxy fix: (1) the free HF image-to-3D pipeline
  (Hunyuan3D-2 `/shape_generation` is the reliable free endpoint), and (2) the
  proxy-safe GLB-embed pattern. *Effective because* they let the next session skip
  straight to the working approach.

## 7. Pitfalls & dead ends

- **`pi-nano-banana` command not found** → use `npx @the-focus-ai/nano-banana` instead.
- **Detached tail cone** in procedural three.js: rotating a cone about its own center +
  a y-offset moves the wide (mating) end. → Parent it to a Group whose pivot is exactly
  at the mating point so only the far end sweeps.
- **TripoSR from a single view** = blobby (thin wings vanish, back hallucinated). → Prefer
  Hunyuan3D-2 for quality; keep TripoSR only as a fast fallback.
- **Hunyuan3D-2 `/generation_all` (textured)** hits a server-side NameError. → Use
  `/shape_generation` (geometry only) — it's reliable and free.
- **Planform (top-down) input** makes the model stand on its tail (length read as "up").
  → Feed a clean **side profile** for correct orientation.
- **"Failed to fetch" on the dashboard canvas** = the proxy origin breaks relative GLB
  fetches (external CDN still loads). → Embed the GLB base64 and `GLTFLoader.parse()`;
  never rely on a relative localhost fetch behind the proxy.
- **`gradio_client` not installed** → `pip install gradio_client` before calling Spaces.
