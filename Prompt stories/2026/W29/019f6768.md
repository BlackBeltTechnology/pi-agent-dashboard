# How we did it: Planning the out-of-cwd session-diff fix — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) to think through a bug: a
session that writes a file *outside its workspace* (the frontend-mockup-loop writing
`/tmp/mime-icon-mockup/index.html`) shows a **clickable change-summary row that opens a
permanently-empty diff tab**. The first real steering prompt sharpened the objective:

> "Is it possible when click that ask TOFU to allow / always allow?"

The *real* objective, once steering clarified it: **let the user opt into viewing
diffs for files the session wrote outside its cwd — without opening any new
arbitrary-file-read hole.** The deliverable was never code; it was a *validated,
doubt-reviewed OpenSpec change* (`opt-in-out-of-cwd-session-diffs`) ready to hand off
to `ship-it` at the worktree boundary.

## 2. TL;DR playbook

1. **Explore first, capture second.** Enter `openspec-explore`; root-cause the bug by
   tracing *both* code paths (client `buildTurnSummaries` vs server `extractFileChanges`)
   before proposing anything.
2. **Name the security pattern early.** The user's "TOFU allow/always allow" prompt is
   the frame — but split **eligibility** (what the server will *ever* read) from
   **trust/preference** (whether the user is *prompted*). Write that orthogonality down.
3. **Scaffold the change** with `openspec new change <name>` (not `openspec change new`
   — that form failed), then draft `proposal.md` + `design.md` + spec deltas.
4. **Run `plan-proposal`** on `develop`, in the main interactive session only.
5. **Doubt-review the design** (`doubt-driven-review`): spawn a fresh-context adversarial
   reviewer, then — mandatory in interactive sessions — a **cross-model** second opinion
   (here `@propose-review-1` / `glm-5.2`).
6. **Let the review kill your design.** Both reviewers disproved the server-read gate
   (pre-execution event args, symlink-follow, reachable with the toggle off). **Pivot**
   to rendering diffs from the *captured Write/Edit event payload* — no server file read.
7. **Verify the pivot's one risk** empirically: is the captured payload faithful? Confirm
   pi's session JSONL holds untruncated Write content (session-addressed by
   `(sessionId, toolCallId)`, never path-addressed).
8. **Second doubt cycle** → refinements only → fold them, run `scenario-design`, fold
   16 automated scenarios into `tasks.md`, `openspec validate --strict`, commit only
   this change's dir, **stop at the worktree boundary**.

## 3. How the collaboration unfolded

**Phase A — Discovery / root-cause.** The AI grepped the diff code paths (`diff:`,
`openDiffTab`, `buildTurnSummaries`, `normalizePath`) and produced a two-column diagram:
the **client** shows the out-of-cwd row (no cwd filter) while the **server**
`/api/session-diff` drops it (`normalizePath` returns null). The click therefore opens an
empty `diff:/tmp/...` tab. *Why it worked:* it read both sides before theorizing, so the
mismatch — not a single bug — was the real finding.

**Phase B — Design the safe grant.** Prompted by "TOFU allow/always allow", the AI
surfaced the load-bearing reframe: **eligibility (exact session-authored realpaths,
server-enforced) ⊥ preference (display-only, default off)**. Trust can only *mute the
prompt*, never *widen the read set*. This collapsed three scary concerns (symlink escape,
`/tmp` TOCTOU, arbitrary target) — on paper.

**Phase C — Capture the change.** Scaffolded `opt-in-out-of-cwd-session-diffs`, wrote
proposal/design/specs, `openspec validate --strict` clean.

**Phase D — Doubt-review demolishes it.** `plan-proposal` → `doubt-driven-review`. A
fresh-context reviewer + a **cross-model** (`glm-5.2`) pass converged: the eligible set
was derived from `tool_execution_start` — a **pre-execution** event — so a *rejected*
`write({path:"/etc/passwd"})` still seeds the readable set; `realpath` follows induced
symlinks; the read fires **with the toggle off**; and the design ignored the repo's
already-shipped `path-containment.ts`. **CLAIM falsified.**

**Phase E — Pivot (the human's lazy-load insight).** The user asked whether large files
could load lazily. The AI verified that `DiffPanel` **already** renders diffs from the
captured event payload (Path C, no server read) and that pi's session JSONL carries the
**untruncated** Write content — addressed by `(sessionId, toolCallId)`, never by path.
The entire server-read channel was deleted; fidelity comes from session-captured data.

**Phase F — Converge & land.** Second doubt cycle found only refinements
(guard-before-enrichment as a *tested invariant*, precise JSONL lookup with **no path
fallback**). Folded, ran `scenario-design`, folded **16 automated scenarios** into
`tasks.md` (30 vanilla checkboxes, parser-safe), committed only this change's dir at
`e7a48f7cd`, and stopped at the worktree boundary — deliberately **not** committing the
shared `openspec/groups/groups.json` (mixed with ~6 other sessions) or the pre-dirty
`package-lock.json`.

## 4. Prompts that worked

- **Goal prompt (`openspec-explore`):** entering explore mode meant the AI root-caused
  and *thought* before writing a line of spec — exactly right for a design with a security
  surface. A stronger kickoff states the observable up front: *"In explore mode, root-cause
  why an out-of-cwd session-written file shows a clickable-but-empty diff row, tracing both
  the client summary path and the server extraction path."*
- **"Is it possible when click that ask TOFU to allow / always allow?"** — a high-leverage
  one-liner: it named the interaction pattern (TOFU) that became the whole design frame.
- **"IS it possible that the large files can be loaded in lazy way? … I think that
  limitation was made for chatView only"** — the pivot-unlocking prompt. It reframed the
  4 KB cap as a *transport concern*, steering the AI to a session-addressed lazy fetch that
  eliminated the read hole. A domain hunch beat the AI's "accept truncation" fallback.
- **"go on" / "poke" / "B"** — cheap unlock tokens that kept momentum through
  investigation without re-specifying.

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was saved, but the session is a textbook run of three existing
skills chained by `plan-proposal`:

- **`openspec-explore`** — kept the AI in think-only mode so it root-caused the two-path
  mismatch before proposing. *Invoke it* whenever the bug's mechanism isn't yet certain.
- **`doubt-driven-review`** (with the **mandatory cross-model** step) — the hero here. A
  fresh-context + cross-model pass *disproved the whole first design* while it was still
  cheap to change. *Invoke it* on any design touching auth/secrets/remote reach, before
  the worktree boundary.
- **`plan-proposal`** — the orchestrator that sequences new→doubt→scenario-design→fold and
  **stops at the git-worktree boundary** (the interactive/headless line).

*Reusable insight worth a memory:* **eligibility ⊥ preference** — a display/preference
toggle must never widen a server's read surface; the two live in separate layers.

## 7. Pitfalls & dead ends

- **`openspec change new <name>` fails** — the correct form is **`openspec new change
  <name>`**. If the scaffold errors, check the verb order.
- **Requirement parser takes the first line as the requirement text** — a line that wraps
  *before* `SHALL` breaks validation. Keep `SHALL` on the requirement's first line.
- **Deriving an eligible read-set from `tool_execution_start`** is unsafe: it's a
  *pre-execution* event, so even a **rejected** write seeds it. If you must gate reads by
  "what the session wrote," use a post-execution signal — or better, don't read at all.
- **`realpath` follows attacker-induced symlinks** — a symlink swap inside a "trusted" dir
  resolves to the target. Path-membership by realpath is not a containment guarantee under
  a remote/multi-actor threat model.
- **Committing shared registries** — `openspec/groups/groups.json` accumulates entries from
  concurrent sessions; committing it sweeps in others' state. Stage only your change's dir.
