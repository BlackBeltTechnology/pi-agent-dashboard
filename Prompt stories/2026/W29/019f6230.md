# How we did it: Diagnose & spec the ask_user double-card bug — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore` skill) — "Enter explore mode.
Think deeply. Visualize freely." — a thinking-partner stance, not an implementation task.
The *real* objective, which crystallized over the next few turns: a live `ask_user{method:"confirm"}`
prompt renders **two stacked cards** in the dashboard chat, and the operator wanted the AI to
(a) pin down the exact bug, (b) mock up the fix, (c) pick the better option, and (d) capture
it as a validated OpenSpec change proposal — **without writing any implementation code.**

## 2. TL;DR playbook

1. Kick off in `openspec-explore` mode so the AI investigates and captures thinking but never implements.
2. Point it at the two rendering code paths: `AskUserToolRenderer` (tool card) vs the interactive dialog renderers (`ConfirmRenderer`/`SelectRenderer`/…).
3. **Feed a screenshot of the actual bug** — it reframed "duplicate card" into the precise "title duplicated, description stranded" diagnosis.
4. Have the AI build a static HTML mockup (Current / Option A / Option B) using real theme tokens from `index.css`, served via `serve_mockup`.
5. Ask it to **score A vs B** against the dashboard design skill + `score_mockup` rubric, then pick a winner ("A").
6. Scaffold the change with `npx openspec new change <name>`; write `proposal.md`, `design.md`, `tasks.md`, and the two spec deltas.
7. Move the mockup into `changes/<name>/mockups/` and reference it from a `## Mockups` section in the proposal.
8. `npx openspec validate <name> --strict` until clean; commit only the change directory.

## 3. How the collaboration unfolded

**Phase 1 — Discovery (code read).** The AI grepped for `AskUserToolRenderer|interactiveUi|GenericDialog`,
read the two renderers and `ChatView`, and pulled theme tokens (`--bg-primary`, `--text-*`,
`--border-secondary`). It formed an initial "the title is duplicated" hypothesis. *Why it worked:*
it grounded the diagnosis in the actual two-code-path layout before drawing anything.

**Phase 2 — Screenshot reframe (the pivotal turn).** The operator replied "The description is not
shown on card" **with an image**. That screenshot changed the diagnosis: the **title** is duplicated
across both cards, while the **description lives only on the tool card** — so naively hiding the tool
card deletes the only copy of the description. This became the central design constraint.

**Phase 3 — Mockup + scoring.** The AI built a 3-column static HTML mockup (Current with red/yellow
overlays, Option A, Option B), served it with `serve_mockup`, and scored it. Playwright's
headless-shell **would not finish downloading** in this environment (3 failed install attempts), so
it fell back to the `agent-browser` screenshot to score visually against the dashboard rubric + the
A-vs-B decision. Operator picked **A**.

**Phase 4 — OpenSpec capture.** A coherence check against archived changes surfaced the real subtlety:
the `interactive-renderers` spec **deliberately drops `message` in resolved states**, and on history
reload the server only replays *pending* prompts — so for an already-answered `ask_user` the tool card
is the *only* record. Suppression must therefore be **conditional on a paired live `interactiveUi`
message** (matched by `toolCallId`). The AI scaffolded the change, wrote all artifacts, and validated strict.

**Phase 5 — Fold mockup in + commit.** Moved the mockup into `mockups/`, added a `## Mockups` section
to the proposal, re-validated, and committed only the change directory — leaving an unrelated stray
`.pi/settings.json.bak-*` untouched.

## 4. Prompts that worked

- **The goal prompt (explore-mode skill invocation).** Starting in `openspec-explore` set the right
  stance: investigate + capture thinking, never implement. Effective because it kept the AI from
  jumping to a code fix before the bug was even correctly understood.
- **"The description is not shown on card" + image** — the single highest-leverage turn. A one-line
  correction plus a screenshot flipped a wrong hypothesis into the exact design constraint. *Lesson:
  when a UI diagnosis feels off, send a screenshot; it's worth more than paragraphs of prose.*
- **"Check with us check skill and score which is better?"** — unlocked the A-vs-B evaluation against
  the design skill + scoring rubric instead of a gut pick.
- **"A"** — a one-character decision that committed the direction and let the AI proceed to spec.
- **"add mockup to proposal"** — turned an ephemeral `/tmp` mockup into a durable review artifact inside the change.

Stronger rewrite of the goal prompt for next time: *"Explore mode. The `ask_user` confirm prompt shows
two stacked cards — diagnose which fields duplicate across `AskUserToolRenderer` and the interactive
renderers, mock up a fix on real theme tokens, and capture it as an OpenSpec change. Here's a screenshot."*
(Lead with the screenshot and both code paths up front to skip the reframe round-trip.)

## 7. Pitfalls & dead ends

- **Playwright headless-shell won't install here.** Three attempts (`npx playwright install chromium`,
  timeout-wrapped, and backgrounded with polling) all failed to complete the download. *If you hit this:*
  don't burn time retrying — screenshot the served mockup with the `agent-browser`/`browser` tool and
  score visually instead.
- **Naive "hide the tool card" deletes the description.** The interactive renderers drop `message` in
  resolved state, and history reload only replays *pending* prompts. *So:* make suppression conditional
  on a paired live `interactiveUi` message sharing the same `toolCallId`, and make resolved renderers
  render `params.message`.
- **Stray backup file in git status.** A `.pi/settings.json.bak-switch-*` from an earlier
  switch-extension op showed up untracked. *Do:* stage only your change directory; leave unrelated strays alone.
