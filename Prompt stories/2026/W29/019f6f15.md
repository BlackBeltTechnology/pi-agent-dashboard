# How we did it: Reroute `/view` into the Monaco editor pane — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) — a thinking stance, no
implementation. The real ask arrived in the second turn:

> *"Currently the opposite. I would like to cange /view command to open in monaco editor in SplitWorkspace."*

Restated after the steering clarified it: **stop the `/view` slash command from
injecting an inline `PreviewCard` row into the chat transcript, and instead route its
target (file *or* URL) into the Monaco editor pane inside `SplitWorkspace`** — reusing
the same rich viewer registry a file-tree click uses. Along the way the scope grew to
(a) retire *only* the `/view`-specific inline subsystem, (b) generalize rich-viewer
support to 5 file kinds (docx·pptx·spreadsheet·asciidoc·email), consuming the in-flight
`fix-eml-preview-in-editor-pane` change, (c) add `isLocalhost`/capability-gated
system-open actions, and (d) fix the disabled diff-panel Preview button — landing as a
single, doubt-reviewed OpenSpec planning artifact set on `develop`.

## 2. TL;DR playbook

1. **Enter explore mode** (`openspec-explore`) — force a read-only map of the surface
   *before* any proposal. Give a one-line intent; let the AI find `parseViewCommand →
   onViewLocal → inject_view_message → ViewMessageStore → PreviewCard`.
2. **Answer the framing questions tersely** (`files only`, `retire`, `all kinds`) — but
   **challenge any "we have to drop X"** claim; here "drop URLs" was a false necessity
   the AI walked back once pushed.
3. **Ask for the coherence check before scaffolding** — it surfaced the active
   `fix-eml-preview-in-editor-pane` overlap, turning "add a viewer" into "generalize a
   change already in flight" (consume it).
4. **Scaffold with `openspec new change`**, then write proposal + design + 3 spec deltas
   + tasks; `openspec validate --strict` after every edit.
5. **Run `scenario-design`** to generate an adversarial `test-plan.md` (falsify, don't
   confirm) — it exposed 3 decision-forcing spec gaps; resolve them and thread the
   answers through every artifact.
6. **Fold new exploration questions in** (system-open actions, diff Preview button) as
   they arise — each becomes a design decision + spec delta + tasks + test rows.
7. **Run `plan-proposal`** → `doubt-driven-review` with a **cross-model reviewer**
   (glm-5.2 → deepseek-v4-pro). This caught the plan resting on non-existent code.
8. **Fix every confirmed defect, re-review, then fold** the 45 scenarios 1:1 into a
   `## Tests` section; commit scoped to the change dir; **stop at the worktree boundary**.

## 3. How the collaboration unfolded

**Discovery (explore mode).** The AI mapped every "view" surface (file-link click,
`skill_manage view`, flow sub-rows) and drew ASCII flow diagrams to *pin down which one*
the terse ask meant. It refused to write code — correct for explore mode. Effective bit:
it built the full `parseViewCommand → onViewLocal → ViewMessageStore → PreviewCard` call
graph and identified `/view` as the **sole feeder** of the inline path (so this was
"retire a subsystem," not "reroute one call").

**Decision locking.** Three terse answers (`files only`, `retire`, `all kinds`) set
direction, but the human immediately pushed back — *"Currently URL-s open in editor pane.
Why it have to drop?"* — and the AI corrected its own framing: dropping URLs was a
consequence of the earlier "files only" pick, **not** a technical requirement. The pane's
`UrlViewer` reuses the exact `dispatchPreview → PreviewBody` the inline card used. The
human chose **Option A** (extend the `?url=` route).

**Coherence + consume.** Before scaffolding, a pre-scaffold check found an active
`fix-eml-preview-in-editor-pane` (0/10 tasks) doing the same 3-surface reconciliation for
`.eml` only. Decision: **one proposal** that generalizes it to all 5 kinds and consumes
the eml change.

**Generate + scenario-design.** Four artifacts + two spec deltas written and validated
strict. `scenario-design` produced 35→45 adversarial scenarios and surfaced 3 spec gaps
(both-params precedence, large-file ceiling, legacy-field replay) — each resolved and
threaded through design/tasks/spec/test.

**Fold-in explorations.** Two mid-session questions (system-open actions; the disabled
diff Preview button) each expanded scope by a full design decision. The diff-Preview
piece went through **five** reframings before the human's final model landed: `Diff · File
· Regions · Preview` (rename the old changed-regions view to *Regions*; new *Preview* =
current on-disk file through the type-based viewer-registry).

**Doubt gate (highest value).** `plan-proposal` → `doubt-driven-review` ran 2 cross-model
cycles. Cycle 1 found the plan rested on **false premises about shipped code**
(`isLocalhost()` doesn't exist; `fileKind()` throws on a relative path; deleting
`PreviewCard` would break `PreviewBody`'s protected callers). All fixed; cycle 2 confirmed
and found 3 narrower gaps. Then a clean 45↔45 fold and a scoped commit
(`fb9e5d8b6`), stopping at the worktree boundary.

## 4. Prompts that worked

- **Goal prompt** (explore stance): starting in `openspec-explore` was the single best
  move — it forced a full read-only map before any code decision, so the eventual
  proposal was grounded in real call paths, not guesses. A stronger kickoff would add the
  concrete symptom + desired end state in one line: *"`/view @path` renders an inline card
  in ChatView; I want it to open in the Monaco editor pane in SplitWorkspace instead —
  explore first."*
- **High-leverage challenge:** *"Currently URL-s open in editor pane. Why it have to
  drop?"* — one question reversed a wrong scope cut and kept URL support.
- **`Consume fix-eml-preview-in-editor-pane to be one proposal`** — a 6-word steer that
  merged two changes and avoided a collision.
- **`scenario-design`** / **`plan-proposal`** — invoking the skills by name routed the
  work into the adversarial-testing and doubt-review machinery that caught the real bugs.
- **Reframing prompt:** *"Maybe Preview is wrong name… the current file where the diff was
  made, in full rich whole file current version from disk"* — a plain-language behavior
  description that finally pinned an ambiguous button after several wrong AI guesses.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Treat a scope cut ("files only") as forcing a technical drop (URLs) | *"Why does it have to drop?"* | Separate **product scope** from **technical necessity**; ask the AI to label which is which. |
| Guess the semantics of an ambiguous button ("Preview") | Iterating 5×, then a concrete example: *"for a diff on README.md, View shows the rendered README, no red/green"* | State the desired behavior as an **input→observable example** up front, not a name. |
| Over-engineer the fix (reconstruct file from `edits[]` fragments) | *"A diff means a file exists on disk — just show that file"* | Prefer "read the real artifact" over "rebuild from payload" when the artifact exists. |
| Cite helpers as "the existing gate" without verifying | doubt-review cross-model reviewer caught `isLocalhost()` doesn't exist | Make **"grep the symbol before citing it"** a hard rule; run doubt-review with a *different model family*. |
| Plan a deletion that breaks shared exports (`PreviewCard`→`PreviewBody`) | doubt-review flagged protected callers | Check re-exports/consumers before writing "delete X / Migration: None". |

## 6. Skills, tools & memory created — and why they're effective

No new skills or memories were created; the session was pure orchestration of existing
ones — and that's the lesson worth capturing:

- **`openspec-explore`** — read-only thinking mode. Effective because it *prevents*
  premature scaffolding; the map it builds is what the whole proposal rests on.
- **`scenario-design`** — turns a spec into adversarial (falsify-don't-confirm) scenarios
  and *surfaces spec gaps as decision-forcing questions*. It found 3 undefined observables
  the prose had glossed over.
- **`plan-proposal` + `doubt-driven-review`** — the cross-model doubt gate is the
  single highest-leverage tool here: it converted a plausible-but-broken plan into an
  implementable one by catching false premises about shipped code. **Always run it with a
  reviewer from a different model family than the author.**

If anything should be saved: a memory that *"doubt-review must grep-verify every cited
helper/symbol; a plan citing `isLocalhost()`-style gates that don't exist is the failure
mode."*

## 7. Pitfalls & dead ends

- **Grep output mangling.** A display filter mangled identifiers (`ViewTarget`→`ln`,
  `/view`→`n`). *If grep results look garbled, read the source file directly* instead of
  trusting the filtered stream.
- **Reconstruct-from-payload dead end.** The first diff-Preview design rebuilt the file
  from `content`/`edits[]` fragments (fake line numbers for Edits). Abandoned once the
  human pointed out the file is on disk — *read it, don't rebuild it.*
- **Stale git lock.** The scoped commit failed on a 0-byte `.git/index.lock` left by an
  interrupted commit. *Confirm no `git` process is actually running (`ps aux | grep git`),
  then `rm -f .git/index.lock` and re-commit* — the `git add` had already succeeded.
- **Empty `ask_user` selection.** A multiple-choice selection came back empty once; the AI
  correctly re-offered rather than guessing. *Re-prompt on empty, never assume.*
- **Citing unverified helpers.** `isLocalhost()` was cited as "the existing helper" but
  never existed — only caught by cross-model doubt-review. *Verify before citing.*
