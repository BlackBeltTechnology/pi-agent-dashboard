# How we did it: Grounding an Office-preview proposal in a real 900-file corpus — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`): *think, don't implement*.
The real objective, once the steering turns landed, was concrete: **decide how the
dashboard should preview Office documents (`.docx`, `.xlsx`, `.csv`, later `.pptx`) in
its `/view` subsystem, and capture that decision as validated OpenSpec change
proposals.** The winning move was never "pick a library from memory" — it was
"measure the operator's *actual* files first, let the data pick the design, then write
the proposal." The output: two `--strict`-valid OpenSpec changes
(`render-office-previews` ready to build, `render-pptx-preview` stubbed→planned),
committed to `develop`.

## 2. TL;DR playbook

1. **Start in explore mode** — `openspec-explore`. Forbid implementation; allow reading,
   searching, and writing OpenSpec artifacts.
2. **Ground in the codebase before theorizing.** `kb_search` + read the existing preview
   dispatch (`dispatchPreview`, `RENDERER_BY_EXT`, `/api/file/render`, `AsciiDocPreview`).
   Find the *template pattern* to copy (here: the AsciiDoc server-render path).
3. **Probe the operator's real corpus, not toy files.** `find ~/Documents/Projektek -iname '*.docx'`
   → 475 real files. Run the candidate library (mammoth) across **all** of them and count failures.
4. **Turn failure rates into design verdicts.** 21% of docx crashed on *one* mammoth bug
   (null-href hyperlink) → a 5-line `transformDocument` guard → 99.8% render. That single
   number flipped "we need Docker/document-converter" into "in-process wins."
5. **Let the operator eyeball fidelity.** Render representative files to HTML, `serve_mockup`,
   hand over clickable `http://localhost:…` links. Human confirms → design crystallizes.
6. **Build a real-token mockup + UX review.** Pull actual theme CSS vars (no guessed hex),
   mirror `PreviewCard.tsx` chrome, `score_mockup` across breakpoints + themes.
7. **Draft against the closest precedent.** Use the existing `add-eml-preview` change as a
   structural template; author the spec *delta* against the current main spec.
8. **Run a coherence sweep** across all active changes touching the same surface; record
   cross-change interactions (union clobber, path relocation) as a `## Coordinates With` note.
9. **Validate `--strict`, commit only your own files** (stage explicitly — the tree had
   unrelated in-progress work).

## 3. How the collaboration unfolded

**Phase 1 — Discovery (ground before theory).** The AI read the preview subsystem end to
end (`kb_search`, `read`, `grep`) and identified that dispatch is pure extension-based,
that docx/xlsx/csv currently fall through to a download link, and that **AsciiDoc's
`/api/file/render` server-render path is the exact template** a new renderer would copy.
*Why it worked:* it found the integration seam before proposing anything, so every later
decision slotted into a known shape instead of inventing one.

**Phase 2 — Gather (measure the real corpus).** Steered by "check docx files first from
Documents/Projektek," the AI ran mammoth across all **475** real docx, then **401** xlsx
and **31** csv. This surfaced the decisive facts: a 21% mammoth crash rate from a single
null-href bug, a 66MB corrupt zip, 16MB HTML image-bloat, a 35-million-cell workbook, a
507MB / 3.3M-line csv. *Why it worked:* the design axis (**unbounded input → bounded-preview
policy**) was *forced by data*, not guessed.

**Phase 3 — Fidelity check (human eyeballs the output).** Prompt "can me show some output
as openable link?" → the AI rendered 5 representative docx (incl. 2 former crash-files),
served them, and handed over clickable links with a per-file meta bar. The human's "seems
ok" locked docx fidelity.

**Phase 4 — Design + mockup.** The AI pulled real theme tokens, built a mockup mirroring
`PreviewCard.tsx`, and ran `score_mockup` across dark/light + breakpoints (falling back to
the browser tool when Playwright headless was absent). WCAG/responsive/token-fidelity all ✔.

**Phase 5 — PPTX branch (a categorical fork).** "Is it possible to add PPTX support?"
forced the realization that decks are *absolutely-positioned visual* content with no
faithful in-process HTML path — so `soffice → PDF → existing PdfPreview` (pixel-perfect).
Decision: **split** it into a follow-up change to keep the office proposal dependency-free.

**Phase 6 — Draft, cohere, commit.** Drafted both changes against the `add-eml-preview`
template, folded in the discovery that `document-converter`'s `renderPdf` *already accepts
docx* (two-tier fidelity-first path, no new engine command), ran a coherence sweep, added
`## Coordinates With` ordering contracts to all four sibling proposals, validated `--strict`,
and committed **only** the operator's own files.

## 4. Prompts that worked

- **The goal prompt (explore mode).** Effective because it set a *stance* (think, don't
  implement) while explicitly permitting OpenSpec artifacts — the AI stayed in analysis
  but still produced durable output.
- **"check docx files first from Documents/Projektek"** — the single highest-leverage turn.
  It redirected the AI from library-theorizing to **measuring real files**, which produced
  the 21%/99.8% numbers the whole design hinges on. Bake this in: *"ground every design
  decision in my actual corpus at <path> before proposing a library."*
- **"can me show some output as openable link?"** — turned an abstract fidelity claim into
  a clickable artifact the human could judge. Reusable pattern: *render + `serve_mockup` +
  hand over the URL.*
- **"Currently document-converter can convert via docker. Is it can be utilized?"** —
  surfaced the fact that LibreOffice is *already bundled* in the engine and `renderPdf`
  accepts docx, which produced the two-tier design.
- **Terse unlockers** — "include", "draft", "fidelity-first", "coherence-check" — each a
  one-word decision that let the AI proceed without re-litigating. They worked *because*
  the AI had already laid out the options; the human only had to pick.

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was persisted this session — but the workflow is a strong
skill candidate. **Recommended skill: `corpus-grounded-proposal`** —

- **What it captures:** the loop of *find the real corpus → run the candidate renderer
  across all of it → convert the failure rate into a design verdict → let the human eyeball
  served output → draft the OpenSpec change against the closest precedent → coherence-sweep →
  validate `--strict`.*
- **Why it's effective:** it replaces "pick a library and hope" with a measured verdict.
  The 21%→99.8% pivot is only visible because the AI ran *all 475* files, not a sample.
- **When to invoke:** any "should we add support for format X to subsystem Y" proposal where
  the operator has a real corpus to test against.

Tools that carried the session: `serve_mockup` (hand the human clickable fidelity proof),
`score_mockup` (rubric-driven UX review across themes/breakpoints), `kb_search` (find the
seam), and OpenSpec's `validate --strict` (the correctness gate on every artifact).

## 7. Pitfalls & dead ends

- **SheetJS ESM drops `readFile`.** `XLSX.readFile(path)` returned 0/401 (silent all-fail).
  → Use `XLSX.read(buffer)` in Node ESM.
- **Long corpus loops hang.** The csv parse hit a 120s timeout on a 507MB / 3.3M-line file.
  → Measure sizes cheaply first; cap/stream; add per-file error capture so one bad file
  doesn't nuke the run (this is *also* the design's bounded-preview requirement).
- **mammoth 1.12.0 crashes on null-href hyperlinks** (`escapeHtmlAttribute(undefined)`),
  ~21% of real Hungarian business docx. → 5-line `transformDocument` guard sets `href=""`.
- **A 66MB "docx" was not a valid zip.** → The renderer must catch and degrade to
  FallbackPreview; ~1% tail is genuinely unrenderable.
- **Playwright headless wasn't installed** for `score_mockup`. → Fall back to the `browser`
  tool for screenshots.
- **Don't build the document-converter Docker image unprompted** — heavy; the AI correctly
  refused and worked in-process.
- **Mixed working tree.** Unrelated `integrate-develop-before-ship-gate` archive move +
  `groups.json` were present. → Stage only your files; commit others' work separately.
