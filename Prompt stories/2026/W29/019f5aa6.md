# How we did it: Root-causing "why kb_search never fires in worktree sessions" into two validated OpenSpec proposals — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`/skill:openspec-explore`) with a stance, not a
task: *"Enter explore mode. Think deeply… you must NEVER write code or implement
features. You MAY create OpenSpec artifacts."* The concrete question the operator was
chasing: **why does `kb_search` almost never show up in recent worktree-based sessions?**

Once the steering turns landed, the *real* objective emerged: don't just answer the
observation — **root-cause it to a real defect and capture the fix as validated OpenSpec
proposals, without leaving explore mode or touching implementation code.** The
investigation uncovered two independent bugs (empty-schema-on-open + an existence-only
init gate; and WAL-sidecar resurrection of removed worktrees), each of which became its
own change proposal, then a clean surgical commit.

## 2. TL;DR playbook

1. Start in `/skill:openspec-explore` — bind the AI to *think, not implement* (it may still write OpenSpec artifacts).
2. Ask the diagnostic question ("why doesn't X happen in Y sessions?") and let the AI **measure before theorizing** — scan the real session JSONLs for actual tool-call frequency, don't trust intuition.
3. When the first schema guess misses, have it **inspect the raw JSONL structure** (`type: "toolCall"`, `name` field) and rescan correctly.
4. Steer with **"dig deeper"** once the surface answer (behavioral: apply-change skill never trips the docs-first gate) is in hand — push for the *technical* compounding cause.
5. Demand an **empirical reproduction**, not a hypothesis: reproduce exactly what `kb index` does inside an orphan worktree → observe the 56K empty husk + ENOENT ordering.
6. Convert the confirmed root cause into an OpenSpec change with `openspec validate --strict`; **run the pre-scaffold coherence check** (inspect adjacent in-flight changes before creating anything).
7. Pick the follow-up direction ("1"), pin *where* the fix lands by tracing the removal code paths, and scaffold the second change.
8. Commit **surgically** — stage only the files you authored; explicitly leave other sessions' untracked work alone.

## 3. How the collaboration unfolded

**Phase A — Measure the phenomenon (Discovery).** The AI's first instinct was to count
real usage, not speculate. It scanned recent worktree session JSONLs for `kb_search`
calls. The detection missed because the JSONL schema uses `type: "toolCall"` with a
`name` field — the AI noticed the zero-result was suspicious, *opened the raw structure*,
and rescanned correctly. Result: **~1/20 organic uses** (and one of those was literally a
manual "is kb_search working?" test). *Why it worked:* it treated a null result as a
possible instrumentation bug, not as the answer.

**Phase B — Split behavioral vs technical cause.** It found the primary **behavioral**
cause: 18/20 worktree sessions open with `/skill:openspec-apply-change`, whose SKILL.md
has zero `kb_search`/`docs-first` references — tasks.md names the files, so no "where is
X" question ever trips the AGENTS.md Docs-First gate. It confirmed `kb_search` **is**
registered in worktrees (a session did call it), ruling out an availability bug.

**Phase C — "dig deeper" → the real defect (steering #1).** Pushed past the behavioral
answer, the AI dug into `kb index` internals. It discovered schema-on-open: `new
DatabaseSync(dbPath)` runs `CREATE TABLE IF NOT EXISTS` immediately, so a **56K empty DB
is written before any file is scanned**. It ruled out the `**/.worktrees/**` exclude glob
by reading the matcher (matches *relative* paths, line 83) and testing it. Then the
**decisive empirical reproduction**: an orphan worktree is missing its tracked source
dirs → `walk()` → `readdirSync('docs')` throws ENOENT → `process.exit(1)` — *after* the
husk is already on disk. Non-idempotent indexing, proven.

**Phase D — Capture as OpenSpec (steering "1").** Before scaffolding, the AI ran the
project's **pre-scaffold coherence check**: it inspected the two adjacent in-flight
changes (`friendlier-worktree-init` = UI feedback only; `add-automatic-session-kb-index` =
session ingestion) and confirmed neither overlapped. It read the `worktree-init-hook` and
`markdown-knowledge-base` capability specs to write correct deltas, then created
`harden-kb-index-failure-atomicity` (atomic-on-failure rename/unlink + missing-source
degrades to warning) — `validate --strict` → valid.

**Phase E — Follow-up: the resurrection bug (steering "1" again).** Picking option 1, the
AI traced *which code removes worktrees* (two paths, both wrapping `git worktree remove`,
neither cleans up). The **WAL sidecars** (`index.db-wal` + `-shm`) in orphans were the
smoking gun: a live kb-extension handle recreates `.pi/dashboard/kb/` in the race after
`git worktree remove --force`. Fix needs both a residual-dir sweep *and* a `closeKb()` on
`cwdMissing` before removal. Second change `sweep-worktree-residual-on-remove` scaffolded
and validated.

**Phase F — Commit (steering "commit").** The AI noticed unrelated dirty files
(`groups.json`, `add-session-tags/`) it hadn't created, and per surgical-changes
discipline staged **only its two proposals** (9 files), leaving the rest untouched.
Commit `a008bf1e7`.

## 4. Prompts that worked

- **The goal prompt** — the `openspec-explore` skill wrapper. Its power was the explicit
  guardrail *"think, not implement; you MAY create OpenSpec artifacts."* That single
  constraint kept a 52-minute deep-dive from ever drifting into code edits, while still
  letting it produce durable, validated proposals.
- **"dig deeper"** (steering #1) — the highest-leverage prompt in the session. It took the
  AI from a *satisfying-but-shallow* behavioral answer to a *reproducible technical
  defect*. Bake this in: after any "here's why" answer, ask for the mechanism + a
  reproduction before accepting it.
- **"1" / "1"** — terse direction-picks after the AI presented numbered options. These work
  *because the AI had already laid out a clean menu* — the operator only needed one keystroke.
- **"commit"** — trusted the AI to figure out scope. It worked because the surgical-changes
  discipline was already in the project's AGENTS.md, so the AI self-limited the stage set.

Weak-prompt rewrite: instead of a bare `"1"`, a stronger operator prompt is *"Take option
1, but first pin exactly which code path removes worktrees so the fix lands in the right
place"* — which is precisely what the AI ended up doing anyway.

## 6. Skills, tools & memory created — and why they're effective

No skill was created (correctly — explore mode is a stance, and the *findings* belong in
OpenSpec, not a reusable procedure). Two compact **project memories** were added recording
*why* `kb_search` is rare in worktree sessions (≈18/20 are `openspec-apply-change` runs
whose tasks.md names files → docs-first gate never trips). These are effective because
they pre-empt the exact same "kb_search is broken!" false alarm next time — the answer is
"it's behavioral, not a bug."

The durable artifacts are the **two validated OpenSpec proposals** — they capture the full
root-cause analysis, reproduction, and TDD-first task lists in-repo, ready to hand to
`openspec-apply-change`. That's the right home for a rich, multi-file finding: versioned,
reviewable, and directly actionable, unlike a truncated memory entry.

*If anything should become a skill:* a "diagnose-worktree-kb-husk" note — reproduce `kb
index` in an orphan worktree, look for `index.db` + `-wal` + `-shm`, and read the empty-husk
ordering — but the two proposals already encode this.

## 7. Pitfalls & dead ends

- **Tool-call scan returned 0 falsely.** The first JSONL scan used the wrong schema. *If a
  session scan returns zero, open one raw JSONL and confirm the event shape (`type:"toolCall"`,
  `name`) before concluding.*
- **The exclude-glob red herring.** `**/.worktrees/**` *looks* like it would break worktree
  indexing, but the matcher runs on relative paths so it doesn't match. *Read the matcher and
  test empirically — don't accept the plausible glob theory.*
- **56K dirs were transient.** Early counts of ~115 orphan `.worktrees/*` dirs mixed already-
  removed transients with live worktrees. *Separate `git worktree list` (live) from physical
  `.worktrees/*` dirs (may be orphans) before drawing conclusions.*
- **Project memory full (4949/5000).** *Don't evict existing entries to record a finding that
  already lives durably in-repo — leave memory as-is.*
- **Shared dirty working tree.** `groups.json` + `add-session-tags/` were another session's
  work. *Stage by explicit path; never `git add -A` in a shared worktree.*
- **One bash command failed** (probing a removed orphan's `index.db` that no longer existed) —
  harmless, the investigation had already moved to live worktrees.
