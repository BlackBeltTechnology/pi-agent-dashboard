## 1. Goal (the ask)

The operator opened in **openspec-explore** mode — a thinking stance, not an
implementation one — to redesign how the worktree "Initialize" action surfaces its
execution in the dashboard UI. The first prompt was the explore-mode skill preamble
("Enter explore mode. Think deeply. Visualize freely."), so the *real* objective only
crystallized through steering: **the folder/worktree row dumps a raw wall of
`<pre>` terminal output inline when you click Initialize, which damages the card
layout — replace it with friendly, opt-in progress feedback that also survives a page
refresh and covers the silent auto-init-on-spawn path.** The deliverable is not code
but a validated OpenSpec change (`friendlier-worktree-init`) with proposal, design,
spec deltas, and an interactive HTML mockup — captured thinking, ready to build later.

## 2. TL;DR playbook

1. **Open explore mode** (`openspec-explore`) so the AI investigates and captures a
   proposal but never implements. State up front you want a mockup + OpenSpec change.
2. **Let the AI map the problem family first.** It found three components sharing the
   same anti-pattern (WorktreeInitButton, BashOutputCard, ToolCallStep all dump raw
   `<pre>`). Confirm which one is biting you to tighten scope fast.
3. **Ask for a real-token HTML mockup** served over `serve_mockup`, rendered with the
   actual dark-theme CSS variables, showing every state (idle/running/failed).
4. **Pick a direction by number** (it offered A/B/C) — but push it to trace the
   *plumbing* behind your choice before committing. Here "does the toast survive a
   refresh?" exposed that progress is keyed by an ephemeral client `requestId`.
5. **Force the state-key reframe:** everything (manual click · auto-on-spawn ·
   refresh) must funnel into ONE **cwd-keyed server registry**. That single insight
   makes all the surfaces cheap views of the same source.
6. **Have it trace the auto-init-on-spawn path** — it was 100% silent (mints a
   requestId then discards it), a real gap worth folding into the same proposal.
7. **Make the mockup part of the proposal** (copy into the change dir, add a
   `## Mockups` section), then `openspec validate` until clean.
8. **Feed it a sibling session id** for related findings, fold them in, `git add` only
   your change dir, commit (amend to keep it one clean commit).

## 3. How the collaboration unfolded

**Phase 1 · Discovery (kb_search + reads).** In explore mode the AI grepped
`packages/` (not stale `src/`), read `WorktreeInitButton.tsx`, `BashOutputCard`,
`ToolCallStep`, and the theme CSS. It reframed the ask as a *family* of three
components that all "run something → dump raw command + stdout into an inline `<pre>`."
Why it worked: mapping the pattern before sketching let the operator narrow to the one
surface (worktree row) that actually mattered.

**Phase 2 · Design mockups (serve_mockup + browser).** It built real HTML with the
project's dark-theme tokens, served it on `localhost:56878`, screenshotted to verify,
and offered three directions in a trade-off table: **A** (status chip + ghost preview +
collapsed `<details>` log), **B** (minimal pill), **C** (corner toast). The design move
that kills the wall: **terminal output becomes opt-in (collapsed), default is one
friendly status line + last-log-line ghost preview.**

**Phase 3 · Plumbing trace (the crux).** The operator picked C and asked the decisive
question: *does the toast reappear after a page refresh?* The AI traced the progress
channel and found it keyed by a **client-minted `requestId`** (`winit-${Date.now()}`) —
on refresh the page forgets it, the ws closes, the server drops the subscription, the
process streams into the void, worst case a double-run. Conclusion: **key on `cwd`
instead** so the run survives refresh. This was the highest-leverage moment of the
session.

**Phase 4 · The silent-spawn gap.** Steered to check the spawn path, the AI traced
`maybeAutoInitWorktreeOnSpawn` → it mints a requestId, discards it, runs the hook, and
**nobody subscribes** → a failed auto-init is silently broken. Two placements emerged:
**D1** sub-state inside the nascent session card (⭐ — no card damage), **D2** reuse of
C's toast. Both are just views of the same cwd-keyed registry.

**Phase 5 · Capture as OpenSpec.** It ran the project's pre-scaffold coherence check
(no collision with active/archived changes), matched a recent archived change's artifact
format, then scaffolded `friendlier-worktree-init/` (proposal, design, tasks, three spec
deltas) and preserved the mockup in the change dir. `openspec validate` → clean.

**Phase 6 · Fold in a sibling + commit.** The operator handed over session id
`019f5a97`, which had diagnosed a *fully-initialized* checkout where the button still
showed — root-caused to **trust invalidation** (hook edited → `hookDefHash` mismatch in
`worktree-init-trust.json`), a distinct reason from "assets missing." The AI folded the
`needsInit` vs `trusted` distinction into the artifacts, staged **only** its own change
dir, and committed (amending to keep one clean commit `45c763016`). It flagged that a
separate untracked `distinguish-initialize-actions/` likely overlapped, then verified
the two are **complementary halves** (disjoint requirement blocks) — no conflict.

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was persisted this session — it was a planning/exploration run.
The reusable asset produced is the **OpenSpec change `friendlier-worktree-init`**
itself (self-contained: written spec + pixel mockup in one dir), plus the coordination
note that it pairs cleanly with `distinguish-initialize-actions`.

**Skill worth creating** from this pattern: a *"refresh-safe progress UI"* checklist —
whenever a click triggers a long server task whose feedback must survive reload, key the
run registry on a **stable identity (cwd / resource id), never a client-minted id**, and
expose it via a `GET active-<task>s` endpoint + a resource-addressable progress channel.
That single rule is what made every surface (button · spawn · refresh · concurrent
stack) fall out cheaply here.

## 7. Pitfalls & dead ends

- **`edit` with `oldText2` is not a valid field.** Two attempts used a phantom second
  `oldText2` and only the first replacement applied — the AI had to redo them as
  separate real edits. Use one `edit` call with multiple entries in `edits[]`, or
  separate calls; never invent `oldText2`.
- **`ctx_execute_file` is sandboxed to the project root** — it errored trying to mine a
  session JSONL under `~/.pi`. Fall back to plain `Bash`/`node -e` to read files
  outside the repo.
- **A stray spec-delta dir** (`specs/worktree-init/`) was created then `rmdir`'d — the
  base capability is `worktree-init-hook`, not `worktree-init`. Check the real base
  capability name (`grep '^### Requirement:' openspec/specs/<cap>/spec.md`) before
  scaffolding a MOD delta.
- **Don't blanket `git add .`** — the tree had four unrelated untracked change dirs and
  a modified `groups.json`. Stage only your change dir (`git add
  openspec/changes/friendlier-worktree-init/`).
