## 1. Goal (the ask)

The session opened in **explore mode** (the `openspec-explore` skill prompt), with a
terse follow-on intent: *"enable TOFU `-s` for external directory support, as in
other agent tools, for session / project bases."*

Decoded, the real objective: today the worktree-init hook uses **Trust-On-First-Use**
that is *permanent and global* — the first "Run" confirmation writes `repoRoot + hash`
to `~/.pi/dashboard/worktree-init-trust.json` **forever**. The user wanted to add a
**scope dimension** — a *session-scoped* (ephemeral) trust option alongside the
existing *project* (persistent) one, matching what Claude Code / Cursor / pi offer,
and covering external non-git directories. The deliverable was **not code** — it was a
fully planned, doubt-reviewed OpenSpec change committed to `develop`, stopping at the
worktree boundary.

## 3. How the collaboration unfolded

**Discovery (ground the terse ask).** The AI loaded `plan-proposal`, `kb_search`'d
"TOFU," then grep'd `packages/server/src` for `isTrusted`/`recordTrust`/`trustStore`
and read the trust store itself. This is the effective bit: instead of trusting the
one-line ask, it established that trust today is *permanent + global, keyed by
`repoRoot + hash`, no scope choice at all.* It rendered the current flow as an ASCII
diagram before proposing anything.

**Clarify (5 `ask_user` questions, verified).** The AI asked scope-shaping questions
(lifetime, where the choice surfaces, non-git inclusion). Crucially it *did not take
the answers at face value* — answer #3 ("session that requested it") triggered a code
check of the init route.

**The pivotal decision point.** The AI verified `POST /api/git/worktree/init` carries
`{ cwd, requestId, confirmHash }` — **no `sessionId`** — and is called by
`WorktreeInitButton` (a human browser click). So "the pi session that requested it"
had *no referent* on the manual path. It then checked the browser gateway and found
**no stable client identity** (raw `ws` sockets, constant reconnects). It laid out
three bindings — **A** browser client (churns on reconnect), **B** server process
(ephemeral, survives reconnect), **C** pi session id (breaks for external dirs). The
human chose **B**, with honest UI labels.

**Generate.** Coherence sweep ran clean (delta on existing `worktree-init-hook` spec;
prior art `generalize-worktree-init-hook` + `support-non-git-init-hook`). The AI
scaffolded the change and wrote proposal.md, design.md, the MODIFIED spec delta, then
validated (3/4).

**Verify (doubt-driven, cross-model).** It ran the doubt cycle: a first adversarial
`Explore` reviewer produced 10 findings; a second **cross-model** reviewer
(`@propose-review-1` = glm-5.2) *converged* on the top ones. The load-bearing flaw
both caught: a malformed `scope` value silently coercing **upward** to permanent
project trust — an RCE-class escalation against ephemeral intent. Fix: omitted→project
(back-compat), present-but-unrecognized→**reject** `bad_request`.

**Fold + commit.** `scenario-design` mapped scenarios to existing test exemplars (L1

boundary.

## 4. Prompts that worked

- **The goal prompt** (`openspec-explore` + the one-liner). It worked *because the AI
  refused to treat it as complete* — it grounded "TOFU" in code first. A stronger
  kickoff would name the concrete files up front: *"Plan a session-scoped trust option
  for the worktree-init hook (`worktree-init-trust.ts`), matching Cursor/Claude Code
  scope choices; external non-git dirs included."*
- **The high-leverage follow-up: `"B"`** — a single character. It resolved the entire
  design because the AI had already done the work of laying out A/B/C bindings with
  their exact trade-offs. Lesson: *make the AI enumerate grounded options so a
  one-token answer can lock the architecture.*

## 7. Pitfalls & dead ends

- **"Session-scoped" is ambiguous — resolve the referent first.** Don't assume it means
  a pi session id. Check whether the triggering path even *carries* a session id
  (`POST /worktree/init` did not).
- **Browser client identity is not stable** here — raw `ws` sockets churn on every
  reconnect. Binding trust lifetime to a browser client (option A) would silently drop
  grants; only paired-device ids survive, and that's heavy.
- **Upward scope coercion = RCE-class hole.** A malformed `scope` defaulting to
  permanent project trust escalates durability against user intent. Reject unrecognized
  values; only *omitted* may fall back to project for back-compat.
- **Memory at capacity (4949/5000).** Don't disrupt existing entries for a fact already
  in a committed artifact — skip the write.
