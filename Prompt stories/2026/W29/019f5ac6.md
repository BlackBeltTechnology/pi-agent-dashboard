# How we did it: A Codex-style change-summary table — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The operator opened in **explore mode** — a thinking-partner stance, no code — and
pointed at a real pain: *file edits get lost in the chat stream*. A pi session fires
many Edit/Write tool calls across many turns; each renders as a collapsed card. There
was no glanceable answer to **"what did this session change?"** The target was the
Codex-style summary block: `N files changed · +adds −removes`, one row per file with a
click-to-open link. The real objective, once steering clarified it, was an **OpenSpec
change proposal** (proposal + mockups + specs + design + tasks) for a *deterministic,
no-LLM* change-summary surface, integrated into the dashboard's existing split editor
pane — not a fresh takeover view.

## 2. TL;DR playbook

1. **Open in explore mode** (`openspec-explore` skill) — investigate before designing;
   never write code in this stance.
2. **Run the docs-first coherence sweep**: `kb_search` + `grep` for the existing
   session-diff plumbing (`session-diff.ts`, `parseShortstat`, `worktreeDiffStat`,
   `DiffFileTree`, the client turn model). Confirm ~80% of the machinery already exists.
3. **Separate deterministic vs LLM** early: the numbers/status/links are computed from
   the patch; only the prose summary would need a model. Ask which the operator wants —
   here the answer was *no LLM*, which collapsed the whole design to deterministic.
4. **Scaffold the change** with `npx openspec new change <name>` after a name-collision
   check against active + archive.
5. **Build HTML mockups** using the real dashboard dark-theme tokens (copy from a sibling
   change's `mockups/_tokens.css`); serve with `serve_mockup`; verify in the browser tool
   (Playwright headless was not installed).
6. **Fold each steering answer** into proposal + spec + mockup immediately (integrate vs
   takeover, fallback route, expanded default, non-git handling).
7. **Continue artifacts** with the OpenSpec workflow → `design.md` (D1–D7 decisions) +
   `tasks.md` (dependency-ordered checkboxes); validate `--strict`.
8. **Run doubt-driven review** before the design stands: extract ARTIFACT+CONTRACT only,
   spawn a fresh-context adversarial reviewer, then a **cross-model** second opinion on a
   different architecture family. Reconcile findings against the source yourself.
9. **Commit surgically** — only this change's files, leaving unrelated working-tree
   changes untouched.

## 3. How the collaboration unfolded

**Phase 1 — Discovery (explore mode).** The AI ran the project's docs-first protocol:
`kb_search`/`kb_get` on the Session File Diff View section, then a wide `grep` sweep of
`packages/shared`, `packages/server`, `packages/client` for diff types, `parseShortstat`,
`worktreeDiffStat`, `DiffFileTree`, and the client turn model. Finding: most plumbing
already exists; line stats just aren't surfaced. *Why it worked:* mapping existing
infrastructure first prevented a from-scratch design and grounded every later claim in
real file names.

**Phase 2 — Reframe (deterministic vs LLM).** The operator corrected the mechanism:
"In codex it is made by an LLM turnaround." The AI split Codex's block into (a)
deterministic counts/status/links and (b) LLM prose — then the operator ruled out the
LLM, collapsing the design to fully deterministic. *Decision point:* per-turn inline
block (client-side, grouped by `turnIndex`) **plus** a running roll-up (`git diff
--numstat` net vs HEAD).

**Phase 3 — Proposal + mockups.** `npx openspec new change add-change-summary-table`
after a collision check (distinct from the archived `session-file-diff-view` takeover
viewer). Wrote `proposal.md`, spec deltas, and `mockups/{index,states}.html` using real
theme tokens; served and browser-verified.

**Phase 4 — Split-target investigation.** The operator asked whether "Changed Files"
could migrate into the existing ChatView split pane. The AI found the `live-server`
virtual-tab precedent (`live:<url>`, `viewerRegistry` as a clean `Record<ViewerKind,
Component>`) and confirmed the merge insight: the tree rail's summary header *becomes*
the roll-up. Added `split.html`; reshaped the proposal.

**Phase 5 — Lock decisions + full artifacts.** Four terse answers (`1. integrate / 2.
keep as fallback / 3. expanded / 4. shown`) were baked into a Resolved Decisions table,
then `design.md` (D1–D7) + `tasks.md` (8 groups, 27 checkboxes) via the OpenSpec continue
workflow; `openspec validate --strict` → valid.

**Phase 6 — Doubt-driven review + commit.** Before the design stood, the AI ran the
`doubt-driven-review` skill: named a CLAIM, extracted ARTIFACT+CONTRACT (no CLAIM
leaked), spawned a fresh-context Explore reviewer (13 findings, several CRITICAL),
spot-verified each against source, then offered and ran a **cross-model** review
(probed gpt-5.2/gemini — empty; deepseek-v4-pro reachable, different architecture).
Two architectures independently reproduced all four CRITICALs → seven real spec gaps
fixed. Committed only this change's 10 files.

## 4. Prompts that worked

- **Goal prompt (explore mode):** launching via `openspec-explore` set the right stance —
  investigate and capture thinking, never implement. A stronger kickoff states the target
  artifact up front: *"Explore a Codex-style change-summary table; end with an OpenSpec
  proposal + mockups, no code."*
- **High-leverage reframe:** *"In codex it is made by an LLM turnaround"* — one sentence
  that corrected the mechanism and forced the deterministic-vs-LLM split.
- **High-leverage unlock:** *"1. integrate / 2. keep as fallback / 3. expanded / 4.
  shown"* — four-token answers to the AI's Open Decisions list, each folded straight into
  artifacts. Terse enumerated answers to an explicit decision list move work fast.
- **The scope-expander:** *"There are Split view in ChatView… Is it possible to migrate
  Changed Files as a Split target?… Investigate and make more mockups"* — turned a
  standalone table into a merged, better-integrated design.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Assume the summary counts come from the model (Codex-style) | "In codex it is made by an LLM turnaround" then ruling out the LLM | State *deterministic, no-LLM* as a hard constraint in the goal prompt |

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was created, but the session is a clean exemplar of chaining
**existing** skills — worth codifying as the standard flow:

- **`openspec-explore`** — enforces the think-don't-implement stance; keeps discovery
  honest before any artifact exists.
- **`openspec-new-change` / continue workflow** — scaffolds proposal → mockups → specs →
  design → tasks with strict validation gates.
- **`doubt-driven-review`** — the high-value move here. It extracts ARTIFACT+CONTRACT with
  no CLAIM leaked, runs a fresh-context adversarial reviewer, then a **cross-model** second
  opinion on a *different architecture family* (probe reachability first — role aliases and
  unreachable ids return empty). Cross-architecture convergence = high confidence the
  findings are real, not single-model noise. It caught four CRITICALs (tab-path collision,
  missing diff data on `ViewerProps`, `turnIndex` only on user messages, `VALID_VIEWERS`
  omitting `diff`) that the compiler could never surface.
- **`serve_mockup` + browser tool** — browser-verify rendering when Playwright headless is
  absent; copy real theme tokens from a sibling change so mockups match the live dashboard.

*Recommended memory to save:* `serve_mockup` binds a **fresh ephemeral port on each
restart** — a dead preview shows as `ECONNREFUSED` on the old port; restart and use the
new URL.

## 7. Pitfalls & dead ends

- **Playwright headless not installed** → `score_mockup`/screenshot capture fails. Fall
  back to the `browser` tool to open and visually verify mockups.
- **Mockup server died mid-review** → proxy returns `500 … ECONNREFUSED 127.0.0.1:51873`.
  `serve_mockup` picks a *new* ephemeral port on restart; the old URL is permanently dead.
- **One atomic edit failed** (wrong glyph in `oldText`) → nothing applied. Re-read the
  exact source text and redo; edits are all-or-nothing.
- **Trusting an adversarial reviewer blindly** → several findings were partial misreads
  (a non-existent "aggregated tab"; a field the design *did* add). RECONCILE means
  verifying each CRITICAL against the source yourself before folding it in.
- **Name collision risk** → check active **and** archive dirs before scaffolding; this
  change was distinct from the archived `session-file-diff-view` takeover viewer.
