## 1. Goal (the ask)

The session opened in **explore mode** — a thinking-partner stance, not an implementation
run. The real objective emerged across the six prompts: turn a vague product itch ("the
open session's card is buried behind collapsed containers in the sidebar; I want a button
that reveals it") into a **fully-planned, validated, committed OpenSpec change** —
proposal, design, spec, tasks, a test-plan manifest, and a live interactive mockup —
without writing a line of production code. The finished artifact set is
`openspec/changes/add-seek-to-session-card/`, committed to `develop` at the git-worktree
boundary, ready for implementation.

## 2. TL;DR playbook

1. **Enter explore mode** (`/skill:openspec-explore`) and state the itch. Tell the AI to
   *ground in real code before theorizing* — it will map the actual client tree
   (`packages/client/src/components/`), not its guess.
2. **Say "trace it and make mockup."** The AI traces the ancestor-resolution path
   (session id → cwd → folder/workspace/ended containers) and builds a live HTML mockup
   in `/tmp` served on a local port, proving the expand→select→rAF→scroll gesture.
3. **Say "capture and move the mock to proposal."** It scaffolds the OpenSpec change by
   mirroring an existing change's directory layout (there is **no** `openspec change new`
   subcommand), moves the mockup into `mockups/`, and validates.
4. **Say "clarify."** The AI surfaces the genuinely-open questions (mobile behavior,
   filtered-out toast) grounded in how the sidebar actually behaves, and folds your
   decisions back into every artifact.
5. **Run `/skill:plan-proposal`.** It runs the doubt-driven-review cycle: a fresh-context
   `Explore` reviewer, then a **mandatory cross-model** reviewer on a non-Claude
   architecture (`@propose-review-1` glm, `@propose-review-2` deepseek).
6. **Let the cross-model reviews rewrite the design.** They caught real errors
   (wrong button-home file, wrong DOM-presence predicate, a heartbeat-timeout premise
   that was actually unsound). Reconcile by precedence, re-validate.
7. **Say "commit."** Commit only the change directory; leave unrelated dirty files alone.
   Stop at the worktree boundary — planning does not enter implementation.

## 3. How the collaboration unfolded

**Phase 1 — Discovery / grounding.** The AI resisted theorizing and instead read the
real client tree. It found the primitive *already existed*: `SessionList.tsx` had a
first-mount auto-scroll and a `FolderNeedsYouPill.onActivate` handler doing exactly
expand→select→rAF→scroll. The feature reduced to *exposing that same move from the
header*. **Why it worked:** "ground before theorizing" turned a green-field feature into
a small, de-risked wiring job.

**Phase 2 — Trace.** On "trace it and make mockup," the AI mapped the full ancestor chain
and discovered everything derives from `session.cwd` + `session.status` — no graph walk.
The one real subtlety: three collapse stores, and the **workspace tier is async server
state** (waits for a `workspaces_updated` echo), which mandates a *retry-until-present*
reveal loop. It captured this in a live mockup on a local port and screenshotted the
before/after reveal.

**Phase 3 — Scaffold.** On "capture and move the mock to proposal," it mirrored an
existing change's structure (no `change new` CLI), wrote proposal/design/spec/tasks, moved
the mockup in, and iterated on `openspec validate` until green.

**Phase 4 — Clarify.** On "clarify," it grounded the mobile question in the actual
`MobileOverlay`/`mobileOpen` behavior, presented two open questions, took the human's
decisions (desktop-only v1, informational toast), and folded them into all artifacts.

**Phase 5 — Plan-proposal doubt cycles.** Two cross-model adversarial reviews materially
rewrote the design (see §5). **Decision point:** after the gate answers introduced new
design surface (heartbeat-derived timeout), the AI ran a *targeted* second doubt pass
rather than auto-grinding — and deepseek disproved the heartbeat premise outright.

**Phase 6 — Commit at the boundary.** It committed only the change directory, spotted
three unrelated dirty files, confirmed scope before touching them, and stopped without
entering implementation.

## 4. Prompts that worked

- **Goal prompt — `/skill:openspec-explore` + the itch.** Effective because the explore
  stance forbids implementation, forcing the AI into a thinking-partner mode that grounds
  in real code and produces *artifacts, not diffs*.
- **"trace it and make mockup"** — a two-verb high-leverage prompt. "Trace" forced the
  ancestor-resolution proof; "make mockup" forced an executable demonstration of the
  gesture before any spec ink was spent.
- **"capture and move the mock to proposal"** — converts exploration into durable OpenSpec
  artifacts in one move.
- **"clarify"** — a one-word unlock that made the AI surface *its own* open questions
  instead of silently guessing.
- **`/skill:plan-proposal`** — hands the whole doubt-review + scenario-design + fold
  orchestration to a skill instead of driving it by hand.

Weak-prompt rewrite: instead of "clarify," a stronger form is *"list the open design
questions you're guessing on, grounded in the real code, and stop for my call."*

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Guess file paths / theorize before reading | explore stance + "ground in code first" | Open with "map the real tree before proposing" |
| Jump toward implementing | staying in explore mode | Use `openspec-explore`; it hard-blocks code writes |
| Silently pick a direction on open questions | "clarify" | Ask it to enumerate open questions and stop |
| Accept its own plan | `plan-proposal` → mandatory cross-model doubt review | Always run a non-Claude cross-model reviewer |
| Commit everything dirty | "confirm scope" (surgical-changes) | Commit only the change dir; leave unrelated files |

The doubt reviews were **not theater** — they landed load-bearing corrections:
**Cycle 1 (Explore + glm-5.2):** button home is `SessionHeader`, not ChatView; `showHidden`
is local `useState` not server-persisted; collapse toggles need an `if(collapsed)` guard
or a second seek re-collapses; DOM-presence predicate must be
`getBoundingClientRect().height > 0` (collapsed folders use `grid-rows:0fr;opacity:0`, so
`offsetParent` stays non-null).
**Cycle 2 (deepseek, targeted):** *disproved* the heartbeat-derived timeout — `watchdog.intervalMs`
is the **tunnel** watchdog not browser-WS, there is **no** server→browser RTT message, and
`K × interval` collapses to a runtime constant (zero real adaptivity). Reverted to
**event-primary (`workspaces_updated`) + a fixed 5s backstop**, and hardened the Retry toast
to suppress auto-dismiss.

## 6. Skills, tools & memory created — and why they're effective

No new skills or memories were created — the session *consumed* existing project skills:

- **`openspec-explore`** — the stance that keeps the AI in thinking mode and produces
  OpenSpec artifacts instead of premature code. Invoke it for any "should we build X?"
  feasibility question.
- **`plan-proposal`** — orchestrates the whole planning phase (doubt-review →
  scenario-design → category-fold → commit at the worktree boundary). Invoke it once
  artifacts are drafted and you want them stress-tested and landed on `develop`.
- **`doubt-driven-review`** (invoked by plan-proposal) — its *mandatory cross-model* rule
  is the effective bit: a non-Claude reviewer (glm, deepseek) with repo access caught
  errors the author model was blind to. The `@propose-review-N` role series picks
  cross-architecture reviewers deterministically.
- **`serve_mockup` / `score_mockup` / `browser`** — build and screenshot a live HTML
  reveal demo, turning "trust me it works" into a verifiable gesture before spec ink.

If anything, this session argues for a small skill capturing "**mirror an existing change
dir to scaffold a new OpenSpec change**" (since there is no `change new` CLI).

## 7. Pitfalls & dead ends

- **No `openspec change new` subcommand.** Don't reach for it — copy an existing change's
  directory structure instead.
- **Playwright headless shell wasn't installed.** The AI fell back to the `browser` tool
  to capture the mockup. If `serve_mockup` screenshots fail, use `browser`.
- **`openspec validate` SHALL-on-first-physical-line rule.** The validator checks the
  *first physical line* of a requirement for `SHALL`; a hard-wrap that pushes `SHALL` to
  line 2, or backticks/parentheticals in the lead sentence, trips the parser. Keep the
  requirement's opening line simple with `SHALL` up front.
- **The one `edit` error** in the run was a single retried edit — expect the occasional
  miss on multi-artifact rewrites; re-read and retry.
- **Don't couple a UI timeout to unrelated config.** The heartbeat-derived-timeout idea
  looked adaptive but reduced to a constant — prefer an event-primary design with a fixed
  backstop.
