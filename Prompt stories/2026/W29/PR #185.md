# How we did it: Unblocking & upgrading a contributor PR (models_list filter) — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (a thinking-only stance, no implementing) — the
literal first prompt was the `openspec-explore` skill preamble, not a concrete task. The
*real* objective surfaced immediately once the operator pointed the AI at **PR #185**
(`feat(extension): filter models_list by enabledModels from pi settings`, from a fork,
against `develop`): find out **why the PR won't merge and fix it — on the original PR
branch, not a fresh one.** The two steering turns pinned it down: (1) *"check the code,
what part is fixed — maybe the current mechanics already fix this"* and (2) *"keep the
original PR and do the fix there."* So: verify the PR's premise is still valid, clear its
merge conflicts, and land the fix back on the contributor's branch.

## 2. TL;DR playbook

1. **Triage the PR machine-readably:** `gh pr view 185 --json number,title,state,mergeable,mergeStateStatus,reviewDecision,statusCheckRollup`. Read `mergeable: CONFLICTING` / `mergeStateStatus: DIRTY` as *needs rebase*, not *broken logic*.
2. **Falsify the "already fixed" hypothesis first.** Grep `develop` for the anchor pattern (`getAvailable().map(toModelInfo)`) and trace whether pi core's registry honors `enabledModels` on its own. It does not — the gap is real and still open.
3. **Isolate in a worktree** so the dirty main checkout (uncommitted docs) is untouched: `git worktree add .worktrees/pr185-filter-models`. For a fork PR, fetch `pull/185/head` into a temp branch first.
4. **Rebase onto `develop`; resolve conflicts as *divergence*.** The anchor pattern still existed verbatim at every call site — keep develop's reorganized import block and just add the one new import (`filterByEnabledModels`). No competing logic to reconcile.
5. **Find the canonical implementation before hand-rolling.** pi core's `resolveModelScope` uses `minimatch` (nocase) against both `provider/id` and bare `id`, stripping an optional `:thinkingLevel` suffix. Mirror it exactly.
6. **Reuse the standalone lib, don't reimplement a glob engine.** Add `minimatch` as a real extension dependency (it's a standalone lib pi already uses — no pi-core coupling). Import version-agnostically (`import * as`) to survive v3-default vs v10-named export.
7. **Test in isolation** with `homedir()` pointed at a temp dir; run via `npm test` (it sets an ephemeral HOME). Verify with the **root** `tsc --noEmit` and `biome check` (the per-package tsc is not the real gate).
8. **Force-push-with-lease** back to the fork (`maintainerCanModify: true`), confirm `mergeable: MERGEABLE`, then remove the worktree and confirm the root repo is untouched.

## 3. How the collaboration unfolded

**Phase 1 — Triage (what's actually wrong).** The AI ran `gh pr view … --json` and read the
status flags rather than eyeballing the diff: `CONFLICTING` + `DIRTY` = merge conflicts,
CodeRabbit green, no approval yet. It correctly reported the blocker as *needs rebase* and
asked whether to pull and resolve. **Why it worked:** machine-readable PR state turns a
vague "won't merge" into a precise, actionable cause in one call.

**Phase 2 — Falsify the redundancy hypothesis (the key decision point).** The operator's
steering — *"maybe the current mechanics already fix this"* — sent the AI to *disprove the
PR's own premise* before touching anything. It grepped all five `getAvailable().map(toModelInfo)`
sites on `develop` (still unfiltered), then traced pi core: `getAvailable()` returns *all*
authenticated models; `getEnabledModels()` exists in `settings-manager` but nothing in the
registry path consults it. Verdict: the gap is real, the PR is *not* redundant, and the
conflict is *pure divergence* (line numbers moved as files grew) — a rebase resolves cleanly.
**Why it worked:** treating a plausible "this might be unnecessary" as a hypothesis to
*kill with evidence* prevented both a wasted rebase and a wrongful close.

**Phase 3 — Isolate & rebase.** Main was dirty with docs work, so the AI built a dedicated
worktree, fetched the fork PR head, rebased onto `develop`, and resolved the two import-block
conflicts by *keeping develop's structure* and adding only the new symbol. It then verified
all six call sites stayed wrapped and no conflict markers survived.

**Phase 4 — Upgrade the filter (the correctness fix).** The AI noticed the PR's matcher only
handled exact refs + `provider/*`, so a realistic glob like `anthropic/claude-*` or
`*sonnet*` would filter out **every** model. It read pi core's `resolveModelScope`, chose to
**reuse `minimatch`** (rejecting a hand-rolled glob engine as fragile and over-complex), added
it as a declared dependency (the extension ships raw `src/` via jiti, so runtime deps must be
declared), and mirrored pi's semantics.

**Phase 5 — Verify & land.** New isolated test (temp-dir `homedir()`, 14 cases), fixed a TDZ
import-time bug (`let`→`var` with fallback) and a version-export mismatch (namespace import),
ran the root `tsc --noEmit` + `biome check` (discovering the per-package tsc is *not* the
gate), re-ran the existing session-sync suite (27 tests pass), committed, force-pushed with
lease to the fork, and confirmed `MERGEABLE`. Cleaned up the worktree; root repo untouched.

## 4. Prompts that worked

- **The goal prompt (implicit).** Pointing the AI at a PR number with the intent "why won't
  this merge?" is a strong kickoff — it has a precise, machine-inspectable target. A stronger
  explicit version: *"PR #185 won't merge. Diagnose why, and if the fix is still needed,
  clear the conflicts and land it on the original branch — don't open a new PR."*
- **"Check the code — maybe the current mechanics already fix this."** High-leverage: it
  forced an *evidence-first falsification* of the PR's premise instead of blindly rebasing.
  Reusable pattern: *"Before fixing, prove the fix is still necessary against `develop`."*
- **"Keep the original PR and do the fix there."** A one-line scope lock that set the entire
  delivery strategy (rebase + force-push to fork, not a new branch). Stating the *landing
  target* up front avoids the AI defaulting to a fresh PR.

## 6. Skills, tools & memory created — and why they're effective

No skill or memory was created this session (hence `premium: false`). But the workflow is
clearly repeatable and a skill **should** exist:

- **Recommended skill: "unblock-and-land-a-contributor-PR."** Captures: `gh pr view --json`
  triage → falsify-the-premise grep pass → worktree-isolated rebase (keep base's import
  structure, add only new symbols) → force-push-with-lease to a fork (`maintainerCanModify`)
  → confirm `MERGEABLE` → remove worktree. It removes the repeated manual reasoning about
  *conflict-as-divergence-vs-competing-logic* and the fork-push mechanics, and makes the
  "prove the fix is still needed" gate a standard step rather than an ad-hoc steer.

## 7. Pitfalls & dead ends

- **`npm install` in the wrong checkout.** Editing `package.json` in the worktree but running
  install in the root leaves the worktree with no `node_modules` and an unchanged lockfile.
  → Run install *inside the worktree* (`cd .worktrees/<name> && npm install`).
- **`minimatch` export shape varies by major.** Root had v3 (CJS default export); pi ships v10
  nested (ESM named export). A plain default or named import breaks on one of them.
  → Use `import * as mm from 'minimatch'` and resolve `mm.minimatch ?? mm.default ?? mm`.
- **TDZ at import time in the test.** A mocked `homedir()` is invoked while modules load
  (provider-register computes a path) — before the test assigns `HOME`. A `let` binding throws.
  → Use `var` with a fallback so import-time calls are safe.
- **Per-package `tsc --noEmit` is not the gate.** It surfaces pre-existing `rootDir` noise from
  doctor tests that ship today. → The canonical typecheck is **root** `tsc --noEmit`; filter
  its output to your files.
- **Biome `noVar` at CI's `--error-on-warnings`.** After deliberately using `var` for the TDZ
  fix, confirm it doesn't trip an error-level rule. (It didn't — the test file was 0/0.)
