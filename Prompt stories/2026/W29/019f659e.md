# How we did it: Root-cause a dashboard diff bug in explore mode, then enrich (not duplicate) an in-flight OpenSpec change — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) with a thinking-only stance:
investigate why "diff links in the content view" render **"No changes for this file"**
in the pi-agent-dashboard, *without* implementing anything. The real objective, once
the exploration clarified it: **prove the root cause of the content-view diff bug down
to the data level, decide whether it warranted a new OpenSpec change, and capture the
findings in the right place** — which turned out to be *enriching an already-active
change* rather than scaffolding a duplicate, then running the `plan-proposal`
planning orchestration up to (but not across) the git-worktree boundary.

## 2. TL;DR playbook

1. Enter `openspec-explore` — a thinking stance, not an implement task. Read/search freely; write nothing.
2. **Disambiguate the surface first.** The dashboard has *two* diff surfaces (inline content-view diff vs the `/session/:id/diff` takeover route). Draw them and make the human pick before chasing code.
3. **Reproduce live in the browser** on a *non-streaming* session (streaming auto-scrolls and eats clicks). Use a wide viewport so the split pane stays visible.
4. **Prove the root cause at the data level**, not just from source: compare the path the row hands the sink (`args.path` = absolute) against the `/api/session-diff` key (repo-relative). `data.files.find(f => f.path === relPath)` is an exact string match → miss → blank.
5. **Audit the siblings** for the same abs-vs-rel assumption: enumerate every client-side exact-match sink vs every server endpoint (server endpoints normalize via `path.resolve`+containment, so only *client* sinks break).
6. **Run the pre-scaffold coherence check before creating any change** — it caught that an active change already owned the bug. Enrich its `design.md` with a marked addendum instead of duplicating.
7. Run `plan-proposal`: `doubt-driven-review` (single + cross-model reviewer) → `scenario-design` → fold automated scenarios into `tasks.md` as a new `§6` with a `test-plan.md` manifest → commit → **STOP at the worktree boundary**.
8. When an irreversible step (`ship-it` = squash-merge + worktree removal) would collide with a *live* session in that worktree, **stand down and hand off** — don't barrel through the gate.

## 3. How the collaboration unfolded

**Phase 1 — Disambiguate (Discovery).** The AI immediately mapped *two* distinct diff
surfaces and drew an ASCII diagram, refusing to chase code until the human confirmed
which one. This is the effective move: an ambiguous bug report ("diff links in content
view") gets grounded against the real UI topology before any grep goes deep.

**Phase 2 — Reproduce live.** Using the `browser` skill (18 calls), the AI drove the
running dashboard, found a live `auto-canvas` worktree session with a change-summary
block, clicked a file row, and captured the `diff:/Users/.../canvas-detect.ts`
(absolute) tab settling to "No changes for this file." Key learning baked in: streaming
sessions auto-scroll and make clicks unreliable — reproduce on an idle/desktop-width
session where the split pane persists.

**Phase 3 — Prove at the data level.** Rather than trust the source read, the AI hit
`/api/session-diff` and showed the file is keyed **relative**
(`packages/shared/src/canvas-detect.ts`, renderable) while the row fed the **absolute**
path — `ABSOLUTE !== RELATIVE` → the exact-match `find` misses. Airtight.

**Phase 4 — Audit siblings.** The AI enumerated every path sink and split them by
resolution site: **server** endpoints (`/api/session-file`, `/api/file`) tolerate
absolute via `path.resolve(cwd,p)`+containment; only **client** exact-match sinks
(`DiffViewer`, `FileDiffView`, `editor-pane-state` dedup) break. It found sibling
`openInSplit` callers (`OpenFileButton`, editor deep-link `?file=` → `SplitRouteSync`)
that also feed absolute, plus a duplicate-tab bug (reducer dedups on full path).

**Phase 5 — Capture as enrichment (decision point).** `"capture"` triggered the
pre-scaffold coherence check, which caught that the active change
`fix-session-diff-open-nongit-and-preview` already owned the exact root cause — with a
*live session implementing it*. The AI **stopped** rather than scaffold a duplicate, and
appended a clearly-marked audit addendum to that change's `design.md` (untouched
in-flight sections, so no collision).

**Phase 6 — plan-proposal, doubt-reviewed.** The AI ran `doubt-driven-review`: a
single-model fresh-context reviewer (source-verified) + a cross-model
`@propose-review-1` (glm-5.2) adversarial pass. Both affirmed the thesis but surfaced 5
valid accuracy gaps (Windows cross-drive `isAbsolute` guard, "3 sinks" over-count →
2-breaking + 1-immune, escape-hatch misattribution, in-cwd scope qualifier, `absOf`
side-effect on the watch set). These were folded into `design.md`. Then
`scenario-design` produced a `test-plan.md` manifest (A1–A5, all automated), folded into
`tasks.md` as vanilla-checkbox `§6`. Committed `428284ec5`.

**Phase 7 — Stop at the boundary.** `ship-it` (steering #6) would run *inside* the
worktree and end by squash-merging + removing the worktree + deleting the branch — but a
live session (`019f6190`) was still streaming WIP in that exact worktree. The AI **stood
down**, left the worktree untouched, and handed the operator a two-step drive plan.
Later `commit` turns only committed a `groups.json` regroup on `develop`.

## 4. Prompts that worked

- **The goal prompt (explore mode).** Loading `openspec-explore` set a *thinking, not
  implementing* stance — which is exactly why the AI disambiguated and reproduced instead
  of jumping to a patch. Effective kickoff for a "why is X broken?" investigation.
- **`capture`** — a one-word high-leverage prompt that unlocked the coherence check and
  the "enrich, don't duplicate" decision. Stronger version to reuse:
  *"Capture this as an OpenSpec change, but run the pre-scaffold coherence check first —
  if an active change already owns it, enrich that one instead."*
- **`plan-proposal` / `ship-it`** — loading the skill by name handed the AI a full
  orchestration with its own preconditions and boundary, so it self-detected the
  in-flight-worktree conflict rather than the human having to catch it.
- The numeric steering (`1`, `2`, `2`) were menu-pick answers to the AI's
  disambiguation questions — effective *because the AI offered enumerated choices* rather
  than open-ended ones.

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was created this session. The value came from *composing existing
skills* correctly:

- **`openspec-explore`** kept the AI in a prove-don't-patch stance — the reason the bug
  got a data-level proof instead of a speculative fix.
- **`doubt-driven-review`** (single + cross-model) turned a plausible addendum into a
  *corrected* one — 5 accuracy gaps caught before the artifact stood. Invoke it before any
  irreversible/high-stakes artifact (a design decision steering an in-flight change).
- **`plan-proposal`** + **`ship-it`** encode the git-worktree boundary as a hard stop;
  their preconditions are what caught the two collision hazards.

Recommended memory to save: *"Dashboard path convention — server file endpoints
(`/api/session-file`, `/api/file`) normalize absolute paths via `path.resolve(cwd,p)` +
cwd-containment; client exact-match sinks (`DiffViewer` `f.path===relPath`,
`editor-pane-state` dedup) do NOT — feed them repo-relative session-diff keys."* That
invariant was rediscovered from scratch here and will recur.

## 7. Pitfalls & dead ends

- **Reproducing on a streaming session fails** — it auto-scrolls and clicks miss. Fix:
  use an idle session at desktop width so the split pane persists (the AI burned several
  browser round-trips before switching sessions).
- **Ended sessions have no diff data** — `/api/session-diff` returns empty once changes
  are committed/discarded, so you can't repro on a finished session. Use a live
  bridge session that still carries diff files.
- **`curl /api/health` / `/api/sessions` failed once** (2 failed bash commands) — the
  dashboard endpoints were probed before confirming the server surface; not fatal, just
  noise.
- **Scaffolding a new change would have duplicated an active one** — the pre-scaffold
  coherence check exists precisely to prevent this. Run it *before* `openspec change new`.
- **Running `ship-it` from the main session** would put two agents in one worktree and
  could yank the worktree out from under the live agent. Stand down; hand off.
