# How we did it: Fix "Subagent not found" on inline expand — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The operator opened a subagent card in the dashboard, expanded it, and the expanded
body showed no timeline. First prompt (with a screenshot):

> "Expanded subagent doen not show the chatview history. What is the reason?"

The *real* objective, once the diagnosis landed and the operator said "yes": don't
just explain the bug — **fix it end-to-end** (root-cause → TDD test → implementation →
live deploy → spec update → scoped commit) so the inline "Details" expand hydrates a
running subagent's timeline instead of rendering "Subagent not found in this session."

## 2. TL;DR playbook

1. **Ask for the reason first, not the fix.** Give the symptom + screenshot; let the AI
   trace the two data paths (card header vs expanded timeline) before touching code.
2. **Unlock the fix with one word** ("yes") once the root cause is convincing.
3. **Demand TDD.** The AI wrote the 2 tests first (`AgentToolRenderer.test.tsx`), ran
   them red, then implemented.
4. **Implement minimally:** extract the existing popout-only resync into a shared
   `requestResyncIfStale()` helper and call it from the inline expand toggle too.
5. **Verify locally:** `npx vitest run …AgentToolRenderer.test.tsx` (all 8 green) +
   `npx tsc --noEmit -p packages/client/tsconfig.json` on the changed files.
6. **Deploy live** (production mode): `npm run build` then
   `POST http://localhost:8000/api/restart`; confirm mode via `/api/health`.
7. **"Update specs if needed"** → fold the behavior into the *existing*
   `subagent-live-detail-reliability` spec (tighten prose + add 2 scenarios), then
   `npx openspec validate --specs`.
8. **Commit scoped:** stage exactly the 4 files; use a `/tmp/commitmsg.txt` heredoc to
   dodge shell-quote breakage; leave unrelated working-tree changes untouched.

## 3. How the collaboration unfolded

**Discovery / root-cause (Prompt 1).** The AI grepped for "Subagent not found",
walked `event-reducer.ts` and the subagents plugin, and explained the bug precisely:
the card header reads from `toolDetails.agentId` (always present), but
`<SubagentDetailView>` looks the agent up in a *separate* `session.subagents` map that
is filled **only** by live `subagent_created/started/completed` frames. For a running
subagent viewed after a refresh/late-subscribe, state-replay never synthesizes those
events, so `.get(agentId)` misses → the not-found message. *Why it worked:* the AI
distinguished the two data paths instead of guessing at the render.

**Build (Prompt 2 = "yes").** TDD: wrote 2 tests, then extracted the resync logic
that previously only fired on the Popout button into a shared `requestResyncIfStale()`
helper and wired it into a new `toggleExpand`. Key subtlety it caught itself:
side-effects inside a React state-updater run twice under StrictMode, so it computed
the resync decision *outside* the updater. Card status (not the map) is the
authoritative "running" signal, so the helper fires even when the map has **no** entry.

**Verify + deploy.** 8 tests pass, type-check clean on changed files (one pre-existing
unrelated error ignored). Because the instance runs in production mode, a client change
needs `npm run build` + `POST /api/restart`; the AI confirmed the new pid and mode via
`/api/health`, and updated the per-file `AGENTS.md` record.

**Spec (Prompt 3 = "Update specs if needed").** The AI found the behavior already had a
home — `subagent-live-detail-reliability` — whose requirement prose intended
"opening the detail surface" but whose scenarios only covered the reconnect trigger.
It tightened the prose to name both surfaces (inline + popout) and the no-map-entry
case, added 2 scenarios, and validated green. *No new capability invented.*

**Commit (Prompt 4 = "commit").** Staged exactly the 4 change files; embedded quotes in
the commit message broke shell parsing, so it switched to a heredoc message file.
Landed `2777c17d7` on `develop`, leaving unrelated working-tree churn out.

## 4. Prompts that worked

- **Goal prompt — "What is the reason?" (not "fix it").** Asking for the *diagnosis*
  first forced a real root-cause trace and a shared understanding before any edit.
  Stronger version: *"Explain the root cause of X (two data paths?) before proposing a
  fix, with file:line references."*
- **"yes"** — a high-leverage one-word unlock: it authorized the full fix once the
  diagnosis was trusted. Effective because the AI had already laid out the plan.
- **"Update specs if needed"** — short, and it correctly let the AI decide *whether* a
  new spec was warranted (it wasn't) vs folding into the existing one.
- **"commit"** — trusted the AI to scope the commit; worked because file discipline was
  already established.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Jump toward a fix | "What is the reason?" | Ask for root-cause-first with file:line before code |
| Leave spec coverage implicit | "Update specs if needed" | Say "update the matching spec's scenarios, don't invent a new capability" |
| Risk committing unrelated working-tree changes | Implicit via "commit" (AI self-scoped to 4 files) | State "stage only the files this change touches" up front |

The operator's light touch worked *because* the AI volunteered guardrails itself: TDD,
StrictMode double-run avoidance, production-mode rebuild+restart, scoped staging.

## 7. Pitfalls & dead ends

- **Embedded quotes in `git commit -m` broke shell parsing** → write the message to
  `/tmp/commitmsg.txt` via a `<<'EOF'` heredoc and `git commit -F`.
- **Side-effects inside a React state updater run twice under StrictMode** → compute the
  resync decision *outside* `setState`, then flip the flag.
- **A stale/empty `subagents` map is NOT the "running" signal** → use the card status as
  authoritative so resync fires even when `.get(agentId)` returns nothing.
- **Production mode swallows client edits** → `npm run build` + `POST /api/restart`;
  a plain restart alone won't pick up unbuilt client changes. Confirm via `/api/health`.
- **Pre-existing unrelated failures** (`tsc` error, `spawn-error-persistence` spec) →
  verify they're outside your changed files, then ignore rather than chase them.
