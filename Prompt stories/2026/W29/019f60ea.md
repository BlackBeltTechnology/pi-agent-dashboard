# How we did it: Diagnose the "No changes for this file" diff blank and capture the fix as an OpenSpec change — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** — the stance where the AI reads, searches, and
reasons about the codebase but is forbidden from writing implementation code. The
implicit goal: *figure out why clicking a newly-written file in the per-turn change
summary block opens a diff tab that says "No changes for this file," even though the
row correctly shows `+N` additions.*

The **real objective** crystallized only after the steering turn: it was never a bug
to fix in place — it was a **diagnosis-and-capture** task. Root-cause the blank diff
end-to-end, then encode three specific product decisions (path normalization,
git-vs-session diff precedence, and in-tab file preview) as a properly-scoped OpenSpec
change — *without touching the implementation*, because explore mode captures thinking,
not code.

## 2. TL;DR playbook

1. **Enter explore mode** (`/skill:openspec-explore`) so the AI stays in
   diagnose-and-capture mode and never writes implementation code.
2. **Trace the pipeline end-to-end with `grep`**, not assumptions: find the summary
   block component (`ChangeSummaryBlock`), the click handler (`onOpenFile` →
   `openDiffTab`), and the server diff source (`session-diff.ts`).
3. **Compare the two path formats at the join point.** The row emits `args.path`
   (absolute); the server keys `data.files` by `normalizePath()` (relative posix).
   `find(f => f.path === relPath)` never matches → blank diff. **It was never a git
   problem.**
4. **State the fix as decisions, not code** — map each of the user's three directives
   to its exact code site and its spec home.
5. **Coherence-check against archived changes** (`openspec list`, `ls
   openspec/changes/archive/`) so you don't duplicate `platform-path-normalization`
   or `session-file-diff-view`.
6. **Read the real requirement headers** of the specs you'll delta so MODIFIED deltas
   reference requirements that actually exist.
7. **Scaffold the change**: `proposal.md`, `design.md`, `tasks.md` + 3 delta specs
   (`session-diff-extraction`, `change-summary-table`, `file-diff-view`).
8. **Validate**: `openspec validate <change> --strict`.
9. **Commit only the change** — stage `openspec/changes/<name>/` explicitly, leave the
   unrelated working-tree churn untouched.

## 3. How the collaboration unfolded

**Phase 1 — Ground the symptom in real code (Discovery).**
The AI resisted the urge to theorize. It ran a cascade of scoped `grep`s across
`packages/server/src` and `packages/client/src` to locate the actual components:
the summary block, the diff viewer, the file tree, and the server's synthetic-diff
path. *Why it worked:* the screenshot showed a flat absolute-path list with green
`+N` — which the AI correctly ruled out as `DiffFileTree` (basenames + folders) and
identified as `ChangeSummaryBlock`. Grep-first, name-the-component-before-theorizing.

**Phase 2 — Find the exact join failure (Root cause).**
The AI traced `onOpenFile` → `openDiffTab(absPath)` → `DiffViewer: data.files.find(f
=> f.path === relPath)` and compared the two path formats. The row's path came from
`lib/lineDelta.ts::toolPath()` **verbatim (absolute)**; the server's `data.files` was
keyed by `session-diff.ts::normalizePath()` (**relative posix**). They can never be
equal. **Decision point:** the AI explicitly rejected the "it's a git issue"
hypothesis and pinned it to a path-format mismatch.

**Phase 3 — The human's three directives (Steering).**
The user supplied the product decisions in one terse steering turn (abs-under-cwd →
relative; git ⇒ gitDiff else sessionDiff; preview file in split diff window). The AI
mapped each directive to its precise code site and its owning spec, keeping all three
tightly scoped.

**Phase 4 — Coherence-check and scaffold (Capture).**
Before writing, the AI checked archived changes to avoid duplication, read the target
specs' requirement headers so the MODIFIED deltas were real, then scaffolded 6
artifacts and ran `openspec validate --strict`.

**Phase 5 — Surgical commit (Land the thinking).**
On `commit`, the AI noticed the working tree had unrelated churn and staged **only**
`openspec/changes/fix-session-diff-open-nongit-and-preview/`, producing commit
`5eb4cf7c5` with nothing else.

## 4. Prompts that worked

- **The goal prompt** (`/skill:openspec-explore`): loading explore mode up front set
  the right stance — the AI diagnosed and captured instead of jumping to a code fix.
  A stronger explicit kickoff would name the symptom *and* the artifact wanted:
  *"Explore mode. Root-cause why opening a newly-written file row shows 'No changes',
  then capture the fix as an OpenSpec change — don't implement."*
- **High-leverage follow-up** (steering #1): three decisions in three lines —
  *"on every file when the path absolute and under the CWD, make it relative / when
  GIT is set for CWD use GitDiff otherwise fallback to sessionDiff / in the Diff
  window be able to preview the file."* Terse but unambiguous; each line became a
  spec contract. This is the model to copy: state decisions as precedence rules, not
  prose.
- **`commit`** — one word, but the AI's own discipline (stage only the change) made
  it safe. Bake that discipline in rather than relying on a longer prompt.

## 7. Pitfalls & dead ends

- **Don't assume "blank diff" = "git missing."** The blank was purely a
  key-comparison miss (`absPath !== relPath`). Check the *join*, not the transport.
- **Don't guess the component from a description — match the screenshot to code.**
  The AI nearly conflated `DiffFileTree` with `ChangeSummaryBlock`; it distinguished
  them by their rendering (basenames+folders vs flat absolute list with `+N`).
- **MODIFIED deltas must reference real requirement headers.** The AI read the
  specs' `### Requirement:` lines *before* writing deltas — skip this and
  `openspec validate --strict` fails.
- **Mid-explore commits are a trap.** With a churned working tree, `git commit -a`
  would have swept in unrelated `AGENTS.md`/`.agent.md` edits. Stage the change dir
  by path.
