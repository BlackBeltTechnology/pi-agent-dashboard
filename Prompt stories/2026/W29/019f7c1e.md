# How we did it: Prove-then-cut the root AGENTS.md with a real A/B behavior experiment — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened with a deliberately open question:

> **"Collect what and when are injected to pi proompt from this repo and why?"**

On its face this is an audit request — inventory the per-turn prompt injections. But the
follow-up steering turns revealed the *real* objective: **measure the token cost of those
injections, then cut the biggest one (the ~7,400-token root `AGENTS.md`) without losing
model confidence — and prove the cut is safe with a real behavior experiment, not a guess.**
The finished artifacts were a reusable A/B harness (`scripts/ab-context/`), a 58%-trimmed
root `AGENTS.md` promoted to main, the same lean-doctrine principle baked into the
`project-init` scaffolding, and a research write-up under `docs/research/`.

## 2. TL;DR playbook

1. **Inventory the injections first.** Ask the AI to trace every per-turn injection (system-prompt fragment, `AGENTS.md` tree, tool schemas) to its source file and *reason for existing*. Start from `kb_search`, then read the injector code.
2. **Quantify before touching anything.** Have it measure each injection in chars → tokens (~4 char/tok). This surfaces that the root `AGENTS.md` (~7.4k) + tool schemas (~4.2k) dominate.
3. **Frame the constraint as a testable hypothesis.** "Without loss of confidence" → *confidence needs information **reachable**, not **present every turn***. That reframes deletion into a **tier split** (keep per-turn doctrine; move task-scoped procedure behind a pointer that names its trigger).
4. **Don't trust the reasoning — run an A/B.** Put the control (full) in the main repo and the treatment (trimmed) in a **git worktree** so the only diff is the injected context. Same commit otherwise.
5. **Build a headless harness** (`run.sh` + `extract.mjs` + `analyze.mjs` + `judge.mjs`): a task battery that targets exactly the *moved* rules + neutral controls, machine-checkable adherence checks, non-inferiority analysis (B ≥ A − δ), and an arm-blind quality judge.
6. **Smoke-test the pipeline on synthetic data first**, then run real headless `pi -p` sessions, capturing each run's new session JSONL by before/after file-diff.
7. **Run it unattended.** Interleave A/B so provider drift spreads evenly; `nohup` + an armed auto-finisher that writes `report.txt` on completion. Poll, don't babysit.
8. **Promote only when the moved-content cells pass.** Copy trimmed → main, verify every pointer target exists, remove the worktree, kill background procs.
9. **Propagate the principle** into `project-init` templates and **capture the method as a project skill**. Commit surgically (only your files).

## 3. How the collaboration unfolded

**Phase 1 — Inventory (Discovery).** The AI led with `kb_search`, found the injection spec, then read `packages/extension/src/dashboard-context-injector.ts` and the per-session `pi.registerTool` calls in `bridge.ts`. It produced a full "what/when/why" table: the session-context fragment (every turn, `before_agent_start`), the `AGENTS.md` tree, and per-session tool schemas shipped on every request. *Why it worked:* grounding in real source (not memory) made every later number defensible.

**Phase 2 — Measure.** On "How many tokens?" it measured each injection's char size and converted to tokens, isolating the two big spenders: root `AGENTS.md` ~7,400 and tool schemas ~2,625+. *Decision point:* the human pushed toward improvement — "Is there a way to improve without loss of confidence?"

**Phase 3 — Reframe + design.** The AI resisted blind deletion and articulated the governing principle: *reachable-not-present*. Every moved block must leave a one-line pointer naming its trigger. When the human asked "is an A/B test possible?", the AI **verified the mechanics before designing** — confirmed headless `pi -p` produces one parseable JSONL per run, with `toolCall` blocks and `usage` tokens. This is the pivotal move: it refused to hand over a hand-wavy design.

**Phase 4 — Build + prove plumbing.** It scaffolded the harness and ran it against **synthetic data first**, confirming an injected regression flowed through extract → analyze and the non-inferiority flag fired. Only then did it clear synthetic data for real runs.

**Phase 5 — Run (the long grind).** Real runs cost ~5 min each (jiti cold-boots the whole dashboard extension per spawn). The AI ran interleaved A/B in the background with an armed finisher and reported *interim* scorecards on each "poll". A counterintuitive live signal emerged early and held: the **trimmed** arm followed the docs-first gate while the **full** one didn't — the signal-dilution hypothesis showing up as real behavior.

**Phase 6 — Verdict + ship.** 50 runs, 9 adherence cells: B non-inferior on all 9, superior on 3, zero regressions; blind quality 5.0 vs 4.1; −47% output, −30% tools. The AI then promoted the trim to main, propagated the principle into `project-init`, created the `ab-test-context-injections` skill, and (later) delegated a `docs/research/` write-up to DocScribe.

## 4. Prompts that worked

- **The goal prompt** — *"Collect what and when are injected to pi prompt from this repo and why?"* Effective because it demanded the **why** per injection, not just a list — that forced source-grounding. A stronger version bakes in the endgame: *"Inventory every per-turn prompt injection with source file + reason, measure each in tokens, and tell me which we could cut without losing model confidence."*
- **"Is there a way to improve without loss of confidence?"** — a high-leverage constraint. It turned "trim the file" into a principled tier-split with a falsifiable safety claim.
- **"Is it possible to make some A/B test about how the model behaviour changes because of these fixes?"** — the unlock. It converted an opinion war ("less is more") into a measurable experiment.
- **"yes" / "1"** — short unlocks that greenlit each build stage (build the harness → build arm B → run the pilot → run the remaining tasks).
- **"poll" / "pull"** — the babysitting-free control loop for a long background run. Effective *because* the AI had armed an auto-finisher; the human only sampled progress.
- **"make the changes in project-init skill's templates"** and **"document it in docs/research"** — scope expansions that turned a one-off win into reusable assets.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Answer the *audit* literally and stop | "and what about tool registrations?" / "how many tokens?" | State the full chain up front: inventory → measure → recommend a cut |
| Risk hand-wavy recommendations | "Is it possible to make an A/B test?" | Demand *measured behavior*, not reasoning, for any confidence claim |
| Want to run 20 real runs synchronously | (implicit via "poll") | Background + armed finisher from the start; poll to sample |
| Treat the trim as done after the pilot | "make the changes in project-init skill's templates" | Ask "where else does this principle belong?" once proven |
| Sweep unrelated working-tree changes into the commit | "commit" (AI self-caught) | Verify `git diff HEAD` is *exactly your files* before staging |

Two safety catches the AI performed unprompted are worth imitating: (1) it noticed arm A's cwd is the *same directory as the live interactive session*, so it hardened capture with before/after file-diff instead of slug guessing; (2) at commit time it separated a **concurrent session's** escape-stack changes from its own, verifying no clobber before staging.

## 6. Skills, tools & memory created — and why they're effective

- **Skill `ab-test-context-injections`** (project scope). Captures the whole method: worktree-isolate the treatment, replay a fixed task battery headless, parse JSONL for behavior, judge non-inferiority. *Effective* because it makes "should we change AGENTS.md / a tool description?" an empirical question with a ready harness — no re-deriving the plumbing. Invoke it before any doctrine or context-injection change you want to validate.
- **The `scripts/ab-context/` harness itself** — `tasks.jsonl` (rule-targeting battery + neutral control), `arms.json`, `run.sh` (interleaved headless capture), `extract.mjs`, `analyze.mjs` (non-inferiority, not significance), `judge.mjs` (arm-blind quality). Reusable independently of the skill.
- **Two project memories** recording the trim was evidence-based (~7,400→~3,078 tok/turn, −58%; non-inferior 9/9, superior 3). *Note:* the project memory store was at capacity, so the durable record is really the skill — a reminder to lean on skills when memory is full.

## 7. Pitfalls & dead ends

- **Subprocess-per-score judge hangs.** The first `judge.mjs` design booted `pi` per answer and hit `ETIMEDOUT` even at 420s (jiti cold-boot ~2 min + lock contention). **Fix:** blind all answers to a key file, then score them in **one in-process subagent call** — no per-score boot.
- **macOS bash 3.2 has no `mapfile`.** `run.sh` broke on it. **Fix:** make the runner portable (avoid `mapfile`).
- **Every headless spawn cold-boots the full dashboard extension (~5 min/run).** Budget ~90 min for 20 runs; run in background with an armed finisher rather than blocking.
- **`total` tokens are cache-inflated.** Report `output` (pure generation) and `cacheWrite` (real per-turn prompt saving), not the raw total.
- **Shared session-slug dir.** Arm A ran in the same cwd as the live session → capture must diff session files before/after, not guess the newest slug.
- **DocScribe mis-sorted the AGENTS.md row** (`context-` before `auto-`). Verify path-alphabetical order after any `docs/` delegation.
- **`docs/` writes must go through DocScribe** (Rule-6, caveman style) — the main agent never edits `docs/` prose directly.
