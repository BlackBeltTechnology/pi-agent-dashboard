# How we did it: pinning an empty-FLOWS-subcard bug into an OpenSpec change — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore` skill) — a thinking-partner
stance where the AI reads, searches, and reasons but never writes code. The operator's
real objective was not stated as prose; it was a **screenshot plus a one-line rule**:

> "When any pill, component inside — do not hide. [image]"

Decoded: a **"FLOWS" subcard** in the dashboard session card was rendering as an empty
labeled box (a "FLOWS" pill over a blank bordered panel with no buttons) in sessions
where the pi-flows extension is loaded but there is nothing actionable to show. The goal
was to **root-cause that empty panel and capture the fix as an OpenSpec change proposal**
— without writing implementation code — then commit only that proposal.

## 2. TL;DR playbook

1. Enter explore mode via the `openspec-explore` skill (`stance: think, never implement`).
2. Ask the AI to trace the *visibility* logic of the leaking UI element — name the exact
   render gates, not just the component.
3. Feed the AI a screenshot + a single crisp rule ("do not hide when there is content").
   Let it distinguish the **outer subcard wrapper gate** from the **inner content gate**.
4. Have the AI produce a **divergence table**: what predicate opens the gate vs. what
   predicate renders content. The bug is always the gap between the two.
5. Ask it to confirm the *fix is implementable synchronously* (no new plumbing) before
   writing the proposal — verify accessor call sites (`getSessionData`, `getPluginConfig`).
6. Scaffold with `openspec new change <name>` (NOT `openspec change new` — wrong subcommand).
7. Write the four artifacts: `proposal.md`, `design.md`, `tasks.md`, and the MODIFIED
   `specs/<capability>/spec.md` delta that pins the bug state + the states that must stay.
8. `openspec validate <name> --strict` → valid.
9. `git add` **only** the change dir; commit with a scoped message. Verify nothing
   unrelated (other changes, `.bak` files) got staged.

## 3. How the collaboration unfolded

**Phase 1 — Locate the leaking element (Discovery).** The AI grep-swept
`packages/web/src` and `packages/*/src` for `flow` / `FLOWS` / `OPENSPEC` in `.tsx`,
excluding tests. It landed on `SessionFlowActions.tsx` and mapped **two render gates plus
one always-rendered inner row**. Effective move: it refused to stop at "found the file"
and instead diagrammed the gate chain.

**Phase 2 — Separate wrapper from content (the key insight).** The operator's screenshot
clarified that the empty box is the **subcard wrapper** (`SessionSubcard` → the "FLOWS"
pill + bordered box), not `SessionFlowActions` itself. The AI traced the slot
`session-card-flows` → `shouldRenderFlowsSubcard` gate, and found `SessionSubcard`'s
`hasMeaningfulChildren` check fails because a React element that *internally* returns
`null` is still a truthy object — so the wrapper renders the empty panel.

**Phase 3 — Name the divergence (Root cause).** The AI produced the crux: the **gate
opens on extension presence** (`computeAvailability` → true whenever a `flows`/`flows:*`
command exists) while **content renders on actual actions** (`flowsList>0 || editMode ||
flowState`). The empty state = "extension loaded, zero flows, edit mode off, no flow ran".

**Phase 4 — Prove the fix is cheap (Design decision).** Before proposing, the AI verified
`getPluginConfig("flows")` is a **synchronous** accessor and `getSessionData("flowsList")`
is already used sync in the same file — so realigning the gate to the content predicate
needs **no new plumbing** and the availability cache/subscriber can be retired.

**Phase 5 — Capture, validate, commit (Generate).** On `capture`, the AI scaffolded via
`openspec new change`, wrote all four artifacts, and `openspec validate --strict` passed.
On `commit`, it staged **only** the `fix-empty-flows-subcard/` dir, leaving an unrelated
change and a `.pi/settings.json.bak-switch-*` backup untouched → commit `c21cef121`.

## 4. Prompts that worked

- **Goal prompt (the skill + screenshot + rule).** The `openspec-explore` stance kept the
  AI in *think-don't-implement* mode, which is exactly right for capturing a bug as a spec.
  The one-line rule "when any pill/component inside, do not hide" + a screenshot was enough
  — a picture of the empty panel beat any prose description of the state.
- **`capture` (high-leverage, one word).** After the root cause was nailed, a single word
  unlocked the full four-artifact proposal. Works because the AI had already been asked to
  confirm implementability, so "capture" had a concrete, validated plan to serialize.
- **`commit` (one word).** Trusted the AI to stage narrowly. It did — and *reported what it
  deliberately left out*, which is the behavior you want.
- **Rewrite for next time:** make the goal prompt explicit about the deliverable —
  *"In explore mode, root-cause why the FLOWS subcard renders empty, then capture it as an
  OpenSpec change (proposal + design + tasks + spec delta). Don't write code."*

## 6. Skills, tools & memory created — and why they're effective

No new skills or memories were created — this was a pure **explore → capture → commit**
run on existing skills (`openspec-explore`, `openspec new change`). The reusable asset is
the **OpenSpec change itself** (`fix-empty-flows-subcard`), whose `spec.md` delta pins the
exact bug contract:

- The archived `session-card-subcards` spec **already mandated** the violated rule: *"a
  plugin whose claim component conditionally returns `null` SHALL declare a `shouldRender`
  so the wrapper does not render an empty panel."* The delta simply pins the FLOWS-specific
  bug state + the two states (edit mode, flow-ran) that must stay visible.
- **Recommended skill to create:** a "gate-vs-content divergence" checklist — for any
  auto-hiding wrapper, tabulate *what predicate opens the gate* vs *what predicate renders
  content*; the bug is the gap. This pattern recurs across subcards.

## 7. Pitfalls & dead ends

- **`openspec change new <name>` fails** — the correct subcommand is
  **`openspec new change <name>`**. The session hit this (1 failed command) and recovered
  by reading `openspec --help`. Check the help before guessing subcommand order.
- **`hasMeaningfulChildren` does not catch null-rendering elements** — a React element
  that internally returns `null` is still a truthy object, so a wrapper's "has children?"
  heuristic passes and the empty panel renders. Don't rely on child-presence; gate on the
  same predicate the content uses.
- **Gate/content predicate drift** — availability caches (`computeAvailability` on command
  presence) diverge from live content predicates. Prefer reading live state synchronously
  over a cached availability proxy.
