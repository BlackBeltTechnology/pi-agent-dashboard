# How we did it: Redesign the chat composer (prompt-input v2) — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) — a thinking stance, not an
implementation task. The literal kickoff was the skill preamble: *"Enter explore mode.
Think deeply. Visualize freely… you must NEVER write code."* The real objective emerged
over the next eight steering turns: **redesign the pi dashboard's chat composer** — today
a stack of three components (`QueuePanel` + `CommandInput` + `StatusBar` model row) with
buttons scattered beside the textarea — into **one rounded container with an inner
toolbar**, the pattern used by Codex CLI, ChatGPT, and Gemini. Deliverables: measured
mockups (desktop + mobile), an anti-slop design review, and a validated OpenSpec change
proposal — all without touching production code.

## 2. TL;DR playbook

1. **Start in explore mode** to keep it a design/thinking task: research + mockups + a
   proposal, no production edits.
2. **Ground the mock in the real system first** — read `CommandInput.tsx`, `StatusBar.tsx`,
   and the `index.css` theme tokens so the mockup uses *actual* colors, i18n strings, and
   pixel dimensions, not invented ones.
3. **Fetch the reference designs** (`ctx_fetch_and_index` the Codex CLI / ChatGPT / Gemini
   composer docs) and build a comparison table of container / affordances / send / footer.
4. **Build an interactive HTML mockup** (`mockups/prompt-input-v2/index.html`) covering all
   6 states (idle, slash menu, mention+attach, `＋` popover, streaming, error).
5. **Measure, don't eyeball**: build `compare.html` that reconstructs the *current* composer
   next to v2 and computes real pixel heights with `getBoundingClientRect()` → answer the
   "how much taller?" question with a hard number (**+71%**), plus a tunable minimal path.
6. **Run the anti-slop review mechanically** (`anti-slop-frontend` skill) — grep the files
   for em-dashes, mixed icon families, fake data; fix the FAILs (swap glyphs for real MDI
   SVGs, hit 44px touch targets).
7. **Do the coherence check before scaffolding** — `kb_search` + read archived changes to
   see what you're *reversing*, then `openspec` scaffold proposal/design/spec/tasks and
   `openspec validate --strict`.
8. **Commit only what you created** — surgical add of the proposal + mockups; leave
   unrelated pre-existing diffs (`groups.json`) alone; flag push/branch safety.

## 3. How the collaboration unfolded

**Phase 1 — Discovery & grounding.** The AI read the real composer sources
(`CommandInput.tsx`, `StatusBar.tsx`), the theme tokens in `index.css`, and the i18n
strings, then drew an ASCII map of the current three-component stack. *Why it worked:* every
later mockup pixel traced to a real token or string, so the design was credible from step
one rather than a generic chat box.

**Phase 2 — Reference gather.** `ctx_fetch_and_index` pulled the Codex CLI / ChatGPT /
Gemini composer docs; the AI distilled them into a container-vs-affordance-vs-send table and
named the through-line: *one rounded container + inner toolbar*. Decision point: pull
model + thinking **into** the composer, retiring the StatusBar model row.

**Phase 3 — Build the mockup.** A 6-state interactive `index.html` served locally; because
Playwright's browser wasn't installed, the AI fell back to `agent-browser` for screenshots
and verified both dark and light themes render with good contrast.

**Phase 4 — Measure the cost.** Prompt 2 ("how many percentage added?") forced a real
number. Instead of estimating, the AI built `compare.html` that renders current-vs-v2 and
reads heights from the DOM: **99px → 169px = +71%**, with a breakdown of where the +70px
goes and three dials to land a **minimal ~+10–15%** variant.

**Phase 5 — Anti-slop review + fixes.** Prompt 3 invoked the `ui-slop` skill. The AI ran it
*mechanically* (grep counts, not vibes): em-dash × 15 (FAIL), three mixed icon families
(FAIL). Fixes across prompts 4–7: swapped glyphs to real MDI SVGs (`mdiConsole`,
`mdiSendVariant`), reorganized the mobile section into a 2×2 captioned phone grid, fixed
44px touch targets, and re-aligned the streaming toolbar to one law (left = controls,
right = single action button).

**Phase 6 — Proposal + commit.** Prompt 8 ("create proposal"): coherence check first
(this **reverses** the archived `statusbar-inline` decision), then scaffold + `openspec
validate --strict` (passed). Prompt 9 ("commit"): surgical commit of 6 files, leaving the
unrelated `groups.json` diff untouched, with a push-safety heads-up.

## 4. Prompts that worked

- **Goal prompt (explore mode):** effective because the stance *forbade implementation* —
  it kept the whole session on research + mockups + proposal, exactly right for a design
  task. A stronger explicit kickoff: *"Explore a redesign of the chat composer into a
  single-container toolbar like Codex/ChatGPT/Gemini; ground it in our real tokens; produce
  measured desktop+mobile mockups and a validated OpenSpec proposal — no production code."*
- **"How many percentage added in the new design?"** — high leverage: it converted a vague
  aesthetic into a **measurable** requirement, which triggered the self-measuring
  `compare.html` and the honest +71% answer.
- **"use ui-slop skill and review mockup. Think about icons and check best practices"** —
  unlocked a whole mechanical QA pass; naming the skill explicitly routed it correctly.
- **"create proposal" / "commit"** — short unlocks that moved the artifact from mockup to
  a committed, strict-validated OpenSpec change.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Design without quantifying the footprint cost | "How many percentage added?" | State up front: *measure current vs proposed in-browser, report a % delta* |
| Leave mixed unicode/emoji glyphs in the mock | "Replace terminal and send icon" / "use ui-slop skill" | Require a single icon family (real MDI SVG) from the first mockup |
| Under-organize the mobile view (prose, not shown) | "organized better mobile" | Ask for a captioned phone-state grid that *demonstrates* each fold |
| Strand a button with a floating spacer | "Wrongly aligned buttons" + screenshot | Enforce one layout law: left = controls, right = single 44px action |

## 6. Skills, tools & memory created — and why they're effective

No new skills or memories were *created* this session, but three existing assets were the
backbone and are worth invoking every time:

- **`openspec-explore`** — the stance that kept a large design task from leaking into code.
  Invoke it whenever the goal is "figure out a redesign," not "ship it."
- **`anti-slop-frontend` (ui-slop)** — run it *mechanically*: grep for em-dashes, count icon
  families, check for fake data and touch-target sizes. It turns "does this look
  AI-generated?" into a countable scorecard. Invoke on any generated frontend mockup.
- **A self-measuring `compare.html`** — the reusable trick: reconstruct the *current* UI
  from real component dimensions beside the new one and read heights from the DOM. Any
  "how much bigger/smaller?" question should be answered this way, not by estimate.

*Recommendation:* this measured-mockup → anti-slop → coherence-checked-proposal flow is
repeatable enough to deserve its own project skill.

## 7. Pitfalls & dead ends

- **Playwright browser not installed** → screenshots failed. Fallback: use `agent-browser`
  (`serve_mockup` + browser screenshots) instead of `score_mockup`'s Playwright path.
- **Raw doc URLs were unreliable** → the first `ctx_fetch_and_index` grabbed stale/wrong
  pages; re-fetch the *current* reference pages before trusting the synthesis.
- **UTF-8 arrow in `perl` swap** → the `↑` send glyph needed explicit UTF-8 handling; the
  terminal glyph swapped cleanly but the arrow did not on the first pass.
- **Proposal reverses an archived decision** (`statusbar-inline`) → don't silently
  contradict shipped intent; call it out in `proposal.md`, justify in `design.md`, gate with
  `doubt-driven-review`.
- **Committed to `develop`, not pushed** → proposal commits straight on `develop` can get
  cleaned up by others; prefer a branch/PR if the work must survive.
- **Unrelated staged diff (`groups.json`)** → don't sweep it into your commit; add only the
  files your change created.
