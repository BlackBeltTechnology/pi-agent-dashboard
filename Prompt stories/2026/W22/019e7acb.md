# How we did it: Rebase a stale, conflicting PR branch onto develop — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The operator opened with a fully-triaged incident report, not a vague plea. A worktree
branch (`gate-publish-on-smoke-and-tests`, PR#43) failed the dashboard's "Install deps +
Spawn" with `bootstrap_failed: install_nonzero_exit`. The report pinned the whole causal
chain: `npm ci` aborted with `EUSAGE` because `package-lock.json` pinned a transitive
`@earendil-works/pi-coding-agent@^0.74.0` while develop had moved past 0.74; the branch was
59 behind / 2 ahead, and PR#43 was `DIRTY`/`CONFLICTING`, idle 3 days. The closing line was
the whole ask: *"cwd is the worktree, rebase it to develop."* The real objective: **replay
the branch's 2 unique commits onto `origin/develop`, resolve every conflict correctly,
regenerate the lockfile so `npm ci` passes, and force-push** — unblocking the PR without
losing the smoke-gating work.

## 2. TL;DR playbook

1. Confirm you're in the worktree and note the branch: `pwd && git status --short && git rev-parse --abbrev-ref HEAD`.
2. Fetch the base and list what's unique to the branch: `git fetch origin develop && git log --oneline origin/develop..HEAD` (here: 2 commits).
3. Start the rebase: `git rebase origin/develop`. Expect conflicts on the doc/index files that both sides touched.
4. Resolve conflicts **by intent, not by side** — for each file decide which content is authoritative (see §5); prefer HEAD/develop's post-split structure over the branch's pre-split bloat.
5. Verify zero remaining markers before staging: `grep -n '^<<<<<<<\|^=======\|^>>>>>>>' <files>`.
6. Stage and continue non-interactively: `git add <files> && GIT_EDITOR=true git rebase --continue`.
7. Prove the fix: confirm the lockfile's root `@earendil-works/pi-coding-agent` spec is now `"*"` (inherited from develop), so `npm ci` will no longer `EUSAGE`.
8. Publish safely: `git push --force-with-lease origin <branch>` — then let PR#43 re-evaluate.

## 3. How the collaboration unfolded

**Discovery (≈30s).** The AI didn't re-triage — the operator's report was already complete.
It confirmed ground truth cheaply (`git status`, branch name, `git log origin/develop..HEAD`
showing 2 commits) and moved straight to action. *Why it worked:* a pre-diagnosed prompt lets
the AI skip investigation and spend its budget on execution.

**Rebase + conflict resolution (the bulk).** `git rebase origin/develop` stopped on conflicts
across `CHANGELOG.md`, `AGENTS.md`, `docs/file-index-shared.md`, and
`docs/file-index-skills-misc.md`. The AI read each hunk and resolved by *meaning*:
- **CHANGELOG.md** — kept **both** `### Added` bullets (develop's roles entry + the branch's smoke-gate entry); a merge, not a pick.
- **AGENTS.md** — took HEAD's minimal split-pointer block; the branch's 270-row inline table was pre-split bloat, and the new workflow rows already existed in `docs/file-index-skills-misc.md`.
- **docs/file-index-shared.md** — kept HEAD's added rows but replaced one purpose string with the branch's richer 5-clause version of the `publish-workflow-contract.test.ts` description.
- **docs/file-index-skills-misc.md** — kept HEAD's `repair-meta-source.mjs` row, dropped a duplicate `release-cut/SKILL.md` row from the branch, kept the branch's superset `sync-versions.js` purpose.

*Why it worked:* the AI treated conflicts as a content-reconciliation problem informed by the
repo's own doc-split convention, not a mechanical "ours/theirs" toggle.

**Verify + publish.** After `GIT_EDITOR=true git rebase --continue` replayed both commits
(`c46332ef`, `0b6dad90`), the AI verified the working tree was clean, re-listed
`origin/develop..HEAD`, and inspected the lockfile to confirm the root spec was now `"*"` —
directly proving the original `EUSAGE` was gone. Only then did it stop and hand the
force-push decision back. The operator's *"ok, do it"* released the `git push
--force-with-lease`.

**The decision points** were all the operator's: which fix path (they chose A: rebase +
regenerate + force-push over B: lockfile-only or C: drop branch), and the go/no-go on the
force-push. The AI paused at exactly that irreversible boundary.

## 4. Prompts that worked

- **The goal prompt** (strong template). It carried *Where / Symptom / Direct cause /
  Underlying cause / Unique work / Fix paths A|B|C*, then one imperative. This is the ideal
  shape for a remediation ask: the AI spends zero turns re-diagnosing and can act immediately.
  Reuse this skeleton for any "fix this broken branch/build" request.
- **High-leverage follow-up:** *"ok, do it."* Three words unlocked the force-push because the
  AI had already staged the whole plan and paused at the one irreversible step. Pausing *before*
  the destructive command is what makes such a terse go-ahead safe.
- **Weak-prompt rewrite:** had the operator only said *"my PR is broken, fix it,"* the AI would
  have burned turns re-deriving the `EUSAGE`→lockfile→drift chain. Always lead with the causal
  chain and the enumerated fix paths you'll accept.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Be ready to pick a resolution strategy | Pre-choosing **fix path A** (rebase + regenerate lockfile + force-push) in the goal prompt | Enumerate the acceptable fix paths in the ask so the AI doesn't guess |
| Pause before the irreversible push (correct instinct) | Giving an explicit *"ok, do it"* go-ahead | State up front "pause before any force-push and wait for my go" |
| Risk resolving conflicts side-by-side (ours/theirs) | Relying on repo convention: HEAD's post-split doc structure beats the branch's pre-split inline table | Note "prefer develop's doc-split layout" when rebasing doc-index files |

The quality bar the operator implicitly imposed: don't just make the rebase *finish* — prove
the lockfile spec flipped to `"*"` so the original `install_nonzero_exit` is actually fixed.

## 6. Skills, tools & memory created — and why they're effective

No skill or memory was created in this session, but the workflow is textbook-repeatable.
**Recommended skill to create:** `rebase-stale-conflicting-branch` (project scope) capturing:
(1) confirm worktree + list `origin/develop..HEAD`; (2) rebase and resolve doc-index conflicts
by the repo's doc-split convention (HEAD structure wins, merge CHANGELOG bullets); (3) verify
no conflict markers remain; (4) `GIT_EDITOR=true git rebase --continue`; (5) prove the lockfile
root spec inherited develop's value; (6) `git push --force-with-lease`. This removes the manual
re-triage of the `EUSAGE`→lockfile→branch-drift chain that recurs whenever a branch idles behind
a `@earendil-works/pi-coding-agent` bump.

## 7. Pitfalls & dead ends

- **First rebase attempt needed a reset.** The AI inspected the `rebase-merge/` state dir and
  ran `git rebase --abort`, then restarted cleanly. *If your rebase state looks tangled, abort
  and restart rather than fighting a half-applied sequence.*
- **One `awk` conflict-stripper failed** (the automated marker-removal one-liner returned
  non-zero). *Don't script conflict resolution blindly* — the AI fell back to reading each hunk
  and resolving by intent, which is what actually produced correct doc merges.
- **AGENTS.md "vanished" from the staged list.** It became identical to HEAD after resolution,
  so it dropped out of `git status` — expected, not an error. Verify with a marker grep before
  worrying.
- **`git rebase --continue` will open an editor** and stall a headless run. Prefix with
  `GIT_EDITOR=true` to auto-accept the commit message.
