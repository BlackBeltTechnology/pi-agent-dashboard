# How we did it: Three grounded pi skills, rewritten cross-platform and shipped to develop — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) — a thinking stance, not
an implementation workflow. The first prompt set the constraint: *investigate the
codebase, visualize freely, but never implement features.* Capturing knowledge as
skills is explicitly allowed inside that stance. The real objective that emerged:
**mine the knowledge that lives only in `AGENTS.md`, `docs/`, and the CI workflows
into three first-class, grounded pi skills** — `implement` (rebuild matrix + code
discipline), `debug-dashboard` (server/bridge/test triage), and `ci-troubleshoot`
(6-workflow release-pipeline triage) — then make them portable and land them cleanly
on `develop` without polluting the active feature branch.

## 2. TL;DR playbook

1. **Enter explore mode** and *investigate before writing*: read the existing skill
   format, enumerate the 21 existing skills, scan `AGENTS.md` + `docs/` + the 6
   GitHub workflows to find knowledge that isn't captured yet.
2. **Draw the gap map** (existing skills vs. uncaptured knowledge) as an ASCII/Mermaid
   diagram, then confirm scope with `ask_user` before drafting anything.
3. **Write each skill grounded in real source** — SKILL.md + `references/*.md` +
   `scripts/*` — quoting the actual `AGENTS.md`/workflow text, not inventing it.
4. **Validate every skill**: frontmatter parses, description ≤ 1024 chars, referenced
   docs exist, scripts pass `bash -n`, cross-references resolve.
5. **Rewrite shell scripts → TypeScript** for cross-platform: `npx tsx ./scripts/foo.ts`,
   Node built-ins only (`node:fs/os/path/child_process`, native `fetch`), no
   `curl`/`jq`/`grep`/`tail`.
6. **Type-check under strict mode** (`target es2022`, `module nodenext`) with a real
   `tsconfig`, then **smoke-run** each script against the live API to catch response-shape
   mismatches.
7. **Land on `develop` via a worktree**: `git worktree add /tmp/pi-dashboard-develop
   develop`, copy the skill dirs in, commit each skill separately, push, remove the
   worktree, delete the copies from the feature branch.

## 3. How the collaboration unfolded

**Phase 1 — Discovery (explore stance).** The AI resisted the urge to write immediately.
It read the skill format, listed the 21 existing skills, and scanned the docs + CI
surface. It then rendered a two-column gap map: *existing skills* vs. *knowledge not
yet captured* (the `AGENTS.md` "Build & Restart" matrix, the tee→grep test pattern,
the 6-workflow release pipeline). *Why it worked:* grounding first meant the skills
described the repo as it actually is, not a plausible fiction.

**Phase 2 — Scope confirmation.** Before drafting, the AI used `ask_user` to confirm
which skills to build and flagged a real tension: the `implement` skill would partly
duplicate `AGENTS.md`'s always-loaded "Code Instructions". It resolved this by making
the skill *rephrase + expand* (concrete patterns, anti-patterns, worked examples) and
reference `AGENTS.md` as the canonical short form. *Decision point:* human chose "both
A and B" — deeper skill that complements, not replaces.

**Phase 3 — Generate.** Three skill trees written: `implement`, `debug-dashboard`,
`ci-troubleshoot`, each with SKILL.md + references + scripts. Every reference quoted
real source (workflow names, restart endpoints, log paths).

**Phase 4 — Cross-platform rewrite (steering #1).** The human pointed out the scripts
were shell-only and this env is multiplatform. The AI checked what runners already
existed (`tsx ^4.21.0` at root, ESM project, existing `.sh`/`.ps1` pairs), then
rewrote all 10 scripts to TypeScript using only Node built-ins, type-checked them
strict, and smoke-ran them. Smoke-running surfaced real API-shape bugs (`/api/sessions`
wraps in `{success, data}`; `/api/health` has no `port`) and a Node 22 `DEP0190`
warning from `shell:true` — all fixed.

**Phase 5 — Land it (steering #2 + #3).** "Commit to develop" — but the AI was on
`feat/enable-standalone-npm-install` with unrelated modified files. Instead of blindly
switching branches, it surfaced the state and asked. The human chose the **worktree**
route: commit to `develop` in an isolated `/tmp` worktree, three separate commits, push,
then remove the worktree and delete the copies from the feature branch. Final state:
3 commits on `origin/develop`, feature branch untouched.

## 4. Prompts that worked

- **The goal prompt (explore mode):** effective because it set a *stance* — investigate
  and capture, don't implement — which pushed the AI to ground everything in real source
  before writing a line. A future kickoff could add the target list up front: *"In explore
  mode, capture the uncaptured knowledge in AGENTS.md + docs + CI as 3 skills."*
- **"Rewrite shell scripts to typescript because in this env its multiplatform solution"**
  — a high-leverage one-liner. It named both the action and the *why* (multiplatform),
  letting the AI pick the ergonomic path (`npx tsx`) without further back-and-forth.
- **"commit to develop"** — short but *underspecified* given the branch reality. A stronger
  version: *"commit these skills to develop without disturbing my current feature branch."*
- **"Check out develop to tmp and add for that. After committed the skills can be removed
  from this branch"** — the decisive steer that resolved the ambiguity cleanly (worktree,
  not branch-switch).

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Write portable-looking scripts in shell (`curl`/`jq`/`tail`) | "Rewrite to TypeScript — this env is multiplatform" | State cross-platform as a hard constraint up front; default new skill scripts to `npx tsx` |
| Take "commit to develop" literally while on a feature branch with unrelated dirty files | Choose the worktree route explicitly | Say "don't switch my branch; use a worktree" when the current branch is dirty |
| Assume API response shapes when writing probes | Smoke-run against the live API | Always smoke-run a script that hits an endpoint before declaring done |
| Risk duplicating always-loaded `AGENTS.md` rules | Confirm the skill should *expand + reference*, not copy | Note "complement AGENTS.md, don't restate it" when a skill overlaps loaded context |

## 6. Skills, tools & memory created — and why they're effective

Three skills now live on `develop`:

- **`implement`** — the 3-component rebuild matrix (extension→reload, server→restart,
  client→build+restart, openspec-apply→full-rebuild) plus the TDD/simplicity/surgical
  discipline rules with worked examples. *Effective because:* it re-surfaces the
  most-forgotten operational knowledge exactly when the agent is about to land a change,
  even after `AGENTS.md` is crowded out of context.
- **`debug-dashboard`** — a 3-layer diagnostic model (server → bridges → tests/UI) with
  log locations, health probes, and the tee→grep test-triage pattern. *Effective because:*
  turns "why isn't X working" into a scripted, deterministic probe sequence.
- **`ci-troubleshoot`** — the 6-workflow taxonomy and prepare→publish→electron→github-release
  pipeline with known failure modes. *Effective because:* release failures are rare and
  high-stakes; the skill preserves the mental map you'd otherwise re-derive under pressure.

All three ship **TypeScript scripts** (`npx tsx`) using only Node built-ins — reproducible
on macOS/Linux/Windows with no external CLI deps.

## 7. Pitfalls & dead ends

- **`tsc` arg parsing via `npm`** ate the flags, ran with default `noEmit:false`, and
  **emitted stray `.js` files** next to the `.ts`. Fix: use a real `tsconfig.json` and a
  clean `npx tsc` invocation; then delete the emitted `.js`.
- **`shell:true` + args array** triggers Node 22's `DEP0190` deprecation. Fix: `shell:false`
  and resolve the `.cmd` suffix on `win32`.
- **Sandbox runs in a temp dir**, so relative validation paths failed — use absolute paths
  when validating skill files from a sandbox.
- **API assumptions:** `/api/sessions` wraps results in `{success, data}` (433 historical
  sessions), `/api/health` has no `port` field. Always probe the real shape.
- **"Commit to develop" while dirty on a feature branch** — don't branch-switch; a worktree
  keeps the feature branch's unrelated WIP (`plugin-registry.tsx`, `ci.yml`) untouched.
