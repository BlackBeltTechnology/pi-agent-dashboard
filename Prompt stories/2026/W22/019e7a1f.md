# How we did it: Root-causing a broken "Changed Files" route in explore mode — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **OpenSpec explore mode** (`/skill:openspec-explore`) with a
single bug report: the **Changed Files** button in the desktop dashboard "does not
work." The real objective — which only crystallized after two steering turns — was
not "make the button clickable" but: **find out *why* clicking Changed Files on
desktop collapses the whole content pane into the global "Pick a session on the
left…" empty state, then capture the fix as an OpenSpec proposal (not code).**
Explore mode's constraint (think, don't implement) meant the deliverable was a
*validated proposal + tasks + spec delta*, not an edit to `App.tsx`.

## 2. TL;DR playbook

1. Enter explore mode: `/skill:openspec-explore` — sets the "investigate, don't
   implement" stance so the output is a proposal, not a hasty edit.
2. Grep the feature surface to map the wiring end-to-end (button → handler → route →
   render branch): `SessionHeader.tsx` (button), `App.tsx` (`onOpenDiffView`,
   `buildSessionDiffUrl`, `useRoute` matches).
3. **Don't trust the wiring read — reproduce in the browser.** Drive the actual UI
   (click the button, screenshot the result) instead of reasoning from source.
4. When "not working" is ambiguous, **stop and ask the user what the failure looks
   like** with a precise, consolidated summary of what you already know.
5. Diff the *working* sibling routes against the *broken* one — the asymmetry is the
   root cause (working routes had a `!selectedId` fallback; the diff route didn't).
6. Confirm the fix is a **one-liner** and scoped (desktop-only, not mobile) before
   writing anything.
7. Write the OpenSpec proposal + `tasks.md` (TDD: repro → failing test → 1-line fix →
   QA → docs → archive) + `specs/…/spec.md` delta; run
   `openspec validate <change> --strict`.
8. Commit with `[ci skip]` in the body (docs-only artifacts, no code) and push.

## 3. How the collaboration unfolded

**Phase 1 — Static wiring map (grep).** The AI traced the button through the code:
`SessionHeader.tsx:462` renders `<button onClick={onOpenDiffView}>Changed Files</button>`
gated on `hasFileChanges && onOpenDiffView`; `App.tsx:1100` wires
`onOpenDiffView={() => navigate(buildSessionDiffUrl(selectedId))}` → `/session/:id/diff`;
`App.tsx:1190` renders `diffMatch && diffSessionId ? <FileDiffView/> : …`. **Why it
worked:** mapping the full path first meant the later "asymmetry" insight had a frame
to sit in. **Why it wasn't enough:** the wiring *looked* intact on both ends, so a
pure source read would have concluded "no bug."

**Phase 2 — Reproduce in the browser (21 browser calls).** Rather than guess, the AI
drove the live UI: dismissed a plugin-hash-mismatch banner, hunted for a session that
actually shows the button (the current session had no Write/Edit calls, so no button),
and clicked it. **The decision point:** the AI recognized it was burning turns hunting
for a repro session and **chose to stop and ask the user** rather than keep guessing.

**Phase 3 — Human supplies the observable (steering).** The user clarified across two
turns: "It is going to open page" → "The dashboard page opens [screenshot]." That
turned an ambiguous "doesn't work" into a concrete failure mode: the detail pane
renders the *no-selection* placeholder instead of `<FileDiffView>`.

**Phase 4 — Root cause via route asymmetry.** With the observable pinned, the AI
found it: `selectedId = match ? params?.id : undefined` (match = `useRoute("/session/:id")`,
an *exact* match that fails for `/session/:id/diff`). So `selectedId` is `undefined`,
`sessionDetail` (the wrapper holding the `diffMatch` branch at line 1190) is `null`,
and the whole pane collapses. Sibling routes (`pi-resources`, `openspec-preview`) had
`!selectedId` fallbacks *outside* the `sessionDetail` block; the mobile shell handled
`diffMatch` in its detail chain — **the desktop fallthrough was missing that branch.**
Bug is desktop-only.

**Phase 5 — Capture as OpenSpec (write, not edit).** The AI wrote `proposal.md`,
`tasks.md` (6-step TDD plan), and `specs/file-diff-view/spec.md` delta, validated with
`openspec validate … --strict`, and on the user's "commit and push … [ci skip]" pushed
docs-only artifacts. The one-line `App.tsx` fix was *described* in the proposal, not
applied — respecting explore mode.

## 4. Prompts that worked

- **The goal prompt** (`/skill:openspec-explore` + "Changed Files does not work"):
  effective because it set the *stance* (investigate → propose) so the AI didn't
  jump to a fix. A stronger kickoff would front-load the observable:
  *"In explore mode: the desktop Changed Files button navigates to /session/:id/diff
  but the pane collapses to the 'Pick a session' empty state — root-cause it and
  write a proposal."* — saves the two steering turns spent extracting the symptom.
- **High-leverage follow-up — the screenshot.** "The dashboard page opens [image]"
  was the single most valuable turn: it converted a vague bug into a precise failure
  mode and unblocked the root-cause phase immediately.
- **"commit and push changes with [ci skip]"** — short, unambiguous, and correctly
  signals docs-only (no CI needed).

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was created this session. The workflow *is* repeatable and is
already covered by existing skills: **`openspec-explore`** (the stance that produces a
proposal instead of a hasty edit) and the **`browser`** skill (drive the live UI to
reproduce rather than infer from source). The reusable lesson worth a memory:
**"route-render asymmetry" — when one URL variant works and a sibling doesn't, diff
their render branches for a missing `!selectedId`/fallback guard** rather than
re-reading the handler. Consider saving that as a project debugging insight.

## 7. Pitfalls & dead ends

- **Grep says the wiring is fine → false negative.** The button, handler, and render
  branch all read correctly; the bug lived in a *route-matching* guard
  (`useRoute("/session/:id")` is exact, so `selectedId` goes `undefined` on the
  `/diff` sub-route). If static reading finds nothing, **reproduce in the browser.**
- **First grep failed** (`grep -rn … src/client …`) because the code lives under
  `packages/client/src`, not `src/client`. If a path grep returns nothing, check the
  monorepo layout (`packages/*`) before assuming the symbol is absent.
- **Wasted turns hunting for a repro session** — the current session had no file
  changes, so the button never rendered. Ask the user for a known-good session/URL
  instead of guessing.
- **Plugin-hash-mismatch banner** ("Dashboard plugins were updated. Refresh…") was a
  red-herring smell during investigation — dismiss it and keep going; it was not the
  bug.
- The facts sheet lists a second change (`fix-expanded-pinned-group-drag`) picked up
  from the session's file/command scan, but the narrative and artifacts only cover
  `fix-changed-files-desktop-route`.
