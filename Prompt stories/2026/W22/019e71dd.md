# How we did it: Redesign the session-card PROCESS subcard into an activity bar — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce

## 1. Goal (the ask)

The session opened tiny and operational — `"restart pi-dashboard server in dev mode"` —
then immediately re-scoped: `"start from source directory. So stop electron server and
start local dasboard server"`. That was just clearing the runway. The **real** objective
surfaced in prompt 3, when the operator dropped into `openspec-explore` mode to rethink
the SessionCard's PROCESS subcard: today it's a flat dump of every PGID child the bridge's
`ps`-scanner finds, which conflates the *safety-net* view of leaked processes with the
*"what is the agent doing right now"* view. The end goal became: **explore the redesign,
land a validated OpenSpec proposal (`redesign-process-list-activity-bar`), move it into
its own worktree/branch, then — days later — archive the completed change and push the
synced specs to `develop`.** A full planning-to-archive lifecycle, run over 113 hours.

## 2. TL;DR playbook

1. **Clear the runway first.** Restart the dashboard from source in dev mode so edits to
   server/shared TS take effect on the next restart with no build step (`pi-dashboard stop`
   → start from the repo root → confirm `mode: dev` via `/api/health`).
2. **Enter `openspec-explore` — stance, not workflow.** Ask the AI to *reflect back* the
   problem before proposing. It drew two ASCII surfaces (SessionCard PROCESS subcard vs.
   ChatView tool calls) to expose the conflation.
3. **Force a shape decision.** The AI offered options; the operator answered `"B"` (the
   conservative "keep the safety net, add a prominent stop line"). One letter unlocked the
   whole design.
4. **Make it buildable.** Have the AI draw the **state machine** (5 card states: IDLE →
   PURE ACTIVE → …) before any spec text, so edge cases are decided up front.
5. **Write the proposal artifacts** grounded in the chosen shape: `proposal.md`, `design.md`
   (decisions + mermaid + spike threads), `tasks.md` (TDD-shaped), and the delta `specs/`.
   Validate against schema before moving on.
6. **Isolate the work: worktree + branch from `develop`.** `git worktree add -b <change>
   develop` → `cp -R` the proposal dir in → `rm -rf` the original. **No jj.** Only move the
   files *this session* produced; leave unrelated in-flight changes untouched.
7. **(Days later) Archive with `openspec-archive-change`.** Run the status check FIRST —
   confirm all artifacts `done` and tasks complete before archiving.
8. **Sync delta specs, then push only the archive files.** In a messy repo (detached HEAD,
   unrelated unstaged work), switch to `develop`, stage *only* the archive + synced specs,
   commit, push.

## 3. How the collaboration unfolded

**Phase 1 — Runway (operational warm-up).** The AI restarted the dashboard, then re-did it
"from source": stopped the Electron-bundled server, started `packages/server/src/cli.ts`
directly via the jiti-backed `pi-dashboard` CLI. *Why it worked:* running from source means
server/shared TS edits land on the next restart with no build — the right footing before a
design session that will touch specs and eventually code.

**Phase 2 — Explore & reflect.** Dropped into `openspec-explore`. The AI's first move was
"Index first" — orient before riffing. It then *reflected the problem back* with two ASCII
diagrams showing the two unrelated "process" surfaces. *Why it worked:* naming the
conflation explicitly (safety-net dump vs. live agent activity) is what made the redesign
tractable — the operator could see the two framings pulling in opposite directions.

**Phase 3 — Shape decision.** The AI surfaced design shapes; the human replied `"B"`. The AI
then drew a **5-state state machine** (IDLE, PURE ACTIVE, …) and enumerated the design
decisions that had to be settled before the card was buildable. *Decision point:* the human
chose the conservative shape (keep safety net + add prominent stop-the-agent line).

**Phase 4 — Generate proposal + isolate.** The AI wrote 7 artifacts (`.openspec.yaml`,
`proposal.md`, `design.md`, `tasks.md`, 3 delta specs), validated against schema, then — on
the operator's instruction — created the worktree/branch from `develop` and moved *only* the
new proposal files there via plain `git worktree add -b` + `cp -R` + `rm -rf`. Critically,
the AI **sanity-checked scope first**: it noticed ~30 modified files belonging to *other*
changes (`harden-worktree-spawn`) and asked before assuming "all modified files from this
session" meant those too. It correctly interpreted the ask as "the proposal files I'm about
to create."

**Phase 5 — Archive (days later, stale mental model).** On resume, the operator invoked
`openspec-archive-change`. The AI's first reaction was to *stop* ("archiving an unimplemented
design doc") — then it re-read the tasks file, found **34/34 done**, corrected its own stale
model, and resumed the skill cleanly. It ran the pre-archive status check, synced delta specs
to main specs, and archived to `archive/2026-06-02-…`.

**Phase 6 — Careful push into a messy repo.** The repo had drifted: detached HEAD, a removed
worktree, and a pile of unrelated unstaged work from other in-flight changes. The AI narrated
the state, switched to `develop`, staged **only** the archive-related files, committed, and
pushed — explicitly listing what it left unstaged on purpose.

## 4. Prompts that worked

- **Goal / re-scope (prompts 1–2):** `"restart … in dev mode"` → `"start from source
  directory"`. Short and operational; effective because they set the *correct footing*
  (source + dev) before design, not after.
- **The real kickoff (prompt 3):** entering `openspec-explore` with "think deeply, visualize
  freely." *Why effective:* it gave the AI a **stance** (think, don't implement) and license
  to draw — which produced the diagrams that exposed the core conflation. A future operator
  should open a redesign this way, not with "implement a new process card."
- **High-leverage one-letter unlock (prompt 4):** `"B"`. A single character committed the
  design direction after the AI laid out the shapes. This is the pattern to reuse — make the
  AI enumerate concrete options, then pick with one token.
- **Scope + tooling guardrail (prompt 5):** `"dont use jj. Create proposal, after create
  <change> worktree from develop … move all modified file from this session there."` Explicit
  about the tool to avoid *and* the isolation mechanism. Weak-prompt rewrite: name the exact
  branch base (`develop`) and scope ("only files this session created") up front — which is
  exactly what unblocked the AI's correct interpretation.

## 6. Skills, tools & memory created — and why they're effective

No new skills or memories were created — this session *consumed* existing OpenSpec skills
rather than authoring assets. The reusable machinery:

- **`openspec-explore`** — the "think, don't implement" stance. *Effective because* it
  licenses diagramming and reflection, which is what surfaced the conflated-surfaces insight.
  Invoke it at the start of any redesign where the problem framing is still fuzzy.
- **`openspec-archive-change`** — the status-checked archive + spec-sync flow. *Effective
  because* it forces a pre-archive completion check (caught the "is this actually done?"
  question) and drives the delta→main spec merge. Invoke when a change's tasks are complete.
- **Two subagents** — `Explore` (find process-list + session-card files) and a
  `general-purpose` spawn to sync delta specs. *Effective because* they keep search/sync
  grunt-work out of the design context.

**Skill that *should* exist:** a "resume-a-stale-change" pre-flight — on any multi-day gap,
auto-read `openspec status --change <name> --json` + `tasks.md` before acting, so the AI
never opens with a stale "nothing's done yet" model. This session hit that exact trap.

## 7. Pitfalls & dead ends

- **`curl -X POST /api/restart -d '{"dev":true}'` failed.** The reliable path was the
  `pi-dashboard` CLI (stop, then start from source), not poking the restart endpoint with a
  `dev` flag. *If the restart curl fails → use `pi-dashboard stop` + start from the repo root.*
- **Stale mental model on resume.** The AI nearly refused to archive ("unimplemented design
  doc") because its memory predated the worktree implementation. *If resuming after a gap →
  re-read `tasks.md` / `openspec status` before trusting your recollection.*
- **Subagent synced into the wrong tree.** The `general-purpose` spec-sync spawn ran against
  the main repo on `develop` instead of the worktree where the change lived. *If a subagent
  operates on a worktree change → pass it the explicit worktree path, and verify `cwd`/branch
  in its output.*
- **Repo drift during the gap.** By archive time: detached HEAD, worktree removed, change dir
  back in `openspec/changes/`, foreign unstaged work everywhere. *If the repo is drifted →
  narrate the state, switch to `develop`, and stage ONLY your target files before pushing.*
- **Leftover heads-up:** GitHub flagged 40 dependabot vulns (4 critical / 17 high / 19
  moderate) on the default branch — unrelated to the push but worth a glance.
