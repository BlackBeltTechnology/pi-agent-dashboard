# How we did it: Benchmarking local speech-to-text (MOSS vs Soniox vs Parakeet + diarizers) — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** to think through offline, speaker-aware
transcription of long recordings on a CPU-only laptop. The operator then made the
real ask concrete:

> "Is it possible to benchmark moss gguf with soniox? Check my current Movies mp3
> files and cut some samples. Test single speaker understanding, multiple speaker,
> speed benchmark"

The **real objective**, once the follow-ups landed: run a fair, reproducible
benchmark of a local GGUF diarizing model (**MOSS-Transcribe-Diarize 0.9B**) against
the cloud **Soniox** API — and, as steering added contenders, against
**Parakeet-v3** and two diarizers (**pyannote** + **Sortformer**) — on the operator's
own **Hungarian** meeting recordings, measuring transcription accuracy,
speaker-count accuracy, and speed (RTF). The whole procedure had to end up
**captured as a re-runnable skill**.

## 2. TL;DR playbook

1. **Ground the model landscape from live data, not memory.** The sandbox clock read
   2026-07 (past the training cutoff), so pull Hugging Face model cards fresh
   (`ctx_fetch_and_index`) before recommending anything.
2. **Probe the environment first.** Find the real audio (`~/Movies` was an iCloud
   symlink — the meetings were dataless placeholders until resolved), locate API keys
   (`~/Documents/.env`, `~/Movies/.env`), confirm toolchain (cmake/clang/ffmpeg/hf).
3. **Cut fair samples with ffmpeg** → 16 kHz mono WAV, ~60 s each: single-speaker HU,
   multi-speaker HU (find a speaker-dense window via an `awk` scan of the existing
   Soniox `.srt`), single-speaker EN.
4. **Build the local runner CPU-only**: `moss-transcribe.cpp` with
   `-DGGML_METAL=OFF` (the default Metal backend crashes on old Intel-Mac GPUs).
5. **Run each engine on the identical clips, timed** → report wall-clock + RTF, and
   flag that local-CPU vs cloud-API speed is not compute-normalized.
6. **Use existing Soniox `.srt` files as free ground truth** for speaker counts.
7. **Add contenders as the operator steers** (Parakeet-v3, then both diarizers);
   for each, find the lightest CPU runner path before installing anything heavy.
8. **Capture everything in a project skill** (`benchmark-moss-gguf-vs-soniox`) with
   the build recipe, the direct-Soniox script, the sample-cutting one-liners, and
   every dead end — so "benchmark MOSS vs Soniox" auto-loads it next time.

## 3. How the collaboration unfolded

**Phase 1 — Ground (research the landscape).** The AI noticed the sandbox clock was
past its training cutoff and fetched live HF model cards rather than trusting memory.
It decoded a garbled clue ("dhydratization" → *diarization*), identified
MOSS-Transcribe-Diarize as the "diarization baked into the model" candidate, and
produced a landscape map (ASR-only vs ASR+diarization vs diarization-only). **Why it
worked:** treating stale memory as untrustworthy and pulling primary sources kept the
recommendation honest — and surfaced the decisive constraint (Hungarian) early.

**Phase 2 — Probe the environment.** Direct bash commands mapped audio, keys, and
toolchain. **Decision point:** the AI caught that `~/Movies` was an iCloud symlink and
that all the operator's meetings were Hungarian — exactly MOSS's weak spot — making
the benchmark genuinely informative.

**Phase 3 — Build + sample.** Built `moss-transcribe.cpp`, downloaded the Q5_K GGUF,
cut three WAV samples. An `awk` one-liner over the existing Soniox SRT found a
speaker-dense window for the multi-speaker test. **Decision point:** the first
multi-speaker file was mostly one speaker; the AI pivoted to a denser window in
another meeting.

**Phase 4 — Benchmark MOSS vs Soniox.** MOSS crashed (exit 134, `MUL_MAT` Metal op on
the AMD RX 580); the AI rebuilt CPU-only and it ran clean (~1× RT). Since
`pi-transcribe` wasn't built, it read the package source and replicated the exact
Soniox `stt-async-v3` flow in a standalone Node script. Verdict: **the Hungarian gap
is a model limit, not a quantization one** (Q8_0 was a wash and slower; English was
byte-identical Q5↔Q8).

**Phase 5 — Add Parakeet-v3 (steered).** ASR-only but officially supports Hungarian.
Two dead ends (`onnx-asr` int8 → `<unk>` garbage; fp32 → onnxruntime external-data
bug) before **sherpa-onnx** gave a clean, self-contained int8 export. Result: **local
speed king (~18× RT)** but **zero diarization**.

**Phase 6 — Add both diarizers (steered).** Parakeet words+timestamps merged with
each diarizer. **pyannote** (via sherpa, no HF token) over-clustered at default and
needed threshold tuning to 1.0; **Sortformer** auto-detected but was brutal to install
on the Intel Mac (torch capped at 2.2.2, NeMo needs ≥2.4 → binary numba/llvmlite
wheels → 2 torch-API stubs → `numpy<2` downgrade). Both folded into the skill.

## 7. Pitfalls & dead ends

- **MOSS build crash (exit 134, `unsupported op 'MUL_MAT'`)** → the default build
  auto-picked the Metal backend on an old AMD RX 580. Rebuild CPU-only:
  `-DGGML_METAL=OFF -DGGML_ACCELERATE=ON -DGGML_BLAS=ON`.
- **`~/Movies` looked empty** → it's an iCloud symlink; files can be dataless
  placeholders. Use `find -L` and confirm real bytes before probing.
- **`pi-transcribe` CLI wasn't built** (missing compiled `run.js`) → don't build it;
  read the package source for endpoints/flags and call the Soniox `stt-async-v3` API
  directly from a small Node script.
- **Parakeet `onnx-asr` int8** → emits pure `<unk>` tokens (broken quant vocab).
- **Parakeet `onnx-asr` fp32** → onnxruntime 1.23.2 external-data init bug
  (`model_path must not be empty`); not fixable via abs-path or disabling graph
  optimization. **Fix:** use **sherpa-onnx** + the `csukuangfj/...-int8` self-contained
  export.
- **NeMo install died building llvmlite from source** (Python 3.12 blocker) →
  pre-install binary wheels: `pip install --only-binary :all: "llvmlite>=0.43" "numba>=0.60"`.
- **NeMo needs torch ≥2.4 but Intel Mac caps at torch 2.2.2** → stub the two missing
  symbols (`SequenceParallel`, `torch.nn.attention`), then downgrade `numpy<2` (torch
  2.2.2 breaks on numpy 2's `tensor.numpy()`). On a Linux box this is trivial instead.
- **pyannote over-clusters at default threshold** (S2→6 speakers) → tune
  `FastClustering` threshold to 1.0 for correct counts — but note you can't tune blind
  in production, which is the honest catch to report.

- Real speech audio (resolve iCloud placeholders first).
- Toolchain: cmake, clang++, ffmpeg, `hf` CLI, python3 + pip.

**Steps:**
- [ ] Pull live HF model cards (don't trust memory past the clock date).
- [ ] Probe audio + keys + toolchain.
- [ ] Cut 3 samples (16 kHz mono WAV): single-HU, multi-HU (speaker-dense window via

- [ ] Build `moss-transcribe.cpp` **CPU-only** (`-DGGML_METAL=OFF`); download Q5_K GGUF.
- [ ] Run MOSS (timed → RTF) and Soniox (`stt-async-v3` via direct Node script) on the

- [ ] Optional contenders: Parakeet-v3 via **sherpa-onnx int8**; diarizers pyannote
      (sherpa, threshold 1.0) + Sortformer (NeMo, expect torch/numpy fights on Intel).
- [ ] Compare speaker counts against the existing Soniox `.srt` ground truth.
- [ ] Save/update the `benchmark-moss-gguf-vs-soniox` skill.

**Artifacts produced:** `~/moss-bench/` (both GGUFs, WAV samples, all transcripts,
`soniox.mjs`, `parakeet.py`, `parakeet_sherpa.py`, `pipeline.py`, `sortformer.py`) and
the project skill `benchmark-moss-gguf-vs-soniox`.

**Key verdicts to remember:** MOSS ≈ real-time, best local *single-model*
