# How we did it: pull develop, build, deploy — and fix a mislabeled folder unit — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The kickoff prompt was three words: **"pull develop, build and deploy"** — the routine
sync-and-redeploy of the local pi-agent-dashboard instance. The *real* objective grew
during the session: (a) sync `develop`, rebuild the web client, restart the server; and
after the operator spotted a UI bug — (b) fix the folder Automations section that showed
**"N flows"** where it should read **"N tasks"**, in all locales; then (c) once upstream
shipped the canonical fix, discard the now-redundant local edit and fast-forward to it —
all while a background SmartGit kept racing the working tree with `index.lock`.

## 2. TL;DR playbook

1. **Sync + deploy:** stash local edits → `git pull --ff-only origin develop` → drop any
   duplicate stash → `npm run build` → `POST /api/restart` → poll `/api/health` for `mode`.
2. **If the build fails on a missing workspace symlink**, run `npm install` (a new
   workspace like `hermes-memory-plugin` was added since your last install), then rebuild.
3. **Locate the UI string** with a scoped grep, not a whole-repo scan:
   `grep -rniE "'flows'|\"flows\"" packages/automation-plugin/src/`.
4. **Fix the fallback AND every locale catalog** together (`FolderAutomationSection.tsx` +
   `i18n.ts` zh-CN/hu) so translations stay at parity.
5. **Rebuild + restart**, then eyeball the live UI (browser screenshot) to confirm the label.
6. **Before landing an uncommitted fix, re-fetch** — the upstream may already carry the
   canonical version. Compare `git log HEAD..origin/develop` and the file's upstream copy.
7. **If upstream is canonical**, `git checkout --` your duplicate edits, stash unrelated WIP,
   `git merge --ff-only origin/develop`, restore the stash, rebuild, restart.
8. **If `index.lock` keeps reappearing** (SmartGit/fsNotifier), wrap each git step in a
   wait-for-lock retry loop rather than deleting the lock once.

## 3. How the collaboration unfolded

**Phase 1 — Sync & first deploy.** The AI checked the branch, stashed the local
`groups.json` edit, pulled `--ff-only` (already up to date at `6385929d5`), and dropped a
duplicate stash. The first `npm run build` failed because the newly-added
`hermes-memory-plugin` workspace wasn't symlinked in `node_modules`; running `npm install`
linked it, and the rebuild + `POST /api/restart` brought the server back in production mode.
*Why it worked:* it treated the build failure as a workspace-linking gap, not a code error.

**Phase 2 — Diagnose the label bug.** On the steering turn ("wrong automation 'flows'
instead of 'tasks'"), the AI grepped the automation plugin, found the count unit fell back
to `"flows"` on line 92 of `FolderAutomationSection.tsx`, and fixed both the component
fallback and the zh-CN / hu catalog keys in `i18n.ts` for locale parity, then rebuilt and
redeployed. A browser screenshot confirmed the label now read "1 tasks".

**Phase 3 — Landing question & the upstream race.** The AI paused to ask how to land the
uncommitted fix, then re-fetched and discovered 5 new commits on `origin/develop` — one of
which (`19cb15daa`, "rename automation unit flows→tasks") was the *exact* canonical fix.
It correctly declared its own edit redundant, discarded it, and fast-forwarded — fighting a
SmartGit-recreated `index.lock` with a retry loop until the merge landed at `19cb15daa`.
A final rebuild + restart deployed the upstream folder-card redesign plus the tasks label.

## 4. Prompts that worked

- **Goal prompt — "pull develop, build and deploy":** terse but unambiguous for a routine
  op the AI already knows the workflow for (rebuild matrix + `/api/restart`). Fine as-is.
- **Steering — "wrong automation 'flows' instead of 'tasks'":** a precise bug report naming
  the wrong string and the right one, so the AI could grep straight to it. Stronger version:
  *"the folder Automations count says 'N flows', should be 'N tasks' — fix the fallback and
  all locale catalogs."*
- **Steering — "now to pull":** short, but it triggered the crucial re-fetch that surfaced
  the upstream canonical fix and avoided a duplicate/conflicting local change.

## 6. Skills, tools & memory created — and why they're effective

No skill or memory was created this session. The workflow is repeatable, though, and two
patterns are worth capturing as project skills if they recur:

- **"deploy-local-dashboard"** — stash → `--ff-only` pull → `npm install` on workspace-link
  failure → `npm run build` → `POST /api/restart` → poll `/api/health`. Removes the
  rediscovery of the rebuild matrix each time. (Overlaps the existing `implement` skill's
  rebuild table — prefer extending that.)
- **"git-under-smartgit"** — a wait-for-`index.lock` retry loop for every git mutation when
  a GUI client races the working tree. Prevents the delete-the-lock-once dead end.

## 7. Pitfalls & dead ends

- **Build fails "workspace not found / not linked":** a new package (`hermes-memory-plugin`)
  was added since your last install → run `npm install`, then rebuild. Not a code error.
- **Duplicate local fix vs. upstream:** you can independently fix a bug that upstream already
  fixed. Always `git fetch` + diff `HEAD..origin/develop` on the affected files before
  committing — then `git checkout --` your redundant edits and fast-forward.
- **`index.lock` reappears immediately after deletion:** SmartGit's fsNotifier is running
  concurrent ops. Deleting the lock once loses the race; loop with a wait-for-lock guard.
- **`package-lock.json` shows untracked** after the workspace-link `npm install` — expected
  side effect; leave it unless you intend to commit the new workspace wiring.
