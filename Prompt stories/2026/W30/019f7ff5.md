# How we did it: De-risk an npm→pnpm migration into an applyable OpenSpec change — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) as an open-ended thinking
partnership. The real objective crystallised at the third prompt:

> "There is a problem in electron build: EALLOWGIT refuses the `@electron/node-gyp`
> git dep. Is pnpm can resolve this problem?"

The true goal, once steering clarified it: **decide whether migrating the repo's
dev/CI/build toolchain from npm to pnpm is worth it — but ground every risk claim in
real, isolated experiments rather than theory, then convert the exploration into a
fully-validated, applyable OpenSpec change** (`adopt-pnpm-for-dev-ci`). The proposal's
framing: `npm` is used across the repo in **three distinct roles** with different
constraints (A = dev/CI/build, movable; B = publish/OIDC, keep npm; C = user-machine
runtime, keep npm). Only role A is a migration candidate.

## 2. TL;DR playbook

1. **Enter explore mode** (`openspec-explore`) — investigate, never implement. Trace
   how the tool-in-question (npm) is actually used before proposing to replace it.
2. **Turn a vague fear into testable hypotheses.** List each risk (EALLOWGIT, native
   compile, workspace linking, phantom deps, electron packaging) as a row in a risk
   table with a "theory vs. data" column.
3. **Spike every risk in throwaway temp dirs and detached git worktrees** — never touch
   the live repo, lockfile, or `node_modules`. Prove/disprove each hypothesis with an
   exit code or a `require()`+`spawn()` smoke test.
4. **Drive the full chain to a real artifact** (here: `electron-forge package` →
   `.app`). "It installs" is not "it ships"; only the end-to-end run flips a NO-GO.
5. **When a NO-GO appears, root-cause it** — read the failing script (`bundle-server.mjs`
   `cpSync`), find the one-line fix (`node_modules` filter, `nodeLinker: hoisted`),
   re-run, confirm GO.
6. **Capture durable knowledge** in a project skill (`pnpm-migration-spike`) + a compact
   project memory pointing at the proposal as the full decision record.
7. **Convert the exploration to OpenSpec artifacts** — `proposal.md`, `design.md`,
   `tasks.md`, spec delta — then `openspec validate --strict`.
8. **Run `plan-proposal`**: doubt-driven-review (cross-model, auto on `@propose-review-1`)
   → reconcile each finding against the repo → scenario-design → fold into `tasks.md`
   → commit at the git-worktree boundary. Stop there.

## 3. How the collaboration unfolded

**Phase 1 — Discovery / trace (explore mode).** The AI grepped `src` + `packages` for
every `npm/npx/pnpm/yarn` invocation to establish where the package manager is load-
bearing, producing the "three roles" framing. Human steered with a single word:
`trace`. *Why it worked:* mapping actual usage before proposing a swap prevented the
classic "migrate everything" over-reach — role B (publish/OIDC) and role C (runtime)
were carved out as keep-npm from the start.

**Phase 2 — Hypothesis → spikes.** Prompted by "Can you do some tests… to gather the
risk parts?", the AI ran isolated experiments in `mktemp` dirs: the `@electron/node-gyp`
git spec under npm vs pnpm (pnpm fetches via HTTPS codeload tarball — no ssh key), and
node-pty native load under pnpm's symlinked layout (loads + spawns via shipped
prebuilds; the `ERR_PNPM_IGNORED_BUILDS` gate is cosmetic for it). *Why it worked:* each
spike answered exactly one question with an exit code, and every finding was recorded in
a running risk table.

**Phase 3 — Full-chain worktree spike.** The decisive test — `electron-forge` packaging —
ran in a **detached git worktree** so the live checkout stayed npm. This surfaced the
real blockers in order: workspace linking (`linkWorkspacePackages: true` in
`pnpm-workspace.yaml`, *not* `.npmrc`), `ERR_PNPM_EXOTIC_SUBDEP` (config knob
`blockExoticSubdeps: false`), and phantom deps. *Decision point:* the human said
"Finish the last spike" — pushing past "install works" to a real `.app`.

**Phase 4 — NO-GO → GO investigation.** After the AI reported electron packaging as
🔴 NO-GO, the human steered: "electron packaging NO-GO - investigate the possible fix."
The AI read `bundle-server.mjs`, found `cpSync` copying pnpm's broken store-symlinks into
the bundle (→ empty node-pty prebuilds), fixed it with a one-line `node_modules` filter,
and discovered electron-forge **self-documents** its requirement (`nodeLinker: hoisted`).
Drove the full chain to a 554M `PI-Dashboard.app` with all 6 node-pty prebuild triples.

**Phase 5 — Capture + convert.** Saved the reusable procedure as project skill
`pnpm-migration-spike` and a compact project memory (memory was near its 5000-char cap —
the AI wrote a pointer instead of force-evicting). Then `turn` → wrote `proposal.md`,
`design.md`, `tasks.md`, spec delta; `openspec validate --strict` passed.

**Phase 6 — plan-proposal (doubt + scenarios).** The `plan-proposal` skill ran a
**cross-model** doubt-driven-review on `@propose-review-1` (glm-5.2, different family).
Cycle 1 found ~9 confirmed release-breaking gaps (the `release-cut` skill still doing
`npm install --package-lock-only`; `cache: npm` in all 6 workflows; wrong Column C
paths). Cycle 2 caught 2 over-corrections the AI's own blanket "flip EVERY workflow"
introduced (`deploy-site.yml` dual-install, `_smoke.yml` engine-strict override). Then
scenario-design produced `test-plan.md`, 16 scenarios folded 1:1 into `tasks.md`,
committed at the worktree boundary. A final steering turn ("investigate gates the
irreversible lockfile swap") hardened the release-ordering gate.

## 4. Prompts that worked

- **Goal prompt** (`openspec-explore` + "Is pnpm can resolve this problem?"): effective
  because it framed a *decision* to investigate, not a task to implement — keeping the
  AI in read/spike mode.
- **"Can you do some tests… to gather the risk parts?"** — the highest-leverage prompt.
  It converted a theoretical risk assessment into empirical spikes. Rewrite for reuse:
  *"Spike each risk in an isolated temp dir / worktree; give me a theory-vs-data table
  with exit codes."*
- **"Finish the last spike"** / **"electron packaging NO-GO - investigate the possible
  fix"** — short redirects that forced the work past "install passes" to a shipping
  artifact and a root-caused fix. The pattern: *don't accept a NO-GO without a
  root-cause + attempted fix.*
- **One-word steers** (`trace`, `run`, `2`, `1`, `commit`, `turn`) worked only because
  the AI had already laid out numbered options / next steps — cheap confirmations on a
  well-structured menu.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| assess risk from theory | "Can you do some tests…?" | default to spikes-in-isolation for any migration claim |
| stop at "install works" | "Finish the last spike" | require the full chain to a shipping artifact before a GO/NO-GO |
| report a bare 🔴 NO-GO | "investigate the possible fix" | pair every NO-GO with a root-cause + one attempted fix |
| over-correct with a blanket rule ("flip EVERY workflow") | rely on cross-model cycle-2 to catch it | verify each mechanical edit against the repo, not a global assumption |
| risk touching the live repo | (AI self-guarded) worktrees + temp dirs | always spike in `mktemp` / `git worktree --detach`; assert live repo untouched |

Scope discipline was strong: the AI carved npm's roles B (publish/OIDC) and C (runtime)
as keep-npm early, so "migrate to pnpm" never ballooned into "rip npm out."

## 6. Skills, tools & memory created — and why they're effective

- **Skill `pnpm-migration-spike`** (project) — captures the whole reusable procedure:
  the 3-role npm split, the isolated-worktree method, the proven pnpm-11
  `pnpm-workspace.yaml` config, the ordered blocker→fix list (EALLOWGIT / exotic-subdep /
  phantom-deps / electron NO-GO→GO), the `npm@11.12.1` tactical unblock, and cleanup.
  *Effective because* it lets a future run skip re-discovering that pnpm-11 config moved
  out of `.npmrc`, that node-pty ships prebuilds, and that electron-forge demands
  `nodeLinker: hoisted`. Auto-loads on triggers like EALLOWGIT / pnpm evaluation.
- **Two project memories** — compact pointers to
  `openspec/changes/adopt-pnpm-for-dev-ci/proposal.md` as the full decision record, with
  the load-bearing facts (keep npm for publish+runtime; pnpm-11 config lives in
  `pnpm-workspace.yaml`). *Effective because* they survive the 5000-char cap by
  delegating detail to the proposal rather than duplicating it.
- **Cross-model reviewer subagent** (`@propose-review-1` = glm-5.2) — a *different model
  family* adversarially reviewing the plan. *Effective because* it found genuine
  release-breaking gaps a same-family self-review would rationalise away.

## 7. Pitfalls & dead ends

- **pnpm-11 config location:** `onlyBuiltDependencies` / `linkWorkspacePackages` in
  `.npmrc` or `package.json#pnpm` are **silently ignored** by pnpm 11 — they must live in
  `pnpm-workspace.yaml` (camelCase). If a knob "does nothing," it's in the wrong file.
- **"Install works" ≠ "ships":** the client build passing under `shamefullyHoist` hid the
  real electron blockers. Only `electron-forge package` exposed them.
- **`cpSync` + pnpm symlinks:** `bundle-server.mjs` copied `packages/*/node_modules`
  (broken store-symlinks under pnpm) into the bundle → empty node-pty prebuilds. Fix =
  one-line `node_modules` filter (and it's npm-safe).
- **Grep-artifact false positives:** the scariest "architectural cycles in `shared`" were
  test-fixture string literals in `__tests__/*.test.ts`, not real imports. Always
  distinguish source imports from test regex fixtures before declaring a cycle.
- **Buggy pnpm 11.0.8:** `pnpm -r build` crashed (`runDepsStatusCheck`) — fixed with
  `verifyDepsBeforeRun: false`; isolate the electron question via `npx pnpm@latest`
  rather than bumping the global pnpm.
- **Blanket edits over-correct:** "flip `cache: npm` in EVERY workflow" broke
  `deploy-site.yml` (separate `site/` lockfile) and `_smoke.yml` (`--engine-strict=false`
  override). Verify each workflow individually.
- **Vestigial pnpm files:** the repo already had a stale git-tracked `pnpm-lock.yaml` +
  placeholder `pnpm-workspace.yaml` from genesis, referenced by nothing — deleted safely
  after confirming `findMonorepoRoot()` falls back to `package.json workspaces`.
