# How we did it: Compacting the sidebar folder header — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) to chase a bug: the
sidebar folder header showed a `Terminals(0)` button that opened an empty Editor pane,
and a **duplicated terminal header** appeared inside the pane. The first steering turn
(`Duplicate header` + screenshot) narrowed the real target. But the *true* objective
crystallized on the third prompt: the folder-group header wasted three rows on controls
— stop treating this as a one-off bug and instead **remove the now-redundant
`Terminals`/`Editor` buttons** (that function already lives in Directory/ChatView) and
**merge the git row and surviving actions into one compact row**, validated with UX
mockups before touching code.

## 2. TL;DR playbook

1. **Enter explore mode first** to diagnose without implementing — trace the real
   component (`FolderActionBar.tsx` rendered by `SessionList.tsx`) via `kb_search` +
   targeted `grep`, and map the button-wiring in `App.tsx`.
2. **Prove the redundancy** before removing anything: confirm both callbacks
   (`onOpenTerminals`, `onOpenEditor`) navigate to the *byte-identical* URL, and that
   the feature stays reachable from `DirectoryHomeView.tsx`.
3. **Build an interactive mockup** (`serve_mockup`) with the current state + 2–3
   compaction variants using the **real theme tokens**; screenshot it and let the
   human pick a variant by letter (`A`/`B`).
4. **TDD the removal**: flip the test from "renders Terminals" to "Terminals **and**
   Editor absent", watch it fail, then edit `FolderActionBar.tsx` + `SessionList.tsx`
   + `App.tsx`, deleting orphaned props/memos/imports.
5. **Build + restart** (client change → `npm run build` + `POST /api/restart`) and
   **visually verify** the live dashboard renders the chosen variant.
6. **Catch the state you forgot**: re-check the *failure/running* states — the wide
   `WorktreeInitChip` (`min-w-[240px]`) overflows an inline `shrink-0` row. Fix with
   `flex-wrap justify-between` so the wide chip drops to its own line.
7. **Fold into an OpenSpec change** post-hoc (proposal + tasks-all-done + delta spec),
   `openspec validate --strict`, then archive + sync the main spec.

## 3. How the collaboration unfolded

**Phase 1 — Discovery (explore mode).** The AI stayed disciplined: it read
`FolderActionBar.tsx`, `SessionList.tsx`, `App.tsx`, and traced the terminal-pane
layering (`EditorPane` header → `EditorTabs` → `TerminalView`), producing a crisp
diagnosis table (three places rendered the terminal title; #3 the `TerminalView`
"Minimal terminal header" was the duplicate). *Why it worked:* it refused to implement
in explore mode and instead delivered a fix-options table for later.

**Phase 2 — Redesign via mockup.** On the "remove buttons + compact" ask, the AI read
the *real* folder-header structure and theme tokens, then served an interactive mockup
with current + compaction variants. The human validated by typing a single letter.
*Decision point:* human picked **variant B** (git row + Initialize + gear merged into
one right-grouped row; Terminals/Editor gone).

**Phase 3 — Safe removal (TDD).** The AI first verified the feature stayed reachable
elsewhere, mapped the orphan cascade (`terminalsByCwd` memo, `TerminalSession` import,
three `App.tsx` props), wrote the test assertion first, then made the edits. `tsc`
clean (only 2 pre-existing unrelated errors), 44 tests pass.

**Phase 4 — Deploy + visual verify.** `npm run build` + `POST /api/restart`, then
browser-screenshot the live folder card to confirm variant B.

**Phase 5 — The regression the design missed.** Human: "The design is flaky on error".
The merged inline row (`ml-auto shrink-0`) only accounted for the *small idle* button;
the wide failure/running chip overflowed the ~290px sidebar. The AI reproduced it in a
width-accurate mockup (the live failure state was ephemeral and couldn't be re-triggered
on demand), fixed with `flex-wrap items-center justify-between`, redeployed.

**Phase 6 — Record + archive.** Folded the landed change into
`compact-folder-header-actions` (proposal/tasks/delta spec), validated, and discovered
a parallel session had already committed the identical change as `1b7d2a862`. Confirmed
`git diff HEAD` empty, then archived + synced the main `folder-action-bar` spec
(`395cb5dd3`), carefully staging only its own files.

## 4. Prompts that worked

- **Goal prompt (`openspec-explore`)** — starting in explore mode forced diagnosis
  before code, which surfaced that the two buttons were *identical* nav (the whole
  justification for removal). Effective because it front-loaded understanding.
- **"remove … Make mockups to ux validations"** — the highest-leverage prompt: it set
  both the scope (remove Terminals/Editor) *and* the quality bar (validate UX with
  mockups first). Rewrite of a weak version like "make the header smaller".
- **Single-letter picks (`B`, `A`)** — a mockup with lettered variants turns a design
  decision into a one-keystroke unlock. Cheap, unambiguous steering.
- **"The design is flaky on error" + screenshot** — a screenshot of the broken state
  is worth a paragraph; it pinned the exact overflow the happy-path design missed.

## 5. Steering & corrections (what to watch for)

|-------------------|----------------------------|----------------------------|
| Treat the report as a single bug | "Duplicate header" + "remove … the buttons … make it compact" | State the full scope up front: "remove redundant buttons AND compact the row" |

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was saved, but the session leaned on existing assets worth
naming:

- **`serve_mockup` + `score_mockup` + `browser` screenshot loop** — the reusable move
  is *mockup-before-implement with real theme tokens and lettered variants*. It removes
  guesswork from UX decisions and makes the choice a one-keystroke reply. Invoke it
  whenever a layout change has >1 plausible arrangement.
- **`implement` rebuild matrix** — client change → `npm run build` + `POST /api/restart`
  (production). Following it made deploy deterministic.
- **OpenSpec post-hoc fold** (`openspec-archive-change`) — recording a landed change as
  proposal + tasks-done + delta spec, then `validate --strict` and archive-with-sync.
  Keeps the capability spec honest even when code lands first.

**Recommended skill to create:** *"verify all component states before merging layout
rows"* — the failure-chip overflow was entirely predictable from
`WorktreeInitChip`'s `min-w-[240px] max-w-[460px]`.

## 7. Pitfalls & dead ends

- **`grep -rn "Terminals(" src/client`** failed — the client lives in
  `packages/client/src`, not `src/client`. Use the `packages/` path.
- **`npx vitest` needed `HOME=$(mktemp -d)`** to run cleanly in this repo.
- **`biome check --changed` processed 0 files** (git-diff base detected nothing) — a
  harness quirk, not a clean bill; rely on scoped `tsc` + targeted tests too.
- **Live ephemeral failure state can't be re-triggered on demand** (init hook resolved
  as a no-op) — verify the fix with a width-accurate mockup reproducing the real chip
  dimensions at ~290px sidebar width.
- **Busy multi-session repo:** a parallel session committed the identical change first.
  Always `git diff HEAD` before assuming there's anything to commit, and never stage a
  sibling session's untracked dir (`harden-worktree-init-corepack/` was left alone).
