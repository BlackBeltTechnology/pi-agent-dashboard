# How we did it: Directory Initialize fails on `corepack: command not found` — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The operator hit a dashboard **Directory Initialize** failure and opened the session in
**explore mode** (`openspec-explore`) with a screenshot of the failing panel. The literal
first prompt was the boilerplate explore-mode skill preamble ("Enter explore mode. Think
deeply… you must NEVER write code"), but the *real* objective — clear from the very first
assistant turn — was: **find out why "Directory Initialize" dies with
`bash: corepack: command not found`, and capture a fix as an OpenSpec change without touching
source in explore mode.** The scope grew across the session into: diagnose → author a change
proposal → (on the green light) implement, verify, doc, commit, and archive it.

## 2. TL;DR playbook

1. **Start in explore mode** with the exact error string and a screenshot of the panel. Ask
   the AI to *trace the command's origin*, not just guess a fix.
2. Let it find that **Directory Initialize runs `worktreeInit.run.command` from
   `.pi/settings.json`**, whose first segment is `corepack enable`.
3. Have it identify **why corepack is missing**: the dashboard runs the hook under its
   *bundled, stripped* Node (`~/.pi-dashboard/node/bin/node`), and
   `packages/electron/scripts/download-node.sh` deliberately `rm -rf`s corepack to save space.
4. Approve the **best-effort guard** fix (one line): change
   `corepack enable &&` → `command -v corepack >/dev/null 2>&1 && corepack enable;` — note the
   `;` not `&&`, so corepack's absence can't abort the chain.
5. `openspec new change harden-worktree-init-corepack` → write a **lean proposal + tasks**;
   add **one ADDED coherence requirement** to `worktree-init-hook` (spec-driven schema needs
   ≥1 delta). No `design.md` for a one-line config fix.
6. Implement in place: edit `.pi/settings.json`, **verify the guard both ways** in a
   sandboxed shell (corepack absent → chain reaches install; corepack present via shim →
   activator still runs), and prove the open-gate retry loop clears.
7. Delegate the **FAQ known-issue note to DocScribe** (caveman style — all `docs/` writes go
   through DocScribe per AGENTS.md).
8. **Commit only this change's files** (stage explicitly — an unrelated `image-fit` change was
   dirty in the tree), then `/opsx-archive` and **sync the delta** into the main spec.

## 3. How the collaboration unfolded

**Phase A — Diagnosis (explore mode, zero edits).** The AI read the error, corrected its own
first guess (the screenshot showed the *Directory Initialize* panel, not the worktree hook),
then traced the command to `worktreeInit.run.command` in `.pi/settings.json`. It kept going
to the *root cause*: the bundled Node has no corepack because `download-node.sh` strips it on
purpose. **Why it worked:** the AI didn't stop at "install corepack" — it followed the chain
to the packaging script, which is what made "best-effort guard, don't reinstall corepack" the
obviously-correct fix. The human's steering here was minimal because the AI framed the choice
clearly.

**Phase B — Capture the fix as a proposal.** On the "A" go-ahead (Option A), the AI scaffolded
`harden-worktree-init-corepack`. It initially reasoned "no engine requirement changes needed",
then adjusted when the **spec-driven schema demanded ≥1 delta** — landing on a clean *ADDED
coherence requirement* that matched the existing `worktree-init-hook` pattern ("Gate SHALL
cover every asset the run restores"). It fixed a validator complaint (SHALL must lead the line
after the header) and got a clean `openspec validate`.

**Phase C — Implement + verify.** After the `/opsx-apply` steer, the AI edited
`.pi/settings.json`, confirmed valid JSON and an unchanged gate, then **verified the guard in a
sandbox** without re-running the real install chain: corepack-absent (this machine's real
shell) fell through to on-PATH `pnpm@11.15.1`; a corepack shim proved the activator still
runs; and it demonstrated the gate clears once `.modules.yaml` exists so the retry loop won't
re-fire.

**Phase D — Doc, commit, archive.** FAQ note delegated to **DocScribe** (caveman style). On
`commit`, the AI **staged only the 7 change files**, leaving the unrelated `image-fit` work
untouched. On the archive steer it confirmed two decisions (archive despite no `design.md`;
sync the delta now), appended the requirement to the main spec, archived, and committed the
move — two clean commits on `develop`.

## 4. Prompts that worked

- **The goal prompt (explore mode + error + screenshot).** Effective because it framed the
  work as *investigation first*, forbidding premature edits. A stronger, non-boilerplate
  kickoff: *"Explore mode. Directory Initialize fails with `bash: corepack: command not found`.
  Trace where that command comes from and why corepack is missing before proposing a fix."*
- **`A`** (steering #1) — a one-character unlock. It worked only because the AI had already
  laid out labeled options (Option A = best-effort guard). **Lesson:** make the AI enumerate
  labeled options so approval can be a single token.
- **`/opsx-apply` skill prompt** (steering #2) — moved from captured-proposal to implementation
  cleanly because the *same session authored the artifacts*, so context carried over.
- **`commit`** (steering #3) — trusted the AI to stage correctly; it did the right thing by
  staging only the change's files.
- **`/opsx-archive`** (steering #4) — closed the loop with a spec sync.

  The whole diagnose-to-archive arc ran on the OpenSpec skill workflow, keeping the fix as a

- **`DocScribe` subagent** for the FAQ note. Effective because `docs/` writes are

- **Recommended new memory:** *"Dashboard runs `worktreeInit`/Directory Initialize under the
  bundled stripped Node (`~/.pi-dashboard/node/bin/node`) — no corepack, no npm docs. Hook
  commands must be best-effort-guarded, not assume corepack."* Saving this would short-circuit
  the entire Phase-A trace next time.

## 7. Pitfalls & dead ends

- **`corepack enable &&` in an init hook is a landmine** under the bundled Node — it hard-fails
  before `pnpm install` even starts. If Directory Initialize dies at step 1, check whether the
  hook assumes corepack; guard it with `command -v corepack >/dev/null 2>&1 && corepack enable;`
  (semicolon, not `&&`).
- **Spec-driven schema rejects a zero-delta change.** If `openspec validate` complains, add one
  coherence requirement that matches the existing spec pattern rather than inventing engine
  behavior.
- **Validator wants SHALL first** on the line right after a `### Requirement:` header — lead with
  the SHALL statement.
- **Don't verify by re-running the real install** — it re-inits the repo. Stub the install tail
  with `echo` and test only the guard branch.
- **Unrelated dirty files in the tree** (here `image-fit-tool-result-images`) — always stage
  explicitly so an unrelated WIP doesn't ride along in the commit.
