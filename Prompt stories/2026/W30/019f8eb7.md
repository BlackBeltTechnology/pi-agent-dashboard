# How we did it: Align the session-card KB slot surface — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was

## 1. Goal (the ask)

The session opened in **explore mode** ("Enter explore mode. Think deeply… you must
NEVER write code or implement features"), so the first prompt was a *stance*, not a
concrete task. The real objective surfaced immediately once exploration began: on a
worktree **session card**, the `KNOWLEDGE BASE` row renders as a bright, raised,
opaque white card while its siblings (`OPENSPEC` / `GIT` / `PROCESS`) are flat,
translucent, tinted subcard panels. The KB row is the lone visual outlier. The goal:
**diagnose why, then align the KB slot's surface with its sibling subcards** — carried
all the way from explore → proposal → mockup → apply → build+deploy+verify →
archive → commit+push, in one sitting.

## 2. TL;DR playbook

1. **Explore first, don't code.** Enter explore mode and trace the two rendering
   primitives sitting side-by-side. Root cause here: native subcards use
   `SessionSubcard.tsx` (translucent `--bg-surface` @ 50%, no shadow); the KB row
   uses `SlotPill.tsx` (opaque `--bg-secondary` + shadow).
2. **"draw proposal"** — turn the diagnosis into an OpenSpec change
   (`align-session-card-kb-slot-surface`): proposal + design (decision D1 + rejected
   alternatives) + tasks + spec delta. Validate `--strict`.
3. **"frontend-mockup"** — harvest the *real* theme tokens from `index.css`, build a
   before/after HTML mockup with a live dark/light toggle, `serve_mockup`, verify
   visually (agent-browser if Playwright shell is absent).
4. **Apply the change.** Thread a new `surface?: "raised" | "flat"` prop through
   `SlotPill`, a `placement` prop through the slot props/consumers, and have
   `FolderKbSection` map `placement:"card" → flat`. Default stays `raised` so the
   sidebar is untouched.
5. **Write the tests first-class:** `SlotPill.test.tsx` (variant bg/shadow),
   `slot-consumers.test.tsx` (`WorktreeCardSectionSlot` passes `placement:"card"`),
   `FolderKbSection.test.tsx` (placement→surface). Run with an **ephemeral HOME guard**
   (`HOME=$(mktemp -d) npx vitest run …`).
6. **"build and deploy and verify with browser"** — `npm run build` → `POST /api/restart`
   → probe `/api/health` for `mode:production` + uptime reset → browser-verify.
7. **Archive + sync specs**, then **commit only this change's files** (exclude other
   parallel sessions' edits) and push to `develop`.

## 3. How the collaboration unfolded

**Discovery (explore mode).** The AI ran `rg`/`kb_search` to locate the KB slot and
the native subcards, then produced a crisp root-cause diagram showing two rendering
primitives with different background contracts. The effective bit: it *named the two
components and the exact CSS var mismatch* before proposing anything — no speculation.

**Proposal ("draw proposal").** It authored four artifacts and validated `--strict`.
Design.md captured the chosen decision **D1** (add a `surface` variant to `SlotPill`)
and, crucially, the **rejected alternatives** (don't flip `SlotPill`'s bg globally —
it's shared with the sidebar; don't wrap the consumer). Decision point: keep the
sidebar's raised look as the *default* so only the session-card placement flips.

**Design/mockup ("frontend-mockup" → "show mockup" → "stop").** Rather than guess
colors, the AI **harvested real tokens** from `index.css` (`--bg-secondary`,
`color-mix(--bg-surface 50%)`, `--shadow-card`, `--border-subtle`) so the mockup was
token-accurate in both themes. Playwright shell was missing, so it fell back to
agent-browser for the visual capture and self-scored a rubric (token fidelity,
AA contrast, hierarchy, anti-slop). The human reviewed and said "stop".

**Apply.** Four surgical source edits + three test files. A stray brace slipped in and
was immediately fixed. Tests were run under an ephemeral `HOME` to avoid config
bleed. 11/12 tasks done; the one deferred task was the live 4-theme visual QA.

**Build/deploy/verify.** `npm run build` → `/api/restart` → `/api/health` confirmed
`mode:production` + a 5s uptime (fresh bundle). The AI confirmed the sidebar KB pills
stayed **raised** live, but **could not** screenshot the flat variant because there
were **zero active worktree sessions** — it reported that honestly instead of faking
proof, leaning on the tests + token-accurate mockup.

**Archive + commit.** Synced the one ADDED requirement into the main
`directory-card-layout` spec, archived the change, then **committed only this change's
14 files**, explicitly excluding edits from other parallel sessions
(`groups.json`, `docs/AGENTS.md`, video-transcription, etc.). Pushed to `develop`.

  clean diagnosis *before* any code. A stronger kickoff would name the artifact and
  the constraint up front: *"Explore why the KB row on a worktree session card looks
  raised/opaque vs its OPENSPEC/GIT/PROCESS siblings; do not code — end with a proposal."*
- **High-leverage follow-ups (all tiny, all unlocked a phase):**
  - `draw proposal` → produced the full OpenSpec change set from the diagnosis.
  - `frontend-mockup` → token-accurate before/after with live theme toggle.
  - `build and deploy and verify with browser` → the whole ship-to-live loop.
  - `commit and push` → scoped commit of only this change's files.
- These worked because the **earlier phases had loaded rich context** (root cause,
  design decision, file list), so a two-word prompt was enough to drive the next stage.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Keep serving/iterating the mockup | `stop` | Say "build the mockup, verify once, then stop — don't keep serving" |
| Stay in the explore/artifact loop | invoke `openspec-apply-change` | Chain explore→apply explicitly when the diagnosis is already firm |
| Try to fully verify live even when impossible | accept the honest partial-verify | State the acceptance bar: "tests + mockup suffice if no live worktree session exists" |
| Risk committing unrelated working-tree edits | `commit and push` (AI self-scoped) | Always `git add` only the change's file set; verify ambiguous files' provenance first |

Quality bars the human implicitly imposed: token-accurate mockups (not eyeballed),
`--strict` validation, tests-first, and a clean commit that doesn't sweep up other
parallel sessions' changes.

## 7. Pitfalls & dead ends

- **Playwright shell missing** → don't block; fall back to **agent-browser** for the
  visual capture.
- **Vitest config bleed** → prefix runs with `HOME=$(mktemp -d)` (ephemeral HOME guard).
- **Vitest only prints test names on failure** → to *confirm* a suite ran, run its file
  explicitly with `--reporter=verbose`.
- **Live worktree verification impossible** → the KB subcard only renders on
  **active/expanded worktree** session cards; ended worktree cards are compact
  (header + branch only). `/session/:id` is the *chat* view, not the list card. If
  none are active, accept tests + mockup as proof and say so.
- **Browser list scrolling fights you** → the app uses an inner scroll container the
  window-scroll command can't reach; `press End`/`press Home` (keyboard) works where
  `scroll` doesn't. Live session-list refresh **invalidates snapshot refs** — re-snapshot.
- **Commit scope** → the working tree held other parallel sessions' edits; verify
  provenance of ambiguous files (`groups.json`, `docs/AGENTS.md`) before staging, and
  add only your change's files.
