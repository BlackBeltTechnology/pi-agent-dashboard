# How we did it: Bubblewrap vs Capacitor for a mobile pi-dashboard — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore` skill) — a thinking-partner
stance, explicitly *not* implementation. The bare kickoff was one word of intent:
**"Bubblewrap"**, dropped into the pi-dashboard repo. The *real* objective, which the
AI inferred from repo context and the user's follow-up, was: **decide how to ship the
pi-dashboard web client as a native mobile app** — is Google Bubblewrap (PWA → Android
TWA) the right vehicle, and how does it compare to Capacitor? The deliverable ended up
being a comprehensive research doc under `docs/research/`.

## 2. TL;DR playbook

1. Enter explore mode (`openspec-explore`) so the AI investigates without implementing.
2. First move: **disambiguate the term** — run a repo-wide grep for `bubblewrap|bwrap|TWA|PWA|manifest|android` to learn which "Bubblewrap" (Google TWA CLI vs Linux `bwrap` sandbox) is in play.
3. **Inventory the substrate** in parallel: `public/manifest.json`, `public/sw.js`, icons, the Electron wrap (`packages/electron`), the pairing shell — establish "what platform-wrap pieces already exist."
4. **Fetch authoritative external docs** (`ctx_fetch_and_index` on Bubblewrap/TWA docs), then `ctx_search` the pulled corpus for the hard technical constraints (Digital Asset Links / origin lock).
5. Deliver the "research transfer" inline: a **disambiguation table**, a **platform-wrap matrix**, and the **decisive constraint** (TWA locks to one verified origin — hostile to per-user dynamic tunnels).
6. On the steering question "what's the difference with Capacitor?", answer with a **philosophy split** (remote Chrome tab vs bundled WebView) + a feature comparison table.
7. When asked to persist: **match the existing `docs/research/` prose style** (read a sibling doc first), write the artifact, and add a **caveman-style index row** to `docs/AGENTS.md`, path-alphabetical.

## 3. How the collaboration unfolded

**Phase 1 — Disambiguate (Discovery).** The AI's first instinct was correct and high-value:
the word "Bubblewrap" is ambiguous (Google's PWA→APK CLI vs the Linux `bwrap` sandbox).
Instead of guessing, it grepped the whole repo for both meanings and used the *context*
(PWA manifest, service worker, Electron shell) to conclude the user meant **Google
Bubblewrap → an Android app**, while still flagging the `bwrap` reading at the end.

**Phase 2 — Inventory the substrate (Gather).** Parallel bash calls mapped what already
exists: the dashboard *already* ships as a PWA with an Electron desktop wrap and a static
pairing shell. Conclusion worth repeating: **zero repo references to TWA/APK, but the
substrate is ~90% of what a TWA needs.** This reframed the question from "build from
scratch" to "close the last 10%."

**Phase 3 — Fetch external truth (Gather).** Rather than reason from memory, the AI pulled
authoritative Bubblewrap/TWA docs via `ctx_fetch_and_index` and searched them for the
binding constraints. This surfaced the **decisive origin constraint**: TWA's Digital
Asset Links lock forces a single verified origin (`pi-dashboard.dev`), which is
fundamentally incompatible with per-user dynamic tunnels.

**Phase 4 — Compare on request (Design).** The human steered with one short question:
*"What is the different with capacitor?"* The AI answered with a crisp **philosophy split**
— TWA runs the user's real Chrome against a *remote* origin; Capacitor bundles the web
dist *locally* inside a WebView you own — and showed why Capacitor sidesteps the exact
origin friction (plus iOS, native push, secure-storage keyring).

**Phase 5 — Persist matching precedent (Generate + Verify).** When asked to save, the AI
did the right thing: **read an existing `docs/research/` doc first** to learn the
established style (comprehensive prose + Mermaid + tables), matched it, then added the
**caveman-compressed** index row to `docs/AGENTS.md` — correctly distinguishing prose
style (research doc) from caveman style (AGENTS tree row).

## 4. Prompts that worked

  the repo context was rich and the AI's first act was disambiguation, not assumption.
  A stronger kickoff for a future user: *"In explore mode: evaluate shipping the

- **Persist prompt — "save this session as a comprehensive research results and save to
  docs/research".** Effective because it named the destination directory, letting the AI
  find and match an existing precedent.

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was created. The workflow is, however, clearly repeatable — a
**"research-transfer in explore mode"** pattern:

1. Disambiguate the term (grep repo for all meanings).
2. Inventory existing substrate in parallel.
3. Fetch authoritative external docs (`ctx_fetch_and_index` + `ctx_search`), don't reason from memory.
4. Deliver disambiguation table → substrate matrix → decisive constraint → alternatives comparison → verdict.
5. Persist by matching `docs/research/` precedent + caveman `docs/AGENTS.md` row.

Tools that carried the weight: **`ctx_fetch_and_index` / `ctx_search`** (authoritative
external grounding, kept raw bytes out of context), parallel **`bash`** greps (substrate
inventory), **`canvas`** (surfaced the final doc). Worth codifying as a project skill if
this "explore → research doc" flow recurs.

## 7. Pitfalls & dead ends

- **Ambiguous library name.** "Bubblewrap" collides with the Linux `bwrap` sandbox — always
  disambiguate before researching, or you'll research the wrong tool.
- **The origin trap.** TWA's Digital Asset Links pins the app to a *single* verified origin.
  If your product relies on per-user dynamic tunnels, a naïve TWA wrap is a dead end — this
  is the constraint that makes Capacitor the durable answer.
- **One failed bash + one failed `ctx_batch_execute`** during discovery (globbing/path
  probes for `packages/`, `public/`). Non-fatal — the AI re-probed with narrower paths.
  If a broad inventory command errors, fall back to targeted `ls`/`cat` on known dirs.
- **Style mismatch risk.** `docs/research/` uses comprehensive prose + Mermaid; the AGENTS
  tree uses caveman rows. Don't cross the streams — read a precedent doc before writing.
