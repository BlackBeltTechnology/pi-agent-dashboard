# How we did it: excluding already-hidden sessions from "Clean up broken" — an AI collaboration guideline

## 1. Goal (the ask)

The user opened with a screenshot and a one-line, slightly rough report:

> "Maybe some changes causes that already hided sessions shown as clenup items [image]"

The *real* objective, once decoded: a recent change caused **already-hidden broken
sessions to reappear as "Clean up broken" candidates**. Since "Clean up broken" works
by *hiding* sessions, sessions that are already hidden should never be counted or
re-hidden. The fix had to make the count and the cleanup action ignore anything already
hidden — a targeted client-side bug fix, then commit.

## 2. TL;DR playbook

1. Locate the feature by its user-facing string: `grep -rni "clean up broken\|cleanupBroken\|broken" packages/client`.
2. Read the count filter and the cleanup loop — both live in `packages/client/src/components/SessionList.tsx`.
3. Identify the missing predicate: broken = `cwdMissing && status === "ended"`, but the filter never excluded `s.hidden`.
4. Add `&& !s.hidden` to **both** the count filter and the cleanup loop (keep them in lockstep).
5. Run the targeted test in a clean HOME: `HOME=$(mktemp -d) npx vitest run packages/client/src/components/__tests__/FolderActionBar-cleanup-broken.test.tsx`.
6. Ignore the pre-existing tsconfig project-reference error from `npx tsc` — it's unrelated to a one-line change.
7. On "commit", write a descriptive `fix(client):` message explaining the root cause; note it's client-only (rebuild or hot-reload to see live).

## 3. How the collaboration unfolded

**Phase 1 — Discovery (grep by the visible string).** The AI grepped the client for
`"Clean up broken"` / `broken`, narrowing from `src/client` to the real location
`packages/client/src/components/SessionList.tsx` and the sibling `FolderActionBar.tsx`.
*Why it worked:* starting from the exact UI label is the fastest route from a screenshot
bug report to the code path.

**Phase 2 — Root cause.** Reading the count filter and the cleanup loop, the AI saw the
broken predicate (`cwdMissing && status === "ended"`) never excluded already-hidden
sessions. With "Show hidden" on (or hidden sessions otherwise present in
`group.sessions`), already-hidden broken sessions inflated the count and re-triggered a
no-op hide — exactly the reported symptom.

**Phase 3 — Surgical fix + verify.** One `edit`: `&& !s.hidden` added to both the count
filter and the cleanup loop. The AI ran the relevant vitest spec (re-running under a
clean `HOME` after the first attempt), confirmed pass, and correctly dismissed a
`npx tsc` project-reference error as pre-existing noise.

**Phase 4 — Commit.** On the user's "ok, commit", the AI wrote a root-cause-explaining
`fix(client):` message and committed as `bfa667cf`.

## 6. Skills, tools & memory created — and why they're effective

No skill or memory was created — the task was a single-file, one-line bug fix. But the
*pattern* is reusable and worth internalizing rather than skill-ifying:

**Pattern: "filter + action must share the same predicate."** When a count/badge drives a
bulk action, the predicate that computes the count and the predicate that performs the
action must be identical. Here, both needed `&& !s.hidden`. When you fix one, grep for the
other and fix them in lockstep — a mismatch is exactly what produces "N shown but nothing
happens" no-op bugs.

## 7. Pitfalls & dead ends

- **`npx tsc -p packages/client/tsconfig.json --noEmit` reports a project-reference error** —
  this is a **pre-existing** tsconfig issue, not your change. Don't chase it; run the scoped
  vitest spec instead.
- **First vitest run needed a clean HOME** — re-run with `HOME=$(mktemp -d) npx vitest run <spec>`
  if the environment leaks config into the test.
- **Fixing only the count (or only the action)** leaves the bug half-alive. Both the count
  filter and the cleanup loop needed `&& !s.hidden`.
