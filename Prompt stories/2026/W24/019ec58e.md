# How we did it: fix-popover-viewport-flip — an AI collaboration guideline

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) — a "think, don't implement"
stance. The real objective, once the steering clarified it: **the `⚙ View` popover
(`ChatViewMenu`) opens off the bottom of the viewport** because it lives in the
bottom-pinned `StatusBar` but is hard-coded to grow downward (`absolute right-0 mt-1`).
The lower rows ("Use global settings", the tool-call toggles) render past the window edge
and are unreachable. The ask evolved from "fix this one popover" into "**audit every
popover for off-screen risk, then draft an OpenSpec proposal** that fixes the bug the
right way." No code was written — the deliverable is a validated change proposal.

## 2. TL;DR playbook

1. **Enter explore mode** for a bug you don't fully understand yet — it forces
   investigation-before-implementation and keeps you from patching the wrong layer.
2. **Locate the offending component** and read its anchoring CSS
   (`grep -n "absolute\|fixed\|bottom\|top-full\|mt-1"`), then find *where it mounts*
   (`StatusBar` leading slot → bottom of viewport = the real cause).
3. **Decide portal-vs-flip early:** check for a clipping `overflow-hidden` ancestor. None
   here → the clip is the viewport itself → a simple **flip-up** solves it, no portal or
   collision library needed.
4. **Sweep the whole surface:** grep every popover/dropdown in the client, then extract
   each one's *actual anchor strategy* and classify 🔴 buggy / ✅ safe / 🟡 latent.
5. **Ground the proposal in history:** search OpenSpec archives — you may find the spec
   *already requires* the behavior. `grep` the archived change + `git log` the file to
   prove drift.
6. **Scaffold the change** (`openspec change new` or `mkdir -p` the dirs) and write
   proposal / design / tasks / spec deltas.
7. **`openspec validate <change>`** until clean.
8. **Commit surgically:** `git reset -q` first, add only your artifacts, leave unrelated
   pre-staged files untouched.

## 3. How the collaboration unfolded

**Phase 1 — Locate & diagnose (prompt 1).** The AI found `ChatViewMenu.tsx`, read its
anchoring (`absolute right-0 mt-1` = always opens downward), and traced its mount point to
`StatusBar`'s `leading` slot — pinned near the viewport bottom. It then checked for a
clipping ancestor and confirmed there was none, which settled the key architectural
question: **the clip is the viewport bottom, not an ancestor**, so an in-flow flip-up (not
a portal) is the correct, self-contained fix. *Why it worked:* it separated the symptom
(clipped rows) from the cause (downward anchor + bottom mount) before proposing anything.

**Phase 2 — Full popover audit (steering #1: "check all PopOver").** Rather than eyeball
it, the AI grepped every dropdown in the client, then extracted each component's real
anchor strategy and classified them into three tiers: 🔴 the bug (`ChatViewMenu`),
✅ already-correct (`ModelSelector`, `ThinkingLevelSelector`, `CommandInput` — all use
`bottom-full mb-1` + `max-h-* overflow-y-auto`), 🟡 latent risk. *Why it worked:* it
derived the correct pattern from the components that already got it right.

**Phase 3 — Ground in history (steering #2: "draft proposal").** Before writing, the AI
searched OpenSpec archives and found the smoking gun: an archived change
(`2026-06-11-fix-settings-panel-and-reset`) had **marked auto-flip tasks `[x]` done** with
a `flipUp` + `IntersectionObserver` plan — but `git log` on `ChatViewMenu.tsx` proved the
file was only ever touched by its original commit. **The flip code was never committed.**
The spec requires auto-flip; the shipped UI violates its own accepted spec. This reframed
the work from "new feature" to "**fix spec/code drift**."

**Phase 4 — Draft & commit (steering #3: "commit changes").** Scaffolded the change dir,
wrote 5 artifacts (proposal, design, tasks, 2 spec deltas), `openspec validate` passed
clean, then committed *only* those files — leaving an unrelated pre-staged
`windows-authenticode-signing/tasks.md` alone.

  Stronger: *"draft the OpenSpec proposal; first check archives/specs for related prior
