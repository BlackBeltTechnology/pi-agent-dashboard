# How we did it: Reorganize the Settings panel into left-nav pages — an AI collaboration guideline

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) — a "think, don't implement"
stance. The literal first prompt was the skill boilerplate: *"Enter explore mode. Think
deeply. Visualize freely. Follow the conversation wherever it goes."* The real objective
that emerged over the next six steering turns: **redesign the dashboard's overloaded
7-top-tab Settings panel into a scalable left-nav page layout, prove it with an
interactive mockup, and capture the whole thing as a validated OpenSpec change proposal
(not code).** The finished deliverable was `openspec/changes/reorganize-settings-into-pages/`
— proposal, design, tasks, delta spec, and a travelling mockup — committed locally.

## 2. TL;DR playbook

1. Enter explore mode: `/skill:openspec-explore`. State up front "we're capturing a
   proposal, not implementing."
2. **Ground in the real code before drawing anything.** Read `SettingsPanel.tsx`, map
   every section per tab from source, and screenshot the *live* UI (each tab) to see the
   actual overload and wasted width.
3. Build a **clickable HTML mockup** of the proposed left-nav layout, styled to match the
   dashboard. Open it in the browser and screenshot a slim page *and* a busy page.
4. Ask "open in browser" → use the OS default browser (`open file://…`) when the MCP
   browser tool has DNS issues; fall back to the `agent-browser` CLI.
5. **Surface the hidden contract early:** find the plugin **settings registry**
   (`VALID_SETTINGS_TABS`, `forTab`, `settings-section` slot). New page ids must be added
   there or plugin claims silently vanish.
6. Resolve the routing tradeoff as **dual-URL compat**: make `/settings/:page?` canonical,
   keep `?tab=` as a legacy alias that `replace`-redirects. One mounted `SettingsPanel`,
   one resolver (preserves the "Save applies across all tabs" spec requirement).
7. Run the **pre-scaffold coherence sweep** against `openspec/changes/archive/` before
   creating the change — confirm it's a delta of `settings-tabbed-layout`, not a duplicate.
8. Scaffold the four artifacts manually mirroring the archived change's delta-spec format;
   `openspec validate <name>` until clean.
9. "add mockup to proposal": copy the HTML + before/after PNGs into `changes/<name>/mockup/`
   and add a `## Mockup` section so it travels with the change.
10. Commit **only** your artifacts — leave unrelated pre-staged files untouched.

## 3. How the collaboration unfolded

**Phase 1 · Discovery / grounding.** The AI resisted the urge to sketch first. It found the
dashboard running (production, port 8000), located the real code
(`packages/client/src/components/SettingsPanel.tsx`), and discovered an *archived*
`settings-tabbed-layout` change — so tabs already existed. It mapped every section per tab
from source and screenshotted the live UI. **Why it worked:** the redesign was anchored in
what actually shipped (7 tabs, `General`/`Advanced` grab-bags, duplicated blocks, content
crammed into `max-w-2xl` with the right half empty), not an imagined baseline.

**Phase 2 · Design via mockup.** The AI built a clickable HTML mockup of a left-nav rail
that reclaims the dead gutter, then captured both a slim page (General) and a busy page
(Sessions). *Human decision point:* "open in browser" → view the real thing. The AI then
posed **three explicit open questions** (left-nav vs. rebalanced tabs, real routes vs.
`?tab=`, and the grouping) instead of silently picking.

**Phase 3 · Registry reveal.** The human steered: *"Don't forget there is registry mechanism
to register pages in settings."* This reshaped the plan. The AI traced the slot mechanism end
to end (`slot-types.ts` → `VALID_SETTINGS_TABS` typed allow-list → `forTab` → `SettingsSectionSlot`)
and found the linchpin: **the page ids ARE the public plugin contract**; inventing new ids
without extending the allow-list makes plugin claims vanish. Resolution: an **additive**
contract, each plugin picks its target page, `general` stays the default fallback.

**Phase 4 · Routing.** Human: *"Is it possible to support both URL — to be compatible?"* →
*"yes"*. The AI worked the constraint that "Save applies across all tabs" forces a single
mounted `SettingsPanel` with one config draft, so the choice is only URL *shape*. Answer:
`/settings/:page?` canonical, `?tab=` legacy alias, `navigate(..., { replace: true })` so old
bookmarks upgrade silently without polluting history.

**Phase 5 · Capture as OpenSpec.** The AI ran the pre-scaffold coherence sweep (clean — a
delta of the archived change, not a duplicate; also flagged a real stale-contract bug:
`VALID_SETTINGS_TABS` omits `plugins`). `openspec change new` turned out not to be a real
subcommand, so it scaffolded the dir manually in delta-spec format and validated.

**Phase 6 · Fold in mockup & commit.** "add mockup to proposal" → moved the HTML + 3 PNGs
into `changes/<name>/mockup/` with a `## Mockup` section. "commit changes" → committed
**only** the reorganize artifacts, deliberately leaving unrelated pre-staged files
(`add-faux-model-integration-tests/*`, `groups.json`) untouched. Local commit `35d4e0ed`,
not pushed.

## 7. Pitfalls & dead ends

- **MCP browser tool DNS failures** — it couldn't resolve `localhost:8000`. Fix: use the
  `agent-browser` CLI directly, or `open file://…` in the OS default browser.
- **`openspec change new` is not a real subcommand here** — it failed. Scaffold the change
  directory manually, mirroring the exact structure of the nearest archived change
  (`openspec/changes/archive/2026-04-04-settings-tabbed-layout`) in delta-spec format.
- **New page ids silently break plugins** — inventing ids (`sessions`, `server`, `developer`…)
  without adding them to `VALID_SETTINGS_TABS` makes plugin `settings-section` claims vanish.
  Always extend the allow-list; keep `general` as the default fallback.
- **Unrelated pre-staged files** — the working tree had `add-faux-model-integration-tests/*`
  and `groups.json` staged by other work. Commit path-scoped (`git commit <your-dir>/`) so
  you don't sweep them in.
