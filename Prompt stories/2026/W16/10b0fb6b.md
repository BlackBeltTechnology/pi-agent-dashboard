# How we did it: Fixing a silently-failing "+ New Terminal" (node-pty exec bit + swallowed handler errors) — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened with a two-word request: `build and deploy dashboard`. That was the
warm-up — the build/restart/reload ran clean in a minute. The *real* work surfaced two
prompts later, when the operator reported that **"+ New Terminal" does nothing in the
packaged Electron app** ("There is no other New terminal button… because there is no
active terminal. I'm using it in Electron App."). The true objective became: **root-cause
a terminal that silently refuses to spawn, fix it live, then harden the two underlying
bugs behind an OpenSpec change** — a hoist-fragile postinstall permission script and a
catch-all that swallowed every handler error.

## 2. TL;DR playbook

1. **Reproduce against the running server, not the app.** `curl /api/health`, then drive the
   exact WebSocket message (`create_terminal`) with a tiny `node -e 'new WebSocket(...)'`
   script to see if the server responds at all.
2. **Follow the silence.** No `terminal_added` broadcast + no server-log error ⇒ suspect an
   exception eaten by an outer `try { switch } catch { /* ignore malformed */ }`.
3. **Inspect the native prebuild directly.** `ls -la node_modules/node-pty/prebuilds/darwin-arm64/`
   — the smoking gun was `spawn-helper` at `-rw-r--r--` (missing exec bit) → `posix_spawnp failed.`
4. **Unblock live first.** `chmod +x` both arch prebuilds, restart, confirm the operator can
   spawn a terminal — *then* propose the durable fix.
5. **Capture the fix as OpenSpec:** `openspec new change` → fast-forward `proposal → design →
   specs → tasks` (two capabilities: `terminal-emulator`, `browser-gateway-decomposition`).
6. **Implement both fixes:** hoist-aware `require.resolve("node-pty/package.json")` in
   `fix-pty-permissions.cjs` + root `postinstall`; split the gateway try/catch so JSON-parse
   stays silent but handler exceptions log `[browser-gw] handler error type=…`.
7. **Add regression tests** (exec-bit assertion + logged-vs-swallowed assertion), run the
   *targeted* vitest files, verify, archive, sync specs, commit.

## 3. How the collaboration unfolded

**Phase 1 — Deploy warm-up (Prompt 1).** `npm run build` → `POST /api/restart` → `npm run reload`.
Production mode confirmed. Trivial; set the stage.

**Phase 2 — Grounded discovery (Prompts 2–3).** The AI entered explore mode and traced the
click path end-to-end on paper (TerminalsView `+` → `create_terminal` WS → `terminalManager.spawn`

**Phase 4 — Live unblock (Prompts 4–5).** `chmod +x` both prebuilds, restart, standalone

No skill or memory was created this session — but the workflow is textbook-repeatable and
**should** be captured. Two candidates:

- **`diagnose-silent-ws-handler-failure`** (project): *symptom* = a WS action does nothing with no
  log; *procedure* = drive the raw WS message with `node -e`, then hunt for an outer
  `try { switch } catch { /* ignore */ }` swallowing the exception. Effective because it converts

- **`fix-node-pty-exec-bit`** (project): *symptom* = `posix_spawnp failed.`; *check* =
  `ls -la node_modules/node-pty/prebuilds/<plat>/spawn-helper` for a missing exec bit; *fix* =

The durable assets this session *did* produce are the code fixes themselves: the hoist-aware

## 7. Pitfalls & dead ends

- **Don't trust a documented postinstall to have run.** AGENTS.md advertised `fix-pty-permissions.cjs`,
  but it never applied to the hoisted install — verify the actual file mode, don't assume.
- **Electron ≠ its own server.** The packaged app is Chromium pointed at the *host-Node* dashboard
  server (PID under `pi-dashboard` CLI), so a "native-ABI mismatch in Electron" is a red herring —
  same binary that works in the browser.
- **Catch-alls hide root causes.** The gateway's `try { switch } catch { /* ignore malformed */ }`
  ate a real spawn exception. When a handler is silent, suspect the outer catch before the handler.
- **`openspec archive` sync can refuse** on legacy-format main specs (`## ADDED Requirements` vs the
  newer `## Purpose`/`## Requirements`). Append manually in the existing shape; migration is its own change.
- **`ask_user` returned `undefined` twice** — the AI wasted two turns re-answering "sync." If a
  dialog returns undefined, drop to plain-text options immediately.
