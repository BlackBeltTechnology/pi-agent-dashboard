# How we did it: Turn the dashboard's dead-end empty state into a 3-step onboarding — an AI collaboration guideline

## 1. Goal (the ask)

The session opened in **explore mode** ("Enter explore mode. Think deeply… you must NEVER write code") — a deliberate *think-first* stance, not an implementation request. The real objective, which surfaced once exploration grounded itself in the code, was: **replace the dashboard's inert empty state (`LandingPage` — just a π glyph and "Select a session to get started") with a guided first-run onboarding surface** that walks a brand-new user through the three things they must do before anything works: (1) set up LLM credentials, (2) add a folder, (3) start a session. The whole arc ran explore → proposal → apply → verify → archive → commit, all inside one OpenSpec change (`add-landing-page-onboarding`).

## 2. TL;DR playbook

1. **Start in explore mode** and force the AI to read the real code first ("ground this before riffing") — it will map where each of the three actions *already* lives (settings route, sidebar dialog, spawn handler).
2. Let it sketch the target UI and name the **design decisions** (visibility model, dialog location, step-gating, credential signal) as flaggable defaults.
3. Say **`create a proposal`** — it scaffolds the full OpenSpec artifact set (`proposal.md`, `design.md` with D1–D6, `tasks.md` TDD-ordered, two delta specs) and validates.
4. Say **`/opsx:apply`** — it implements TDD: failing test → hook → lift dialog → LandingPage rewrite → wire into `App.tsx` → docs. Tasks self-check off.
5. When the full `npm test` disrupts your environment, tell it **"the full test killed the sessions. Ignore it"** — it pivots to running only the affected client suites.
6. **Test the real thing manually** and report the gap: "Currently credentials set and Step 2 is inactive" — this exposed that OAuth logins live in a *different* endpoint than the hook queried.
7. Say **`update proposal`** after any in-flight scope change so the artifacts stay truthful.
8. Close the loop: `manual tests ok, all green` → **`/opsx:verify`** → `fix` (clears the one suggestion, e.g. CHANGELOG) → **`/opsx:archive`** (syncs delta specs to main) → **`commit changes`** (stage only *this* change's files in a dirty repo).

## 3. How the collaboration unfolded

**Phase 1 — Explore & ground (prompt 1).** The AI resisted the urge to design in a vacuum: "Let me ground this in the actual code before riffing." It grep'd `LandingPage`, `App.tsx`, `SettingsPanel`, `PinDirectoryDialog`, and the spawn handler, then produced a table showing all three onboarding actions *already existed but were scattered* — settings had a clean `?tab=` route, "Add folder" was awkwardly buried inside `SessionList.tsx`. That map became the design's backbone. **Why it worked:** grounding first turned a vague "make onboarding" into a precise "lift the buried dialog + surface the three existing routes."

**Phase 2 — Proposal (prompt 2: `create a proposal`).** It scaffolded the change via `openspec change new`, wrote `proposal.md` / `design.md` (decisions D1–D6, visual sketch, risks, open questions) / `tasks.md` (TDD-ordered) plus two delta specs (one NEW capability, one MODIFIED for the dialog move), and validated clean. It baked its recommended defaults in but explicitly invited overrides ("flag any to revisit").

**Phase 3 — Apply / TDD (prompt 3: `/opsx:apply`).** 0/26 tasks → implemented in strict test-first order: `useProvidersReady` hook (test → impl), lift `PinDirectoryDialog` from `SessionList` to `App.tsx`, rewrite `LandingPage` as three pending/done/locked cards with a backward-compatible fallback, wire props through `App.tsx`, then docs. It carefully distinguished **its** passing new tests from **pre-existing** failures on main ("4 failing are pre-existing… unrelated").

**Phase 4 — Manual-test correction (prompts 4–6).** The human ran it for real and hit the key defect: credentials *were* set but Step ② stayed inactive. Root cause: OAuth logins (Anthropic, Copilot, Gemini) write to `~/.pi/agent/auth.json` and surface via `/api/provider-auth/status`, **not** `/api/providers`. The AI rebuilt the hook to query *both* endpoints in parallel with OR-logic + fault tolerance, updated its tests (6 → 8), and re-synced spec + design + proposal to match ("update proposal").

**Phase 5 — Verify → archive → commit (prompts 7–11).** `all green` → `/opsx:verify` produced a completeness/correctness/coherence report with a requirement→code→test table; the lone suggestion (missing CHANGELOG entry) was cleared with `fix`; `/opsx:archive` synced both delta specs into main specs; `commit changes` staged **only** the 15 onboarding files out of a repo holding 74 unrelated in-flight files — using stash/restore to split a mixed CHANGELOG.

## 4. Prompts that worked

- **The goal prompt (explore mode):** effective *because* it forbade implementation and forced thinking + grounding first. The one improvement: state the concrete target ("redesign LandingPage into a 3-step onboarding") up front so exploration converges faster.
- **`create a proposal`** — a two-word unlock that converted a well-explored idea into a complete, validated OpenSpec artifact set. High leverage precisely because the exploration had already done the design work.
- **`the full test killed the sessions. Ignore it`** — a sharp environment guardrail that redirected the AI from a destructive whole-repo `npm test` to scoped client suites. Reusable verbatim in this repo.
- **`Currently credentials set and Step 2 is inactive`** — the single most valuable follow-up: a concrete, observed manual-test symptom. It's far stronger than "it doesn't work" because it pins the exact step and state, letting the AI find the OAuth-endpoint gap immediately.
- **`update proposal`** — keeps artifacts honest after mid-flight scope changes; cheap to say, prevents spec drift.
- **`fix`** — worked only because `/opsx:verify` had just enumerated exactly one actionable suggestion; a bare "fix" is safe when the preceding report is precise.

## 7. Pitfalls & dead ends

- **Whole-repo `npm test` is destructive here** — it killed live sessions mid-run. If you hit this, switch to `cd packages/client && npx vitest run <suite>`.
- **Single-endpoint credential detection is a trap** — `/api/providers` holds only API-key/baseUrl config; OAuth logins are invisible there. Query `/api/provider-auth/status` too and OR the results.
- **Pre-existing failing tests obscure your signal** — the repo had 4 failing `SessionList spawn button` tests and 176/189 pre-existing spec-validation failures unrelated to this change. Baseline first (the AI used `git stash` + re-run to prove failures pre-dated its edits) so you don't chase ghosts.
- **`tsc --noEmit` on a composite/project-references client is fiddly** — several attempts (`-p`, `--composite false`, `-b`, a temp tsconfig) were needed to get a clean client-only type-check. Prefer the repo's own `reload:check` path.
- **Committing in a dirty tree** — 74 unrelated files were present; a naive `git add -A` would have bundled other people's in-flight work. Stage per-file and stash-split mixed files like CHANGELOG.
