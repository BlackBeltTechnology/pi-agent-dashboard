# How we did it: Header brand mark + barber-pole "working" indicator — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

## 1. Goal (the ask)

The session opened in **explore mode** — a thinking-partner stance, no implementing:

> _"Enter explore mode. Think deeply. Visualize freely… You must NEVER write code or
> implement features… You MAY create OpenSpec artifacts."_

The *real* objective, once the exploration narrowed, was a small **visual-polish batch on
the dashboard chrome**: (1) replace the plain text `π` in the sidebar header with the
actual app brand mark, and (2) make the "session is working" card animation read as
*obvious motion* — a scrolling barber-pole stripe layered on top of the existing breathing
pulse — while preserving the semantic split (`stripes = working`, `pulse-only = waiting on
you`). A third gap surfaced mid-flight: a cryptic `📌+` pin button that needed a real
label. The whole thing was driven through the full OpenSpec loop: explore → proposal →
apply → verify → archive → commit.

## 2. TL;DR playbook

1. **Start in explore mode** to shape the change; end the exploration by asking the AI to
   `create proposal` — it captures decisions (layering, coprime animation periods,
   reduced-motion guard) into `openspec/changes/<name>/`.
2. **State the preservation constraint up front**: _"keep the current pulsing too"_ — the
   new effect **layers on**, it does not replace.
3. `/opsx:apply` the change. Let the AI edit `index.css` (the animation) and the sidebar
   component, add a smoke test, and update `AGENTS.md`.
4. **Build + deploy every visual change**: `npm run build && curl -X POST
   localhost:8000/api/restart`, then **hard-refresh (Cmd-Shift-R)** — production CSS is
   bundle-hashed and browser-cached.
5. **Verify in the actual running UI, with screenshots.** The stripe-not-scrolling bug and
   the "logo didn't change" bug were only catchable by eyes on the live dashboard.
6. When "the logo didn't change" — **grep for a second component**: the header rendered
   `SessionList.tsx`, not the `SessionSidebar.tsx` that was edited first.
7. When PWA assets 404 — **check `vite.config.ts` `publicDir`** (it resolves relative to
   `root: src/`, so it needs one extra `../`).
8. `/opsx:verify` then `/opsx:archive`, then a **scoped commit** (`git add -p` / partial
   staging) because several parallel changes share the working tree.

## 3. How the collaboration unfolded

**Phase 1 — Explore & propose (prompts 1–3).** The AI read the sidebar/card sources,
diagrammed the `text π` vs `app-icon Π` mismatch in ASCII, and laid out a options table
(raster `<img>` vs inline SVG). The human unlocked the design with one constraint —
_"keep the current pulsing too"_ — and the AI designed a **two-layer CSS background** (a
drifting 45° stripe layer over a breathing flat tint) with **coprime 2s/3s periods** so the
two effects never lock into one rhythm. Then `create proposal` produced the OpenSpec
artifacts (proposal/design/tasks + 2 spec deltas).

**Phase 2 — Apply (prompts 4–5).** `/opsx:apply` edited `SessionSidebar.tsx`, rewrote
`.card-working-pulse` in `index.css`, added a smoke test, updated `AGENTS.md`, marked
10/15 tasks, and paused for manual QA. `build and deploy` shipped it.

**Phase 3 — The stripe-scroll saga (prompts 6–16).** This was the hard part, and it took
**five wrong fixes** before the animation visibly scrolled. The chain of misdiagnoses:
1. Visible seams every 40px → `background-size: 40px` didn't match the gradient's natural
   `20/√2 ≈ 14.142px` diagonal period.
2. Dropped `background-size` entirely → position shift now just *clipped* instead of
   scrolling.
3. Set `background-size` to an integer multiple of the period → still looked static.
4. Renamed keyframes (suspected a name-collision with the class) + bigger scroll distance
   → still static.
5. **Root cause found:** translating `background-position` along `(+1,+1)` moves *along*
   the 45° stripes — a pattern-invariant direction, so **zero visible motion** even though
   the numbers change. Fix: scroll horizontally (`0 0 → Npx 0`), *across* the stripes.

**Phase 4 — Logo, the sequel (prompts 17–19).** Screenshot: logo unchanged. The AI
grepped and found **two sidebar components** — the header actually renders
`SessionList.tsx`. Fixed both. Then "Not found" screenshot → the PWA icons 404'd because
`vite.config.ts` had `publicDir: "../../public"` which Vite resolves relative to `root`
(`src/`), silently missing. Then the raster PNG showed a **black box in light theme**
(it ships its own opaque rounded square). Pivot to an **inline `<PiLogo>` SVG** with
`fill="currentColor"` — transparent, theme-adaptive, crisp at any size.

**Phase 5 — Label, verify, archive, commit (prompts 20–26).** Renamed `📌+` → `📌 Add
folder`. Updated the proposal to match what actually shipped (PNG→SVG pivot, two sidebars,
publicDir fix). `/opsx:verify` produced a per-requirement evidence table; a `fix` restored
the coprime 2s/3s periods (a 3s/3s value had leaked in from debugging). `/opsx:archive`
synced 7 requirements across 5 capabilities — and side-fixed a malformed
`session-sidebar/spec.md`. Finally, `commit changes` had to **scope one commit** out of a
working tree holding several concurrent changes, racing a parallel session's staging twice.

## 4. Prompts that worked

- **Goal prompt (explore mode):** effective because it *forbade implementation* — the AI
  produced a well-reasoned proposal (layering, coprime periods, reduced-motion) instead of
  jumping to code. For a polish batch, exploring first pays off.
- **`keep the current pulsing too`** — one short constraint that steered the entire design
  from "replace the animation" to "layer on top". High-leverage: state preservation rules
  the moment you sense the AI may overwrite existing behavior.
- **Screenshot + one line** (`The stripes not scrolling left to right`, `The logo is not
  replaced`, `in light theme it has black background`) — visual bugs are fastest reported
  as *image + the observable symptom*. Each unlocked a concrete root-cause hunt.
- **`update proposal`** after the implementation drifted — kept the OpenSpec artifacts
  truthful to what shipped (the PNG→SVG pivot, the publicDir fix).
- Weak → strong rewrite: the repeated bare `wait 10 sec` / `the stripes are not scrolling`
  were low-information. Stronger: _"stripes still static after hard-refresh — confirm the
  animation is in the live bundle and try translating across the stripe axis, not along
  it."_ That points the AI at the actual failure class instead of another blind rebuild.

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was saved this session, but the workflow is textbook-repeatable and
two assets *should* be captured:

- **`PiLogo.tsx`** (created) — an inline SVG brand-mark component with
  `fill="currentColor"`. Reusable primitive: any theme-adaptive logo should be this, not a
  raster `<img>`. It solves the light-theme black-box problem permanently.
- **A candidate skill: "diagnose a CSS animation that won't visibly move."** The five-step
  misdiagnosis chain (seams → clipping → tile-size → keyframe-name → *pattern-invariant
  translation direction*) is exactly the kind of non-obvious, costly loop worth a skill.
  Invoke when a `background-position` animation renders but shows no motion.
- **A candidate memory: `vite.config.ts publicDir` resolves relative to `root` (`src/`)** —
  so `../../public` silently misses; it needs `../../../public`. This 404'd all PWA assets
  invisibly. Worth a project memory to save the next operator the same hunt.

## 7. Pitfalls & dead ends

- **45° stripe won't scroll?** Don't keep tweaking `background-size`. Translating
  `background-position` along `(+1,+1)` moves *along* the stripes = zero visible motion.
  Scroll horizontally (`0 0 → Npx 0`) to cut *across* them.
- **Diagonal-tile seams** appear when `background-size` isn't an integer multiple of the
  gradient's natural period (`20/√2 ≈ 14.142px` for 20px 45° stops). Use `28.2843px`
  (= `20·√2`, one full period) so tiling *and* position-animation both behave.
- **"My UI edit didn't take" — there may be two components.** The header rendered
  `SessionList.tsx`, not `SessionSidebar.tsx`. `grep -rn` every render site first.
- **PWA icons 404 silently** — `publicDir: "../../public"` in `vite.config.ts` resolves to
  a non-existent `packages/public/`. It only *looked* fine because a stale `dist/` copy
  lingered. Fix: `../../../public`, then confirm via `curl` that assets serve as
  `image/png`.
- **Raster logo = black box in light theme** — the PNG ships its own opaque background.
  Inline SVG + `currentColor` is the correct primitive.
- **Production CSS is bundle-hashed + cached** — always **hard-refresh (Cmd-Shift-R)** and,
  when in doubt, `curl` the served `assets/index-*.css` to confirm your rule is actually
  live before deciding the fix "didn't work".
- **Concurrent commits race the index** — in a shared working tree with parallel sessions,
  staging got clobbered twice. Scope with `git add -p`, verify the staged set right before
  committing, and be ready to redo.
