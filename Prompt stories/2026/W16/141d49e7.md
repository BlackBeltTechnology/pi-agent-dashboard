# How we did it: Fix the model selector staying disabled after provider auth — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

## 1. Goal (the ask)

The session opened in **explore mode** ("Enter explore mode. Think deeply… you must
NEVER write code or implement features"), so the real goal only crystallized through
steering. The user's actual problem: in the dashboard, an *existing, live* session
shows its model selector **disabled ("no model")** and stays that way even after the
user authenticates a provider (Anthropic OAuth) in Settings — only **newly created**
sessions get a selectable model. The objective: find the root cause of the stale
model list on already-open sessions, then fix it so provider auth refreshes the
selector in place without needing a page reload or a fresh session.

## 2. TL;DR playbook

1. **Start in explore mode.** Don't implement — trace the whole `models` data flow
   end-to-end first: client `request_models` → server subscribe handler → bridge
   `getAvailable()` → `models_list` broadcast → client `modelsMap`.
2. **Read pi's own source** (`@mariozechner/pi-coding-agent/dist/core/`), not just the
   dashboard. The truth was in `model-registry.js` (`getAvailable()` returns only
   models with configured auth) and `auth-storage.js` (`reload()` re-reads disk).
3. **State the exact repro to collapse hypotheses.** The user's "the session is
   active — green, just no model can be selected" ruled out the ended-session /
   page-reload branches and pointed at the live-bridge refresh chain.
4. **Name the root cause precisely:** provider auth broadcasts `credentials_updated`
   to *bridges* (which refresh and push `models_list`) but nothing tells the *browser*
   to drop its stale `modelsMap[sessionId] = []` and re-request.
5. **Create the OpenSpec change** (`create proposal` → `/opsx:ff`) to capture the fix:
   a new `models_refreshed` server→browser message that clears the client cache and
   re-requests for the selected session, plus real error logging in the bridge.
6. **Apply it** (`/opsx:apply`): add the protocol type, broadcast it from both
   credential-write routes, wire `browserGateway` into those routes, handle it in
   `useMessageHandler` (clear map + re-request via a `selectedSessionIdRef`), and
   replace silent `/* ignore */` catches in the bridge with `console.error`.
7. **Test the pure logic**, type-check, commit. Deploy = restart server + `npm run reload`.

## 3. How the collaboration unfolded

**Phase 1 — Trace the data flow (explore).** The AI grepped the client, server,
shared, and extension packages to map every hop of the `models` list: where
`request_models` is sent (`App.tsx` ~line 308), how the server subscribe handler
forwards it, how the bridge answers, and how `useMessageHandler` writes `modelsMap`.
*Why it worked:* building the full mental pipeline before guessing meant the eventual
root cause was placed on a specific broken edge, not hand-waved.

**Phase 2 — Read the framework, not just the app.** The critical insight came from
reading pi's compiled core (`model-registry.js`, `auth-storage.js`): `getAvailable()`
filters models to those with configured auth, so **no auth = empty list = disabled
button** (`hasModels = models && models.length > 0`). This confirmed the empty array
was *correct* at first load — the bug was the failure to refresh it later.

**Phase 3 — Collapse the hypothesis space with the human.** The AI generated several
competing theories (dashboard OAuth page-reload clears state; ended sessions have no
bridge; React re-render/Map-identity race). It laid them out as ASCII timelines and
asked the user to pin the exact scenario. The user's two-line answers — "Login for
model provider" and "the session is active — green, just no model can be selected" —
eliminated every branch except **live session + provider auth in Settings**, isolating
the real gap: the browser never learns credentials changed.

**Phase 4 — Capture as an OpenSpec change.** `create proposal` → `/opsx:ff` scaffolded
`proposal.md`, `design.md`, `specs/model-refresh/spec.md`, and `tasks.md` (6 tasks, 3
groups: protocol/server, client, bridge).

**Phase 5 — Implement + verify.** `/opsx:apply` walked the tasks: new
`ModelsRefreshedMessage`, broadcast from `provider-auth-routes.ts` and
`provider-routes.ts` (both needed `browserGateway` threaded through from `server.ts`),
client handler that clears `modelsMap` and re-requests for the selected session using a
new `selectedSessionIdRef`, and bridge error logging. Pure-function tests, type-check,
then commit `f78e675` on `develop`.

## 7. Pitfalls & dead ends

- **Assuming the bridge push is enough.** `credentials_updated` → bridge refresh →
  `models_list` *looks* complete, but the browser had already cached `[]` and nothing
  invalidated it. If a value refreshes only for new sessions, suspect a **client-side
  stale cache**, not the server push.
- **Chasing the page-reload branch.** Dashboard OAuth remounts React and clears state,
  so it's a red herring for "stays disabled" bugs — the real case is in-place provider
  auth. Confirm whether the page reloads before theorizing.
- **The re-request effect didn't depend on `modelsMap`.** The `App.tsx` effect keyed on
  `[selectedId, send, status]`, so merely clearing the map wouldn't re-fire it — the
  handler had to *both* clear the cache *and* actively send `request_models` (needing a
  `selectedSessionIdRef` since `selectedId` wasn't in scope).
- **Two credential-write routes.** Both `provider-auth-routes.ts` and
  `provider-routes.ts` broadcast credential changes; the browser notification had to be
  added to **both**, and `browserGateway` threaded into each from `server.ts`.
- **Silent `/* ignore */` catches in the bridge** hid failures — replacing them with
  `console.error` was part of the fix so future refresh failures are visible.
- **Don't run the full suite when it can kill the live session** — scope to changed
  packages + type-check (`ignore full test because kill session`).
