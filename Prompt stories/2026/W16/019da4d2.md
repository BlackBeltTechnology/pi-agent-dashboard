# How we did it: Build a public marketing site from explore mode — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** — a deliberately no-implementation stance:

> *"Enter explore mode. Think deeply. Visualize freely. Follow the conversation wherever it goes… You may read files, search code, and investigate the codebase, but you must NEVER write code or implement features… You MAY create OpenSpec artifacts."*

The *real* objective, once the steering answers landed, was concrete: **turn the
project's only public face (a dense GitHub README) into a visually stunning,
animated, Supabase-style marketing site** — an Astro + Tailwind static site under
`/site`, deployed to GitHub Pages, with real product screenshots and a Playwright
capture pipeline. Explore mode was the *front door*; the session then flowed through
an OpenSpec change (`add-marketing-site`) into a full implementation, ~13-card bento
grid, AI-generated screenshots, dual theme, a dynamic download section, CI wiring,
verify, and archive — an ~18-hour arc across 29 prompts.

## 2. TL;DR playbook

1. **Kick off in explore mode** to lock aesthetic + stack decisions *before* any
   code. Answer the AI's cascading decision questions tersely (`1. Supabase / 2.
   Astro + tailwind / 3. Playwright / 4. /site`).
2. **Capture the locked decisions as an OpenSpec change** (`proposal.md`,
   `design.md`, `tasks.md`, `specs/marketing-site/spec.md`) — the explore→build
   bridge so nothing is lost. Scaffold artifacts by hand if `openspec change new`
   doesn't run in the repo.
3. **Implement phase-by-phase** against `tasks.md` (scaffold → primitives → hero →
   sections → screenshot pipeline → deploy workflow → polish), verifying `npm run
   build` + a JS-size budget check after each batch.
4. **Watch the bundle budget**: swap **React → Preact** the moment the gzipped JS
   crosses the budget (44 KB of React alone → ~32 KB total with Preact).
5. **Generate real screenshots with the `nano-banana-imagegen` skill** (Gemini) —
   calibrate one prompt, then batch the rest with a shared `STYLE=` prefix.
6. **Verify visually via the system browser** (`open <url>`) plus `curl` HTML
   sanity checks when the in-session `browser` tool / Playwright download isn't
   available.
7. **Iterate on look-and-feel in tight loops** driven by short user nudges (mission
   background graph → anchor top → ping rings → scroll reveals → theme toggle).
8. **Commit surgically**: stage only marketing-site files, leave parallel-session
   hunks untouched (`git add` the clean-new files; skip mixed-scope files).
9. **Close the loop**: `/opsx:verify` → fix findings → sync main spec → `/opsx:archive`.

## 3. How the collaboration unfolded

**Phase 1 — Explore & decide (10:22–10:32).** The AI refused to implement (correct
explore-mode discipline), reframed the ask with ASCII diagrams, and surfaced the
"loaded words" (*visually stunning, animated, screenshots*) as decision points. The
human answered in terse numbered lists; the AI played the answers back as a
**locked-decisions** block. *Why it worked:* decisions were pinned before a single
file existed, so downstream work never thrashed on direction.

**Phase 2 — Capture as OpenSpec (10:32–10:36).** The AI discovered `openspec change
new` doesn't scaffold in this repo and **fell back to writing the four artifacts by
hand** at `openspec/changes/add-marketing-site/`, then `openspec validate` ✅. The
change encoded palette, stack, hero animation, bento sizing, screenshot pipeline,
and deploy target.

**Phase 3 — Implement the app (10:36–10:50).** Nine phases / ~64 tasks. The AI
batched hero + sections to get a working page fast, then hit the **50 KB JS budget**
at ~69 KB and swapped React→Preact to land at ~32 KB. Screenshot pipeline built with
two modes (target a live dashboard, or spawn a fixture server).

**Phase 4 — Verify without a headless browser (10:50–11:00).** The in-session
`browser` tool needed pi-agent-browser (absent) and the Playwright chromium download
timed out. The AI **fell back to `curl` HTML assertions + `open` in the system
browser** — pragmatic verification the human could eyeball.

**Phase 5 — Real screenshots + look-and-feel loop (11:18–13:17).** On the human's
nudge ("logos everywhere. Is there nano banana skill?"), the AI generated proper
dashboard mockups via `nano-banana-imagegen`. Then a long, tight iteration loop:
mission background graph → top-anchor it → add ping rings → scroll-triggered card
reveals → real app icon → code-server feature card → reorganize bento to clean
12-column rows → dual light/dark theme with no-FOUC script. Each nudge was one short
sentence; the AI produced a targeted diff + a before/after ASCII sketch.

**Phase 6 — Dynamic download + CI (19:14–19:53).** Build-time GitHub-release fetch
with a committed JSON cache fallback, a dynamic Hero CTA (`Download v0.2.9 →`), and a
`sync-release-version.yml` workflow so releases auto-refresh the site.

**Phase 7 — Debug, verify, archive (01:38–04:18, next day).** Chased a "theme toggle
doesn't work" report — proved via scripted Playwright that it *did* work (root cause:
stale browser cache, needs hard reload). Generated light-mode screenshot variants.
Ran `/opsx:verify` (90/90 → honestly re-opened 3 post-deploy tasks to 87/90), synced
the delta spec into a new main spec, and archived with clean R100 renames.

## 4. Prompts that worked

- **The goal prompt (explore mode).** Effective because it *forbade* implementation
  and *permitted* OpenSpec capture — forcing decisions to crystallize before code.
  A future user should still open here, but could add the target up front: *"Explore
  a Supabase-style Astro marketing site under `/site`, deployed to GitHub Pages —
  help me lock aesthetic + stack, then capture it as an OpenSpec change."*
- **Terse cascading answers** (`1. Supabase / 2. Astro + tailwind / 3. Playwright /
  4. /site / 5. Screenshot only / 6. github.io then pi-dashboard.dev / 7. Playful`).
  High leverage: one line collapsed a whole decision tree.
- **"Is there nano banana skill installed? If yes use that"** — unlocked real
  screenshots by pointing the AI at an installed capability it wasn't using.
- **Single-sentence look-and-feel nudges** ("Little circle explosions also can be
  cool added to stars", "Make the scrolling… more dynamically", "Flows in motion too
  large") — each unlocked a focused, verifiable diff. Terse + specific beat verbose.
- **"update proposal with changes" / "update specs and commit changes"** — kept the
  OpenSpec artifacts honest as the implementation drifted past the original plan.

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was persisted this session, but two reusable patterns emerged
and **should be captured**:

- **`nano-banana-imagegen` for product screenshots.** Effective because it removes
  the entire "seed a live dashboard + capture with Playwright" pipeline for the
  common case — a shared `STYLE=` prompt prefix + one calibration image yields a
  coherent batch matching the brand palette. Invoke it whenever a marketing/mockup
  surface needs realistic screenshots and no live instance is handy. Pitfall it
  taught: vertical phone shots crop badly in horizontal cards — regenerate as **wide
  landscape product-shots with abstract gray bars** instead of fake text.
- **Explore → OpenSpec → implement → verify → archive as one arc.** The repeatable
  spine of this session. Recommend a project skill: *"marketing-surface build"* that
  scaffolds `/site` (Astro + Preact + Tailwind, JS budget check), the deploy
  workflow, and the four OpenSpec artifacts in one shot.

## 7. Pitfalls & dead ends

- **`openspec change new` doesn't scaffold in this repo** → write the four artifacts
  by hand at `openspec/changes/<name>/` and `openspec validate`.
- **React blows the JS budget** (~44 KB gzipped alone, total ~69 KB vs 50 KB cap) →
  swap to **Preact** (same JSX, `jsxImportSource: preact`) → ~32 KB.
- **In-session `browser` tool needs pi-agent-browser** (absent here) and **Playwright
  chromium download times out** → verify with `curl` HTML assertions + `open <url>`
  in the system browser; for scripted checks use system Chrome, not the bundled one.
- **"Theme doesn't work" was a stale-cache false alarm** → a scripted Playwright
  flip proved the CSS vars + `<html>.dark` class toggle correctly; fix was a
  hard-reload (`⌘/Ctrl+Shift+R`), not code.
- **Astro frontmatter is plain TS, not JSX** → SVG icon markup belongs in the
  template body, not the frontmatter script block.
- **Mixed-scope working tree** (parallel sessions) → never `git add -A`; stage only
  your clean-new files and leave mixed hunks for their owner. Confirm renames show as
  R100 before committing archive moves.
