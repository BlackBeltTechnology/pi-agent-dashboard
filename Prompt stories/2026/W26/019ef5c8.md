# How we did it: Weave CodeRabbit into the implementation inner loop — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) — a thinking stance, not an
implementation task. The real objective surfaced on the second prompt: *"How can this
[code-review] skill be **automatically applied in the implementation phase** of a
proposal?"* The repo already had an on-demand `code-review` skill (CodeRabbit) and an
`autofix` skill (applies PR-thread feedback **after** push) — but nothing that ran AI
review **during** implementation, before commit. The goal became: **add a CodeRabbit
review gate that fires automatically in the dev inner loop, works in worktrees and
against the Docker-isolated instance, never blocks, and is captured as an OpenSpec change
and shipped as a PR.**

## 2. TL;DR playbook

1. **Ground reality before designing.** Run the actual CLI (`coderabbit --version`,
   `--help`, `auth status`, a live `review --agent -t committed --base HEAD~1`) to learn
   the *installed* flags and confirm rate-limit headroom — do not trust web-research flags.
2. **Research in parallel, then reality-check.** Fan out `@fast` subagents for
   best-practice ranking, but discard any pattern the installed CLI version can't do.
3. **Map the automation surface.** Distinguish *auto-load* (skill text enters context on
   NL match) from *auto-execute* (a deterministic script/hook). "Automatic" needs a
   workflow step or a script — not just a skill.
4. **Pick the correct hook point.** Put the gate in a **server-independent, worktree-safe**
   script that runs on the git diff — NOT in a deploy/build step.
5. **Make it advisory.** Warn-and-continue, exit 0, defer on rate-limit, add `--no-review`
   / `SKIP_CR_REVIEW=1` escape hatches.
6. **Extract a pure parser** (`parse-findings.ts`) and unit-test it where vitest scans
   (`scripts/__tests__/*.test.mjs`) — don't burn API quota re-running live reviews.
7. **Write the OpenSpec change honestly** — implemented tasks `[x]`, follow-ups `[ ]`.
   Run `openspec validate`.
8. **Branch + stage ONLY your files**, commit **atomically** (stage+commit in one command)
   because the shared working tree's index can be reset by concurrent sessions, then push
   and open the PR against `develop`.

## 3. How the collaboration unfolded

**Phase 1 — Discovery & reality-check (explore stance).** The AI ran the CodeRabbit CLI
directly: version, help, auth, and a *live* `--agent` review against the last commit. This
proved v0.5.2 is cloud-backed (no local model), authenticated, and **not** rate-limited —
and revealed the real flag set (`--agent`, `--plain`, `-t`, `--base`, `-c`). *Why it
worked:* it caught that web-research flags (`--light`, `--config=prompts/*.md`) **don't
exist** here, so the design was grounded in the installed tool, not a blog post.

**Phase 2 — Research, ranked by ROI (@fast subagents).** Parallel research produced a
priority-ordered pattern list (correctness→security→perf→maintainability passes, severity
buckets + nit caps, harness config, agent-JSON fix loops, diff scoping). The AI then
adapted only the patterns the real CLI supported and enhanced `code-review/SKILL.md` in
place (v0.1.0 → v0.2.0).

**Phase 3 — Wire the automatic gate (first attempt, WRONG place).** The AI mapped the
implementation phase and initially added the gate to `full-rebuild.ts`. **Decision point:**
the human corrected that `full-rebuild.ts` is a *deploy-to-local-instance* op (build →
restart → reload) that feature work in a worktree / Docker-isolated instance never runs.

**Phase 4 — Correct the design.** The AI reverted the gate out of `full-rebuild.ts`, wrote
a standalone **`review-changes.ts`** (pure git-diff review, no build, no server,
worktree-safe, advisory), and re-wired the `implement` skill to call it at implementation
completion. On the human's instruction, it also documented the deploy-vs-review distinction
in `AGENTS.md`.

**Phase 5 — Capture as OpenSpec + harden.** Pre-scaffold coherence check confirmed the
active `add-code-quality-skill` (Biome, deterministic lint) is orthogonal to this
(CodeRabbit, AI review) — composable, no collision. The AI scaffolded
`add-coderabbit-review-gate` (proposal/design/tasks/spec), extracted `parse-findings.ts`,
added a 5-test vitest suite, and delegated file-index doc rows to a docs subagent.

**Phase 6 — Ship the PR (index race).** Staged **only** the 13 own files (excluding two
other concurrent WIP changes), then hit a git-index reset mid-commit. *Decision point:* no
hooks existed — a concurrent session had touched the index — so the AI staged+committed
**atomically in one command**, pushed, and opened PR #156 against `develop`. It saved the
race as a project memory.

## 4. Prompts that worked

- **The goal prompt (steering #1):** *"How can this skill be automatically applied in the
  implementation phase of a proposal?"* — Effective because it names the *phase* and the
  *automatic* requirement, forcing the AI to map auto-load vs auto-execute rather than just
  re-describe the skill.
- **High-leverage correction (steering #3):** *"The full-rebuild can be done in local
  existing instance… When implementing a feature (maybe in worktree) it hasn't restart the
  server."* — One sentence that relocated the entire gate from a deploy script to a
  server-independent one. This was the pivotal prompt.
- **Short unlocks:** *"yes"*, *"Add to AGENTS.md"*, *"make proposal"*, *"yes, and create
  PR"* — each a one-liner that advanced a full phase because the AI had already staged the
  plan and asked for confirmation.

Rewrite of the goal prompt for a future operator: *"I want CodeRabbit AI review to fire
automatically during the implementation inner loop (worktree + Docker-isolated), before
commit, decoupled from build/deploy, advisory-only. Ground the design in the installed CLI
version's real flags, then capture it as an OpenSpec change and open a PR against
develop."*

## 6. Skills, tools & memory created — and why they're effective

- **Memory saved (project · tool-quirk):** *the working tree is shared with concurrent pi
  sessions; the git index can be reset between separate Bash calls, so stage+commit
  atomically.* **Why effective:** turns a confusing one-off failure (commit aborted, no
  hooks) into a standing rule that prevents future WIP leaks and mystery abort loops.
- **`review-changes.ts` (new script):** the reusable asset — runs `coderabbit review
  --agent -t uncommitted` on the working tree only, advisory, worktree-safe. Invoke at
  implementation completion, before commit.
- **`parse-findings.ts` (extracted pure parser):** isolates NDJSON finding-parsing so it's
  unit-testable **without** live API calls. Invoke pattern: extract the pure function when
  you need coverage but can't afford to re-run a metered/live tool.
- **No new skill was created**, but the workflow (ground-CLI → adapt-research → advisory
  gate → OpenSpec → scoped PR) is repeatable and this guideline captures it.

## 7. Pitfalls & dead ends

- **Wrong hook point.** Adding the gate to `full-rebuild.ts` conflated deploy with review.
  *If you hit this:* the gate must run on the git diff, no build/restart, so it works in
  worktrees and against the Docker-isolated instance.
- **Trusting research flags.** Web-recommended `--light` / `--config=prompts/*.md` don't
  exist in CLI v0.5.2. *If you hit this:* run `coderabbit --help` first and adapt to the
  installed flag set.
- **Git index reset mid-commit on a shared tree.** Commit aborted with no hooks present.
  *If you hit this:* a concurrent session touched the index — stage+commit atomically in
  one command; don't split `git add` and `git commit` across Bash calls.
- **Burning API quota.** *If you hit this:* verify the live `--agent` path once, then
  unit-test the pure parser on sample NDJSON instead of re-running live reviews on doc-only
  changes.
- **OpenSpec collision fear.** The active `add-code-quality-skill` looked overlapping but is
  Biome (deterministic lint) vs CodeRabbit (AI review). *If you hit this:* read the
  overlapping active change before scaffolding; document the composable relationship.
