# How we did it: Redesign goal-create as a modal dialog — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) on the Goal plugin —
a thinking stance, not an implementation task. The real objective, once the AI grounded
itself, was two-part: **(1)** the just-shipped "new goal" flow renders as an *inline
form* that pushes the sidebar/board down, while every other folder-plugin create flow
(automations) uses a **modal dialog** — so make goal-create a dialog too; and **(2)**
the standalone `mockups/goal/index.html` had drifted from the shipped `GoalForm`
(stale field names, obsolete "needs new wiring" tags) and needed to be re-synced to
real code. The deliverable stayed at the **mockup + OpenSpec proposal** level — no
`.tsx` was touched (explore mode forbids implementation).

## 2. TL;DR playbook

1. **Enter explore mode** with `openspec-explore` — establishes the "think, don't
   implement" guardrail so the AI produces artifacts (mockups, proposals), not code.
2. **Let the AI ground itself first.** It recovered context from a compacted session,
   found the archived `sophisticate-goal-authoring-and-control` change, and located the
   live mockup + the existing modal pattern (`CreateAutomationDialog`) to mirror.
3. **Point at the reference pattern:** the AI copied the automation dialog's overlay
   chrome verbatim (`fixed inset-0 z-50 flex items-center justify-center bg-black/40`)
   so the goal dialog is visually faithful and precedent-consistent.
4. **Edit only the target screen** of the mockup (Screen A → modal), re-sync fields to
   the shipped `GoalForm` (Max turns / Max spend, editable criteria, judge select).
5. **Ask "what was lost?"** → have the AI `git diff` the mockup against its committed
   version and build a live side-by-side `compare.html` (Before ↔ After + annotated
   "what was lost vs changed on purpose").
6. **Restore genuine content losses** ("add them") — teaching hints the shipped code
   doesn't carry (judge-model rationale, criterion→`/subgoal` mapping).
7. **"draw proposal"** → run a pre-scaffold **coherence check** for duplicate/archived
   goal work, then scaffold the OpenSpec change and author proposal + design + tasks +
   spec delta.
8. **Revert `groups.json`** — the scaffold auto-mutates it and grabs unrelated churn;
   `git checkout -- openspec/groups/groups.json` keeps the change clean.

## 3. How the collaboration unfolded

**Phase 1 — Ground (recover + locate).** Picking up from a compacted session, the AI
first rebuilt context: it found the archived goal changes, the live mockup
`mockups/goal/index.html`, the new shared `GoalForm.tsx`, and — crucially — that
`CreateAutomationDialog` already implemented the modal pattern goals lacked. *Why it
worked:* it named the exact inconsistency ("automations = dialog, goals = inline") before
proposing anything, so the fix was targeted.

**Phase 2 — Adapt the mockup (Screen A → dialog).** It read the automation dialog's
overlay classes and re-synced Screen A's fields to the shipped `GoalForm`, then served
the mockup and screenshotted via agent-browser (tight visual loop). *Decision point:* the
human implicitly approved the dialog with no steer, so the AI swept the remaining screens
for stale tags (`needs new wiring`, `partial`) and removed them.

**Phase 3 — Diff & recover (compare.html).** Prompt "what was lost… Make a HTML that
compares the two versions" turned an assumption into evidence: the AI pulled the committed
mockup from git, categorized every removed line as *intentional* vs *genuine loss*, and
built a live Before/After `compare.html`. *Why it worked:* forcing a visible diff caught
teaching content the field-sync had silently dropped.

**Phase 4 — Restore ("add them").** The two dropped teaching hints (judge-model rationale,
criterion→`/subgoal`) were re-added to the After dialog, code-faithful otherwise.

**Phase 5 — Draw the proposal.** "draw proposal" flipped to implement-mode intent. The AI
ran a coherence check (no duplicate goal-dialog change existed; archived work was
presentation-agnostic), scaffolded `redesign-goal-create-dialog`, and authored all four
artifacts, then reverted the auto-mutated `groups.json`.

## 4. Prompts that worked

- **The goal prompt** (`openspec-explore` skill invocation): effective because it set a
  hard stance — *artifacts, not code* — so the AI never drifted into premature `.tsx`
  edits and instead delivered a mockup + proposal.
- **"what was lost from mockup. Make a HTML that compares the two versions"** — a
  high-leverage follow-up: it converted a restyle into an auditable diff, surfacing
  silent content losses. Reusable pattern: *don't trust a sync; demand a Before/After.*
- **"add them"** — a two-word unlock: the AI had already tabled the exact list of losses,
  so a terse approval restored precisely the right items.
- **"draw proposal"** (repeated) — short, but the AI had enough grounded context to run
  the full coherence-check → scaffold → author pipeline unaided.

*Weak-prompt rewrite:* instead of the bare "add them", a future operator could say
*"restore the two teaching hints but keep the shipped empty-state behavior"* to remove
any ambiguity about which drops to reverse.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Silently drop explanatory content while "syncing to shipped code" | "what was lost… make a compare HTML" | Always `git diff` a mockup edit and render Before/After before declaring it done |
| Treat a field-sync as pure win (no losses) | asking to categorize losses vs intentional changes | State up front: "flag any rationale/teaching text a sync removes" |
| Stop at the mockup | "draw proposal" (twice) | Name the end state early: "mockup → then draw the OpenSpec proposal" |
| Leave `groups.json` churn from the scaffold | (AI self-corrected per repo rule) | Keep the rule "never blind `git add` groups.json; `git checkout --` it" |

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was created this session. The **repeatable workflow worth
capturing** is *mockup-drift audit*: after any edit that claims to "sync a mockup to
shipped code", (1) `git diff` the file against its committed version, (2) categorize each
removed line as intentional-restyle vs genuine-content-loss, (3) render a live
`compare.html` (Before/After iframes + annotated panel), (4) restore only the genuine
losses. This removes the biggest risk of "sync" edits — silently deleting design
rationale — and makes the change auditable in a browser. Consider saving it as a skill
next time this pattern recurs.

The session leaned on existing infrastructure effectively: `openspec-explore` (stance
guardrail), the **agent-browser tight visual loop** (serve mockup → screenshot → verify),
and the **coherence-check-before-scaffold** discipline that kept the new change from
duplicating archived goal work.

## 7. Pitfalls & dead ends

- **Port already in use.** The mockup server on `8777` was taken; the serve command
  failed once. *Fix:* pick a fresh port (`8782`) rather than fighting the stale one.
- **`groups.json` auto-mutation.** `openspec` scaffold/validate rewrites
  `openspec/groups/groups.json`, grabbing unrelated churn (archived changes reshuffled)
  and sometimes *not even adding your change*. *Fix:* `git checkout --
  openspec/groups/groups.json` and never blind-`git add` it — verify only your 5 change
  files remain.
- **Sync-without-diff = silent content loss.** Re-syncing the mockup to shipped
  `GoalForm` dropped judge-model rationale and the criterion→`/subgoal` teaching. *Fix:*
  the compare-HTML audit from §6 catches these; don't skip it.
