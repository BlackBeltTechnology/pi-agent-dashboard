# How we did it: Turning an explore-mode research burst into a durable, correctly-filed doc — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore` skill) — a thinking stance, not an implementation task. The user's real ambition surfaced through the exploration: they wanted to *"train a neuron based model which helps improve LLM context by learning the training data"* and *"the trained model can be used to build knowledge graph from document/code."*

The AI's first high-value move was to **split that one wish into two distinct ambitions** — a memory/retrieval system (mostly *not* a trained net) vs. an extraction model (where a small trained net earns its keep). Once the thinking was rich, the *actual* deliverable the user asked for was mundane but important: **capture everything — findings, all ~40 links, the reasoning — into a standalone research document that can be processed later**, and file it in the right place. The last third of the session was pure documentation housekeeping (where does it live, and merge the sibling `plan`/`plans` dirs).

## 2. TL;DR playbook

1. Enter explore mode (`openspec-explore`) — you get a thinking partner that will *not* write code, only capture thinking.
2. Kick off **parallel web research** across the key angles before designing anything (KG construction, relation-extraction models, GraphRAG, on-device training).
3. When the research is rich, ask the AI to **reframe the tangled ask** into clean, separable ambitions before deciding anything.
4. Say **"create a research document and save all details, links. It will be processed later"** — this converts volatile chat into a durable, ~19 KB annotated artifact.
5. Decide *where* it lives. Root `research/` avoids the repo's caveman-style `docs/` protocol; `docs/research/` is more discoverable. Let the AI flag the trade-off, then pick.
6. `git mv` the file into the chosen home; remove the now-empty source dir.
7. For any dir-merge housekeeping (`plan` → `plans`), **grep for cross-references first** so you don't break links.
8. Before touching anything, **re-check disk reality** — a concurrent session may have already done the work.

## 3. How the collaboration unfolded

**Phase 1 — Gather (parallel research).** The AI fired two `web_search` batches immediately, covering KG construction, REBEL/UniRel relation extraction, GraphRAG, GNN⊗LLM, agent memory, log→dataset ETL, and Apple-Silicon (MLX/GGUF) training feasibility. *Why it worked:* front-loading breadth meant the later reframing rested on real sources, not guesses.

**Phase 2 — Reframe (the thinking payload).** Rather than answer "how do I train it," the AI surfaced a **fork**: Ambition A ("improve LLM context") is really a memory/retrieval + KG layer, *not* a net you train on your logs; Ambition B ("build a KG from docs/code") is the extractor where training pays off. *Decision point:* the human accepted the split and asked to preserve it in writing.

**Phase 3 — Capture (the artifact).** On *"save all details, links…for later"*, the AI wrote `research/pi-logs-knowledge-graph-training.md` (~19 KB, §0–8: TL;DR, reframing, 5-step reference pipeline, 3 trained-model slots with ROI ranking, hardware matrix, best-practice distillates, **all ~40 annotated links**, open decisions, next steps). It deliberately placed it at **repo root**, outside `docs/`, to dodge the caveman-style docs protocol.

**Phase 4 — File it right (steering).** The human nudged: *"Maybe there is a research directory inside docs."* The AI checked (none existed), flagged the caveman-style-vs-verbose-prose tension, and on approval `git mv`d it to `docs/research/`, deleting the empty root dir.

**Phase 5 — Housekeeping + concurrency surprise.** On *"merge plan and plans,"* the AI grepped for references first (found one in `design.md`), started the merge — then noticed **disk state didn't match its own commands**. A **concurrent session** had already consolidated `plan`, `plans`, and `architecture-notes` into `docs/research/` and fixed the `design.md` reference. The AI verified nothing was broken and stood down cleanly rather than fighting the other session.

## 4. Prompts that worked

- **The goal prompt (skill-driven):** entering `openspec-explore` set the right stance — think, don't implement. A future kickoff can be as plain as *"Explore mode: I want to train a model to improve LLM context and build KGs from my logs — help me think it through."*
- **High-leverage capture prompt:** *"create a research document and save all details, links. It will be processed later"* — one sentence that converted a whole exploration into a durable, processable artifact. The phrase **"processed later"** is what justified verbose prose + full link annotation over terse notes.
- **Filing nudge:** *"Maybe there is a research directory inside docs"* — gentle, let the AI check reality and raise the protocol trade-off instead of guessing.
- **Housekeeping:** *"merge plan and plans"* — terse but unambiguous; the AI correctly expanded it into "grep refs → merge → fix links."

No new skill or memory was created this session. The reusable pattern it demonstrates is worth codifying:

- **Recommended skill: `explore-to-research-capture`.** Captures the move from an explore-mode thinking burst → a standalone, annotated research doc filed under `docs/research/` (exempt from caveman-style since it's a later-processed capture, not agent-loaded context). *Why effective:* it removes the recurring friction of "where does verbose research live in a repo whose `docs/` protocol wants terse fragments," and standardizes the §0–8 structure (TL;DR → reframing → pipeline → model slots → hardware → best practices → annotated links → open decisions).
- **`openspec-explore` (used, not created):** the right container for this work — it guarantees no code gets written while still allowing artifact capture.

## 7. Pitfalls & dead ends

- **`git mv docs/plan/electron-app.md docs/plans/…` failed** — the on-disk state had already shifted under a concurrent session. *If you hit a failed `git mv` during a merge, stop and re-inspect `ls` + `git status` before retrying* — don't assume your last command succeeded.
- **Concurrent-session collisions are real.** Two pi sessions were reorganizing `docs/` at once. *If disk reality contradicts your own recent commands, a sibling session is likely editing the same tree — verify, don't overwrite.*
- **The `docs/` caveman-style protocol fights long-form prose.** A verbose annotated research artifact would be gutted by the "short fragments, dropped articles" rule. *Keep research captures explicitly exempt* (they're processed-later artifacts, not per-turn agent context).
- **Worktree false-positive references.** A grep match inside `.worktrees/feat-coderabbit-review-gate/` was correctly *ignored* — it's a different branch's checkout, not a live reference to fix.
