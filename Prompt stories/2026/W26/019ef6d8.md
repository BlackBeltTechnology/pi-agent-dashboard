## 1. Goal (the ask)

The session opened with a one-line question — *"Is knoledge base system plugin activated?"* — but the real objective grew through steering into a full activation project: **take the repo's own `kb`/`kb-extension` workspace packages from dormant-on-disk to live-and-authoritative.** That meant wiring the extension into `.pi/settings.json`, fixing the broken workspace symlinks so its import resolves, pinning the right index sources (`docs/`, `openspec/`, `packages/`, `.pi/`) at both project and global scope so git worktrees inherit, documenting the packages in the file-index, and finally editing `AGENTS.md` + the tool's `promptGuidelines` so the model reaches for `kb_search` **before** `ctx_search`/`memory_search`/grep. Ship it as one clean commit.

## 2. TL;DR playbook

1. **Disambiguate first.** Two "knowledge bases" coexist: the global **context-mode** KB (`ctx_*`, always healthy) and this repo's own **kb plugin** (`kb_search`/`kb_neighbors`/`kb_get`). Confirm which one the user means before answering.
2. **Prove activation state, don't assume.** The definitive test: are `kb_*` tools present in the session? Check `.pi/settings.json` `extensions[]` and `~/.pi/agent/settings.json` — the kb-extension is deliberately *not* wired by default.
3. **Wire it:** add `+packages/kb-extension/src/index.ts` to project `.pi/settings.json`.
4. **Fix the missing link:** the `kb` + `kb-extension` workspace packages weren't symlinked into `node_modules` → the `@blackbelt-technology/pi-dashboard-kb` import fails. Run `npm install` to create the symlinks. Verify with a jiti import smoke test.
5. **Reload + restart:** `npm run reload` (all sessions) then `POST /api/restart`; poll `/api/health` until back up.
6. **Index bounded sources only.** NEVER `--source .` at the repo root (it walks 26k+ `node_modules` md files and appears to hang). Pin `["docs","openspec","packages",".pi"]` in `.pi/dashboard/knowledge_base.json`, with `exclude` = `["**/node_modules/**","**/.worktrees/**","**/archive/**"]`.
7. **Write the config twice** — project (`.pi/dashboard/knowledge_base.json`) AND global (`~/.pi/dashboard/knowledge_base.json`) — because the resolver does NOT walk up parents, so worktrees inherit only via the global fallback (sources are stored relative).
8. **Document via subagent.** New `docs/file-index-kb.md` split + register its row — delegate the `docs/` write to a general-purpose subagent in caveman style per the Documentation Update Protocol.
9. **Make it the default:** add a kb-first rule to `AGENTS.md` (STOP gate + Investigation Protocol) and strengthen the tool's `promptGuidelines`. Add the file-index caveat (§5).
10. **Commit only your files** — stage explicitly, leave concurrent-session changes alone.

## 3. How the collaboration unfolded

**Phase 1 — Discovery / disambiguation.** The AI ran `ctx_doctor`, reported the context-mode KB as PASS, but flagged the ambiguity: the repo *also* ships its own `kb` packages. The human's steering (*"there is a kb plugin in project base"*) locked the target. The AI then read `.pi/settings.json`, the global settings, and the extension source, and proved non-activation by the absence of `kb_*` tools — evidence, not assertion. **Effective bit:** it treated "is X active?" as a falsifiable claim with a concrete test (tool presence).

**Phase 2 — Wire + repair.** Added the extension to settings, then hit the real blocker: the workspace symlinks for `@blackbelt-technology/pi-dashboard-kb[-extension]` were missing from `node_modules`, so the import errored. `npm install` created them; a jiti import smoke test confirmed `LOADED OK`. Reload + `/api/restart`, poll health until green.

**Phase 3 — Index engine test.** *"test kb search"* → the AI drove the CLI (since `kb_*` tools don't load in the already-running session). First index attempt with `--source .` appeared to hang; *"why it stuck?"* prompted the diagnosis: **26,660 md files (13,329 in `node_modules`)**, no nested-`node_modules` exclusion. Re-indexing bounded `docs/` (36 files → 704 chunks) proved search ranks correctly with BM25 + term highlighting.

**Phase 4 — Source pinning + worktree inheritance.** *"Add openspec too... And the config be in worktree parent's directory too"* drove the AI to read the config resolver (`projectConfigPath` does NOT walk up), then write BOTH a project and a global config so worktrees inherit. Config-driven index (no `--source`): 828 files / 14,297 chunks, worktrees excluded.

**Phase 5 — Routing / make-it-default.** A run of conceptual steering (*"LLM will use kb_search automatically?"*, *"Before LLM will call ctx, or memory...?"*) forced the AI to explain the honest truth — `kb_search` is the **weakest** of three competing retrieval surfaces (context-mode has a hierarchy directive + PreToolUse hook; memory has a policy block; kb had one soft `promptGuidelines` line). The human then said *"Add to AGENTS.md to search use kb_search tool first"* — the AI edited the STOP gate + Investigation Protocol and strengthened the tool guidelines.

**Phase 6 — File-index reality check + commit.** *"what files related to session card?"* then *"kb_search does not contain doc index?"* exposed a subtle bug: the file-index *is* indexed, but the giant single-line `SessionCard.tsx` row gets **BM25-buried** under tighter spec chunks. The AI corrected its earlier wrong claim and added a caveat routing per-file lookups to `kb get` / an Explore subagent. Final: staged only the 7 kb files, committed `1b09e99c`.

## 4. Prompts that worked

- **Goal prompt** — *"Is knoledge base system plugin activated?"* Weak as written (ambiguous which KB; a typo). A stronger kickoff: *"Is the repo's own kb-extension (kb_search tool) wired into this project's pi settings? If not, activate it."*
- **High-leverage follow-ups:**
  - *"why it stuck?"* — a two-word prompt that turned a silent hang into the durable `--source .` footgun lesson.
  - *"And the config be in worktree parent's directory too"* — forced the AI to read the resolver instead of guessing, producing the correct dual-config solution.
  - *"Before LLM will call ctx, or memory will use kb_search tool?"* — extracted an honest ranking of the three retrieval surfaces, which directly motivated the AGENTS.md change.
  - *"kb_search does not contain doc index?"* — a skeptical push that caught the AI's incorrect claim and produced a real ranking-vs-coverage diagnosis.

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was created in-session, but the workflow is clearly repeatable and two durable rules were encoded into the repo itself:

- **`AGENTS.md` kb-first rule + file-index caveat** — captures the retrieval routing (kb_search first for facts; `kb get` / Explore for per-file lookups) so every future session inherits it without re-deriving. Effective because AGENTS.md loads every turn, outranking soft per-tool guidelines.
- **Strengthened `kb_search` `promptGuidelines`** in `packages/kb-extension/src/extension.ts` — spells out the corpus boundary (repo docs vs session memory) at the tool layer.

**Recommended skill to create:** a project skill *"activate-kb-plugin"* capturing steps 3–7 of the playbook (wire → `npm install` symlink fix → reload/restart → bounded dual-config index) — it removes the symlink-blocker rediscovery and the `--source .` footgun every time.

## 7. Pitfalls & dead ends

- **`--source .` at repo root looks like a hang** — it's actually walking 26,660 md files (13,329 in `node_modules`). Fix: pin `docs/openspec/packages/.pi` and exclude nested `node_modules`.
- **Extension import fails silently after wiring** — workspace symlinks for `@blackbelt-technology/pi-dashboard-kb[-extension]` were never in `node_modules`. Fix: `npm install`, verify with a jiti import smoke test.
- **Worktrees don't see the project config** — `projectConfigPath(cwd)` does NOT walk up parents. Fix: also write the global `~/.pi/dashboard/knowledge_base.json` (relative sources make it resolve per-worktree).
- **File-index rows don't surface in `kb_search`** — the index *has* them, but the enormous single-line `SessionCard.tsx` row is BM25-buried under tighter spec chunks. Fix: use `kb get docs/file-index-<area>.md` directly, or an Explore subagent.
- **Current session never gets the new tools** — extension changes apply only on session reload/new-start; use the CLI to exercise the engine in the live session.
- **Concurrent-session changes in `git status`** — don't blanket `git add .`; stage only your files.
