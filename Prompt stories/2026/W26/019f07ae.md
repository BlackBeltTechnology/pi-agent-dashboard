# How we did it: De-flaking the image-fit jimp tests — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) — a thinking-only stance,
no implementation. The real, unstated objective surfaced immediately once the AI dug
in: **the `image-fit-extension` test suite was flaking in CI, and the user wanted to
know whether their own change caused it and how to stop the flake.** The genuine goal
was a two-parter: (1) diagnose whether the failure was the user's diff or the
environment, then (2) make the suite comfortably fit inside CI's 30s timeout. The
explore stance framed the first half (diagnose, don't touch code); the terse steering
prompts unlocked the second half (shrink the fixtures).

## 2. TL;DR playbook

1. **Run the suspect suite locally** with verbose timing:
   `cd packages/image-fit-extension && npx vitest run --reporter=verbose 2>&1 | tail`.
2. **Separate signal from noise:** if all tests *pass locally* but the wall-clock is
   near the CI timeout (here **22.98s vs a 30s budget**), the flake is
   **environmental (load-induced), not a code bug**.
3. **Prove it's not your diff:** `git diff --name-only main...HEAD` — confirm zero
   files in the flaking package are touched.
4. **Find the real cost center by per-test timing**, not by assumption. The first
   guessed culprit (the resize fixtures) was wrong; verbose timing pointed at
   `extension.test.ts`.
5. **Shrink the heavy jimp fixtures** to the *smallest* size that still trips the
   code path (`maxEdge: 1568` → use `1600×1200`, preserving the 4:3 aspect so
   dimension math in assertions stays valid).
6. **Re-run twice** to confirm stability and measure: `for i in 1 2; do npx vitest
   run 2>&1 | grep -E 'Tests|Duration'; done`.
7. **Run the review gate** (CodeRabbit on the diff) before committing test-only
   changes.
8. **Stage only your files** — commit the two test files, leave unrelated
   working-tree changes (`openspec/groups/groups.json`) untouched.

## 3. How the collaboration unfolded

**Phase 1 — Diagnose (explore stance).** The AI ran the suite locally, saw 72/72
pass, and flagged the tell: **22.98s duration against a 30s CI budget**. It built an
*evidence chain* — empty diff for the package, real jimp pure-JS PNG/JPEG round-trips
on 4032×3024 images, `testTimeout: 30000` in `vitest.config.ts`. Verdict:
**environmental flake, not the user's change.** Why it worked: the AI refused to
assume the user broke it and instead grounded the claim in the diff + the timeout
config + the wall-clock margin.

**Phase 2 — First fix attempt (mis-attributed).** Prompted with "Shrink fixtures,"
the AI shrank the `resize.test.ts` fixtures (4032×3024 → 1600×1200) while preserving
4:3. Result: only a modest **3s drop**. The AI honestly reported the fixtures "clearly
aren't the dominant cost — something else eats ~17s."

**Phase 3 — Find the real culprit.** Re-prompted "Shrink fixtures" again, the AI used
per-test timing to locate the true cost: **`extension.test.ts`**, where
`makeOversizePng` built 12M-pixel images with a per-pixel `scan()` loop *then*
JPEG/PNG-encoded them — four tests at 3.3–4.6s each. It verified the assertions only
checked path rewrite / extension / existence / cache (not absolute source dims), so
shrinking was safe. Shrank those to 1600×1200 (still above `maxEdge: 1568`).

**Phase 4 — Verify + ship.** Full suite dropped **22.98s → 7.66s (3×)**, slowest
single test **4.6s → 1.18s**, 72/72 still green. On "yes," the AI ran CodeRabbit
(clean), staged **only** the two test files, and committed `71695872` on `develop`.

## 4. Prompts that worked

- **Goal prompt (`openspec-explore` stance):** Effective because it forced a
  *diagnose-first* posture — the AI proved root cause before touching a line. For a
  future run, the stronger explicit kickoff is: *"The image-fit tests flake in CI.
  First tell me if it's my diff or the environment — don't change code yet."*
- **"Shrink fixtures" (×2):** A high-leverage two-word steer that moved from
  diagnosis into implementation. The repeat was the operator's way of saying "not
  done — the number didn't move enough." A crisper version: *"The resize fixtures
  weren't the cost — find the actual slow file and shrink those fixtures too."*
- **"yes":** The classic short unlock — approved commit + review gate in one word.

## 6. Skills, tools & memory created — and why they're effective

No skill or memory was created this session. But the workflow is textbook-repeatable
and **should be captured** as a project skill, e.g. `diagnose-load-induced-test-flake`:

- **What it would capture:** the diagnostic heuristic *"passes locally + wall-clock
  near the CI timeout = environmental flake, not a code bug,"* plus the fix pattern
  *"shrink heavy jimp/image fixtures to the smallest size that still trips the code
  path (just above `maxEdge`), preserving aspect ratio so assertion math holds."*
- **Why it's effective:** it removes the two traps this session hit — blaming your
  own diff, and shrinking the wrong file. It codifies "measure per-test time first."
- **When to invoke:** any CI flake in a package that does real image/crypto/encode
  work under a `testTimeout`, especially when it passes in isolation.

The concrete tools that carried the work: `vitest run --reporter=verbose` for
per-test timing, `git diff --name-only main...HEAD` for the innocence proof, and the
repo's CodeRabbit review gate for the ship check.

## 7. Pitfalls & dead ends

- **Dead end: shrinking `resize.test.ts` first.** It was the *obvious* fixture file
  but only a minor contributor (~3s). If you hit "the number barely moved," **stop
  guessing and time each test** — the cost was hiding in `extension.test.ts`.
- **Pitfall: shrinking fixtures below the trigger.** The resize gate only fires when
  the long edge exceeds `maxEdge` (1568). Shrink to `1600×1200`, not smaller, or the
  code path under test never runs and the test silently stops testing anything.
- **Pitfall: breaking assertion math.** Keep the **4:3 aspect ratio** so
  `expectedShort` and any dimension-equality assertions stay valid after shrinking.
- **Pitfall: committing unrelated staged changes.** `openspec/groups/groups.json`
  was already in the working tree — stage your test files **by name**, don't
  `git add -A`.
