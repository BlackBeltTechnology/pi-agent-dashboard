## 1. Goal (the ask)

The session opened in **openspec-explore mode** — a thinking-partner stance, no
implementing — with an open-ended prompt to investigate **Headroom** (a local-first
context-compression layer for AI agents) and reason about integrating it with the pi
coding agent. The *real* objective evolved across two arcs: first, produce a grounded
**research dossier** on whether/how Headroom could plug into pi; then, pivoting off a
second explore prompt about `addyosmani/agent-skills`, decide which of those skills
are **additive** to the repo's mature openspec pipeline and **ship the additive subset
as a new monorepo package**. Net output: one research doc + a fully-wired
`packages/eng-disciplines/` skills package, both committed.

## 2. TL;DR playbook

1. **Start in explore mode** for anything you don't yet understand — investigate first, don't build. Fire parallel `web_search` + `fetch_content` at the target repo *and* the ecosystem around it (found the crucial prior-art package on the first search).
2. **Ground both sides before concluding.** For Headroom: read its 4 integration surfaces. For pi: grep the extension events (`context`, `before_provider_request`, `tool_result`) to find the *cleanest* hook.
3. **Write the dossier as readable prose** deliberately *outside* `docs/` (at `research/`) to dodge the repo's caveman-style docs convention.
4. **Steer placement** ("move research to docs's research dir") → mechanical `git mv`, not a rewrite, to preserve prose. Then `commit`.
5. **Re-enter explore** for the skills question. Map overlap-vs-gap against the existing openspec pipeline before importing anything.
6. **Push the AI to check the layer it missed** ("There are extensions packaged modules in monorepo. Check thats too") — surfaced the Tier-1 (dev) vs Tier-2 (shipped) skills distinction.
7. **Give the build directive** ("Bundle as separate package in monorepo"). AI studies the closest analog package first, proposes a plan + skill table, then scaffolds.
8. **Copy only the openspec-orthogonal skills, retarget every trigger** off `spec/plan/build/ship/review` verbs, preserve MIT attribution (NOTICE), register the workspace, verify, `commit`.

## 3. How the collaboration unfolded

**Phase A — Discovery (Headroom).** Parallel `web_search`/`fetch_content` on the
Headroom repo, its docs (`llms-full.txt`), npm, and — critically — the ecosystem. The
first search surfaced `@raquezha/noheadroom`, an *existing* pi↔Headroom integration.
Effective because it reframed the whole question from "how would we build this" to
"how did the prior art already solve this, and what traps did they hit."

**Phase B — Grounding the hooks.** The AI grepped pi's extension event docs to isolate
the three mutation points (`context`, `before_provider_request`, `tool_result`) and
learned the prior art applies **only `toolResult` mutations**, leaving user/assistant
bytes identical. Decision point: prose research artifact placed at `research/` (outside
`docs/`) on purpose.

**Phase C — Relocate + commit.** Human steered placement into `docs/research/`. The AI
did a **mechanical `git mv`** (not a rewrite) to keep readable prose, flagged that it
skipped caveman conformance, and committed (`b0c2cdfd`, 1 file, +314).

**Phase D — Skills overlap analysis.** A second explore prompt about
`addyosmani/agent-skills`. The AI resisted the human's instinct ("more skills → more
focus") and argued the *opposite*: auto-routing by NL trigger means two skills for the
same job = ambiguous routing = **less** focus. It mapped Addy's generic lifecycle pack
against the repo's openspec-native pipeline as DUP-vs-gap.

**Phase E — The missed layer.** Human: "There are extensions packaged modules in
monorepo. Check thats too." This forced the AI to discover Tier-2 **packaged & shipped**
skills (`packages/*/.pi/skills/`, bundled extensions) — a layer its first analysis had
ignored, changing the recommendation.

**Phase F — Build & ship.** Directive: "Bundle as separate package in monorepo." The AI
studied the closest analog (a pure-skill package), proposed a package name + a table of
the 6 additive skills with reworded triggers, then scaffolded: copied 6 skills, rewrote
each frontmatter (`name` to match dir, triggers retargeted), added `package.json` +
`README` + MIT `NOTICE`, ran `npm install --workspaces` to register, verified, committed
(`d01e4e4d`, 10 files, +1980/−2).

## 4. Prompts that worked

- **The goal prompt (explore-mode stance).** Effective because it set a *thinking-first*
  constraint — the AI investigated and produced a grounded dossier instead of jumping to
  a half-informed integration.
- **"There are extensions packaged modules in monorepo. Check thats too"** — a
  high-leverage one-liner. It named a blind spot and forced a re-analysis that materially
  changed the conclusion. Rewrite for reuse: *"Before you conclude, also account for the
  packaged/shipped skills under `packages/*/.pi/skills/` and the bundled extensions."*
- **"Bundle as separate package in monorepo"** — short directive that unlocked the whole
  build phase. It worked because the prior explore phases had already established *which*
  skills and *why*, so "bundle" had unambiguous scope.
- **"move research to docs's research dir" / "commit"** — terse steering that worked
  because the AI had already produced a clean artifact; low-ambiguity next-actions.

## 7. Pitfalls & dead ends

- **Caveman-docs trap:** placing prose under `docs/` implicitly opts into the repo's
  caveman-style + subagent-delegation convention. Sidestep by keeping readable research at
  `research/` or `docs/research/` and doing a **mechanical move**, not a rewrite.
- **`npm query` reads installed state:** a freshly-added workspace won't appear until you
  run `npm install --workspaces --include-workspace-root` to register the symlink. Install
  *before* asserting the workspace is wired.
- **Trigger-fight risk:** bulk-importing a lifecycle skill pack next to an existing
  openspec pipeline creates ambiguous NL routing. Only import the orthogonal subset and
  reword every trigger.
- **MIT attribution:** copying Addy's skills requires preserving the copyright — ship a
  `NOTICE` file, don't drop the license.
