# How we did it: Three reconnection/replay bugs in one session — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The kickoff prompt was a single symptom report:

> "For some reason openspe apply does not show that openspec event happens"

The *real* objective, once the steering turns landed, was broader: **hunt down and fix
three distinct dashboard state-sync bugs that all trace back to the bridge→server replay
path** — (1) the OpenSpec activity badge never rendering for prompt-template-invoked
skills, (2) a session card stuck on "Waiting for input" while the agent was actually
streaming after a reconnect/reload, and (3) events multiplying exponentially ("jibberish
which increasingly comes sometimes") on repeated reconnects. Then document all three and
ship them in one commit.

## 2. TL;DR playbook

1. **Report the symptom, not a fix.** "openspec apply doesn't show the event happens" —
   let the AI trace the event flow from bridge → server extraction → client render.
2. **Follow the render gate to its source.** The badge only rendered on
   `session.openspecPhase`; the phase is never set when a skill loads via a prompt
   template (SKILL.md read by the framework, not a `Read` tool call). Fix: render when
   `openspecPhase || openspecChange`, and make the badge's `phase` prop optional.
3. **When a card shows a stale status, suspect replay.** Reconnect/reload replays
   `message_*` + `tool_execution_*` events but **not** `agent_start`/`agent_end`, so
   status never leaves "active" (rendered as "Waiting for input").
4. **Track streaming in persistent bridge state.** Add `isAgentStreaming` to
   `BridgeState`, set on `agent_start`/clear on `agent_end`+`session_shutdown`, and emit a
   **synthetic `agent_start`** after `replay_complete` when still streaming.
5. **When events "increasingly" multiply, suspect double-insertion.** `canSkipWipe` kept
   the event store but still re-inserted every replayed event → exponential doubling per
   reconnect. Fix: a `skipReplayInsert` set that skips both the re-insert and the
   `event_replay` batch send (browser already has them).
6. **Verify with build + restart, not just tsc.** `npm run build` → `curl -X POST
   /api/restart` (server) and `npm run reload` (extension). A pre-existing tsconfig error
   is not your regression — confirm the build passes.
7. **Update docs in the same pass:** `docs/architecture.md` (reconnection section) +
   `AGENTS.md` per-file rows. Then `git add -A`, **reset unrelated `openspec/` changes**,
   commit all three fixes together, push.

## 3. How the collaboration unfolded

**Phase 1 — Trace the OpenSpec badge (discovery).** The AI grepped the detector, the
bridge tool-forwarding path, the server extraction, then the client render. It found the
gate: `SessionCard.tsx` rendered the badge only on `openspecPhase` (two spots — desktop +
mobile), but the server correctly sets `openspecChange` without a phase. *Why it worked:*
following the data end-to-end (emit → extract → render) surfaced that the bug was purely
client-side render logic, not detection.

**Phase 2 — Fix the render gate.** Made `OpenSpecActivityBadge`'s `phase` prop optional
(neutral "OpenSpec" label when absent) and changed both render conditions to
`openspecPhase || openspecChange`. Confirmed the detector regex already matched
`openspec instructions apply --change "name"`.

**Phase 3 — "Waiting for input" stuck status.** Steering turn #1 opened a second bug. The
AI traced `state-replay.ts` and confirmed the replay emits no `agent_start`/`agent_end`.
*Decision point:* rather than synthesize status inside the server, track streaming in the
**bridge's persistent state** and replay a synthetic `agent_start` — so the server's
existing `extractSessionUpdates` picks it up naturally with no new server logic.

**Phase 4 — Exponential event duplication.** Steering turn #2 was a screenshot of
"jibberish" that increases over time. The AI recognized the growth pattern as
double-insertion: `canSkipWipe` preserved the store but the bridge still re-inserted every
replayed event. Fix: a `skipReplayInsert` set gating both the insert and the batch resend,
including the 5s safety-timeout fallback path.

**Phase 5 — Document + ship.** "update specs" → rewrote the architecture reconnection
section (full-replay vs skip-replay fast path, `skipReplayInsert`, streaming recovery) and
the `AGENTS.md` rows for `bridge.ts` and `event-wiring.ts`. "commit and push" → `git add
-A`, then **`git reset HEAD openspec/`** to drop unrelated change files, one commit with
all three fixes, pushed to `develop` as `63fc2ea`.

## 4. Prompts that worked

- **Goal prompt** ("openspec apply does not show that openspec event happens") — effective
  because it names an *observable* symptom and lets the AI own the trace. A stronger
  version would add the reproduction: "when a skill is invoked via a `/opsx:` prompt
  template, the badge never appears — trace emit→extract→render."
- **"The session is running, card shows Waiting for input"** — a crisp state-vs-expected
  mismatch. High-leverage: it points the AI straight at status derivation and replay.
- **"Some jibberish which increasingly comes sometimes: [image]"** — the word
  *increasingly* is the whole diagnosis. Growth-over-time = duplication/accumulation, not a
  one-shot render bug. Name the *trend*, not just the glitch.
- **"update specs" / "commit and push"** — terse unlocks that worked because the prior
  phases had already established exactly what changed.

## 7. Pitfalls & dead ends

- **A red `tsc --noEmit` may be pre-existing.** The client tsconfig threw an error
  unrelated to the edits — don't chase it. Confirm with `npm run build` instead, which
  passed.
- **Vitest failed on "missing DOM environment"** for the SessionCard tests — an
  environment/config gap, not a regression from the change.
- **One `grep -oP` with `\x27` escapes failed** (the shell/quoting); the AI fell back to a
  `node -e` regex check to verify the detector pattern. Prefer `node -e` for regex
  validation over fighting shell-quoted PCRE.
- **`git add -A` swept in unrelated `openspec/` files** — always `git reset HEAD
  openspec/` (or stage explicitly) before committing a targeted fix.
