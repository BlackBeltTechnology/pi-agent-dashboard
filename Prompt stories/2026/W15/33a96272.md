# How we did it: Brand + package the Electron app for macOS, Windows & Linux — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The kickoff prompt:

> `/skill:openspec-explore` — "The electron App does not have icon, proper about, name etc. Have to be packaged in macOS dmg, Windows installer and linux deb, rpm — or some distribution independent package."

The *real* objective, once steering clarified it: give the Electron shell a proper identity (centered π icon, tray glyph, About panel, product name) **and** produce working installers for all three platforms — DMG (macOS), NSIS `.exe` (Windows), and DEB + AppImage (Linux). The hidden ~90% of the work turned out to be making the **bundled dashboard server actually launch inside the packaged app on a clean OS** — a 32-hour debugging odyssey through native-module and Docker cross-build failures. The visible deliverable (4 installers) sat on top of a deep runtime-plumbing fix.

## 2. TL;DR playbook

1. **Frame it as an OpenSpec change first.** `/skill:openspec-explore` → `create proposal` → `/opsx:ff electron-branding-packaging` to scaffold proposal/design/specs/tasks, then `/opsx:apply`.
2. **Icon pipeline:** recenter the π with `npx @the-focus-ai/nano-banana`, then `npx electron-icon-builder --input=resources/icon.png --output=resources --flatten` to emit `.icns`/`.ico`; hand-make `trayTemplate.png` / `trayTemplate@2x.png` (white π on transparent) with ImageMagick.
3. **Pin the Node version before touching Forge.** `electron-forge` + `@electron-forge/plugin-vite` need Node **≥22.12** — on 22.11 you get `require() of ES Module vite/index.js not supported`. Use `nvm use 22`.
4. **Don't ship the dashboard server via npm — bundle it.** The `@blackbelt-technology/pi-dashboard` package isn't published, so add the server source as an `extraResource` (`bundle-server.sh`) and resolve its `cli.ts` from `resources/server/…` in `server-lifecycle.ts`.
5. **Launch the bundled server with the `tsx` *binary*, not `node --import tsx/esm`.** The ESM loader does **not** shim `__dirname`; `node-pty`'s CJS `unixTerminal.js` needs it. `spawn(tsxBin, [cliPath, …])` fixed months of `__dirname is not defined`.
6. **Build Linux/Windows in Docker with `--source-only` + in-container `npm install`.** Never let a macOS host bake macOS `node-pty` prebuilds into a Linux bundle. Rebuild native modules inside the target container and keep only that platform's `prebuilds/`.
7. **Add a Doctor + retry loop for the clean-OS path.** `doctor.ts` checks ~12 components and does a live server-launch test; `main.ts` retries `ensureServer()` and shows a "Run Setup / Retry / Quit" dialog instead of silently quitting.
8. **Close the loop:** update `openspec/specs/electron-*`, `AGENTS.md` key-files, write `docs/electron-session.md`, then `npm run electron:build -- --linux` etc. Result: 4 installers.

## 3. How the collaboration unfolded

**Phase A — Discovery & spec (prompts 1–7).** The AI inventoried `packages/electron/` (forge.config, tray.ts, existing PWA icon), then ran the OpenSpec flow: explore → proposal → fast-forward artifacts → apply. This front-loaded a plan and specs before any code, which paid off when the work sprawled across 24 files. *Decision point:* the user picked AppImage over RPM ("AppImage is ok") and confirmed switching to the public-dir icon as the base.

**Phase B — Branding assets (early apply).** nano-banana recentered the π; `electron-icon-builder` produced the icon set; ImageMagick carved a white-on-transparent tray template. Effective because it chained an AI image edit into a deterministic icon generator rather than hand-cutting every size.

**Phase C — Forge maker wrestling (prompts 8–14).** A cascade of packaging errors, each surfaced by the user pasting the raw `npm run make` output: `paths[0] argument must be of type string` (third-party NSIS maker), `ENOENT ./resources/node`, `Cannot find module 'appdmg'`, and the decisive `require() of ES Module vite` — which traced back to **Node 22.11 < 22.12**. Lesson baked in: pin Node first.

**Phase D — The bundled-server strategy (prompts ~44–56).** The turning point: the dashboard server package isn't on npm, so a clean OS had nothing to run. The AI pivoted from "install via wizard" to "bundle the server as `extraResource`" and taught `server-lifecycle.ts` to resolve the CLI from the app's own resources. It also made the wizard install async (`execSync` was freezing the Electron main process) and added `NODE_PATH` + `~/.pi-dashboard/server.log`.

**Phase E — The `__dirname` saga (prompts ~57–70, 83).** Six attempts over hours: define it locally (already done), fix `type:module` scope, a `dirname-shim.js/mjs`, `tsx/register` CJS hook… The root cause: **`node-pty`'s CJS module uses bare `__dirname`, but tsx's ESM loader doesn't shim it**. The clean fix was to stop using `node --import` entirely and spawn the **`tsx` binary directly**, which shims correctly for all module kinds.

**Phase F — Native-module platform mismatch (prompts 64–73).** `pty.node` for `linux-x64` was missing because the bundle was built on macOS and copied macOS prebuilds into the Linux container. Fix: `bundle-server.sh --source-only` (no host `npm install`), then `npm install` + `npm rebuild node-pty` **inside** the Linux Docker container, retaining only the target platform's prebuilds.

**Phase G — Docker infrastructure grind (prompts 74–94).** A long tail of container-image problems: GPG signature failures on `node:22-bookworm`, out-of-disk (`docker system prune -af`), missing `bzip2`/`xz`/`wget`/`ca-certs`, `nsis`/`wine` absent from Bookworm, `npm prune --production` deleting the `@electron-forge/cli` devDep, `npx electron-forge` resolving the deprecated v5 package, and bare `electron-forge` not on `PATH`. Each was diagnosed from pasted build output. **Outcome:** all 4 installers built — DMG 164 MB, DEB 108 MB, AppImage 158 MB, NSIS `.exe` 111 MB.

## 4. Prompts that worked

- **The goal prompt** (`/skill:openspec-explore` + a plain-English gap list) was effective because it named the concrete deliverables (dmg / Windows installer / linux deb) *and* invoked the spec workflow, so the AI produced a plan instead of diving into code.
- **Terse unlock replies** — `AppImage is ok`, `create proposal`, `1`, the `/opsx:ff` and `/opsx:apply` slash-commands — kept momentum without re-explaining context.
- **The dominant high-leverage move was pasting raw terminal error output verbatim.** ~40 of the 94 prompts were literal `npm run make` / launch-test dumps. This was the single most productive prompt pattern here: the exact stack trace let the AI jump straight to the failing module/line.
- **Rewrite of a weak prompt:** instead of "it's still broken," prefer *"here's the full `~/.pi-dashboard/server.log` and the exact `spawn` command — the error is `__dirname is not defined` at `node-pty/lib/unixTerminal.js:30`."* Pinpoint the failing file + line and the AI skips the guessing loop.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Guess at Forge failures without the trace | Pasting the full `npm run make` output | Always capture build stderr to a file; hand the AI the exact stack + failing module |
| Try to `npm install` the unpublished dashboard package | Reporting the clean-OS failure | State up front: "server package is NOT on npm — it must be bundled as extraResource" |
| Reach for `node --import tsx/esm` to run TS | Reporting recurring `__dirname is not defined` | Rule: **launch bundled TS servers with the `tsx` binary**, never the ESM `--import` loader (it doesn't shim CJS globals) |
| Bundle native modules on the host | Reporting `pty.node` missing on Linux | Rule: cross-platform native modules are built **inside the target container**, prebuilds pruned to that platform |
| Let `execSync` block the UI | Reporting a frozen wizard | Any install/long op in Electron main → async `exec`/`spawn`, never `execSync` |
| Silently `app.quit()` on startup failure | Reporting the app "just closes" | Add a retry loop + a dialog that shows *why* it failed |
| Assume the VM white screen was code | Reporting a blank window on VMware | Auto-detect VMs via `sysctl -n hw.model` and `app.disableHardwareAcceleration()` |

## 7. Pitfalls & dead ends

- **`require() of ES Module vite` →** you're on Node < 22.12. `nvm use 22` (≥22.12). Not a code bug.
- **`__dirname is not defined` from a dependency →** you launched TS via `node --import tsx/esm`. Switch to the `tsx` binary. Shims like `dirname-shim.mjs`, forcing `type:module` off, and `tsx/register` were all tried and are **not** the durable fix.
- **`pty.node` / prebuild missing on the target OS →** the bundle carried the *build host's* native binary. Use `--source-only` and rebuild inside the target Docker container; prune `prebuilds/` to the one platform.
- **`paths[0] must be of type string` / `Cannot find module appdmg` →** third-party/native Forge makers with missing deps; verify each maker resolves before a full `make`.
- **Docker GPG signature errors on `node:22-bookworm` →** transient image issue; `node:22-bookworm-slim` worked, or allow-unauthenticated temporarily.
- **Docker "no space left" →** `docker system prune -af --volumes` + `docker builder prune -af`; raise Docker Desktop disk limit.
- **`electron-forge` not found in Docker →** `npm prune --production` drops the `@electron-forge/cli` devDep; and `npx electron-forge` resolves the deprecated **v5** package. Call the workspace binary at `node_modules/.bin/electron-forge` via the root `electron:make` script.
- **`nsis`/`wine` absent from Bookworm →** they're Windows-only; make their install non-fatal so Linux builds don't block.
- **Env vars via `open "PI Dashboard.app"` don't reach Electron →** detect conditions in-process (e.g. VM via `sysctl`) instead of relying on `ELECTRON_DISABLE_GPU`.
