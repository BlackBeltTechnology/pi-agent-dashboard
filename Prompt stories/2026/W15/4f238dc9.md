# How we did it: Making the Electron desktop app actually start pi sessions on Windows — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The kickoff was terse: *"Read @docs/electron-session.md. Current version still not work, the pi session not started."* On the surface this reads as one bug — the Electron desktop build spawns a pi session card that flashes and vanishes. The **real** objective, which only emerged over 37 steering turns across ~5h40m, was much larger: ship a **cross-platform Electron desktop app that boots, renders, and successfully spawns pi sessions on Windows (inside a VMware VM, under a Unicode username with a space), plus macOS/Linux** — and produce working distributables (ZIP, portable exe, NSIS installer). The single "session not started" symptom turned out to have a stack of independent root causes, each surfacing only after the previous one was fixed.

## 2. TL;DR playbook

1. **Reproduce and trace the spawn flow first.** Confirm `spawnStrategy` default is `headless`, then follow the pi process from spawn → register. The card flashing-then-vanishing = pi starts but never registers back.
2. **Bundle the bridge extension** (`packages/extension/`) into the server bundle and **auto-register it** in `~/.pi/agent/settings.json` at server startup. Without the bridge, pi has no way to connect back — this is root cause #1. Write a test for the no-crash-on-missing-settings path.
3. **On Windows, spawn the real Node entry point, not the `.cmd` shim.** Resolve `node.exe path/to/pi/dist/cli.js` instead of `spawn("pi.cmd", …, {shell:true})`. No shell → no console-window flash, no path-splitting on spaces.
4. **Externalize `node:*` builtins in the Vite main/preload configs.** Bundling `node:fs`/`node:path` into the ESM main bundle breaks `require` on Windows (worked on mac/Linux by luck).
5. **Quote every path and handle Windows layout differences.** npm lives at `node_modules/npm/` on Windows (not `lib/node_modules/npm/`); usernames like `Róbert Csákány` contain spaces and Unicode.
6. **Use `detached:false` + `child.unref()` on Windows**, never `detached:true` (which forces a console window even with `windowsHide:true`).
7. **Replace workspace symlinks with real copies** after `npm install` in the Docker build — symlinks survive the ZIP but break in the portable exe's temp extraction.
8. **Make the extension stale-path cleanup regex platform-aware** (`C:\…` as well as `/usr/lib/…`).
9. **Add disk-based startup logging early** (before other imports) when the app dies with no window and no console — it tells you exactly where boot stalls.
10. **Commit in themed chunks, update `docs/electron-session.md` (phases + lessons), `architecture.md`, `AGENTS.md`.** Add a splash screen last for the ~1-min boot.

## 3. How the collaboration unfolded

**Phase 1 — Discovery & root cause #1 (the missing bridge).** The AI traced the spawn flow through `process-manager.ts` and the client's spawning-placeholder logic, then realized the DEB/bundle never shipped `packages/extension/`. Fix: bundle it + auto-register in `~/.pi/agent/settings.json` via a new `extension-register.ts`, with a test for malformed/missing settings. *Why it worked:* the AI resisted patching symptoms and instead asked "how does pi connect back at all?" — the answer was "it can't." Decision point: the user confirmed "It works. Update specs, session."

**Phase 2 — Cross-compiling Windows from Linux/Docker.** A long grind: Forge's NSIS maker refuses to run on Linux → switch to `electron-forge package` + `electron-builder`; missing `unzip`; `wine` required for NSIS uninstaller extraction (`wine32:i386` uninstallable on bookworm-slim) → **abandon NSIS in Docker, ship portable/ZIP; NSIS builds natively in CI**. *Why it worked:* the AI kept the risk boundary clear — guaranteed targets (ZIP, portable) vs best-effort (NSIS). Decision points were driven by pasted build logs.

**Phase 3 — The app runs but nothing renders (Windows VM).** VMware GPU blocks Chromium; the AI hardened VM detection (`wmic computersystem get manufacturer,model`). Then the app died with no window and *no log*. The AI added disk logging — but the log never appeared, meaning the crash was before its code ran. Root cause: **Vite bundled `node:*` builtins**, breaking `require` on Windows. Fixed by externalizing builtins in both Vite configs.

**Phase 4 — Wizard works, but spawn fails.** A cascade of Windows-isms: bundled npm path (`node_modules/npm/` not `lib/…`); `spawn EINVAL` on `.cmd` files needing `shell:true`; spaces in `Róbert Csákány` needing quoted paths; then the cleaner **spawn `node.exe` directly** to kill both the shell requirement and the console-window flash; `detached:false` to stop the flash entirely.

**Phase 5 — Portable exe specifics + final polish.** Portable exe needed `executableName: "pi-dashboard"` (Forge's name ≠ electron-builder's `productName` assumption); workspace symlinks broke in temp extraction → replace with copies; extension cleanup regex made Windows-aware. Committed in themed chunks; ended with a splash screen for the ~1-min cold boot.

## 6. Skills, tools & memory created — and why they're effective

No pi skill or memory was created in-session, but the workflow is strongly repeatable and **`docs/electron-session.md` served as the durable artifact** — the AI appended phases (20, 21) and a lesson ("bundle all components pi needs"). That running phase-log is the real reusable asset: it let a terse kickoff inherit hours of prior context.

**Recommended skill to create:** `electron-windows-spawn-fixes` — a project skill capturing the Windows spawn checklist (spawn `node.exe` not `.cmd`; `detached:false`+`unref`; quote paths; branch npm/node layout; replace workspace symlinks with copies; externalize `node:*` in Vite; platform-aware extension-register cleanup). Every one of these was discovered by painful trial; a checklist collapses the next Windows-bring-up from 5h to minutes. Invoke it whenever touching Electron packaging or cross-platform spawn.

## 7. Pitfalls & dead ends

- **Full test suite kills the live session** — scope to the changed package.
- **NSIS via Docker/Wine** — `wine32:i386` can't install on bookworm-slim; the uninstaller-extraction step fails. Don't. Ship ZIP+portable from Docker; build NSIS natively in CI.
- **Debug logging that uses `require` in an ESM main bundle** crashes before it can log — the classic "no log, no window" trap. Root cause was Vite bundling `node:*`; externalize them.
- **`detached:true` on Windows** forces a console window even with `windowsHide:true`.
- **Workspace symlinks** survive ZIP extraction but break in the portable exe's 7z temp extraction — replace with copies post-`npm install`.
- **`executableName` mismatch** — Forge emits `pi-dashboard.exe`, electron-builder's portable wrapper assumes `productName` → set `executableName: "pi-dashboard"`.
- **Unix-only path checks** (`startsWith("/")`) silently skip all `C:\…` paths — stale extension registrations never got cleaned on Windows.

## 8. Reproduce it faster — checklist

- [ ] Confirm spawn strategy + trace spawn→register; if card flashes-then-vanishes, suspect the bridge isn't reaching the server.
- [ ] Bundle `packages/extension/` + auto-register in `~/.pi/agent/settings.json`; test the missing/malformed-settings path.
- [ ] Vite main+preload: externalize all `node:*` builtins.
- [ ] Spawn `node.exe <entry cli.js>` directly on Windows; `detached:false` + `unref()`; `windowsHide:true`; quote every path.
- [ ] Branch npm layout: `node_modules/npm/` (Win) vs `lib/node_modules/npm/` (Unix).
- [ ] Docker cross-build: platform-aware native modules (keep `win32-x64` `node-pty` prebuilds); replace workspace symlinks with copies; produce ZIP + portable (`executableName: pi-dashboard`); leave NSIS to CI.
- [ ] Make extension stale-path cleanup regex match `C:\…` and `/usr/lib/…`.
- [ ] Add early disk-startup log when the window never appears.
- [ ] Update `docs/electron-session.md` (new phase + lesson), `architecture.md`, `AGENTS.md`; commit in themed chunks; add a splash screen for the slow cold boot.
