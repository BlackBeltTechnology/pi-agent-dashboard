# How we did it: rich Agent tool cards in the dashboard — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **OpenSpec explore mode** — *"Enter explore mode. Think deeply.
Visualize freely… you must NEVER write code or implement features."* The real objective
that crystallized through steering: **the dashboard renders `Agent`, `get_subagent_result`,
and `steer_subagent` tool calls with the `GenericToolRenderer`** — raw JSON args and plain
text — which is unreadable. Build **rich, live, per-tool cards** (status, tokens, duration,
markdown result) for subagent tool calls, driven end-to-end through an OpenSpec change:
explore → proposal → design → specs → tasks → apply → verify → archive.

## 2. TL;DR playbook

1. `/opsx:explore` the problem first — let the AI trace the **data flow** (event pipeline)
   before proposing anything. It found the fix lived in one place: `partialResult` was cast
   to `string` but is actually `{ content, details: AgentDetails }`.
2. `create proposal`, then `/opsx:ff` to fast-forward design + specs + tasks in one pass.
3. `/opsx:apply agent-tool-card` — implement the 19 tasks TDD-first (event-reducer fix +
   tests, then shared `AgentCardShell`, then 3 renderers registered in the registry).
4. **Extract shared code**: pull `formatTokens`/`formatDuration`/status-icon + a card shell
   out of `FlowAgentCard` into `agent-card-utils.ts` + `AgentCardShell.tsx`; refactor
   `FlowAgentCard` to compose it. DRY from the start.
5. `build and deploy` (`npm run build` → `curl -X POST .../api/restart`).
6. **Verify from a *different* session** — launch an `Agent` subagent from another pi
   session so the card appears here *without* the recursive browser-in-browser scroll trap.
7. Fix the **replay path** too: thread `details` through `state-replay.ts` so cards render
   on reconnect, not just live.
8. `/opsx:verify` → fix the 2 warnings (spec still said "collapsible" after the user
   switched to always-expanded markdown) → `/opsx:archive`.

## 3. How the collaboration unfolded

**Phase 1 — Discovery (explore mode).** The AI grepped `ChatView`, `ToolCallStep`, the
tool-renderer registry, and `event-reducer.ts`, then chased the event pipeline *up into the
installed pi packages* (`@tintinweb/pi-subagents`, `@mariozechner/pi-coding-agent`) to see
what `subagent_*` events and `AgentDetails` actually carry. Payoff: it discovered all the
data already flows over the WebSocket — the reducer just **mangles `partialResult` by casting
an object to `string`** (`[object Object]`). The fix was small and surgical, not a new event
channel.

**Phase 2 — Proposal + fast-forward.** `create proposal` → `/opsx:ff` generated design (6
decisions), specs (6 requirements / 12 scenarios), and 15→19 tasks. Decision point: the user
added *"Extract shared code from FlowSessionCard as AgentSessionCard"* — turning a one-off
renderer into a reusable `AgentCardShell` shared with flows.

**Phase 3 — Apply (TDD).** 19 tasks, checkpoint-announced one by one. Reducer fix landed
first *with tests* (structured vs string `partialResult`), then the shell extraction, then
the three renderers. Type errors (`args?.prompt` is `unknown`) were fixed inline; the build
distinguished new vs pre-existing TS errors.

**Phase 4 — Deploy + visual verify.** `build and deploy`, then the tricky part: verifying a
card *for this very session* meant driving the browser inside the session it was rendering —
auto-scroll kept jumping to the live browser calls. The unlock (user's idea): **launch the
Agent from a separate session** so the card renders here statically.

**Phase 5 — Second-order fixes + verify/archive.** Found the **replay gap** (`details` not
threaded through `state-replay.ts`), the user asked for **always-expanded markdown** result,
and folded in changes made in a *sibling session* (`7e9dabea`) via *"Update proposal with
that"*. `/opsx:verify` caught spec drift (spec still said "collapsible"), fixed it, archived.

## 4. Prompts that worked

- **Goal prompt (`/opsx:explore` + "think deeply / trace the data flow").** Forcing
  investigation *before* code is why the fix was one-line-surgical instead of a new pipeline.
  A stronger kickoff states the artifact up front: *"Explore how Agent/get_subagent_result/
  steer_subagent tool calls render today, trace the event pipeline end-to-end, and draft an
  OpenSpec proposal for rich cards — don't implement yet."*
- **`Update spec. Extract shared code from FlowSessionCard as AgentSessionCard`** — one
  sentence that made the whole thing DRY and consistent across flows + subagents.
- **`build and deploy`** — short, unambiguous, maps to the repo's build→restart matrix.
- **`okay. In this session create an agent to be able to see the agent card here`** — the
  verification unlock: test the renderer by generating real data from a clean vantage point.
- **`Lot of changes was outside proposal and in session <id>. Update proposal with that`** —
  keeps the OpenSpec artifact honest when work spilled across sessions.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Build a one-off renderer | "Extract shared code from FlowSessionCard as AgentSessionCard" | State "share the card shell across flows + subagents" in the proposal scope |
| Verify the card by driving the browser *inside the session being rendered* (auto-scroll trap, recursive browser-in-browser) | "In this session create an agent to see the card here" / launch from a **separate** session | Default rule: verify live UI from a **different** session, never self-observe |
| Spam `npm run reload` (subagent read AGENTS.md and looped it) — floods the chat | "The repeated calls cause problem to check" | Constrain Explore subagents ("do NOT run reload"); improve consecutive-call grouping |
| Fix only the **live** path | (found later) thread `details` through replay | Remember: live = `tool_execution_update`, replay = `state-replay.ts` + `tool_execution_end.details` |
| Claim parallel agents work, but calls ran **sequentially** | "But it was not called parallel" — issue multiple Agent calls in ONE block | To truly parallelize, emit all `Agent` calls in a single tool block |
| Leave spec saying "collapsible" after switch to always-expanded | `/opsx:verify` flagged it → fix spec + `GetSubagentResultRenderer` | Update the spec scenario in the same turn you change the behavior |

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was saved this session. The workflow is highly repeatable, so the
reusable asset is **this playbook** plus two patterns worth a skill:

- **"Verify live dashboard UI from a second session"** — solves the recursive
  browser-in-browser scroll trap. Invoke whenever validating a renderer that reacts to the
  session you're driving. (Candidate skill; overlaps the existing
  `isolated-ui-verification` project skill — prefer that.)
- **Shared `AgentCardShell` extraction** — `agent-card-utils.ts` (`formatTokens`,
  `formatDuration`, `getStatusIcon`) + `AgentCardShell.tsx` now back both `FlowAgentCard`
  and the new subagent renderers. Reuse it for any future agent-status card.

## 7. Pitfalls & dead ends

- **`partialResult` is an object, not a string.** The reducer's `string` cast turned
  `{ content, details }` into `[object Object]`. If a running tool shows garbled text, check
  the reducer cast before touching the bridge.
- **Live works, replay doesn't.** Cards were blank on reconnect because `state-replay.ts`
  didn't forward `details` on `tool_execution_end`. Fix both paths.
- **Don't verify a card from the session rendering it** — auto-scroll + live browser tool
  calls make it impossible; launch the Agent from another session.
- **`run_in_background: true` alone isn't parallel** — pi still serializes tool calls issued
  one-per-block; emit all Agent calls in a single block for true concurrency.
- **`openspec change new` failed** — the CLI subcommand differs; check `openspec --help`.
- **Explore subagents can loop AGENTS.md commands** (ran `npm run reload` ~100×), swamping
  the chat; scope their prompts tightly.
