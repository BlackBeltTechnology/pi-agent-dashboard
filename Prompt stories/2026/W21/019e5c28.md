# How we did it: Fixing a broken Vite dev page (and two bugs behind it) — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened cold — the literal first prompt was just `?`. The real goal
surfaced with the first steering turn: a Vite dev server was throwing
`[plugin:vite:import-analysis] Failed to resolve import ".../packages/flows-plugin/src/client/index"`
because `packages/client/src/generated/plugin-registry.tsx` had been **committed to
git with another developer's absolute paths** (`/home/skrot1/...`). The dashboard
served a blank page as a result.

The real objective, once steering clarified it: **get the dev page rendering again,
then fix the two root causes it exposed** — (1) a machine-specific generated artifact
being tracked in git, and (2) a CLI/TUI session being rendered with the wrong
("dashboard robot") icon because its `.meta.json` was mis-stamped `source: "dashboard"`.

## 2. TL;DR playbook

1. **Recognize the class of bug.** A committed *generated* file with absolute paths
   from another machine → delete it and let the generator re-emit. Never hand-edit.
2. **Restart the process that owns the generator.** Here `plugin-registry.tsx` is
   regenerated by the Vite plugin's `buildStart`, which only runs at Vite startup —
   kill the stale long-running Vite PID and `npm run dev` again.
3. **Fix the root cause, not the symptom.** Change the generator to emit
   **package-name imports** (`@blackbelt-technology/pi-dashboard-flows-plugin`)
   instead of absolute filesystem paths — npm-workspace symlinks resolve them to
   local source in dev and to installed packages in prod.
4. **Make every entry point self-heal.** Add pre-hooks / `buildStart` so `lint`,
   `build`, `test`, and direct-workspace builds all regenerate the file (fresh
   clones and CI don't break on a missing artifact).
5. **Untrack the artifact** (`git rm --cached` + `.gitignore`) so cross-machine path
   drift can never recur — but only *after* imports are portable.
6. **For the wrong-icon bug, read the data before the renderer.** The icon was
   correct for the data; the `.meta.json` was wrong. Fix in `source-detector.ts`:
   `hasUI === true` (a TUI is attached) short-circuits and overrides any stale
   `source: "dashboard"` tag.
7. **Add a regression test** for the new short-circuit, run it in an isolated
   `HOME=$(mktemp -d)` to avoid real sidecar interference.
8. **Capture the deeper fix as an OpenSpec change** (`openspec-ff-change`) rather
   than shipping a hidden hack — proposal → design → specs → tasks.
9. **Land the three concerns on the right branches** with jj (colocated git+jj repo):
   split proposal → `develop`, icon fix → `develop`, plugin-registry portability →
   `feat/enable-standalone-npm-install`; keep the unrelated QA tweak in the working copy.

## 3. How the collaboration unfolded

**Phase 1 — Triage the blank page (Discovery).** The AI immediately identified the
committed `plugin-registry.tsx` with `/home/skrot1/...` paths as a stale generated
artifact and advised delete + restart. The key insight (worth repeating): *a
generated file that regenerates on startup should never be edited or trusted when
committed.* The human pushed back twice ("still empty page") — which forced the AI
to discover the actual blocker: **the Vite process had been running since the
previous day and was never restarted**, so `buildStart` never re-ran. Killing the
stale PID and restarting was the unlock.

**Phase 2 — Decide the durable fix (Design).** The human asked the sharp architecture
question: *"How can I switch between source dirs in dev and versioned deps in prod —
or is a switch even necessary? Think hard."* The AI resisted speculating, read
`loader.ts` and the workspace layout, and answered **"No switch necessary"** —
npm-workspace symlinks already give source-in-dev / package-in-prod for free. That
reframed the fix from "add a toggle" to "emit package-name imports." The human chose
**Option B** (fix the generator) over Option A (gitignore + pre-hooks scaffolding),
and the AI reverted the throwaway scaffolding once B landed.

**Phase 3 — The wrong-icon bug (Diagnose → Fix → Test).** The human posted a CLI
session URL showing a dashboard-robot icon. The AI traced it precisely: PID on
`/dev/ttys001` = real terminal, but `.meta.json` stamped `source: "dashboard"`;
root cause was the **cwd-only matcher in `event-wiring.ts`**. Fix went into
`source-detector.ts` (`hasUI` short-circuit) plus two regression tests, run under
`HOME=$(mktemp -d)`.

**Phase 4 — Formalize the deeper fix (Generate).** Rather than shipping only the
bridge-side patch, the AI ran `openspec-ff-change` to produce a full 4-artifact
change (`fix-dashboard-spawn-correlation-by-token`): proposal, design (typed
token-keyed `PendingDashboardSpawns` registry behind a `STRICT_SPAWN_CORRELATION`
flag, plus a one-shot `repair-meta-source.mjs` cleanup), specs, and tasks.

**Phase 5 — Land it correctly (Verify + Commit).** The repo is colocated jj+git, so
the AI used **jj, not git**. It discovered mid-flight that `feat/enable-standalone-npm-install`
*already* solved the portability problem via relative-path imports — so it **merged
the two approaches** (package-name preferred, relative-path fallback) instead of
clobbering. Three focused commits landed on the right bookmarks; the QA tweak stayed
in the working copy; nothing was lost or accidentally pushed.

## 4. Prompts that worked

- **The (missing) goal prompt.** `?` cost nothing but a round-trip. Stronger
  kickoff: paste the Vite error *and* the symptom in one message — which the human
  did on the next turn, and that's what actually started the work.
- **"still empty page" (steering #3).** A blunt two-word correction that stopped the
  AI from declaring victory and forced it to find the *real* blocker (stale Vite PID).
  High-leverage: refuses a premature "should work now."
- **"How can I switch… or is it necessary… Think hard." (steering #7).** The best
  prompt of the session — it invited the AI to *challenge the premise* rather than
  build the toggle. Result: a simpler, correct architecture. Reuse this shape:
  *"or is X even necessary?"* before accepting added complexity.
- **"Option B" (steering #8).** One-word decisive pick after the AI laid out A/B.
  Cheap and unblocking — the pattern of *AI enumerates options, human picks by letter*.
- **"create a proposal for that" → "draft" → `openspec-ff-change`.** Escalated a
  one-off patch into a tracked change without ceremony.

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was created in-session, but the workflow used two existing
ones well and revealed one worth saving:

- **`openspec-ff-change`** — turned an ad-hoc bug into a fully-specified, reviewable
  change in one shot. Invoke it whenever a "quick fix" exposes a systemic root cause
  worth tracking (here: the cwd-only spawn matcher).
- **jj commit-splitting discipline** — `jj split` by path to separate mixed working-copy
  concerns onto distinct bookmarks. Effective because it kept unrelated changes
  (proposal / icon fix / portability / QA) from cross-contaminating branches.
- **Recommended new memory:** *"Generated artifacts (e.g. `plugin-registry.tsx`) must
  emit portable imports (package-name or workspace-relative), never absolute paths,
  and should be gitignored + regenerated at every entry point."* This encodes the
  session's core lesson so it never recurs.

## 7. Pitfalls & dead ends

- **Stale long-running Vite process.** Deleting the generated file does nothing if
  Vite isn't restarted — `buildStart` only runs at startup. If the page stays blank
  after a "regenerate" fix, `ps aux | grep vite` and kill the old PID first.
- **Committing generated files.** The whole incident traces to a generated artifact
  being tracked in git. If you see machine-specific paths in a committed file, that
  file should be gitignored and regenerated, not edited.
- **Fresh-clone / CI breakage.** Gitignoring the artifact breaks `tsc`/`lint` on a
  clean clone *unless* every entry point regenerates it. Wire pre-hooks (or emit
  portable imports so the committed copy is harmless) before untracking.
- **Trusting `.meta.json` over live process state.** The wrong icon was *correct for
  the data* — the sidecar was stale. When a UI element looks wrong, check whether the
  data source is authoritative (`hasUI` from a live TUI beats a cached meta tag).
- **`git` in a jj repo.** Reaching for git here would fight the working copy. Use jj;
  reattach HEAD with the project's helper when done.
- **Parallel fixes on another branch.** `feat/enable-standalone-npm-install` already
  had a relative-path solution — a blind rebase would have clobbered it. Always diff
  the target branch first.
