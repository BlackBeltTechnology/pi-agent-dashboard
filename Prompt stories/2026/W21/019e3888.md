# How we did it: Untangling the PI Dashboard force-reinstall / bootstrap mess — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened on a hard failure:

> "Pi exited immediately. See log below. RPC keeper exited within crash window (code 1)."

The literal ask was "why won't a session spawn?" — but the steering turns revealed the
**real** objective: fully repair the Electron PI Dashboard's install/recovery pipeline so
that Force Reinstall leaves a *consistent* `~/.pi-dashboard/`, the dashboard server boots
clean, and the Settings page loads. What looked like one crash was actually a **chain of
four distinct bugs** (broken symlinks → a missing import → npm pruning bundle deps → a
Doctor self-deadlock) plus a **client-side red herring** (localStorage pointing at the wrong
server). The finish line was: DMG rebuilt with real code fixes, install verified healthy,
and the session's fixes committed to a branch while `develop` was reset clean.

## 2. TL;DR playbook

1. **Read the actual keeper log first** — `cat ~/.pi/dashboard/sessions/keeper-*.log`. The
   spawn `ENOENT` was a broken `.bin/pi` symlink pointing at a missing `.bundle-node-modules/`.
2. **When the renderer shows an error but curl returns 200, suspect the client, not the server.**
   Check `localStorage["pi-dashboard-last-server"]` — it can point `getApiBase()` at a *different
   machine*. Clear it: `localStorage.removeItem("pi-dashboard-last-server"); location.reload();`
3. **Grep the failing IPC handler for undefined symbols** — `writeAuditEntry` was called in
   `recovery-ipc.ts` but never imported. Add `import { writeAuditEntry } from "./audit-log.js"`.
4. **Fix the pruning root cause, not the symptom.** `forceReinstall` ran `npm install` which
   prunes materialized `@blackbelt-technology/*` workspace packages and their 89 transitive
   bundle deps. Two fixes: (a) call `materializeWorkspaceSymlinks(managedDir, { force: true })`
   after install; (b) add `--no-save --no-package-lock --no-prune` to `buildOfflineInstallArgs`.
5. **Kill the Doctor self-deadlock.** `probeServer` in `doctor-routes.ts` `execSync`'d
   `curl localhost:8000/api/health` *against its own blocked event loop*. Read health from the
   running process (env vars) instead; in Electron's `doctor.ts` use `fetch` + `AbortController`.
6. **Build the DMG with the bundled Node**, not your shell's: `source ~/.nvm/nvm.sh && nvm use
   24.15.0 && bash packages/electron/scripts/build-installer.sh`. Run `npm rebuild macos-alias` once.
7. **If the same version ships new code, force a fresh extract.** `needsExtraction()` short-circuits
   on an unchanged `.version` — wipe `~/.pi-dashboard/{packages,node_modules,.version}` (keep the
   bundled `node`) so the new bundle actually lands.
8. **Land fixes without polluting `develop`:** commit to a feature branch, then `git reset --hard
   origin/develop`.

## 3. How the collaboration unfolded

**Phase 1 — Diagnose the spawn crash (log-first).** The AI read the keeper log and immediately
found the true cause: every `.bin/` symlink targeted `.bundle-node-modules/` (missing), while the
real binaries had moved to `node_modules/`. It offered a quick relink patch *and* the "proper"
Force Reinstall path — good instinct to separate the band-aid from the fix.

**Phase 2 — The missing import.** Force Reinstall then threw `writeAuditEntry is not defined`. A
one-line grep confirmed three call sites, zero imports. Fixed. This is where the AI first noted the
coverage gap (no `recovery-ipc.test.ts`) — worth a follow-up test.

**Phase 3 — DMG build friction.** Building the DMG failed on `macos-alias` (ABI mismatch: built for
Node 22, shell on Node 25). The decision point: **the root build requires the project's bundled Node
(24.15.0)**, reached via `nvm use`, plus a one-time `npm rebuild macos-alias`.

**Phase 4 — The "Settings failed" swamp (the hard part).** For ~40 minutes the AI repeatedly told the
user "the server is healthy, it's a stale renderer, press Cmd+R." Curl returned 200; the user's UI did
not. The user pushed back hard ("It doesn't help", "Same shit", "FAILED"). This deflection loop was the
session's biggest waste. It broke only when the AI **stopped instructing button-presses and diagnosed
directly**, finding *two* real causes: (a) `localStorage["pi-dashboard-last-server"]` pointed the client
at `192.168.16.242:8000` (another machine) so every fetch missed localhost; (b) `npm install` had pruned
89 bundle deps (fastify, readable-stream, …) off disk, so fresh lazy `require()`s crashed even though the
already-running server survived on in-memory modules.

**Phase 5 — Fix the pruning at the source.** Two code fixes landed: re-materialize after force-reinstall,
and pass `--no-save --no-package-lock --no-prune` to the offline installer. Tests green.

**Phase 6 — The Doctor self-deadlock.** The user's screenshot ("It is on settings page", "cosmetic
function which WARN because the dashboard-server output parsed too strict") pointed at the Doctor WARN.
Root cause: `probeServer` `execSync`'d curl against its own blocked event loop → 3s timeout → false
"Not running". Fixed both server- and Electron-side.

**Phase 7 — The stale-extract trap.** New DMG, same `0.5.3` version → `needsExtraction()` skipped the
extract, so the managed install kept the *old* pre-fix code. The AB had to wipe the managed copies to
force re-extraction.

**Phase 8 — Wizard jiti workaround + clean commit.** A `jiti/static` ESM-exports resolution failure in
the bundled-extensions wizard got a symlink workaround + a try/catch so it degrades to "skip" instead of
crashing the wizard. Finally, the session's fixes were committed to `new_bootstap_mess` and `develop`
was reset to `origin/develop`.

## 7. Pitfalls & dead ends

- **"It's just stale renderer state, reload" is a trap** when curl returns 200 — the real cause here was a
  client `localStorage` server override AND pruned on-disk deps. Don't repeat the reload advice more than once.
- **Building the DMG on the wrong Node** fails on `macos-alias` (ABI mismatch). Always `nvm use 24.15.0`
  first and `npm rebuild macos-alias` once.
- **`npm install` inside force-reinstall prunes** materialized `@blackbelt-technology/*` and their ~89
  transitive bundle deps. A still-running server survives on in-memory modules and masks the breakage until
  the next lazy `require()`. Use `--no-save --no-package-lock --no-prune` and re-materialize after install.
- **Same-version DMG won't re-extract** — `needsExtraction()` sees an unchanged `.version` and skips, so the
  managed install keeps old code. Force-wipe the managed copies.
- **`probeServer` shelling out to curl against its own server self-deadlocks** — never `execSync` a request
  to the process you're running in. Read state from env / use async `fetch` + `AbortController`.
- **Old `.bin/` symlinks pointing into the app bundle** clash with a fresh extract — clean them before re-extracting.
- **`jiti/static` fails to resolve from Electron's main process** — symlink `node_modules/jiti/static` →
  `lib/jiti-static.mjs` as a workaround, and wrap `loadPiPackageManager()` in try/catch so the wizard degrades
  to "skip bundled extensions" instead of crashing.
