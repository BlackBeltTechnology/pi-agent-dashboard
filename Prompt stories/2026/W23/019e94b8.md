# How we did it: Elevate the folder "+Session" button out of the cramped action bar — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) — a thinking stance, not an
implementation run. The real objective, which crystallized over the four prompts, was a
**UI/UX redesign captured as an OpenSpec change, not code**: the `+Session` button — the
primary way a user starts work in a folder — was a cramped `text-[10px]` pill jammed among
`Worktree`, `Terminals(N)`, `Editor`, and the Pi Resources icon inside `FolderActionBar`.
The user wanted it **promoted** to a prominent, always-reachable control. The output was a
validated proposal + tasks + delta spec under `openspec/changes/elevate-folder-spawn-buttons/`,
committed surgically to `develop`. No feature code was written — that was the point of the stance.

## 2. TL;DR playbook

1. Enter explore mode (`openspec-explore`) — declare up front that the goal is to **capture
   thinking as an OpenSpec change, not to implement**.
2. Ground the discussion: locate `FolderActionBar.tsx` via `docs/file-index*.md`, then read
   the real component under `packages/client/src/components/`.
3. Watch for **decoy prior work** — a same-named worktree (`os-session-card-plus-session-button`)
   turned out to be a *different* feature (per-session-card sibling buttons). Inspect its
   commit, confirm it's unrelated, move on.
4. Draw the current folder-group layout as ASCII (header → action bar → session cards) so the
   human can point at exactly where the button should move.
5. Offer **lettered placement options** (Option A/B…) and let the human pick + amend in one
   short reply.
6. Resolve every loose end explicitly (e.g. "if Worktree leaves the pill bar, where does it go?")
   before scaffolding — don't scaffold on an ambiguous decision.
7. Scaffold with the CLI: check `openspec/specs/` capability names, write `proposal.md` +
   `tasks.md` + `specs/<capability>/spec.md`, then `openspec validate <change> --strict`.
8. Commit **only the change files** to `develop`, leaving unrelated staged work untouched.

## 3. How the collaboration unfolded

**Discovery (ground the layout).** The AI tried to spawn an `Explore` subagent, found the role
unavailable, and fell back to the doc index (`docs/file-index*.md`) + direct `grep`/`read`. It
corrected an early path assumption (`src/` → real path `packages/client/`) and read the actual
`FolderActionBar.tsx` and the folder-group render block. *Why it worked:* it refused to design
against a guessed structure — every layout claim was grounded in a file it had opened.

**Decoy investigation.** A worktree named `os-session-card-plus-session-button` looked like prior
work on the same request. The AI inspected its commit (`feat(session-card): add +Session and
+Worktree spawn buttons`) and concluded it was a *different* feature (per-card sibling buttons,
not the directory card's button). *Decision point:* the human's request was re-scoped to the
**Directory card**, avoiding a wasted merge.

**Design (visualize + choose).** The AI rendered the current group as ASCII and offered placement
options. The human picked **Option B** (stack in the always-visible header) and added the key
behavior: **auto-expand on spawn when collapsed**. The AI flagged a leftover ambiguity — if the
Worktree pill also leaves the action bar, where does it land? — and got an explicit answer before
proceeding. Final shape: a new full-width `FolderSpawnButtons` stack (`+ New Session` green,
`+ New Worktree` orange & git-gated) in the header; both removed from the trimmed `FolderActionBar`.

**Generate (scaffold the change).** With the design locked, the AI checked `folder-action-bar` as
the target capability, wrote `proposal.md`, `tasks.md` (5 groups: component → trim bar → wire →
tests → verify), and the delta spec (3 MODIFIED + 2 ADDED requirements), then ran
`openspec validate --strict` — clean.

**Land (surgical commit).** The working tree had **unrelated staged changes** (jj-skill renames,
`add-end-user-docs`). The AI added *only* the `elevate-folder-spawn-buttons/` files and committed
`77802b4d` to `develop`, leaving the rest staged and untouched.

## 4. Prompts that worked

- **Goal prompt (explore-mode preamble).** Effective because it set the *stance*: think & capture,
  never implement. This kept the whole session focused on producing a proposal rather than editing
  React. A future operator should open with the same framing: *"Explore this UI change and capture
  it as an OpenSpec change — don't write feature code."*
- **`Option B, but when the button pushed and cards collapsed, on that case expand`** — a high-leverage
  one-liner. It picked from the lettered menu *and* injected the one behavior (auto-expand) that
  resolved the "spawn blind while collapsed" problem. Lettered options make this kind of terse,
  decisive reply possible.
- **`yes`** — unlocked the scaffold step once the design was fully settled. Cheap because the AI had
  already laid out exactly what "yes" would do.
- **`commit canges to develop`** — worked only because the AI proactively scoped the commit to the
  change files. Stronger version: *"commit ONLY the elevate-folder-spawn-buttons files to develop;
  leave other staged changes untouched."*

No new skills or memories were created this session. It was a clean application of an existing

## 7. Pitfalls & dead ends

- **`Explore` subagent role unavailable** → the AI fell back to `docs/file-index*.md` + direct
  `grep`/`read`. If the role isn't wired, don't stall — go straight to the doc index.
- **Path assumption `src/` was wrong** (real path `packages/client/`). If a `find`/`read` fails,
  reconcile against `docs/file-index*.md` before continuing — one `find` here failed and was
  recovered this way.
- **Same-named worktree ≠ same feature.** `os-session-card-plus-session-button` was per-card
  buttons, not the folder card. Always `git show <commit> --stat` before assuming a worktree is
  your prior work.
- **Unrelated staged changes in the tree.** Never `git add -A` here — scope the commit to the
  change directory only.
