# How we did it: Persist the process-drawer collapse state per session — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The user opened in **explore mode** (`openspec-explore` skill) pointing at a UI annoyance: the
background-processes drawer in the PROCESS subcard kept auto-expanding on its own. The literal
first prompt was the explore-mode stance ("Enter explore mode. Think deeply… you must NEVER write
code"). The *real* objective, once the steering clarified it: **stop the drawer from auto-expanding,
default it to collapsed, and make the user's collapse/expand choice stick — per session, across
reloads and devices.** By session end that had shipped through the full OpenSpec lifecycle:
explore → proposal → apply (14 tasks) → PR → archive → merged to `develop`.

## 2. TL;DR playbook

1. **Explore first, don't code.** Launch `openspec-explore`. Ask the AI to *map* the current
   behavior — where the expand default lives and why. (Answer: `useDrawerExpansion()` in
   `SessionCard.tsx`, rule `contextualDefault = activityEmpty && drawerNonEmpty`.)
2. **Make it find the existing pattern, not invent one.** Prompt: "map out what persistence
   machinery already exists so we fit existing patterns." It surfaced the per-session
   `displayPrefsOverride` → `.meta.json` transport (auto-prunes on session delete — solves stale keys for free).
3. **Pick the scope explicitly.** The one real decision: per-session + server-synced. Say so; the
   AI then designs **Path 3** — a parallel per-session lane mirroring `displayPrefsOverride`.
4. `create proposal` — scaffolds proposal.md / design.md / tasks.md / delta spec; `openspec validate --strict` clean.
5. Run `openspec-apply-change`. TDD-ordered: shared types → server persistence → client hook → tests. 14 tasks.
6. **Verify at runtime, not just unit tests.** Restart prod server (`POST /api/restart`), drive a
   real WS `set_session_process_drawer` toggle, confirm `.meta.json` write + broadcast + REST read-back.
7. `commit and push` — **scope the commit to only your files** (jj scoped fileset); leave concurrent unrelated work in `@`.
8. Update the PR body to structured sections. Then `openspec-archive-change` → sync spec → commit archive to `develop`.

## 3. How the collaboration unfolded

**Phase 1 — Discovery (explore mode).** The AI (a subagent role was unavailable, so it worked
directly off the file index) located the drawer's controlling hook and drew the truth table of when
it expands. Effective because it *diagnosed the rule* (`contextualDefault = activityEmpty && drawerNonEmpty`)
before proposing anything.

**Phase 2 — Ground the design in existing machinery.** The decisive move: the user told it to
inventory existing persistence rather than invent a new one. The AI found two flavors
(`useSidebarState` localStorage; per-session `displayPrefsOverride` in `.meta.json`) and
corrected its own diagram twice as it read the actual route code — landing on the fact that the
per-session lane travels via WS `set_session_display_prefs` → `session-meta-handler` →
`.meta.json` (which auto-prunes). **Decision point:** user chose per-session + server-synced, so
resolution collapses to `session.processDrawerCollapsed ?? true`.

**Phase 3 — Scaffold (`create proposal`).** Four artifacts, Path 3, validates strict-clean. The AI
flagged a real dependency: its delta MODIFIES a requirement ("Drawer default state is contextual")
that only existed in the *unarchived* `redesign-process-list-activity-bar` change.

**Phase 4 — Apply (14 tasks, TDD).** Shared (`types.ts`, `session-meta.ts`, `browser-protocol.ts`)
→ server (`meta-persistence.ts` setter, `session-scanner` load, `session-meta-handler` handler,
`browser-gateway` dispatch, `server.ts` onChange) → client (`useDrawerExpansion` now defaults
collapsed, reconciles authoritative value via `useEffect`, threads `onSetProcessDrawer` through
App → SessionList → SessionCard). Updated the two stale drawer tests that asserted the old default.
7099 unit tests green, `tsc -b` clean, prod build clean.

**Phase 5 — Runtime verification.** Restarted the prod server and drove a real WS toggle end-to-end,
confirming sync broadcast + `.meta.json` persistence + REST read-back, then cleaned the test residue
off the real session's meta file.

**Phase 6 — Ship & archive (the messy part).** Committed a **scoped** jj fileset (15 files only),
pushed a branch, updated PR #70. Then a **concurrent session** fast-forwarded `develop` straight
through the implementation commit — GitHub auto-marked PR #70 **merged**, the archive commit got
stranded on the branch, and the OpenSpec change flip-flopped active↔archived as the shared jj working
copy was reorganized by other sessions. The AI re-checked state each time and finally landed a clean
archive dir-move commit (`0c82563d`) directly on `develop`.

## 4. Prompts that worked

- **Goal / explore kickoff** — entering `openspec-explore` kept the AI in diagnose-not-implement
  mode, which produced the truth table and the "reuse existing machinery" insight before any code.
  *Stronger version:* "Explore why the process drawer auto-expands, and inventory existing
  persistence patterns before proposing a fix."
- **"map out what persistence machinery already exists"** — the highest-leverage prompt. It stopped
  the AI from inventing a localStorage hook and steered it onto the proven `.meta.json` transport
  that already auto-prunes.
- **"create proposal"**, **"yes"**, **"commit and push"**, **"1"**, **"close"**,
  **"commit to git develop"** — terse follow-ups that each advanced one lifecycle stage. They worked
  because the AI had already loaded enough context to act unambiguously on one-word confirmations.
- **"update description of PR"** — turned a raw-commit-message PR body into structured
  Summary / What changed / How it works / Testing sections.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |

| Reach for a new localStorage hook | "map out what machinery already exists" | Always inventory existing persistence before designing a new store |

Key quality bar the user imposed implicitly: **do not pollute the PR / develop with other sessions'
in-flight work.** The AI honored it by using jj scoped filesets throughout.

No new skill or memory was created this session. The workflow leaned on existing project skills:

## 7. Pitfalls & dead ends

- **Subagent role unavailable.** The `Explore` subagent failed to spawn; the AI fell back to direct
  file-index investigation. *If a subagent role is down, don't block — grep the file index directly.*
- **Diagram-from-memory was wrong twice.** The per-session override does NOT ride the
  `/api/preferences/display` envelope. *Read the route before trusting a transport diagram.*
- **Concurrent sessions share ONE jj working copy.** `develop` fast-forwarded through the
  implementation commit, auto-merging PR #70 and stranding the archive commit on the branch. The
  OpenSpec change bounced active↔archived. *In this repo, always `jj status` + compare local vs
  origin/develop before every commit; expect churn between steps.*
- **Modifying a requirement that doesn't exist yet.** The delta targeted a requirement living only
  in an unarchived change. It resolved itself when a concurrent session archived that change — but
  *design-time dependencies can shift under you; re-verify at sync time.*
- **A few grep-shape command failures** (4 of 75) from over-complex one-liners — harmless, retried.
