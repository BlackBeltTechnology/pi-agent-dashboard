# How we did it: Directory Settings tree + resize — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) with the standing "think, don't
implement" stance — no concrete task in the first prompt, just permission to investigate.
The *real* objective crystallized within a couple of turns: the Directory Settings →
Instructions file picker renders every writable `.md` candidate as a **flat list of full
`relPath` strings**. With dozens of `.pi/skills/**`, `.pi/agents/**`, `.pi/prompts/**` rows
sharing the same prefix, the meaningful leaf gets truncated and there's no way to collapse
noise. The operator wanted to (a) **fold the flat list into a collapsible folder tree** and
(b) **make the list ↔ editor split resizable** — then capture it all as a validated,
doubt-hardened OpenSpec change ready for `/opsx-apply`. Nothing was implemented; the
deliverable is a **change proposal + design + spec + tasks + mockups**, committed.

## 2. TL;DR playbook

1. **Enter `openspec-explore`** and let the AI *ground in the real code first* — it grepped
   for `DirectorySettings`, read `FilePicker.tsx` / `InstructionsEditorPane.tsx`, and
   crucially **found existing idioms to reuse** (`resource-tree.tsx` chevron/indent,
   `ResizableSidebar.tsx` + `useSidebarState` drag/clamp/localStorage).
2. **Ask for a live mockup grounded in real theme tokens** — the AI built an HTML mockup,
   `serve_mockup`'d it, `score_mockup`'d it, and browser-verified the dark-theme toggle
   actually switched (it caught its own false "contrast held" claim and re-checked).
3. **Answer the open decisions tersely** — a 4-line reply (`1. persist / 2. expanded /
   3. mock mobile too / 4. a`) locked in persistence, default-expanded, a mobile design,
   and plain-tree (no single-child collapse).
4. **Say `stop`** to kill the mockup server once the visual direction was agreed.
5. **Run `openspec-ff-change`** to fast-forward all four artifacts (proposal → design +
   specs → tasks) in one go, validating after each. Move the mockups aside so `openspec new`
   can scaffax the empty dir, then restore them.
6. **Say `doubt review`** to trigger doubt-driven-review **before implementation stands** —
   spawn a fresh-context `Explore` reviewer with ARTIFACT + CONTRACT only (no CLAIM), then a
   **cross-architecture** second pass (DeepSeek via `@fast`) to catch shared blind spots.
7. **Reconcile every finding** into a class (contract-misread / actionable / trade-off /
   noise), fold the actionable fixes back, and **STOP** — don't re-spawn on an unchanged
   artifact.
8. **Say `commit`** — stage ONLY the change dir, leave unrelated working-tree noise untouched.

## 3. How the collaboration unfolded

**Phase 1 — Discovery (ground before sketching).** The AI refused to sketch until it had
read the actual component behind the screen. It grepped `Directory Settings`, opened
`FilePicker.tsx` and the editor pane, then went hunting for **existing** tree and resize
patterns. This is the load-bearing move: it found `resource-tree.tsx` (chevron + `depth*16px`
indent) and `ResizableSidebar.tsx` / `useSidebarState` (clamp + localStorage, already tested)
— so the eventual design *reuses idioms* instead of inventing them. It also pulled the real
`--bg-primary` / `--text-primary` theme tokens so the mockup would match the dashboard exactly.

**Phase 2 — Design via live mockup.** The AI built `instructions-tree-resize.html`, served it
(`serve_mockup`), screenshotted it, and **verified its own claims in a browser** — when the
dark-theme toggle "didn't visually switch," it re-checked rather than asserting success, and
confirmed contrast held. It surfaced one genuine design question (repeated `SKILL.md` leaves →
auto-collapse single-child dirs? Option A vs B) and let the human decide.

**Phase 3 — Decisions + mobile.** The human's 4-line reply resolved everything: persist,
default-expanded, design mobile too, plain tree. The AI reasoned that resize/split has no room
at 375px and designed a **master/detail** mobile pattern (tap file → editor, back → tree),
building a second mockup `instructions-mobile.html`.

**Phase 4 — Generate artifacts (`openspec-ff-change`).** Scaffolded the change (temporarily
moving the mockups out of the way so `openspec new` could create the empty dir, then restoring),
wrote proposal → design → specs (4 ADDED requirements, 11 WHEN/THEN scenarios) → tasks
(6 TDD-ordered groups), validating after each.

**Phase 5 — Doubt-driven review (the payoff).** On `doubt review`, the AI ran the full
discipline: named a CLAIM, extracted ARTIFACT + CONTRACT, spawned a fresh-context reviewer
**without** the CLAIM, then ran a **cross-model** pass on DeepSeek (a genuinely different
architecture reached via `@fast`), probing reachability first. Both models **independently
converged** on the load-bearing flaw: the mobile master/detail requirement collides with
shipped behavior — the URL-resolution effect auto-selects a default file when `?file=` is
absent (so `selected` is never null → the tree can never show), and the depth-aware back
action treats settings as depth-1 → ejects to the card list, not the tree. The design had
asserted "the existing back-walk already returns to the tree" as *fact*; it was false. The AI
reconciled every finding, converted the mobile requirement to a MODIFIED delta, and STOPPED.

**Phase 6 — Surgical commit.** Staged ONLY `directory-settings-tree-and-resize/`, explicitly
left unrelated working-tree changes (`.pi/skills/manage-flows/`, `groups.json`, scratch files)
untouched. Result: commit `6ae11737a`, 7 files, +937.

## 4. Prompts that worked

- **Goal prompt (`openspec-explore`)** — effective because the "think, don't implement" stance
  forced grounding-before-sketching. The AI's discipline of *reading the real component and
  reusing existing idioms* flowed directly from being told not to build yet.
- **`1. persist / 2. expanded / 3. Think about and make mocup for that too / 4. a`** — the
  highest-leverage prompt in the session. Four terse lines resolved four open design questions
  and unlocked the entire artifact-generation phase. Terse *numbered* answers to the AI's
  numbered options are a very efficient decision channel.
- **`doubt review`** — a two-word prompt that invoked a whole discipline (CLAIM → EXTRACT →
  DOUBT → cross-model → RECONCILE → STOP) and caught a load-bearing spec/behavior collision
  before any code was written.
- **`stop`** — cleanly ended the mockup-serving phase.
- **`commit`** — trusted the AI to scope the stage surgically.

A **weak** spot to rewrite: the goal prompt carried no concrete task (pure explore stance). If
you already know the ask, front-load it: *"Explore mode. The Directory Settings Instructions
picker is a flat relPath list — I want it folded into a collapsible tree and the list↔editor
split made resizable. Ground in the real components, reuse existing idioms, mock it up."*

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was created — the session *consumed* existing project skills. The
reusable lesson is the **chain** itself:

- **`openspec-explore` → `openspec-ff-change` → doubt-driven-review → commit** is the
  proven pipeline for turning a vague UI itch into a validated, implementation-ready change.
- **doubt-driven-review with a cross-model second reviewer** is the highest-value link. Running
  a fresh-context reviewer **plus** a different architecture (DeepSeek via `@fast`) produced
  *independent convergence* on a real flaw — exactly the signal cross-model exists to generate.
  Invoke it on any change whose correctness rests on assumptions about *shipped* behavior
  (URL models, back semantics, existing hooks) before a single line is implemented.
- **`serve_mockup` + `score_mockup` + browser verification** against **real theme tokens** is
  the way to make a mockup that survives contact with the actual dashboard chrome.

## 7. Pitfalls & dead ends

- **`openspec new` won't scaffold a non-empty dir.** The change dir already held the mockups.
  Fix: `mv` the mockups to `/tmp`, run `openspec new change`, then restore them alongside.
- **A theme toggle can *look* like it works and not.** The AI's first "contrast held" claim was
  premature; only a re-screenshot confirmed the dark pass. Verify visual claims with a fresh
  screenshot, don't assert.
- **`ctx_batch_execute` erred twice** and `edit` erred twice (stray `oldText2/3/4` keys). If a
  multi-target edit fails, redo it as clean single-target edits rather than patching the payload.
- **Cross-model reviewer runs from the repo root, not your cwd.** DeepSeek's "referenced mockups
  do not exist" was a false flag — it ran `find mockups/` from root; the mockups live under
  `openspec/changes/<name>/mockups/`. Classify wrong-cwd findings as noise, not action.
- **Spec/behavior collisions hide in "the existing X already does Y" prose.** The design asserted
  the back-walk returns to the tree; it actually ejects to the card list. Doubt review caught it.
