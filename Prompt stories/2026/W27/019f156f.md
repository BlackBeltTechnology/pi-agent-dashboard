# How we did it: Reduce session replay traffic — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was

## 1. Goal (the ask)

The user entered **explore mode** ("Enter explore mode. Think deeply… you must NEVER
write code") to think through a performance idea: *opening a session the client has
already seen re-ships the entire chat history — can we avoid that?* The stated hunch
was "cache messages by ID." The **real objective**, once the AI grounded it in the
code, turned out narrower and sharper: the transport is an **event-sourced stream**
(`message_start → message_update* → message_end`), an incremental `lastSeq` replay
protocol **already exists**, and the *only* real gap is **page reload throwing away
in-memory `maxSeqMap`/`sessionStates`**. The session ended with a validated OpenSpec
proposal (`reduce-session-replay-traffic`) capturing two strategies plus one
explicitly-rejected option — no code written, by design.

## 2. TL;DR playbook

1. **Enter explore mode** (`/skill:openspec-explore`) — a thinking stance, no implementation.
2. **Ground before reasoning.** Have the AI read the transport end-to-end first:
   `docs/architecture.md`, the server event buffer/store, the client event-reducer,
   the subscription-handler (`minSeq`/`lastSeq`), and the REST events route.
3. **Let the code correct the framing.** The "cache by ID" idea collides with the
   event-sourced reality — accept the reframe to "persist the existing replay cursor."
4. **Pin down the one true gap** with a scenario table (switch / reconnect / refresh /
   reload / restart). Only **page reload** loses delta state → that's Strategy A.
5. **Probe the second axis** ("lazy load on expand?") and force the goal split:
   bandwidth vs. fidelity. Conclude bandwidth-play = bad trade, fidelity-feature = worth it.
6. **Draft the OpenSpec change** — match an existing change's exact format
   (`proposal.md`, `design.md`, TDD-ordered `tasks.md`, `.openspec.yaml`, spec deltas).
7. **`openspec validate <change>`** until green; fix SHALL-wording parse quirks.
8. **Test each later idea against the draft** ("prioritize active first?") — most
   converge into Strategy A; record the *rejected* option with re-entry conditions.
9. **Commit only your artifacts** — `git add openspec/changes/<change>/`, leave
   unrelated tree noise (`groups.json`) untouched unless asked.

## 4. Prompts that worked

- **Goal prompt (explore mode):** strong because it set a *stance* — think, don't
  implement, artifacts allowed. This is what let the AI reframe freely without
  jumping to code. A future user should keep the "NEVER implement, but MAY create
  OpenSpec artifacts" boundary explicit.
- **"But in expand way is worth the limitation?"** — high-leverage: it demanded a
  verdict, forcing the bandwidth-vs-fidelity split instead of a vague "it depends."
- **"draft proposal with both optimalization"** — converted exploration into a
  durable artifact at exactly the right moment.
- **"1" / "add" / "commit"** — terse confirmations that kept momentum; effective only
  *because* the AI had laid out numbered options and a clear next action first.
- **Rewrite of a weak prompt:** instead of "Is it possible to prioritize active
  sessions first?", ask "Does the current load path already prioritize the active
  session, or do we need prefetch?" — it points straight at the grounding step.

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was created — appropriate for a single explore-mode planning
session. The reusable asset produced is the **OpenSpec change itself**
(`reduce-session-replay-traffic`): a TDD-ordered `tasks.md` that turns the exploration
into an executable plan, plus a `design.md` that preserves *why* prefetch was rejected.

If this pattern recurs, the skill worth creating is **"ground-then-reframe a perf
idea"**: (1) read the transport/data path end-to-end, (2) build a scenario table to
isolate the true gap, (3) split fuzzy goals into named axes with a trade table, (4)
capture as an OpenSpec change. That removes the biggest manual cost here — repeatedly
re-deriving the event-sourced model before every optimization discussion.

## 7. Pitfalls & dead ends

- **"Cache messages by ID" is a trap** — messages aren't single wire objects; a
  server-side projection would be needed and doesn't exist. Don't design around it.
- **Collapse ≠ bandwidth saving** — the collapsed body is *already on the client*;
  lazy-on-expand only saves bytes if the *server* ships a stub during replay.
- **First scenario table was wrong** — the `lastSeq: 0` sites were the Refresh
  button, not reconnect. Verify which code path a symptom actually lives on.
- **OpenSpec validate SHALL quirk** — a requirement failed validation despite having
  SHALL; simplify the description wording to match the validator's expected pattern.
- **Truncated edit clobbered a heading** — a long edit ended mid-sentence and deleted
  the Strategy B heading. Re-read after big edits; don't trust the write blindly.
- **`git add -A` would have swept `groups.json`** — scope the add to your change dir.
