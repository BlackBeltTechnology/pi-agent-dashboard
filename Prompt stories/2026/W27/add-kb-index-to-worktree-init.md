# How we did it: Add the kb index to worktree init — an AI collaboration guideline

## 1. Goal (the ask)

The user opened with a single deceptively small prompt: **"Is there anything to clarify?"** — asked against an existing OpenSpec change (`add-kb-index-to-worktree-init`) whose proposal/design/tasks were already drafted. The *real* objective, once the steering turns landed, was: **validate the change's assumptions against actual repo state, fix the one that was wrong, implement the `worktreeInit` gate + `run.command` edit, verify every task end-to-end, then ship it through the full PR pipeline.** The change makes a freshly `git worktree add`-ed checkout self-heal: rebuild the generated `openspec-*` skills **and** the gitignored `kb` markdown index (`.pi/dashboard/kb/index.db`) so a new worktree isn't silently missing dev assets.

## 2. TL;DR playbook

1. **Don't trust the spec — verify it.** Before implementing, read `proposal.md` + `design.md` + `tasks.md`, then run cheap shell probes against the real repo to confirm every concrete assumption (bin paths, gitignore status, sentinel files).
2. **Find the load-bearing wrong assumption.** Here: task 1.3 assumed the kb build was *conditional*. Prove it's **mandatory** — `packages/kb/dist/` is gitignored with no `prepare` script, so `npx kb index` fails on every fresh `npm ci`.
3. **Fix the gate + run.command in `.pi/settings.json#worktreeInit`.** Broaden the skip-gate to fire when *any* restored asset is absent; add an explicit kb build step before `kb index`.
4. **Prove it end-to-end, once.** Run the full `run.command` on a truly un-inited worktree (no `node_modules`) — 762 files → 13477 chunks → 21 MB `index.db`. This both verifies tasks 1.2/1.3 and empirically confirms the blocker.
5. **Delegate every `docs/` write to a subagent** (AGENTS.md rule) with the caveman-style instruction verbatim; then re-index kb with `--force` and prove the new content is searchable.
6. **Simulate the exact bug + TOFU cycle** for the manual tasks: delete the index with `node_modules` present → gate re-fires; edit `worktreeInit` → `hookDefHash` changes → trust re-prompt.
7. **Keep the diff surgical.** `openspec init --force` regenerated an unrelated skill — revert it (`git checkout --`) so the diff is exactly the change.
8. **Ship via the `ship-change` skill:** gate → archive+sync → commit → PR → watch CI → fix → merge → clean up worktree/branches.

## 3. How the collaboration unfolded

**Phase A — Skeptical discovery (the highest-value phase).** The AI read the change artifacts, then immediately cross-checked them against reality with a burst of shell probes (`grep` for the kb bin, `cat` package.json, check `.gitignore`, look for `dist/cli.js`). Two problems surfaced fast; the AI stopped and reported **"the one thing that will actually break"** rather than plowing ahead. *Why it worked:* treating a drafted spec as a hypothesis, not gospel — the whole change hinged on this correction.

**Phase B — Implement + prove (steer: `run.command`).** With the build step confirmed necessary, the AI edited the gate and `run.command`, validated the JSON, then ran the full command on a genuinely fresh worktree. The empirical run *was* the verification — `dist/cli.js` really was absent after `npm ci`, closing the argument. It then updated design D2 / task 1.3 to say "mandatory, not conditional."

**Phase C — Tasks 2–4 (steer: `yes`).** Spec delta already validated; docs were delegated to a `general-purpose` subagent (caveman style, per AGENTS.md). The AI re-indexed kb (needed `--force` — kb keys on mtime, which `git worktree` preserves) and simulated the gate re-fire + `hookDefHash` TOFU re-prompt to cover the manual tasks honestly. It then caught an out-of-scope file (`manage-flows/SKILL.md`, regenerated by `openspec init --force`) and reverted it.

**Phase D — Ship (steer: `use ship-change skill`).** Ran tests: 3 failures, all triaged as **non-regressions** (2 timing flakes that pass in isolation, 1 environment leak from a real `~/.pi-dashboard/node` on this machine). Archived + synced specs, opened **PR #217**, watched CI. CI failed on **Biome Tier A** — `--muted:#59617`, an invalid 5-digit hex — but in an *unrelated* change's mockup that was already red on `develop`. Fixed the one char (`#596172`), CI + CodeRabbit went green, squash-merged, cleaned up. *Decision point:* the AI paused before pushing a red gate (guardrail) and again before merging (0 actionable review threads).

## 4. Prompts that worked

- **The goal prompt — "Is there anything to clarify?"** Effective *because* it invited scrutiny before code. It turned the AI into a spec-auditor and surfaced the mandatory-build blocker before a single edit. A stronger explicit version: *"Before implementing, verify every concrete assumption in this change against the repo and tell me what will break."*
- **"run.command"** (steering #1) — a two-word unblock that said "yes, put the build step in `run.command`, proceed." High leverage: it confirmed the fix direction without re-litigating.
- **"yes"** (steering #2) — approved proceeding through tasks 2–4 in one go; let the AI batch the remaining work instead of pausing per task.
- **"use ship-change skill"** (steering #3) — named the exact workflow, so the AI ran the full, disciplined pipeline (gate → PR → CI → merge → cleanup) instead of improvising a merge.

## 7. Pitfalls & dead ends

- **`kb index` fails on a fresh worktree** — `packages/kb/dist/` is gitignored, no `prepare` script. → Always `npm run build --workspace=@blackbelt-technology/pi-dashboard-kb` before `npx kb index`.
- **Incremental `kb index` reports "0 changed" after doc edits** — kb keys on **mtime**, which `git worktree` preserves. → Use `kb index --force` to pick up restored/edited docs.
- **Local test failures that aren't yours** — under a loaded machine (right after `npm ci` + full index), timing tests flake (`4817 < 3000`, 5s timeouts). → Re-run the specific files in isolation with a sandboxed `HOME=$(mktemp -d)`; they pass.
- **Electron `resolves to bundled node` test fails locally** — an *environment leak*: resolution finds the real `/Users/robson/.pi-dashboard/node` installed on this box (absent on CI). → Not a regression; CI (clean env) is authoritative.
- **`openspec init --force` regenerates unrelated skills** (`manage-flows/SKILL.md`). → `git checkout --` it to keep the diff surgical.
- **Post-merge Bash tool pinned to a deleted worktree cwd** — `--delete-branch` couldn't drop the remote branch. → Run cleanup from the parent repo path (or the sandbox), then `git push origin --delete <branch>` explicitly.
- **CI red from someone else's typo** — `--muted:#59617` (5-digit hex) in `add-kb-folder-slot`'s mockup was breaking `develop` itself. → Biome `lint .` scans the whole repo; a one-char fix (`#596172`) unblocked both PR and base branch.
