# How we did it: Migrate the flat file-index into a recursive AGENTS.md tree — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** — a thinking-partner stance, no implementation:
*"Enter explore mode. Think deeply… you must NEVER write code."* There was no concrete
feature request at the start; the operator was probing how this repo's documentation
system actually works. Over eight steering turns the *real* objective crystallized:
**understand why docs churn so much, discover that the repo adapted `agent0ai/dox` but
dropped its recursive-`AGENTS.md`-tree data structure, and then capture — as an OpenSpec
change proposal, not code — a migration from the flat `docs/file-index-*.md` splits to a
per-directory `AGENTS.md` tree that preserves `kb_search` searchability and is populated
by parallel `@fast` subagents.** The deliverable was a validated OpenSpec change
committed to `develop`, with zero implementation.

## 2. TL;DR playbook

1. **Start in explore mode** (`openspec-explore` skill) so the AI investigates and
   visualizes but is forbidden from writing code — the right stance for "is this even
   possible / where does X live" questions.
2. **Ask a measurable question first:** "does this repo update docs often?" The AI
   quantified it with `git log` churn analysis (26% of commits touch `docs/`) instead of
   guessing.
3. **Trace the injection channel** — "is the DOX rule part of AGENTS.md or another prompt
   injection?" forces the AI to map exactly one authoritative source instead of hand-waving.
4. **Compare against the upstream** — fetch `github.com/agent0ai/dox`, then ask "was it
   adapted? is it missing?" The AI produced a KEPT-vs-REPLACED table (philosophy kept,
   tree structure replaced by `packages/kb/src/dox.ts` tooling).
5. **Pose the migration feasibility question** — "can we move to a recursive AGENTS.md
   and keep searchability?" The AI grounded the answer in how `kb_search` indexes
   (FTS5+BM25 over markdown chunks, `doc_type: agents`), proving location-agnosticism.
6. **Force a reality check with a dry run** — `kb dox init --dry-run` exposed that a naive
   run plans 188 files, ~166 noise, and maps `.md` not source. This is the finding no
   prior artifact recorded.
7. **Say "capture it" + specify the mechanism** — "make it use parallel @fast subagents…
   because descriptions must be migrated from the file-index." This unlocked artifact
   creation while pinning the design.
8. **Iterate the proposal** — "update proposal" drove the tiered refinement (Tier-0
   deterministic copy for file-index hits; Tier-1 `@fast` subagents only for gaps).
9. **Commit surgically** — "commit" → the AI staged ONLY the new change dir, leaving
   unrelated pre-existing edits untouched.

## 3. How the collaboration unfolded

**Phase 1 — Discovery / quantify the problem.** The AI ran `git log` churn analysis over
90 days: 310/1208 commits touch `docs/`, concentrated in `file-index-*.md` +
`architecture.md`. *Why it worked:* it answered "do docs churn?" with a number and named
the driver (the Documentation Update Protocol forces a file-index row per file change),
not an opinion.

**Phase 2 — Map the injection channel.** Prompted by "is DOX part of AGENTS.md?", the AI
grep'd every candidate and concluded the docs rule lives in **exactly one** place —
`AGENTS.md` lines 100–135 — injected verbatim into the system prompt; every other match
merely *references* it. *Decision point:* the human confirmed the single-source model
before moving on.

**Phase 3 — Compare to upstream `agent0ai/dox`.** After a `fetch_content` of the repo, the
AI built a KEPT-vs-REPLACED table: the *concept* (traverse-before-edit, update-after) was
kept, but the *signature mechanism* (a hand-authored tree of per-directory `AGENTS.md`)
was replaced by the `packages/kb` `dox.ts` tooling with a "detect-don't-write" rule (CLI
fills path columns, LLM authors purpose text).

**Phase 4 — Feasibility of the migration.** "Can we keep searchability?" The AI showed
`kb_search` is FTS5+BM25 over markdown *chunks* tagged by `doc_type`, so a row produces
the same BM25 tokens regardless of which file holds it — set `indexAgentsFiles: true`,
point the glob at `AGENTS.md`, filter with `--doc-type agents`. Verdict: searchability
survives and likely improves.

**Phase 5 — Reality check via dry run.** `kb dox init --dry-run` was the highest-value
move: it revealed the tool maps `.md`/`.mdx` (docs), not `.ts`/`.tsx` (source), plans 188
files dominated by `.worktrees`/`openspec` noise, and invents `part-N` pseudo-dirs. Three
dealbreakers for a naive run — each became a proposal finding.

**Phase 6 — Capture + design.** On "capture it… use parallel @fast subagents", the AI
first ran a coherence check (archive + active sweep, no duplicate), then hand-created the
change dir (no `change new` scaffolder) with four artifacts, validated `--strict`, and
fixed a spec bug where a backtick `<area>` was parsed as an HTML tag eating the `SHALL`.

**Phase 7 — Refine + commit.** "update proposal" drove the tiered-routing insight (copying
a file-index purpose is deterministic string work → Tier-0 orchestrator, zero tokens;
`@fast` subagents fire only on gaps). "commit" landed 4 files / 351 insertions as
`11b0b4487`, leaving unrelated working-tree edits unstaged.

## 4. Prompts that worked

- **Goal prompt (`openspec-explore`).** Effective because the *stance* (think, don't
  implement) matched an open-ended investigation — it kept the AI from prematurely writing
  code and let the question evolve across turns.
- **"The DOX is part of agents.md? Or there is other prompt injection?"** — a precise,
  falsifiable question that forced a single-source map instead of a vague overview.
- **"the …/dox was adapted. Is it missing?"** — anchoring the AI to a concrete upstream
  produced a crisp KEPT-vs-REPLACED comparison.
- **"Is it possible to move to recursive AGENTS.md… keep the searchability?"** — a
  feasibility question with an explicit constraint (searchability) made the AI prove it
  against the actual index implementation.
- **High-leverage: "capture it, but make that use parallel @fast subagents… because
  descriptions have to be migrated from file index".** One sentence both *unlocked*
  artifact creation and *pinned* the core design mechanism.
- **"update proposal" / "commit"** — terse follow-ups that worked only because the prior
  turns had fully established context; each triggered a well-scoped action.

*Rewrite of the weak "a" / "A" turns:* those bare acknowledgements ("proceed") worked
here only because the AI had just presented a clear next step. A stronger version:
*"Yes — run the dry run and show me the real plan"* removes ambiguity about what
"proceed" means.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Treat the question abstractly (would docs churn matter?) | Asking a measurable question that demanded a `git log` count | Open with "quantify it first" so the AI reaches for data, not opinion |
| Assume DOX was simply "missing" | "the dox was adapted. Is it missing?" | State the upstream reference up front; ask KEPT-vs-REPLACED, not present/absent |
| Design the migration hand-wavily ("batches of N") | "update proposal" → forced concrete concurrency/contract | Demand a concrete table (pool size, work unit, failure mode) in the first design pass |
| Spawn a subagent per directory (blindly) | Refinement to tiered routing (Tier-0 deterministic, Tier-1 on gaps) | State "copying an existing row is deterministic — only author gaps" as a design rule |
| Potentially commit everything in the tree | "commit" answered with surgical staging | Say "commit ONLY the change dir; leave unrelated edits" explicitly |

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was persisted this session — but two reusable tools carried it:

- **`openspec-explore` (skill, invoked).** Enforces a think-don't-implement stance and
  permits capturing thinking as OpenSpec artifacts. *When to invoke:* any "is X possible /
  where does Y live / should we migrate" investigation that should end in a proposal, not
  code.
- **`kb dox init --dry-run` (CLI, the MVP move).** A zero-write plan preview that exposed
  the doc-vs-source mismatch and the 188-file noise problem. *When to invoke:* before
  trusting any tree-scaffolder, run its dry run and read the *actual* plan — it turns
  assumptions into findings.

*Skill worth creating:* a **"file-index → AGENTS.md tree migration"** procedure capturing
the tiered-routing pattern (deterministic copy for index hits, `@fast` subagents only for
gaps, bounded concurrency, atomic per-directory work unit) — this session designed it but
did not persist it.

## 7. Pitfalls & dead ends

- **`kb dox init` maps markdown, not source.** If you expect it to scaffold `src/**`
  AGENTS.md from the file-index, it won't — it walks `.md`/`.mdx`. Fix path: patch
  `walkMd` regex + `DEFAULT_EXCLUDE` + the `areaFiles` grouping (group by `dirname`, not
  top-level dir), and delete the `part-N` pseudo-dir chunking.
- **Naive `dox init` plans ~166 noise files** from `.worktrees` + archived `openspec`
  proposals. Always read the `--dry-run` plan before running for real.
- **A backtick path `` `<area>` `` in spec markdown is parsed as an HTML `<area>` tag** and
  silently eats the following `SHALL`. If `openspec validate --strict` complains about a
  missing requirement keyword, check for angle-bracket tokens in inline code and reword.
- **No `openspec change new` scaffolder** exists here — create the change directory
  manually; copy the format from a recent change (e.g. `add-kb-folder-slot`).
