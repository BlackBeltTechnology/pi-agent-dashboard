## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) — a thinking-partner stance,
not an implementation task. The first prompt was the skill's boilerplate: *"Enter explore
mode. Think deeply. Visualize freely. Follow the conversation wherever it goes… you must
NEVER write code or implement features… You MAY create OpenSpec artifacts."*

The **real objective** emerged over the first two steering turns: when a pi chat message
prints a **loopback dev-server URL** (e.g. `http://localhost:50452/…`), a plain click should
**open it inside the dashboard's split-pane live viewer** instead of spawning a new browser
tab — with a **modifier/middle-click escape hatch** to the system browser. The deliverable
was a **spec-only OpenSpec proposal** (`open-loopback-links-in-split-viewer`), never code.

## 2. TL;DR playbook

1. **Enter explore mode** with `openspec-explore` — stance is "capture thinking as OpenSpec
   artifacts," not implement.
2. **Ground before sketching.** `rg` the actual anchor renderers (`MarkdownContent.tsx`,
   `UrlLink.tsx`), the live-server plumbing (`live-server.ts`, `LiveServerViewer`), and the
   split-pane seam (`SplitWorkspaceContext.tsx`, `viewer-registry.tsx`) *before* proposing anything.
3. **Find the "already 90% built" insight.** State it plainly: the pieces exist; only the
   chat-link→viewer wire is missing. This collapses scope to ~3 real edits.
4. **Coherence-check against archive/active** (`openspec/changes/archive/…`) so you extend
   `unify-file-link-openability` rather than duplicate it.
5. **Scaffold with the CLI:** `openspec new change <name>` (not `openspec change new`).
6. **Write proposal → design → specs → tasks** matching the house format; `openspec validate`.
7. **Fold in the second surface on steering** ("serve mockup") — the `serve_mockup` card is
   `GenericToolRenderer → LinkifiedText → UrlLink`, a *different* renderer. Apply DRY: one
   shared hook, not duplicated logic.
8. **Run a real doubt review** against the code, not memory. Verify the routing API, the
   hook-throws-outside-provider claim, and tab de-dup with `rg`/`sed`.
9. **Bake corrections in**, re-validate, then **commit only this change's artifacts.**

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was created — this session *consumed* existing skills well:

- **`openspec-explore`** — kept the AI in a capture-thinking stance; prevented premature code.
- **`doubt-driven-review`** (invoked as *"doubt review"*) — the star of the session. It caught
  three defects (one critical wrong-API, one would-crash) that reading alone had missed.
  **Invoke it before any spec's core mechanism is committed.**
- **Recommended skill to create:** a small **"verify-the-routing-API"** checklist for
  UI-plumbing proposals — *before claiming `fn(x, y)` routes to Z, grep the signature and the
  reducer that actually produces Z.* This session shows that pattern paying off twice.

## 7. Pitfalls & dead ends

- **`openspec change new` fails** — the correct form is **`openspec new change <name>`**. The
  session burned one failed command discovering this (checked `openspec new --help`).
- **Wrong routing API in the first draft (critical).** The spec claimed
  `openInSplit("live:"+href, "live-server")`, but `openInSplit(relPath, line?)` has **no viewer
  arg** — it derives the viewer from `fileKind(absOf(cwd, relPath))`, which can *never* yield
  `live-server`. Fix: a new context method `openLiveTarget(url)` doing
  `dispatch({type:"openFile", path:"live:"+url, viewer:"live-server"}) + updateSplit({open:true})`.
- **Wrong hook for graceful degradation (would-crash).** `useSplitWorkspace()` **throws**
  outside its provider (line 170); use `useOptionalSplitWorkspace()` (returns `null`).
- **Repeated stray-field edits.** Two `edit` calls failed / had to be reissued because of a
  stray `oldText_note` / extra field — re-issue the edit cleanly rather than patching the patch.
- **Dirty tree at commit.** Unrelated files (`manage-flows/SKILL.md`, `groups.json`, scratch
  `b05_*.txt`) sat in the tree; stage the change dir explicitly (`git add openspec/changes/<name>/`),
  never `git add -A`.
