# How we did it: Fix the duplicated inlined screenshot in ChatView — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** (`openspec-explore`) — the first prompt was the
skill boilerplate, not a concrete task. The *real* goal surfaced one turn later, when the
user corrected the AI: a `browser` screenshot was rendering **twice, side-by-side ("on
parallel")** inside the dashboard's **ChatView**, on the **live** event path. The image
content was fine — the renderer was being handed the same screenshot twice. The objective:
find the layer that duplicates the image, fix it surgically, prove it on real data, and
land it as an OpenSpec change (proposal → fix → archive).

Restated: *"A live `browser` screenshot shows up as two identical thumbnails in ChatView.
Root-cause which component doubles it, fix only that, and verify against a real captured
result."*

## 2. TL;DR playbook

1. **Don't trust the first framing.** The AI first chased the *mockup* (`editor.html`);
   the user redirected to ChatView. State the layer up front: "this is the dashboard
   ChatView tool-result renderer, live event path."
2. **Trace the image from render back to source.** `ToolResultImages.tsx` maps an `images[]`
   array in a `flex-wrap` row → two entries = two thumbnails. Walk back through
   `extractToolResultImages` (event-reducer) to where the array is filled.
3. **Find the injector.** The bridge's `inlineToolResultImages` (`tool-result-image-inliner.ts`)
   reads a `Screenshot saved: /…png` path from the text block and **appends** the file as an
   image — but the MCP `browser` result **already** carries a native `type:"image"` block,
   so the append is a byte-identical duplicate.
4. **Fix at byte granularity (Option A).** Collect base64 of image blocks already present;
   if a path's bytes match an existing block, **strip the path from text but don't append**.
   Genuinely-different images still inline (preserves the existing mixed-image test).
5. **Propagate strip-only rewrites.** In `bridge.ts`, apply the rewrite on **result-identity
   change**, not just `inlinedCount > 0`.
6. **TDD it.** Add regression tests for the `[text, native image, path-to-same-file]` shape
   first; keep the existing "mixed different images" test green. `npx vitest run` the file,
   then the whole extension suite.
7. **Verify on REAL data.** Read this session's persisted JSONL, extract the actual `browser`
   result, confirm `[text, image]` shape and that native-image base64 === file-on-disk base64.
   Then run the *shipped* `inlineToolResultImages` against that real payload → 1 image.
8. **Land it as OpenSpec:** scaffold `fix-duplicate-inlined-screenshot` (proposal + tasks +
   spec delta), `openspec validate --strict`, commit, archive, sync the delta spec into the
   main spec, commit the move.

## 3. How the collaboration unfolded

**Phase 1 — Wrong layer (Discovery).** The AI opened the `editor.html` mockup and
screenshotted it, hypothesising the duplication was in the HTML or a gallery wrapper. It
proved the mockup renders *once* full-bleed — a correct finding about the *wrong subject*.
*Decision point:* the user cut in — **"Wrong mockup. It is on parallel. Tgis is in chat
view"** — reframing the whole investigation.

**Phase 2 — Right layer (Trace).** The AI reset cleanly ("I was debugging the wrong
layer"), then traced ChatView rendering: `ToolResultImages.tsx` maps `images[]` in a
`flex gap-2 flex-wrap` row → identical array entries = side-by-side duplicates. It followed
`extractToolResultImages` back to the **live** content path (`event-reducer.ts`), narrowing
to "the result carries the screenshot twice."

**Phase 3 — Root cause (Confirm).** Landed on the bridge inliner: `inlineToolResultImages`
was built for the **bash-run** `browser` skill (text-only result: `Screenshot saved: /…png`),
so it reads that path and appends the file as an image. But the **MCP** `browser` tool
already returns text **plus** a native `type:"image"` block → the append is a byte-identical
second copy. The AI drew an ASCII root-cause chain from MCP result → inliner → reducer →
`ToolResultImages.map`.

**Phase 4 — Fix (TDD).** *Decision point:* user chose **"A"** (Option A). The AI refined
"A" to the right granularity after spotting an existing test ("preserves pre-existing
non-text content blocks") that a blunt "skip if any image present" would break. It wrote
the byte-identity dedup guard + regression tests first, fixed `bridge.ts` to apply
strip-only rewrites, ran 12/12 targeted then 1122/1122 extension tests green.

**Phase 5 — Real-data verification.** Instead of trusting mocks, the AI read this session's
own persisted JSONL, confirmed the real `[text, image]` shape, proved native-image base64
=== file base64 (55844 chars), and ran the **shipped** function against the real payload →
`inlinedCount 0`, **1 image**, path stripped. It also correctly explained why the *live*
ChatView still showed two images that turn: **reloading a session mid-turn doesn't hot-swap
the running bridge for events emitted in the same turn** — a reload-timing artifact, not a
fix failure.

**Phase 6 — Land it (OpenSpec + commits).** *Decision points:* **"draw proposal"** → the AI
scaffolded `fix-duplicate-inlined-screenshot` (proposal + 8 tasks + spec delta), validated
strict. **"commit"** → committed only the fix files, deliberately leaving unrelated
pre-staged files (`.pi/settings.json`, `manage-flows`, `groups.json`, `.bak`) untouched.
`openspec-archive-change` → synced the delta into the main spec, moved to `archive/`, and a
follow-up **"commit"** finalized the deletions of the moved originals.

Key insight the AI surfaced (worth stating as a rule): **a mid-turn `npm run reload` does
not hot-swap the running bridge for events emitted in the same turn** — so live re-render
is not a valid verification of a bridge fix within the same turn; run the shipped function
against the real payload instead.

## 7. Pitfalls & dead ends

- **Wrong layer first.** ~10 minutes spent proving `editor.html` renders once. *If a
  screenshot looks duplicated, confirm whether it's a capture/framing artifact or a live
  renderer defect before touching source.*
- **Blunt Option A would break a real test.** "Skip inlining if any image present" breaks
  the legitimate mixed-images case (native image + text path to a *different* file). *Dedup
  at byte granularity, not block presence.*
- **`inlinedCount > 0` gate missed strip-only rewrites.** After dedup, a result can change
  (path stripped) with `inlinedCount 0`. *Apply the rewrite on result-identity change.*
- **Invalid `in_content` property** in a `ctx_execute_file` attempt (1 tool error); **sandbox
  blocked the session-JSONL path** — fell back to a plain node script via Bash. *For reading
  arbitrary repo/session files, a node one-liner via Bash is more reliable than the sandbox.*
- **Reload-timing trap.** Post-reload screenshots still showed two images *this turn*; that's
  not a broken fix — the running bridge wasn't hot-swapped for same-turn events.
- **A tsc project-reference config quirk** flagged unrelated errors; confirm the touched
  files type-clean directly rather than trusting the whole-project `tsc`.
