## 1. Goal (the ask)

The session opened with a raw CI failure dump — a wall of `tsc` errors:

```
error TS2554: Expected 1-4 arguments, but got 0.   (browser-gateway-handler-errors.test.ts)
error TS7006: Parameter 'args' implicitly has an 'any' type.
error TS2558: Expected 0-1 type arguments, but got 2.   (pi-core-routes.test.ts)
error TS2459: Module '.../rest-api.js' declares 'ApiResponse' locally, but it is not exported.
Process completed with exit code 2.
```

The real objective — clarified over the following steering turns — was **"make the
build and test suite green again and land it,"** which unfolded into three distinct
problems: (1) fix the TypeScript errors, (2) fix a batch of client test suites that
crashed with `window is not defined` (which turned out to be a Vitest 4 workspace
migration), and (3) days later, diagnose why **new dashboard sessions stopped
connecting** — a `pi` version/`typebox` crash unrelated to the tests.

## 2. TL;DR playbook

1. **Paste the raw CI error block as prompt 1.** The file:line:code triples are enough
   for the AI to jump straight to the offending lines — no need to describe them.
2. **Fix TS errors at the source, not the call site** where possible: re-export the
   missing `ApiResponse` type from `packages/shared/src/rest-api.ts`; add the required
   `isSessionPinned` callback and annotate `args: unknown[]`; modernise `vi.fn<...>`
   generics to the single function-type form.
3. **Verify with `npx tsc --noEmit`** (clean) then run just the two touched suites with
   `npx vitest run <file> <file>` before committing.
4. **When client suites crash with `ReferenceError: window is not defined`,** suspect the
   test environment wiring — here Vitest 4 had **dropped `vitest.workspace.ts`**. Delete
   it, add a root `vitest.config.ts` with `projects`, and drop `root: "."` from each
   per-package config.
5. **If `window.localStorage` is empty under jsdom, check the Node version.** CI pins
   Node 22 (`.github/workflows/ci.yml`); Node 25's jsdom misbehaves. Run client tests
   under `nvm exec 22`.
6. **Give the "how do I run one test" answer as reusable commands,** scoped per-package
   (`cd packages/client && npx vitest run <file>`) — the root project filter otherwise
   swallows single-file targets.
7. **Commit each logical fix separately** and push to `develop`.
8. **For "new sessions won't connect,"** enumerate pi processes vs. WebSocket owners on
   `:9999` (`lsof -nP -iTCP:9999`), find the crash in the extension load, and check the
   **global pi version against `piCompatibility.minimum`** — upgrade pi if the bridge's
   peer dep (`typebox`) is missing.

## 3. How the collaboration unfolded

**Phase A · TypeScript triage (prompt 1).** The AI read the named test files and the
shared `rest-api.ts`, grepped for `ApiResponse` and the gateway/store factory
signatures, then made three surgical edits: re-export the type, supply the now-required
`isSessionPinned` callback with `() => false`, annotate implicit-any `.find()` callbacks,
and update `vi.fn` generics from the old 2-arg `<[boolean?], Promise<...>>` to the
current `<(refresh?: boolean) => Promise<...>>`. Verified with `npx tsc --noEmit` +
targeted `vitest run`. *Why it worked:* the fix went to the root (a missing re-export)
rather than papering over each import site.

**Phase B · commit & push (prompts 2, 5).** Short "commit and push" / "commit staged
changes" turns. The AI wrote descriptive conventional-commit messages and pushed to
`develop` (commits `9af9dd8`, `a4cced2`).

**Phase C · the Vitest 4 workspace migration (prompt 3 + prompt 4).** A second CI dump
showed 9 client suites failing with `ReferenceError: window is not defined` /
`Element is not defined`. The AI dug through `node_modules/vitest` and `@vitest`
internals, wrote throwaway sanity tests, and discovered **Vitest 4 removed
`vitest.workspace.ts`**. It deleted the workspace file, created a root `vitest.config.ts`
using `projects`, and removed `root: "."` from the per-package configs. Along the way it
found the **Node-version gotcha**: on Node 25 jsdom leaves `window.localStorage` empty;
CI uses Node 22, so `nvm exec 22` reproduces the passing state.

**Phase D · knowledge transfer (prompt 4).** "How can I execute test from command line?"
→ the AI produced a scoped cheat-sheet: `npm test` (all), per-package `cd packages/<x> &&
npx vitest run`, single-file and `-t "name"` filters, `--project <name>` from root, and
the Node-22 caveat.

**Phase E · five days later, the connection outage (prompts 6, 7).** "Kill all pi
processes not connected to a dashboard server," then "new Session is not working now."
The AI cross-referenced `ps` output against `lsof -nP -iTCP:9999` to distinguish orphan
`pi --mode rpc` headless processes from connected TUI pairs, killed the 3 orphans, then
root-caused the new-session failure: the bridge extension imports `typebox` (a pi
`0.70+` dep), but the global pi was `0.67.68`, so every fresh spawn crashed with
`Cannot find module 'typebox'` before opening a WS. Fix: `npm install -g
@mariozechner/pi-coding-agent@latest` → `0.70.2`; verified a new session registered.

## 7. Pitfalls & dead ends

- **`window is not defined` in client tests is not a test bug** — it means the DOM
  environment isn't wired. Under Vitest 4 the cause was the removed
  `vitest.workspace.ts`. Don't edit the tests; fix the config.
- **jsdom + Node 25 = empty `window.localStorage`.** Many sanity tests and
  `node_modules` spelunking were spent before pinning it to the Node version. Run client
  tests on Node 22 (matching `.github/workflows/ci.yml`).
- **Single-file `vitest run` from the repo root gets swallowed by the project filter.**
  Run from inside the package (`cd packages/client && npx vitest run <file>`).
- **New sessions silently failing to connect** was NOT a dashboard bug — it was a global
  pi version below the bridge's peer-dep floor (`typebox`, pi `0.70+`). Check
  `pi --version` against `piCompatibility.minimum` before touching dashboard code.
- **Existing sessions don't pick up a pi upgrade** until reloaded (`npm run reload`).
