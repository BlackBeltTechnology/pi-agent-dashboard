# How we did it: Answer "how to build the Windows Electron zip?" — and turn a bad first answer into a durable docs rule

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The user opened with a plain how-to question: **"How to build windows electron zip?"** On the surface, a one-line answer. But the real objective — revealed through four steering turns — was **not** the command itself. The user already suspected the answer existed in the repo. What they actually wanted was: (a) the *correct* already-implemented command, and (b) a **systemic fix** so the AI (and every future agent) stops answering "how do I build X" from a narrow grep instead of the docs that already cover it. The session ended with a new FAQ doc and an `AGENTS.md` rule — the how-to answer was the trigger, the process guardrail was the deliverable.

## 2. TL;DR playbook

1. For any "how do I build/run/X" question, **grep `README.md` + `docs/` FIRST** — not source files. `grep -rn -i "windows.*zip\|electron-builder" docs/ README.md`.
2. Confirm the real build path: `packages/electron/scripts/build-installer.sh --windows [--arch arm64]` → emits `out/make/zip/<arch>/PI-Dashboard-<arch>.zip`.
3. When you got it wrong, **say so plainly** and name the root cause (grepped only 2 assumed-authoritative files, skipped `docker-make.sh` where the pipeline diverges to `electron-builder`).
4. When the user asks to "add a QA + make an instruction", **use `ask_user`** to pin down (a) FAQ location and (b) AGENTS.md rule scope before writing.
5. Create `docs/faq.md` (caveman style, cross-ref existing docs) via a subagent; register it in `docs/file-index.md`.
6. Add a short rule to `AGENTS.md` above the Investigation Protocol: *grep README.md + docs/ before answering how-to/build/setup questions.*
7. Stop. The artifact is the rule, not the command.

## 3. How the collaboration unfolded

**Phase 1 — Fast, wrong answer (Discovery).** The AI grepped only `forge.config.ts` and `build-installer.sh` for `zip|win|ZIP`, concluded "no Windows ZIP maker exists," and proposed adding `@electron-forge/maker-zip`. Both claims were false. *Lesson: a narrow grep over assumed-authoritative files produces confident wrong answers.*

**Phase 2 — First steer: "Why didn't [you] find that there is electron builder?"** The AI re-grepped the whole `packages/electron/` tree + `package.json`, found `docker-make.sh` hands off to `electron-builder --win portable` and **already produces the zip**. It corrected itself and gave the real command. *The effective move: grep the whole subtree + deps, not two files.*

**Phase 3 — Second steer: "Is it in docs presented?"** The AI grepped `docs/` + `README.md` and found the answer was documented in **six** places (README distribution table, `installation-windows.md`, `release-process.md`, `electron-session.md`, two file-index docs). This is the pivotal decision point: the user was demonstrating that docs-first would have answered the question instantly.

**Phase 4 — Third steer: "Add a QA in docs and make instruction in agents md."** The user converted the lesson into work. The AI paused with `ask_user` to choose FAQ location and rule scope (the user replied "1" → new `docs/faq.md`, short rule, no FAQ pointer). A `general-purpose` subagent wrote `docs/faq.md`; the AI edited `AGENTS.md` and `docs/file-index.md`.

## 4. Prompts that worked

- **The goal prompt** — "How to build windows electron zip?" was fine as a trigger but the AI should have treated it as a *docs lookup*, not a code investigation. A stronger self-instruction: *"Answer build/how-to questions from README + docs first."*
- **"Why didn't [you] find that there is electron builder?"** — high leverage: forced a wider search and exposed the shallow-grep failure.
- **"Is it in docs presented?"** — the killer follow-up. Six words that proved the answer was already written down and reframed the whole session from *answer the question* to *fix the process*.
- **"Add a QA in docs and make instruction in agents md"** — converted insight into a durable artifact. Rewrite for reuse: *"This keeps happening — add a FAQ entry and an AGENTS.md rule so agents grep docs before answering how-to questions."*
- **"1"** — minimal disambiguation reply to the `ask_user` menu; worked because the AI had framed clean numbered options.

## 6. Skills, tools & memory created — and why they're effective

- **`docs/faq.md` (new file)** — seeds a caveman-style FAQ with the Windows-electron-zip Q&A and cross-refs to the six existing docs. *Effective because:* it gives future agents a single grep target for recurring how-to questions instead of re-deriving from source.
- **`AGENTS.md` rule (edited)** — added above the Investigation Protocol: *grep `README.md` + `docs/` first for how-to/build/run/setup questions.* *Effective because:* it fires every turn and prevents the exact shallow-grep failure that opened this session.
- **`docs/file-index.md` (edited)** — new "Standalone topic docs" section registers `faq.md` so the file-index discipline stays intact.
- **Recommended skill (not created):** a `docs-first-howto` procedure could formalize the grep-order (docs → README → source) for any "how do I X" question. This session is exactly its motivating case.

## 7. Pitfalls & dead ends

- **Shallow grep → confident wrong answer.** The AI grepped `forge.config.ts` + `build-installer.sh` only and declared "no ZIP maker." *If you hit this, do:* grep the whole feature subtree + `package.json` before concluding a capability is missing.
- **`docker-make.sh` is where the pipeline diverges.** On Linux/Docker, the `@felixrieseberg/electron-forge-maker-nsis` entry in `forge.config.ts` is effectively dead — the build runs `electron-forge package` (no makers) then hands off to `electron-builder --win portable` + a manual `zip -r`. *Don't* reason about the Windows zip from `forge.config.ts` alone.
- **Proposing to add what already exists.** The first answer suggested `npm i -D @electron-forge/maker-zip`; the zip was already produced. *Verify before proposing additions.*
