# How we did it: Preserve the optimistic prompt across a session replay — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was

## 1. Goal (the ask)

The operator opened with the **explore-mode stance** prompt — "Enter explore mode. Think
deeply. Visualize freely… you must NEVER write code" — to investigate a real UX bug: when
you type a prompt into an *ended* session's chat input, the optimistic message bubble
disappears for 1–3 seconds before pi echoes it back. The real objective, once the steering
clarified it, was a full round-trip: **confirm the root cause, capture the fix as an OpenSpec
change, implement it surgically, test it, and land it on `develop`** — in a jj-colocated repo
where `git commit` is forbidden. The bug turned out to be entirely client-side:
`auto-resume-on-prompt` reuses the same session id, but the bridge re-register fires
`session_state_reset` / `event_replay`, and the client's reset handlers call
`createInitialState()`, which discards `pendingPrompt`.

## 2. TL;DR playbook

1. **Start in explore mode** to trace the flow read-only — do NOT let the AI implement yet.
2. Steer it to **verify the root cause in the actual dependency source** (`pi-coding-agent/dist/core/session-manager.js`) rather than trusting the first guess.
3. Once the cause is pinned to the client, say **`create proposal`** → then **`/opsx:ff`** to fast-forward all OpenSpec artifacts (proposal → design → specs → tasks).
4. Run **`/opsx:apply`** to implement — expect two surgical edits in `useMessageHandler.ts` plus unit tests.
5. Run the client vitest suite with `HOME=$(mktemp -d)` to dodge the home-dir config crash.
6. Say **`Tests ok` / `I've tested`** to unblock the manual-verification tasks and archive.
7. Say **`commit git`** — but in this jj-colocated repo the AI correctly refuses `git commit` and uses **`jj split`** to peel just this change's files off a mixed working copy.
8. Push via jj (translates to a git ref on `develop`); confirm with `git log origin/develop`.

## 3. How the collaboration unfolded

**Phase 1 — Discovery (explore mode).** The AI traced the client→server→bridge→client flow
and drew an ASCII sequence diagram of the ended-session resume path. Effective because the
explore-mode guardrail kept it *reading and diagramming*, not patching a symptom.

**Phase 2 — Root-cause verification.** The human steered: *"dig deeper into whether pi reuses
or rotates session ids on --mode continue."* The AI grepped the installed pi package under
`~/.nvm/.../pi-coding-agent/dist` and found `setSessionFile` **reuses** the header id — so the
first hypothesis (id rotation) was wrong. The bug was `canSkipWipe` being fragile plus the
client's `createInitialState()` dropping `pendingPrompt`. This is the decisive move: *confirm
against real source before writing the proposal.*

**Phase 3 — Capture as OpenSpec.** `create proposal` → `/opsx:ff` generated proposal, design
(D1 carry client-side vs server mirror, D2 only carry `pendingPrompt`, D3 patch both reset
sites), specs, and tasks. 4/4 artifacts validated.

**Phase 4 — Implement + test.** `/opsx:apply` made two surgical edits in `useMessageHandler.ts`
(`session_state_reset` and `event_replay` shouldReset branches both carry `pendingPrompt`
across the `createInitialState()` swap), added a 3-assertion unit test, and delegated the
docs-index row to a general-purpose subagent per the docs protocol.

**Phase 5 — Archive + land.** After the human confirmed manual tests, the AI archived the
change, synced the spec delta, then — on `commit git` — recognized the jj-colocated repo,
refused `git commit`, and used `jj split` to isolate 8 files from a working copy that mixed
five unrelated in-flight changes. Pushed to `develop`, verified on `origin`.

## 4. Prompts that worked

- **The goal prompt (explore-mode stance):** effective because it *forced investigation before
  implementation* — the AI produced a correct root-cause diagram instead of a premature patch.
- **`dig deeper into whether pi reuses or rotates session ids on --mode continue (to confirm
  root cause)`** — high-leverage: it redirected the AI to read the real dependency source and
  overturned a wrong first hypothesis. Reuse this shape: *"verify X against the actual source

- **`commit git`** — deliberately terse; the AI supplied the jj-safe path itself.

## 7. Pitfalls & dead ends

- **Wrong first hypothesis (session-id rotation).** If you assume the id rotates on
  `--mode continue`, you'll chase the server. It doesn't — pi's `setSessionFile` reuses the
  header id. Verify in `pi-coding-agent/dist/core/session-manager.js` first.
- **Client vitest crashes on a real `$HOME`.** Run with `HOME=$(mktemp -d) npx vitest run …`
  to avoid the home-dir config crash.
- **`curl … /api/restart` is blocked** by the context-mode hook inside the session — have the
  operator run the restart manually.
- **Mixed working copy.** `@` held five unrelated changes; committing everything would have
  bundled them. `jj split` the target files into a focused change first.
- **Pre-existing spec-header lint noise** (167 specs lack `## Purpose`/`## Requirements`) — not
  introduced by this change; don't fix it here.
