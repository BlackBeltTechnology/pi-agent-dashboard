# How we did it: Auto-scroll the selected session card on background re-sort — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened in **explore mode** — "Enter explore mode. Think deeply. Visualize
freely… you must NEVER write code." The real objective, once the thinking settled, was
a concrete UI fix: when the currently-selected session card **moves position in the
sidebar** for a background reason — its status flips (`active` → `ended`), it gets
hidden, the move-to-front policy fires on bridge reattach, or a drag-to-resume reorders
it — the card can slide off-screen and the user loses sight of the session they're
actually viewing. The fix: **auto-scroll the selected card back into view on background
re-sort — but NOT when the user simply clicks a card.** That "not on click" distinction
was the sharpest steering of the session (see §5).

## 2. TL;DR playbook

1. **Start in explore mode** to model the problem before touching code. Ask the AI to
   ASCII-diagram the sidebar/main-pane layout and enumerate every trigger that moves the
   selected card.
2. **Capture the thinking as an OpenSpec change** (`/opsx:ff auto-scroll-selected-session-card`)
   — proposal → design → specs → tasks — while still forbidding implementation.
3. **Design a pure fingerprint helper**: `selectedId|status|hidden|cwd|orderIdx`. When the
   string changes, the card moved; scroll it. This makes the trigger testable in isolation.
4. **Steer the behavior early**: "Do not scroll when I click a card. Only when it moved in
   the list." Bake the smooth-vs-instant + suppress-on-click rule into the spec, not just code.
5. **Apply the change TDD-first** (`/opsx:apply`): helper + unit tests → `data-session-id`
   on the card `<li>` roots → `listRef` + `useMemo(fingerprint)` + `useEffect` three-branch
   logic → behavioral render tests mocking `scrollIntoView`.
6. **Run the full suite** (`npm test`) to prove zero regressions, then `npm run build` +
   `pi-dashboard restart`.
7. **Archive** (`/opsx:archive`), fixing any pre-existing spec-header gaps that block it.
8. **Commit only the change's files** — explicitly leave unrelated WIP in the tree.

## 3. How the collaboration unfolded

**Phase A — Explore & model (prompts 1–3).** The AI read `SessionList.tsx`,
`SessionCard.tsx`, `SessionSidebar.tsx`, and `App.tsx`, then drew ASCII diagrams of the
sidebar-vs-chat layout and confirmed key facts: `SessionSidebar.tsx` is **dead** (only its
own test imports it), `SessionList.tsx` is the real sidebar, `MobileShell` hides the list
via CSS transform (DOM stays intact), and `sessionOrderMap` is the per-cwd order array.
The human just nudged — "yes", "keep poking" — letting the shape emerge. **Why it worked:**
the discovery ruled out dead code and settled the DOM-addressing question before any spec.

**Phase B — Capture as OpenSpec (prompt 4).** `/opsx:ff` generated proposal → design →
specs (3 requirements, 18 scenarios) → tasks (7 groups, TDD-ordered), all valid and
apply-ready. The design's centerpiece: a **fingerprint string** helper instead of watching
the whole `sessionOrderMap` — a third, cleaner option the AI proposed over the two obvious ones.

**Phase C — The lost-work scare (prompts 5–8).** The human asked "Where is the proposal?"
The files had **vanished** — `jj` had reset the working copy to a fresh empty commit at
21:35, abandoning the writes. The AI diagnosed it via `jj log` and **re-created all four
artifacts**, then confirmed nothing was implemented or archived yet.

**Phase D — Behavior correction (prompt 9).** "Do not scroll when I click on card. Only
when it's moved in the sessionList." The AI reworked the spec/design: user-click → **no
scroll**, programmatic select → no scroll, background re-sort → instant scroll, deep-link
first mount → one-shot instant scroll. The prev-ref is **always updated even when scroll is
suppressed**, so the *next* background re-sort of the new selection still scrolls correctly.

**Phase E — Apply, test, ship (prompts 11–14).** `/opsx:apply` ran TDD: 9/9 helper tests,
then `data-session-id` on both mobile+desktop `<li>` roots, wiring, 7 render tests, full
suite **4287 passed / 0 failed**. Build + `pi-dashboard restart` (new pid), archive (fixing
a missing `## Purpose`/`## Requirements` header that blocked it), and a scoped commit
`b66889a` — 13 files, +548/-55 — leaving unrelated WIP untouched.

## 4. Prompts that worked

- **Goal prompt (explore mode preamble).** Effective because it forced *modeling before
  coding* — the AI mapped every trigger and killed the dead-code path before a line was
  written. A future operator should keep this: "explore first, capture as OpenSpec, don't implement."
- **`/opsx:ff <name>`** — one command turned settled thinking into a full, valid, apply-ready
  change. High leverage: proposal+design+specs+tasks in one pass.
- **"Do not scroll when I click on card. Only just when its moved in sessionList."** — the
  single most valuable steering turn. Short, unambiguous, and it reshaped the whole behavior
  contract. **Rewrite for next time (state it up front):** *"Auto-scroll the selected card
  ONLY on background re-sort (status/hidden/cwd/order change). Never on user click or
  programmatic selection. One-shot instant scroll on deep-link first mount."*
- **`/opsx:apply`** then **"build and deploy"** then **"git commit changed"** — a clean
  three-beat close: implement → ship → commit-scoped.

## 5. Steering & corrections (what to watch for)

| The AI tended to… | The human had to steer by… | Bake this in next time by… |
|-------------------|----------------------------|----------------------------|
| Auto-scroll on *every* selection change, including user clicks | "Do not scroll when I click on card. Only when it moved in sessionList" | State the trigger contract up front: background re-sort only; suppress on click + programmatic select; one-shot on deep-link mount |
| Lose track that files were gone after a `jj` working-copy reset | "Where is the proposal?" / "Missing from openspec" | On "files vanished", check `jj log`/`jj op log` for a working-copy reset before re-doing work; re-create then re-`openspec validate` |
| Assume the change might already be implemented/archived | "is it implemented? archived?" / "What is missing?" | Diff spec-required items vs current code (grep `data-session-id`, count `tasks.md` `[x]`) before claiming status |
| Watch the whole `sessionOrderMap` object | (AI self-corrected) | Prefer a **fingerprint string** (`id\|status\|hidden\|cwd\|orderIdx`) — a pure, memoizable, testable trigger |
| Leave manual-QA/restart tasks ambiguously "done" | (AI flagged them explicitly) | Mark browser/mobile QA tasks not-done with a note; they need a human at a browser |
| Commit the whole dirty tree | "git commit changed" | Commit ONLY the change's files; list the untouched WIP back to the user |

## 7. Pitfalls & dead ends

- **`jj` ate the artifacts.** The working copy reset to a fresh empty commit at 21:35 and all
  uncommitted proposal/design/spec/task files went with it. *If your files vanish mid-session,
  check `jj log`/`jj op log` for a working-copy move before re-creating — then `openspec validate`.*
- **`curl … /api/restart` intercepted by the env.** The restart curl failed twice inside the
  sandbox. *Use `pi-dashboard restart` (which delegates to `/api/restart`) instead of raw curl,
  or defer the restart to the user.*
- **Render tests expected a scroll where the card left the DOM.** A `status` flip moves the
  card to a collapsed "Ended" bucket → no DOM node → correct noop, but the naive test asserted
  a scroll. *Write behavioral tests around position changes that KEEP the card in the DOM.*
- **Archive blocked by missing spec headers.** The main `session-card-selection/spec.md` lacked
  `## Purpose` / `## Requirements` (pre-existing gap). *Fix the header shape in-place before archiving.*
- **`find / -name … 2>/dev/null`** (whole-filesystem search) — slow and noisy; scope to
  `/Users/robson` or the repo.
