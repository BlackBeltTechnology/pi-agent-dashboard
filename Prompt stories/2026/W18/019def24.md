# How we did it: Fix stale sessions on WebSocket reconnect (and land it cleanly in a jj colocated repo) — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce

## 1. Goal (the ask)

The session opened with a five-word bug report: **"There is green (active) cards on ended"** — running/active session cards were showing up in (or with the styling of) the *ended* group in the dashboard. The real objective, once the AI traced the code, was bigger than a CSS fix: after a **dashboard server restart**, the browser's WebSocket reconnect left a **stale `sessions` Map** in client state. The reconnect handler cleared `sessionOrderMap` and `terminals` but never cleared `sessions`, so old entries lingered and mis-grouped until a manual page refresh. The fix became a full OpenSpec change: a new `sessions_snapshot` protocol message that the server sends once on connect and the client applies by **replacing** (not merging) its session Maps. The second half of the session was pure delivery discipline: archiving the change and pushing commits **without ever using a mutating `git` command** in a Jujutsu (jj) colocated repo.

## 2. TL;DR playbook

1. **Reproduce-by-reasoning first.** Ask the AI to trace the exact code path (`SessionCard.tsx` dot color → `SessionList.tsx` grouping → `App.tsx` reconnect handler) before touching anything. It found the data + dot logic were *correct in isolation* and the real bug was stale client state surviving reconnect.
2. **Name the root cause precisely:** `App.tsx` reconnect effect clears `sessionOrderMap` + `terminals` but leaves the `sessions` Map stale.
3. **Design the minimal protocol fix:** one new `SessionsSnapshotMessage` (`type: "sessions_snapshot"`, full session list + per-cwd orders), sent **once** on connect, replacing the per-session `session_added` + per-cwd `sessions_reordered` loops.
4. **Run the OpenSpec workflow:** `openspec new change fix-stale-sessions-on-reconnect` → proposal → design → specs (4 deltas) → tasks. Pause for user confirmation before implementing (per AGENTS.md).
5. **Implement REPLACE semantics on both ends:** server emits one snapshot; client `case "sessions_snapshot"` does `setSessions(new Map(...))` / `setSessionOrderMap(new Map(...))` — replace, never merge. Remove the now-redundant `setSessionOrderMap(new Map())` pre-reset in `App.tsx`.
6. **Pin behavior with tests** (server: single-snapshot + alive+ended both present; client: replace-not-merge), typecheck with root `npx tsc --noEmit`, add a **BREAKING** CHANGELOG entry, delegate doc-index updates to a subagent.
7. **Archive + sync specs** via the OpenSpec skills (delegate delta sync to a subagent).
8. **Land it the jj way** — `jj split` / `jj squash --from/--into` / `jj describe` to build clean commits, `jj git push --bookmark develop` to publish. **Never** `git commit/rebase/stash/reset --hard/checkout`.

## 3. How the collaboration unfolded

**Phase A — Discovery (reason before edit).** From the vague "green cards on ended" report, the AI grepped `SessionCard.tsx`, `SessionList.tsx`, and the status/grouping logic and concluded the dot-color and grouping code were correct — an existing unit test even pinned that ended sessions render neutral gray, not green. It resisted a knee-jerk CSS patch and instead hunted for a *state* bug. **Why it worked:** treating a UI symptom as a possible state-sync bug avoided fixing the wrong layer.

**Phase B — Root cause.** Reading `App.tsx:344-352` it found the reconnect handler cleared `sessionOrderMap` and `terminals` but not `sessions`, so stale entries survived a server restart and the on-connect re-broadcast merged rather than replaced. **Decision point:** the human's terse symptom ("running card below the 'Show N ended' divider, fixed by page refresh after server restart") was the clue that anchored the diagnosis to reconnect state.

**Phase C — Design via OpenSpec.** The AI proposed a single `sessions_snapshot` message and, per AGENTS.md, **paused to confirm the plan before touching the protocol**. It then ran the full artifact chain: proposal, design (D1–D5 decisions + risks + migration), 4 delta specs, tasks (8 groups). **Why it worked:** the change touched a shared protocol, so spec-first prevented client/server drift.

**Phase D — Implement + verify.** Protocol type → server emit → client handler → App.tsx cleanup, each task marked as it landed. Two new tests pin the REPLACE-not-merge contract. Root `tsc --noEmit` was used as the canonical typecheck. A local `os.userInfo()` env bug blocked one vitest run (worked around, later confirmed passing by the user). A **BREAKING** CHANGELOG entry was added and doc-index updates were delegated to a general-purpose subagent.

**Phase E — Archive + land in jj.** Archive + delta-spec sync (subagent), then the delicate part: the working copy held ~46 files of *unrelated* in-flight work across 4+ other proposals. The AI used `jj split`/`jj squash`/`jj describe` to carve one clean archive commit, kept everything else in `@`, then later described five separate commits and pushed `develop` via `jj git push`. It hit a race (someone advanced `develop` mid-operation, so a bookmark landed on the wrong commit) and cleanly deleted the stray bookmark. **Decision point:** the human pasted the jj-workspace safety manual and steered every git-vs-jj boundary.

## 6. Skills, tools & memory created — and why they're effective

No new skill or memory was persisted this session, but two workflows proved reusable and *should* be captured:

- **`jj-colocated-safe-landing` (recommended skill).** Captures the exact allowed/forbidden git set for a jj colocated repo and the native-jj equivalents (`jj split`, `jj squash --from/--into <files>`, `jj describe`, `jj git push --bookmark`, `git reset` no-flags as the only safe git mutation to clear a dirty index). **Why effective:** this session spent hours re-deriving these rules from a pasted manual; a skill makes it one invocation and prevents irreversible file loss. **Invoke when:** landing/splitting/pushing any commit in a repo with side-by-side `.jj/` and `.git/`.
- **Subagent delegation for mechanical OpenSpec chores.** Two `general-purpose` subagents handled *doc file-index updates* and *delta-spec sync* — isolating token-heavy, low-judgment work from the main context per AGENTS.md. **Invoke when:** archiving a change (sync deltas) or after any file that needs a doc-index row.

## 7. Pitfalls & dead ends

- **`curl http://localhost:8000/api/sessions` failed repeatedly** — no live server / stale port during discovery. If a live repro isn't available, reason from the code path instead of chasing the endpoint.
- **`os.userInfo()` throws locally**, breaking a vitest run (`node -e "os.userInfo()"` fails; a `HOME=$(mktemp -d)` workaround was attempted). It's an env bug unrelated to the change — don't let it block the task; confirm the test separately (the user did: "Tests are ok").
- **`git stash` / `git reset --hard` are landmines** in a jj colocated repo — they silently corrupt jj history and cause **irreversible file loss**. Use `jj new -m "WIP"` to set work aside, or bare `git reset` (no flags) only to clear a dirty index.
- **`develop` moved mid-operation** — a concurrent push advanced the branch, so a bookmark created at `@-` landed on the wrong commit. Re-inspect immediately before pushing; delete stray bookmarks locally *and* on origin.
- **Don't fix the wrong layer.** The "green cards" symptom looked like CSS but was stale reconnect state. Trace the full path before editing.
