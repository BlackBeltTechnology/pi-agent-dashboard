# How we did it: Turning a static kraken-brain PNG into a live, theme-aware Astro hero backdrop — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was

## 1. Goal (the ask)

The kickoff was one line:

> *"Read @.shadow/npm-trusted-publishing/output/kraken-brain.png and make animated js from that which can be used as hero of a page"*

Plain reading: turn a static concept image (a neon brain wrapped in kraken tentacles + binary data streams) into an animated web hero. What the *real* objective became over 29 steering turns: a **production-grade, dependency-free canvas backdrop** that (a) lives inside the project's real Astro marketing site, (b) adopts the site's indigo/violet design tokens and live light/dark theme switching, (c) matches the source image's orientation and mood, (d) performs at ≥30fps via adaptive DPR, (e) reacts to the cursor, and (f) layers correctly behind the existing `MissionGraph` backdrop without a hard seam — then gets folded back to `develop` and specced in OpenSpec. The one-liner was the seed; the finished artifact was a fully-integrated, spec-documented site feature.

## 2. TL;DR playbook

1. **Prototype standalone first.** Ask for a self-contained `.html` (single `<canvas>`, no build step) so you can iterate visually in the browser before touching the real site.
2. **Open it immediately** (`open file.html`) and drive changes from what you *see*, not what you imagine.
3. **Fix perf before features.** When it's "slow as hell", the AI's first move should be: kill per-frame `shadowBlur`, pre-bake static layers to offscreen canvases, cap DPR.
4. **Generate the hero asset with nano-banana** (neon brain on pure black), then **luminance-key it to alpha** client-side and recolor via `source-in` compositing — so one PNG serves every theme.
5. **Read the real site's tokens** (`global.css`, `tailwind.config.cjs`) and bind every canvas color to CSS custom properties (`--kb-*` → `--pi-accent` / `--pi-accent2`). Detect theme via the site's convention (`<html class="dark">`) with a `MutationObserver`.
6. **Port the prototype into an Astro component** (`KrakenBrainBackdrop.astro`) with `IntersectionObserver`/`visibilitychange` pause, calmer defaults, and layer it (`-z-20`) behind the existing backdrop.
7. **Layer honestly.** Don't hide sibling backdrops with an opaque scrim — make your canvas semi-transparent and fade its bottom with a `mask-image` so it cross-dissolves into the page.
8. **Fold back with jj** (rebase onto `develop`, move bookmark, `jj git push` — never `git commit` in a colocated repo), then **spec it in OpenSpec** with one scenario per implemented behavior.

## 3. How the collaboration unfolded

**Phase 1 — Standalone prototype (Discovery → Generate).**
The AI built a self-contained `kraken-brain-hero.html`: deep-space nebula, pulsing ripple rings, a procedural brain, 8 sinusoidal tentacles, binary data streams. *Why it worked:* a zero-dependency single-file artifact is the fastest possible visual feedback loop — open, look, steer. Decision point: the human immediately said **"open in browser"**, establishing the see-then-steer rhythm that ran the whole session.

**Phase 2 — Performance triage.**
"It slow as hell." The AI correctly diagnosed the killers — per-frame `shadowBlur` on 100+ glyphs, re-rasterized nebula, DPR 2 on retina — and rewrote the renderer: pre-baked static layers into offscreen canvases, `Float32Array` point buffers, stacked-stroke glow instead of `shadowBlur`, capped DPR. *Why it worked:* it treated "slow" as a profiling problem with named root causes, not a vibe.

**Phase 3 — Controls + theming scaffold.**
A collapsible controls panel (tentacle count, streams, speed, hue, DPR) plus a Light/Dark/Auto theme with `localStorage` persistence. This made every later aesthetic decision a slider instead of a code round-trip.

**Phase 4 — Real brain asset (the pivotal move).**
"Replace the brain with a pulsating image… use nano-banana… support dark/light… maybe colormap overlay?" The AI generated a neon brain on pure black, **luminance-keyed it to an alpha mask** (`alpha = max(r,g,b)`), and recolored per-theme via `source-in` compositing driven by CSS vars. This one technique — greyscale mask + gradient fill — is why a single PNG works on any background/theme. It survived every subsequent restyle unchanged.

**Phase 5 — Match the source + match the site.**
Rounds of orientation ("rotate 90°" → then "no, same orientation as the kraken image" → regenerate the PNG in lateral side-profile), brightness taming (drop additive double-pass, calmer pulse), and palette adoption. The AI **opened the actual Astro site at localhost:4321**, read its tokens, and switched to indigo/violet with `html.dark` detection.

**Phase 6 — Integrate into Astro.**
Ported to `KrakenBrainBackdrop.astro`, copied the PNG to `site/public/`, wired it into `Hero.astro` layered behind `GlowBackdrop`. Added `centerSelector` so the brain anchors to the `<h1>` bounding box, and theme-aware canvas opacity for dark-mode paragraph readability.

**Phase 7 — Interaction + polish.**
Cursor-following tentacle tips (`u³` falloff so only tips reach), animated marching dashed lines, tip↔dash spark collisions with cooldown, adaptive DPR (≥30fps, 0.25 steps, 0.5 floor, 3s cooldown), and a heartbeat lub-DUB pulse (two Gaussians over a slow breath sine).

**Phase 8 — Layering truth + ship.**
The scrim used to hide the body's dot-grid was *also* hiding the site's `MissionGraph` constellation. Fix: **remove the scrim entirely**, drop redundant bubble rings, keep only a bottom `mask-image` fade so the canvas dissolves into the page. Then fold back to `develop` via jj rebase + push, and add an OpenSpec requirement with 7–8 scenarios.

## 7. Pitfalls & dead ends

- **`getImageData` taints `file://` images** in Chrome — the colormap needs pixel access. *Fix:* inline the PNG as a base64 data URL (fetch→blob with base64 fallback), so pixel reads work under `file://`.
- **Rotating the brain 90° was wrong** — the source wanted lateral side-profile. *Fix:* regenerate the asset in the correct orientation via a precise nano-banana prompt ("lateral side-profile view, facing right"), then drop the `g.rotate()`.
- **The opaque scrim hid the site's `MissionGraph`** and created a hard bottom seam. *Fix:* delete the scrim, go semi-transparent, and fade the bottom with `mask-image: linear-gradient(to bottom, black 75%, transparent)`.
- **`mcp__context-mode__ctx_stats` isn't wired in this session** — only `mcp__pi__*` tools are. *Fix:* skip it, or run `/context-mode:ctx-stats` from a session where it's connected.
- **Astro dev server needed `npm install` first** and an explicit `--host 127.0.0.1 --port 4321`; blind `curl` probes of guessed ports failed. *Fix:* install, then start with explicit host/port and tail the log for the ready line.
- **`git commit` in a jj-colocated repo bifurcates history.** *Fix:* fold back with `jj git push --bookmark develop` after rebasing onto the moved tip; never `git commit` directly.
- **`openspec validate --strict` flagged a pre-existing schema mismatch** (`## ADDED Requirements` delta header in a synced spec) — not caused by this change; note it, don't chase it.
