# How we did it: turning "why can't a flow agent see my extension?" into a shipped dashboard plugin — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened as a debugging question, not a build request:

> "Why flow agent cannot access extension which add claude instructions?"

The *real* objective only crystallized across the next dozen steering turns. What the
operator actually wanted was: understand why a pi-flows spawned agent doesn't inherit
the `@pi/anthropic-messages` tool-name bridge, decide whether that can be fixed, and —
once it was clear it *could* — **ship a first-party dashboard plugin**
(`flows-anthropic-bridge-plugin`) that forwards the bridge into every flow agent, with
a Settings UI, deferred peer-gated activation, tests, and an OpenSpec proposal capturing
the leftover wiring gap. A diagnostic turned into a designed, tested, documented package.

## 2. TL;DR playbook

1. **Frame the "why" as an architecture question first.** Ask the AI to explain *why*
   the extension is invisible to the subprocess before asking it to fix anything. Here
   the answer was pi-flows' agent-isolation model: extensions must opt in via
   `flow:register-agent-extension`.
2. **Make the AI check the upstream source, not just theorize.** It found the integration
   was *already wired* in pi-flows (`anthropicMessagesAgentFactory`), which reframed the
   whole problem — the bug was billing/quota, not the bridge.
3. **Separate the layers explicitly.** Have the AI draw the "bridge (name translation)"
   vs "provider (who bills tokens)" distinction so you stop chasing the wrong error.
4. **Escalate from one-file extension → dashboard plugin** once you know it works:
   "Draw as a pi-dashboard plugin."
5. **Nail the name early and once** (`pi-flows-anthropic-bridge-plugin`, matching the real
   `pi-flows` package name) — renames rippled through ~10 identifiers.
6. **Demand deferred, peer-gated activation:** install unconditionally, probe for both
   peers (`pi-flows` + `@pi/anthropic-messages`), register hooks only when both resolve,
   re-probe on `session_start`, broadcast state to the UI.
7. **Model on an existing first-party plugin** (`flows-plugin`), not the scaffold templates
   — matches repo conventions.
8. **Extract the probe into a pure `peer-probe.ts`** so it's unit-testable without the pi
   runtime; write the tests first.
9. **Run the full suite + tsc + production build** before declaring done (423 files /
   4293 tests here).
10. **Capture the leftover gap as OpenSpec** (`wire-plugin-registry-into-shell`) when the
    plugin is invisible because the registry isn't populated — don't hand-patch silently.

## 3. How the collaboration unfolded

**Phase 1 — Diagnosis (why is it invisible?).** The AI explained pi-flows' agent isolation:
flow agents are isolated sub-sessions whose system prompt comes from the agent `.md` body,
not `AGENTS.md`/`CLAUDE.md`, and parent-session extensions don't auto-load. *Why it worked:*
grounding the answer in `pi-flows/docs/architecture.md` (fetched live) instead of guessing.

**Phase 2 — The plot twist (it's already wired).** Prompted to actually look, the AI cloned
pi-flows and found `anthropicMessagesAgentFactory` already feeding `@pi/anthropic-messages`
into every spawned agent. That flipped the question from "can it work" to "what's breaking
the chain." *Decision point:* the operator asked "when it's true why do I get an anthropic
error back?" — forcing evidence over theory.

**Phase 3 — The real error was billing.** The AI read the log and identified the error as a
Claude.ai overage/quota message ("out of extra usage"), not a bridge failure — the previous
turn had succeeded on `claude-opus-4-7`. It cleanly separated *name-translation bridge* from
*provider quota*.

**Phase 4 — Escalate to a plugin.** Once the mechanism was understood, the operator pushed:
"Draw as a pi-dashboard plugin." The AI designed a single workspace package with three entry
points (bridge / server / client), then iterated the name twice
(`pi-flow-` → `pi-flows-` → final `flows-anthropic-bridge-plugin`) and the activation model
(eager → **deferred, peer-gated with a state machine**: probing → waiting_peers → active →
degraded).

**Phase 5 — Generate + verify.** Modeled on `flows-plugin`, created the package, added it to
`vitest.config.ts` projects, wrote 6 peer-probe tests, ran the full suite (4293 tests green),
tsc, and the production build. Dropped an unsupported WS subscription in the client in favor of
a REST `/api/flows-anthropic-bridge/status` endpoint + refresh button.

**Phase 6 — Document the gap.** Asked "is there any proposal which mentions [this]?", the AI
searched active + archived changes, found none covered the two missing wires, and authored the
`wire-plugin-registry-into-shell` OpenSpec change (proposal + design + tasks + spec).

## 4. Prompts that worked

- **Goal prompt — "Why flow agent cannot access extension which add claude instructions?"**
  Effective because it asked *why*, not "fix it" — forcing a root-cause explanation that
  exposed the isolation model before any code was written.
- **"When its true why I got anthropic error back?"** — a high-leverage skeptic prompt: it
  refused the tidy theory and demanded the AI reconcile it with the actual observed error,
  which surfaced the billing/quota red herring.
- **"Draw as a pi-dashboard plugin."** — five words that pivoted the whole deliverable from a
  throwaway one-file extension to a real workspace package.
- **"The extension can be installed, but have to check and listens extension registrations and
   if both extension available, register the hooks."** — the single most valuable design
  prompt; it specified deferred, peer-gated activation precisely enough to implement directly.
- **"Add to this monorepo"** — the unlock that moved from sketch to shipped package.

*Rewrite of the weak opener for next time:* "Explain why a pi-flows agent subprocess doesn't
inherit a parent-session extension's hooks (cite the isolation model), then tell me whether
`@pi/anthropic-messages` is already forwarded into flow agents upstream."

## 6. Skills, tools & memory created — and why they're effective

No reusable skill or memory was created in this session. One subagent was spawned
(`general-purpose`) to add a `docs/file-index-plugins.md` row in caveman style per the project's
documentation-update protocol — and it *got the package name wrong*, which the main agent had to
correct with a one-fact edit (see Pitfalls).

The durable asset is instead an **OpenSpec change**: `wire-plugin-registry-into-shell`, which
captures the two missing wires (`viteDashboardPluginsPlugin` absent from `vite.config.ts#plugins[]`,
and `App.tsx` keeping an empty `createSlotRegistry()`) that keep every manifest-declared slot claim
invisible in the UI.

*Recommended skill to create:* a **"forward a pi extension into every flow agent"** playbook —
the peer-probe + `flow:register-agent-extension` forwarder + deferred state machine is a
repeatable pattern, and `peer-probe.ts` is a clean, testable template worth generalizing.

## 7. Pitfalls & dead ends

- **Chasing a bridge bug that was really a quota cap.** If a flow agent throws an "anthropic
  error" but a prior turn succeeded, read the log — "out of extra usage" is Claude.ai billing,
  not the bridge. Fix: top up, or switch the agent off Opus, or route through a non-OAuth provider.
- **Assuming an upstream patch is needed.** pi-flows already forwards `@pi/anthropic-messages`
  via `anthropicMessagesAgentFactory`. Check the source before writing a fix.
- **WS live-state subscription in the client failed** — the runtime API doesn't support it. Use
  REST `/api/flows-anthropic-bridge/status` + a refresh button instead.
- **The file-index subagent used the wrong package name.** Delegated caveman-style doc edits can
  get a fact wrong; verify the package name row and correct it (`@blackbelt-technology/pi-dashboard-flows-anthropic-bridge-plugin`).
- **Name churn cost edits.** `pi-flow-` → `pi-flows-` rippled through ~10 identifiers
  (dir, package name, plugin id, settings key, events, components, test ids). Settle the name first.
