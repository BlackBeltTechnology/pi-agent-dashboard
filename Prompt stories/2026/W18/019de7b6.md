# How we did it: Cutting AGENTS.md from 132 KB to 12.7 KB — an AI collaboration guideline

> A reusable playbook reconstructed from a real pi session. It explains **what was
> asked, how it was built with the AI, what had to be steered, and how to reproduce
> the result faster next time.** Write for a future operator who has the same goal.

---

## 1. Goal (the ask)

The session opened with a bare `hello`, but the real objective arrived in the second
turn: *"The initial context usage is 70k. What is the reason? How can be it improved
without loosing track"*. The operator noticed every new pi session in this project
booted at ~70k tokens of system-prompt overhead and wanted that shrunk — **without
losing any of the knowledge** the loaded context encoded. The real objective:
diagnose where the 70k came from, then relocate the bulk of it out of the
always-loaded `AGENTS.md` into an on-demand file, preserving every fact verbatim.

## 2. TL;DR playbook

1. **Measure first.** `wc -l AGENTS.md && wc -c AGENTS.md` to size the always-loaded file, then `grep -n "^## " AGENTS.md` to see its section skeleton.
2. **Attribute the tokens.** Identify the single biggest block — here a ~50 KB "Key Files" table with inline change-history footnotes — and confirm it dominates the 70k budget.
3. **Confirm the plan before cutting.** State: move the giant table to an on-demand `docs/file-index.md`, leave a slim curated backbone + pointer in `AGENTS.md`. Get a "yes".
4. **Extract the section losslessly.** `awk '/^## Key Files/{p=1} /^## Build & Restart/{p=0} p' AGENTS.md` to pull the exact byte range into a temp file; prepend an intro that says "loaded on demand".
5. **Write `docs/file-index.md`** with the full table verbatim (all rows + change-history annotations preserved).
6. **Cut the section out of `AGENTS.md`** with a line-range `sed -i.bak '<start>,<end>d'` (delete the `.bak` after), replacing it with a curated architectural-backbone map grouped by layer + an explicit `Full file map: see docs/file-index.md` pointer.
7. **Verify the byte drop** (`wc -c` before/after) and report the estimated token savings; tell the operator to boot a fresh session and check the new initial count.

## 3. How the collaboration unfolded

**Phase 1 — Diagnosis (measure, don't guess).** The AI ran `wc` and `grep -n "^## "`
over `AGENTS.md`, then presented a token-attribution table (`AGENTS.md` ~55–60k, skill
descriptions ~3–4k, base system prompt ~6–8k → ~70k). *Why it worked:* it grounded the
"why 70k" answer in actual file sizes instead of hand-waving, and it named the single
culprit — the Key Files table with per-file change-history footnotes.

**Phase 2 — Proposal.** The AI proposed the fix (relocate change-history + the big
table out of the always-loaded file; keep `AGENTS.md` a *map*, not a *changelog*) and
paused. The human's one-word `yes` was the decision point that unlocked execution.

**Phase 3 — Lossless extraction.** The AI used `awk` range-matching (`/^## Key Files/`
… `/^## Build & Restart/`) to carve out the exact section into `/tmp`, then built a new
`docs/file-index.md` header explaining it loads on demand. *Why it worked:* range-based
`awk`/`sed` moved the content byte-for-byte — no re-typing, no dropped rows.

**Phase 4 — The cut.** A line-range `sed -i.bak '152,497d' AGENTS.md` deleted the giant
block; the `.bak` was removed immediately after. `AGENTS.md` got a slim curated backbone
grouped by layer (Protocol, Bridge, Server, Routes, Browser WS, Client, Cross-platform,
Plugins, Electron) plus a pointer to the full index.

**Phase 5 — Verify.** A before/after `wc -c` echo confirmed 132 KB → 12.7 KB, and the
AI reported ~30k tokens of estimated initial-context savings (70k → ~40k on next boot).

## 4. Prompts that worked

- **The goal prompt:** *"The initial context usage is 70k. What is the reason? How can
  be it improved without loosing track"*. Effective because it paired a **measurable
  symptom** (70k) with an explicit **constraint** ("without losing track") — that
  constraint is what steered the AI toward *relocate losslessly* instead of *delete*.
  A stronger version bakes in the target: *"Our session boots at 70k. Find what's in
  the system prompt, then move the largest chunk out of AGENTS.md into an on-demand
  doc — preserving every row verbatim. Show me before/after byte counts."*
- **High-leverage follow-up:** `yes`. One word that approved a well-formed plan and
  unlocked the whole execution phase — proof that a clear Phase-2 proposal makes the
  human's job trivial.

## 7. Pitfalls & dead ends

No commands failed in this session (0/10). Guardrails that kept it clean:

- **Line-range `sed` deletion is fragile** — the `152,497d` range only works because
  the AI first re-ran `grep -n "^## "` to confirm exact boundary line numbers *after*
  writing the new content. If you hit an off-by-N cut, re-grep the headers and recompute
  the range; never trust a stale line number.
- **Always `-i.bak` then `rm` the backup** — the destructive `sed -i` was done with a
  `.bak` safety copy, deleted only after `wc`/`grep` verified the result. If a cut goes
  wrong, restore from `.bak` before it's removed.
- **Prove the win with bytes, not vibes** — the closing `wc -c` before/after echo is what
  turns "should be smaller" into "132 KB → 12.7 KB". Always end with the measurement.
