"Knowledge Base (KB)" section: single FTS5 table `chunks` over `node:sqlite`; zero network/LLM, mechanical ranking. Backend `SqliteFtsStore` (`packages/kb/src/sqlite-store.ts`); config layered project → global → defaults (`packages/kb/src/config.ts`). "KB retrieval pipeline" `store.search()`: one BM25 pass + staged pipeline. Stage order: body-hash collapse (byte-exact dedup, `akaPaths`, runs first) → source dedup (one hit per `(root,path)`, best BM25 score, `suppressedSections`) → MMR (`diversity`, config-gated default on) → coverage rerank (default off) → lane interleave → limit slice → parent expand (`expandParent` default on, attaches parent `headingPath`). `limit` bounds distinct sources not chunks (BREAKING); fetch depth `limit × 6` source-dedup / `limit × 4` body-hash-only, cap 4000. Lane quota `ranking.laneQuota` (default 0.5): `agents` 3.2% of index ~3× longer, BM25 length normalisation buries ~30:1; second FTS pass `doc_type='agents'` shallow pool interleaved; explicit `docType` bypasses quota. Coverage rerank + RM3-style PRF (`queryExpansion.mode: "prf"`) default off; measured regression (markdown-intent R@10 0.630→0.491, latency ~4×). Condensed render emits leaf heading not breadcrumb + `(+N more sections)`; full `headingPath` retained. `kb_get` path-only fetch returns first chunk + `suppressedSections`, never silent 1-of-N.
