# Plugin Seams

Authoring guide for plugin server-entry seams: credential
store, OAuth flow start, private bridge→server request/reply lane, editor-pane tabs
(`editor-pane-tab` slot + `ctx.openEditorTab`), and plugin prompt metadata (`pluginMeta`). All
exposed on `ServerPluginContext` from
`@blackbelt-technology/dashboard-plugin-runtime/server`. Worked example:
`packages/demo-plugin` (fixture).
First production consumer: `packages/gmail-plugin` → see [`gmail-plugin.md`](gmail-plugin.md).

See change: `expose-plugin-credential-and-oauth-seams`.

## Credential store (`ctx.credentials`)

Namespaced, locked, 0600 credential persistence. File
`~/.pi/agent/plugin-credentials.json`, plaintext at rest — same posture as
`auth.json`. Deliberately NOT `connector-auth.json` (claimed by
`add-connector-layer` with another schema).

Schema `{ "<pluginId>": { "<key>": <record> } }`. Plugin sees OWN namespace only.
Namespace = manifest id, bound by host. No cross-namespace surface.

```ts
const credentials = ctx.credentials; // optional — absent on hosts that do not wire it
await credentials?.set("demo-account", { access: "…", refresh: "…" });
const rec = await credentials?.get("demo-account");   // clone, or undefined
const keys = await credentials?.list();               // keys only, no records
const all = await credentials?.snapshot();            // clone of own namespace, one read
await credentials?.remove("demo-account");
await credentials?.update("demo-account", (prev) => prev && { ...prev, refreshedAt: Date.now() });
```

### API

| Call | Behaviour |
|---|---|
| `get(key)` | Record clone, or `undefined`. Never creates file. |
| `list()` | Key strings only. Never record contents. |
| `snapshot()` | Clone of caller's OWN namespace from one read. |
| `set(key, record)` | Locked whole-file atomic rewrite. |
| `remove(key)` | Locked whole-file atomic rewrite. |
| `update(key, fn)` | `fn` runs INSIDE lock — atomic read-modify-write. Return `undefined` deletes. |

Reads (`get`/`list`/`snapshot`) unlocked. Safe: file only replaced by atomic
rename; read never creates file. Writes (`set`/`remove`/`update`) share the
`locked-json-file.ts` lock with `auth.json`.

### Limits and errors

- Keys 1–200 chars. Reserved keys `__proto__`, `constructor`, `prototype` rejected.
- Records plain JSON objects ≤ 64 KiB serialized.
- ≤ 256 keys per namespace. ≤ 2 MiB per namespace.
- `PluginCredentialError` codes: `invalid_key`, `invalid_record`,
  `record_too_large`, `too_many_keys`, `namespace_too_large`.

`update` is the only atomic read-modify-write. Concurrent `get`+`set` races.

## OAuth flows (`ctx.oauth.startFlow`)

Start a plugin sign-in through the host flow store. Returns `{ flowId }`; the
`flowId` is served by the host's `/api/provider-auth/flow/:flowId` routes.

```ts
const { flowId } = await ctx.oauth!.startFlow({
  key: "default",
  loginFlow: myLoginFlow,              // PluginOAuthLoginFlow
  persist: (credential) => credentials!.set("account", { ...credential }),
});
```

- Flow `provider` = `plugin:<pluginId>:<key>`. Second start with same plugin key
  supersedes the first.
- Rejects with `PluginFlowStartError` codes `start_timeout` | `login_failed`.
- `persist` receives the object `login()` resolved with, UNTOUCHED — no
  normalisation. Extra fields (`sub`, `email`, `grantedScopes`) preserved.
  Each flow has its own `persist` closure; concurrent flows do not race.
- Start handshake bounded by `FLOW_START_TIMEOUT_MS` = 15 s.
- Registry-independence: flows whose provider starts `plugin:` skip the
  `await registryReady` (pi-ai provider registry) wait, so plugin sign-in works
  even when the LLM registry is slow or failed to build.
- Flow TTL 10 min. Flow input NEVER logged.

### Serving the flow

| Route | Method | Action |
|---|---|---|
| `/api/provider-auth/flow/:flowId` | `GET` | status |
| `/api/provider-auth/flow/:flowId` | `DELETE` | cancel |
| `/api/provider-auth/flow/:flowId/input` | `POST` | answer pending prompt |

Client helper `oauthFlowClient` (`status` / `input` / `cancel`) wraps these, so
plugin clients never hard-code paths. Render the flow with the `ui:oauth-flow`
primitive — `packages/demo-plugin/src/client.tsx` is the working consumer.

### Loopback callback (`createLoopbackCallback`)

One-shot OAuth redirect listener for plugin server entries. Import from
`@blackbelt-technology/dashboard-plugin-runtime/server`.

```ts
import { createLoopbackCallback } from "@blackbelt-technology/dashboard-plugin-runtime/server";

const cb = await createLoopbackCallback({ path: "/callback", timeoutMs: 300_000, signal });
// cb.redirectUri → http://127.0.0.1:<port>/callback
// cb.state       → generated by helper (32 random bytes, base64url)
const { code } = await cb.waitForCode();
cb.close(); // idempotent
```

- Binds `127.0.0.1` on port 0 (ephemeral). Generates `state` itself — avoids a
  late-registered state.
- Only `GET <path>` counts. Other paths → 404; helper keeps waiting.
- State check comes FIRST:
  - missing/mismatched `state` → 400, helper keeps waiting. A stray or hostile
    local request cannot kill the flow — including one carrying `error=`.
  - matching `state` + `error=` → rejects with `error` / `error_description`.
  - comparison length-checked before `timingSafeEqual`.
  - match → static completion page, resolves with `code`, closes.
- `close()` idempotent. Timeout and abort reject and close.
- Local-only. Remote dashboards use the `manual_code` paste fallback instead.
- Pure `node:http`. No dashboard server import.

## Request/reply lane (bridge ↔ server)

Private request from a plugin bridge entry (pi tool) to its plugin server entry.
Never rides `pi.events`. Replies resolve a Promise held only by the caller.

### Bridge side

```ts
import { requestPluginServer } from "@blackbelt-technology/dashboard-plugin-runtime/bridge";

const reply = await requestPluginServer("demo", "demo/echo", { text });
// reply.ok === true → reply.result ; false → reply.error code/message
```

- Core bridge installs a Promise-returning fn at
  `Symbol.for("pi-dashboard.pluginRequest")` on `globalThis` while connected.
- Symbol absent (old extension, or not running under dashboard) →
  `{ ok: false, error: "unavailable" }`.
- `requestPluginServer` RESOLVES, never rejects. Always check `reply.ok`.

### Server side

```ts
ctx.registerPiRequestHandler?.("demo/echo", async (payload, { sessionId }) => {
  // authorize on payload — sessionId is "some session of this user"
  return `echo: ${String((payload as { text?: unknown })?.text ?? "")}`;
});
```

- One handler owner per `(manifest pluginId, type)`. Duplicate registration throws.
- Registry separate from fire-and-forget `registerPiHandler` — those handlers
  (`mcp_token_minted`, …) untouched.
- `sessionId` from the socket key, never from the payload.
- Handler throw → reply `error` = message only, never the stack.

### Error codes and caps

- Request cap 256 KiB; reply cap 256 KiB (serialized UTF-8 bytes).
- Error codes: `no_handler`, `timeout` (15 s), `disconnected`,
  `request_too_large`, `reply_too_large`, `reply_not_serializable`,
  `unavailable`. Plus `request_not_serializable` (bridge-side).
- Reply sent host-internally — NOT the priority-gated `sendExtensionMessage`. A
  reply answers a request the same session's bridge made, on that session's
  socket, so it is sent for plugins of any priority.

```mermaid
sequenceDiagram
  participant T as plugin bridge (tool)
  participant X as core bridge (extension)
  participant S as host server
  participant P as plugin server handler
  T->>X: globalThis[Symbol.for("pi-dashboard.pluginRequest")](pluginId,type,payload) → Promise
  X->>X: size check ≤256KiB; requestId=uuid; pending.set(requestId,{resolve,timer 15s})
  X->>S: {type:"plugin_request",requestId,pluginId,messageType,payload}
  S->>S: lookup requestHandlers[(pluginId,type)] (single owner)
  S->>P: handler(payload,{sessionId})  (sessionId from socket key)
  P-->>S: result | throw
  S->>S: serialize + size check
  S->>X: host sends {type:"plugin_reply",requestId,ok,result|error}
  X->>T: resolve({ok,result|error})
```

## Editor-pane tabs (`editor-pane-tab` slot)

React-only slot, multiplicity many, predicate input never. Addressed by path prefix, never filtered by predicate.

Claim fields: `component` (tab body), `pathPrefix`, optional `labelComponent` (tab-strip label).

- `pathPrefix` matches `^[a-z][a-z0-9-]{1,31}$` (`PANE_TAB_PREFIX_RE`). Reserved: `diff|term|url|live` — always built-in viewer, never claimable.
- Tab path = `<pathPrefix>:<rest>`. Viewer kind `plugin`.
- Body props `EditorPaneTabProps` `{ path, session, isActive, onClose }`. Label props `{ path, session }`.
- Label stays mounted for background tabs. Body renders while active.
- Unclaimed or disabled prefix → `PluginTabUnavailable` placeholder (`"Tab unavailable (<prefix>)"` + Close). Never reaches `/api/file`.
- Cross-plugin duplicate `pathPrefix` fails registry generation, naming both plugins.
- Registry hash includes `pathPrefix` / `labelComponent`.
- Pane hydration drops only unknown-viewer entries per entry (`dropUnknownViewers`). Structure stays all-or-nothing.

See change: `add-browser-editor-pane-tab`.

## Editor-pane file handlers (`editor-pane-file-handler` slot)

React-only slot, multiplicity many. Attaches to real workspace files by extension. Adds alternative preview/edit modes beside the built-in viewer. Design: openspec `add-editor-pane-file-handlers` (D1–D7). See change: `add-editor-pane-file-handlers`.

Claim fields (`PluginClaim`, `packages/shared/src/dashboard-plugin/manifest-types.ts`):

| Field | Req | Rule |
|---|---|---|
| `component` | yes | handler body (`module` lazy ok) |
| `id` | yes | `^[a-z][a-z0-9-]{0,31}$`, unique per plugin |
| `extensions` | yes | non-empty; each `^\.[a-z0-9][a-z0-9+-]{0,15}$`; no wildcard, no multi-dot |
| `mode` | yes | `preview` \| `edit` |
| `label` | yes | ≤ 40 chars |
| `keepAlive` | no | `{ max: 1..3 }` |
| `maxBytes` | no | ≤ `HANDLER_MAX_BYTES` (128 MiB); default = ceiling |
| `firstOverwriteNotice` | no | ≤ 300 chars |
| `validator` | no | `true` = saves need registered validator (fail closed) |
| `copySuffix` | edit: yes | `^[a-z][a-z0-9-]{1,31}$` |

Validation:

- Text-backed ext rejected: `isTextBackedExt(ext)` (`packages/shared/src/file-kind.ts`). True when `fileKind("/x"+ext)` is `editable`, or recognised kind with viewer in `monaco|markdown|mermaid|asciidoc|html|diagram`.
- Text stays on `/api/file/write`. Unrecognised ext (`.drawio`, `.psd`) stays claimable.
- Extensions also rejected via frozen deny list `HANDLER_DENIED_EXTS` (`packages/shared/src/file-kind.ts`, `isUnclaimableHandlerExt`).
- Deny list groups: secrets (`.env` `.npmrc` `.pem` `.key` `.crt` …), scripts (`.ps1` `.bat` `.cmd` …), plain text (`.patch` `.diff` `.jsonl` `.ipynb` `.lock` …).
- List fixed. Claimable set does not shift when `fileKind` learns a kind.
- Ordering: plugin `priority` → plugin id → claim id. No per-claim priority.
- Two plugins may claim same ext. Switcher lists both.

### `FileHandlerProps` (`slot-props.ts`)

```ts
{ cwd, path, session, isActive,
  snapshot(): Promise<{ bytes, size, mtime, sha1 }>,
  save(bytes, { target: "overwrite" | "copy" }): Promise<{ ok: true, path, mtime, sha1 } | { ok: false, reason, message }>,
  setDirty(state: boolean | "unknown"),
  context: PluginContext }
```

- `save` reasons: `cancelled` · `conflict-unresolved` · `rejected` · `too-large` · `busy`.
- `snapshot` = digest bracket: `GET /api/file/digest` → `GET /api/file/raw` (`no-store`) → digest. Accept when `sha1₁ = sha1₂ = sha1(bytes)`. Retry ×3, then reject. Size over `maxBytes` → refused before content fetch.
- Snapshot sets changed-on-disk baseline to its `sha1`.
- `setDirty` initial = `"unknown"`. Call as soon as doc loaded. `"unknown"` = dirty for guards, never evictable.
- Core trusts `setDirty(false)`. Lying handler loses edits on eviction.
- `save` overwrite sends `expectSha1` = last snapshot/save sha1.
- 409 → conflict dialog: Reload (confirm if dirty) · Save as copy · Overwrite anyway (explicit exception: replaces current disk content) · Cancel.
- Success: wrapped in `trackedFileWrite`. Own save: no banner, including watch events during flight.
- First overwrite per instance with `firstOverwriteNotice`: Overwrite · Save as copy · Cancel. Later overwrites don't ask. Reset on tab close, reload, instance close.

### `POST /api/file/write-binary` (`packages/server/src/routes/file-write-binary-routes.ts`)

- Body: raw bytes, `application/octet-stream`, `bodyLimit` 128 MiB. Encapsulated Fastify plugin (only this route gets the parser).
- Query: `cwd`, `path`, `mode=overwrite|copy`, `expectSha1` (required for overwrite), `claim=<pluginId>/<claimId>`.
- Tier `control` (`packages/shared/src/route-tiers.ts`). `networkGuard` preHandler.
- 200 `{ success:true, data:{ mtime, sha1, path } }`.
- 400 bad query · missing `expectSha1` on overwrite.
- 403 unknown cwd · path/realpath outside `<cwd>/**` · requested or real ext not in `claim.extensions` · claim missing · plugin disabled · `mode` ≠ `edit` · `enabled()` false · non-regular target.
- 409 overwrite: content sha1 ≠ `expectSha1` (or file gone). Body top-level `sha1?`, `mtime?` (absent when gone). Copy: no free name (`-99` exhausted).
- 413 body > claim `maxBytes`.
- 415 Content-Type not `application/octet-stream` or body missing (only octet-stream parser installed in this route's scope).
- 500 generic `write failed`. No paths in body.
- 422 validator rejected, threw, or timed out.
- 503 validator pool busy (`retryable: true`) or `validator: true` claim without loaded validator.
- Overwrite: under realpath lock; hash-compare, not mtime. tmp + rename; keeps file mode. Lock key = realpath, shared with `/api/file/write`.
- Copy: `<stem>.<copySuffix>.<ext>`, then `-2`…`-99` via exclusive `wx`. Never overwrites. Mode = source's, else `0644` & umask.
- Residual: external writer racing between hash and rename not excluded (same as text route).

### `ctx.registerFileValidator`

```ts
ctx.registerFileValidator({ claimId, module, enabled? });
// module exports validate(bytes, ext) → { ok: true } | { ok: false, reason }
```

- Own edit claims only. Foreign `claimId` throws.
- `module`: relative, no `..`, realpath-confined to plugin package.
- `enabled?()`: main-thread predicate, checked first. `false` → 403. Lets a plugin refuse saves live.
- Runs in `worker_threads` pool (`packages/server/src/lib/file-validator-pool.ts`): 2 workers, queue 8, 11th → 503. Timeout 5 s → `terminate()`. Bytes transferred.
- Runs before per-target lock. Slow validator never stalls text saves.
- Validator can only reject.
- Fail closed: `validator: true` claim writable only while plugin server entry loaded (`getPluginStatusStore().getStatus(id)?.loaded`) and validator registered. Live re-enable → 503 until restart.

### Keep-alive, cap, guards (client)

- Layer `FileHandlerLayer` mounted once at app shell, outside `EditorPane`/`SplitWorkspace`. Instances survive pane close, layout change, tab switch, session switch.
- Handler modes only in session editor panes. Folder panes: no switcher.
- Instance key: `sessionId + cwd + normalize(path) + claim`. Same file+claim in one session shares instance.
- Mode state: `handlerMode: "<pluginId>/<claimId>"` on tab (`editor-pane-state`). Missing/disabled claim → built-in view for that tab only.
- Built-in `CappedViewer` not mounted while handler mode active. No preview fetch / conversion.
- Cap: `MAX_LIVE_HANDLERS = 3` per page (`file-handler-logic.ts`). `keepAlive.max` lowers own share. LRU = oldest activation.
- Eviction: LRU with `setDirty(false)` only. Tab shows "Editor closed to save memory — Resume". None evictable → dialog: save or discard one. Cancel aborts mount.
- Claim without `keepAlive`: closed on tab inactive only if state `false`. Else hidden, counts to cap.
- Plugin disabled live: component ref kept. `false` → closed, built-in view. Unsaved/unknown → overlay: Re-enable · Discard (confirm). Server refuses saves.
- Guarded discard (state `true`/`"unknown"`): mode switch, last-tab close, banner/manual refresh, conflict Reload, plugin disable, `beforeunload`. Eviction never auto-discards.
- Refresh on handler tab: `remount(instanceKey)` after guard. Banner clears only when remount proceeds.
- Deleted/renamed file: instance stays. Next overwrite → 409 → copy offered.

### Limits and residuals

- Large-file limit gates built-in view only. Handler gated by `claim.maxBytes`.
- Outside session cwd: mode shown unavailable ("outside the session folder").
- D7 residual: sandboxed opaque-origin frames can issue credential-less loopback GET `/api/*`. CORS hides response; side-effecting GETs still run. Follow-up hardening in shared genuine-local predicate. Handler plugins that frame third-party code must document this.

## Opening plugin tabs

ONE navigation opens one or more tabs: `/session/<id>/editor?tab=<path>[&tab=...]`.

- Helper `openPluginTabRoute(navigate, sessionId, paths[])` (`packages/dashboard-plugin-runtime/src/editor-pane-tab.tsx`). Stamps fresh history-state `openNonce`. Identical re-open after close still re-applies.

- Virtual paths excluded from file-watch set (`openPathsKey`).

## Server-initiated tab open (`ctx.openEditorTab`)

```ts
ctx.openEditorTab(sessionId, path); // path under an OWN editor-pane-tab prefix
```

- Own prefix only. Prefixes derived from manifest claims by host, passed as `ownedPaneTabPrefixes`. Foreign prefix → throws.
- Broadcasts core WS message `editor_tab_open { sessionId, path }`.
- Client acts only on current route `/session/<sessionId>` or `/session/<sessionId>/editor`. Other routes ignore, no navigation.
- Agent session id comes from request-lane meta (socket key), never payload — see "Request/reply lane".

## Plugin prompt metadata (`pluginMeta`)

Plugin-namespaced data on PromptBus dialog requests. Core keys (`message`, `toolCallId`) stay core-owned.

```ts
ctx.ui.confirm({ message: "Take over browser?", pluginMeta: { pluginId: "browser", kind: "browser-takeover", instanceId } });
```

- `ctx.ui.*` opts accept `pluginMeta` (`packages/extension/src/prompt-meta.ts`). Plain JSON object, ≤ 2048 UTF-8 bytes serialized.
- Copied into prompt `metadata.plugin`. Invalid (non-plain, unserializable, oversize) dropped with warning. Prompt still raised.
- Never overrides `message` / `toolCallId` / `kind`.
- Client copies into interactive request `params._pluginMeta`. Exposed in plugin context `InteractiveUiRequestSnapshot`.
- Example: browser takeover `{ pluginId: "browser", kind: "browser-takeover", instanceId }`.

See change: `add-browser-editor-pane-tab`.

## Host read seams (`getPiResources` / `onPiResourcesInvalidated`)

Optional, additive. Absent → plugin route returns 501. See change: add-skill-atlas-screen.

- `getPiResources?(cwd?: string, opts?: { fresh?: boolean }): Promise<PiResourcesResult>`.
  - Type `GetPiResourcesFn` (`packages/dashboard-plugin-runtime/src/server/server-context.ts`).
  - Default: cached → as is; stale → one background refresh; cold miss → await.
  - `fresh: true` → scan started after call. Host awaits in-flight scan that predates call, then rescans.
  - Returns raw scan result (no provenance join).
  - Missing `cwd` → `process.cwd()`.
- `onPiResourcesInvalidated?(handler: (cwd: string | undefined) => void): () => void`.
  - Type `OnPiResourcesInvalidatedFn`.
  - Fires on watcher invalidation (`cwd`, `undefined` = global) and on `commands_list` arrival (cwd from session).
  - Per-subscriber try/catch. Returns unsubscribe.

Consumer: `packages/skill-atlas-plugin` (see [`skill-atlas.md`](skill-atlas.md)).

## Lazy claim modules (`module`)

Lazy-load a claim's `component` into its own chunk. Additive, optional. See change: lazy-plugin-claim-modules.

Manifest (`PluginClaim`, `packages/shared/src/dashboard-plugin/manifest-types.ts`):

- `module?: string`. Package-relative path. Starts `./`. No `..` segment.
- Requires `component`.

Generator (`packages/dashboard-plugin-runtime/src/vite-plugin/index.ts`):

- Claim with `module` → no static import of `component`.
- Emits `Component: lazyClaim(() => import("<spec>"), "<component>")`.
- Import spec: `<pkg>/<subpath>` if `package.json#exports` has exact subpath key targeting module file. Else path relative to generated file, ext stripped.
- `predicate`, `shouldRender`, `labelComponent` stay static from main client entry.
- `module` included in registry hash (`deterministicSerializePlugins`, `packages/dashboard-plugin-runtime/src/server/loader.ts`).

Generation FAILS (error names plugin, slot, component, module) when:

- Module file missing.
- Module lacks named export `component`.
- Main client entry also exports `component` (named, `export { X } from`, or `export *` resolving to module file).

Production build FAILS (vite `renderChunk`) when lazy module lands in registry's own chunk. Error lists static importers. Cause: eager code imports module.

Runtime:

- `lazyClaim(load, name)` in `packages/dashboard-plugin-runtime/src/lazy-claim.tsx`. Exported from runtime barrel.
- Memoized `React.lazy` keyed `(loader, name)`. Module fetched once per page.
- Render path: `SlotErrorBoundary > Suspense(fallback) > CurrentPluginLayer > Component`.
- Failed load contained to that claim. Siblings render.

Fallback per render site:

- `renderClaim` (`slot-consumers.tsx`): optional `fallback` arg, default `null`. `ContentClaimSkeleton` for `shell-overlay-route`, `content-view`.
- `renderPaneClaim` (`editor-pane-tab.tsx`): `null`.
- `ToolCallStep.tsx`: `null`.
- `CustomEntryRow.tsx`: default `CustomEntryCard`.

When to use:

- Lazy: surfaces opened on demand (settings, overlay routes, content views, editor tabs, command routes). Components ≳10 KB raw with exclusive deps.
- Eager: session-card badges/chips, predicates, catalogs, composer-inline claims, hot sidebar sections, small chat-history renderers (suspense gap visible).

Author rules:

- Do NOT export lazy component from plugin main client entry.
- Do NOT import `module` from eager code.
- Secondary heavy children: `lazy()` inside plugin. Example: automation `FolderAutomationSection` lazy-loads `CreateAutomationDialog`.

Compatibility:

- Plugin adopting `module` needs dashboard shipping this change. Set `engines`/peer floor to that dashboard version.
- Older dashboard ignores `module` → build fails `does not export`. Loud, not silent.
- Rollback: remove `module` from manifests. Restore barrel exports (main client entry re-exports `component`).

First-party adoption (lazy):

- settings-section: apple-tools, automation, blackhole, browser, chat-gateway, context-mode-settings, cost-estimator (+ CostView command-route), flows (FlowsSettings), flows-anthropic-bridge, goal, grammar, quota, roles, subagents, system-one.
- shell-overlay-route: AutomationBoard, AutomationRunMonitor, GoalsBoardClaim, GoalDetailClaim, KbSettingsClaim, FolderMcpPage, SubagentPopoutClaim.
- mcp-client: McpSettingsClaim (settings).
- blackhole: PipelineDetailView (content-view).
- browser: BrowserPaneTab (editor-pane-tab).
- flows: FlowDashboardClaim (content-header-sticky; pulls FlowGraph dagre/d3/lodash), FlowYamlPreviewClaim, FlowInputWiringClaim, FlowWriteToolRenderer.

## Trust boundary

"Private" means NOT observable and NOT forgeable — NOT authenticated.

- Wire `pluginId` claimed by the requesting code. Not verified against the socket.
- Any code in any of the user's pi sessions can call any plugin's handler.
- Handlers MUST treat every request as coming from "some session of this user"
  and authorize on the payload. Gmail lease authorizes by account level, e.g.
- Passive or other extensions can neither observe nor forge replies: a reply
  resolves a Promise held only by the caller.
- Malicious in-process pi extension OUT OF SCOPE. It shares the process and the
  user's filesystem, can read any `~/.pi` file, and can impersonate a plugin id.
- No encryption at rest. Plaintext 0600, same as `auth.json`.

## Fixture gate

`PI_DASHBOARD_FIXTURE_PLUGINS=1` gates plugins declared `fixture: true`.

- Server and bridge entries load only under the flag. Without it, a fixture
  bridge would auto-register into `~/.pi/agent/settings.json` and inject fixture
  tools into every pi session.
- Same flag keeps fixture CLIENTS in a production client build
  (`fixturePolicy: "included"`).
- Docker test harness sets it at build and runtime. Nothing else does.
- `packages/demo-plugin` is the worked example: `demo/echo` handler, fake login
  flow via `ctx.oauth.startFlow`, credential persisted via `ctx.credentials`,
  `demo_echo` bridge tool on the lane.
