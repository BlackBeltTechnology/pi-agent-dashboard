# research/agent-bash-sandboxing.md — index

Research dossier. Explore-mode, no change / no impl. Problem: path-gate gates pi `read`/`write`/`edit` only; `bash` spawns processes that bypass tool-level guard; command-string parsing unsound → enforce below shell. Four layers light→heavy: L1 just-bash (Vercel Labs, Apache-2.0, beta; TS bash emulator, `InMemoryFs` default, `OverlayFs` CoW over real dir with 100 MB `maxCopyOnWriteSize`, `ReadWriteFs` confined to `root`, no real binaries → poor fit for coding agent); L2 srt `@anthropic-ai/sandbox-runtime` (seatbelt macOS / bwrap Linux, proxy allowlist network, `denyRead`/`allowRead`/`allowWrite`/`denyWrite` with allowRead-beats-denyRead and denyWrite-beats-allowWrite, `SandboxViolationStore` + `commandId` attribution, beta, used by Claude Code); L3 AgentFS (Turso, MIT, beta; SQLite-backed upper layer, FUSE Linux / NFS macOS, `agentfs run /bin/bash` experimental, audit+undo not hard isolation); L4 containers/microVMs (general-knowledge names only, unverified). Comparison table: real binaries, bypass-proof, network, undo, macOS native, interactive-ask fit. pi example `examples/extensions/sandbox/index.ts` overrides `bash` via `registerTool` ("bash (sandboxed)") → `SandboxManager.wrapWithSandbox` → `spawn("bash",["-c",…])`; config `~/.pi/agent/extensions/sandbox.json` + `<cwd>/.pi/sandbox.json`; `--no-sandbox`, `/sandbox`, `user_bash` hook; `tool_call` input-mutation alternative. Hybrid verdict candidate: read/write/edit stay path-gate; bash = srt policy from same `GrantCache` store (`~/.pi/dashboard/access-grants.json`); srt violation → path-gate ask → grant → retry (post-hoc, not mid-command; mid-command needs L3 FUSE). Open: threat model, toolchain need, static-policy-retry vs blocking, Windows unverified. Next: spike pi example or OpenSpec proposal. Not decided.
