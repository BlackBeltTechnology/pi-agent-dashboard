Research dossier. Explore-mode, no change / no impl. CLM = Contrastive Language Models (Stanford/NVIDIA, Jacky Kwok et al., Apache-2.0, released 2026-09-24, PyPI `contrastive-lm` v0.1.0, repo `github.com/Contrastive-LM/CLM`): frozen Qwen3-8B backbone + ~20M-param trainable heads, InfoNCE contrastive, score = `scale·cos(state,action)` (`logit_scale` 100), states/actions embedded separately → option embeddings cacheable. Authors report on par with Jev on computer-use/gaming/tool-calling, up to 9× lower H100 latency, verifier SOTA DeepSWE 81.6% / Terminal-Bench 2.1 87.6%. Wire (`src/clm/server.py`, `embedder.py`, `pyproject.toml`): `clm-serve` FastAPI — `POST /v1/systemone` (Jev-compatible), `GET /v1/models`, `GET /health`, `POST /v1/rank` (extra primitive, not in Jev wire), playground `/` (`--no-ui`); flags `--host` default `0.0.0.0` (!), `--port` 8700 (`CLM_PORT`), `--emb-url` `http://127.0.0.1:8090/v1/embeddings` (`CLM_EMB_URL`), `--emb-model qwen3-8b`, `--max-tokens` 2048, `--ckpt`/`CLM_CKPT`, `--device`, `--action-cache`, `--no-download`, `--cors`; auth optional `CLM_API_KEY`; client `CLMClient` reads `CLM_BASE_URL`/`CLM_API_KEY`. Two processes: `clm-serve` needs separate OpenAI-compatible `/v1/embeddings` encoder — upstream `vllm serve Qwen/Qwen3-8B --served-model-name qwen3-8b --runner pooling --enable-prefix-caching --max-model-len 2048 --port 8090`, Linux + NVIDIA GPU. Encoder contract: `Qwen/Qwen3-8B` (NOT Embedding-8B), raw text, no chat template/BOS/EOS, last-token pooling after final RMSNorm, 4096-dim, L2-normalised; >2048-token states silently truncated keeping FIRST 2048 (raise via `--max-model-len` + `--max-tokens`); RealityCat notes heads trained on LAST tokens → tail truncation possibly better; `pyproject` hard-depends `vllm>=0.6` + torch → Mac install needs vllm excluded (uv `--no-deps`), unverified; head runs on CPU, only encoder GPU-bound.
