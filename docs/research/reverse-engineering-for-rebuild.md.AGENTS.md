Research artifact. Web research: code -> spec -> clean-room rebuild (builder never sees source). Gap vs `reverse-spec-from-code`: existing skill = kb-searchable OpenSpec, observable behavior, 3-8 reqs, auditor blocks hallucination not omission; rebuild needs data shapes, business rules as rules, state machines, exact contracts, depended-on quirks. Fitness = round trip: extract -> spec -> blind builder; characterize -> black-box conformance suite on both; original passes + rebuild fails => spec gap. Sources: MirrorCode (arXiv 2606.30182; execute-only CLI rebuild, Opus 4.7 56%, hidden duals ~34%, failure modes edge cases/overfit/untested req/premature submit), AgentModernize (arXiv 2605.17535; BSG nodes w/ `source_location`+`confidence`, explicit vs implicit rules, 92.3% recall, bottleneck codegen), Reversa (arXiv 2605.18684; claims+gaps+Gherkin parity, COBOL ATM -> Go), abstract-only: From Code to Requirements, ACL 2026 COBOL/PL/I, COBRAIN, SpecGen, SpecRover, RepoZero. Tools: Thoughtworks blackbox (rebuild prototype as validator), greenfield (closest analog, L1-L7 + gates, sanitization, test vectors, provenance), CodeCartographer, DDS, characterization tests/golden masters. Best practices: behavior not structure, file:line citations, confidence + gaps, explicit/implicit tags, executable acceptance, hidden duals, per-phase gates, deterministic IR first, build-order plan. Implications (undecided): existing skill ~= greenfield L1-3; candidate skills `reverse-discover`/`reverse-extract`/`reverse-characterize`/`reverse-rebuild-check` or `--mode rebuild`; option fork greenfield. Open Qs: target langs, rebuild stack, output unit, round-trip in v1, quirk policy.
