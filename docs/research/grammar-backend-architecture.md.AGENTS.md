# research/grammar-backend-architecture.md — index

Architecture decision record. Composer "writing" backend: LanguageTool (Java) vs LLM vs hybrid. Status: OPEN — undecided. Offline backend already IS LanguageTool (Java server): ~25 ms, offline, deterministic, i18n en/hu, extensible XML/Java custom rules, n-gram confusion data, `disabledRules`, `motherTongue`; gap = no LLM rewrite. Options: A LanguageTool primary (fast, deterministic, offline; no rewrite); B LLM haiku (grammar + writing improvement, ~2–4 s, per-token cost, non-deterministic, prompt-hardened); C Hybrid (LT live check-while-typing instant, LLM behind manual "improve writing" — best UX/cost, needs per-trigger backend + settings/UI). 5 open questions: correctness-vs-rewrite fork; stock `erikvl87/languagetool` vs custom Java service + ownership; offline/privacy (LLM sends draft off-box); bundle/auto-start LT (non-goal) vs bring-your-own; coordinate `add-grammar-correction-eval` GEC scorer for objective comparison. Recommended first step: land GEC harness, score LT vs haiku on one dataset, decide on evidence. Cross-refs docs/grammar-checker.md, docs/grammar-model-guidance.md.
