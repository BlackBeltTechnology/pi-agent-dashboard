# research/bridge-transport-and-identity.md — index

Research dossier. Explore-mode, no change / no impl. Question: bridge↔server (pi node ↔ dashboard) use P2P instead of WebSocket? Verdict: no — pain is (1) unauthenticated name→endpoint indirection + (2) absent peer identity, not the transport. Driver: WS fragile + discovery headaches; planned remote-join. ~18 openspec changes / 5 months on this one connection → 4-class root-cause taxonomy: class 1 endpoint ambiguity (unauth name→endpoint resolves wrong; P2P dial-by-key dissolves), class 2 peer identity (transport gives none; server reconstructs from self-reported pid+cwd+token, priority token > pid > cwd, `pi-gateway.ts`; P2P dissolves), class 3 application protocol (ordering/drops/state restore; P2P fixes nothing), class 4 lifecycle races (untouched). Seam: bridge thin (`ConnectionManager` `WebSocketImpl?: any`, ~9 members: new WS/send/close/onopen/onmessage/onclose/onerror/readyState===1); server thick (`ws.ping()`/`'pong'` contention liveness oracle in `bridge-contention.ts`, `terminate()`, `wss.clients`, 4-state readyState). Decisive experiment: WS over unix socket (`ws+unix:///path.sock:/` + `WebSocketServer({server})` over `http.createServer().listen(sockPath)`) — ping/pong, readyState, wss.clients.size, terminate all survive; `chmod 0600` = owner-only auth; transport swap needs ZERO protocol change, unlike iroh (would force re-founding liveness oracle). Failure-mode inversion: stale socket fails loud (ENOENT/ECONNREFUSED immediate); stale mDNS advert fails silent (connects to real live WRONG server, 23h reconnect-loop). `server-auto-start.ts` `PI_DASHBOARD_NO_MDNS` quote: co-located mDNS advert overrides explicit `PI_DASHBOARD_URL` — remote-join broken today despite `PI_DASHBOARD_URL` existing (`bridge.ts:725`). Security: `:9999` pi gateway NO auth (`grep token|auth|secret pi-gateway.ts` → comments only; "is not a claim about the gateway port's own authentication"); not loopback-pinned — `piGateway.start(config.piPort, config.host)` follows `--host`/`PI_DASHBOARD_HOST`, docker `EXPOSE 8000 9999`, `.env.example` bind `0.0.0.0` ⇒ reach :9999 = register any sessionId, displace live bridge, receive send_prompt/set_model. `:8000` contrast: OAuth + `bearer-auth.ts` + network guard + CORS + CSP + `ws-ticket.ts` + Ed25519. Reuse candidates: `openspec/specs/server-identity-keypair` (persistent Ed25519, fingerprint stable across URLs, nonce challenge, pin + detect impostor = identity==address); `pairing/pairing.ts` + `paired-devices.ts`; `bearer-auth.ts`; `ws-ticket.ts` (`WsRouteScope` = browser|terminal|live — no bridge scope); `home-lock.ts` (one dashboard per `<canonicalHomedir>/.pi/`, stable per-instance `identity` vs `/api/health`). Selection: HOME already the selector; socket via `dashboard-paths.ts` `getDashboardConfigDir` → `~/.pi/dashboard/`, `homedir` test seam; temp-HOME isolation already works. Decision: enforce one dashboard per HOME; escape `PI_DASHBOARD_SOCKET`; `instances/<identity>.sock` + ladder = additive future option. Options matrix (kills class 1/class 2/cross-host/native dep/darwin-x64): UDS wins local; signed handshake over existing WS = remote half; Tailscale + ZeroTier already in `GATEWAY_PROVIDERS` (`gateway-providers.ts`) so substrate-P2P already ships. Only QUIC gives connection migration surviving client IP change — cross-host only. Verdict: fix local = HOME-derived rendezvous + platform-appropriate transport, unchanged WS protocol; remote = bridge as paired device (new `bridge` ws-ticket scope) + pin server Ed25519 fingerprint. Captured: openspec change `add-pi-gateway-transport-identity`. Local split: POSIX unix socket mode 0600 kernel auth; Windows `ws://127.0.0.1:<piPort>` + local-token (`ensureLocalToken`/`verifyLocalToken`, `X-Pi-Local-Token`), listener loopback-pinned; named pipes rejected (flat machine-global namespace → hash name, security descriptor not chmod, native code). Rendezvous record already exists: `home-lock.ts` `LockMetadata {httpPort, piPort, identity, pid, ppid, startedAt, version, url, hostname}` + `getMetaPath`/`readMetadata`/`writeMetadataAtomic`. New finding: chmod no-op on Windows (`local-token.ts:36`, `paired-devices.ts:78`) — owner-only of `local/token`, `identity.key`, `paired-devices.json` rests on inherited NTFS profile ACLs, assumed never verified; test on real Windows, `qa/tests/windows-nsis-*.ps1`. Asymmetric guarantee: `--host 0.0.0.0` exposure unrepresentable on POSIX (nothing listens), survivable on Windows (listener + token guard). Open Q: mixed-version rollout, docker split topology, cwd asymmetry from `fix-bridge-mdns-migration-hijack`, how much Class-2 correlation machinery dies once bridges have crypto identity, is `~/.pi/dashboard/local/token` unreadable by a second OS user on Windows.
