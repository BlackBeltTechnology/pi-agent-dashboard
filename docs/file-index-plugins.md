| `packages/flows-anthropic-bridge-plugin/package.json` | **NEW** workspace package `@blackbelt-technology/pi-dashboard-flows-anthropic-bridge-plugin`. Plugin id `flows-anthropic-bridge`, priority 500. Manifest declares `client` + `server` + `bridge` + `configSchema`. Slot claim: `settings-section` general tab → `FlowsAnthropicBridgeSettings`. Bridge entry peer-probes `@pi/anthropic-messages` + `pi-flows` via `createRequire(cwd).resolve` + `pi.events.listenerCount("flow:register-agent-extension")` fallback; both-present → `await piAnthropicMessages(pi)` + `pi.events.emit("flow:register-agent-extension", { factory })` so every spawned flow agent gets same hooks; re-probes on every `session_start`; states `probing | waiting_peers | active | degraded`; broadcasts `flows-anthropic-bridge:status` + `flows-anthropic-bridge:agent-active` on pi event bus. Server entry: `GET /api/flows-anthropic-bridge/status` returns last-known per-PID snapshots; subscribes to `flows-anthropic-bridge:*` when host runtime exposes them, broadcasts `flows_anthropic_bridge_status` + `flows_anthropic_bridge_agent_active` to subscribers. Client entry: settings panel renders peer status table per pid + Refresh button hitting REST endpoint; `forceCanonical` / `disableCanonical` toggles map to `PI_ANTHROPIC_MESSAGES_FORCE_CANONICAL` / `PI_ANTHROPIC_MESSAGES_DISABLE_CANONICAL` env vars consumed by `@pi/anthropic-messages`. Both peers runtime-only — NOT in package.json deps (intentional: plugin idle when missing). Registered in `vitest.config.ts` projects array. |
