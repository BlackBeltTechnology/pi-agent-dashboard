## Why

`chat-gateway-multi-guild` (A) gives each Discord server a `mode`, but a `query` server can only refuse: every `!` command gets `Refused: query_mode.` Operators want a request-only bot. It should answer questions about dashboard sessions, search and summarize what was said in the server's channels, and give that server's admins a few management commands and reports, all without ever starting, driving or mirroring a session there. The gateway keeps no message history today, so there is nothing to search. Some limits used by chat replies are still hardcoded (`LIST_LIMIT = 25`).

Change B of the stack A → B (`chat-gateway-query-mode`), A → C, A → D. It consumes A's contract verbatim.

## What Changes

- **Read commands in both modes.** `!sessions`, `!status [n|id]`, `!show <n|id> [turns]`, `!search <terms> [in:#channel] [from:@user]`, `!ask <question>`. They match a closed grammar (a reference is a positive integer or a hex id prefix of at least 8 characters, so one-word steer text is never swallowed) and are answered in `interactive` and `query` servers alike, never delivered to a bound session as prompts (`!search`/`!ask` free text, in an `interactive` server, only where no binding resolves). In a direct message only the session verbs answer, binding-only; server and admin commands are dropped. Session verbs authorize with the binding's tier inside a binding of an `interactive` server and through A's `team.authorizeServerRequest` otherwise (every verb in a `query` server, whose bindings are dormant); server verbs always through it. Session reads in a channel without a binding see only the workspaces the operator lists (`query.workspaces`, default none); bound channels keep today's bound-workspace scope. `query.workspaces` holds live dashboard workspace ids (an unresolvable or folderless one adds nothing, never `allowedRoots`). `!show` reads assistant text turns from the host event store (user turns only with `query.showUserTurns`) and is not posted in a channel `@everyone` can view unless the operator allows it (`query.transcriptRepliesPublic`). Any other `!` command in a `query` server keeps A's `Refused: query_mode.` `!disarm` is A's per-server latch (observe+) and is not changed here.
- **`!ask`** is on by default but needs the per-server setting `query.askModel` (`provider/modelId`). It retrieves matching indexed messages the asker may view and makes **one in-process model call** through the plugin server context's `modelRuntime` (`streamSimple`, verified present, no host change). It starts no session and gives the model no tools, extensions or MCP. A timeout, token cap and concurrency caps bound it, and channel content goes in as nonce-delimited, JSON-encoded **untrusted data**.
- **Persisted local message index** (new capability). It is opt-in per server (`index.enabled`, default off) and covers only the channels listed in `index.channels`. Bots, webhooks, DMs and private threads are excluded. Segments are per day, mode 0600, and written atomically. Retention is set in days and the size cap in bytes. Edits replace the indexed text of an existing entry only (an edit never inserts, and an edit into a command removes the entry), deletes remove it, and capture continues while the server is disarmed. Removing the server, disabling the index or removing a channel purges that data. Backfill through Read Message History is optional and off by default. Search and ask return only messages from channels the requester can view and that are also readable by the reply audience (the invoking channel or `@everyone`).
- **Admin chat commands** for per-server gateway admins, in either mode: `!mode interactive|query`, `!bind <#channel>` / `!bind remove <#channel>` (the server's channel opt-in), `!config show` (a fixed projection that never includes secrets or ids), and `!report channels|members|activity` (index aggregates only, never the command log; not posted in channels `@everyone` can view unless the server allows it). `!disarm` keeps A's per-server semantics. Chat config writes reuse A's record-level patch lane (no revision from chat, same write queue, so a stale dashboard tab gets `revision_changed` instead of reverting them) and are refused while the server is still `legacy` or when they would remove the last channel.
- **Member report** needs the privileged Server Members intent. A new top-level `discordIntents.guildMembers` setting (default `false`, restart required) controls it. With the setting off, the report shows only the approximate member count.
- **Replies** suppress mentions and link embeds and are capped in message count. Any elision is marked explicitly.
- **Limits are settings.** `0` = unlimited applies throughout (A's convention). `LIST_LIMIT` becomes `limits.listRows` (default 25). The new `limits.indexFlushMs`, `limits.indexSweepMs`, `limits.maxAskCalls` and `limits.askDisarmPollMs` (how often an in-flight ask checks the disarm latch) sit next to it (all written through A's `patchLimits`), and the rate limit window is `query.rateWindowSec`. No setting has a schema `default` (the host would persist it); defaults live in code. A caller value never lifts a nonzero operator cap, and `0` = unlimited composes by one rule. The per-server `query.*` and `index.*` counts, sizes and durations are settings too. Discord's 2000-character message limit is a platform fact.

## Capabilities

### New Capabilities
- `chat-gateway-query-mode`: read commands, transcript audience gate, command-log ring eviction of read entries, `!ask` posture, rate and reply bounds, admin chat commands, `!config show`, admin reports, per-server query settings.
- `chat-gateway-message-index`: opt-in capture, storage, retention and size cap, edit/delete handling, purge, backfill, visibility-filtered search.

### Modified Capabilities
- `chat-gateway-guilds` (added by A): `Query-mode servers refuse interactive actions`, where the placeholder refusal now applies only to commands B does not answer (A's disarm sentence and scenario are kept), and `Live server configuration write`, which now also admits the two chat fields from a server's gateway admins.
- `chat-gateway`: `Reach dashboard sessions from chat` (the row cap is now `limits.listRows`, `!sessions` is answered in `query` servers, and the read commands match a closed grammar in both modes) and `Configuration surface` (query/index settings, index stats, the members-intent toggle). B no longer touches the tool-policy or hidden-session requirements: `!ask` spawns no session.
- `chat-gateway-audit`: `Append-only command log` gains one carve-out: commands refused by the per-user command rate limit are logged once per burst (`command_rate_limited`), not once per command.
- `chat-gateway-tier-authorization`: `Tier resolution from chat identity` adds the six server-scoped verbs (A ships `disarm`) that resolve from the server record even inside a binding. `Verb tiers come from the dashboard's shared effective-tier table` gains the new chat-local verbs. `Configuration is editable only from the dashboard` gains the admin exception for a server's `mode` and channel opt-in.

## Discipline Skills

- `security-hardening`: covers the untrusted channel content fed to a model, the structurally tool-less in-process call and the data egress to the model provider, the cross-channel visibility leak through search, and the chat-initiated config writes (`!mode`, `!bind`). `!config show` must never print secrets, and mention/embed spam must be suppressed.
- `performance-optimization`: the index write path (batched atomic segment writes), the search scan over segments without blocking the event loop, and the retention/size sweeps.
- `observability-instrumentation`: new background jobs (flush, sweep, backfill) and new outcomes (ask ok/no_match/timeout/busy/model_unset/model_unavailable, index capture/drop/purge) are counted and surfaced on the server row.
- `doubt-driven-review`: a chat-initiated `!mode interactive` escalates what the server can do. The purge rules are irreversible.
- `review-code`: before commit.

## Impact

- Code: `packages/chat-gateway` only. Files touched: `src/configSchema.json`, `src/shared/types.ts`, `src/server/{config,guilds,gateway,index,seam}.ts` (`seam.ts` gains an optional `complete` over `ctx.modelRuntime` and an optional `readTurns` over `ctx.eventStore`), the new `src/server/query/` (commands, ask, reports) and `src/server/index-store/` (message index), `src/server/team/{tier,authorize,surface}.ts`, `src/adapters/{base,discord,fake}.ts` and `src/client/ChatGatewaySettings.tsx`. No core, bridge or protocol change. The manifest `priority` stays at 100.
- Discord: no new intent by default. `GuildMembers` is used only when the operator opts in; if the Portal switch is off the adapter retries without it. Read Message History is needed only for backfill.
- Data: new `~/.pi/dashboard/chat-gateway/index/` (0700 dir, 0600 files). `!ask` writes nothing.
- Privacy: `!ask` sends retrieved message text to the provider of `query.askModel`; a local model keeps it on the machine.
- Docs: `docs/chat-gateway.md` (via DocScribe) and the `packages/chat-gateway/**/AGENTS.md` rows.
- Ceiling: `!ask`, `!mode` and `!bind` need tier `control`; with the default global ceiling `observe` they are refused until the operator raises it.
- Rollback: older versions ignore the new keys, and A-only versions must tolerate the reserved keys (design §Rollback). Index files are left on disk unswept, and the manual purge is documented.
