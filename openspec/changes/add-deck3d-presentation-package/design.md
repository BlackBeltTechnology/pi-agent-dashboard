## Context

See proposal.md — Why. Everything below was prototyped in `openspec/changes/add-deck3d-presentation-package/mockup/deck3d-strategy-lab.html` (single-file, three.js r16x via CDN ESM, mermaid v11 ESM, opentype.js, Poppins-Bold TTF from Google Fonts CDN). The lab already exports a `deck.json` and persists per-slide overrides in `localStorage` — that export is the seed of the IR.

Constraints that shape the design:
- **Deterministic converter code, LLM tunes the result** (user requirement). Determinism must be provable (byte-identical outputs); tuning must be lossless across re-parse.
- Mermaid harvest needs a browser (mermaid renders through DOM/SVG; dagre layout reads bounding boxes). Output must not need one.
- Hungarian glyphs: every three.js `typeface.json` font ships corrupt double-acute outlines (`ő ű Ő Ű` → earcut failures). Only a real TTF through opentype.js works.
- Package shape precedent: `packages/video-production` (TS engine + `pi.skills` + bin + vitest).

## Goals / Non-Goals

**Goals:**
- Two-stage pipeline with a schema-validated IR in the middle; `overrides` as the only user-writable region.
- Port the lab's proven visuals (materials, floor, bloom, scenes, builders, label treatment) into tested TS modules.
- Fixture-driven determinism tests (IR and HTML byte-equality).

**Non-Goals:**
- Live editing UI / configurator in the output (the lab's gear panel stays in the lab).
- Diagram types beyond flowchart + sequence (class, state, ER, gantt → warn + `none`).
- PPTX export or import; the existing python-pptx pipelines are separate.
- Image generation for reference plaques (the lab's "builder reads this image" idea) — content illustration comes from glTF props (D7), not 2D images.
- Automatic prop selection by code (keyword → model heuristics). Selection is the LLM's job by design; code only searches, fetches and renders.
- Sketchfab and Objaverse as sources (OAuth / licence noise) — candidates for a follow-up.
- Dashboard UI integration (preview card for `.deck3d.html`) — later change if wanted.

## Decisions

### D1 — IR in the middle, `overrides` as the single tuning region
`deck.json` = `{ meta, defaults, slides[], overrides }`. `slides[]` and everything under it are **derived** (regenerated by parse). `overrides` is keyed: `overrides.deck`, `overrides.slides[<slideId>]`, `overrides.nodes[<slideId>/<nodeId>]`, `overrides.edges[...]`. Parse = derive → deep-merge overrides → validate. Render reads the merged view.
- *Why*: a single place the LLM may write means re-parse can never clobber tuning, `validate` can warn on writes elsewhere (diff against a fresh derive), and diffs of `overrides` are a readable log of what the agent changed.
- *Alternatives*: (a) let the LLM edit anything in the IR — simplest, but a markdown edit + re-parse silently loses the tuning; (b) tuning via CLI flags — not expressive enough per-node; (c) tuning by editing the HTML — undiffable, unrepeatable.

Slide ids = slugified title + ordinal on collision; node ids = mermaid node ids (author-chosen, stable); message ids = `m<index>`.

### D2 — Harvest in headless chromium at parse time, never at view time
`parse` spins Playwright chromium, loads a tiny harness page bundling mermaid@11 (exact pin), runs `mermaidAPI.getDiagramFromText` → `db` (semantics) and `render` → SVG (layout), samples edge paths with `getPointAtLength`, returns the graph IR. The harness matches node elements by id `<renderId>-flowchart-<nodeId>-<n>` and edge paths by `id^=L_<from>_<to>` (the v11 scheme — pinned and fixture-guarded).
- *Why*: no parser/layout of our own; mermaid's own semantics; dagre layout identical to what the author sees in 2D.
- *Alternatives*: (a) `mermaid` in Node via jsdom — dagre needs real `getBBox`, jsdom lacks it; (b) our own parser + elkjs — large, diverges from mermaid's semantics; (c) harvest at view time — makes the output network-dependent and non-deterministic.

Playwright is already a dev dependency of the repo (`tests/e2e/`); `parse` reuses the installed chromium and prints the install command when missing.

### D3 — Renderer is a template + bundled runtime + inlined IR
`render` writes `deck.html` = fixed template + `<script type="module">` containing an esbuild-bundled runtime (three.js, opentype.js, our builders) + `window.__DECK = <IR JSON>` + base64 subset Poppins TTF. Determinism: bundle built once at package build (`dist/runtime.js`), subset font is a pure function of the glyph set, JSON serialised with sorted keys. No dates, no random.
- *Why*: single file, offline, byte-identical. The runtime is the lab's code split into modules.
- *Alternatives*: (a) CDN imports like the lab — not offline, not deterministic across CDN changes; (b) server-side render to video — loses interactivity, huge.

Runtime modules (all ported from the lab): `text/` (opentype → ShapePath → ExtrudeGeometry; canvas label with `P.bg` outline), `materials/` (glass/metal/matte PBR, palette), `scene/` (floor, fog, bloom, key/fill/rim, shadow bias), `backgrounds/` (scene library keyed by slide semantics), `builders/` (`flowchart`, `sequence`, `brain`, `loop`, `swarm`), `camera/` (rail/dolly, hash deep-link, cull neighbours), `loop.ts` (rAF with `setTimeout` fallback when `document.hidden`).

### D4 — Labels: canvas + inverted outline; titles: extruded
Diagram labels are `CanvasTexture` planes, Poppins 700 via `FontFace` from the same TTF buffer, filled `P.text`, stroked `P.bg` at 18 % of size, `MeshBasicMaterial{toneMapped:false, depthWrite:false}`, offset in front of the node surface (`h/2` for round shapes). Titles stay extruded + bloomed as the hero element.
- *Why*: extruded small text blooms and becomes unreadable (user feedback); unlit + outline is legible on any material in both modes.

### D5 — Package layout
```
packages/deck3d/
  package.json            @blackbelt-technology/pi-dashboard-deck3d, bin: deck3d, pi.skills
  .pi/skills/deck3d/SKILL.md   + reference/ir-fields.md (generated from schema)
  src/cli.ts              parse | validate | render | build | check | snapshot
  src/check/              rules.ts (pure), run.ts (Playwright driver), report.ts
  src/ir/schema.json      JSON Schema (ajv), src/ir/merge.ts (overrides), src/ir/ids.ts
  src/parse/markdown.ts   deck grammar → slides
  src/parse/harvest/      playwright harness + mermaid bundle
  src/render/index.ts     template + inline runtime + font subset
  src/runtime/            three.js modules (D3)
  assets/Poppins-Bold.ttf (OFL)
  assets/props/           vendored CC0 GLBs + manifest.json + LICENSES
  src/props/              search.ts (polypizza, vendored), fetch.ts (hash, caps), generate.ts (gradio_client shim), restyle.ts
  fixtures/               strategy-lab.md → expected deck.json + expected deck.html hash
  test/                   vitest: determinism, schema, harvest (needs chromium; skipped when absent), grammar
```
`ir-fields.md` is generated from `schema.json` `description`s by a build script — one source of truth for the LLM's knob reference.

### D7 — Content-related props: LLM picks, code fetches/pins/renders
Sources v1: **Poly Pizza** REST (`https://api.poly.pizza/v1.1/search`, free key in `POLY_PIZZA_KEY`, CC0/CC-BY low-poly, direct GLB download URLs); **vendored CC0 subset** of Kenney + Quaternius packs under `assets/props/` with `manifest.json` (name, tags, tris, bytes) — offline, most style-consistent, searched first; **generate fallback** via HF Space `tencent/Hunyuan3D-2` `/shape_generation` through `gradio_client` (python3 optional dep; geometry only, so `restyle: palette` forced). Search = text match on name/tags; no embedding model — the LLM reads the candidate table and picks.

IR: `overrides.props[]` (see spec). Cache: `.deck3d/props/<source>-<id>.glb` beside the deck, sha256 pinned in the override; `render` verifies hash → determinism holds (IR + cache → same HTML). Runtime: `GLTFLoader` + meshopt decoder, `Box3` normalise to `size`, ground to floor, `lookAt` camera yaw; `restyle: palette` traverses meshes and swaps materials for the deck's PBR (`metal` for hard-edged, `matte` default; glass never — reads noisy). Roles: `hero` (right of title block), `illustration` (empty region opposite bullets, computed from bullet panel bbox), `ambient` (N instances drifting in the background scene, `InstancedMesh`), `node:<id>` (replaces the flowchart primitive; label + edge endpoints keep the node's bbox). Anim presets are small functions of `t` on the prop group. Credits slide generated at render for any non-CC0/non-generated licence.
- *Why*: reuse of thousands of consistent CC0 models beats generating; hash-pin keeps determinism; roles avoid free-form 3D placement in JSON.
- *Alternatives*: (a) code picks props by keyword heuristics — brittle, and contradicts "LLM tunes"; (b) embed a text-embedding search — heavier than value for ≤20 candidates the LLM can read; (c) 2D image plaques — flat in a 3D scene.
- Security: downloads restricted to `.glb|.gltf` MIME/magic, size cap, cache names from `source+id` slug only (no URL-derived paths), no glTF extensions that execute (none exist, but `KHR_*` allowlist anyway).

### D8 — `check`: measure the scene graph in a browser, not the pixels
The deck exposes `window.__deck3d` (`gotoSlide`, `setTime`, `ready`, `measure`, `peaks`). `measure()` walks the slide's objects, projects each labelled thing's `Box3` to CSS px and reports label cap height exactly (labels are canvas planes with known world height) plus a camera→label raycast. The CLI (`src/check/`) runs Playwright headless at dpr 1, per viewport, per slide, at `t=0` and each animation peak, and applies pure rules: fit vs 4 % safe margin, legibility ≥ 14 px @1080 (scaled), overlap IoU > 0.1, occlusion, contrast ≥ 3:1 from a cropped `toDataURL` of the pixels behind the label. Findings carry severity + a suggested `overrides` key (`slides[n].diagram.scale|offset`, `slides[n].camera.distance`, `slides[n].labels.size`) so the LLM's fix is one edit. `build` runs it (fail only with `--strict`). Same IR + viewport ⇒ same report (deterministic clock; no rAF timing in the measurement path).
- *Why*: OCR/pixel-diffing is flaky and can't attribute a problem to an object; the scene graph knows every label's world box. Contrast is the one rule that needs pixels because backgrounds are animated scenes — sampled at the deterministic clock so it's stable.
- *Alternatives*: (a) OCR screenshots — slow, non-deterministic, no object attribution; (b) LLM-only visual review — keeps working alongside, but cannot reliably see 9 px text or 3 % spill; (c) static layout math without a browser — misses projection/occlusion/contrast, and the harness already has Playwright.

### D6 — Quality tiers
`defaults.quality` ∈ low|medium|high toggles bloom, mirror reflector, shadow map size, particle count. Default `high`. Also overridable per slide.

## Risks / Trade-offs

- [mermaid id scheme changes on upgrade] → exact pin + one fixture per diagram type asserting node count and first node found; bump is a deliberate change.
- [Harvest needs chromium; CI runners without it] → tests mark harvest suites `skipIf(!chromium)`; `parse` fails with install hint; `render`/`validate` never need a browser.
- [HTML byte-equality is brittle to bundler nondeterminism] → esbuild with fixed options and no hashes; fixture stores a hash, test diffs on failure.
- [IR grows into a second programming language] → schema stays small; anything needing logic becomes a named `scene`/`builder` in code, not a JSON expression. Rule in SKILL.md: if you need a knob that isn't there, propose a schema field, don't hack HTML.
- [Subset font misses a glyph added by an override] → glyph set is computed from the merged IR at render time, not from markdown.
- [Large output (~1.5 MB with three.js + font)] → acceptable for a deck; `low` quality does not shrink code, only runtime cost.
- [Mixed prop styles look cheap] → vendored set searched first; `restyle: palette` default; skill tells the LLM to prefer one pack per deck.
- [Poly Pizza API changes / key missing] → source is optional; offline vendored set always works; API response parsed defensively with a fixture.
- [Hunyuan3D quota / server errors] → fallback only, fails loud with retry hint; never on the render path.
- [Prop binaries bloat HTML] → size cap per prop + budget warning; meshopt compression at render.
- [`check` false positives on intentionally cropped hero elements] → per-slide `check.ignore: [ids]` override, reported as `skipped` so nothing is silent.
- [Contrast sampling varies with animated backgrounds] → sample at deterministic `setTime`; rule uses mean luminance over the label rect.
- [LLM edits derived fields anyway] → `validate` diffs merged IR against fresh derive; warns with the JSON paths.
