## Context

See proposal.md — Why. Everything below was prototyped in `openspec/changes/add-deck3d-presentation-package/mockup/deck3d-strategy-lab.html` (single-file, three.js r16x via CDN ESM, mermaid v11 ESM, opentype.js, Poppins-Bold TTF from Google Fonts CDN). The lab already exports a `deck.json` and persists per-slide overrides in `localStorage` — that export is the seed of the IR.

Constraints that shape the design:
- **Deterministic converter code, LLM tunes the result** (user requirement). Determinism must be provable (byte-identical outputs); tuning must be lossless across re-parse.
- Mermaid harvest needs a browser (mermaid renders through DOM/SVG; dagre layout reads bounding boxes). Output must not need one.
- Hungarian glyphs: every three.js `typeface.json` font ships corrupt double-acute outlines (`ő ű Ő Ű` → earcut failures). Only a real TTF through opentype.js works.
- Package shape precedent: `packages/video-production` (TS engine + `pi.skills` + bin + vitest).

## Goals / Non-Goals

**Goals:**
- Two-stage pipeline with a schema-validated IR in the middle; `overrides` as the only user-writable region.
- Port the lab's proven visuals (materials, floor, bloom, scenes, builders, label treatment) into tested TS modules.
- Fixture-driven determinism tests (IR and HTML byte-equality).

**Non-Goals:**
- Live editing UI / configurator in the output (the lab's gear panel stays in the lab).
- Diagram types beyond flowchart + sequence (class, state, ER, gantt → warn + `none`).
- PPTX export or import; the existing python-pptx pipelines are separate.
- Image generation for reference plaques (the lab's "builder reads this image" idea) — content illustration comes from glTF props (D7), not 2D images.
- Automatic prop selection by code (keyword → model heuristics). Selection is the LLM's job by design; code only searches, fetches and renders.
- Sketchfab and Objaverse as sources (OAuth / licence noise) — candidates for a follow-up.
- Dashboard UI integration (preview card for `.deck3d.html`) — later change if wanted.

## Decisions

### D1 — IR in the middle, `overrides` as the single tuning region
`deck.json` = `{ meta, defaults, slides[], overrides }`. `slides[]` and everything under it are **derived** (regenerated by parse). `overrides` has exactly one grammar (schema-enforced; unknown keys rejected):

```
overrides: {
  deck:    { ...defaults fields... },                       // deck-level knobs
  effects: [{ id, params? }],                               // deck-level effect list (replaces defaults)
  props:   [{ source, id, licence, author, sha256, slide, role, size, count?, restyle, anim }],
  slides:  { "<slideId>": { mode?, scene?, camera.distance?, diagram.scale?, diagram.offset?, labels.size?, quality?, check.ignore?, effects? } },
  nodes:   { "<slideId>/<nodeId>": { shape?, position?, size?, material? } },
  edges:   { "<slideId>/<edgeId>": { kind?, material? } }
}
```
Every path the tooling names — `check` suggestions, skill scenarios, field reference — is spelled in this grammar (`overrides.slides["<slideId>"].labels.size`, never a derived `slides[6]…` path). Merge rule: objects deep-merge over derived values, **arrays replace** (an `effects` or `props` list in overrides is the whole list). Parse = derive → apply overrides → append derived `credits` slide when any prop licence requires attribution (id `credits`, always last, so the deep-link count stays in the IR) → compute `meta.derivedHash` (sha256 of the canonical derived fields) → validate. Render reads the merged view; `validate` recomputes `derivedHash` from `slides[]` and warns "edited outside overrides" on mismatch — no markdown needed. Dangling *override* targets (slide/node/edge id gone) are **warnings** (kept, inert, named); dangling references inside *derived* data (edge to a missing node) are **errors**. `validate` on unmodified parse output therefore exits 0 with warnings only when orphans exist, and `build` never fails on an orphan.
- *Why*: a single place the LLM may write means re-parse can never clobber tuning, `validate` can warn on writes elsewhere (diff against a fresh derive), and diffs of `overrides` are a readable log of what the agent changed.
- *Alternatives*: (a) let the LLM edit anything in the IR — simplest, but a markdown edit + re-parse silently loses the tuning; (b) tuning via CLI flags — not expressive enough per-node; (c) tuning by editing the HTML — undiffable, unrepeatable.

Slide ids = slugified title (ASCII-folded; `ő→o`, empty → `slide`) + `-<ordinal>` on collision; an author may pin one with `# Title {#my-id}`, which wins and is stable across renames. Parse warns on every orphaned slide override and suggests pinning `{#id}`. Node ids = mermaid node ids (author-chosen, stable); edge ids = `<from>-><to>#<k>` with `k` the ordinal among parallel edges of the same endpoints in source order (stable unless parallel edges are reordered — mermaid's `L_a_b_N` render counters are never used as ids); message ids = `m<index>`.

Markdown inline overrides (`<!-- deck3d: {...} -->`, front-matter) are source of truth: parse writes them into `overrides` and they **win** over a `deck.json` value on the same key, with a warning naming the clobbered key — the agent moves a tuned value into markdown to make it permanent.

### D2 — Harvest in headless chromium at parse time, never at view time
`parse` spins Playwright chromium, loads a tiny harness page bundling mermaid@11 (exact pin), runs `mermaidAPI.getDiagramFromText` → `db` (semantics) and `render` → SVG (layout), samples edge paths with `getPointAtLength`, returns the graph IR. The harness runs mermaid with `htmlLabels: false`, `securityLevel: 'strict'`, embeds the same Poppins TTF as `@font-face` for label metrics, and matches node elements by id `<renderId>-flowchart-<nodeId>-<n>` and edge paths by `id^=L_<from>_<to>` (the v11 scheme — pinned and fixture-guarded). Determinism claim is scoped to the pinned Playwright chromium build (dagre sizes nodes from `getBBox` text metrics); the fixture test asserts byte-equality on that build.
- *Why*: no parser/layout of our own; mermaid's own semantics; dagre layout identical to what the author sees in 2D.
- *Alternatives*: (a) `mermaid` in Node via jsdom — dagre needs real `getBBox`, jsdom lacks it; (b) our own parser + elkjs — large, diverges from mermaid's semantics; (c) harvest at view time — makes the output network-dependent and non-deterministic.

Playwright is already a dev dependency of the repo (`tests/e2e/`); `parse` reuses the installed chromium and prints the install command when missing.

### D3 — Renderer is a template + bundled runtime + inlined IR
`render` writes `deck.html` = fixed template + `<script type="module">` containing an esbuild-bundled runtime (three.js, opentype.js, our builders) + `window.__DECK = <IR JSON>` + base64 subset Poppins TTF. Determinism: bundle built once at package build (`dist/runtime.js`), subset font is a pure function of the glyph set, JSON serialised with sorted keys. No dates, no random.
- *Why*: single file, offline, byte-identical. The runtime is the lab's code split into modules.
- *Alternatives*: (a) CDN imports like the lab — not offline, not deterministic across CDN changes; (b) server-side render to video — loses interactivity, huge.

Font subsetting runs at `render` from the merged IR's full text (titles, bullets, labels, override-added strings) via `opentype.js` in the CLI — so text added through overrides never lacks glyphs. Runtime modules (all ported from the lab): `text/` (opentype → ShapePath → ExtrudeGeometry; canvas label with `P.bg` outline), `materials/` (glass/metal/matte PBR, palette), `scene/` (floor, fog, bloom, key/fill/rim, shadow bias), `backgrounds/` (scene library keyed by slide semantics), `builders/` (`flowchart`, `sequence`, `brain`, `loop`, `swarm`), `camera/` (rail/dolly, hash deep-link, cull neighbours), `loop.ts` (rAF with `setTimeout` fallback when `document.hidden`).

### D4 — Labels: canvas + inverted outline; titles: extruded
Diagram labels are `CanvasTexture` planes, Poppins 700 via `FontFace` from the same TTF buffer, filled `P.text`, stroked `P.bg` at 18 % of size, `MeshBasicMaterial{toneMapped:false, depthWrite:false}`, offset in front of the node surface (`h/2` for round shapes). The runtime awaits `FontFace.load()` before painting any label canvas and before `__deck3d.ready` resolves, so headless snapshots/check never see fallback glyphs. Titles stay extruded + bloomed as the hero element.
- *Why*: extruded small text blooms and becomes unreadable (user feedback); unlit + outline is legible on any material in both modes.

### D5 — Package layout
```
packages/deck3d/
  package.json            @blackbelt-technology/pi-dashboard-deck3d, bin: deck3d, pi.skills
  bin/deck3d              thin launcher → dist/cli.js
  .pi/skills/deck3d/SKILL.md   + reference/ir-fields.md (generated from schema)
  src/cli.ts              parse | validate | render | build | check | snapshot
  src/check/              rules.ts (pure), run.ts (Playwright driver), report.ts
  src/fx/                 <id>.ts + <id>.meta.json corpus; index.ts registry; catalogue.ts → reference/effects.md
  src/ir/schema.json      JSON Schema (ajv), src/ir/merge.ts (overrides), src/ir/ids.ts
  src/parse/markdown.ts   deck grammar → slides
  src/parse/harvest/      playwright harness + mermaid bundle
  src/render/index.ts     template + inline runtime + font subset
  src/runtime/            three.js modules (D3)
  assets/Poppins-Bold.ttf (OFL)
  assets/props/           vendored CC0 GLBs + manifest.json + LICENSES
  src/props/              search.ts (polypizza, vendored), fetch.ts (hash, caps), generate.ts (gradio_client shim), restyle.ts
  fixtures/               strategy-lab.md → expected deck.json + expected deck.html hash
  test/                   vitest: determinism, schema, harvest (needs chromium; skipped when absent), grammar
```
`ir-fields.md` is generated from `schema.json` `description`s by a build script — one source of truth for the LLM's knob reference.

### D7 — Content-related props: LLM picks, code fetches/pins/renders
Sources v1: **Poly Pizza** REST (`https://api.poly.pizza/v1.1/search`, free key in `POLY_PIZZA_KEY`, CC0/CC-BY low-poly, direct GLB download URLs); **vendored CC0 subset** of Kenney + Quaternius packs under `assets/props/` with `manifest.json` (name, tags, tris, bytes) — offline, most style-consistent, searched first; **generate fallback** via HF Space `tencent/Hunyuan3D-2` `/shape_generation` through `gradio_client` (python3 optional dep; geometry only, so `restyle: palette` forced). Search = text match on name/tags; no embedding model — the LLM reads the candidate table and picks.

IR: `overrides.props[]` (see spec). Cache: `.deck3d/props/<source>-<id>.glb` beside the deck, sha256 pinned in the override; `render` verifies hash → determinism holds (IR + cache → same HTML; the hash pins the *normalised* cached GLB, so remote encoding drift cannot reach the output). Ambient role carries `count` (instances) as an override field so no renderer input is hidden. Runtime: `GLTFLoader` + meshopt decoder, `Box3` normalise to `size`, ground to floor, `lookAt` camera yaw; `restyle: palette` traverses meshes and swaps materials for the deck's PBR (`metal` for hard-edged, `matte` default; glass never — reads noisy). Roles: `hero` (right of title block), `illustration` (empty region opposite bullets, computed from bullet panel bbox), `ambient` (N instances drifting in the background scene, `InstancedMesh`), `node:<id>` (replaces the flowchart primitive; label + edge endpoints keep the node's bbox). Anim presets are small functions of `t` on the prop group. Credits slide generated at render for any non-CC0/non-generated licence.
- *Why*: reuse of thousands of consistent CC0 models beats generating; hash-pin keeps determinism; roles avoid free-form 3D placement in JSON.
- *Alternatives*: (a) code picks props by keyword heuristics — brittle, and contradicts "LLM tunes"; (b) embed a text-embedding search — heavier than value for ≤20 candidates the LLM can read; (c) 2D image plaques — flat in a 3D scene.
- `props generate` shells out to `python3 -m gradio_client` (optional; absent → exits non-zero with the pip install hint; never required by parse/render/build). Trade-off accepted: the free HF Space has no Node client.
- Security: downloads accept `.glb` magic only; a `.gltf` is converted to a single GLB with embedded buffers at fetch time and rejected if any `uri` is external (self-containment), size cap, cache names from `source+id` slug only (no URL-derived paths), no glTF extensions that execute (none exist, but `KHR_*` allowlist anyway).

### D8 — `check`: measure the scene graph in a browser, not the pixels
The deck exposes `window.__deck3d` (`gotoSlide`, `setTime`, `ready`, `measure`, `peaks`). `measure()` walks the slide's objects, projects each labelled thing's `Box3` to CSS px and reports label cap height exactly (labels are canvas planes with known world height) plus a camera→label raycast. The CLI (`src/check/`) runs Playwright headless at dpr 1, per viewport, per slide, at `t=0` and each animation peak, and applies pure rules: fit vs 4 % safe margin, legibility ≥ 14 px @1080 (scaled), overlap IoU > 0.1, occlusion, contrast ≥ 3:1 from a cropped `toDataURL` of the pixels behind the label. Findings carry severity + a suggested `overrides` key (`slides[n].diagram.scale|offset`, `slides[n].camera.distance`, `slides[n].labels.size`) so the LLM's fix is one edit. `build` runs it (fail only with `--strict`). Same IR + viewport ⇒ same report (deterministic clock; no rAF timing in the measurement path).
- *Why*: OCR/pixel-diffing is flaky and can't attribute a problem to an object; the scene graph knows every label's world box. Contrast is the one rule that needs pixels because backgrounds are animated scenes — sampled at the deterministic clock, ratio rounded to 0.1. Rasterisation differs per GPU/SwiftShader, so contrast is `warn`-only and **excluded from the report byte-equality guarantee** (geometric rules are exact). `measure()` reports the current slide's objects only; neighbour culling by the camera rail never affects it. `build` runs `check` only when chromium is present — otherwise prints `check skipped: chromium missing (<install cmd>)` and exits 0; `--strict` fails when check cannot run. `render`/`validate` never need a browser; `parse` (harvest) always does.
- *Alternatives*: (a) OCR screenshots — slow, non-deterministic, no object attribution; (b) LLM-only visual review — keeps working alongside, but cannot reliably see 9 px text or 3 % spill; (c) static layout math without a browser — misses projection/occlusion/contrast, and the harness already has Playwright.

### D9 — Effects corpus: modules + metadata cards, agent selects, parser defaults
Every visual effect is `src/fx/<id>.ts` (one interface: `create(ctx, params) → { object?, pass?, material?, tick?, dispose }`) plus `<id>.meta.json` (kind, mood/content tags, cost 1–5, modes, param JSON Schema, conflicts, source URL, SPDX licence). A build step compiles cards into `reference/effects.md` with `fx preview` thumbnails and into the IR schema (so `validate` bounds params). `parse` assigns deterministic defaults via a static keyword/diagram-kind → content-tag table (cheapest match per kind); `overrides.slides[n].effects` replaces the list. `render` enforces `conflicts`, skips mode-incompatible effects with a warning, and warns over the `quality` cost budget (low 6 / medium 12 / high 20); `check` surfaces both.
- *Licence gate (verified 2026-09-18)*: three.js MIT, `pmndrs/postprocessing` Zlib, `@pmndrs/drei-vanilla` MIT, `n8ao` CC0 (LICENSE file verified) — admitted (`troika-three-text` MIT is vetted as a future candidate; not a v1 dependency, labels are canvas planes per D4). LYGIA is Prosperity (non-commercial without sponsorship) and Shadertoy defaults to CC BY-NC-SA — inspiration only; the corpus test rejects cards without a permissive SPDX id. **Single post stack:** the runtime adopts `pmndrs/postprocessing`'s `EffectComposer` exclusively; the lab's three.js `UnrealBloomPass`/`FilmPass` are re-expressed as its `BloomEffect`/`NoiseEffect` (the port test compares against a tolerance image, not bytes, for these two). `defaults.transition` is the id of a `transition`-kind effect — one knob, not two.
- *Why cards*: the LLM chooses well from a short typed catalogue (tags, cost, modes) and badly from source code; cards also make params validatable and budgets computable. Deterministic defaults keep a bare deck presentable without any agent pass.
- *Alternatives*: (a) LLM writes effect code per deck — non-deterministic, un-reviewable, breaks the overrides-only rule; (b) embedding-based effect retrieval — overkill for ~30 items, tags suffice; (c) no defaults, always agent-picked — bare `build` output would be flat.

### D6 — Quality tiers
`defaults.quality` ∈ low|medium|high toggles bloom, mirror reflector, shadow map size, particle count. Default `high`. Also overridable per slide.

Timeouts (scenario-design gap fill): harvest 60 s per mermaid block, `check` 120 s per viewport, `props search` online 10 s → vendored fallback. Mermaid syntax error = hard parse failure (unsupported *type* stays a warning). Default `check` viewports `1920x1080,1280x720`. Prop cap is inclusive MiB. Zero-heading markdown = one slide `slide`. Fixture build budget 20 s post-launch / 2.5 MB html.

## Risks / Trade-offs

- [Effect ports drift from upstream / licence changes] → `source` + `licence` on every card, corpus test audits SPDX list, upstream deps pinned.
- [Slide title edits orphan tuning] → slug ids + optional `{#id}` pin; parse warns per orphan with the pin suggestion.
- [Harvest text metrics vary by chromium build] → embedded harness font, Playwright pin, fixture byte-equality asserted on the pinned build only.
- [Contrast rule differs per GPU] → warn-only, out of the report determinism guarantee.
- [mermaid id scheme changes on upgrade] → exact pin + one fixture per diagram type asserting node count and first node found; bump is a deliberate change.
- [Harvest needs chromium; CI runners without it] → tests mark harvest suites `skipIf(!chromium)`; `parse` fails with install hint; `render`/`validate` never need a browser.
- [HTML byte-equality is brittle to bundler nondeterminism] → esbuild with fixed options and no hashes; fixture stores a hash, test diffs on failure.
- [IR grows into a second programming language] → schema stays small; anything needing logic becomes a named `scene`/`builder` in code, not a JSON expression. Rule in SKILL.md: if you need a knob that isn't there, propose a schema field, don't hack HTML.
- [Subset font misses a glyph added by an override] → glyph set is computed from the merged IR at render time, not from markdown.
- [Large output (~1.5 MB with three.js + font)] → acceptable for a deck; `low` quality does not shrink code, only runtime cost.
- [Mixed prop styles look cheap] → vendored set searched first; `restyle: palette` default; skill tells the LLM to prefer one pack per deck.
- [Poly Pizza API changes / key missing] → source is optional; offline vendored set always works; API response parsed defensively with a fixture.
- [Hunyuan3D quota / server errors] → fallback only, fails loud with retry hint; never on the render path.
- [Prop binaries bloat HTML] → size cap per prop + budget warning; meshopt compression at render.
- [`check` false positives on intentionally cropped hero elements] → per-slide `check.ignore: [ids]` override, reported as `skipped` so nothing is silent.
- [Contrast sampling varies with animated backgrounds] → sample at deterministic `setTime`; rule uses mean luminance over the label rect.
- [LLM edits derived fields anyway] → `validate` diffs merged IR against fresh derive; warns with the JSON paths.
