## 1. Verifier and identity data

- [ ] 1.1 Add optional persisted `piLinkedAt` and non-persisted `restored` / `identityRefused` to the registry entry; round-trip `piLinkedAt` in `persist()` / `cleanupOrphans()`.
- [ ] 1.2 Implement async `verifyRestored(pid, anchorMs, { probe })` → `match | gone | mismatch | unverifiable`, one-sided per design D2, injectable `probe` defaulting to `processStartedAt`. Bound each probe by 2000 ms (timeout ⇒ `unverifiable`); a missing, non-finite or unparseable anchor, or a failed sidecar `stat`, ⇒ `unverifiable`; clamp a future anchor to now (G5, G6).

## 2. Registry gating

- [ ] 2.1 `cleanupOrphans`: mark restored entries; verify the spawn pid; mismatch ⇒ reclaim as `identityRefused`; 7-day kill only on `match` (design D4).
- [ ] 2.2 `killEntry` / new `killBySessionIdChecked(sessionId, { verifyIdentity })`: verify each restored pid immediately before its first signal; clear a mismatched `piPid` + `piLinkedAt`; gate the 200 ms keeper-group timer on a keeper or pi `match`; return `signalled | no-entry | refused-identity`.
- [ ] 2.3 Apply design D5: `unverifiable` refused on unattended paths (terminator `verifyIdentity`, 7-day kill, keeper discovery), signalled on operator paths (shutdown, force-kill, `killAll`); `mismatch` and `identityRefused` never signalled.
- [ ] 2.4 Make `killAll({ exitIntent })` async, with `exitIntent: ExitIntent | null` optional and a null or absent value unattended (G1); unverifiable restored entries signalled only for `shutdown` / `user-quit` / `restart`: snapshot keys, verify restored entries in parallel under a 5 s total budget (a timeout ⇒ `unverifiable`; a rejected probe never rejects `killAll`) (G6), signal, delete only snapshotted keys; keep the `isUnsafeTestHomeScan` guard.
- [ ] 2.7 Give `killEntry` / `killByToken` an explicit `verifyIdentity` (default unattended); the terminator's `reclaimByToken` passes unattended. Define the partial outcome (design D4): `signalled` when any rung signalled, `refused-identity` only when none could.
- [ ] 2.8 Re-probe the keeper pid when the 200 ms keeper-group timer fires (G3): skip on `mismatch`; `unverifiable` follows the D5 path rule; `match` and `gone` still call `killProcessGroup(keeperPid, { timeoutMs: 2000 })`. Never group-signal a keeper pid marked `identityRefused`, even when pi matched (G7).
- [ ] 2.9 Operator paths hitting a registry `mismatch`: `killBySessionId` returns `false` and the force-kill handler returns `force_kill_result` `success: false` naming the identity reuse (G2).
- [ ] 2.10 `linkByPid` skips `identityRefused` entries in every tier (G8); `linkByToken` is unchanged.
- [ ] 2.5 Log one `[headless-pid-registry] identity OUTCOME pid=P kind=<spawn|pi|keeper> session=<id|->` line per refusal.
