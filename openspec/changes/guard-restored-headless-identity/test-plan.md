# Test Plan — guard-restored-headless-identity

Stage: design   Generated: 2026-10-26

Decisions applied (all accepted):
- Q1 — `unverifiable` is refused on unattended paths, signalled on operator paths.
- Q2 — legacy `piPid` window W = 60 s. Tolerance = 2000 ms (`IDENTITY_TOLERANCE_MS`).
- G1 — `killAll` null/absent intent ⇒ unattended.
- G2 — operator path + registry mismatch ⇒ `killBySessionId` `false`; force-kill `success:false` naming identity reuse.
- G3 — 200 ms timer: skip on `mismatch`; `gone` still group-kills; `unverifiable` follows the D5 rule. Task 2.8 corrected.
- G4 — a mismatched keeper pid is treated as dead for registration.
- G5 — unparseable/missing anchor ⇒ `unverifiable`; future anchor clamps to now.
- G6 — probe timeout 2 s; `killAll` budget 5 s; timeout ⇒ `unverifiable`; a rejected probe never rejects `killAll`.
- G7 — a refused keeper spawn pid is never group-signalled, even if pi matched.
- G8 — `linkByPid` skips `identityRefused` entries.

Conventions: `A` = anchor ms. `start` = value the injected probe returns. "no signal" = `killProcess`, `killProcessGroup`, `killPidWithGroup`, `process.kill` (non-zero signal) all uncalled for that pid. "refusal log" = one `[headless-pid-registry] identity <outcome> pid=<p> kind=<spawn|pi|keeper> session=<id|->` line.
