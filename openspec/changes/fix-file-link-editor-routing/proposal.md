## Why

Three open issues share one surface: how a file reference reaches the editor pane, and what the pane does to the user's edits there.

- [#1137](https://github.com/BlackBeltTechnology/pi-agent-dashboard/issues/1137) — a full-path file link opens the legacy `FilePreviewOverlay` instead of the editor pane.
- [#1157](https://github.com/BlackBeltTechnology/pi-agent-dashboard/issues/1157) — `~/…` links resolve to "not found" (or the legacy overlay) when the file is outside the session cwd.
- [#1166](https://github.com/BlackBeltTechnology/pi-agent-dashboard/issues/1166) — unsaved Edit-mode changes vanish silently on tab close / session switch.

Verified root causes (all CONFIRMED against current code):

1. `packages/client/src/components/tool-renderers/FileLink.tsx:60` — `canSplitOpen = !!ws && !absolute && …`; absolute and tilde tokens (`absolute: true`, `linkify-tool-output.ts:237,245`) always reach `void openFile(result.resolved, line)` (`FileLink.tsx:96`), which `tool-renderers/useFileOpenRouting.ts` (`openFile`, ~L56-62) routes to the overlay. When no split exists for the session there is no `buildEditorUrl` deep link either (`OpenFileButton.tsx:45` has one; `FileLink` does not).
2. `packages/server/src/lib/resolve-file-mention.ts:82-83` — anchors `[cwd, canonCwd?, ~/.pi]` + grants; any other candidate returns `null`, which `FileLink.tsx:85` renders as a struck-through "not found". The mention never reaches `/api/file`, whose gate (`file-routes.ts` `gateReadPath`) is the one that raises the grant prompt (operator click) or the denial notice. Spec scenario "home file outside ~/.pi rejected → null" encodes this.
3. `MarkdownViewer.tsx:42-44,90` and `EditablePreviewTab.tsx:45-46,82` hold `content`/`buffer` in local `useState`; `EditorPane.tsx:375-388` `closeTabAt` only guards handler tabs (`f?.handlerMode`), the pane close button (`EditorPane.tsx:518`) calls `updateSplit({mode:"closed"})`, `useSessionActions.ts:264` `handleSelect` navigates unconditionally, and no `beforeunload` covers the built-in viewers (`FileHandlerLayer.tsx:251-259` arms one for handler tabs only; others: `InstructionsPage.tsx:186`, `SettingsPanel`). The viewer is keyed by tab path (`EditorPane.tsx:280,364`), so each leave unmounts the buffer. Plugin file-handler tabs already have a guard (`use-file-handler-pane.ts` `guardTabClose`, `close-risk.ts`); built-in editable tabs do not.

Not already fixed: archive sweep (`2026-07-17-non-disruptive-file-open`, `2026-10-22-composer-dock-collapse-and-file-open`, `2026-06-07-unify-file-link-openability`) shows the out-of-folder Open was explicitly deferred; no active change overlaps.

## What Changes

- `FileLink`: route resolved links to the editor pane — `normalizeUnderCwd(resolved, cwd)` → `ws.openInSplit`; no live split but a `sessionId` → `navigate(buildEditorUrl(...))`; overlay only when there is no session id. Offline-fallback (resolve request failure) unchanged. *Worktree sessions (confirmed (owner, 2026-11-20), `design.md` D4):* an absolute link into the parent checkout is first re-rooted to the worktree copy via the existing `resolveLinkOrigin` + a resolve round-trip; it opens the worktree copy when it exists, else the parent path as resolved.
- `resolve-file-mention.ts` + `POST /api/file/resolve-mention`: a candidate that fails containment returns `{ resolved, kind, outside: true }` with **no stat** (no existence oracle); contained-missing still returns `null`. Client `ResolveMentionResult` gains `outside?: boolean`. *(Security posture — confirmed (owner, 2026-11-20), see `design.md` D1.)*
- Editor pane: tabs outside the cwd are **editable**, through a new **write mode on path grants** (confirmed (owner, 2026-11-20), `design.md` D2). `AccessGrant` (`access/access-grants.ts:88-108`) gains an optional `mode: "write"` (absent = read; `version: 1` store unchanged). Existing read grants and the cwd's bound-checkout-root widening do **not** admit out-of-cwd writes. `POST /api/file/write` (today cwd-only via `isWritableMdTarget`): an allowlisted text doc outside the cwd runs a write-mode containment check (cwd only, no bound-checkout widening, write-mode grants only); an un-granted miss suspends for a **write prompt** (allow once / allow-always for the chosen subtree as a write grant / deny; the mode is derived server-side from the route, never from the client reply); denied/expired/ineligible → `403` with the denial remedy, the save fails and the buffer is kept. A write grant also admits reads under its subtree (write ⊃ read). The Access settings page shows each grant's mode and revokes a write grant independently of any read grant on the same subject. Under YOLO the write hold is auto-answered allow-once like a read hold (confirmed (owner, 2026-11-20)), still bounded by the YOLO session roots. Extension allowlist, dashboard-state refusal, `mtime` 409 and atomic write are unchanged.
- Unsaved-edits guard for built-in editable tabs: an app-level module store (`editor-pane/unsaved-store.ts`, `fileHandlerStore` precedent — not React context, because `handleSelect` runs above the split providers; serves session and folder panes) where viewers publish `{dirty, save}`, a `confirmLeave` helper + page-level `UnsavedChangesHost` Save / Discard / Cancel dialog, wired into single tab close, bulk close (`planBulkClose` risk list), pane close, `LayoutModeSwitch`, `handleSelect` (sidebar session switch) and a store-armed `beforeunload`.

## Non-goals

- Guarding browser back/forward and non-sidebar route changes (wouter has no blocker; only owned chokepoints + `beforeunload`; #1166's "navigating to another route" is covered via the sidebar session switch only — owner-confirmed guard scope, D3).
- Guarding tab *switch* (buffer is dropped there too today; see DECISIONS D3 — follow-up: keep-alive buffers).
- A preference gate for out-of-folder open/edit (the write-mode grant + prompt is the only gate); watching outside files (a tab outside the cwd gets no live changed-on-disk push — the save-time `mtime` 409 still protects it); writes outside the cwd in global scope (no `cwd` → still `~/.pi/agent` only); a per-session or per-file write grant (a write grant is a subtree grant, see `design.md` D2 risk); granting write to `.mmd/.mermaid` or non-text files (directory-only / refused as today).
- Removing `FilePreviewOverlay` (still the no-session fallback).
- Fixing stale `openEditor`/`ToolContext.editors` wording in the "Click routing — localhost editor" requirement (pre-existing drift).

- Server: `lib/resolve-file-mention.ts`, `lib/writable-md-target.ts` (split extension/state check from scope check), `routes/file-routes.ts` (resolve response mapping; `prepareMdWrite` + `/api/file/write` write-mode gate with the live request/reply for the hold), `access/access-grants.ts` (`mode`, `grantedWriteSubjects()`, `(subject, mode)` idempotency, per-mode revoke), `access/{named-grant,planes,access-plane}.ts` (carry the action to the grant), `access/{containment-gate,denial-hold,pending-grant-registry,grant-coordinator}.ts` (`action` on denial facts, registry key, write-mode check + re-evaluation), `lib/path-containment.ts` (`isAllowedReal` option to skip bound-checkout widening), `routes/access-routes.ts` (grants list carries `mode`; `DELETE` accepts optional `mode`), shared `GrantRequestMessage` (optional `action`), `docs/security/http-route-inventory.md` rows (DocScribe).
- **Migration**: none. `access-grants.json` stays `version: 1` (bumping would make a pre-change build refuse the whole file and drop every grant); `mode` is optional and additive, absent = `read`. Existing persisted grants are read-only and are never rewritten; a hostile/unknown `mode` value loads as read (fail closed). Pre-change, an out-of-cwd write was a flat `403`, so no previously working write is removed. Nothing to back-fill.
- **Compatibility**: `outside` and `mode` are additive; `GET /api/access/grants` rows gain `mode` only for write grants; `DELETE /api/access/grants` with no `mode` keeps today's meaning (remove every entry for the subject). Old clients ignore `outside` (they open the legacy overlay; its read is still gated) and render a write grant as an ordinary row. Newer client + older server: `outside` absent → `null` → not-found; no write prompt exists (the old route 403s) so Save shows the existing error. Consumers of the grant list (grep, browse roots, pi-trust mirror, provisioning) treat a write grant exactly like a read grant (write ⊃ read); only the write gate distinguishes the mode.
- **Rollback**: revert the change; no data migration. A write grant already on disk survives (a pre-change build spreads unknown fields through load/rewrite, `access-grants.ts:206`) and is then read as a plain **read** grant on that subtree — a bounded read widening the operator already accepted (the write prompt copy says allowing it also allows reading); it can be revoked from the Access page. Re-applying the change restores the write capability. Revoke it first if the widened read is unwanted.
- **Behaviour changes to call out**: (1) bound-checkout roots (a worktree session's parent checkout, a repo sibling of a subdirectory cwd) admit reads silently but a text-doc write there now raises the write prompt; (2) a worktree session's parent-checkout link opens the worktree copy when it exists.
