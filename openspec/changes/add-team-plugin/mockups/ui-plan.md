# UI plan — add-team-plugin (team-app)

Token authority: repo `ui-contract.md` → `packages/client/src/index.css` (dark `:root`, light `[data-theme="light"]`). `tokens.css` = verbatim copy of those two blocks; every mockup rule references `var(--…)` only.
Reference UX: Marveen "Csapat" agent card (`marveen/web/index.html:405-470`, `app.js:3511-3640`, MIT) — anatomy only (avatar · name · description · model badge · status dots · "Beszélgetés"). No Marveen assets, copy or CSS reused.

Model (2026-10-04): the **project selector** in the header picks the target (a project or the user's own workspace). The grid shows the personas assigned to that target. Each agent has **many conversations** per target.

Two hosts (D16, `add-plugin-app-host` board-style embedding): **standalone** at `/apps/team/` (app header below) or **embedded like the OpenSpec board** — content area beside the visible sidebar, `EmbeddedApp` top bar — globally at `/team/` (sidebar row "Csapat →", requested global slot) or per folder at `/folder/:cwd/team/` (project locked, D17); mock control "Host" switches.

Mockup: `index.html` (+ `mockup.css`, `mockup.js`). The real app lives at `<dashboard>/apps/team/` (D14); hash routes here mirror its D10 routes: `#/` grid · `#/agent/:key` conversation list · `#/agent/:key/c/:id` conversation · `#/personas/new[?target=|?fork=]` · `#/personas/:key` · `#/signin` · `#/signin-unavailable` · `#/not-admitted`. The dashed "Mockup controls" strip is not part of the app.

## Cited rules driving the design

- **Jakob's Law / consistency (H4)** — Marveen card anatomy + dashboard card recipe; the chat keeps the dashboard ChatView look; the conversation list follows the common "list | detail" chat pattern.
- **Visibility of system status (H1)** — every card shows aggregate status, conversation count and recency; ensure/resume/reconnect states are announced (`role=status`); the selected project is always visible in the header.
- **Recognition over recall (H6)** — the selector shows where you are; conversation titles come from the auto-namer and can be renamed; the newest conversation opens by default.
- **Common region + proximity (Gestalt)** — the header selector scopes everything below it; two titled persona sections; list pane and chat pane separated by one border.
- **Hick's Law** — one visible primary per card plus one secondary ("+ Új"); persona actions in one menu; conversation actions in one menu; no selector menu when only the own workspace exists.
- **Error prevention (H5)** — new conversations are not offered where they would be refused (retired, unassigned, `full` in multi-user, limit); disabled controls state their reason; deletes are confirmed and state their consequence; archive is the reversible alternative to delete.
- **User control and freedom (H3)** — archive / restore; restore returns to the active list where the conversation now lives.
- **Help users recover from errors (H9, GOV.UK error summary)** — field-level server errors with a focused summary; read-only conversations say why and what is still possible.
- **Persistent labels / single column (NN/g form design)** — labels above fields; counters as live help text.
- **Color not the sole channel (WCAG 1.4.1)** — status shape + word; unconfined pill icon + text.
- **Target size (WCAG 2.5.8 + contract `tap-target`)** — ≥ 44 px at mobile, ≥ 32 px from 640 px.
- **Focus order / visible focus (WCAG 2.4.3, 2.4.7)** — focus stays on the selector after switching target and returns to the opener after menus and dialogs.
- **Reflow (WCAG 1.4.10)** — below 640 px the project selector moves to its own header row; below 1024 px list and conversation are separate views.
- **Match between system and the real world (H2) + recognition (H6)** — the team is found where the work is (the folder of the session), not behind a separate app switch; the folder row shows counts before opening.
- **Error prevention (H5) for enable** — the enable item only exists where enabling would succeed (admin/operator, unmatched folder); the dialog blocks an empty name or an empty user list in place.
- **Language of parts (WCAG 3.1.1)** — `<html lang>` follows the HU/EN toggle; persona content and conversation titles are user data and are not translated.
