Defects — cited, severity-ranked

4
D1 · Destructive action, no confirm. “Forget reserved URL” destroys a URL you may have shared, in one click, with no undo. Rubric #8 — destructive actions must be reversible or confirm-gated (Nielsen H3/H5).
4
D2 · Silent fallback. When a reserved name is taken or invalid, the connect still succeeds on a random URL. Only a console.warn records why. Rubric #7 — every state-changing action shows status (Nielsen H1, visibility of system status).
3
D3 · Capability invisible. Nothing shows or sets the reserved name. Nielsen H6 — recognition rather than recall.
3
D4 · Shown out of context. “Forget reserved URL” renders for ngrok / tailscale / zerotier, which have no zrok name. Rubric #11 — nothing on screen may fail to serve the current goal (H8).
3
D5 · Equal weight, unequal risk. “Disconnect” (recoverable) and “Forget reserved URL” (irreversible) are styled identically. Rubric #6 — one dominant action; Von Restorff.
2
D6 · Placeholder-only labels. Rubric #13 — every input needs a persistent label.
2
D7 · Target size. Footer actions are ~30px tall. Rubric #2 — ≥24px AA, primary ≥44px.

Why this is a state, not an error toast

·
The connect succeeded — every layer honestly returns { ok: true, url }. Reporting a failure would be a lie. Nielsen H9 — errors must state the real cause.
·
Derived from stored-name vs effective-name, so a watchdog recycle re-renders the same banner instead of firing a new notification each cycle. Rubric #7 without alarm fatigue.
·
Offers both exits — fix it or accept it. Nielsen H3 — user control and freedom.
·
Colour is never the only channel: icon + bold cause + border. Rubric #4 / WCAG 1.4.1.
