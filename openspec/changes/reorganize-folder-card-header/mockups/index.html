Project setup is idempotent — not a birth event

Setup must be re-runnable on an already configured directory: a repo may have openspec/ but no AGENTS.md, or an AGENTS.md that predates the recommended pi layout. The action is “bring this directory up to the recommended setup”, not “initialize once”. Two consequences: it lives permanently in ⋯ → DIRECTORY (never hidden), and the banner appears only when something is actually missing.

Correction — tier 3 was never state-only

I asserted “tier 3 is state-only” without checking. It is false. The slot pills carry 9 action buttons today — more than tier 1's four — and directory-card-layout mandates them: “each slot section SHALL keep its own data hook and secondary actions (refresh, create)”. Invariant 1 was being enforced on Workspace alone.

PillButtons todayGlyphProposed
AUTOMATIONSfolder-automation-new-btnmdiPlus⋯ → CREATE
folder-automation-refreshmdiRefreshfolded into one Refresh
GOALSfolder-goal-new-btnmdiPlus⋯ → CREATE

OPENSPECfolder-openspec-refreshmdiRefreshfolded into one Refresh
folder-archive-btnmdiArchiveOutline⋯ → OPEN

The menu taxonomy is owned by the host, not by plugins. Groups are a fixed verb set — WORKSPACE · DIRECTORY · CREATE · OPEN · MAINTENANCE — and each contributed item declares which one it belongs to. Grouping by verb rather than by plugin keeps single-item groups from appearing, and a group renders only when non-empty. Items in the OPEN group carry a slot-qualified label (“OpenSpec archive”) because the group name no longer says which slot they came from.

The glyph audit gets worse before it gets better. mdiRefresh appears four times on one card meaning four different scopes, and mdiPlus twice. That is invariant 4 violated six times over — and it is invisible precisely because each pill looks locally reasonable.

Resolved: four per-slot refreshes collapse to one Refresh folder data — nobody wants to refresh only goals, and per-slot refetch is data plumbing leaking into the UI. Archive and Specs move to an OPEN group rather than being deleted. Net: 9 pill buttons → 0; the menu grows to 13 items across 5 groups.

Plugin contract consequence. SlotPill exposes actions?: ReactNode, so kb-plugin, goal-plugin and automation-plugin inject arbitrary markup into the pill. That prop is removed: plugins now contribute declarative items ({ id, group, label, icon, badge, onSelect }) to a folder-actions-menu slot. The host gains control of grouping, ordering, keyboard semantics and the mobile sheet; plugins lose the ability to render markup into the card. Breaking for plugin authors — deliberately.

Staleness — three questions, and only two have a mechanism

QuestionMechanism todayVerdict
Does the hook need running? the project's own gate bash — needsInit: exit === 0 exists, project-defined
Is the hook still the one I trusted? hookDefHash = sha256 over canonical worktreeInit; TOFU key is repoRoot + hash exists — but it is a security gate, not a freshness signal
Are my setup files current with the recommended templates? nothing — configured?: boolean is the only signal the real gap

The sha256 does exist — but editing the gate/command/prompt/model changes the hash, which revokes trust and forces a re-confirm before repo-provided bash may run from a UI click. That is a different event from “the recommended templates moved on”. Project setup has no stamp at all, so template drift is currently invisible.

Banner. hookDefHash moved → trust revoked. Blocking: the hook cannot run until you re-confirm. Earns a banner because it stops work and carries a security decision.
