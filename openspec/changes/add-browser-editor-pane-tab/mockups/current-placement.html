Browser relay: where the screencast is placed today (as built)

Sources: packages/browser-plugin/src/client/LiveViewTile.tsx, BrowserRelayBadge.tsx, relay-store.ts, and in the shell SessionContentGate.tsx and App.tsx (renderSession). Change: add-browser-relay and fix-browser-live-view-subscribe-and-reopen.

A. Desktop: the live view replaces the session detail (chat and composer)

The view uses the content-view slot. While hasLiveInstance() is true (at least one relay instance with at least one tab, not dismissed), SessionContentGate renders the slot instead of the chat for the selected session. The relay is global, so this happens for every session you select, not only the one that is driving the browser.

One tile per {instanceId, tabId}. Grid is 1 column below md and 2 columns at md and up. Each frame is an <img> set to the JPEG at w-full h-auto. Clicks, mouse moves, wheel and keys on the tile go out as browser_relay_input with coordinates normalized to [0,1]. There is no session header, no chat and no composer.

B. After clicking Close: the chat comes back and the badge is the way to reopen

dismissLiveView() sets the gate to false, so the chat renders again. The session-card-badge pill ("N browser tabs") is a button that calls reopenLiveView(). A material change in instances or tabs also brings the view back on its own.

Tiles stack in one column. The frame scales to the full width, so a 1280-px page is shrunk to roughly 280 px. Input is click only: onClick, onMouseMove, onWheel and key events. There are no touch handlers, no pinch-zoom and no soft-keyboard bridge. Tapping does register as a click, but typing requires a hardware keyboard to focus the tile.
The tile also mounts its own browser_relay_status listener, so it still updates when no session card is mounted, as on mobile.

Observations on the current placement

1. The view is not an editor-pane tab. The research record (docs/research/user-browser-in-editor-view.md) proposed an rbi:<id> viewer in the editor pane. What shipped is a whole-content content-view takeover.
2. The view is global, not per session. isLiveViewActive ignores the session, so any selected session shows the browser and every card shows the badge.
3. You can't see the chat and the browser side by side. Close is the only way to toggle between them.
4. Priority 500 is shared with other content-view claims (flows 100, blackhole 200). How claims that are all active at once get resolved depends on ContentViewSlot.
