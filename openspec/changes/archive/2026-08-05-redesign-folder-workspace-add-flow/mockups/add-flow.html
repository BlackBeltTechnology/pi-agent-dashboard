1The small “add to workspace” button

Stays in both places it lives today — the folder row and the session card. Only the affordance changes: the stray +ws text token becomes a compact icon button.

Why +ws fails. 10px text, absolute top-1 right-7, no icon, no border, ~22×16px hit box. It floats outside the row’s icon cluster, so proximity/grouping gives the eye no hint it belongs to the folder — and “ws” is jargon that only reads as “workspace” once you already know.

The idea: folder-plus + micro-caret, sized into the existing icon cluster

V1 — icon + caret recommended

mdiFolderPlus + mdiMenuDown. Folder-with-plus is the universal “add this folder to a collection” glyph (VS Code, Finder, Drive). The caret is the Material convention for “opens a menu”.

2Add Folders — a real explorer, not a path prompt

Row click navigates into the folder (explorer convention). The checkbox selects. Two independent things, never fighting for the same click.

What’s wrong today. PathPicker renders ⬆ for the parent row, 📁 for every folder and ＋ for create — emoji, so they shift with platform font and ignore currentColor/theme. Clicking a row both descends and becomes the answer, so there’s no way to pick more than one folder.

Row anatomy. [ checkbox ] [ folder ] name … [ badges ] [ chevron ] — checkbox = select, everything else = open. The trailing chevron is the explicit “descend” affordance so the gesture is discoverable, not just implied by the row being clickable. 3 sessions badges mark loose cwds you already work in — the folders most worth adding, surfaced without typing a path.
Pin is implicit — there is no pin choice. Adding a folder is pinning it; that’s what makes it visible. So the dialog asks exactly one question (which workspace, if any) instead of two. Unpinning from the row cluster removes the folder from the sidebar instantly — pin is the visibility switch, not a separate destination.
