Option A: browser relay as an editor-pane tab PROPOSED · not built

A new editor-pane-viewer plugin slot. The browser plugin claims the virtual-path prefix browser:<instanceId>:<tabId>, and each relay tab opens as one editor tab next to files, term:, live: and diff: tabs. The existing RelayTile (one subscription per mount) becomes the tab body. The full-content content-view takeover is removed or made optional.

  1. Badge: the pill becomes a menu of relay tabs. "Open in pane" dispatches openFile(path:"browser:<inst>:<tab>", viewer:"browser"), the same way term: and live: tabs open.
  2. Chat link: the agent prints a browser: link, which opens like the existing loopback links that open in the split viewer.
  3. Agent intent ("open in editor view"): a server-to-client open message (out of scope for v1).
  4. Auto-open when a new relay tab appears is off by default, so the pane is never forced on the user. This is the opposite of today's takeover.

On mobile, the tab is reached through the pane switch the shell already has, so no new layout is needed.
Today's tile has no touch handlers. The pane tab adds pointer events (tap → click) and a text bridge: a real <input> under the frame that opens the soft keyboard and sends key input. This is new work. It is needed in any placement, not only the pane.
"Fit" scales the frame to the pane width. On a phone, a 1280-px page shown at 280 px is barely readable, so remote viewport resize is a later step (only allowed while input is allowed, per the research §17).

What changes compared with today

Gained: the chat and the browser are visible side by side. The browser sits next to files and terminals. The view is per-pane-tab, so it is effectively per session. Nothing is forced open.
Core work: add editor-pane-viewer to SlotId. Change EditorPane so that when a path matches no built-in pseudo-tab prefix, it resolves plugin claims by prefix. Pane persistence needs a "gone" state.
Decided (design D4): agent-initiated opens go to the calling session's pane. The session comes from the plugin request lane via the browser_show_in_pane / browser_await_human bridge tools. Manual opens go to the session currently being viewed.
