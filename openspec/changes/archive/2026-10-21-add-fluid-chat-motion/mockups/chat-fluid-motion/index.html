Fluid (proposed)

Patterns used (and where they come from)

T1 · Row entry, live rows only

New user, tool, and assistant rows fade in and rise 6 px over ~220 ms, animating only opacity/transform. The user card grows from its bottom-right corner, toward the composer.

riskThe TanStack virtualizer remounts rows on scroll-back and history replay. The animation must key on a live-arrival marker (as streamedLive does for reasoning), not on mount.

Alternatives: CSS @starting-style (Baseline 2024) or a plain keyframe class. Neither needs Motion/Framer.

T2 · Paced reveal (buffer → rAF drain)

Received text goes into a buffer. A requestAnimationFrame loop reveals max(baseCps·dt, backlog·(1−e^(−dt/τ))) characters per frame. That gives steady flow during normal streaming and catches up quickly after a stall dump. Lag stays at about τ (120 ms) rather than growing.

Same idea as AI SDK smoothStream (done server-side) and the Upstash rAF typewriter. Their fixed ms-per-char rate falls behind on fast models, which is why this version adapts to the backlog. Fits here because the bridge already flushes in 50 ms bursts (COALESCE_WINDOW_MS).

T3 · Fresh-token fade

Only text revealed in the last ~400 ms is wrapped in spans that fade from opacity 0. Older text is plain markup, so the DOM stays small. A negative animation-delay (−age) keeps the fade continuous when React re-renders. Blur-in is a variant.

Pattern from FlowToken. A thin blinking caret follows the last glyph and goes solid while text is flowing.

riskMarkdownContent re-parses the whole tail on every update. That needs memoized stable blocks plus a re-rendered last block (the approach Streamdown takes for incomplete markdown).

T4 · Spring stick-to-bottom

Each frame, scrollTop moves toward the bottom with velocity v = (damping·v + stiffness·Δ)/mass instead of jumping instantly with every chunk. Scrolling up with the wheel or touch turns stickiness off, and “↓ Latest” turns it back on.

Algorithm from use-stick-to-bottom (StackBlitz/bolt). We would port only the spring step into the existing stickToBottomRef logic, because the virtualizer grow-pin and selection-anchor writers must keep a single scroll writer.

T5 · Tool card transitions

When a tool finishes, its check icon pops in (same motion as tool-group-flash). The result body expands using the grid-template-rows: 0fr→1fr trick: no JS measuring, and the height is bounded. This fits the existing “bounded height transition” requirement in chat-view.

Guardrails

All animation is opacity/transform/filter, and none of it changes layout. Under prefers-reduced-motion all of it is suppressed: text appears per chunk, and scrolling is instant. Nothing animates when the session is idle or the tab is hidden (chat-idle-render-cost).
