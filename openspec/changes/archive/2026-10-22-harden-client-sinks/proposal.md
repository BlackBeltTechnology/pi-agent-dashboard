# Proposal

## Why

The dashboard client turns untrusted strings into navigations and HTML in about 40 places. Agent tool arguments, file content, git remotes, npm metadata and OIDC discovery documents all feed those sinks. Every sink has its own guard, or none: five separate URL gates exist, and `CtxToolRenderer`, `ToolsSection`, `WhatsNewDialog`, `TabActions` and `SessionCard.openUrl` bypass all of them.

One real script-execution bug is live. `packages/client-utils/src/identity/login-flow.ts:102` passes `authorization_endpoint` from a fetched discovery document, unchecked, to `window.location.assign` (line 125), so a `javascript:` endpoint runs in the dashboard origin.

The spike `docs/research/trusted-types-spike.md` measured the runtime sink surface. The browser can enforce sink discipline through Trusted Types for a small set of app-owned sites: 8 seen at runtime, plus `DiagramPreview` and `DocxPreview`, found statically. A naive sanitizing default policy silently breaks 6 of 13 Mermaid diagrams. A tuned one keeps them pixel-identical, apart from one colorize step that needs a named policy. Doing this as one change keeps one URL policy, one policy registry and one lint guard. Four partial fixes would each re-derive the same sink inventory.

## What Changes

The phases are ordered and each ships behind its own gate. They revert in reverse order (C, B, A, 0) by commit revert. The Trusted Types knob is the runtime off-switch for Phase B.

- **Phase 0 — OIDC endpoint scheme check.** `login-flow.ts` rejects discovery `authorization_endpoint`, `token_endpoint` and `end_session_endpoint` values that are not `https:`. `http:` is allowed only for a loopback host. The logout path at `login-flow.ts:151-155` has the same `location.assign` sink. A rejected endpoint fails with `LoginFlowError("discovery-failed")` and never reaches `location.assign` or `fetch`.
- **Phase A — one URL policy and navigation chokepoints.**
  - New `packages/shared/src/url-policy.ts` with `classifyUrl(raw, origin)`. It returns `internal`, `loopback`, `external`, `mailto` or `blocked`.
  - New client chokepoints: `<SafeLink>`, `openUrl()` and `navigateTo()`. `dashboard-plugin-runtime` re-exports them for plugins.
  - Migrate every navigation sink that takes a variable: `window.open`, `location.*`, `setAttribute('href'|'src')`, and the JSX `href={expr}` sites fed by agent, file, relayed or remote data. The inventory comes from the guard's own report, not a hand count.
  - The navigation gates `UrlLink` and Electron `link-handling.ts` delegate to `classifyUrl`. The markdown media and protocol gates (`safeUrlTransform`, `is-external-href.ts`) keep their specified behaviour (`data:image`, `pi-asset:`, `irc:`/`xmpp:`).
  - New CI guard `scripts/check-client-sinks.mjs`, comment-aware and scoped to client-side source.
    - Its navigation rule set (raw `window.open(`, `location.assign(`, `location.replace(`, `location.href =`) turns on in Phase A.
    - Its HTML and worker rule set (`dangerouslySetInnerHTML`, `.innerHTML =`, `.outerHTML =`, `insertAdjacentHTML`, `srcdoc`/`srcDoc`, `new Worker(`) turns on in Phase B, once those sinks use named policies.
    - Only allowlisted modules and annotated lines are exempt.
- **Phase B — Trusted Types.**
  - New client module `trusted-types.ts` registers named policies:
    - `pi-sanitized-html`: DOMPurify, using each sink's existing config.
    - `pi-static-svg`: team-app constant `ICON` and `GALLERY` maps, by key.
    - `pi-worker-url`: same-origin `/assets/*.m?js` and `/sw.js` only.
  - The client also registers a tuned **`default`** safety-net policy for library internals (mermaid d3 labels, mermaid `<style>`). Its rules: a string with no `<` passes through; `<svg` uses the mermaid sanitize config; anything else goes through DOMPurify HTML/SVG/MathML; `createScript` returns `null`.
  - Every app-owned sink uses a named policy:
    - MermaidBlock (inject and colorize);
    - AsciiDocPreview;
    - DiagramPreview (server-rendered PlantUML/Kroki SVG);
    - DocxPreview;
    - adoc-math (template and KaTeX);
    - the EmlPreview `srcDoc`;
    - team-app icons and avatars;
    - `main.tsx` `serviceWorker.register`.
    
    The complete list is whatever the Phase B guard reports, not a hand count. Worker constructors generated by bundlers or libraries (Monaco via Vite's worker wrapper, pdf.js) go through the `default` policy's strict script-URL allowlist.
  - The baseline CSP gains `require-trusted-types-for 'script'` under a new `PI_DASHBOARD_TRUSTED_TYPES=off|report|enforce` knob. When unset, it follows the baseline: `off` if `PI_DASHBOARD_CSP=off`, otherwise `report`. It is separate from `PI_DASHBOARD_CSP`, so existing `enforce` users are not hit by TT enforcement.
  - The server tells the client the mode through an injected `<meta name="pi-trusted-types">`.
  - In `report` mode the `default` policy is pass-through-and-count. The browser does invoke a default policy under a report-only directive (spike Mode B), so a sanitizing default would otherwise change library output.
  - The sanitizing rules apply only in `enforce` mode.
  - Client-observed violations are batched to an authenticated `POST /api/csp-violations` and counted per directive, sink and source.
  - The spike harness moves into `tests/e2e/` as a tracked violation budget and per-diagram visual-regression check.
  - Electron's bundled pages get a `<meta>` CSP with an enforced `require-trusted-types-for 'script'`: `src/renderer/doctor.html` (no CSP today), `remote-connect.html`, `connecting.html`, and `resources/loading.html` (no CSP today; `innerHTML` at line 106). Each page keeps the inline script and style allowances it needs. These pages are static, fully owned and test-covered, so they enforce from day one; the server knob does not reach them.
- **Phase C — signed navigation intents.**
  - The server mints short-lived HMAC navigation intents (`POST /api/nav-intent`), following the `SignedChallenges` pattern in `auth/passkey/challenge-store.ts`.
    - The MAC binds principal, route, target and expiry.
    - The URL carries only the expiry and the MAC, so no principal and no path appear in clear.
    - The client requests an intent only for the operator actions `preview-egress-grants` already lists. Agent-declared targets and modifier or new-tab opens never get one.
  - Route-backed overlays (`/pi-view?url=`, `/folder/:cwd/view?path=`) carrying a valid `ni=` intent declare **operator** provenance.
  - Without an intent, or with an invalid, expired or mismatched one, they keep today's fail-closed **agent** provenance. A pasted or crafted link therefore never gets open egress or the grant dialog.
  - `returnTo` and `returnUrl` are **not** re-signed. They are already HMAC-bound in the OAuth `state` and restricted to same-origin by `sanitizeReturnUrl` / `safeReturnTo`.
- **Supersedes** the in-flight draft `add-trusted-types-report-only`. Its scope is fully contained in Phase B, and the spike evidence contradicts two of its points.
  - Its D2 says one DOMPurify default policy covers the Mermaid and AsciiDoc/DOCX sinks. The naive variant broke 6 of 13 diagrams.
  - Its D3 risk note says the Mermaid policy "only accepts strings that DOMPurify has already sanitized". In fact the colorize parse runs before the final sanitize.
  
  That change should be withdrawn, not merged.

## Capabilities

### New Capabilities
- `client-navigation-url-policy`: one URL classifier shared by client, plugins and Electron; navigation chokepoints; the CI sink guard.
- `client-trusted-types`: the named policy set, the default safety-net rules, the sink-to-policy assignment, the violation channel and the measured budget.
- `signed-navigation-intent`: minting, verification and the provenance effect of server-signed navigation intents on route-backed overlays.

### Modified Capabilities
- `baseline-content-security-policy`: adds the Trusted Types directive and its independent `PI_DASHBOARD_TRUSTED_TYPES` mode.
- `client-untrusted-content-sanitization`: sanitized Mermaid and document HTML is produced as `TrustedHTML` through named policies. The Mermaid colorize step works on an already-sanitized DOM (no parse of unsanitized output) before the final sanitize.
- `browser-principal-client`: OIDC discovery endpoints are scheme-validated before any navigation or token request.
- `electron-renderer-hardening`: Electron's bundled local renderer pages carry a CSP that requires Trusted Types.
- `preview-egress-grants`: a route-backed overlay opened through a valid navigation intent counts as an operator open. Expand on an operator-provenance preview card is named explicitly as an operator action; today the route-backed Expand overlay falls back to agent provenance.

## Impact

- **Client:** `packages/client/src/main.tsx`; new `lib/security/trusted-types.ts` and `lib/nav/safe-navigation.ts`; `components/preview/{MermaidBlock,AsciiDocPreview,DiagramPreview,DocxPreview,EmlPreview,PreviewOverlayView}.tsx`; `lib/preview/adoc-math.ts`; `components/editor-pane/monaco-setup.ts`. Sink migration touches about 30 component files: `CtxToolRenderer`, `ToolsSection`, `WhatsNewDialog`, `TabActions`, `SessionCard`, `ConnectionStatusBanner`, `LoginGate`, `UserBar`, `OAuthFlowView`, `ConnectMachine`, `NetworkDiscoverySection`, `useOpenExternal`, …
- **client-utils:** `identity/login-flow.ts`, `identity/oidc-flow.ts`.
- **shared:** new `url-policy.ts`, and a `nav-intent` wire type.
- **Server:**
  - `auth/csp.ts` gets the TT directive and the new mode knob.
  - New `POST /api/csp-violations`: authenticated, rate-limited, counters only, no payload persistence.
  - New `POST /api/nav-intent` (mint) and verify; the per-process HMAC key is re-keyed on restart, so intents do not survive a restart.
- **Plugins:** `team-app/src/ui/icons.tsx`, `craft-web-plugin` `CraftFrame`, `dashboard-plugin-runtime` `embedded-app.tsx` and `team-plugin` `team-open.ts` move to the chokepoints. `dashboard-plugin-runtime` gains the chokepoint re-exports, which is additive SDK surface.
- **Electron:** `src/renderer/{doctor,remote-connect,connecting}.html`, `resources/loading.html`, and `lib/link-handling.ts` delegating to `classifyUrl`.
- **CI:** `scripts/check-client-sinks.mjs` runs as a `ci.yml` step and in the ship gate. Tests: `tests/e2e/` gains the TT budget and Mermaid visual-regression spec.
- **CodeQL:** expected to close the 8 `js/xss` and 6 `js/client-side-unvalidated-url-redirection` untriaged entries owned by `triage-codeql-alert-debt`, which should then drop them from its residue.
- **Compatibility:**
  - No public API removal.
  - Third-party plugins that write raw `innerHTML` keep working: in `report` mode nothing blocks, and under `enforce` the `default` policy sanitizes.
  - Browsers without Trusted Types (older Safari and Firefox) ignore the directive.
- **Rollback, per phase:**
  - Phase 0: revert one guard.
  - Phase A: chokepoints are pass-throughs for allowed URLs; revert per file.
  - Phase B: `PI_DASHBOARD_TRUSTED_TYPES=off` is the runtime rollback for the dashboard directive and its reporting. The sink rewiring and the shared sanitizer configs are output-preserving code changes that revert by commit. The Electron page CSPs revert by commit.
  - Phase C: without `ni=`, overlays keep today's agent provenance, so dropping the mint endpoint returns to current behaviour.

## Discipline Skills

- `security-hardening`: the whole change hardens untrusted-input sinks (URLs, HTML, script URLs) and adds a signed capability.
- `doubt-driven-review`: before (a) the `default` policy rules are accepted, since they are the only path for unknown sinks; (b) the nav-intent HMAC binding and key lifecycle stand; (c) any switch of the TT default from `report` toward `enforce`.
- `observability-instrumentation`: the new `/api/csp-violations` endpoint and its counters; also the `/api/restart` caller-attribution gap noted in the spike, which stays out of scope here.
- `performance-optimization`: the `default` policy runs DOMPurify on hot Mermaid label paths (~155 calls per diagram-heavy page), so measure it before enforcing.
- `review-code`: before each phase commit.
