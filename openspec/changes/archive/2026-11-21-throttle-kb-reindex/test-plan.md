# Test Plan — throttle-kb-reindex

Stage: design   Generated: 2026-11-20

Requirement refs: **R1** Engine fingerprint covers only row-producing sources · **R2** Batch commits are time-bounded · **R3** Index passes cancellable + progress (kb-indexing-pipeline) · **R4** Reindex runs in a kb worker thread · **R5** Running reindex can be cancelled · **R6** Reindex progress + job telemetry · **R7** Per-source status endpoint (MODIFIED) (kb-plugin-index-jobs) · **R8** Stale dist rejected (kb-retrieval-eval).

Ids are S1..S83 (stable). Gap answers G1–G5 (owner-accepted, `/tmp/scen-out/decisions.md`) are applied: G1 `jobStatus` stays `running` while cancelling + idempotent cancel (S34, S68) · G2 `progress` absent before first batch (S42) · G3 completed source keeps its stamp (S57) · G4 pre-`ready` load failure falls back in-process, runtime crash fails the job (S44–S46) · G5 200 ms lag target asserted by opt-in `KB_MEASURE=1` tests, not default `npm test` (S73–S76). All gaps are resolved; no open clarifications remain.
Frontend note: no client/rendered-UI surface ⇒ no L3 rows; "frontend-quirk" applies to API-consumer async convergence (stats polling) at L1.
