## Conventions

- **Levels (this repo).** L1 = vitest `packages/*/src/**/__tests__/*.test.ts` (route-level rows use Fastify `inject` with injected callers, per the exemplar). L2 = `qa/tests/*.sh|*.ps1` process smoke (no rendered-UI asserts). L3 = Playwright `tests/e2e/*.spec.ts` against the docker harness; the dashboard port is read from `.pi-test-harness.json` `dashboardPort` (written by `docker/test-up.sh`), never hard-coded. `—` = manual-only.
- **exemplar** = nearest existing test of that category to copy the harness/fixtures from (every path verified with `ls`).
- **Requirement refs** use these codes — D1: `TCB` trust-and-credential-boundaries › Dashboard state is never served to an unproven caller; `FRC1` file-read-containment › anchors/layered; `FRC2` › git-root widening unconditional; `FRC3` › decisions bound to path; `PAG` path-anchor-grants; `DPL` dashboard-plugin-loader. D2: `DMSA`/`DMSB` dashboard-mcp-server (self-drive / prompt answers not MCP); `MTT` mcp-tool-tiers; `CGT` chat-gateway-tier-authorization. D3: `OA1` callback handling; `OA2` OIDC groups; `OA3` public classified; `OA4` open enrolment refused; `OA5` sessions rejected; `OA6` surfaced/audited; `SC` shared-config.
- A `✗/✓` marker in E19 means refused / admitted.
- Row ids stay stable (E#/P#/F#/X#) for the tasks.md fold.
