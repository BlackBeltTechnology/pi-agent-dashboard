Design notes — what changed from v1 and why
  • Two consumers, one candidate list. You asked for independent selection; duplicating the whole list twice doubles the scroll and hides divergence. A two-column matrix gives the same freedom and makes a mismatch a single glance — two dots on different rows.
  • Linked by default. The 95% case is one decision. Unchecking “Keep both in sync” is the deliberate act that unlocks mismatching, so divergence is always chosen, never stumbled into.
  • The two lanes at the top name the consumer, not the tool. “Sessions spawn” / “Server imports” — nobody should need to know that pi and pi-coding-agent are separate registry entries to use this.
  • Colour encodes the consumer (blue = spawn, purple = import) and is carried by the lane border, the column header, the radio accent, and the selected-card ring — so the matrix reads without the header row.
  • Asymmetric apply semantics are stated: spawn takes effect for new sessions, import needs a server restart.
  • Below-floor rows render disabled with the reason, in both columns. Hiding makes users hunt.
  • 44px cells. Each radio sits in a full-height labelled hit area, not a bare 16px input.
