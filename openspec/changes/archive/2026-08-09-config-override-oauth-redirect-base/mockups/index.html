3 · Remove — reverses exactly what add wrote

User control and freedom (heuristic 3) + recognition rather than recall (heuristic 6): the reversal is listed, not implied.

  • publicBaseUrls − https://pi.example.com
  • cors.allowedOrigins − https://pi.example.com
  • auth.redirectBaseUrl → cleared (OAuth falls back to the tunnel address)

Only values this gateway added are removed. Anything you set yourself is left alone.

7 · Remove the last OAuth provider — a lockout, not a disable

Nielsen #5 error prevention. The consequence is irreversible without server access, so the dialog states it in plain language and requires an explicit acknowledgement — not a second “Are you sure?”, which people click through.

Remove google?

1 of 2 sign-in methods.

github stays configured, so you can still sign in.

Remove github?

This is your last sign-in method.

You may lock yourself out

Removing the last provider does not turn authentication off — the login gate keeps running with no way to sign in. Anyone connecting remotely, including you, is refused until the server is restarted.

You can still get back in from this machine, or from a trusted network.

Nielsen #1 visibility of system status. The chain has four tiers, so “is my value valid” is the wrong question — the operator needs to know which tier won. Reachable over loopback precisely because a broken OAuth login means a remote operator cannot authenticate to ask.
