Design notes

  • Placement: the search box sits at the top of the nav rail. While a query is active, the page list is replaced by grouped results (Group › Page header, Section › Field rows). Clearing the query brings the page list back. The page you were on stays open.
  • Scope: searches a static index (page → section → field + keywords + config key), never the DOM, so lazily loaded pages and plugin pages are found too.
  • Matching: the field label (in the active language plus the English fallback), synonym keywords and the config key (e.g. auth.bypassHosts). A match found only by keyword shows a "matches: tunnel" reason line, so the result doesn't look random.
  • Jump: navigates through the existing unsaved-changes guard (requestRailNavigate), scrolls the field into view and pulses an accent outline for 1.6s. Pulse plus outline, so it doesn't rely on colour alone.
  • Changed only: limits results to fields that differ from their default or have unsaved edits (dirty ones get the amber dot), reusing the pi-settings page's existing "changed only" behaviour.
  • Folder settings (/folder/:cwd/settings/:page): same search box in the folder rail. It indexes this folder's pages, Session-card rows and item names (instruction files, add-ons, skills, agents, extensions, prompts, themes) with a local/global scope badge. After the folder results comes a Global settings group (tagged global) listing only global settings flagged as affecting folders, e.g. session defaults, worktrees, archive, card-section defaults. Picking one opens /settings/… with a "← Back to folder settings" chip.
  • A11y: combobox + listbox, aria-activedescendant, an aria-live match count, match highlighting by weight + underline (not tint alone), 44px rows on touch.
