## Context

See proposal.md — Why. The package already holds most of the machinery this change exposes:

- `src/runtime/builders.ts` has `buildBrain/buildLoop/buildSwarm`; `DiagramKind` lists them; but `parse` never emits them and `overrides.slides[].diagram` only admits `scale`/`offset` → unreachable.
- `src/fx/` is the D9 corpus: `<id>.ts` + `<id>.meta.json`, `FxFactory = (ctx: FxContext, params) → FxHandle`, `composeEffects` enforces conflicts/mode/budget, `defaultEffectsFor` routes by a small keyword table then `BY_DIAGRAM[kind]` then `particles`.
- `src/render/index.ts` inlines `dist/runtime.js`, the subset TTF and `__DECK_PROPS__` (base64 GLBs) into `template.html`; determinism = same IR + same cached bytes ⇒ same HTML.
- `src/props/` fetch/embed is hash-pinned; `render` refuses a cache/IR hash mismatch. That rule is the precedent for local effects.
- `src/runtime/palette.ts` `PALETTES` table (3 named + `custom`).
- Runtime navigation (`navTo`, key/click/hashchange) is already on the working tree with `src/__tests__/navigation.test.ts`.

Constraints carried from the v1 design: D1 (overrides are the only writable region; markdown wins over `deck.json`; arrays replace), D3 (self-contained HTML, no network at view time), D9 (deterministic engine, LLM selects; per-deck effect *code* was rejected because it was un-pinned — this change pins it).

## Goals / Non-Goals

**Goals:**
- Every lever the mockup showed is reachable from `overrides` or markdown, with `validate` bounding it.
- LLM-authored effects are first-class yet deterministic: pinned bytes, sandboxed surface, previewable, promotable.
- A bare `build` already looks varied per topic; the Style pass makes it deliberate.

**Non-Goals:**
- Runtime code loading from outside the HTML (no `<script src>`, no dynamic `import()`).
- The configurator editing the embedded IR in place, or persisting anything except in `localStorage` under a deck-hash key.
- Text-to-3D quality: `generate --prompt` is a convenience hop onto the existing image path; geometry quality is whatever the free service returns.
- Layout engines for built diagrams beyond fixed parametric arrangements (no dagre for `bars`/`funnel`).

## Decisions

### D1 — Local effects: `fx/<name>.js` + `.meta.json`, `local:` ids, hash-pinned, inlined as source
Layout: beside `deck.md`, a `fx/` directory; one effect = `fx/<name>.js` + `fx/<name>.meta.json` (same card schema as the corpus, `source: "local"`, `licence` required — the agent writes `"MIT"` for its own code). Reference grammar in `overrides.slides["<id>"].effects[]` and `overrides.effects[]`: `{ id: "local:<name>", sha256: "<hex of the .js bytes>", params? }`. `<name>` = `[a-z0-9-]+`.

Module shape (fixed): plain ES2020 whose **first statement** (after optional leading comments/whitespace) is `export default function (ctx, params) { … return { object?, tick?, dispose } }`, with **no other `export`/`import` statement** (`validate` rejects named exports, imports, and a source that does not start with that prefix once comments are stripped — so the replacement below is anchored, never a search). Local cards are restricted to `kind: background | motion` (the kinds the `{ object, tick }` handle grammar can fulfil; `post`/`material`/`light`/`edge`/`transition` need `pass`/`material` hooks and are rejected for `local:`). Render replaces that leading `export default` with `return`, embeds each referenced source **and its card** in `window.__DECK_LOCAL_FX = { "<name>": { card, src } }` as JSON with `<` escaped to `\u003c` (so `</script>` inside a module cannot terminate the block — the same escaping `render/index.ts` applies to the runtime token). Determinism: source bytes are embedded, so IR + files ⇒ identical HTML; the sha256 pins the bytes. `render` fails (exit non-zero, names the slide and file) on: missing file, hash mismatch, missing card, card invalid, size > 64 KiB.

**One factory contract for corpus and local effects.** `FxContext` grows to `{ THREE, palette, mode, quality, rng, slide: { id, title, kind } }`; `rng` is the runtime's seeded LCG seeded by slide id, `slide` is read-only metadata. Existing corpus effects ignore the new fields (additive TypeScript change; the corpus card test asserts every effect still constructs).

**Sandbox = shadowed globals + static lint + measured offline.** The runtime instantiates a local module as `new Function("ctx", "params", ...SHADOWED, src)` and calls it with `undefined` for every shadowed name, so inside the module these identifiers resolve to `undefined`: `window document globalThis self fetch XMLHttpRequest WebSocket EventSource Image Worker WebAssembly navigator location localStorage sessionStorage indexedDB postMessage setTimeout setInterval requestAnimationFrame queueMicrotask Promise Date performance crypto eval Function importScripts`; `Math` is shadowed by a frozen copy whose `random` is `ctx.rng` so `Math.random()` is deterministic. This is a determinism/offline guardrail, **not a security boundary** — the deck author runs their own deck and `THREE` loaders remain reachable; the design does not claim otherwise. Static lint at `validate` time rejects the identifiers `import` `require` `eval` `Function` (case-sensitive, `\b`-bounded, string/comment-stripped — so `function` in the scaffold never matches) as an early, readable error. `validate` also resolves every `local:` referent when the deck path is known (`fx/` beside the `deck.json`): missing file, sha256 mismatch, missing/invalid card, unsupported card `kind`, size > 64 KiB are **validate errors**, and `render` re-checks the same set before embedding (the deck3d-ir "IR is schema-validated" requirement gains the referent scenario). **Offline is measured:** `check` runs Playwright with `page.route("**/*")` aborting every non-`file:` request and emits an error finding `local-fx-network` `{ slide, effectId, host }` for each attempt — the deck3d-render "Offline open" scenario becomes a checked property for every deck. Runtime wraps `create`, `tick` **and `dispose`** in try/catch; a throw disables that effect for the slide (never the slide), records `{ slide, effectId, phase }` in `__deck3d.effects().errors`, and logs the message to `console.error`. `check` reports `local-fx-error` with `{ slide, effectId, phase }` only — no message text — so the finding is byte-stable and stays inside the geometric byte-equality class; the browser's message is written to stderr, not the report. Attribution of `local-fx-network`: a shadowed `fetch`/`XMLHttpRequest` call throws inside the module and therefore surfaces as `local-fx-error`; requests that *do* fire (e.g. via `ctx.THREE` loaders) are seen by `check`'s route handler, which knows the slide it is currently measuring — the finding is `{ slide, host }`, deduplicated and sorted by `(slide, host)` (slide-level; no per-effect attribution is attempted, and the rule applies to every request the deck makes, not only local effects). Because *whether* a request fires inside the measurement window is timing-dependent, `local-fx-network` joins `contrast` in the class **excluded from report byte-equality** (severity stays `error`); `local-fx-error` and `style-defaults` are inside the byte-equal class.

**Composition:** `composeEffects` gains a `localCards` argument (the cards embedded in `__DECK_LOCAL_FX`), so `local:` ids resolve to a card exactly like corpus ids and enter conflict / mode / cost-budget gating; an unknown `local:` id is still `skipped` with a warning.

Writable-region reconciliation: `overrides` stays the only user-writable region **of `deck.json`**. `fx/` is source input beside `deck.md`, like the markdown itself and the props cache, and is admitted into the render only through a hash pinned in `overrides` — same status as a fetched GLB.

CLI: `fx scaffold <name> [--kind background] [--for <slideId>]` writes the two files (typed stub uses `ctx.THREE`, `ctx.rng`, a `tick`, `dispose`) and prints the override line with the computed sha256; `fx hash <name>` reprints the sha256 after an edit; `fx preview local:<name> [--palette p]` renders a one-slide deck headless to PNG (existing preview path, corpus or local); `fx promote <name> --source <url> --licence <spdx>` moves the pair into `src/fx/`, rewrites `source` and `licence` from the flags (both required: local cards carry `source: "local"`, which the corpus test rejects; the licence must be on the allow-list and is re-confirmed here because scaffolds routinely adapt three.js examples), runs the corpus card test and regenerates `reference/effects.md`.

- *Why*: pinning bytes is what made props deterministic; the same rule makes agent-written code admissible under D9. Escaped inlining keeps D3 (no loader, no network). A fixed `export default` shape avoids a bundler at render time. Shadowing plus a measured network check turns "deterministic + offline" from a promise into a test.
- *Alternatives*: (a) bundle local effects with esbuild at render — heavier dependency in the render path, and `import` would have to be allowed then policed; (b) a JSON "scene DSL" instead of JS — deterministic but far less expressive than what the user asked for; (c) allow `import three` — breaks self-containment and duplicates the bundled THREE.

### D2 — Built diagrams reachable via `overrides.slides[].diagram.kind` + `data`, with parse heuristics
Schema: `overrides.slides["<id>"].diagram.kind ∈ none | brain | loop | swarm | bars | funnel | timeline-rail | globe | orbit-cluster | stack`; `diagram.data?: { labels?: string[], values?: number[] }` — `data` is **atomic**: an override `data` replaces the whole derived `data` object (never deep-merged, so labels and values cannot mix provenance). Derived `slides[].diagram.kind` for a `content` slide without a mermaid block comes from a deterministic table evaluated **in the listed order, first match wins**, on `title + bullets`, word-bounded, case-insensitive: (1) two distinct `\b(19|20)\d\d\b` years across title/bullets, or `\b(timeline|road ?map)\b` → `timeline-rail`; (2) ≥ 2 bullets starting with a number that is **not** a `(19|20)\d\d` year → `bars`; (3) `\b(funnel|pipeline|deal ?flow)\b` → `funnel`; (4) `\b(agents?|swarm)\b` → `swarm`; (5) `\b(loop|cycle|iterat\w*)\b` → `loop`; (6) `\b(LLM|model|brain|intelligence)\b` → `brain`; (7) `\b(global|regions?|geo\w*|trade)\b` → `globe`; (8) `\b(ecosystem|partners?|platform)\b` → `orbit-cluster`; (9) `\b(compute|infra\w*|layers?)\b` → `stack`; else `none`. `title`/`section`/`credits` slides never get a built kind by default; `defaults.autoStyle: false` disables the table (→ `none`). `data.values` for `bars`/`funnel`/`stack` come from bullets with a leading number or percentage (`- 88% adoption` → label `adoption`, value 88); a leading `(19|20)\d\d` year is a label, never a value; absent numbers → equal heights. For `timeline-rail`, labels are the bullets and a leading year becomes the milestone caption. Precedence: a **supported** mermaid block (`flowchart`/`sequence`) present ⇒ mermaid wins; a `diagram.kind` **or `diagram.data`** override on that slide is warned as inert (markdown is source of truth, D1). An **unsupported** mermaid fence (`pie`, `gantt`, …) already yields `kind: none` with a warning; such a slide is treated as diagram-less here — the table applies and overrides are honoured. `builders.ts` gains the six new topologies as parametric arrangements (no layout engine): `bars` (extruded columns on a plinth, labels below), `funnel` (stacked tapering slabs), `timeline-rail` (milestone pucks along a tube, labels alternate above/below), `globe` (wire sphere + arcs between seeded points), `orbit-cluster` (hub sphere + N satellites on tilted rings), `stack` (offset layered slabs). Each returns the existing `{ g, tick, nodes, labels }` so `check` measures them unchanged.
- *Why*: makes the shipped builders and the mockup's promise real with one schema field; heuristics keep a bare build presentable; `data` lets bullets drive the geometry without a new grammar.
- *Alternatives*: (a) a markdown fence like ```deck3d-diagram — a second grammar for what `overrides` already expresses; (b) always require the override — bare decks stay flat.

### D3 — Topic tags drive parse defaults; topic-world backgrounds join the corpus
Cards gain an optional `tags.topic: string[]` with the closed vocabulary `ai | agents | geo | trust | security | compute | data | money | work | timeline | sales | process` (schema-enforced in `meta.schema.json`); the existing free-form `tags.content` list is untouched, so current cards, the catalogue hash test and the `fx list --tag network` scenario are unaffected. `defaultEffectsFor` keeps the v1 precedence as a strict prefix and inserts the topic step exactly where v1 falls to `particles`:
1. v1 keyword table match (`security`→`glyph-rain`, `data`→`data-columns`, …) → that background (unchanged, still outranks everything as today).
2. title-ish slide (v1 `isTitleish`) → `swarm` (unchanged).
3. `flowchart` / `sequence` diagram → `BY_DIAGRAM[kind]` background + edge (unchanged).
4. **new:** unless `overrides.deck.autoStyle === false` — ordered topic keyword table → topic → cheapest `background` card whose `tags.topic` contains it (ties by id).
5. `particles` (v1 fallback).
Consequence: the only slides whose default background changes are those that reach `particles` today. A built kind from D2 (`brain`, `bars`, …) is not a `BY_DIAGRAM` kind; such a slide takes steps 4–5, so topic scenery and the built object are chosen independently. New backgrounds (all `three` primitives, MIT): `globe-arcs` (geo), `city-grid` (work/sales), `neural-mesh` (ai), `vault-glyphs` (trust/security), `server-racks` (compute), `market-tape` (money/data), `orbit-agents` (agents), `paper-stack` (process). Each exposes `density`, `speed`, and where meaningful `count` params, uses the seeded rng, and honours `quality` for instance counts. `hex-grid`/`grid-horizon`/`constellation`/`data-columns`/`glyph-rain` get topic tags retro-fitted.
- *Why*: the user's complaint "only cubes and stars" is the fallback path; routing by topic tag makes the corpus reach the slide without an agent pass, and the tag is what the LLM reads in `fx list`.
- *Alternatives*: embedding-based matching — overkill for ~20 backgrounds; keep the table.

### D4 — Configurator: DOM overlay in the runtime, runtime-only state, exports D1-grammar overrides
`template.html` gains a hidden `<aside id="deck3d-hud">` + a `⚙` button; `src/runtime/hud.ts` binds it. Toggle: gear click or `C` key; `Escape` closes. Controls (lab parity): slide counter `n / N`, scope switch **Deck | This slide**, `mode`, `palette`, `quality`, `transition`, `durationSec`, `backgroundIntensity`, `camera.distance` (slide scope), `labels.size` (slide scope), effects checklist (composed list for the slide; unchecking removes, order kept), autoplay (seconds per slide, off by default). A `●` marks a control whose current value came from an override (deck-level from `overrides.deck`/`effects`, slide-level from `overrides.slides[id]`). Changes apply live: look/camera/labels via existing `rig.applyLook` + slide `cfg`; effects via disposing and recomposing that slide's effect handles (`composeEffects` is already pure over the list). State lives in memory and `localStorage["deck3d:" + meta.derivedHash]`; **the embedded `__DECK` is never mutated**. **Export** downloads `overrides.json` = `{ deck?, effects?, slides: { "<id>": {…} } }` in D1 grammar containing the scalar keys the user changed; because arrays replace, touching a slide's effects checklist exports that slide's **whole** composed list (the HUD shows "pins the effect list" beside the checklist — accepted trade-off, it is exactly what an agent would have to write by hand). `deck3d overrides apply <deck.json> <overrides.json>` deep-merges it into `overrides` under the D1 grammar (objects deep-merge, arrays and `diagram.data` replace) and re-validates. It cannot know which keys the markdown also sets inline; the existing parse warning `inline override … clobbers deck.json value (markdown wins)` surfaces that on the next `build`, and the HUD's export dialog states "markdown inline overrides win over this file". Keyboard navigation **and the `C` toggle** are suppressed while a HUD input has focus. `check` clears the HUD `localStorage` key, ignores the HUD (DOM, not scene graph) and runs with it closed. HUD hidden ⇒ zero visual difference from today.
- *Why*: the lab proved the interaction; exporting D1-grammar overrides keeps the single writable region rule and gives the agent a merge target instead of screenshots.
- *Alternatives*: (a) HUD writes into `__DECK` and re-renders whole slides — mutates the IR contract; (b) a separate "lab" build flag — two artefacts to keep in sync.

### D5 — Palette table growth
Add to `PALETTES`: `midnight` (indigo accent / slate), `ember` (amber / charcoal), `arctic` (cyan / near-white light, deep navy dark), `forest` (moss green / cream), `mono` (white accent / greys, high contrast), `neon` (magenta / black, dark-leaning but with a light variant). Each has `dark`+`light` sets. `ir/types.ts` `Palette` union and `schema.json` enum grow; `fx preview --palette` accepts them; the corpus card test asserts every palette meets ≥ 4.5:1 text/bg in both modes (computed, not eyeballed).

### D6 — Ambient prop search + text prompt generate
`props search <kw> --role ambient` filters candidates to `tris ≤ 2 000` and prints an `ambient` entry template `{ role: "ambient", count: 12, anim: "float", restyle: "palette", size: 0.6 }` (existing `anim` enum; no schema change). `props generate --prompt "<text>" --name <n>` runs a text-to-image hop through a free HTTP image service (URL in `DECK3D_T2I_URL`, default Pollinations; output PNG cached beside the GLB) then the existing `--from-image` path. Network only at generate time; result hash-pinned as today; absent `python3`/`gradio_client` → same non-zero + hint as `--from-image`.

### D7 — `check --style` and the Style pass
Rule `style-defaults` (warn): a slide whose merged `effects` equals `defaultEffectsFor(slide)`, has no props targeting it, and whose `diagram.kind` is the parse default. Static over the IR + files, so deterministic and inside report byte-equality. (`Math.random` needs no rule — D1 shadows it to `ctx.rng`.) `build` prints `style: <n>/<N> slides styled`. SKILL.md tune loop gains step 4 **Style** (per slide: corpus effect *or* `fx scaffold`; built kind for content slides; `props search` per section with roles) and the pitfall "a `check: clean` deck can still be bare — read the style line".

### D8 — Navigation
Already implemented on the tree (`navTo`, clamped, hash-synced, `pointerup` left button, `hashchange`). Folded as the first task with its existing test. Interaction with D4: HUD open ⇒ keys go to the panel, clicks inside the panel do not advance.

## Risks / Trade-offs

- [LLM-written effect throws at runtime and blanks a slide] → try/catch per handle, effect disabled not the slide, `check` error names the override key; skill mandates `fx preview local:` before `build`.
- [Shadowed globals are not an isolate — `THREE.TextureLoader` etc. can still reach the DOM/network] → stated as a determinism/offline guardrail, not a security boundary (author runs their own deck); the property that matters — no network at view time — is *measured* by `check`'s request block and fails the deck with a named finding.
- [Parse-default change alters existing decks' output] → intended (proposal); precisely: a slide changes only if it (a) falls to `particles` today and has no `effects` override, or (b) is a `content` slide without a supported mermaid block, matches the D2 table, and has no `diagram.kind` override — a slide tuned only with `diagram.scale`/`offset` *does* gain a built object. `overrides.deck.autoStyle: false` restores v1 for both; fixture decks re-baseline in-change.
- [Local effect bytes bloat the HTML] → 64 KiB cap per module; counted in the existing 2.5 MB build budget warning.
- [Built-kind heuristics misfire (e.g. "2031" → `timeline-rail` on a title-ish slide)] → title/section kinds excluded; `diagram.kind: "none"` override silences; `check --style` output lists the chosen kind so the agent sees it.
- [Configurator + `localStorage` state confuses `check`] → `check` clears the key before measuring and runs with the HUD closed; state keyed by `derivedHash` so a re-parsed deck starts clean.
- [Palette additions fail contrast in one mode] → computed contrast test in the corpus suite; failing palette cannot ship.
- [Pollinations/HF availability] → generate paths are optional and network-only at authoring time; render never depends on them.
- [`new Function` flagged by CSP-strict viewers] → the deck already inlines its runtime `<script>`; no CSP is set in the HTML. Documented.

## Migration Plan

Schema-additive: existing `deck.json` files validate unchanged (new enum values and optional keys only). **Render output of bare slides changes by design** (topic backgrounds, built kinds); `defaults.autoStyle: false` opts a deck out. Existing fixtures re-baseline their expected HTML in-change. `presentations/business-next-5-years/` is restyled in-change as the proof and copied into `packages/deck3d/fixtures/` as the second fixture (with its `fx/`). Rollback = revert; no persisted state outside the repo except a user's `localStorage` HUD key.
