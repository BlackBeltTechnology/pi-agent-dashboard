## 2. Server — byte-accurate accounting + subagent-aware over-ceiling reduction

- [x] 2.1 Make the size walk BYTE-ACCURATE and BOUNDED (`walkSize` / `exceedsSerializedSize`, and expose a `measureBytes(value, cap)` returning min(total, cap+1)): per string add its actual JSON-serialized byte length (UTF-8 width + escape expansion), NOT `length + 2`; short-circuit a huge string via the code-unit lower bound (`str.length` ≥ remaining budget ⇒ over, do not scan); count a base64 image `data` at its REAL size, not the constant 8; keep early-exit at the ceiling. This is a generic-path change (also fixes the pre-existing image-bearing non-subagent undercount → such events now correctly hit the `{ __truncated }` placeholder).
- [x] 2.2 Add a TYPE-scoped detector `locateSubagentTimeline(event)`: returns the resolved `details` object + its `entries[]` array ONLY when `data.toolName === "Agent"` (or eventType `tool_execution_update`/`tool_execution_end` with a `details.agentId`) AND an array sits at `data.partialResult.details.entries` or `data.details.entries`; else undefined. Return the resolved `details` reference so `description`/`content` are capped on the SAME object. Shape alone (a bare array) MUST NOT match.
- [x] 2.3 Add `capLargeStrings(clonedData)` (step 0): head+tail-`capString` `args.prompt`@`PROMPT_CAP=2_000`, `details.description`@`DESC_CAP=1_500`, and EVERY string reachable inside `data.partialResult.content[*]` — both `.text` AND base64 image `.data` (recurse container blocks e.g. `tool_result.content[j]`) — @`CONTENT_CAP=1_500`. No image preservation on this path. After step 0 no non-`entries` string exceeds its cap.
- [x] 2.4 Add `shrinkEntryToBudget(entry, B)` (D3a, entry-level): while `measureBytes(entry) > B`, head+tail-`capString` the entry's CURRENTLY-largest string leaf (found by one bounded walk) at a shrinking cap down to `ENTRY_FLOOR=256`; stop when `measureBytes(entry) ≤ B` or all leaves at floor. Bounds the ENTRY total regardless of leaf count; caps base64 leaves inside entries. Do NOT rely on `truncateStrings`' per-leaf `maxSize`.
- [x] 2.5 Add `reduceSubagentEvent(event, ceiling)` returning a NEW `{ ...event, data }` with the touched spine (`data`, `data.args`, resolved `details`, `details.entries` reassigned) cloned — NEVER mutates the in-flight event. Constants: `K_HEAD=1`, `K_TAIL=4`, `MID_FLOOR=800`; derived: `E = ceiling − measureBytes(data-without-entries, post-cap) − markerReserve`, `ENTRY_FINAL = clamp(round(E×0.45), 1_500, 6_000)`, `ENTRY_MID = (E−ENTRY_FINAL)/(kept−1)`. Steps: (0) `capLargeStrings` (2.3); (1) compute `E`/`ENTRY_FINAL`, **drop the middle** — keep first `K_HEAD` + last `K_TAIL`, splice removed middle into one `text` sentinel `{ kind: "text", text: "⋯ {hiddenCount} steps hidden ⋯", ts }` (`ts` = first removed entry's `ts`); (2) **shrink intermediate entries** to `ENTRY_MID` via `shrinkEntryToBudget` (2.4); if `ENTRY_MID<MID_FLOOR` decrement `K_TAIL` (fold into sentinel count) and recompute; (3) **shrink the final entry last** to `ENTRY_FINAL`, down to `ENTRY_FLOOR`; (4) **byte-accurate terminal proof** — `measureBytes(reducedData) ≤ ceiling` (NO `JSON.stringify`); if still over shrink further, if unreducible (e.g. empty `entries[]`) **fall back to `{ __truncated }`** (small object, no stringify of the original).
- [x] 2.6 In `createTruncator`, DETECT subagent-timeline events (2.2) on the ORIGINAL event BEFORE the generic per-field pass: for such events SKIP the generic `truncateStrings` pass and route to `reduceSubagentEvent(...)`; all other events keep the existing generic pass + `{ __truncated }` over-ceiling behavior. Confirm the generic `obj.length > 20` clobber can NEVER reach a detected `entries[]` regardless of `maxStringFieldSize`.
