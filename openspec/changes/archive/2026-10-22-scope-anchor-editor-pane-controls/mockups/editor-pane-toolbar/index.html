A · Regroup in place minimal diff

Same three rows. Header becomes three labelled zones: browse (Files + Search) left, document (path + its actions) centre, pane (+ New ▾, ✕) right, separated by dividers. Cheap, but the doc actions still sit above the tab strip, and the mode row stays a separate row.

B · Scope-anchored recommended

Every control sits on the surface it acts on. Pane bar = rail toggle · tabs · + (new tab) · ✕ close pane. Document bar (replaces header path and the Preview/Edit row) = breadcrumb · view mode · reload · open externally · reveal · ⋯. Rail header = Files | Search views, so search results live in the rail, beside the tree, and the document stays visible. Net: 2 chrome rows instead of 3.

Decisions so far

  • D1 — tab strip merges into the pane bar (B over A).
  • D2 — breadcrumb folders reveal in tree; leaf opens the ⋯ menu.
  • D3 — terminal / plugin tabs keep a title line in the document bar, no file actions.
  • D4 — bulk close: tab right-click (Close · Close others · Close to the right · Close all) + ⌄ tab-list menu (all tabs + Close others / Close all). New reducer action closeTabs(paths); one summary confirm only when a terminal would be ended or a handler tab has unsaved edits; otherwise silent. Confirm buttons: Cancel · Close all but these N (risky tabs stay open) · Close all & discard (ends terminals, drops unsaved edits).
  • D5 — Chrome-style Search tabs: the ⌄ pane-bar button opens a popover with focus in a filter field. Matches the displayed label + location (folder, url/live target, "terminal", plugin path; internal prefixes excluded), case- and accent-insensitive; ↑↓ / ⏎ / Esc; per-row ✕; unsaved dot. Empty field = full list + Close others / Close all; with a query the bulk action becomes Close N matching tabs (same D4 confirm). No match → ⏎ hands the text to project file search. Keyboard shortcut: TBD (must not clash with Cmd-P / Cmd-Shift-F).

Behaviour notes (B): breadcrumb segments reveal that folder in the tree; the leaf opens the ⋯ menu. "Open externally" uses mdiOpenInNew (same glyph as the URL-tab "Open in system browser") and "Reveal" is labelled per platform (Finder / Explorer / file manager); both remain gated on capabilities.systemOpen. Below ~640px pane width, Open/Reveal fold into ⋯; "Files" keeps its text label at every width (spec: labelled rail toggle). Protected: tree-toggle, editor-search-toggle, new-terminal-launch, live-preview-launch, tab-open-in-app, tab-reveal-in-file-manager, file-mode-* test ids and Cmd-P / Cmd-Shift-F keep working; only their location changes.
