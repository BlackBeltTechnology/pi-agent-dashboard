## As-built findings (to verify on the board)

| # | Finding | Evidence |
|---|---|---|
| A1 | Raw palette colours (`cyan-400`, `yellow-400`, `green-400`, `red-400`, `blue-500/60`) instead of severity / tint / link tokens; light theme contrast at risk | section rows, result line, chip |
| A2 | Action buttons and status text at 10–11 px, ~22 px high — below the 12 px interactive floor and the tap-target floor | `text-[10px] px-2 py-1` |
| A3 | Status is the raw enum line `schema: X · generated: outdated` — tells the user nothing about what it means or what to do | status `<span>` |
| A4 | All allowed actions render as six equal-weight buttons; destructive **Remove** sits beside **Update** with the same style | action loop |
| A5 | **Remove** is offered while `configured === pi-spec-driven`; the server always refuses that (spec: refused while the config names the schema) | `REMOVE_FROM` ignores `configured` |
| A6 | One busy row disables every row's buttons; the busy row shows no progress | `disabled={busyCwd !== null}` |
| A7 | Result is `Done.` / `Nothing to change.` plus a comma-joined path list; no reminder that the dashboard never commits | `toResult` |
| A8 | Enable dialog mixes a prose sentence with backticks into the monospace path list | `pathsFor("enable")` |
| A9 | Dialog names the action generically (`Update pi-spec-driven?`) and the confirm button repeats one verb; no consequence statement per action | `ConfirmDialog` |

## Proposed design decisions

- **D1 Project card.** One card per cwd: folder basename (field-label recipe) + full path (11 px mono, `--text-secondary`), a **status pill** (severity triple, icon + human label, never colour alone), one plain sentence saying what the state means, the **recommended action** as a secondary button, the rest in a **More actions** menu button (APG menu; Remove last, after a separator, `--tint-red` icon + `--text-primary` label).
- **D2 State → copy → recommended action** (the allowed-state table is unchanged; only presentation). The authoritative order and rows are the numbered table of the `settings-panel` delta (first match wins, incl. the approved "Default schema missing" row); this table is the original design input:

| Status (configured / generated) | Pill (severity) | Sentence | Recommended | In menu |
|---|---|---|---|---|
| other / `none` | Not enabled (neutral) | New changes use `<configured>`. | Enable… | — |
| other / `current`·`outdated` | Disabled, files kept (neutral) | Schema files are still in the repo (`outdated`: "an update is available"); new changes use `<configured>`. Takes precedence over "Update available" (approved). | Enable… | Update…, Remove… |
| pi / `current`, 0 unpinned | Enabled (success) | New changes use pi-spec-driven. | — | Update… (re-stamp), Disable… |
| pi / any, N unpinned | N changes not pinned (warning) | These changes follow the new default because they have no `.openspec.yaml`. | Pin N changes… | Disable…, Update… |
| pi / `outdated` | Update available (warning) | Generated by an older dashboard or CLI. | Update schema… | Disable… |
| any / `newer` | Newer version (info) | Generated by a newer dashboard; left untouched. | — | Disable… / Enable…, Remove… (when not configured) |
| any / `incompatible` | CLI too old (error) | This schema needs a newer OpenSpec CLI. Update the CLI. | — | Remove… (when not configured) |
| any / `conflict` | Version conflict (error) | Stamp is newer in one part and older in the other. Align the dashboard and CLI versions. | — | Disable… / Enable…, Remove… (when not configured) |
| any / `unmanaged` | Not managed (warning) | `pi-spec-driven/` has no dashboard stamp. Adopting regenerates it. | Adopt… | Disable… (when configured) |
| pi / `none` + `missing` | Schema files missing (error) | The config names pi-spec-driven but its files are absent (partial checkout?). | Regenerate… (= Update) | Disable… |

- **D3 Remove gating fix (A5).** Client hides Remove while `configured === pi-spec-driven`, matching the server; no request that is certain to be refused.
- **D4 Per-row busy (A6).** Only the acting row is busy: its recommended button shows a spinner and `Enabling…` (`aria-busy` on the card); other rows stay interactive (the server's per-cwd lock already serializes a cwd).
- **D5 Result callout (A7).** Severity callout under the card: success — "Enabled. 4 paths written on branch `wt-1`. The dashboard does not commit: review and commit them to share with your team." + **Show files** disclosure (mono list); no-op — neutral; partial — warning "Partially applied. Run Enable again to finish." + files; refusal — error with the server message + the current state; 409 — info "Another action is running for this project."
- **D5b Skipped pins (A14, approved).** A Pin result names the changes the server skipped (`data.skipped`): "1 change skipped — already has a `.openspec.yaml`: `<name>`."
- **D6 Dialog per action (A8, A9).** Title names action and project (`Enable pi-spec-driven in a?`); a one-line consequence; **Files written** as a mono list of paths only (prose such as "a `.openspec.yaml` for each change without one" moves to a sentence above it); worktree branch as an info callout ("Files land on branch `wt-1`. The dashboard never commits."); Update shows "Affects N active changes" + up to 5 names + "and K more"; Adopt and Remove carry a warning callout; previous-default select is a full settings field (label, help text). Confirm buttons: `Enable`, `Update schema`, `Adopt and regenerate`, `Pin N changes`, `Disable`, `Remove schema files` (danger only for Adopt / Remove).
- **D6b Shared dialog primary (A13, approved app-wide).** `Dialog.Action` intent `primary` in `packages/client-utils` uses `--accent-solid` (contract primary-button recipe, 5.17:1) instead of white on `--accent-primary` (3.68:1); affects every dialog.
- **D7 Folder chip (A10).** Warning or error severity pill (fg on own bg), MDI alert icon, human label `Workflow schema: update available`, 12 px link text, tap-target from the contract; same states as the card pill.
- **D8 Deep link (A11).** Target card gets a `--focus-ring` outline plus "Opened from folder" caption; focus moves to its heading (`tabIndex=-1`).
- **D9 Empty state (A12).** "No OpenSpec projects yet. A project appears here once the dashboard has polled a folder that contains `openspec/`."
- **D10 Section intro.** Two short sentences: what pi-spec-driven is ("adds an explicit 'Not needed' design skip"), and that per-project actions write files immediately while the default switch waits for Save.
