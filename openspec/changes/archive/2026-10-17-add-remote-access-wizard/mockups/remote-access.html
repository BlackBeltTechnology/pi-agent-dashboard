A · Remote access dialog (clickable)

Opens on status, then four tasks. Each task is a step list; steps whose check already passes show collapsed with a ✓ "already set" and can be reopened. Steps that do not apply to the chosen provider are not listed. Change the machine state on the left to see steps skip.

B · Toolbar icon variants

Replaces mdiQrcode. The button now stands for "who can reach this machine"; the QR is one step inside. A state dot plus a text title (never colour alone), and a count badge when devices are waiting for approval. Pick one row.

Dot: grey = this computer only · blue = LAN · green = internet share up · amber = partly connected · red = failed. Title text carries the same fact, e.g. "Remote access: internet on, 1 device waiting".

D · Decisions

  • Status first, then tasks — Nielsen #1 Visibility of system status; the operator's first question is "can anything reach this machine right now?".
  • Tasks named by intent, not by subsystem ("Share over the internet", not "Setup") — Nielsen #2 Match between system and the real world.
  • Satisfied steps collapse with ✓ and stay reopenable, never vanish — Nielsen #3 User control and freedom; NN/g "Wizards" (show progress and position).
  • Steps that don't apply are omitted (no public name for tailscale/zerotier) — GOV.UK "Don't show users things they can't use".
  • Every step that widens exposure states its consequence before the button (LAN bind = unencrypted http; public URL = request page reachable) — Nielsen #5 Error prevention.
  • One primary action per step; Settings ▸ Network linked as the expert view — Von Restorff / Hick's Law.
  • No default value rendered as fact while loading — every step check shows "Checking…" until its source answers (fixes the dialog's "Off" while loading).
