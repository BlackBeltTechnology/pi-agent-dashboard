Flow agent cards — consolidation directions

Same flow, same five steps, same container widths in every block below — so the only variable is the card design. Data is the real rackinspect:defect-analysis flow (load-ticket, transcribe, fill-form, check-form, assemble). The graph strip stays as-is for context.

What is actually wrong today (measured on the live dashboard, 1280×577):
  • Unequal cards. The grid child is a bare <div data-step> that stretches to the 154px row height, but AgentCardShell has no h-full — so the visible cards are 137 / 154 / 135 / 154 / 154px and their button rows sit at 498 / 500 / 517 / 517 / 517px.
  • Truncated absolute paths eat the widest line of 4 of 5 cards (‹› /Users/bmiller/Projects/Rack…) — irrelevant to any decision a reader is making.
  • Icon buttons are 15×21px — under the WCAG 2.5.8 minimum target of 24×24.
  • Equal height is faked with three &nbsp; pad rows in the card body.
  • The two readable lines fail WCAG AA. Both the waiting: line and the path line use --text-muted, which measures 2.47:1 on the card fill in dark and 2.13:1 in light — against the 4.5:1 that WCAG 1.4.3 (Contrast Minimum) requires for body text. --text-tertiary clears it at 5.58:1 / 5.51:1. Every direction below uses --text-tertiary.

A · Compact uniform tiles recommended 88px

One fixed row height, so every tile is byte-identical in geometry. The card keeps only what a reader needs at a glance — status, name, kind, and one muted line — and its control row becomes a fixed three-slot cluster, so the row's geometry is identical on every card.

  • Fixed height (grid-auto-rows + h-full) replaces the &nbsp; padding hack — same guarantee, in the layout layer where it belongs.
  • The path is gone, not merely truncated: it is already behind the handler button and the graph. Nielsen heuristic #8, aesthetic and minimalist design — drop what the reader does not act on.
  • A fixed three-slot control row, each slot a real 24×24 target (WCAG 2.5.8 Target Size Minimum). An affordance that does not apply keeps its box (hidden, not collapsed) so a click can never land on the neighbouring card.
  • One muted line, priority ordered: waiting: X → last tool → model. Gestalt similarity: the same slot carries the same class of information on every card.
  • Smaller column (minmax(168px, 1fr)) puts 6 per row on a 1060px pane instead of 5.

B · Uniform tiles, keep the grid body chosen 124px

Keeps today's information set — a status line plus the last 2 tool calls — but makes the geometry honest: equal height, bottom-aligned control row, every slot always reserved, and the path reduced to its basename.

  • Body = the last 2 tool calls, newest first (▸ newest, · previous). Two reserved lines, so a step with 0 or 1 calls keeps the same height.
  • Control row: one file button (handler {} for code steps, 📄 for agent steps) + Details. No separate eye icon — Details is the only detail affordance.
  • Equal height via a fixed row height again; the reserved slots do the aligning rather than &nbsp; pads.
  • Path → basename only, on its own monospace line (load-ticket.ts) — no truncation ellipsis mid-word.
  • Cost: at 124px the grid is ~40% taller than A, so fewer agents stay above the fold in a short pane.

C · Dense list rows 28px / row

The most consolidated direction: one row per step, one line each. Five steps cost ~170px instead of ~154px per row of five tiles, and the columns make scanning comparable values trivial — which is what a reader does with a DAG's steps.

  • Best ratio of information to pixels; stays fully readable in a 243px pane with the graph above it.
  • Alignment is structural (one grid template), so raggedness is impossible — Gestalt common region + proximity.
  • Loses the tile/stage look and the per-card "recent tool calls" body; detail moves to the existing Details dialog.
  • Row height 30px keeps every icon target ≥24px (WCAG 2.5.8), which the current 15px icon cannot.
  • Mobile cost: below 480px the fixed columns would crush waiting on to ~1px, so the kind column is dropped there (kind is still carried by the action icons and the graph glyph). Tiles (A/B) need no such rule.
