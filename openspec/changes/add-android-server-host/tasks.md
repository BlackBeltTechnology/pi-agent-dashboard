- [ ] 1.2 Spike (design D4, D5, D7, D8, D6), on the emulator against an isolated server. Record each result in design.md:
  - (a) does `WebViewClient.onReceivedHttpError` fire for a `fetch()` to `/api/sessions` answering `403`;
  - (b) does a main-frame `302` to an off-origin URL reach `shouldOverrideUrlLoading` with `isRedirect=true` before any request to the target;
  - (c) after a session-only cookie copy, then close + `removeSessionCookies` + process kill, does the bearer appear anywhere under `app_webview/` (grep);
  - (d) does a WebView `fetch` carry the HttpOnly cookie after `CookieManager.setCookie`;
  - (e) after Forget's steps, do cookie, localStorage, IndexedDB and Cache Storage for the origin remain;
  - (f) does `NsdServiceInfo.getHost()` return an IP address on API 29+;
  - (g) does Tink Ed25519 verify run on API 29 (fallback: BouncyCastle).
- [ ] 1.3 Spike (design D9, **gate for sections 9 and 13 push rows**), with UnifiedPush connector 3.x in a throwaway app plus the ntfy distributor APK on the emulator. Verify:
  - (a) the connector returns endpoint + `p256dh` + `auth`;
  - (b) `POST /api/push/register {transport:"web-push", deviceToken}` on the isolated server (`push.enabled: true`, `webPush.contactEmail` set) answers `200`;
  - (c) `POST /api/push/test` delivers, and the connector decrypts the `PushPayload`;

  - (e) the ntfy app trusts a throwaway test CA installed as a user CA on the emulator (needed by the CI device harness).
  - On failure of (a)–(d): STOP, write the result into design D9, and re-plan through `plan-proposal`. On failure of (e) only: re-plan the push rows of the device harness.
