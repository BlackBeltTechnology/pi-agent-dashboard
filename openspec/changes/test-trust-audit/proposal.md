## Why

The suite (~1,700 test files, ~18,800 tests) is green but its numbers mislead. Measured on the extension project: files that tests load report 93% line coverage, yet `packages/extension/src/bridge.ts` — 3,630 of the package's 19,189 source lines (19%), the runtime entry point — is imported by no test, sits at 0%, and is absent from the report because no coverage provider is configured. The same "green only because isolated" pattern hides elsewhere: running the client project with `--no-isolate` produces 417 failures from leaked globals and mocks; 14 test files assert on source text rather than behaviour; and the client project spends ~85% of its 109s wall time on fixed per-file cost (fork + jsdom + import — sum of test bodies 118s, median file 66ms). Reproduce: `HOME=$(mktemp -d) npx vitest run --project @blackbelt-technology/pi-dashboard-web --reporter=json` for timings, add `--no-isolate` for the failure count, and `--coverage.enabled --coverage.provider=v8 --coverage.reportOnFailure` (provider temporarily installed) for the 93%. Trust and speed share one root: tests were never gated on what they actually load or leave behind.

## What Changes

- **Honest coverage report.** Add `@vitest/coverage-v8` (root devDependency) and a `test:coverage` script that carries the same `HOME=$(mktemp…)` + `--localstorage-file` wrapper as `test`, reports *unloaded* source files at 0% (explicit `coverage.include` — vitest 4 reports only loaded files otherwise), and still writes the report when a test fails (`coverage.reportOnFailure: true`). Scope: `packages/*/src/**` minus `__tests__`/`test-support`; electron and `scripts/` are out of the coverage scope (stated, not silent). Untested large files (`bridge.ts`, `server/src/session/session-api.ts`, `shared/src/tool-registry/definitions.ts`) become visible.
- **Bridge handler extraction (continues `bridge-decomposition`).** `bridge.ts`'s `export default function (pi)` currently holds: 5 named `pi.on` handlers (`session_start`, `turn_end`, `session_shutdown`, `session_info_changed`, `project_trust`), 2 loops registering `enrichedEventTypes` / `passThroughEventTypes` forwarders, 4 `pi.registerCommand`s, and a 21-branch inbound WebSocket dispatch — all sharing closure state (`sessionReady`, `cachedCtx`, `isActive()`, …). Move the handler bodies, forwarder bodies and dispatch into importable modules that receive an explicit per-incarnation instance object (which references the existing process-global `BridgeState` that survives reload); `bridge.ts` keeps that global state and its cross-reload adoption, the generation counter, `EVENT_BUS_MAP` + the EventBus emit intercept, and the registration wiring; the instance carries its captured generation and derives `isActive()` from it. The moved code touches more closure state than the three named (`subagentTickThrottle`, agent-streaming state that survives reconnect, `sessionId`, `connection`, nonce/offline queue, …): design inventories every closure variable the moved code reads or writes before anything moves, and the instance object covers all of them — no module-level state in the new files. Each extracted module gets a test-plan'd suite. Every test that reads `bridge.ts` source text (10 today under `packages/extension/src/__tests__/`: `bridge-agent-settled-contract`, `bridge-liveness-heal`, `bridge-queue-update-forward`, `command-path-mapping`, `multiselect-dashboard-routing`, `no-session-replacement-calls`, `no-tui-multiselect-arm-regression`, `pi-version-tracker`, `session-register-carries-pid`, `ui-stale-guard` — found by `rg -l 'bridge\.ts' packages/extension/src/__tests__`) is retargeted to wherever its scanned code now lives, never left passing vacuously. No runtime behaviour change.
- **Source-grep test triage.** Classify each of the 14 tests that read a source file and assert on its text: (a) deliberate structural pin with an inline rationale (e.g. `ChatView.notify-gate`, `i18n-orphans`, `engine-purity`, `no-bash-on-windows`, `no-tui-multiselect-arm-regression`) → keep, retarget if its target moved; (b) behaviour that a runtime test can assert → replace; (c) neither → delete with a one-line reason in the commit. No pin is deleted without a replacement or a reason.
- **Global-leak hygiene → cheaper isolation (gated).** Make client tests restore what they mutate (`localStorage` replacement, `getBoundingClientRect` stubs, module-level `vi.mock` state, missing `ThemeProvider`). Move pure client util/reducer tests (no DOM) to the `node` environment via a second project in root `vitest.config.ts` (vitest 4 has no `environmentMatchGlobs`); the jsdom project's include is narrowed so no file runs in both, and the new project imports the shared worker-target module. Then attempt `isolate: false` on the jsdom client project; **adopt only if** three consecutive full runs are green, a run with `--sequence.shuffle` (random file order within forks) is also green, AND the per-file HOME and per-fork localStorage invariants of `parallel-test-execution` still hold — otherwise keep `isolate: true` and land the hygiene + node-env wins alone. Split the three subprocess-heavy `shared` files (`ensure-cli`, `git-checkout-roots`, `openspec-poller-parity`) so they don't serialize a worker.

Out of scope: rewriting `bridge.ts` logic, the e2e/Playwright layer, coverage thresholds as a CI gate (report first, threshold later), and the pinned pi version (`pnpm-lock.yaml` resolves `0.85.1`; `pi-version-tracker.test.ts` passes after `pnpm install`).

Trade-off acknowledged: four orthogonal slices in one change (user decision). Mitigation: design orders them as independently-landable slices — coverage → grep triage → bridge extraction → hygiene/isolation — each green before the next starts.

## Capabilities

### New Capabilities
- `test-coverage-reporting`: `npm run test:coverage` produces a v8 report covering every file under `packages/*/src` (loaded or not), survives test failures, runs under the isolated-HOME wrapper, and states its exclusions.

### Modified Capabilities
- `bridge-decomposition`: `pi.on` lifecycle handlers, event forwarders and inbound message dispatch live in importable modules that never import the entry point; `bridge.ts` delegates through a per-incarnation instance object and keeps the global state, adoption and generation counter.
- Every spec whose requirement text pins moved code to `bridge.ts` gets a location-only delta (behaviour unchanged). Known today (13 specs mention `bridge.ts`; these pin code that moves): `bridge-extension` (`session_start` PromptBus block, cached ctx/registry, multiselect lint-scan target), `command-routing` (`sessionPrompt`, `flow_management` handler), `mid-turn-prompt-queue` (`sessionPrompt` fallback, `edit_followup_entry`), `multiselect-dialog` (`ctx.ui.multiselect` after the PromptBus block), `flow-event-bridge` (intercept stays in `bridge.ts` — delta only if wording needs it), `agent-session-context-injection` (`sessionId` update in `session_start`), `pi-api-feature-detection`, `ask-user-tool`, `model-selector`. The remaining three (`jiti-cjs-transpile-safety` — import graph `bridge.ts → command-handler.ts` unchanged; `markdown-knowledge-base`, `electron-launch-source` — reference `bridge.ts` as entry-point path only) need no delta. Design finalises the list from the closure inventory.
- `parallel-test-execution`: pure client tests run under `node`; the jsdom client project may run `isolate: false` only under the gate above.

## Impact

- Root `package.json` (`@vitest/coverage-v8`, `test:coverage`), root `vitest.config.ts` (coverage block; new `client-node` project importing `vitest.workers`).
- `packages/extension/src/bridge.ts` shrinks; new `packages/extension/src/bridge-handlers/*.ts` (name decided in design) + `__tests__`; 10 source-reading tests retargeted; ~9 spec location deltas.
- `packages/client/vitest.config.ts` (include narrowed; isolate gate); ~40–80 client test files touched for cleanup (417 failing *tests* under `--no-isolate`; the failing-file set, found by the design's measure step, is the upper bound).
- 14 source-grep test files reviewed across electron/client/server/extension.
- `packages/shared/src/tool-registry/__tests__/ensure-cli.test.ts`, `packages/shared/src/platform/__tests__/git-checkout-roots.test.ts`, `packages/shared/src/__tests__/openspec-poller-parity.test.ts` split.
- No public API, protocol, or runtime behaviour change.
