## 2. codegraph-driver (pure CLI adapter)

- [ ] 2.1 Implement `presence(cwd)` → `{ binaryResolved, indexed }` where `binaryResolved` delegates to the **full `resolveBinary` ladder** (2.7) — NOT a bare PATH probe — and `indexed` means **ready**, judged via `status` — NOT a bare existence check for `<cwd>/.codegraph/`, since an interrupted `init` leaves the directory present and an existence check would then report ready, suppress cold-start permanently and serve a partial index. One truth-source only. Verify: unit test asserting `binaryResolved` is TRUE when only a bundled binary or `CODEGRAPH_BIN` override exists and PATH is empty (a PATH-only implementation fails this test).
- [ ] 2.2 Implement spawn helper: argument-vector only (no shell string); env carries `CODEGRAPH_NO_DAEMON=1` **and telemetry disabled** (one place covers every rung and every caller — the desktop/global install path must not ship a phoning-home binary just because task 7.1 only disables it for Docker); a `--` separator before user-supplied query text (argv-only blocks shell metacharacters but NOT a query starting with `-`/`--`, which the CLI would consume as its own flag), a bounded query length and NUL rejection; a **configurable query timeout (default 10s)**; `init` is exempt from wall-clock bounding entirely and is watched for **liveness** instead, so a slow-but-progressing build on a large repo is never killed while a hung one still is. Returns a THREE-way typed result — `{ ok, json }` | `{ unavailable, reason }` (no binary resolved) | `{ error, reason }` (binary ran and failed: malformed query, writer lock, corrupt index) — never throws. Verify: shell metacharacters in query cannot alter the command; **a query of `--help` / `-v` is treated as a query, not a flag**; over-long and NUL-bearing queries are rejected; telemetry env asserted on every spawn; a slow-but-progressing `init` is not killed while a hung one is; **a binary that exits non-zero yields `error`, NOT `unavailable`** (else a real failure masquerades as "not installed" and silently degrades).
- [ ] 2.3 Implement `init(cwd)`, `sync(cwd)`, `index(cwd, {force})` wrappers over the spawn helper. Verify: unit tests assert correct argv per command.
- [ ] 2.4 Implement `status(cwd)` → parse `codegraph status <cwd> --json` into a typed health/freshness struct. Verify: fixture-JSON parse test + graceful handling of missing/malformed output; argv includes `<cwd>`.
- [ ] 2.5 Implement `explore(cwd, query)` → run `codegraph explore <query>` (JSON), returning the passthrough result, `{ unavailable }`, or `{ error }` per the 2.2 taxonomy. Verify: fixture-JSON passthrough test; a non-zero exit surfaces as `error`, not `unavailable`.
- [ ] 2.6 Export the driver surface from the package barrel; add a test/lint asserting driver src imports neither pi (`@earendil-works/*`) **nor kb (`@blackbelt-technology/pi-dashboard-kb`, `…-kb-extension`)**. The kb-independence invariant is the one this change exists to protect, and a pi-only namespace check does not enforce it. **Apply the kb half of the guard to all THREE packages** — driver, extension and plugin — since the spec forbids a kb dependency in every one of them, not just the driver (the pi half stays driver-only; the extension legitimately imports pi). Verify: the lint fails when a kb import is added to any of the three.
- [ ] 2.7 Implement `resolveBinary(cwd)` ladder: (1) `CODEGRAPH_BIN` env/config, (2) bundled `<process.resourcesPath>/codegraph/<exe>` with dev fallback, (3) system PATH probe, (4) self-installed path resolved **directly from the npm global prefix** (`npm prefix -g` + `bin/`) rather than by re-probing PATH — a bare PATH re-probe would both duplicate rung 3 and fail in the common case where the global bin dir is not on the server process's PATH, (5) none → `{ unavailable, installHint }`. Verify: unit tests for each rung's precedence; **rung 4 resolves a binary installed into the npm prefix while PATH is empty**.
- [ ] 2.8 Implement `installViaNpm({ pin })` → run `npm install -g @colbymchenry/codegraph@<pin>` (prefer bundled node/npm when present), then re-probe via the ladder. Handle and distinguish the real failure modes: npm absent; global prefix not writable (`EACCES`); install succeeded but the binary is not at the expected npm-prefix location, so the rung-4 re-probe still fails; running inside a packaged Electron app, where it MUST target a writable user-scoped prefix and never write into the signed bundle. Verify: argv test; each failure mode returns a typed reason and never reports success on an unresolvable binary.
- [ ] 2.9 Validate a resolved candidate before trusting it: bounded `version` probe on the binary returned by any rung; a candidate that fails is skipped in favour of the next rung. Closes PATH-shadowing (any executable merely *named* `codegraph`). Verify: a fake `codegraph` on PATH that fails the probe is rejected and the next rung is used.
- [ ] 2.10 Serialize ALL writers per cwd through one queue. With the daemon disabled CodeGraph allows a single writer per project and a second exits on the writer lock — and `init`, the debounced `sync`, and the freshness reconcile are all writers, so guarding only init-vs-init leaves the other collision pairs open. Verify: a `sync` requested during a running `init` for the same cwd waits (or coalesces) instead of failing on the lock; writers for *different* cwds still run concurrently.
- [ ] 2.11 Detect and recover a stale writer lock (CodeGraph ships an `unlock`): a background `init` killed mid-run leaves a lock that fails every later operation on that worktree, turning graceful degradation into permanent per-worktree breakage. **A live writer's lock must be distinguishable from a stale one** — clearing a lock held by a running indexer risks corrupting the index, so liveness is checked (recorded pid) before any unlock. Verify: a simulated stale lock is detected and cleared and the next operation succeeds; a lock held by a live process is NOT cleared.

## 3. codegraph-extension (pi tool + lifecycle)

- [ ] 3.1 Register the `codegraph_explore` native tool via `pi.registerTool` (input: query; description that routes code-structure/who-calls/blast-radius questions here). Verify: tool listed; returns driver result.
- [ ] 3.2 Cold-start as a BACKGROUND job: on `codegraph_explore` in a cwd with no `.codegraph/`, return built-in-tools guidance **immediately** and schedule `init(cwd)` once in the background; never block the tool call on the full-repo parse. A per-cwd in-flight guard means a second explore during a running `init` spawns nothing (SQLite is single-writer). **Judge index completeness by `status`, not by directory existence** — the guard is in-memory, so a restart mid-init leaves `.codegraph/` present but partial, and an existence check would report it ready and serve a partial index as whole. FAILED-init policy: a background init that fails (binary vanished, disk full, non-repo cwd) is retried **once**, on the next explore after a **5-minute cooldown**; a second failure is recorded and surfaced on the settings surface rather than retried again — never a per-explore spawn loop, never permanently latched with no path to recovery. Verify: the call returns without awaiting init; cold cwd triggers init exactly once; N concurrent explores spawn exactly one init; **an interrupted init is reported not-ready**; a failed init neither loops nor latches.
- [ ] 3.3 Graceful degradation: binary absent or index absent → tool returns clean "use built-in tools" guidance, never errors. Verify: tests for both absent cases.
- [ ] 3.4 Own debounced `tool_result` write-hook: non-`.md` source writes schedule a per-cwd debounced `sync(cwd)` — debounce **configurable, documented default 800ms** (matching kb-extension's `DEFAULT_DEBOUNCE_MS`) — and coalesce overlapping runs (clone kb-extension reindex debounce/inflight structure). **Path exclusions are load-bearing:** skip `.codegraph/`, `.git/`, `node_modules/` and build outputs — `sync` itself writes `.codegraph/codegraph.db{,-wal,-shm}` inside the cwd, so without the exclusion the hook retriggers itself in an unbounded loop. NOTE: kb-extension's `isNudgeEligible` already matches every non-markdown path, but it is a DOX-nudge predicate that excludes no directories — do not reuse it as the sync gate. Verify: debounce + coalesce unit tests; `.md` writes do NOT trigger sync; **a simulated write under `.codegraph/` schedules NO sync** (regression test for the feedback loop).
- [ ] 3.5 Per-cwd state map + cleanup on cwd removal (mirror kb-extension eviction). Verify: removed cwd is a safe no-op.
- [ ] 3.6 Extract pure lifecycle logic into a no-pi-imports module (like `reindex.ts`) for testability; wire it in `extension.ts`.
- [ ] 3.7 Bounded freshness reconcile before serving explore. The write-hook sees only **agent** writes — IDE edits, `git checkout` and rebases are invisible and the daemon is banned, so without this staleness is unbounded and surfaces as confidently-wrong blast radius rather than an error. No fixed latency budget up front: measure the p95 added per query during implementation and record it as the regression baseline. Verify: a file changed out-of-band (not via a tool write) is reflected on the next explore; the reconcile degrades to serving the stale index rather than erroring; the observed p95 is recorded.
