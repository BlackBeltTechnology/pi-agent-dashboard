# Test Plan — device-key-mutual-check

Stage: design (HARD gate)   Generated: 2026-05-17   Status: final — all gap questions answered (see `## Decisions`).

Routing used: L1 vitest `packages/*/src/**/__tests__/*.test.ts`; L3 Playwright `tests/e2e/*.spec.ts` against the docker harness (port = `DASHBOARD_PORT` from `tests/e2e/lifecycle.ts`, derived from `.pi-test-harness.json` by `docker/test-up.sh`, never hardcoded); Electron main-process logic = L1 in `packages/electron` with injected fakes; `electron` = packaged app only; aesthetics = manual-only.

Harness facts the L3 rows must respect (from `tests/e2e/lan-knock.spec.ts` header): every device context reaches the server from one docker-gateway address → knock limiter treats them as one source (a deny starts a 10-minute cooldown; run serially, deny LAST) and device-status limiter (60/min/peer) would be shared too, so the flood test is L1 only. Harness origin `http://127.0.0.1:<port>` is a secure context, so Ed25519 WebCrypto is available there; the plain-http/no-WebCrypto path is L1 (jsdom with `crypto.subtle` undefined).

Notation: `fpA`/`fpB` = server fingerprints `sha256:<43 b64url>`; `dk:` ids are `dk:` + 12 chars; "proof" = `{ deviceNonce, pub, sig }`; "unverified" = body `{"status":"unverified"}`.

## Decisions

All eight gap questions were answered with the recommended option and folded into the change specs and design.

- G1 — client timeout: 2 s for the identity challenge and 2 s for device-status, each (X3).
- G2 — credential held, key held, check `unknown`: row reads "Status unknown" until the verifying call returns (E11, X4).
- G3 — `POST /api/pair/device-key` with a bad signature, malformed field or replayed/unknown/expired nonce: 400 (E10).
- G4 — purge at age ≥ 90 d; "Deleted for good in N days" rounds up, under 24 h reads "1 day" (E16, F4).
- G5 — revoke of an unknown or already-revoked id: 404; a revoked store of valid JSON but wrong shape is set aside like unparseable JSON (E14, X17).
- G6 — companion signature verified over the origin exactly as sent; stripping only for storage/display (E7).
- G7 — Delete now confirmed in a dialog naming the device; Undo on 404/409 shows inline "No longer available" and refreshes (F4).
- G8 — browser pair link omits the companion when the fragment would exceed 512 chars (F3).
- G9 — expired browser devices (final human decision): `expired` is a fourth device-check status, `revoked` wins, the row reads "Access expired" with "Pair again", a `401 bearer_expired` at a proven route discards the credential and the device key together, Undo never extends expiry, revoke invalidates the grace bearer, rotation keeps the key (E19–E22, X19, X20); revoke, restore, delete-now and purge share the existing audit line shape (E23); proof, bind and knock go only to the literal that proved the pin (X21).
- Draft cross-references that named no real decision were dropped: E4 exact-60.000 s TTL boundary is not asserted; E8 has no route-level fifth-companion path.
