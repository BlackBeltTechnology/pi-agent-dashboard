## 2. Effective view

- [x] 2.1 `core/effective-view.ts`: compute the kept global set through the shared `keptGlobalOf()` (no `piError`, first-wins on collision), display merged exposure aliases resolved, merge valid overrides into the global row with `projectOverride: { path, keys, raw }`, and report orphan, bad-key and invalid overrides as folder rows with pi's message. Skip clash and project-`auth` checks for overrides. Keep the untrusted handling (design D1–D3).

## 3. Writer, service, routes

- [x] 3.1 `config-writer.ts` `setProjectOverride(name, patch, scope)`: read-modify-write (unspecified keys preserved), `null` = delete key, empty → delete entry, a no key change touches no file, `no-global-server` when the shared `keptGlobalOf()` has no base (`unparseable` takes precedence), merged validation via `classifyProjectEntry`, no clash or `auth` checks (design D1/D4/D5). Expose it from `service.ts`.
- [x] 3.2 Route project-scope `setEnabled` for global-sourced servers through the smallest-write table, with no file created on a no-op (design D4). Delete the copy path and new `omitted` results. Keep `needs-choice` for whole-entry copies.
- [x] 3.3 `saveServer`: refuse entries for which `isProjectOverride` is true at project scope, and renames where either side is an override (`invalid-entry`, pointing to the project-override route). `collisionCandidates`: ignore `isProjectOverride` folder entries at global scope.
- [x] 3.4 `convertLegacyCopy(name, scope)`: keep only override keys that differ from global, delete when none remain, return the previous raw entry
- [x] 3.5 `src/server/routes.ts`: `PUT …/servers/:name/project-override` (validate body types and enums before `parseScope`; project scope only) and `POST …/servers/:name/convert-to-override`, both behind `guard` and known-folder admission (design D6)
