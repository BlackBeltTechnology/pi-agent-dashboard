# Test Plan — add-windows-process-identity

Stage: design   Generated: 2026-10-26

Decisions applied (all accepted):
- Q7 — a transient probe or helper failure is `unconfirmed`; the existing give-up tracker retries up to 3 sweeps. A start-time mismatch is `refused-identity` (terminal).
- Q8 — `unknown` on a Windows server keeps today's operator-path signal (already reflected; no new row).
- W1 — `error` ⇒ `unconfirmed`; `mismatch` ⇒ `refused-identity`; `absent` ⇒ confirmed only after a liveness re-check.
- W2 — unattended WSL with liveness `unknown` ⇒ `unconfirmed`; `verifyAndKillWsl` not run.
- W3 — force-kill / shutdown with `error` ⇒ `success:false` "not terminated" (shutdown: unconfirmed + orphan signal); `absent` ⇒ success, already gone.
- W4 — the WSL check takes `minAgeMs` (server-computed from `pidRecordedAt`), not an absolute time.
- W5 — the limiter (2) covers probes, verify-and-kill and liveness; `timeoutMs` excludes queue wait.
- W6 — invalid pid, distro, `maxStartMs`/`minAgeMs`, a non-win32 platform, or missing/relative `SystemRoot` ⇒ probe `null`, verify `error`, liveness `unknown`; nothing spawned.
- W7 — scripts force `LC_ALL=C` and print an explicit marker; absence only by marker.
- W8 — pgid read from `/proc/<pid>/stat`, no `ps`.
- W9 — enforcement test targets probe/signal tokens; allowlist `extension/process-scanner.ts`, browser-plugin `process-identity.ts`, the tmux spawn in `process-manager.ts`.
- W10 — marker match is exact (trimmed); anything else ⇒ `error`.
- W11 — handle-pin CI check: the pinned arm sees 0 reuse across 500 spawns; the control arm is logged, not gating.
- W12 — verify-and-kill exec timeout is `timeoutMs + 10 s`.
- W13 — target type is `{ kind: "host" } | { kind: "wsl", distro }` everywhere.

Conventions in every row: `T = 1_700_000_000_000` (recording time), `tol = IDENTITY_TOLERANCE_MS = 2000` (`session-terminator.ts:31`), pid `4242`, distro `D = "Ubuntu-22.04"`, `SystemRoot = "C:\Windows"`. Helper results: `killed|mismatch|absent|error`; liveness `alive|absent|unknown`. Terminator outcomes: `confirmed-dead|unconfirmed|refused-identity|no-identity`. "No signal" = `killProcess`, `verifyAndKillWindows`, `verifyAndKillWsl` all uncalled for that pid.

Harness (verified to exist):
- Platform helpers → `packages/shared/src/__tests__/platform-process.test.ts` (injected `platform`/`exec`/`kill`; real `spawn` children).
- Terminator → `packages/server/src/spawn-process/__tests__/session-terminator.test.ts` (fake process table `World`, `createSessionTerminator` deps).
- Force-kill → `packages/server/src/__tests__/force-kill-handler.test.ts`; shutdown → `packages/server/src/browser-handlers/__tests__/shutdown-terminator-delegation.test.ts`.
- Registry probe → `packages/server/src/__tests__/headless-pid-registry.test.ts`.
- Give-up → `packages/server/src/embed-lifecycle/__tests__/reclaim-give-up.test.ts`, `idle-reaper.test.ts`.
- Repo invariant → `packages/shared/src/__tests__/no-direct-process-kill.test.ts` (walk + regex + fixture pattern).
- `ci` level → new job modelled on `.github/workflows/ci-gateway-platform.yml` `windows:` job (`windows-latest`, `pwsh`, `QA_REPO_ROOT`); real-process driver `qa/tests/53-windows-process-identity.ps1` modelled on `qa/tests/45-windows-reclaim-refused.ps1` (tsx probe file + JSON verdict lines). WSL arm via `Vampire/setup-wsl` (distro `Ubuntu-22.04`).
