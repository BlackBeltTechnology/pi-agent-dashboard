# Implementation notes

Deviations from the planned file names and the reasons. None weakens a scenario.

- **Test files.** `tasks.md` names `file-endpoint.test.ts` as the exemplar for most file-route tests, but that file is a pure path-logic unit test with no `inject` harness. The decision-table tests for the file-family routes live in the new `packages/server/src/__tests__/file-cwd-admission-routes.test.ts`; package + canvas-types in `package-canvas-cwd-admission.test.ts`; `watch_files` in `file-watch-manager.test.ts` (handler extracted to `watch-files-handler.ts` so it is testable); the editor-pane save in `file-write-binary.test.ts`; resources toggle in `resource-activation-routes.test.ts`; groups in `openspec-group-routes.test.ts`; add-ons in `addons-folder.test.ts`; the exists prompt flows in `access-grant-denial-sites.test.ts`; live-preview gates in `live-preview-policy.test.ts` and `file-cwd-admission-routes.test.ts` (`gateFilePath`).
- **Test-first order.** Group 1, the `friendlyReadError` mapping (5.8) and the first run of the existing route suites followed fail-first (the new assertion failed before the change, then passed). For the file / package / canvas / group routes the helpers were refactored first and the decision-table tests written after, so those tests were not seen failing against the old code; the pre-change behaviour they replace (exact session membership, no gate on package / canvas / resources) is what the existing suites exercised.
- **`GateWire` + `lib/file-cwd-admission.ts`.** `admitFileCwd` lives in a shared lib module (not `file-routes.ts`) because `file-write-binary-routes.ts`, `grep-routes.ts`, `watch-files-handler.ts` and the package / canvas / resources routes import it and `file-routes.ts` already imports `file-write-binary-routes.ts` (a cycle otherwise).
- **`getWorkspaces` is optional** on `KnownFolderSources.preferencesStore` so a minimal store (many route tests) contributes no workspace folders; the production `PreferencesStore` always has it.
- **`null` cwd = absent** on the optional-cwd routes (md routes, packages, canvas-types, resources toggle). The design names `undefined` and `""`; a JSON body can carry `null`, which previously also meant "no cwd", so it keeps that meaning (it never selects anything the absent value does not).
- **Existing tests updated** for the additive `code: "cwd_unknown"` (raw route, resolve-mention, exists deny body, the "gate refusals never leak their internal code" tests now assert the internal numeric status `code` is still not leaked and the wire code is the string) and for the new admission (`package-routes.test.ts`, `resource-activation-routes.test.ts`, `live-preview-policy.test.ts` pass a known set).
- **Bench output** goes to stderr (`[bench]` lines) because the suite stubs `console.log`.
- **E2E #F2** (`tests/e2e/pinned-folder-preview.spec.ts`) was authored against the folder-pane deep link `/folder/:enc/view?path=` and is run in the docker harness at ship time.
