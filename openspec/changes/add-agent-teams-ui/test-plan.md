Notes
- Column set: `input` = data/state (perf: workload, error: fault), `trigger` = action/condition (perf: metric + threshold), `expected observable` = measurable fact (perf: window). `exemplar` = nearest EXISTING test of that category (path verified to exist).
- `technique`: EP / BVA / DT (decision table) / ST (state-transition) / SC (state-convergence + invariants) / FI-d / FI-a (fault injection delay/abort) / PBT (property/fuzz) / perf.
- Requirement refs: CR = agent-teams-chat-rendering, TV = team-view, SB = session-badge, LS = ui-live-state, AC = ui-access; D# = design decision; B# = decisions-sheet item. Spike refs: A = Phase A (faux), B = Phase B (real models).
- L1 = vitest, L2 = `qa/tests/*.sh` (no rendered-UI asserts), L3 = Playwright vs docker harness (port from `.pi-test-harness.json` `dashboardPort`, never :18000). Dual-leg rows (`L1+L3`, `L1+L2`) are one scenario asserted at both levels and fold to ONE task line.
- Multi-session mechanics (stop settle, coalesced notices, no auto-claim after stop) use L1 + pi-ai `fauxProvider` as in `/tmp/agent-teams-plan/spike-code/` (core's runtime is the unit under the wrapper).
- Scenarios whose subject is core (`abortMember`, `teamDelete`, claim, coalescer, `parseEnvelope`) belong to core's plan; here only the UI wrapper's observable is asserted.
- Owner decisions applied: every recommended option accepted (A1, A5, A6, A10, A12; B22–B49, B83, B102). Thresholds follow A12: structural gates in CI, wall-clock numbers non-gating.
