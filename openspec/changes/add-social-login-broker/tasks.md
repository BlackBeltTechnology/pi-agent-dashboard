## 1. Social-login broker

- [ ] 1 D26 `social-login` broker plugin (oidc-provider AS; GitHub + Google + generic OIDC upstreams; one issuer). Prereq: `harden-trust-and-credential-boundaries` B5 + B25 landed.
  - [ ] 1.a SPIKE (decides before production code): mount `oidc-provider` from a dashboard plugin via `@fastify/middie`; root `.well-known/{oauth-authorization-server,openid-configuration}` resolve for the issuer path; public AS routes (`/authorize`, `/token`, `/jwks`, `/interaction/*`, `/reg`, device endpoints) pass the network guard + D24 floor + route→tier map while every other `/api/*` stays gated; issuer/callback origin from configured `publicBaseUrl`, never `Host`. Outcome recorded in D26; if a plugin cannot mount it, fall back to a host seam (core mounts, plugin configures) and say so.
  - [ ] 1.b Upstream interaction: login page (one button per enabled upstream), GitHub (plain OAuth2: numeric `id`, verified email, orgs/teams via `read:org`), Google + generic OIDC (`openid-client`, `email_verified`, `hd`); state bound to interaction uid; allowlist → tier, no match ⇒ refused (tests first, fake GitHub + fake OIDC upstream).
  - [ ] 1.c Accounts: JSON adapter (grants/sessions/clients) + user/link table; signing keys + config `0600`; `findAccount().claims()` → `sub,name,email,tier`; allowlist re-checked at refresh.
  - [ ] 1.d Resolver + D22/D25 descriptor (`loginUrl`,`tokenUrl`,`logoutUrl`,`postLogoutUrl`,`label`) so the browser path reuses the core login page unchanged.
  - [ ] 1.e Settings section: per-upstream enable / client id / masked secret / copyable callback URL / allowlist→tier; ephemeral-base warning; arm only after a successful test sign-in by an allowlisted `operate` user; one-shot import from legacy `auth.providers`.
  - [ ] 1.f Matrix scenario K (fake GitHub + fake Google) incl. account linking (GitHub then Google ⇒ same principal) and non-allowlisted refusal.
  - [ ] 1.g Follow-ups (separate items once 1.a–f land): Electron RFC 8252 loopback PKCE login replacing remote pairing; CLI device flow (`pi-dashboard login`); MCP OAuth (RFC 9728 metadata on `/mcp` 401 + dynamic registration) replacing hand-minted MCP tokens.
