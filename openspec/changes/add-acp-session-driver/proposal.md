## Why

The dashboard can only supervise pi. Every session path — spawn, register, heartbeat, prompt, abort, stream, interactive prompts, queue, replay — is built around the pi bridge extension speaking the bridge WebSocket protocol (`packages/shared/src/protocol.ts`). The Agent Client Protocol (ACP) is now the de-facto stdio contract for coding agents (25+ agents in the ACP registry, including querymt's `qmtcode --stdio`), and ACP v2 (Draft; TS SDK `@agentclientprotocol/sdk` ≥1.3 experimental API) converges on shapes we already built ad hoc (prompt acceptance ack, id-keyed upserts, explicit foreground state, replay cursors). Supervising any ACP agent widens the dashboard beyond pi; doing it by **impersonating a bridge** reuses every existing server and client path instead of re-implementing them server-side (a server-side driver was rejected in doubt-review: prompt origination, replay, queue, registration and persistence are all bridge-owned). Research: `docs/research/querymt-agent-backend.md` §5.

## What Changes

- New **transport-agnostic ACP adapter core** in `packages/server/src/acp-bridge/`: bridge-protocol messages on one side, ACP on the other (the server's real session seam is the `PiGateway` interface — `event-wiring.ts` and ~30 modules never touch a socket). Two hosts, chosen per agent by `durable`: **in-process** (default) via a new `PiGateway.attachLocalConnection` running the same per-connection handling as a WebSocket bridge (ends on server restart), or **out-of-process** under the rpc-keeper via `packages/server/bin/acp-bridge.mjs` (jiti) over WebSocket (survives restart). The core is an **ACP client** toward one child agent (JSON-RPC 2.0 NDJSON over stdio, argv-only, allowlisted env) and a **bridge** toward the local dashboard gateway (existing protocol: `session_register` + heartbeat, `event_forward`, `prompt_received`, `queue_update`, `models_list`, `commands_list`, `prompt_request`, `replay_complete`), handling the full server→bridge message union exhaustively.
- New shared, typed **ACP v2 session-update model** (`packages/shared/src/acp/`): v2 update variants with open-enum preservation; **v1 → v2 normaliser** (v1 = today's agents); **v2 → pi-shaped `DashboardEvent` adapter** (segment grouping, live thinking deltas, stop-reason vocabulary) so ACP sessions render through the unchanged client reducer. v2 wire requested only behind `acp.protocolV2`.
- Adapter owns ACP session state in-process: prompt queue (existing follow-up semantics), echo suppression, permission prompts (`session/request_permission` → interactive `select`), config options (`model` / `thought_level` ↔ existing model + thinking controls), commands, and an append-only event log replayed on reattach after a dashboard restart.
- Server: `acpAgents` + `acp` config parsed, env redacted on read and preserved on write; WS `spawn_session` and REST spawn accept optional `agent` → forced headless keeper spawn with `SessionOptions.childCmd` (no pi resolution / pi argv / pi preflight); `driver: "acp"` accepted on register, persisted in session meta, exposed in payloads; pi-only operations rejected for ACP sessions. Additive protocol members: `SessionRegisterMessage.driver?`, `BridgeDiagnosticEvent` `"acp"`, `CommandInfo.source` `"acp"`. Client: spawn-dialog agent picker; pi-only controls hidden for `driver: "acp"`.
- Out of scope (deferred): northbound ACP endpoint; projecting pi sessions into the v2 model; v2-native reducer; pi-acp coexistence; ACP remote transport; resuming an ended ACP session; generated per-session agent config (querymt TOML injection); per-message token/cost stats; plan UI beyond the debug raw-event view; Windows `.cmd`/`.bat` agent commands; filesystem isolation of same-user agents.

No **BREAKING** changes: every protocol/API change is an optional field or an added union member; the rpc-keeper is unchanged; spawns without `agent` take identical code paths.

## Capabilities

### New Capabilities
- `acp-agent-sessions`: ACP agent registry/config (redact + preserve), spawn routing (WS + REST), the acp-bridge adapter (registration, heartbeat, initialize/negotiation, prompt/queue/echo/cancel, permissions, config options, commands, server-message coverage, reattach replay), child-env allowlist, refused client methods, untrusted-output handling, `driver` persistence and degraded-feature contract.
- `acp-update-model`: typed ACP v2 session-update model, v1→v2 normalisation, open-enum preservation, and synthesis of pi-shaped `DashboardEvent`s for the existing client.

### Modified Capabilities
_None._ Only additive optional fields / union members; no existing requirement's behaviour changes for pi sessions.

## Impact

- **Code**: `packages/server/src/pi/pi-gateway.ts` (extract per-connection handler, add `"local"` transport + `attachLocalConnection`); new `packages/server/src/acp-bridge/` (`acp-session-adapter.ts`, `local-bridge-socket.ts`, `local-host.ts`, `main.ts`, `gateway-client.ts`, `acp-connection.ts`, `session-state.ts`, `event-log.ts`, `child-env.ts`, `server-requests.ts`) + `packages/server/bin/acp-bridge.mjs`; new `packages/shared/src/acp/` (`update-model.ts`, `normalize-v1.ts`, `to-dashboard-events.ts`); `packages/shared/src/config.ts` (`parseAcpConfig`), `protocol.ts` / `browser-protocol.ts` / `rest-api.ts` / `types.ts` / `session-meta.ts` (additive fields); server `browser-handlers/session-action-handler.ts`, `session/session-api.ts`, `spawn-process/process-manager.ts` (+ preflight), `pi/pi-gateway.ts` (register normaliser), `session/session-to-meta.ts`, `config-api.ts` (redact + preserve), pi-only-op guards; `packages/client/` spawn dialog + control hiding.
- **Dependencies**: `@agentclientprotocol/sdk` (Apache-2.0) added to `packages/server`, pinned minor — shipped by the existing npm and Electron server bundles. `packages/shared` gains no dependency.
- **Config**: `acpAgents`, `acp.{protocolV2, spawnTimeoutMs, requestTimeoutMs, maxLineBytes, eventLogMaxBytes}` in `~/.pi/dashboard/config.json`; absent → feature invisible.
- **Compatibility**: pi sessions unchanged. ACP sessions lack pi-only features (flows, subagents, extension UI panels, kb/memory/roles plugins, fork/tree, reload, steering, on-demand transcript, file listing, terminal commands, context-budget, token/cost stats). Older servers ignore `driver` in `.meta.json`.
- **Rollback**: remove `acpAgents` + restart; running adapters end naturally; `~/.pi/dashboard/acp/` can be deleted.
- **Security**: argv-only launch, no shell; allowlisted child env with forbidden-key filter on configured env; config API redacts and preserves agent env; agent session id never used as a path; bounded line parsing, no eval; no fs/terminal delegation; permission prompts are the only agent side-effect the dashboard mediates. Same-user file access by the agent is out of scope (documented).
