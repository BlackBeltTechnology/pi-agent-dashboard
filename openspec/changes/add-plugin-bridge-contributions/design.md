## Context

- Bus forwarding is subscription-based: one `pi.events.on(channel)` per channel in `FLOW_EVENT_MAP` + `SUBAGENT_EVENT_MAP` + `extraMaps` (`packages/extension/src/flow-event-wiring.ts:120-157`); `extraMaps` is never passed. Called once from `initBridge` at extension load (`packages/extension/src/bridge.ts:3066`).
- Gate `forwardBusEvent` (`flow-event-wiring.ts:70-93`): subagent channels forward live only when ready+active+connected, else `buffer()` (latest-wins per `agentId`, `SubagentFrameBuffer`, `maxAgents=64`); other channels forward when ready+active, else drop.
- Plugin bridges announce themselves by emitting on the bus (`packages/flows-plugin/src/bridge/index.ts:26-31` → `prompt:register-adapter`); the main bridge attaches those listeners inside `session_start` (`bridge.ts:3415`). No "bridge ready" event exists, so an emission before the listener is lost.
- Plugin bridges are registered for every discovered manifest regardless of `enabled` (`packages/server/src/server.ts:4064-4071`, `packages/shared/src/plugin-bridge-register.ts:278`); the toggle route does not deregister (`plugin-activation-routes.ts:228-300`), contrary to `openspec/specs/dashboard-plugin-loader/spec.md` "Disable removes managed entries from both registries".
- Producer ≥ 0.3.0 (`../pi-dashboard-subagents/CHANGELOG.md` `[0.3.0]`) omits `entries` from progress ticks, emits `subagents:entry` `{v,agentId,toolCallId,index,entry,blockId?}`; 0.4.0 (`CHANGELOG.md` `[0.4.0]`) adds `subagents:delta` `{v,agentId,toolCallId,blockId,kind,offset,text,final}` — contiguous per block, exactly one `final:true` before the block's entry, ≤ 4 pieces/s (`../pi-dashboard-subagents/extensions/events.ts:120-160`, `agent.ts:631-700`). Terminal frames still carry full `entries`.
- Server stores any `eventType` (no allowlist, `packages/server/src/event-wiring.ts:1021-1067`). Oversized subagent carriers are head(1)+tail(4)-reduced with a `⋯ N steps hidden ⋯` sentinel (`memory-event-store.ts:948-955,1119-1200`, entry `createTruncator` `:1227`, ceiling 256 KiB `:617`).
- Client: unknown events fall to the reducer `default` arm and render as raw JSON rows (`packages/client/src/lib/chat/event-reducer.ts:2993`). `readSubagentDetails` keeps existing entries when an incoming `entries` is empty (`:549-578`). Healed tool rows get `SUPERSEDE_SENTINEL_BODY` (`:624`, `:645`, `useStaleToolReconcile.ts:262`); `AgentToolRenderer` renders the tool `result` prop (`AgentToolRenderer.tsx:433,500,532`) though `SubagentState.result` exists (`packages/subagents-plugin/src/client/types.ts:40`). `MinimalChatView` stringifies non-string tool output (`packages/client-utils/src/minimal-chat/MinimalChatView.tsx:121-125`).
- Roles: `roles:get-all` fills `data.roles` with the effective role map (`packages/extension/src/role-manager.ts:271-281`). pi `before_agent_start` exposes mutable `systemPromptOptions` with `toolGuidelines: Record<string,string[]>` (pi `dist/core/system-prompt.d.ts`, `NormalizedBuildSystemPromptOptions`; docs `extensions.md:103`). roles-plugin has no bridge entry.

## Goals / Non-Goals

**Goals:** plugins declare forwarded channels without core edits; exact, growing live timeline + in-progress block for producers ≥ 0.4.0; no `steps hidden`; healed card shows the real result; role guidance appears only with the roles plugin enabled and roles present.
**Non-Goals:** moving `FLOW_EVENT_MAP` / `SUBAGENT_EVENT_MAP` out of core (follow-up); plugin-provided client reducers; changing the producer; changing the card ticker.

## Decisions

**D1. Declaration = bus event, not manifest.** A plugin bridge emits `dashboard:register-event-forward` with `{ pluginId, channels: Record<channel, { as?: string; delivery: "live"|"latest"|"stream"; key?: string }> }`. Matches the existing `prompt:register-adapter` pattern and needs no server round-trip; works for third-party plugins. Manifest-declared channels rejected: the main bridge does not read plugin manifests and would need discovery inside pi.

**D2. Handshake.** The main bridge attaches the declaration listener in `initBridge` (load time, next to `registerEventBusForwarding`) and then emits `dashboard:bridge-ready`. A plugin declares on activate AND on every `dashboard:bridge-ready`. Declarations are idempotent per `(channel)`: same spec → no-op; a channel already declared (core map or another plugin) → first wins, conflict counted and logged. A new bridge instance (reload) re-emits ready, so declarations survive reload.

**D3. Validation (untrusted input).** `pluginId` must match `^[a-z0-9][a-z0-9-]{0,63}$`; channel name must match `^[a-z0-9][a-z0-9:_-]{0,63}$` and contain `:`; `as` must match `^[a-z0-9_]{1,64}$`; `key` must match `^[A-Za-z][A-Za-z0-9_]{0,31}$` and is required for `latest`/`stream`; core-reserved event types (pi core types, `event_forward` control types) rejected; ≤ 32 channels per plugin, ≤ 256 total; malformed → ignored + counted. At forward time the key VALUE must be a string or finite number ≤ 128 chars, else the message is forwarded live-only (never retained) and counted. All registries/buffers are `Map`s (no plain-object key lookup). The declaration payload is read field-by-field (no spread/clone of untrusted objects).

**D4. Delivery modes.** Applied in the generic gate. `live`: today's non-subagent rule. `latest`: retain newest per key while not ready/connected, flush on ready (generalises `SubagentFrameBuffer.buffer`). `stream`: retain ALL messages per key in emission order while not ready/connected, flush in order on ready; bounded per key (2000 msgs or 2 MiB). **One shared key budget:** `latest` and `stream` retention together hold at most 64 keys across all plugins (drop-oldest key, counted), so distinct-key floods stay bounded. **Cross-channel order:** all `stream` channels share ONE buffer keyed by `(pluginId, key value)` holding `(channel, data)` in emission order, so `subagents:delta` / `subagents:entry` for one agent flush in their original interleaving. Live path (ready+connected) forwards immediately — never coalesced or throttled (the subagent tick throttle applies to `tool_execution_update` only, unchanged).

**D5. Server storage.** `subagent_entry` stored as-is (generic per-string cap 4000 applies to entry fields — display text, offsets not involved). `subagent_delta.text` is EXEMPT from the per-string cap (it carries offsets); but stays under the per-event ceiling (256 KiB). No fragmentation (rejected: `insertEvent` is one-in/one-row, `memory-event-store.ts:23-27`, and broadcast sends that one row, `event-wiring.ts:1064-1068`); a single piece is one producer window (at most 250 ms) of text, far below the ceiling. A piece that still exceeds it is stored as a bounded delta placeholder — the envelope (`agentId`, `toolCallId`, `blockId`, `kind`, `offset`, `final`) kept, `text: ""`, `omittedLength: <UTF-16 length>` — bypassing the generic path; the client appends nothing, so the next piece's `offset` exceeds the text length and the existing gap rule marks the hole until the block's entry arrives. Deltas are collapsed when their block finishes: inserting a `subagent_entry` with `blockId` drops stored deltas of the same `(agentId, blockId)`; a terminal `subagent_completed/failed` drops all remaining deltas for that agent. Drops follow the existing middle-deletion contract: update `buf.bytes` and `globalBytes` (`memory-event-store.ts:1607-1609`), never renumber `seq`, count in `storeTrim`. Replay compaction (`packages/server/src/session/replay-compaction.ts:46-47`) must keep raw-vs-replay reducer equivalence for streams containing entries and open-block deltas. Replay of a mid-block reload rebuilds the open block from stored deltas.

**D6. Remove head+tail truncation.** Delete `reduceSubagentEvent` path. No persistent index (rejected: per-session indexes must be maintained across trim, collapse, LRU eviction and delete, `memory-event-store.ts:269-287,366-412`). Instead, ONLY when a subagent carrier is over the ceiling (rare), the store scans that session's resident buffer for `subagent_entry` rows of the same `agentId` and collects their indices. If `details.entryCount` is a safe integer `>= 0` AND one pass over the resident buffer (O(resident events)) finds valid integer indices in `[0, entryCount)` whose distinct count equals `entryCount`, replace `details.entries` with `[]` (keep `entryCount`) — the complete timeline lives in the stored step events, so replay renders the same timeline and the canonical "terminal frame still carries the full timeline" guarantee (`openspec/specs/subagent-details-payload/spec.md` scenario of that name — a WIRE guarantee, unchanged) is not weakened for replay. Otherwise (legacy producer, or a step lost to stream bounds / trim) fall to the generic truncation path, the same as any other over-ceiling event. Under-ceiling terminal frames are stored unchanged. Alternative kept-for-legacy head+tail rejected: user decision; legacy producers are pre-0.3.0.

**D7. Client reduction.** New reducer arms in `event-reducer.ts` (core owns `session.subagents`): `subagent_entry` → place `entry` at `index` in `subagents[agentId].entries` (dedupe by index; gaps allowed and rendered once filled); `subagent_delta` → `liveBlock` = `{blockId, kind, text, gap}`; append when `offset === text.length`, ignore duplicates (`offset + len ≤ text.length`), mark `gap` when `offset > text.length`. **Tombstones:** per agent keep `closedBlockMax` (highest `blockId` finished by an entry with `blockId` or by a `final` piece followed by its entry) and `terminal`; a delta with `blockId ≤ closedBlockMax` or arriving after terminal is ignored (blockIds are a per-run monotonic counter, producer `agent.ts` `createBlockDeltaEmitter`). An entry arriving before its block's final piece still clears and tombstones the block. Terminal frame: `entries` from the frame only when longer than the streamed list (legacy path). `default`-arm raw rows never produced for these two types.

**D8. Inspector.** `SubagentDetailView` passes the assembled live block (full text) as `liveEntry` when present, else falls back to `liveTail` (legacy producer). Rendering uses the main-chat thinking/text block styling, growing, with a gap marker only when `gap`. The #831 "hold tail across block-end gap" workaround is unnecessary on the delta path (final piece precedes entry) and kept only for the `liveTail` fallback. Card ticker unchanged.

**D9. Resync.** Unchanged for legacy producers. For streams, reload/popout rebuilds from the server store (stored entries + open-block deltas); the cadence hook stops re-firing once `entries.length === entryCount`.

**D10. Healed card.** The reducer stamps every synthesized `healedBy` value (`superseded` and `session_ended`) onto the row's `toolDetails.healedBy`; today only `superseded` is stamped and `session_ended` clears it (`event-reducer.ts:2551-2561`); a real end still clears it. `AgentToolRenderer` displays `sub.result` when the row was healed (`toolDetails.healedBy` is set — `superseded`, `event-reducer.ts:645`, or `session_ended`, `packages/server/src/session/open-tool-calls.ts:132-144`) and `sub?.result` is non-empty; keeps the `recovered` badge. Keyed on the marker, not the sentinel text, so both heal paths are covered.

**D11. Tool output unwrap.** `MinimalChatView` tool output: string → as-is; object with `content: Array<{type:"text",text}>` → joined texts; else `JSON.stringify(…, null, 2)`.

**D12. Role guidance.** New `packages/roles-plugin/src/bridge/index.ts`: on `before_agent_start`, emit `roles:get-all` probe (answered synchronously by `role-manager.ts:271-284`; it overlays built-in role NAMES with empty values, so the map is filtered to entries whose value is a non-empty `provider/model[:level]` ref); if any remain, append to `systemPromptOptions.toolGuidelines["Agent"]` one bullet: prefer `model: "@<role>"` over literal ids, listing `@name → provider/model` (≤ 12 roles, sorted). No-op when the Agent tool is not registered or the probe has no listener. Guideline is per run, so role edits apply next turn. Existence of the bridge = plugin enabled (D13).

**D13. Bridges honor enablement.** `server.ts` registers a plugin bridge only when `resolvePluginEnabled(pluginCfg, manifest.defaultEnabled)` is true (the same predicate the loader uses, `server.ts:3009,3020`), so default-disabled plugins are not registered; enabled→disabled deregisters it (both registries, per existing spec) at next server start and at toggle time; pi picks it up at next session start.

## Risks / Trade-offs

- [Declaration lost when the plugin activates before the main bridge] → D2 handshake; test both load orders.
- [Stream buffer growth during long disconnect] → D4 bounds + drop counters in `/api/health`.
- [Stored delta volume] → D5 collapse on entry; deltas ≤ 4/s/agent.
- [Legacy producer loses head/tail view on huge terminal frames] → accepted (generic truncation); producers ≥ 0.3.0 unaffected.
- [Third-party plugin hijacks a core channel] → D3 reserved-name rejection, first-wins.
- [Role guideline bloats prompt] → single bullet, ≤ 12 roles.

## Migration Plan

Ship dashboard; producers 0.2.x/0.3.x/0.4.x all work (0.3.x gains entries; 0.4.x gains growing block). Rollback = revert; plugin bridge entries removed from `packages[]` by D13 on disable.
