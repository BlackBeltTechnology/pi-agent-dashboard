## 3. Shared terminator

- [ ] 3.1 Add `packages/server/src/spawn-process/session-terminator.ts` with `createSessionTerminator({ sessionManager, headlessPidRegistry })` → `terminate(sessionId, { graceMs?, spawnToken?, verifyIdentity?, stampManualClose? })` returning `{ outcome, terminated, pid? }`.
- [ ] 3.2 Implement the ladder (design D1): capture `headlessPidRegistry.getPid(id)` → registry kill (attempt flag only) → `pid = session.pid ?? registryPid` → `signalZero` already-gone check → optional grace poll on `signalZero` → identity guard (only when `verifyIdentity` and the pid is `session.pid`) → `killProcess(pid, { timeoutMs: 2000 })` → confirm by `signalZero(pid) === "esrch"` only. Do not use or modify `isProcessAlive`.
- [ ] 3.3 Identity guard: `processStartedAt(pid)` non-null and `<= pidRecordedAt + 2000`; null or missing stamp ⇒ unverifiable. On failure re-probe `signalZero`: `esrch` ⇒ `confirmed-dead`, else `refused-identity` with a diagnostic naming `pid reused` or `identity unverifiable on <platform>`; never signal.
- [ ] 3.4 Return `outcome: "no-identity"` (no pid from record or registry, no token match) with `terminated: false` — never claim a kill.
- [ ] 3.5 When a `spawnToken` is passed and no pid was resolved, reclaim via `findPidsBySpawnToken(token)` → `killProcess` per pid → confirm with `signalZero`; win32 returns `[]`, so the outcome stays `no-identity`.
- [ ] 3.6 Keep the no-direct-`process.kill` invariant in the new module: all signalling goes through `killProcess`.
- [ ] 3.7 Implement the close stamp (design D10, D1 steps 0 and 8): with `stampManualClose`, before any signal set in-memory `closedReason: "manual"` only on a record that is not `ended` and has no reason; when the outcome is not `confirmed-dead` and the record is still not `ended`, restore `closedReason: undefined`.
