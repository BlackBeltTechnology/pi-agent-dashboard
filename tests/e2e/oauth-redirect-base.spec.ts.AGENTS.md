# oauth-redirect-base.spec.ts — index

L3 spec (change: config-override-oauth-redirect-base, review of PR #409). Seeds `auth.providers.github` + `auth.bypassUrls:["/"]` + `auth.redirectBaseUrl` via `PUT /api/config`, then RESTARTS (auth plugin registers no `/auth/*` route and no `_reloadAuth` when the boot-time registry is empty). F1/F1b: `GET /auth/start/github` + single-provider `/auth/login` auto-redirect 302 `Location` carries `redirect_uri=<override>/auth/callback/github`. F2: `PUT /api/config` changes the base and takes effect with the SAME pid (hot reload, not a restart). F2b: cleared override falls back to `http://localhost:<port>/...` (never the relative `/auth/callback/...` a `??` would emit). F2c: an unrelated `auth` write preserves the override. F10: Settings ▸ Security `redirect-base-url-input` + `save-btn` persists `auth.redirectBaseUrl` and `/auth/start` reflects it. NO test here restarts the server: the provider is seeded at container BOOT via `PI_E2E_OAUTH=1` (`docker/test-entrypoint.sh`, set by `global-setup.ts`), because `pi-state` is a RAM-backed tmpfs — every container start hands the server a fresh empty `~/.pi` and discards config written through `PUT /api/config`, so a seed-then-restart spec silently lost its provider (`GET /api/config` → `auth: undefined`, `/auth/start` → 200 SPA fallback). `beforeAll` skips loudly when `/auth/start` is not 302 (harness started without the env). `afterAll` restores the seeded base; the boot-seeded provider stays armed and denies nothing via `bypassUrls:["/"]`. 6/6 green against the docker harness.
