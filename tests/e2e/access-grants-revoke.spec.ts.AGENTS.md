Walks the operator journey end to end: a refused read offers a remedy → accepting it makes the SAME read admitted with NO restart → the Access tab lists the grant as `Scope: Project` → revoking from the tab makes the read fail again, still with no restart. **Grant seeded in-container** via `docker exec -i <container> node`, because `POST /api/access/grants` refuses any non-loopback socket peer BY DESIGN (design D15) and a host-driven spec is exactly such a client; the in-container step still goes through the real path (trigger the refusal, take its `denialId`, submit it) rather than writing the store file, so the denial→grant binding is exercised, not bypassed. **The probe path must EXIST** — `isGrantAdmitted` realpaths the request, so a missing path is refused by the predicate itself and admission could never be observed; the spec materialises `/fixtures/__access-e2e-probe__/probe.txt` in-container and admission then reads as 200 `{exists:true}` against a 403 `path outside cwd` before it. Requires `ensureGitSession(page)` FIRST: containment gates on a KNOWN session cwd and an unknown one refuses with `"unknown cwd"` — a 403 carrying NO `denialId`, which would starve the remedy. Two deliberate anti-false-pass guards: the 403 precondition is asserted (incl. a `denialId`) rather than assumed, and after revoke the spec waits for the entry to DISAPPEAR before asserting the read is refused again — a silently-failed revoke would otherwise leave the read refused and pass for the wrong reason.
