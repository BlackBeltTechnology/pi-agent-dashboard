# session-state-honesty.spec.ts — index

L3 rendered-honesty gate (change: stop-discarding-known-session-state, test-plan Q1/Q2/Q3).

- **Q1** — a prompt typed while the dashboard socket is down fails HONESTLY and blames the CONNECTION, never the session. The cut is a HARD-offline simulation (`armHardOffline` init script): once `__cutDashboardWs` is set the wrapped `WebSocket` constructor THROWS (exactly a no-network browser) and the tracked established sockets are closed. Neither `context.setOffline(true)` (measured: does not close an established WebSocket — the app stays `connected`) nor `page.routeWebSocket` (its mocked reconnect still fires the page's `onopen`, which resets the app's backoff and status) can hold the client disconnected for the 10 s outbox window. Precondition = the DESKTOP shell's own banner ("Connecting…"/"Server offline"; the `ConnectionStatusBanner` with "Disconnected from" is mobile-only); then asserts `pending-prompt-card[data-status=failed]` + "Dashboard is offline — your prompt never left this browser." + a `Retry` button, and that the 30 s "may not have been received" wording is absent.
- **Q2** — `docker exec kill -9 <session pid>` (out of band; nothing in the dashboard's own state is touched), then the card renders `session-ended-reason-<id>` with a `data-closed-reason` in `{manual, process_gone, spawn_failed, unknown}` and NOT `manual`. Measured against the harness: the only server path that classifies an involuntary death is the gateway reconnect-grace expiry, `HEARTBEAT_TIMEOUT` (180 s) + one grace period = **361 s** to `process_gone`; hence the 460 s test timeout.
- **Q3** — the zero-pixel healthy contract (mockup Surface 2: "Healthy renders nothing"). Precondition POLLED from `/api/sessions` (row live AND `processMetrics.updatedAt` < 35 s old) so the absent pill proves "healthy", not "unknown"; then asserts no `session-host-pressure-<id>` in the DOM while the card stays visible.

Container resolved by published port (`docker ps --filter publish=$DASHBOARD_PORT`) — `test-up.sh` hash-derives the per-worktree compose project, so the name is not knowable statically. Needs `PI_E2E_SEED=1` + the Docker harness; browser via `PW_CHANNEL=chrome` when the bundled headless shell is absent.
