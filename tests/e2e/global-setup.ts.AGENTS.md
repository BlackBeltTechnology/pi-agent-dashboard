Else spawn `docker/test-up.sh -d --build` (--build MANDATORY: server+client run from baked image) detached from throwaway tmp workspace (keeps overlay off repo), STRIPS `DASHBOARD_PORT`/`PI_GATEWAY_PORT`/`PW_E2E_PORT`/`PW_GATEWAY_PORT` from spawn env so test-up.sh hash-derives ports in-window, sets `PI_E2E_SEED=1` in spawn env, blanks `ANTHROPIC_API_KEY`/`OPENAI_API_KEY`/`GEMINI_API_KEY` so host keys never leak into disposable container, write `test-results/.e2e-managed` marker `{workspace,pid,logPath}`, `bootHealthyPorts` re-reads `.pi-test-harness.json` each iteration via `resolvePortsFromStateFile` + polls derived `/api/health` until 200 (BOOT_TIMEOUT_MS: 180s LOCAL default; `PW_E2E_BOOT_TIMEOUT_MS` overrides it — CI sets 1200s because a cache-less runner spends ~6-8min building the image before the poll can succeed), then locks `process.env.PW_E2E_PORT`+`PW_GATEWAY_PORT` for workers. A boot that never goes healthy is DIAGNOSED, not just timed out: every ~10s `bootHealthyPorts` reads `harnessRestartCount` and throws early once restarts >= 2 (a failed entrypoint crash-loops under compose.test.yml's `restart: unless-stopped`, which is otherwise indistinguishable from a slow boot); on timeout it calls `captureHarnessFailure` → `test-results/harness-failure.log` (container state + log tail), uploaded per shard by ci-e2e-browser.yml. `test-up.sh`'s own output ends at `Container ... Started`, so without this bundle the first CI dispatches died with no cause. See change: stabilize-browser-e2e.
