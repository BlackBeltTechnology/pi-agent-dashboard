# helpers/windowed-session.ts — index

Shared glue for L3 specs needing a REAL replay window. `buildWindowedSession({mode,window,transcripts})` builds a long transcript FIRST, then arms windowing (`PUT /api/config` + `POST /api/restart`) — `maxReplayEvents`/`replayWindowMode` are read once at server construction, so they are restart-only on the ONE shared container. `WINDOW=100` (not the shipped 2000 — `computeReplayWindow` is parametric and pinned at L1; only scroll/splice/affordance need a browser). One `long-transcript` ≈604 events → ≈504 gap vs `BACKFILL_MAX_SPAN` 500, so rows needing a second substantial splice must pass `transcripts: 3`. `teardownWindowedSession` restores limits EXACTLY as read (never `?? 0`) and ends the session it built. `openWindowedSession` defaults `requireLoadButton:false` — in `tail-only` the climb's unstamped `scrollTop` write is read as genuine user intent and auto-loads, replacing the button. `nudgeAscent` descends first so the return is a real rising edge (writing `scrollTop=0` while AT 0 fires no event). `watchBackfillFrames` MUST be attached BEFORE the page opens — `page.on("websocket")` only sees sockets created after. NOT new infra: every primitive is shipped and already used by `history-backfill-gap`/`-perf`. See change: add-tail-only-replay-window.
