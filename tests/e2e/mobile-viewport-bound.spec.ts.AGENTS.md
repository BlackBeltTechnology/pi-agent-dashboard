Browser E2E for test-plan #F12–#F15 (capability `mobile-resilience`, change: fix-long-session-ux-degradation §4, design D4). Six tests at the 390×844 repro device. `forceStaleBanner` rewrites `/api/health.bundleHash` (passthrough) so the 43 px in-flow plugin-staleness banner always renders. **F12** — banner visible → `documentElement.scrollHeight === window.innerHeight` (baseline defect 887 vs 844), `scrollY === 0`. **F13** — click `plugin-staleness-dismiss` → banner gone → still bounded in both states. **F14** — `ensureGitSession` + click card + focus `composer-root` textarea → `documentElement.scrollTop === 0`, `header-app-bar` `boundingBox().y <= 1`. **F15** — first-launch modal (`first-launch-display-backdrop`, GET `/api/preferences/display` forced seedless, no auto-dismiss handler), add-folders dialog (`add-folders-dialog`), app toast (`auto_name_error` frame → `showToast`), spawn-error host (`spawn_error` frame, off-screen cwd), recovery host (`recovery_offer` frame), worktree-init stack (`/api/git/worktree/active-inits` two running runs) — each asserted to have a `position: fixed` ancestor and to keep the document bounded. Server→client frames are delivered by capturing the shell WebSocket in `installFrameInjector` (`page.routeWebSocket`, installed before navigation). Only this layer has a layout engine — jsdom reports fictional `scrollHeight`. Use when the mobile viewport bound or an overlay's no-height contract regresses.
