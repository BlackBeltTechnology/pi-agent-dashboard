# harness-isolation-faults.spec.ts — index

L3 deliberate-poisoning scenarios for harness-global trust isolation (X8 timed-out narrowing restored, X15 undeclared write attributed + healed, X14 leaked `afterAll` write caught by the pre-test baseline check, X10 SIGKILLed worker healed by the successor's worker-start re-assert). SKIPS unless `PW_E2E_HARNESS_FAULTS=1`; run ONLY on a dedicated fresh harness (a reused poisoned harness records the poison as its baseline); never in default shards. Fault tests are RED BY DESIGN (timeout / pre-body leak failure / killed worker); the recovery test after each MUST be green; groups are not `serial` so a red fault does not skip its recovery. Allowlisted by the trust-write lint (raw `writeConfig` is the fault). Not reproducible here: network-guard refusal on a credentialed harness (healed by the pre-test baseline check before the refusal verdict can latch) and host-gate refusal (needs a non-loopback `Host`); both pinned at L1 in `scripts/__tests__/e2e-reap-core.test.mjs`. See change: triage-browser-e2e-offbox-poison.
