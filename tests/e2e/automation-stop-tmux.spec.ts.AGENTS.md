# automation-stop-tmux.spec.ts — index

L3 gate for the unattended-reclaim leak (#459, test-plan #X19/#X20). The harness spawns with the default `PI_SPAWN_STRATEGY=tmux`, so an automation run's pi is invisible to the headless PID registry. Creates a `core.prompt` automation whose prompt is `[[faux:ask-select-roundtrip]]` (agent blocks on `ask_user`, so the run is alive until stopped), fires it, then `POST /api/plugins/automation/stop` and asserts the CONTAINER's process table (`/proc` via `docker exec`) loses the pi: X19 after the session registered (`session.pid` rung), X20 before `session_register` lands (spawn-token rung). Uses `helpers/container-proc.ts`. Idle-reaper reclaim of a tmux session has no L3 row: no harness path yields a persistent `ephemeral` session (the engine terminates a run's session at completion), so it is covered at L1 (`idle-reaper.test.ts`, `session-terminator.test.ts`). See change: fix-session-reclaim-tmux.
