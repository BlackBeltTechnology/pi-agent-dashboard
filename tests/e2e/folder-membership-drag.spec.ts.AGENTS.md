# folder-membership-drag.spec.ts — index

L3 for `drag-folders-across-workspaces` (test-plan #F11-#F13, #F16, #F18, #F20, #X6) — the scenarios needing REAL geometry: spring-load dwell, mid-drag droppable remeasurement, empty-tier zone height, two-client convergence. `setupWorkspaces` NORMALIZES the shared container each test (fixtures pinned; `E2E Drag A`=[sample-git], `E2E Drag B`=[kb-sample,kb-parent,sample-hook-ok]) because these specs mutate membership; workspace ids are read off `workspace-header-<id>`. Two non-obvious drag rules: (1) `closestCenter` measures the DRAGGED CARD'S collision rect, NOT the pointer, so `beginDragOnto` aims the card CENTER at the target and returns a cursor for further moves; (2) folder cards must stay EXPANDED (a collapsed card shrinks the drag gutter to its chevron button, whose `onPointerDown` stops propagation — no drag starts), so it uses a 1400x2400 viewport instead of collapsing. Needs `PI_E2E_SEED=1`. See change: add-folder-actions-menu — every `folder-open-home-<cwd>` anchor became `folder-home-row-<cwd>`; `openFolderMenu(page,cwd)` (idempotent, reads `aria-expanded`) now gates add-to-workspace and remove-from-workspace, and `ensureTopLevel` removes via the menu item `folder-menu-item-remove-from-workspace` instead of the deleted `ws-remove-<wsId>-<cwd>` button. Adds F9 (folder trigger glyph != `mdiDotsHorizontal`, imported from `@mdi/js` and compared against the rendered `path[d]`), F10 (zero `session-card-add-to-workspace-*`, desktop + mobile), X5 (collapse while the menu is open leaves no orphaned popover, no console error) and X6 (drag-reorder while open, same invariant).
