## harden-peer-address-identity

Proof bound to an address literal: `http` hostnames resolve (injected `lookup`, ≤ 8 literals/name, 2 s) to literals, each proven separately; exchange, origin, heal, re-verify use the proving literal. `probe` → `ok|self|foreign|unverified|unreachable` via shared `classifyProof` + `discovery.localFp()`. `pickHost` returns proving literal + `foreign[]`; candidates: stored, then discovered ordered by `orderByLocality` (own last), batches of 12. Window state `live|parked|blanked`; `reselect(ow, proof)` is the ONE transition behind `reverify` and `recheck`: transport failure keeps page + reruns `pickHost`; self/foreign ⇒ `about:blank`, `clearStorageData({storages:["cookies"]})` awaited (fail ⇒ stay parked, retry next trigger), then `pickHost` ⇒ `replaceWindow` (`host moved`) | foreign seen ⇒ `blanked` + one notice | else parked "not reachable". `focusExisting` replaces non-`live`. `pairAgain`/`connectDiscovered` pass `alternatives`. Logs `candidate skipped … reason=self`, `foreign proof …`, `host moved …` (no secrets). See change: harden-peer-address-identity.

## device-key-mutual-check

Refused exchange (`classifyExchange` `refused`: 401 or 403 `network_not_allowed`; `exchange()` now returns `{verdict, refusal}`) at a proven route ⇒ `onRefused` runs the device check. Check = fresh `deps.prove(origin)` (must still prove fp, yields `deviceNonce`) then `POST {origin}/api/pair/device-status {deviceNonce,pub,sig}` (`signDevcheck`; `deps.fetch`, 10 s). `origin` is the literal `pickHost` just proved (`http`) or the name (`https`) — threaded via `loadVerified(host)` / `ow.origin`; never the name, never a sibling literal; no literal proves ⇒ no exchange, nothing sent. Outcomes: `revoked` ⇒ record mark `access-removed`, keep bearer+key, no load, offer once (`askNeedsPairing(label,"access-removed")`) | `paired`+403 nna ⇒ display-only mark `network-not-allowed` (memory only, NOT keyring), keep all | `paired`+401 / inconclusive (`unverified`, no answer, no nonce, re-challenge proves other fp) ⇒ open fails "could not confirm … nothing changed", no state | `unknown` ⇒ `unpair` (`markNeedsPairing` drops bearer+key, cookie removed) + offer once | `expired` ⇒ same + reason `access-expired`. Keyless: 401 ⇒ discard; 403 nna ⇒ keep bearer, mark `network-not-allowed`, offer Pair again. Other 403 / timeout / 500 ⇒ `transport`, nothing discarded. Exchange ok + keyed ⇒ background `refreshDeviceView` (`paired`/`revoked` replace the view; `unknown`/`expired`/inconclusive never override `access-removed`, never discard). Exchange ok + credential and no key ⇒ `bindDeviceKey` once per app start (`bindAttempted`): fresh challenge at the proven origin, `generateDeviceKey`, `POST /api/pair/device-key` with bearer, key persisted via `keyring.setDeviceKey` only on 200; failure never retried until next start. Open window: `recheck` (5 min per window, unchanged limiter) reuses `onRefused`; conclusive outcomes set `ow.unpaired`. `records` Map = last check per fp (memory); `deviceView(fp)` → `{state,tier?,networkNotAllowed?}` via shared `deviceRowState` (stale when key pub differs); cleared on pairing approval + forget; `deps.onDeviceChange` fires on change; `deviceNote(view)` = menu words. `ports.askNeedsPairing(label, reason?)`. Pair again always makes a new key (pairing client). See change: device-key-mutual-check (D1, D9).
