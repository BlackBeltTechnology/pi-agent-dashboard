| `index.ts` | Server entry (no bridge). NO peer extensions — plugin owns every provider contract (see `quotas/`). `createAuthAdapter(ctx)` adapts host seams `ctx.providerAuth.getCredential` (raw credential, e.g. Codex `accountId`) + `ctx.modelRuntime.getModelRegistry().getApiKeyAndHeaders` (OAuth-refreshing token) to `{get,getApiKey}`; NEVER deep-imports the server package, NEVER reads `~/.pi/agent/auth.json`; missing seam ⇒ `no-credential`, not a throw. `enabledProviders()` = `SUPPORTED_PROVIDERS` ∩ config, gated on `enabled` + per-provider `enabled` (both default-off) ⇒ ZERO network calls when closed. `computeQuota()` (exported, unit-tested) fetches enabled providers in PARALLEL, each failing independently. RETENTION: `lastGood` Map keeps the last successful snapshot per provider and re-serves it flagged `stale:true` when a refresh fails (throttled 429 no longer makes a provider VANISH); dropped immediately when the provider or plugin is disabled, so stale data cannot outlive an opt-out; `_resetQuotaRetention()` is the test seam. Enabled-but-empty providers with NO retained snapshot are reported in `unavailable[]` with a reason (`no-credential`/`peer-rejected`/`no-data`/`no-adapter`) so settings can explain the silence. Default `registerPlugin(ctx)`: guarded `GET /api/quota` (skips if Fastify already listening) + `quota_update` broadcast. Logs provider id + failure KIND only — never a token. See change: publish-quota-plugin. |
| `quotas/http.ts` | Dependency-free JSON fetch. SECURITY CHOKEPOINT: token goes in a HEADER only, never a URL/query/log; every failure message passes `scrub()` (redacts `sk-`/`ghp-`-style prefixes, JWTs, `Bearer …` echoes, any 40+ char blob, any URL) and is capped at 200 chars, because upstream error bodies can echo the credential back. `FETCH_TIMEOUT_MS`=15s per request so one hanging provider cannot stall the snapshot. Exports `fetchJson`, `scrub`, `JsonResult`, `HttpFailureKind`. `HttpFailureKind` is module-private — referenced only by the local result union; the package `exports` map admits `.`, `./client` and `./server` only, so it was never reachable externally and the export just fed the knip ratchet. See change: add-tail-only-replay-window. |
