# DOX — packages/mcp-server-plugin/src/server

Files in this directory. One row per source file. See change: add-dashboard-mcp-server.

| File | Purpose |
|------|---------|
| `auth.ts` | `parseBearer(header)`, `authenticate(header, deps) -> McpCaller \| null`. Credential check LOCAL to `/mcp` — `createNetworkGuard` is per-route, so `/mcp` sits outside it and self-guards. Pure function of the `Authorization` header value: takes no address/`isGenuinelyLocal` param (so no loopback carve-out can leak in, A3) and never reads `request.isAuthenticated` (so a cookie-authed browser cannot reach it, A4). Statelessness gives per-request credentials for free (A7). Session tokens checked before device tokens. |
| `dispatch.ts` | `dispatchRpc(request, headerVersion, caller, deps)`, `buildDiscoverResult`, `parseSubscriptionFilter`, `REMOVED_METHODS`. Validates the protocol version BEFORE the method, so an unsupported client never reaches a handler. `initialize`/`notifications/initialized`/`resources/{subscribe,unsubscribe}` → 404 `MethodRemoved` (never silently accepted). `tools/call` validates required args BEFORE the self-target guard, so a malformed call reports invalid-params rather than being masked by a refusal (E26). `server/discover` built fresh from constants each call → equivalent, side-effect free (E19/E20). Filter: `params.sessionIds[]`; absent/empty/non-array → `-32602` (S3 unreachable by construction). |
| `guard.ts` | `evaluateSelfTarget(caller, targetSessionId, tool)`, `SESSION_TARGETING_TOOLS`. Req 6. Takes NO prompt text — G2's slash-command case is handled by construction, so no payload can route around the verdict and the refusal necessarily precedes extension-command dispatch. Equality normalises case, surrounding whitespace and ONE matched quote pair (G7), no further (G3 must still work). Device callers exempt (G4). Indirect A→B→A loop PERMITTED and asserted (G6) — documented scope limit. Malformed target permitted, deferring to invalid-params. |
| `index.ts` | Server entry `registerPlugin` (+ `export default`, required by the loader). Creates the token registry and subscription registry, mounts routes on `ctx.fastify`, registers `mcp/mint-token` + `mcp/revoke-token` pi handlers, wires `ctx.onSessionEnded` → `revokeSession`, probes the adapter version, and provisions `~/.pi/agent/mcp.json`. Registry is created HERE and never persisted, so it dies with the plugin (X8) and a restart invalidates everything (X9). Provisioning failure is logged, never thrown — it is a convenience, not a precondition for serving `/mcp` (J7). Logs completeness + partition failures at load. |
| `jsonrpc.ts` | JSON-RPC 2.0 framing: `parseRpcRequest`, `rpcResult`, `rpcError`, `extractId`, standard codes. Keeps the HTTP-status/RPC-code pairing explicit because on revision 2026-07-28 it is a conformance requirement: unknown method = 404 + `-32601`. Unparseable bytes (`-32700`) are a DIFFERENT failure from valid JSON that is not JSON-RPC (`-32600`) — E17 asserts both separately. |
| `protocol.ts` | `resolveProtocolVersion(headerValue, params)`, `SUPPORTED_PROTOCOL_VERSIONS` (exactly `["2026-07-28"]`, Decision 10), `META_VERSION_KEY`, `PROTOCOL_VERSION_HEADER`. Fixed check order: header present → `_meta` present → body version is a STRING → header/body agree → supported. The string check precedes the comparison because a non-string can never equal the header, so leaving it later would misreport every malformed version as `HeaderMismatch` and blame the header for a body defect (E12). Never throws on arbitrary input. |
| `provisioning.ts` | `provisionDashboardEntry(io, path, url)`, `probeAdapterVersion(installed)`, `DASHBOARD_MCP_KEY = "pi-dashboard"`, `ADAPTER_VERSION_FLOOR = "2.20.0"`. Reuses `apple-tools/src/mcp-config.ts` discipline: merge-only, atomic rename, refuse-unparseable, injected `ConfigIO`. Entry uses the HTTP `url` shape, NOT the stdio `command` shape (J1), and never omits `protocolVersion` — without it the adapter defaults to the LEGACY handshake against a server bound to ignore it (J2). Reserved key: absent→create, has `url`→overwrite, any other shape→REFUSE THE WHOLE WRITE (J6). Probe names floor + installed + failure mode, because below the floor the symptom is a silent handshake hang (X1–X3). |
| `rate-limit.ts` | `AuthFailureThrottle`, `MAX_AUTH_FAILURES` 10 / `AUTH_FAILURE_WINDOW_MS` 60s / `AUTH_LOCKOUT_MS` 60s / `MAX_TRACKED_SOURCES` 10000. Added for CodeQL `js/missing-rate-limiting`: `/mcp` is an authorization boundary reachable over a zrok tunnel and runs a credential comparison per request. Counts ONLY failed attempts, and a success clears the counter, so legitimate traffic is never throttled (a throttle that locks out real users is a self-inflicted outage). The tracking map is itself capped — an unbounded per-IP map would trade CPU exhaustion for memory exhaustion, which is worse because the attacker picks the key space. Defence in depth; the primary control is the token's 256-bit entropy. |
| `routes.ts` | `mountMcpRoutes(fastify, deps)` → registers inside an ENCAPSULATED Fastify scope. That is load-bearing: `setErrorHandler` is global on the instance it is called on, so calling it on the shared `ctx.fastify` would replace the DASHBOARD'S handler and 500 every SPA route. Registers every non-POST method explicitly (405 + `Allow: POST`), because Fastify falls an unmatched method through to `setNotFoundHandler` → 200 + SPA HTML in `--dev`, a conformance failure that looks like success. `HEAD` is asserted but NOT registered — Fastify derives it from `GET`, and declaring both throws. `MCP_BODY_LIMIT_BYTES` 1 MiB (X11). Auth runs first, from the header alone. |
| `streaming.ts` | `McpSubscription`, `SubscriptionRegistry`, `MAX_BUFFERED_EVENTS = 1000`. `ctx.onEvent` delivers EVERY session's events, so per-subscription filtering is a spec requirement, not an optimisation (S2). Clean close, transport abort and shutdown all funnel through one idempotent `close()`, and registry deregistration is wired INTO `close()` rather than left to call sites, so no teardown path can forget (S4–S6). `isStillAuthorised` re-checked per delivery, so a revoked token TERMINATES the stream instead of letting it drain silently (S9). A slow consumer is disconnected, not silently dropped — a stream with a hole is worse than none (X12). |
| `tokens.ts` | `McpTokenRegistry`, `McpCaller`. Opaque 256-bit `mcp_`-prefixed token, SHA-256 at rest, plaintext returned once, no independent expiry, IN-MEMORY only (Decision 7). Rows are a flat ARRAY, not a hash-keyed `Map`, so a miss performs the same `timingSafeEqual` work as a hit — a `Map` would leak membership through timing while still passing a naive test (X10). `mintForSession` trusts its caller to have proven identity; only the bridge socket key can (Decision 6). `revokeSession` is the primary revocation path; `dispose()` covers plugin unload. |
