| `auth.ts` | `parseBearer(header)`, `authenticate(header, deps) -> McpCaller \| null`. | `protocol.ts` | `resolveProtocolVersion(method, headerValue, params)` → `{ ok, era: "modern"\|"legacy", version }` or failure, `LEGACY_PROTOCOL_VERSIONS` (`2025-03-26`/`2025-06-18`/`2025-11-25`), `MODERN_PROTOCOL_VERSION` = `SUPPORTED_PROTOCOL_VERSIONS` union tail, `META_VERSION_KEY`, `PROTOCOL_VERSION_HEADER`, `ProtocolVersionFailure` (+`AmbiguousHeader`). | `rate-limit.ts` | `AuthFailureThrottle`, `MAX_AUTH_FAILURES` 10 / `AUTH_FAILURE_WINDOW_MS` 60s / `AUTH_LOCKOUT_MS` 60s / `MAX_TRACKED_SOURCES` 10000. Added for CodeQL `js/missing-rate-limiting`: `/mcp` is an authorization boundary reachable over a zrok tunnel and runs a credential comparison per request. Counts ONLY failed attempts, and a success clears the counter, so legitimate traffic is never throttled (a throttle that locks out real users is a self-inflicted outage). The tracking map is itself capped — an unbounded per-IP map would trade CPU exhaustion for memory exhaustion, which is worse because the attacker picks the key space. Defence in depth; the primary control is the token's 256-bit entropy. |
| `routes.ts` | `mountMcpRoutes(fastify, deps)` → registers inside an ENCAPSULATED Fastify scope. That is load-bearing: `setErrorHandler` is global on the instance it is called on, so calling it on the shared `ctx.fastify` would replace the DASHBOARD'S handler and 500 every SPA route. SINGLE VERSION-RESOLUTION SITE: `resolveProtocolVersion` runs once per POST, before the `subscriptions/listen` interceptor (closes the pre-change gap where a `listen` never had its version checked); version failures map via `versionFailureResponse`, resolved `{era, version}` passed into `dispatchRpc`; a legacy-era `listen` never hijacks the reply (D3). `send()` echoes `Mcp-Session-Id` ONLY from the legacy-era initialize adapter — a modern response never carries one (E5/E11). Optional `deps.onMcpRequest?()` fires per POST — the lazy adapter-diagnostic hook. Registers every non-POST method explicitly (405 + `Allow: POST`), because Fastify falls an unmatched method through to `setNotFoundHandler` → 200 + SPA HTML in `--dev`. `HEAD` is asserted but NOT registered — Fastify derives it from `GET`, and declaring both throws. `MCP_BODY_LIMIT_BYTES` 1 MiB (X11). Auth runs first, from the header alone. See change: mcp-legacy-clients-and-token-issuance. |
| `streaming.ts` | `McpSubscription`, `SubscriptionRegistry`, `MAX_BUFFERED_EVENTS = 1000`. `ctx.onEvent` delivers EVERY session's events, so per-subscription filtering is a spec requirement, not an optimisation (S2). Clean close, transport abort and shutdown all funnel through one idempotent `close()`, and registry deregistration is wired INTO `close()` rather than left to call sites, so no teardown path can forget (S4–S6). `isStillAuthorised` re-checked per delivery, so a revoked token TERMINATES the stream instead of letting it drain silently (S9). A slow consumer is disconnected, not silently dropped — a stream with a hole is worse than none (X12). |
| `tokens.ts` | `McpTokenRegistry`, `McpCaller`. Opaque 256-bit `mcp_`-prefixed token, SHA-256 at rest, plaintext returned once, no independent expiry, IN-MEMORY only (Decision 7).
