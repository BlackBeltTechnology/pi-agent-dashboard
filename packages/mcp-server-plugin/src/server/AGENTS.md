| `rate-limit.ts` | `AuthFailureThrottle`, `MAX_AUTH_FAILURES` 10 / `MAX_IP_AUTH_FAILURES` 100 / `AUTH_FAILURE_WINDOW_MS` 60s / `AUTH_LOCKOUT_MS` 60s / `MAX_TRACKED_SOURCES` 10000. API `(ip, fingerprint, now)` — per-`(ip,fingerprint)` bucket + coarser per-ip ceiling (D7): one session's stale token no longer throttles the other local sessions sharing 127.0.0.1; credential rotation walks into the ceiling. Maps SEPARATE, so fingerprint churn never evicts a per-ip record (P3). Added for CodeQL `js/missing-rate-limiting`: `/mcp` is an authorization boundary reachable over a zrok tunnel and runs a credential comparison per request. Counts ONLY failed attempts, and a success clears the counter, so legitimate traffic is never throttled (a throttle that locks out real users is a self-inflicted outage). The tracking map is itself capped — an unbounded per-IP map would trade CPU exhaustion for memory exhaustion, which is worse because the attacker picks the key space. Defence in depth; the primary control is the token's 256-bit entropy. |
