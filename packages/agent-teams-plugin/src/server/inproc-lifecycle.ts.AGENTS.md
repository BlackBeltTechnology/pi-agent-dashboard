# inproc-lifecycle.ts — index

`createInProcLifecycle`: server intake of the lead host's `{op:"event"}` reports + hello `snapshot`. `parseEvent` strict. `started` ⇒ `spawning→busy` (first run: spawn-prompt mail acked, queued mail flushed, readiness clock `spawnTimeoutMs` armed ⇒ no guarded hello in time ⇒ child stopped + member `failed`) / `idle|disconnected→busy` via `ops.reportMemberState` (never core's `busy` op: it would undo a just-dispatched task); stale `started` (run ≤ `lastSettleId`) ignored. `idle` ⇒ core `ops.idle` (`settleId = run`, dedupe, notice, auto-claim; async gate ⇒ answered after commit) then `driver.onMemberIdle` (nudge) + `retryNotStarted`. `gone` ⇒ `releaseMember` (`GONE_REASONS`; unknown ⇒ `stopped` + `inproc_unknown_event`; spawning + `child_failed` ⇒ `failed`). `state` ⇒ `reportMemberState` + `queuePosition`. `reconcile(team, session, snapshot)`: re-bind ids, `disconnected` ⇒ snapshot state, ack mail the child already got, apply `unackedSettle`, `redeliver`; absent ⇒ `gone: not_alive` (`spawning` with pending command or `childId` kept). Released members never resurrect. Logs ids/sizes only. See change: add-agent-teams-in-process.
