# device-auth.ts — index

Paired-device bearer store + consumption for the browser (web-client analogue of shell `connect.ts`). Exports `getDeviceBearer`/`storeDeviceBearer`/`clearDeviceBearer` (localStorage key `pi-dashboard:device-bearer`), `installDeviceAuthFetch` (idempotent global `fetch` wrapper adding `Authorization: Bearer` to same-origin `/api/*`+`/v1/*`; never overrides an explicit header), `mintWsTicket(scope)` (`POST /api/ws-ticket` with bearer → ticket; null when unpaired), `appendWsTicket`. Durable bearer never rides WS (F6). See change: make-pairing-qr-camera-scannable.

`finishDevicePairing` returns `{keepFailed}` and clears the in-memory bearer ONLY after a cookie-only authenticated request has succeeded — on a plain-http LAN origin the device cookie may be dropped, and clearing first would strand an already-approved device. See change: add-lan-knock-pairing.

`mintWsTicket(scope, {probeCookie})`: unmarked browser tries cookie once; 2xx+ticket ⇒ sets `pi-dashboard:device-paired` marker; refusal leaves it unmarked (marker cleared on 401 only when it was set). See change: fix-electron-server-window-ws-ticket.

Per-origin slots: bearer lives in `pi-dashboard:device-bearer:<apiOrigin>` as JSON `{token, expiresAt?}` (`expiresAt` epoch ms). Legacy global key `pi-dashboard:device-bearer` only ever DELETED — `migrateLegacyDeviceBearer()` removes it on every path (no exchange, no send, no copy). `getDeviceBearer`/`storeDeviceBearer(token, expiresAt?)`/`clearDeviceBearer` act on the current API origin's slot. Wrapper attaches the slot of the REQUEST's own origin (exact match; identity token only for page origin), also drives rotation + `bearer_expired` handling. `finishDevicePairing(token, expiresAt?)`: cross-origin stores `{token, expiresAt}`; same-origin keep-failed writes the page-origin slot `{token}`.

`browserHolderBody()` → `{holder:"browser"}` only when API base is cross-origin, else `{}`; spread into pairing redeem/poll bodies (`PairLanding`) and rotate body. Electron/CLI keyring modules never import this file (AE78 static check).

Rotation (cross-origin slots only): `startDeviceBearerRotation(apiBase?)` at startup (`main.tsx`), call-driven `maybeRotate` when remaining < 25 % of issue→`expiresAt` (issue time = this page's write, else `expiresAt − 7 d`), ≥ 60 s between attempts, no timers. `POST <origin>/api/paired-devices/rotate` Bearer slot token body `{holder:"browser"}`. Slot replaced ONLY by 200 with non-empty `token` + finite future `expiresAt`; 404 ⇒ unsupported for the page session; 409/429/5xx/malformed/network ⇒ slot untouched (409 `bearer_superseded`: other tab's token arrives via `storage` event, in-memory override dropped). `setItem` failure ⇒ bearer kept in memory + one `onDeviceBearerNotice("storage-failed")` (App toast `warning`). 401 `bearer_expired` on a slot-authenticated request ⇒ clear that origin's slot (if still the sent token) + ONE `location.assign(<origin>/pair?request)` (deduped per origin). `resetDeviceAuthRuntimeForTests()` clears module state. Tests: `__tests__/device-auth-bearer.test.ts` (AE55/57/59–62/74/76–78, AP3, AX5–8/14/15), `device-auth-cookie.test.ts` (AE54/56/58). See change: harden-auth-credentials.
