# WorktreeSpawnDialog.tsx — index

Fullscreen `+Worktree` dialog. Lists existing worktrees (one-click `Spawn →`) + create-new form (base picker, new-branch input, path preview via `slugifyBranch` → `<repo>/.worktrees/<slug>`). Existing-worktree rows spawn directly (`Spawn →`); init delegated to folder-action-bar Initialize button. Create-new runs no install/init step. See change: generalize-worktree-init-hook. Orphan-path detection (debounced `probePathExists`) + cleanup affordance + one-shot auto-retry. `attachProposal` forwarded through `onSpawn.opts`. Reacts to attachProposal prop changes — sets newBranch=os/<name> unless user typed. See change: auto-fill-branch-from-proposal-in-worktree-dialog. Adds "From a pull request" source mode toggle. PR mode renders `PrCombobox`, derives path `pr-<N>`, submits via `POST /api/git/worktree/from-pr`. gh-unavailable disables toggle + inline hint. See change: add-worktree-from-pull-request. Source toggle widened binary→ternary `mode: "fork"|"checkout"|"pr"` ("Fork to new branch" / "Check out existing branch" / "From a pull request"). Default mode = fork when `attachProposal` set, else checkout; "pr" never auto-picked; mode does not auto-flip on later attachProposal change. Checkout mode: picker label "Branch", no new-branch input, path slug `slugifyBranch(localNameOf(base))`, submit omits `newBranch`, `canSubmit` needs only base. `branch_in_use` enriched message renders inline. See change: worktree-checkout-existing-branch. `branch_exists` error (fork hits lingering branch, no worktree) renders inline `worktree-dialog-branch-reuse` button "Check out this branch instead". Click switches sourceMode=checkout, base=orphan branch, resubmits once via `handleCreateAndSpawn({mode,base})` override (bypasses stale React state). See change: fix-worktree-fork-orphan-branch-recovery. Adds PRE-submit fork collision pre-check `forkCollision` memo (fork mode only; `newBranch` matches a `data.localBranches` name) rendering advisory `worktree-fork-collision` block under the new-branch input; does NOT disable submit (mirrors orphan-path warning). Routes by holder: `holder===null` (branch lingers, no worktree) → `worktree-collision-checkout` reusing `handleReuseAsCheckout`; `holder!==null` (branch held by a worktree) → `worktree-collision-spawn` calling `handleSpawnExisting(holder)`, since checkout would fail `branch_in_use`. See change: warn-fork-branch-collision-before-submit.
