# ProviderAuthSection.tsx — index

Settings section for LLM provider auth. Exports `ProviderAuthSection`. Fetches `/api/provider-auth/status` + `/handlers`. Splits OAuth vs API-key providers. `OAuthProviderRow`: auth-code flow (polls status 2s, 5min timeout; tolerates transient failures, aborts after 3 consecutive malformed/non-ok responses) + device-code flow (`deviceModal`, polls `/device-status/<flowId>` 3s) + GitHub Enterprise domain prompt. `ApiKeyRow`: masked key, edit/save/remove. Uses `useAsyncAction` for deletes. A failed/malformed status (non-ok or non-array body) renders an inline error + Retry (`provider-auth-status-error` testid), keeping the section mounted and interactive — never an ErrorBoundary. See change: fix-corrupt-auth-json-500.

`AnthropicPeerHint` (local): inline advisory rendered inside `OAuthProviderRow` below the header line, only for `peerMissing && provider.authenticated` (`peerMissing` passed by the section for `id === "anthropic"` only). Source of truth = `useAnthropicPeerProbe()`, called ONCE per section. `InlineMessage` `severity="warning"` + a single `Install peer` pill wired to `usePackageOperations("global", undefined).install(ANTHROPIC_PEER_SOURCE)`; renders `statusFor`/`messageFor` for that source so an install failure surfaces. A `reason` starting with `IMPORT_FAILURE_PREFIX` (`import failed:`) withholds the install control — the package IS installed. Post-install state is an explicit latch (NOT `statusFor(...) === "success"`, which auto-clears after 3s), released when the probe reports the peer resolving. Tests: `src/__tests__/ProviderAuthSection.peer-hint.test.tsx` (E1–E9, F1–F9, X1–X7). See change: warn-missing-anthropic-messages-peer.

`handleChanged` dispatches `PROVIDER_AUTH_EVENT` (imported from `hooks/useProvidersReady.js`) on `window`, zero payload, then refreshes + calls `onCredentialsChanged`. It is the SINGLE funnel for all five write paths (API-key save, API-key removal, OAuth sign-in poll completion, device-code poll completion, OAuth sign-out). Never dispatch in `refresh` — `refresh` also runs on mount, and a mount must not look like a credential write. A failed write never reaches `handleChanged`, so it dispatches nothing. Tests: `src/__tests__/ProviderAuthSection.test.tsx` (D1–D6, E1–E2, X1, X3, R1 rows). See change: dispatch-provider-auth-event.
