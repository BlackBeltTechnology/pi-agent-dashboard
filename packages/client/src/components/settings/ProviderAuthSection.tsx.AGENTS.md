# ProviderAuthSection.tsx — index

The Settings → Providers **connected list** (redesigned by change: redesign-providers-settings-page). Exports `ProviderAuthSection`, `customEndpointConfigured`.

## List projection

One list of everything credentialed, merged from TWO independent fetches keyed by `(source, id)` — `auth` rows from `GET /api/provider-auth/status`, `custom` rows from `GET /api/providers`. Both sources degrade INDEPENDENTLY: a `/status` failure (`provider-auth-status-error` testid + Retry) never hides custom rows and vice versa (`providers-list-error`); a non-array body never reaches an array method; the section never throws into the ErrorBoundary and stays interactive. Rows list on `configured ?? authenticated` — an older server omitting `configured` must NOT produce an empty list (E9). `customEndpointConfigured(entry)` = apiKey non-empty AND not an UNRESOLVED `$NAME` ref (E8; the server's `apiKeyResolved` annotation on the `/api/providers` entry — present ONLY for `$`-refs — is AUTHORITATIVE when present; absent annotation → conservative `process.env` fallback, false in a browser). Badges carry KIND as a word (`provider-badge` testid): Subscription / API key / Environment / Custom endpoint — ONLY `ambient` or `source === "environment"` (and no `maskedKey`) earns Environment; stored key beats ambient. Rows render `data-testid provider-row` + `data-row-id` + `data-row-source`; a dual-registered id (OAuth + providers.json entry) renders BOTH rows (D6/F11). Catalogue-unavailable (`GET /api/provider-auth/catalogue-ready` → `{ready}` === false) renders the scoped `catalogue-unavailable-notice`, keeps the Add control, and SUPPRESSES the `providers-empty` state (D5/F7); unknown → fail open.

## Flows (D4) and writes

The section OWNS every flow: auth-code + device-code timers live in `flowsTimersRef` keyed PER PROVIDER (two flows never share a timer or failure counter — F3), state in `flows`. Flows START from the Add-provider dialog; dismissing the dialog never ends one, section unmount still does. The auth-code poll reads the RAW `/status` array (the rendered list is configured-only — F2), aborts after `POLL_MAX_CONSECUTIVE_FAILURES = 3` consecutive malformed/non-ok responses; the device-code poll deliberately keeps NO failure budget. Completion closes the dialog and funnels `handleChanged`.

`handleChanged` is the SINGLE dispatch funnel: exactly ONE `PROVIDER_AUTH_EVENT` (from `hooks/useProvidersReady.js`, zero payload) per successful write from ANY control (api-key save, custom create/edit/remove, sign-out, key removal, flow completion) + section refresh + `onCredentialsChanged` (panel `refetchCatalogue`). NEVER dispatched from `refresh` (a mount must not look like a write). Custom-endpoint writes go through `PATCH`/`DELETE /api/providers/:name` (name percent-encoded, immutable in Edit — rename is DELETE+PATCH), update the list optimistically, and schedule EXACTLY ONE health read `HEALTH_RECONCILE_DELAY_MS = 2000` after the write response (F10); pending rows show the pending pill until that read reconciles. Cross-type refusals render the TRANSLATED message via `conflictMessage` (`err.provider_auth.credential_type_conflict` + `vars.storedType`), never the raw English; a late (post-dismissal) refusal renders inline on the SECTION (`provider-flow-error`) and the provider never shows connected (X6).
