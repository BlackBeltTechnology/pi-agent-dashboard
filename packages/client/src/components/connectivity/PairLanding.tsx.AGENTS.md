# PairLanding.tsx — index

Browser `/pair` landing — phone-camera counterpart of the Electron shell `PairView`. Exports `PairLanding`. Decodes payload from `location.hash` (`decodePayloadString`); runs challenge (pin `fingerprint == payload.id`, refuse on mismatch) → redeem → shows confirm code on this phone → poll → `storeDeviceBearer` → `window.location.href="/"`. Error+restart affordance on missing/invalid hash, expired/rejected poll. Same-origin `/api/pair/*` (public routes). D12 desktop typed-approval unchanged. Mounted (lazily, `React.lazy`) by `main.tsx` when `pathname === "/pair"` (pre-auth, no WS). Colors = theme tokens only (`--text-*`, `--accent`/`--accent-soft`/`--accent-solid`, `--severity-{error,success}-*`); no hardcoded Tailwind palette — pinned by `PairLanding.test.tsx` token test. See change: make-pairing-qr-camera-scannable. Poll `rejected` → `pair-landing-rejected` ("The dashboard declined this device", severity-error tokens, NO restart; polling stops). Only `pending` keeps polling — any unknown status is terminal (X12). See change: add-pairing-approval-dialog.
