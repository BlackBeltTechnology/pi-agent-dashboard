## fix-popover-pane-bounded-height

- Composer dropdown (command + file/mention) applies BOTH `ddMinHeight` and `ddMaxHeight`, and opts into `minPopoverHeight: LIST_POPOVER_MIN_HEIGHT` (260) — both lists filter as you type.
- That dropdown NOW consumes `boundaryRef` (it previously passed none). `left-3 right-3` pins both composer edges so it stays immune HORIZONTALLY, but it applies a height bound and an offset pane's bottom edge sits above the viewport's — the vertical axis must measure the pane. `boundaryRef` is hoisted above both hook calls.
- Attach (＋) menu NOW consumes both height bounds (it hosts terminal + delivery states): `maxHeight`/`minHeight` + internal scroll, direction from `flipUp`. See change: add-composer-dock.

Textarea has no focus-ring; focused card border full `--accent` (single focus indicator). See change: redesign-composer-session-strip.

See change: add-team-skill-access — optional `invalid?: boolean` prop: `aria-invalid` on the textarea + card border `--severity-error-border` while set (team-app composer pre-check refuses an unavailable `/skill:`; the visual error box lives beside the composer in team-app `skills.css`).

`sessionStatus` is the RECONCILED composer liveness (`composerLiveness`: known server status wins, reducer fallback; `"ended"` = terminal), not the raw reducer status. `isWorking = isComposerWorking(sessionStatus, retrying)`: the `retrying` Stop leg is suppressed when `ended`; `pendingIdle` cancel stays ungated; stop-state resets on `!isWorking`. Plugin composer panels receive the reconciled value. See change: fix-composer-liveness-on-reload.
