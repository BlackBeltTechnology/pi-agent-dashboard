# MermaidBlock.tsx — index

Renders fenced mermaid blocks via lazy `mermaid.render()`. Module-level `_outcomeCache` (`MermaidOutcome` = `ok{svg}` | `repaired{svg,code,applied,error}` | `error{message}`) keyed ORIGINAL code+`themeId` (`<themeName>:<resolved>`) so per-named-theme accents cache separately; avoids re-render flicker; serialized `renderQueue` guards concurrent renders. `sanitizeMermaidCode` (entity decode + dedent), `sanitizeMermaidSvg` (strip script/on*). `renderMermaid` sanitizes then colorizes once before caching. `colorizeDefaultNodes(svg, accents, textColor)` DOMParser pass tints default (un-authored) flowchart/class nodes with theme accent palette: fill=accent@8% wash, border=accent@85%, label keeps `--text-primary`; skips shapes whose inline `style` has `fill:` (author intent wins); color keyed by `hashId(g.id)` (djb2, edit-stable). `resolveAccents` reads 6 `--accent-*` vars live (fallback ramp for jsdom); `rgba(hex,alpha)` helper. Streaming-aware via `complete` prop; focus-gated zoom/pan + `ZoomControls`. Exports `MermaidBlock`, `MermaidOutcome`, `_outcomeCache`, `colorizeDefaultNodes`, `hashId`, `rgba`. See change: colorize-mermaid-default-nodes.

NOT migrated to the shared escape-stack (inline focused mode, no portal/backdrop; sibling diagrams focus independently, so LIFO would track focus not z-order). Focused-mode Escape double-close is a deferred follow-up handled with local focus-scoped Escape, not the modal stack. See change: fix-stacked-escape-closes-layers (Eligibility rule / Non-goals).

Viewport fixed height `clamp(240px,50vh,640px)` (was minHeight 120); initial scale = contain-fit from `mermaid-fit.ts`, ResizeObserver re-fit until user input. See change: fix-markdown-remount-storm.

Auto-repair: `renderMermaid` never rejects; queued job renders normalized source via `renderOnce` → on throw `renderRepaired` runs `repairMermaid` (`lib/preview/mermaid-repair.ts`) → applied≠[] retries once with id `<id>-r` → `repaired` outcome; no rule / retry fails / repair throws → `error` with ORIGINAL message. `renderOnce` removes `#d<id>` after each attempt. Hook `useMermaidOutcome(code,themeId,key,resolved,complete)` owns outcome state + render effect + show-original state (`showOriginalFor === key`, so code/theme change closes it); streaming (`complete=false`) never renders nor repairs. Config via `mermaidConfig(resolved)` (`mermaid-config.ts`). `RepairBadge` (null unless repaired; testid `mermaid-repair-badge`) renders as a sibling BEFORE `.mermaid-diagram` (its first child div stays the viewport, its only svg the diagram): rule `<code>` (testid `mermaid-repair-rule`, `aria-describedby` → sr-only localized `preview.mermaid.rule.R<n>`, `title`), "Show original" toggle (`aria-pressed`), `CopyButton` copy-fixed (testid `mermaid-copy-fixed`, copies `outcome.code`), then `ErrorView` (raw `code` prop + original error) while toggled. Toggle sets viewport `hidden` (not unmounted → zoom survives) + clears `focused`. `measureFitScale(el,svg)` returns null on 0×0 rect (hidden viewport would re-seed scale 1). See change: add-mermaid-auto-repair.
