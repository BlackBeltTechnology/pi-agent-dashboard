# useSessionActions.ts — index

Session action callbacks extracted from App.tsx. Sends send/abort/force_kill/stop_after_turn/resume/spawn/shutdown/hide/rename/terminal/follow-up-queue messages; writes optimistic prompt/closing/resuming state. `handleRetrySession(id)` rechecks latest `sessionStatesRef` for a settled, non-cancelled error, then sends the TYPED `{type:"retry_session", sessionId}` (the legacy hidden `/__dashboard_retry` prompt sentinel is gone); the server gateway forwards it to the owning bridge, which re-drives the turn via `pi.sendMessage({customType:"pi-dashboard:retry", display:false},{triggerTurn:true})` — never a process resume or prompt replay. Exports `useSessionActions`, `SessionActionDeps`. See changes: add-session-tags, sidebar-tag-collapse-and-delete, fix-retry-error-lifecycle. `handleSend`/`handleSendPromptToSession` consume the `SendVerdict`: a `rejected` send marks the bubble `failed` immediately with `failureCause:"connection"` (no 30 s wait, timer never armed); a `no-session-file` ended target is `failed` with `failureCause:"no_session_file"` and is never sent. `markPromptUndelivered(sessionId,text)` is the late correction for a queued prompt the outbox dropped (identity-keyed on status `sending` + exact text, so a later retype is not clobbered). See change: stop-discarding-known-session-state.
