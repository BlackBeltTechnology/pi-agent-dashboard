# useWebSocket.ts — index

WebSocket lifecycle: connects `url`, parses `ServerToBrowserMessage`, exposes `send`/`onMessage`/`status` (`connected`/`connecting`/`offline`/`auth_required`). Exponential backoff reconnect (via `connectRef` so reconnect re-runs the current path), auth probe after `OFFLINE_THRESHOLD` closes, registers `send` as plugin-action sender. Paired-device browsers (`getDeviceBearer()` set) mint a FRESH single-use `/api/ws-ticket` per (re)connect and present only `?ticket=` (durable bearer never rides WS, F6); unpaired browsers skip ticketing (cookie/loopback path unchanged). Exports `useWebSocket`, `ConnectionStatus`, and the live `ws` socket (state, set on open / null on close) so consumers that attach their own `message` listener — the plugin runtime's `usePluginMessage` — re-attach on every (re)connect. See changes: make-pairing-qr-camera-scannable, add-browser-relay. `send` returns a `SendVerdict` (`handed` | `queued` | `rejected{no_socket|send_failed}`) — never claims delivery; a bounded never-sent-only outbox queues non-OPEN sends, pops before flush (so a handed prompt is NEVER retransmitted — `send_prompt` is not idempotent), and drops oldest-first at `OUTBOX_CAPACITY`. Prompt entries expire at `OUTBOX_EXPIRY_MS` (10 s, strictly below the 30 s pending-prompt deadline); expiry OR capacity eviction emits through `onOutboxExpiry` (`OutboxExpiryListener`) so a dropped prompt can be surfaced instead of ageing into the 30 s wording. `flushOutbox` reports an entry whose flush write THROWS (popped, never retried) rather than dropping it silently. See change: stop-discarding-known-session-state.
