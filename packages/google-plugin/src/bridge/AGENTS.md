# DOX — packages/google-plugin/src/bridge

Bridge entry + the shared product tool runtime. See change: add-google-connect.

**Adding a product's tools (`gdrive`, `gdocs`, …):** create `tools/<product>.ts` exporting a `ProductTools` (copy `tools/gcal.ts`: `rt.define({ name, level, write?, parse, prepare?, summary?, run })`), add ONE import + ONE entry to `PRODUCT_TOOLS` in `tools/index.ts`. Nothing else changes: account resolution, level/disabled gate, headless block, confirm, lease, 403/backoff, guard declarations and registration are done by `runtime.ts`.

**Testing a product's tools:** `__tests__/fake-google.ts` is the shared kit — `createFakeGoogle()` (routes `.on(method, path|RegExp, reply | reply[] | (req, n) => reply)`, records `.calls` with token/query/body, `.writes()`, `.to()`), `makeToolHost({ accounts: [{ sub, email, alias?, products: { drive: "write" } }], google, runtime? })` (REAL `google/lease` handler + in-memory store; `host.run(name, params, ctx)`, `host.leaseCalls()`, `host.disconnect(sub)`, `host.store`), `uiCtx(true | false | "throw" | "never" | async fn)` (recorded confirm dialog) / `NO_UI`, `googleError(status, reason, metadata?)`, `jsonOf` / `textOf`. Copy `__tests__/gcal.test.ts` for the shape. Fake Google paths are the path below the API base (`/calendars/primary/events`).
