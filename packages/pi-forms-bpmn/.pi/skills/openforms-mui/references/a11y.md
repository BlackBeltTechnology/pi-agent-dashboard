# Accessibility guidance

The component targets **no serious or critical** axe violations across all 14
field types. The composite widgets carry the pitfalls; this page records them.

## General

- Every input has a programmatically associated label. Validation errors are
  associated with their field and announced to assistive technology.
- **Required/optional marking is truthful:** the component marks whichever is the
  *minority* among currently-visible fields, and never states a convention the
  rendered fields do not use. When every visible field is required, no per-field
  marker is shown and a single statement says so.
- **Conditional reveals are announced** (WCAG 4.1.3) via a polite live region,
  and the revealed field states *why* it appeared, so the change does not read as
  an unexplained layout shift.
- **Calculated fields** are visually distinct and carry text stating the value is
  computed; **disabled** state is conveyed by a non-colour cue as well as colour.
- **Severity tint matches severity:** a warning is never drawn on the error
  surface, because the tint is itself a signal. The blocked-submit summary uses
  the error surface only.

## Error summary

On a blocked submit or page advance, a summary lists every blocking error above
the form and **receives focus**, so a keyboard/AT user is told why the form did
not advance. Each entry that names a reachable field links to it and moves focus
there on activation. An entry with no reachable control (a cross-field rule whose
targets are all hidden/disabled, or a duplicated `key`) is still listed and reads
as a form-level problem rather than a dead link. Error text states **how to
correct** the value, not merely that it is invalid.

## Matrix

- Renders as a `Table` with a single-choice group per row; **collapses to one
  card per row below the `md` breakpoint**.
- The **row label stays programmatically associated** with its options in both
  presentations (table row header ↔ card `FormLabel`/`aria-labelledby`).
- Only **one** presentation exists as a control at a time, and the submitted
  value is identical whichever was used.
- In the table, the **whole cell is the activation target** (a `label` spanning
  the cell), and every interactive element clears the **48px** touch floor.

## Repeater

- `useFieldArray` with add/remove controls honouring `minItems`/`maxItems` (the
  add control disappears at `maxItems`; below `minItems` fails validation).
- Each item is a labelled card; child field errors are addressable at their array
  path (`people.0.name`) and shown on the specific sub-field instance.
- **Child fields have no conditional logic** — the upstream renderer never
  evaluates rule state for repeater children (diagnosed `inert-repeater-child-rule`).

## Signature

- Default canvas exposes `role="img"` with an accessible name and a
  **keyboard-reachable Clear button**; the canvas is focusable.
- It draws with `currentColor` (theme-driven), never a literal colour.
- MUI has no signature primitive, so a **documented accessible alternative** is
  the `SignatureComponent` prop — supply a component that offers whatever richer,
  accessible interaction you need; it must still emit a base64 PNG.

## Responsiveness

- Columns occupy their `width` span at `md`+ and full width below `md`.
- Visual order matches DOM and focus order at every breakpoint, including where
  the action bar stacks (WCAG 2.4.3): **Back precedes** the primary action.
- The multi-page stepper uses a compact vertical variant below `md` so step
  labels cannot collide with adjacent markers.
