# DOX — packages/shared/src/piai-compat

Files in this directory. One row per source file.

Lives in `shared` (not `server`): `packages/extension` depends only on `shared` + `bus-client`, so a seam under `server` is uncompilable from the bridge (design D1).

| File | Purpose |
|------|---------|
| `index.ts` | Public seam entry. Exports `adaptPiAi(module, resolvedPath?, deps?)` → `AdaptedPiAi { generation, module, oauth }`. ONE seam absorbs THREE pi-ai boundary breaks: module shape, transcript normalization, OAuth relocation. ASYNC seam, SYNCHRONOUS surface — every `await import()` happens during construction (pi-ai is ESM-only; a static import would bind `shared`'s own pinned copy instead of the resolved runtime), so `InternalRegistry.getAllModels()` keeps consuming `getProviders()`/`getModels()` synchronously. `deps { importPath, exists }` injectable for tests. Throws on an unrecognized module and on a factory runtime missing a required subpath — never a silently wrong catalogue. See change: adopt-piai-factory-api-registry. |
| `types.ts` | `PiAiModule` + `PiAiOAuthModule` MOVED here from `packages/server/src/model-proxy/{internal-registry,internal-auth-storage}.ts`, which re-export them for existing importers. Also `PiAiGeneration`, `AdaptedPiAi`, `AdaptDeps`, `OAuthRefreshCredentials`. `PiAiOAuthModule` gains per-provider `isAvailable(providerId)` + optional `unavailableReason`. See change: adopt-piai-factory-api-registry. |
| `detect.ts` | `detectPiAiShape(module)` → `{kind:"legacy"\|"factory"\|"unrecognized", reason?}`. BOTH generations positively identified — "not legacy ⇒ factory" never inferred. legacy ⇔ all 7 global members are functions; factory ⇔ `createModels`+`createProvider` functions AND no legacy member present; else `unrecognized` naming what is missing/conflicting. `LEGACY_MEMBERS`/`FACTORY_MEMBERS` exported. See change: adopt-piai-factory-api-registry. |
| `subpath.ts` | Path-safe derivation (design D5). `piAiDistDir(resolvedPath)` + `derivePiAiSubpath(resolvedPath, relative)`. Uses `path` operations only, normalizes foreign separators, asserts basename `index.js` inside `dist/`, throws WITH the resolved path. Replaces the POSIX-only `/\/dist\/index\.js$/` regex, which silently NO-OPed on a native-separator Windows path — a no-op is worse than an error. See change: adopt-piai-factory-api-registry. |
| `api-table.ts` | `API_LAZY_TABLE`: the explicit `model.api` → `{module, exportName}` map for the 10 TEXT-streaming `dist/api/*.lazy.js` factories (names irregular: `openAICodexResponsesApi`, `googleGenerativeAIApi`, …). `Api` is an OPEN union, so exhaustiveness is untestable at compile time — `api-table-drift.test.ts` diffs it against the runtime's shipped set instead. `NON_TEXT_LAZY_FILES` explicitly excludes `openrouter-images.lazy.js` (returns `{generateImages}`, no `streamSimple`), which a naive "every factory" diff would false-fail. See change: adopt-piai-factory-api-registry. |
| `oauth-facade.ts` | Builds `PiAiOAuthModule` (design D7). Resolution order: usable legacy `dist/oauth.js` (only when it actually exports the functions) → relocated async `dist/auth/oauth/load.js` loaders behind a provider-id map → unavailable. ASYNC loaders pre-loaded during `adaptPiAi` so the storage keeps its synchronous `getOAuthProvider(id)`; translates `refresh(credential, signal)`/`{access,refresh,expires}` ↔ `refreshToken(creds, signal)`/`{accessToken,refreshToken,expiresAt}` in BOTH directions while PRESERVING opaque fields (pi's `OAuthCredentials` has an index signature; `github-copilot` reads `credential.enterpriseUrl` back at refresh time, so a three-field rebuild would redirect an enterprise user's refresh to github.com). A refresh returning no access token THROWS instead of flowing into the storage's `?? cred.access` fallback, which would reuse the expired token while stamping a fresh expiry. Degradation is PER-PROVIDER and diagnosed — the ≥0.85 `export {}` stub is truthy, which is exactly what made the old `if (!this.oauthModule)` guard pass and then throw `TypeError`. `OAUTH_LOADER_EXPORTS` omits `radius` (needs a config argument the dashboard cannot supply). See change: adopt-piai-factory-api-registry. |
| `factory-surface.ts` | Synthesizes the 7-member `PiAiModule` over a ≥0.85 runtime. `getProviders()` PROJECTS `Provider` objects to id STRINGS — the legacy contract is `() => string[]` and feeding objects into `getModels()` returns ZERO models with NO error (a 200 with an empty catalogue, the exact original bug). `streamSimple` calls the RESOLVED runtime's own `normalizeContext` (root export, else derived `utils/transcript.js`) then dispatches API-FIRST (**api-ONLY when the model names an api**: `model.api` → memoized lazy api, and an unmapped or unloadable api THROWS naming the api + model + load failure). The built-in provider is consulted ONLY when the model carries no `api` at all — falling back to the provider for an unmapped api would silently route through the WRONG protocol, since `createProvider`'s single-api form ignores `model.api` (`apiFor = (model) => single ?? byApi?.[model.api]`) and `cloudflare-workers-ai` is single-api — never `Models.streamSimple`, which resolves auth and throws `Provider is not configured` for OAuth-only providers handed a caller key. Caller options pass through WHOLE (signal/env/maxTokens), apiKey+headers applied last. `{VAR}` baseUrl placeholders substituted from `options.env` then `process.env`, restoring 0.75.5's `resolveCloudflareBaseUrl` semantics that ≥0.85 moved into a provider-level wrapper (task 1.11 regression) — ALLOWLISTED to `CLOUDFLARE_ACCOUNT_ID`/`CLOUDFLARE_GATEWAY_ID` only, never a generic `process.env` scan, so a model `baseUrl` cannot splice an arbitrary secret into an outbound URL; unlisted or empty-valued placeholders stay verbatim and the caller's model is never mutated. `registerApiProvider`/`unregisterApiProviders`/`registerBuiltInApiProviders` are no-ops: registering would surface custom providers in `getProviders()` and discard the native `models.json` capability projection in `InternalRegistry`'s dedup-keeps-first. See change: adopt-piai-factory-api-registry. |
