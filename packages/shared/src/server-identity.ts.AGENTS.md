# server-identity.ts — index

Identity-verified dashboard detection over GET /api/health. Exports `DashboardStatus`, `DashboardCheckOpts`, `isDashboardRunning(port, host?, opts?)`. Replaces bare TCP port probe; flags `portConflict` for foreign JSON on HTTP 200 (ALL non-ok statuses map to `portConflict` — a 5xx is never retried). Bounded retry loop via `opts.retries` / `timeoutMs` / `retryDelayMs`; defaults preserve legacy single-attempt 2 s behaviour. Retry semantics: retries on AbortError (timeout) only — definitive outcomes short-circuit after one attempt: `portConflict` and a real ECONNREFUSED refusal (detected internally incl. dual-stack AggregateError `cause.errors[]` shapes; the `refused` flag never leaks into the public `DashboardStatus`). `_sleep` opts seam for retry-delay tests. The bridge auto-start consumes this signature (widened seam) to probe candidates at their advertised host + bootstrap-aware opts — see `server-auto-start.ts.AGENTS.md` and change fix-autostart-discovery-precedence (task 1.1).

Health probe URL built with `formatHostPort` (IPv6 literal bracketed). See change: stabilize-mdns-server-identity.

`DashboardStatus` gains optional `timedOut` (no attempt was definitive: every attempt timed out / reset — "held but silent"; absent on a refusal) and `instanceId` (from the health body, for ownership proof). Refusal = ECONNREFUSED / EADDRNOTAVAIL / ENETUNREACH / EAFNOSUPPORT (an IPv6-less host refuses `::1` with the latter). See change: harden-dashboard-start-detection.
