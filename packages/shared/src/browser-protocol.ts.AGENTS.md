# browser-protocol.ts — index

Server↔Browser WebSocket message contracts. Exports `ServerToBrowserMessage` + `BrowserToServerMessage` unions, `BootstrapStateSnapshot`, `Workspace`, `SpawnFailureCode`, follow-up-queue bridge-buffer messages, re-exports batch `ask_user` types from `protocol.ts`. `RoleRemoveBrowserMessage` (`role_remove`) added to `BrowserToServerMessage` — server gateway forwards it to the session bridge (change: add-custom-roles-ui). `SpawnSessionBrowserMessage.initialPrompt` = optional first prompt dispatched on session_register (no-hook Initialize pre-injects `/skill:project-init`). See change: project-init-skill-and-profiles. `SubagentResyncRequestBrowserMessage` (`subagent_resync_request` `{sessionId,agentId}`) added to `BrowserToServerMessage`; server forwards to owning bridge. See change: fix-subagent-live-detail-reliability (D2). `WorktreeInitSubscribe`/`Unsubscribe` messages carry optional `cwd` (stable per-checkout key) alongside optional `requestId`; new `ActiveWorktreeInit` type ({cwd,phase,startedAt,lastLine?,code?}) for `GET /active-inits`. `SetSessionTagsBrowserMessage` (`set_session_tags` `{sessionId,tags}`) added to `BrowserToServerMessage`. `RemoveTagGloballyBrowserMessage` (`remove_tag_globally` `{tag}`) added to `BrowserToServerMessage` — server fans the strip out to every carrying session (see change: sidebar-tag-collapse-and-delete). `PackageOperationCompleteMessage.action` union widened with `"reset"` (reset-to-npm composite op reuses `moveId` + `partialSuccess`). See changes: friendlier-worktree-init, add-session-tags, reset-override-to-npm. `PluginActionErrorMessage` (`plugin_action_error` `{pluginId,action?,error}`) added to `ServerToBrowserMessage` — gateway sends it to the sender when a `plugin_action` targets a pluginId with no registered handler. See change: fix-plugin-action-fanout-and-handlers. `MoveFolderToWorkspaceMessage` (`move_folder_to_workspace` `{path, toWorkspaceId: string | null, index?}`) added to `BrowserToServerMessage` — ONE nullable-target message for both directions; `toWorkspaceId: null` ejects the folder from all workspaces and pins it, `index` is the clamped insert position (omitted = append, ignored when the target is null). See change: drag-folders-across-workspaces. `BrowserNotifyMessage` (`notify`) added to `ServerToBrowserMessage`; re-exports `NotifyLevel`. See change: split-notify-from-prompt-request.

`SessionOrphanedMessage` (`session_orphaned` + `sessionId` + surviving `pid`) is emitted ALONGSIDE `session_removed`, never instead of it, when a session's process outlives SIGTERM → SIGKILL. The record is still released (retaining it wedges the session in the UI and stalls the E2E reap, which awaits `session_removed` per session), but a removal indistinguishable from a successful kill is what hid #452 for weeks. See change: fix-tmux-session-shutdown-leak.

Adds `SessionHistoryWindowMessage` (`history_window`) + `HistoryBackfillResultMessage` (`history_backfill_result`) to the server→browser union and `HistoryBackfillRequestMessage` (`history_backfill`) to the browser→server union. `history_window { headMaxSeq, tailMinSeq, gapCount, oldestGapSeq }` — sent once per subscriber before the first `event_replay`, FULL-STREAM paths only; `gapCount` is the gap events the store HOLDS, never the seq distance. `history_backfill { fromSeq, toSeq }` both inclusive. `history_backfill_result { events, servedFrom, servedTo, remainingGapCount, error? }` with `error` ∈ `not_subscribed | in_flight | out_of_range | stale_generation`; EXACTLY one result per request on every path, refusals included. All additive — an older client never sends `history_backfill` and ignores `history_window`. See change: lazy-load-session-history (D5, D6).
