# config.ts — index

Dashboard config loader. `loadConfig()` reads `~/.pi/dashboard/config.json` via `CONFIG_FILE`; `ensureConfig()` seeds defaults. Exports `DashboardConfig`, `AuthConfig`, `OpenSpecPollConfig`, `ModelProxyConfig`, `SpawnStrategy`, `ReattachPlacement`, `parseReattachPlacement`, `parseModelProxyConfig`, `getPluginConfig`, `clampSpawnRegisterTimeoutMs`. v2 (support-zrok-v2): `tunnel.zrok` gains `reservedName?`/`persistent?` (default false, in DEFAULTS + `normalizeTunnelConfig`); legacy `reservedToken` preserved on read but NOT promoted to `reservedName`. External-editor `EditorConfig`/`parseEditorConfigForTest` removed (change: remove-external-editor-integration). `AuthConfig` gains optional `redirectBaseUrl?` (OAuth redirect-URI base; trimmed, blank omitted, parsed in `parseAuthConfig`). Top-level `publicBaseUrls?: string[]` promotes the legacy `pairing.publicBaseUrls`; read via `resolvePublicBaseUrls(config)` (top-level first, legacy fallback, else `[]`). Deliberately NOT in `DEFAULTS` and never seeded by `ensureConfig()` — absence is what selects the legacy fallback, and it is not an OAuth source (D7). Adds `GatewayAuthMode`/`GatewayWroteRecord`/`GatewayRecord` + optional top-level `gateways?: GatewayRecord[]` (provenance of what the add-gateway action wrote; malformed entries and unknown modes filtered, never defaulted). See change: config-override-oauth-redirect-base. `ModelProxyConfig` + `parseModelProxyConfig` gain optional `preferredModels?: string[]` (ordered, drop non-string/empty, omit empty) + `modelAliases?: Record<string,string>` (drop non-string/empty key or value, omit empty). See change: fix-and-prefer-model-proxy-resolution. Adds `EmbedLifecycleConfig` + `DEFAULT_EMBED_LIFECYCLE` (`config.embedLifecycle`, default-inert `enabled:false` + idle/hardCeiling/grace/sweep/register seconds + per-visitor & global caps), parsed clamped via `parseEmbedLifecycleConfig`. See change: add-embed-session-lifecycle.

`MemoryLimitsConfig.maxReplayEvents: number` (default `0` = unlimited) caps events replayed to a browser on a FULL-stream subscribe. `parseMemoryLimits`: absent / non-numeric / negative / `NaN` / `Infinity` → `0`; positive below exported `MIN_REPLAY_WINDOW` (100) clamps UP to 100; `0` never clamped; fractional floored. Requires server restart. See change: lazy-load-session-history (D3, D13).
 `DashboardConfig` gains `removeBatchCap` (number, default 50) + `clampRemoveBatchCap` (clamps to [1, 500], non-integer/non-positive fallback to default). See change: apply-checkout-root-to-worktree-ops.

`subagentTickThrottleMs` default flipped `0` → `500` (`DEFAULT_SUBAGENT_TICK_THROTTLE_MS`, exported). `DashboardConfig` declares `subagentTickThrottleMigrated?: boolean` and `loadConfig` round-trips it, so a settings save cannot strip the marker (a stripped marker re-runs the migration and undoes a deliberate `0`). `ensureConfig()` seeds the marker unconditionally on a fresh install. The one-shot rewrite itself lives on the server boot path (`server/src/config-api.ts` `migrateSubagentTickThrottle`), never in `loadConfig` — a pure read called by every bridge process. See change: heal-orphaned-tool-cards-on-session-end.

`DashboardConfig` gains `maxConcurrentSubagents` (number; `DEFAULT_MAX_CONCURRENT_SUBAGENTS` = 2, exported) + optional `subagentSaturation?: SubagentSaturationThresholds` (`eventLoopDelayMs`/`cpuPercent` PROCESS-domain, `loadAvg1m` MACHINE-domain). `resolveMaxConcurrentSubagents`: absent → 2; a non-negative integer is honoured (including the explicit `0` disable value); anything else is MALFORMED and resolves to `Number.POSITIVE_INFINITY` — the fail-open (uncapped) path, deliberately NOT the disable path. `parseSubagentSaturation` drops non-positive/non-numeric thresholds and collapses an all-invalid object to `undefined`. `loadConfig` round-trips both; `ensureConfig` does NOT seed the cap (absence = active default). See change: bound-subagent-fanout-under-host-pressure.

`DashboardConfig` gains top-level `sessionHeap: SessionHeapConfig` + `serverHeap: ServerHeapConfig` (types/defaults re-exported from the browser-safe `heap-limits.ts`). TWO top-level keys, not one nested block: settings page attribution resolves per top-level key, so a shared block would strand the session fields on the Server page (D7). `parseHeapMb` takes the default for anything that is not a finite integer at or above `MIN_HEAP_MB` — there is NO `0` = unlimited sentinel here, unlike the `memoryLimits` byte budgets, because `0` is a request V8 rejects. `parseOptionalHeapMb` keeps absent absent and drops present-but-invalid. `maxSemiSpaceMb` is validated as a plain positive integer (young gen is single-digit MB; the old-space floor must not apply to it). NOT `memoryLimits`, which bounds the event store. See change: bound-session-heap-and-gc-telemetry.
