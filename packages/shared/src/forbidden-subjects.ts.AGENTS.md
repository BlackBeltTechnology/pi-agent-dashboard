# forbidden-subjects.ts — index

Subjects that may never be granted, and why (design D15). `forbiddenGrantSubjects` / `isForbiddenGrantSubject` / `subsumesForbiddenGrantSubject` / `isUngrantableSubject`. Matching is deliberately SPLIT: `whole` (`/`, `$HOME`, platform system roots) matches EXACTLY, while `sensitive` (`~/.ssh`, `~/.pi`) matches exact-OR-descendant. A blanket descendant rule would forbid every project directory (they all live under `$HOME`) and macOS temp dirs under `/private/var`, making the feature unable to grant anything. `subsumes` rejects an ancestor RUNG that would admit a forbidden subject. Comparison is against realpaths, so `/etc` reached through the `/private/etc` alias is caught. Callers MUST pass the subject that will be PERSISTED, not a pre-normalization input. See change: add-access-grants-and-review. `subsumesForbiddenGrantSubject(candidate, env, sets?)` accepts precomputed `forbiddenGrantSubjects(env)` for multi-rung callers (#P3). See change: add-access-grant-dialog. See change: surface-denial-remedy-in-previews — `forbiddenGrantSubjects({homedir,platform,env})` platform-scoped (Windows from `%SystemRoot%`/`%ProgramFiles%`/`%ProgramFiles(x86)%`/`%ProgramData%`, `C:\` fallback); junk cross-platform entries gone → cwd ancestors grantable. `isUngrantableSubject` builds list once. Exports `realpathNearestAncestor`.
