# forbidden-subjects.ts — index

Subjects that may never be granted, and why (design D15). `forbiddenGrantSubjects` / `isForbiddenGrantSubject` / `subsumesForbiddenGrantSubject` / `isUngrantableSubject`. Matching is deliberately SPLIT: `whole` (`/`, `$HOME`, platform system roots) matches EXACTLY, while `sensitive` (`~/.ssh`, `~/.pi`) matches exact-OR-descendant. A blanket descendant rule would forbid every project directory (they all live under `$HOME`) and macOS temp dirs under `/private/var`, making the feature unable to grant anything. `subsumes` rejects an ancestor RUNG that would admit a forbidden subject. Comparison is against realpaths, so `/etc` reached through the `/private/etc` alias is caught. Callers MUST pass the subject that will be PERSISTED, not a pre-normalization input. See change: add-access-grants-and-review. `subsumesForbiddenGrantSubject(candidate, env, sets?)` accepts precomputed `forbiddenGrantSubjects(env)` for multi-rung callers (#P3). See change: add-access-grant-dialog. See change: surface-denial-remedy-in-previews — `forbiddenGrantSubjects({homedir,platform,env})` platform-scoped (Windows from `%SystemRoot%`/`%ProgramFiles%`/`%ProgramFiles(x86)%`/`%ProgramData%`, `C:\` fallback); junk cross-platform entries gone → cwd ancestors grantable. `isUngrantableSubject` builds list once. Exports `realpathNearestAncestor`. Moved here from `packages/server/src/access/` (server keeps a re-export shim); Node-only (`node:fs`/`node:os`) — the browser client MUST NOT import it (guard test `__tests__/client-no-node-subjects-import.test.ts`). See change: ask-agent-file-access-in-chat.

harden-agent-tool-guards (D7): the `sensitive` list also holds `~/.aws`, `~/.config/gh`, `~/.gnupg`, `~/.kube`, `~/.docker`, the exact file `~/.netrc` and the browser user-data roots of the platform (`browserProfileRoots(platform, home, env)`: the design D7 table, Chrome equals `chromeUserDataDir`; to add a browser edit that function + its test row). One edit makes them sensitive in every consumer (agent gate, grant backstop, ladder, planes, YOLO roots + auto-allow, provisioning, cwd verdicts, allow-once admission, agent grant acceptance, trust-mirror deny, browse roots). Ancestors become ungrantable (`~/.config`, macOS `~/Library/Application Support`, `%LOCALAPPDATA%`). The listed locations resolve through a per-call cache with `Error.stackTraceLimit` zeroed (ENOENT per missing entry stays cheap); `realpathNearestAncestor` (caller-supplied subject) is realpath-only, no extra fs probe (CodeQL js/path-injection). `isUngrantableSubject(subject, env?, sets?)` canonicalises once. `subsumes` treats only `..` or `..<sep>…` as escaping the candidate (`..x` is a child name). Residual drift: local lists in `provisioning.ts` and `pi-trust-mirror.ts` untouched. See change: harden-agent-tool-guards.
