# heap-flags.ts — index

V8 heap FLAG plumbing, pure strings, no node imports. Exports `HEAP_FLAG_MARKER_ENV` (`PI_DASHBOARD_HEAP_FLAG`), `maxOldSpaceFlag`, `isValidHeapMb`, `buildSessionHeapArgs`, `buildSessionHeapNodeOptions`, `stampHeapFlag`, `stripDashboardHeapFlag`. `buildSessionHeapNodeOptions` emits only the subset `NODE_OPTIONS` accepts — `--initial-old-space-size` is rejected by the allow-list and a child carrying it refuses to boot. `stampHeapFlag` re-stamps its OWN previous token (marker match) so a restart adopts a changed config, and leaves an operator pin alone (dropping the stale marker with it). `stripDashboardHeapFlag` is provenance-gated and surgical: removes only the marker-matched token, drops `NODE_OPTIONS` when nothing is left, and deletes the marker. Presence of the flag is NOT provenance — the dashboard stamps that same flag into its own env. See change: bound-session-heap-and-gc-telemetry.

Token removal (`stripDashboardHeapFlag`, `stampHeapFlag`, `mergeHeapIntoNodeOptions`) goes through internal quote-aware `optionSpans` / `optionTokens` / `withoutToken` — options split on whitespace only OUTSIDE double quotes (backslash escapes inside); exact-option match, no split/join, so a quoted value (`--require "/a  b.js"`, even one containing our token) keeps its bytes. Pin detection uses the same tokens. See change: guard-server-heap-and-store-coupling.
