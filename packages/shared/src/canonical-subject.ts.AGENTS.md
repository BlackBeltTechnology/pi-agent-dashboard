# canonical-subject.ts — index

Volume-appropriate canonical form for access-subject comparison (task 2b.3a). `volumeCaseInsensitive` / `canonicalSubject` / `isSameSubject` / `isSubjectWithin`. Probes case sensitivity FROM THE VOLUME (flip an existing component's case, ask whether the flipped sibling exists; memoised per device) instead of assuming it from `process.platform` as the codebase-wide `samePath` does — which is wrong for a case-SENSITIVE volume on a case-insensitive host (APFS case-sensitive, a container bind mount, a network share), where two subjects differing only in case are different objects and folding them together silently widens a grant. NFC-normalises before folding. Containment is component-wise (`path.relative`), never a string prefix, so `/repo-secrets` is not inside `/repo`. An unresolvable path returns `null` and never matches. Deliberately does NOT modify `samePath`: that primitive's semantics are depended on across the server, so changing them here would alter shipped containment everywhere at once; the boundary is that a caller comparing an ACCESS SUBJECT uses this module. See change: add-access-grant-dialog (task 2b.3a). `isSubjectWithin` treats a child named `..foo` as inside (only `..` / `../x` escape). See change: add-access-grant-dialog (2b.7 review). Moved here from `packages/server/src/access/` (server keeps a re-export shim); Node-only (`node:fs`/`node:os`) — the browser client MUST NOT import it (guard test `__tests__/client-no-node-subjects-import.test.ts`). See change: ask-agent-file-access-in-chat.
