# prompt-answer.ts — index

Moved from `client/src/lib/chat/prompt-answer-encoder.ts` (client + REST share it). Pure helper encoding interactive renderer `result` → `answer` string for PromptBus `prompt_response`. Exports `encodePromptAnswer(result, cancelled)`. Precedence: cancellation→undefined, `answers[]`→JSON, `values[]`→JSON (multiselect), `value`→string, `confirmed`→"true"/"false", fallback `String(result)`. Empty multiselect (`"[]"`) distinct from cancellation (`undefined`). See change: fix-multiselect-auto-cancel-on-dashboard. Also `validateQuestionAnswer(prompt:{type,options?,metadata?}, answer)`→`{ok:true}|{ok:false,reason}`: confirm `"true"`/`"false"`; select∈options; multiselect JSON array of distinct options (`[]` ok); input/editor any string; batch JSON array, one entry per `metadata.questions` sub-question (`{confirmed}`/`{value}`/`{values}`), `images` rejected (text-only road); unknown type → invalid; malformed sub-question `options` (non-array) → `[]` → clean 400, never a throw. Tests: `__tests__/prompt-answer.test.ts` incl. encoder→validator round trip. See change: add-pending-question-stack.

Inline Other: `hasOwnOtherOption(options)` (`/^other(?![\p{L}\p{N}])/iu` on trimmed strings; non-strings ignored) and `isOtherAllowed({allowOther,options})` (`allowOther===true`, non-empty options, no own Other) — the ONE predicate shared by client renderers and the REST validator. `ValidatablePrompt.allowOther?`. For opted-in prompts `validateQuestionAnswer` accepts a custom select string / at most one custom multiselect value (non-empty, equal to its own trim, distinct); per batch sub `isOtherAllowed(sub)`. Non-opted prompts validate exactly as before. See change: add-ask-user-inline-other.
