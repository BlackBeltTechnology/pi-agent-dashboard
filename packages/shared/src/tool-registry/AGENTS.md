| `strategies.ts` | Reusable resolution strategies (pure over `StrategyCtx`). Exports `overrideStrategy`, `managedRuntimeStrategy`, `bundledNodeStrategy`, `bundledGitBashStrategy`, `managedBinStrategy`, `managedModuleStrategy`, `npmGlobalStrategy`, `whereStrategy`, `bareImportStrategy`, `StrategyDeps`. `whereStrategy` filters AppImage self-hits via `isAppImageSelfHit`. `bareImportStrategy` resolves via `createRequire` → exports-map dir-walk → `import.meta.resolve`. That ESM step is LAST and is an INERT GUARD, not a fallback: this module is itself jiti-loaded from a `data:` URL where `import.meta.resolve(<bare id>)` throws, so the step has never produced a value in production and the dir-walk has carried every step-1 miss. Behaviour preservation holds BECAUSE step 2 was already dead — do not "restore" the obvious order. Unreachability is contingent on bare (not subpath) ids + the default `anchor`. The ESM call MUST stay a direct `import.meta.resolve(id)`: a TypeScript cast makes the node `TSAsExpression`, defeats jiti's erasure, and forces its `data:`-URL ESM fallback (fatal on Bun hosts, issue #408) — enforced by `scripts/__tests__/jiti-cjs-transpile-safety.test.mjs`. See change: fix-jiti-cjs-transpile-safety.
