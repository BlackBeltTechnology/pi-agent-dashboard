Extension↔Server WebSocket protocol. `ExtensionToServerMessage` + `ServerToExtensionMessage` unions. `SessionRegisterMessage` (spawnToken, dashboardSpawned, `isGitRepo?` tri-state), `GitInfoUpdateMessage` (`isGitRepo?` refresh), `ProcessKind`/`ProcessListMessage`, `InteractiveMethod`/`BatchQuestion`/`BatchAnswer`/`BatchResult`, `AssetRegisterMessage`, `ServerRestartingExtensionMessage`, follow-up-queue + plugin emit messages. `RolesListMessage.builtinRoleNames?` + `RoleRemoveExtensionMessage` (`role_remove`) added (change: add-custom-roles-ui). `SubagentResyncRequestExtensionMessage` (`subagent_resync_request` `{sessionId,agentId}`) added to `ServerToExtensionMessage`; bridge replies with synthetic `subagent_started` `event_forward` (change: fix-subagent-live-detail-reliability D2). Re-imported by `browser-protocol.ts`. See change: gate-session-worktree-button-on-git. `NotifyMessage` (`{type:"notify", sessionId, notifyId, message, level?}`) added to `ExtensionToServerMessage` — a notification is not a `prompt_request`: no `promptId`, no `component`, no `placement`. Re-exports `NotifyLevel` from `types.ts`. See change: split-notify-from-prompt-request.
`BridgeDiagnosticEvent` gains `"watchdog_force_close"` — a client-initiated liveness teardown. Without it a bridge hang-up, a network drop and a server reap are all just `connection closed` + re-register in `server.log`, so reconnect churn cannot be attributed.
Adds server→extension `RegisterRejectedExtensionMessage` (`type: "register_rejected"`, `sessionId`, `reason`) — sent immediately BEFORE the gateway closes a bridge that lost a session-id contention; the refusal is terminal, so the bridge stops retrying for that id and surfaces `reason`. See change: fix-duplicate-bridge-registration.

Adds `InboundDropReportMessage` (`inbound_drop_report`, bridge→server: `dropClass` `session_mismatch|queue_overflow`, `messageType?`, `droppedSessionId?` payload-not-routing, `suppressed?`) and optional `promptId` on `SendPromptToExtensionMessage` + `PromptReceivedToServerMessage` (the per-prompt handle's round trip). Both optional, so an older bridge degrades cleanly: no drop record, prompts stay `transmitted`. Exports `InboundDropClass`. See change: fix-spawn-correlation-ttl-coupling.

Adds optional `SessionHeartbeatMessage.agentRunning?: boolean` — bridge-reported agent liveness (`getBridgeState().isAgentStreaming`) carried on the existing periodic beat. No new message type. Absent ⇒ no reconcile ⇒ pre-change behaviour, so an old bridge against a new server degrades rather than breaks. Advisory for the heartbeat watchdog: it MUST NOT alter timeout/grace behaviour. See change: fix-stuck-streaming-status-latch.

Adds optional `ProcessMetrics.fanoutAdmitted?` / `fanoutRefused?` / `fanoutSaturationRefused?` — cumulative subagent fan-out admission counters riding the existing heartbeat metrics transport. `fanoutSaturationRefused` distinguishes saturation refusals from static-cap refusals. Refusals are ALSO written durably (`subagent-admission-refused`), because the live counters vanish when the process dies — the case the capability mitigates. See change: bound-subagent-fanout-under-host-pressure.

`ProcessMetrics` gains six OPTIONAL fields: `heapSizeLimit`, `external`, `arrayBuffers`, `gcCount`, `gcMajorCount`, `gcPauseMsTotal`. Optional in BOTH directions — an old bridge sends none, a new bridge against an old server sends fields it ignores; nothing parses strictly, so the only way to break it is coercing an absent field to `0` (which reads as "ceiling is zero" / "no GC happened"). GC counters are read-and-reset PER HEARTBEAT, like the event-loop histogram, so nothing buffers between beats. The server-side counters on `/api/health` are deliberately the opposite (cumulative) — a polled GET must stay idempotent. See change: bound-session-heap-and-gc-telemetry.
