# manifest-validator.ts — index

Hand-rolled manifest validator. Throws `ManifestValidationError` with `pluginId` + `reason`. No Zod dep. Validates optional `requires` shape: `piExtensions`/`binaries`/`services` each must be `string[]` when present. See change: add-plugin-activation-ui. Validates `shell-overlay-route` `presentation` is `"page"`\|`"dialog"` — FATAL on an unknown value (unlike `depth`, which warns and defaults) so a typo cannot silently restore the opted-out behaviour. See change: add-route-backed-overlay-dialogs. Requires a non-empty `customType` + `component` on `custom-entry-renderer` claims and rejects intra-plugin duplicate `(custom-entry-renderer, customType)` pairs beside the `tool-renderer`/`command-route` checks. See change: add-custom-entry-renderer-slot. `validateNavHint`: settings-section `nav` shape-checked, DROPPED with one `console.warn` (id, claim index, field) — never fatal; NFKC+trim, label ≤ 40 / description ≤ 200, rejects Unicode Cc/Cf, finite `order`, blank description dropped alone; `nav` on other slots dropped silently. See change: promote-model-roles-settings. `editor-pane-tab`: requires `component` + `pathPrefix` (`^[a-z][a-z0-9-]{1,31}$`, not `diff\|term\|url\|live`), optional `labelComponent`; duplicate prefix within a plugin rejected; fields carried only for that slot. See change: add-browser-editor-pane-tab. Accepts `presentation:"content"` (check + normalisation copy); `"content"` without `depth` FATAL; fatal message lists `"page"`, `"dialog"`, `"content"`; `path` wildcard only as literal trailing `/*?`, other `*` FATAL. See change: add-plugin-app-host. Validates optional `projectTypes` (≤8 entries, 1–16 markers, pinned grammar, fatal). See change: add-project-scoped-apps.

`tool-renderer` claims: `expandWhileRunning` must be boolean, `resultPending` a string; both rejected on any other slot (naming plugin + slot); copied onto the normalized claim only when set. See change: decouple-plugins-from-core (task 4.5).

Optional string `clientBundle` / `clientStyles` (package-relative prebuilt client entry / stylesheet) are type-checked with `client`/`server`/`bridge` and copied onto the normalized manifest when set; layout (dedicated asset root) is checked at discovery by `server/client-layout.ts`, not here. See change: decouple-plugins-from-core (task 6.1).

Optional `emits`: static array of exact event names the plugin may emit into sessions (distinct from inbound `eventTypes`). Rejected with an error naming `emits`: non-array, non-string/empty/whitespace-bearing entry, entry >128 chars, >64 entries, reserved prefix (`roles:` `role:` `model:` `prompt:` `dashboard:` `ui:`, case-insensitive). Absent/`[]` = emits nothing. Exports `MAX_EMITS_ENTRIES`, `MAX_EMITS_ENTRY_LENGTH`. See change: harden-git-terminal-plugin-boundaries (D16).
