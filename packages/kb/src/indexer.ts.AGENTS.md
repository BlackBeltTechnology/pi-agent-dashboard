# indexer.ts — index

Indexer. `indexSource` is ASYNC: walks source, mtime→sha256 change detection, structural chunking, Tier-1 graph extraction, BATCHED transactional upsert — commits + `await setImmediate` every `YIELD_EVERY`=100 files so the walk yields the event loop (a concurrent `/stats` reader observes `indexing`+live counts) and releases the WAL write lock; trades whole-walk atomicity for responsiveness (mid-walk throw leaves earlier batches committed; reindex idempotent). All callers must `await`. A source whose `dir` does not exist is skipped with `console.warn` (returns `missing:true`), not a thrown ENOENT — partial source set still indexes what exists. `docTypeOf` classifies `*.AGENTS.md` per-file index sidecars as `agents` doc_type (searchable; name != `AGENTS.md` so pi never auto-injects them). Walk honours `.gitignore` via `gitignore.ts` when `respectGitignore` is not explicitly false (config default true) — makes the long-declared default real; `cwd` option bounds the up-walk; ignored dirs pruned unconditionally (excluded-parent rule). See change: fix-dox-lint-blind-rows, fix-kb-gitignore-excluded-parent. See change: split-components-agents-dedup-rollup; fix-kb-index-feedback; harden-kb-index-failure-atomicity. Walk regex + default `extRe` widened to `.adoc`/`.asciidoc`; per-extension chunker dispatch routes them to `chunkAsciiDoc` (design D4 — all three selection gates widened together with `config.ts`, since widening one alone indexes zero extra files); title fallback strips adoc extensions. The `extRe` gate stays DEAD (never applied), only its default widened. See change: asciidoc-support. `walk` is async + exported (tests); `WALK_YIELD_EVERY=500` (+ `WALK_YIELD_MAX_MS=50` time bound) yields walk + gitignore pre-scan; `.worktrees` in `DEFAULT_EXCLUDE`. See change: bound-kb-search-freshness. Heading nodes `<file>#<heading path>` (`headingNodeName`); `reconcileChunkMap` at pass start; ENOENT on stat/read = deleted file; deletion demotes file node + `sweepPlaceholders`; `IndexOptions.heartbeat`. See change: fix-kb-index-integrity. `IndexOptions.onFirstBatch` runs inside the first batch's transaction (engine-record clear). See change: add-kb-worktree-seed. Batch loop also commits+yields when `INDEX_BATCH_MAX_MS`=50 elapsed since the last yield (time budget); additive `IndexOptions.signal` (throws `KbIndexAborted` at per-file/batch boundary, batch rolled back) and `onProgress({root,done,total})` per batch commit.
