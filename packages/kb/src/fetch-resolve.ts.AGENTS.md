# fetch-resolve.ts — index

Shared section-fetch resolver for `kb_get` tool + `kb get` CLI. `resolveFetch(store, roots, arg, section?)` → `hit` | `ambiguous{on:path|section, candidates}` | `section-missing{sections}` | `missing`. `section-missing` = path resolved, section did not; `sections` = distinct body heading paths via REQUIRED `FetchStore.getChunks` (rowid order, `:meta` excluded); render `(section not found: <section> in <arg> — sections:)` + ≤50 paths + `(+K more section[s])`, or `— no sections)`. `missing` (`(not found: <arg>)`) = unresolved path only. See change: fix-kb-parent-link-and-section-miss. Readings: literal per root, id-qualified `<id>:<path>` (longest id wins), dir-qualified `<relDir>/<path>`; dedup (root,path). Section via `getChunkBySection`; one heading path = hit. `buildFetchRoots(rootIds, fsSources, cwd)` sets `relDir` (`/`) for filesystem roots only. `renderFetch` → `(not found: …)` / `(ambiguous: …)` + candidates / body + `(+N more sections)` trailer. See change: fix-kb-get-roots-and-guard.
