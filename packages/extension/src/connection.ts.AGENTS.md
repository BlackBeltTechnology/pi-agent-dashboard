# connection.ts — index

WebSocket connection manager with exponential backoff reconnect, message buffering while disconnected, server-liveness watchdog. Exports `ConnectionManager`, `ConnectionManagerOptions`, `WatchdogFireInfo`.
Watchdog force-close is ATTRIBUTABLE: `onWatchdogFire(info)` fires immediately before teardown, carrying `silentForMs` / `watchdogTimeout` / `readyState` / `inboundQueueDepth` / `refusedInbound`. Reported BEFORE `handleDisconnect()` nulls `this.ws`. Callback throw is swallowed — diagnostics never block the reconnect. Keepalive context: bridge beats every `HEARTBEAT_INTERVAL` (15s, `bridge.ts`) and server acks, so `DEFAULT_WATCHDOG_TIMEOUT` (60s) = 4 missed beats, NOT a 1× race with the server's 60s `WS_PING_INTERVAL`. `maxTickDriftMs` (worst lateness of the watchdog's OWN check tick) discriminates: ~0 + silence at threshold = peer went quiet; large = THIS loop stalled. `silentForMs` alone cannot — a blocked loop and a silent peer produce the same number.
Force-close is DEFERRED one loop turn: `isSilentPastThreshold()` is re-evaluated in a `setTimeout(…,0)` (re-enters timers phase only AFTER poll), guarded by `watchdogRecheckPending`. WHY: a block inside an I/O callback wraps the loop to timers BEFORE poll, so the watchdog read a stale `lastMessageAt` and hung up on a live peer — measured 42 frames sent / 5 processed, `readyState=1`. NOT `setImmediate`: vitest fake timers never run it, which would make the defect untestable. Pinned by `watchdog-poll-phase.test.ts` (real timers + out-of-process peer; a fake-timer or in-process version passes against the BROKEN code). Consequence: reconnect backoff starts one turn later. Holds `suppressUntil` deadline for `server_restarting` quiesce window.
Handles `register_rejected` as a TERMINAL refusal: bypasses the inbound pump, fires `onRegisterRejected(sessionId, reason)`, sets `intentionalClose` and tears down — so the refused duplicate never reconnects/re-registers for that id. Every other close still reconnects with backoff. See change: fix-duplicate-bridge-registration.

Exports `reportInboundDrop({dropClass, messageType?, droppedSessionId?})` — best-effort server-side record of an inbound message the bridge threw away, since the drop sites' `console.error` lands in `/dev/null` under the default `keeperLog.capturePiOutput:false`. Gated on a LIVE socket and sent via raw `ws.send`, never `this.send`, so a report is never buffered and replayed after reconnect (it would misdescribe when the drop happened). Bounded at 10 per session per 60_000 ms; elided reports ride the next permitted one as `suppressed`. Routing id is the bridge's OWN session (`ConnectionManagerOptions.getSessionId`); the dropped id travels as `droppedSessionId` payload. Wired at the `maxInboundQueue` overflow drop. See change: fix-spawn-correlation-ttl-coupling.

Migration gate (fix-bridge-mdns-migration-hijack): `updateUrl` is REPLACED by `retargetTo(newUrl, {trigger, verify?})` — the only endpoint mutation, and it is gated: cooldown (rejected endpoint not re-adoptable for `MIGRATION_COOLDOWN_MS`=60s) → established+registered protection (cold-start/never-registered migrates freely) → candidate health probe BEFORE dropping the incumbent (`verify`, D1) → localhost preference (remote never displaces established loopback, D3). Reversibility (D2): `failedOpensSinceMigration` counted only while `url !== lastRegisteredUrl`; at `MIGRATION_MAX_FAILED_OPENS`=4 the manager returns to `lastRegisteredUrl`, resets backoff, cooldowns the rejected endpoint. `noteRegistered()` (called by bridge at the initial register + `sendStateSync`) sets `lastRegisteredUrl` when the register went out on a LIVE socket; a note while connecting is promoted on open. Every decision — accepted or refused, including fallback — fires `onMigrationEvent` exactly once (D5 record chokepoint; bridge routes it to `transportDiagnostics` as `retarget_accepted`/`retarget_refused`). Per-attempt `prepareConnect` URL override now applies to the DIAL only (`openSocket(dialUrl)`), so the base endpoint is never mutated by ticket preparation. Pinned by `connection-migration.test.ts` (+ migrated `connection.test.ts` retargetTo block).

Adds `ConnectionManagerOptions.onPostFlush?: () => void` — fired after the drop-buffered frames are flushed onto the reopened socket, and paired with `onReconnect` (skips the first open). `onopen` fires `onReconnect()` BEFORE the flush, so anything sent from there overtakes a buffered real `agent_end`: a status correction sent that early would settle the session to `idle` first and the real `agent_end` would arrive with `before.status === "idle"`, erasing the `streaming→idle` edge `isUnreadTrigger` needs. Ordering pinned by construction, not by comment. See change: fix-stuck-streaming-status-latch (D8).
