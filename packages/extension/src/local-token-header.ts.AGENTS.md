# local-token-header.ts — index

Bridge side of D6: `readLocalToken(env?)` + `localCredentialPlan(endpoint, deps?)` → `DialPlan` for a LOOPBACK `ws:`/`wss:` dial only (undefined for `ws+unix:`, remote, or no token and no marker; no pre-connect then; `ws:` pre-connects via `net.connect`, `wss:` via `connectTls` = `tls.connect` with `servername` unless an IP host). It pre-connects the socket itself (injectable `connect` / `connectTls`), binds a fresh `X-Pi-Local-Proof` to `canonicalBinding(socket.remoteAddress, socket.remotePort)`, and hands the socket to `ws` via `createConnection`; the raw token is never sent. `markerEnforces(marker, endpoint)`: empty ⇒ unmarked; parsed marker enforces only on the same endpoint (host case-insensitive literal, port after default); an unparsable non-empty marker enforces on every loopback dial. A marked dial adds `verifyUpgrade` (counter-proof from `X-Pi-Local-Proof-Server`, causes `server-proof-missing`/`server-proof-invalid`); no token + marked ⇒ fails closed. Wired as `planDial` in `bridge.ts`. See change: add-pi-gateway-transport-identity (task 5.3); loopback-credential-proof (D1, D6, D7).

Counter-proof now required on EVERY loopback dial (`ws:` and `wss:`) for a token holder, independent of the spawn marker: `requiresServerProof({endpoint,tokenHeld,optOut,marker})` (`ws+unix:` exempt; no token + marked ⇒ still fails closed). Explicit opt-out `ALLOW_UNPROVEN_LOCAL_SERVER_ENV` = exactly `PI_DASHBOARD_ALLOW_UNPROVEN_LOCAL_SERVER=1` (logs `skipping server counter-proof` once per dial; the proof header is still sent). `wss:` dials open a TLS socket via `connectTls` (default `tls.connect`). `proofFailureLogCause(cause)` maps `server-proof-missing` → logged `server_proof_missing`. New deps `connectTls`, `allowUnproven`, `log`. See change: harden-bridge-inbound-and-discovery (D19).
