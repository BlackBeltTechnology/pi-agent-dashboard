# server-launcher.ts — index

Spawns dashboard server as detached process via shared `launchDashboardServer`. Exports `LaunchResult`, `resolveServerCliPath`, `buildBridgeEnvOverrides` (was `buildSpawnEnv`), `buildSpawnArgs`, `launchServer`, `DEFAULT_SERVER_MAX_OLD_SPACE_MB`. Resolves CLI path (monorepo-dev vs installed), stamps `DASHBOARD_STARTER=Bridge`, logs to `getDashboardServerLogPath()`, 10s health timeout. `buildSpawnEnv` adds `--max-old-space-size=<serverHeap.maxOldSpaceMb>` to `NODE_OPTIONS` (heap headroom) unless the user already pinned a limit. See change: bound-subagent-event-serialization. Classifies `JitiNotFoundError`/`PortConflictError`/`EarlyExitError` → `logOwned` flag.

`DEFAULT_SERVER_MAX_OLD_SPACE_MB` is now `DEFAULT_SERVER_HEAP.maxOldSpaceMb` (1536, was a hardcoded 8192). `buildSpawnEnv(baseEnv, maxOldSpaceMb?)` delegates the stamp to shared `stampHeapFlag`, replacing the dash-or-underscore regex that could not tell the dashboard's own stamp from an operator's pin (and had drifted from the wrapper's substring test). CRITICALLY, `launchServer` now PASSES `env: buildSpawnEnv(process.env, config.serverHeap?.maxOldSpaceMb)` to `launchDashboardServer` — it previously passed none, so this builder was exported and tested but never ran in production. Not tidying: once the spawn-side strip lands, a bridge-auto-started server inherits a STRIPPED env and would otherwise run at the bare V8 default on exactly the recovery path where the event store is hottest. See change: bound-session-heap-and-gc-telemetry.

`buildSpawnEnv` REPLACED by `buildBridgeEnvOverrides(baseEnv, heapMb)` → narrow overrides only: `DASHBOARD_STARTER=Bridge`, `NODE_OPTIONS` + heap marker (`stampHeapFlag` over two-key seed; absent → `undefined`), `PI_DASHBOARD_ELECTRON`/`PI_DASHBOARD_RESOURCES_PATH` = `undefined`. `launchServer` passes it; no full `process.env` copy (`server-launch` spec) → shared launcher keeps `buildSpawnEnv` PATH prepends on every platform. See change: fix-windows-path-env-key-casing.
