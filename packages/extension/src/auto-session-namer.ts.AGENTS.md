# auto-session-namer.ts — index

Automatic session topic-naming (bridge-side). Pure helpers `shouldSkipByPrefilter`, `parseTitle`, `buildTranscriptWindow`, `isEligible`, `classifyNameChange`, `generateTitle` (in-process pi-ai `streamSimple` + `registry.getApiKeyAndHeaders`; carries the stream's normalized stop `reason`; hard-error on unknown model / OAuth-only-unauthable, soft-error on transient), `SUMMARIZER_SYSTEM_PROMPT`. `createAutoNamer(hooks)` = per-session state machine: eligibility gate, pre-filter, model call, verdict-based parse (`title`/`waiting`/`starved`), once-only auto-name, provenance latch (auto→external→user lockout via `onObservedName`), one-shot `emitError`. `sanitizeSessionName` (newline-collapse + trim, pi's own sanitization) applied inside `classifyNameChange` both sides so a newline-bearing self-title matches the sanitized `session_info_changed` name (self-lockout regression guard). See change: add-auto-session-naming, adopt-pi-074-080-features. Naming is BOUNDED and LOUD: `parseTitle(raw, stopReason)` keys on the stop reason BEFORE the text so a truncated fragment is never applied; adaptive cap `TITLE_MAX_TOKENS_BASE` 1024 -> `TITLE_MAX_TOKENS_ESCALATED` 2048 once a session records `starved`; ONE attempt budget (3) shared by `starved`+`waiting` then a permanent stop with a cause-matched remedy (tie -> starved); transient errors and aborts spend nothing; `PersistedNamerState` carried across reload as VALUES + persisted to `.meta.json`, cleared by re-resolution (never a roles event) which resets budget AND re-arms the error; eligibility re-checked AFTER the await and the re-entrancy guard latched BEFORE it; every exit path reports exactly one deduplicated outcome. Model = `@naming` -> `@fast`. See change: fix-auto-naming-reasoning-model.
