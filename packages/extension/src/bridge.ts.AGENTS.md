# bridge.ts — index

Main bridge extension entry (default export). Connects to dashboard server, forwards pi events via `mapEventToProtocol`, relays `ServerToExtensionMessage` commands back. Wires `PromptBus`, `DashboardDefaultAdapter`, provider register, role manager, flow listeners, metrics monitor, model/git/session trackers. `tool_execution_end` runs `inlineToolResultImages`; applies its result on result-identity change (not `inlinedCount>0`) so strip-only rewrites propagate. See change: fix-duplicate-inlined-screenshot. On `agent_end`, classifies terminal assistant msg via `classifyTurnActionability` + `EmptyActionableGuard.observe`: `continue` → `enqueueSystemFollowup(CONTINUATION_NUDGE)` (only when `bridgeFollowUp` empty); `surface` → forwards `empty_actionable_surface` event (non-error). Never leaves an empty-actionable turn silent-idle. See change: fix-gemini-subagent-silent-tool-schema-failure. Routes `role_remove` (emit `roles:remove`; on success re-emit `roles_list`); all `roles_list` sends carry `builtinRoleNames`. See change: add-custom-roles-ui. See changes: simplify-error-retry-single-card, fix-retry-error-lifecycle — no billing special-casing. Retry synthesis: `message_end` records error or closes active chain on first non-error/non-aborted assistant completion; `agent_end` emits waiting; armed `agent_start` emits deferred in-flight start only while tracker remains active; native `agent_settled` closes unresolved chain. Abort installs tracker cancellation before `ctx.abort`; only observed user `message_start` releases it. Floor-pi waiting attempts forward `agent_settled{retryPending:true}`; expected-attempt deadline terminalizes only when matching `agent_start` never arrives. EventBus forwarding is per-channel `pi.events.on` subscription via `registerEventBusForwarding` (NOT an `emit` intercept -- `pi.events` is per-extension, so a patch never saw foreign emits; see change: fix-automation-run-lifecycle). Its handler treats subagent channels as reconcilable: forward live only when `sessionReady && isActive() && connection.isConnected`, else `subagentFrameBuffer.buffer` (covers `!sessionReady` AND transient WS drops — `sessionReady` stays true across reconnects, so gating on `connection.isConnected` keeps reconnect-window frames in the per-agent buffer instead of the shared FIFO ring). `flushPendingSubagentFrames()` after `sessionReady=true` AND in `onReconnect`; `subagentFrameBuffer.reset()` on session change/shutdown. `onMessage` handles `subagent_resync_request` → replies synthetic `subagents:started` `event_forward` from `subagentFrameBuffer.resync`. See change: fix-subagent-live-detail-reliability. Subscribes `agent_settled` (enriched): forwards native; floor-pi uses `settleFollowUp` plus waiting/expected-attempt reconciliation so per-attempt compatibility settles cannot clear active retry state. Registers `session_info_changed` → `autoNamer.onObservedName` (push external renames early; poll fallback) and `project_trust` → `decideProjectTrust` (auto-trust dashboard-spawned headless in `activationCwd`, captured at activation). See change: adopt-pi-074-080-features.
 `ctx.ui.notify` is no longer proxied onto `prompt_request`: the patch now installs `createNotifyProxy` (notify-proxy.ts), which sends `{type:"notify", sessionId, notifyId, message, level?}` on the dedicated channel — never PromptBus, no `as any` at the send site. See change: split-notify-from-prompt-request.

The `session_start` `session_register` (a FRESH session's FIRST register) now carries `pid: process.pid` and `spawnToken` via `consumeSpawnToken()`. Both were absent while `session-sync.ts`'s two registers had them: for a tmux spawn the server therefore had NO pid (`tmux new-window` returns tmux's pid) so shutdown could not terminate the session, and tier-1 spawn correlation never fired so concurrent spawns produced false register-timeouts. Pinned by `session-register-carries-pid.test.ts`. See change: fix-tmux-session-shutdown-leak. Follow-up buffer state moved to `followup-buffer.ts` (`createFollowupBuffer()`): entries are `{text, images?}`, bounded by depth AND aggregate bytes; `emitQueueUpdate` projects to `{text, imageCount}` so image bytes never cross the wire; the drain sends `buildUserMessageContent(entry.text, entry.images)` with NO send options; all four refusal sites (`bufferFollowupSend` cap+bytes, `enqueueSystemFollowup` under command `enqueue_followup`, `edit_followup_entry` bytes, image-validation drops) emit `command_feedback{status:"error"}` via `sendCommandFeedback` instead of a silent `console.warn`. FOUR mutation handlers, not five. See change: fix-bridge-followup-image-drop.

Migration wiring (fix-bridge-mdns-migration-hijack): the autoStart-discovery `.then` no longer blanket-refuses via `decideRetarget(identityVerified:false)` — that also blocked every LEGITIMATE migration. Pinned endpoints still refuse (decideRetarget + `retarget_refused` record). Unpinned: the candidate goes through `connection.retargetTo(candidateUrl, {trigger, verify})` with `verify = probeEndpointReachability(http://<host>:<httpPort>/api/health)` on the record's HTTP port; adoption, refusal and fallback are decided (and recorded) on the connection. `ConnectionManager.onMigrationEvent` is the single record chokepoint → console.log + `transportDiagnostics` (`retarget_accepted`/`retarget_refused`, protocol union extended) — a re-target cannot occur without a record. `connection.noteRegistered()` called at the initial `session_register` send and inside `sendStateSync()` (the register-acknowledged marker driving reversal).
