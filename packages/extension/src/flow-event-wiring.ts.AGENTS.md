# flow-event-wiring.ts — index

Core EventBus forwarding for pi-subagents lifecycle channels. Exports `SUBAGENT_EVENT_MAP`, `registerCommandsChangedListener`. pi-flows channels are NOT core: the flows plugin bridge declares them via `dashboard:register-event-forward` (no `FLOW_EVENT_MAP`). See change: update-flows-plugin.

Also owns EventBus FORWARDING: `forwardBusEvent`, `forwardedBusChannels`, `registerEventBusForwarding`, `EventBusForwardingDeps`. Forwarding = ONE `pi.events.on` subscription per channel in `SUBAGENT_EVENT_MAP` (+`extraMaps`); returns a dispose releasing them. MUST NOT wrap `pi.events.emit`: pi gives every extension its OWN `events` facade over the shared bus (`createExtensionAPI` -> `events:{emit,on}`), so an emit patch saw only the bridge's own emissions -- pi-flows `flow:complete` never forwarded, automation runs hung until the max-age reaper. `forwardBusEvent` keeps the gates: subagent channels forward only when ready+active+connected else `subagentFrameBuffer.buffer` (latest-wins); other channels forward when ready+active; forwarding never throws into the emitter. See change: fix-automation-run-lifecycle.

`registerCommandsChangedListener(bc,isSessionReady)` re-sends `commands_list` on the generic `dashboard:commands-changed` bus signal (payload ignored); any plugin emits it (flows: on `flow:rediscover`/`flow:complete`). See change: update-flows-plugin (D4).
