# followup-drain.ts — index

Pure follow-up drain gate sequence, extracted from `bridge.ts` so tests drive the real decision, not a mirror. Exports `drainOneFollowup({buffer, ctx, emitQueueUpdate, sendUserMessage})` → `DrainOutcome` (`empty`/`pending`/`busy`/`sent`/`lost`), `DrainContext`, `DrainDeps`. Gates in order: empty buffer, `ctx.hasPendingMessages()` (pi owns queued items), `ctx.isIdle()` — ONE check, no retry timer; next `agent_settled` drains. Then pop-before-send, emit-before-send, fresh-turn send with NO options (`buildUserMessageContent`), catch-and-drop (`console.warn` `drainFollowupQueue … entry lost`, no re-push). `bridge.ts` keeps the `isDraining` lock; `bridge-handlers/forwarders.ts` schedules `setTimeout(drain, 0)` from the `agent_settled` branch. Tests: `followup-drain.test.ts`, `forwarders-followup-drain.test.ts`. See change: update-pi-core-1-3-adopt-apis.
