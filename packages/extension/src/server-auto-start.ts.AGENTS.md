# server-auto-start.ts — index

Auto-start orchestration: discover dashboard via mDNS → health-check fallback → spawn server process. Exports `DiscoveredServer`, `AutoStartDeps`, `AutoStartResult`, `autoStartServer`. Honors `PI_DASHBOARD_NO_MDNS` opt-out gate, `shouldSuppressAutoStart` restart-quiesce hook, `onServerSpawned` PID exclusion callback, `onLaunchStart`/`onLaunchEnd` spinner hooks. Surfaces `getDashboardServerLogPath()` on launch failure.

Auto-start now runs two guards BEFORE the spawn step, both before `onLaunchStart` so neither leaks a spinner. (1) Worktree refusal (`autostart-guard.ts`): resolved cliPath in a `.worktrees` segment AND (port 8000 OR piPort 9999) → log + `{}`, never `launchServer`, never a lockfile. (2) Single-flight (`autostart-lock.ts`): winner spawns inside `try/finally` (lock always released, records `childPid`); loser logs the holder, then POLLS (`lossPollIntervalMs`, default 250ms) until the dashboard answers or the holder releases, bounded by the holder's REMAINING `SPAWN_READINESS_BUDGET_MS`, and attaches or returns `{}`. Reachable-dashboard path still short-circuits before either guard (P2 <5ms). New test seams: `resolveCliPath`, `lockDir`, `lockProbes`, `log`, `readinessBudgetMs`, `lossPollIntervalMs` (there is deliberately NO `sleep` seam — a stubbed sleep starves the macrotask queue and the loser spins the whole budget). Spawn body extracted to `spawnAndAttach`. See change: fix-worktree-server-autostart-leak.
