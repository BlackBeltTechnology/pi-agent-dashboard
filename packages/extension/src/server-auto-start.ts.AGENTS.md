# server-auto-start.ts — index

Auto-start orchestration: probe the RESOLVED port (bootstrap-aware) → when silent/foreign, mDNS discovery with health-verified candidates → deterministic selection → launch gates → spawn. Exports `DiscoveredServer`, `AutoStartDeps`, `AutoStartResult`, `autoStartServer`, `selectLocalCandidate`. Honors `PI_DASHBOARD_NO_MDNS` opt-out gate, `shouldSuppressAutoStart` restart-quiesce hook, `onServerSpawned` PID exclusion callback, `onLaunchStart`/`onLaunchEnd` spinner hooks. Surfaces `getDashboardServerLogPath()` on launch failure.

Discovery precedence (fix-autostart-discovery-precedence, D1–D4/D-post): the resolved-port gate runs FIRST with bootstrap-aware opts (`RESOLVED_PORT_PROBE_OPTS`: 8s timeout, 2 retries, retry on AbortError only — ECONNREFUSED falls to launch immediately); a SERVING resolved port is returned without consulting discovery and emits NO mismatch record/banner. Discovery runs only on the silent/foreign path; every candidate is admitted only after a `/api/health` probe at its ADVERTISED host+port (`firstVerifiedLocal`, rejections logged endpoint+reason); `portConflict` refusal applies only AFTER discovery yields no verified candidate (D2b). Selection is the shared total order `selectLocalCandidate` (resolved-port match → lowest port → host string; D3) — never arrival order. The mismatch warning+record survive ONLY on the probed-silent + verified-candidate path; the post-launch branch (`spawnAndAttach`) probes the resolved port with the same opts, never adopts an other-port candidate, and never raises the "resolved port silent" warning (D-post). Widened seam: `AutoStartDeps.isDashboardRunning(port, host?, opts?)` + `probeSleep` test seam (threads into `DashboardCheckOpts._sleep`). See change: fix-autostart-discovery-precedence.

Auto-start still runs two guards BEFORE the spawn step, both before `onLaunchStart` so neither leaks a spinner. (1) Worktree refusal (`autostart-guard.ts`): resolved cliPath in a `.worktrees` segment AND (port 8000 OR piPort 9999) → log + `{}`, never `launchServer`, never a lockfile. (2) Single-flight (`autostart-lock.ts`): winner spawns inside `try/finally` (lock always released, records `childPid`); loser logs the holder, then POLLS (`lossPollIntervalMs`, default 250ms) until the dashboard answers or the holder releases, bounded by the holder's REMAINING `SPAWN_READINESS_BUDGET_MS`, and attaches or returns `{}`. Reachable-dashboard path still short-circuits before either guard (P2 <5ms). Lock-loser + post-failure probes stay on the default 2s/0-retry probe. Test seams: `resolveCliPath`, `lockDir`, `lockProbes`, `log`, `probeSleep`, `readinessBudgetMs`, `lossPollIntervalMs` (there is deliberately NO `sleep` seam — a stubbed sleep starves the macrotask queue and the loser spins the whole budget). See change: fix-worktree-server-autostart-leak, fix-autostart-discovery-precedence.
