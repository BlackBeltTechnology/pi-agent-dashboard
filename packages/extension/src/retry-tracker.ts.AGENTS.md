# retry-tracker.ts — index

Pure helper class `RetryTracker` synthesizes `auto_retry_start` / `auto_retry_waiting` / `auto_retry_end` by OBSERVING pi's own retry behavior — NO regex. pi ExtensionAPI does NOT expose `auto_retry_*` and nothing lands on the EventBus (re-verified pi 0.81.1 + 0.83: retry lifecycle events go to RPC/SDK consumers ONLY; 0.83's `willRetry` is compaction-only, on `session_before_compact`/`session_compact`). The bridge is an extension, so it must observe-synthesize.

**CORRECTED observe model (change: retry-forever-with-stop-control).** pi does NOT keep a retry chain inside one agent turn. Measured: every attempt is a complete `agent_start` … `agent_end` cycle, and exactly ONE `agent_settled` fires after the final `agent_end`. The prior model (error `message_end` → fresh assistant `message_start` in the same turn) never matched, so the tracker synthesized ZERO events and the retry surface was dead in production — replaying pi's real order through the old tracker yielded `auto_retry_start emitted: 0`.

Rules: error assistant `message_end` records pending error text, emits NOTHING, does not clear the chain. Error `agent_end` = an attempt ended and another is (optimistically) coming → advance the counter, arm the next `agent_start`, emit `auto_retry_waiting{attempt,maxAttempts,delayMs,nextAttemptAt,errorMessage}`; chain NOT cleared. Waiting signal SUPPRESSED once `attempt > maxRetries` (no further attempt will follow). Armed `agent_start` → emit `auto_retry_start` (waiting:false, in flight). `agent_settled` = SOLE terminal → emit `auto_retry_end{success,attempt,finalError?}` + clear all per-session tracking.

Native `agent_settled` carries NO `messages` (verified), so the terminal disposition is remembered per-chain as `lastEndWasError` at `agent_end` time rather than read from the settle payload.

`maxAttempts`/`delayMs` come from injected `RetrySettings` (`{maxRetries,baseDelayMs}`, defaults 3/2000), sourced read-only by the bridge via `pi-retry-settings.ts`. `delayMs = baseDelayMs · 2^(attempt-1)` (pi's own arithmetic); `baseDelayMs <= 0` → `delayMs: 0` → surface renders elapsed-only. The `-1` sentinels are REMOVED. Tracker never writes pi's settings.

Exports `RetryTracker`, `SyntheticRetryEvent`, `ObservedAssistantMessage`, `RetrySettings`. API: `observeAgentStart(sessionId)`, `observeMessageEnd(sessionId,message)`, `observeAgentEnd(sessionId,agentEndData)`, `observeAgentSettled(sessionId)`, `noteAbort(sessionId)`, `isRetrying(sessionId)`. Bridge wiring: `agent_start` → `observeAgentStart` (synth deferred via `setTimeout(0)` so it lands AFTER `agent_start`, which the reducer uses to defensively clear `retryState`); `message_end` → `observeMessageEnd`; `agent_end` → `observeAgentEnd` (waiting signal, sent before the `agent_end` forward); `agent_settled` → `observeAgentSettled`; abort → `noteAbort`. A regression test pins pi's real event order so the next upstream shape change fails a test instead of the product. See change: retry-forever-with-stop-control.
