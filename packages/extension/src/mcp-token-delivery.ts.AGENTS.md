# mcp-token-delivery.ts — index

Bridge-side per-session registration of the dashboard MCP server with pi's BUILT-IN MCP. `createMcpDashboardRegistrar({pi, sessionId, reportUnavailable, log})` → `onMinted(msg)` / `onSessionStart()` / `onSessionShutdown()`. `onMinted` requires `token` + `url` and calls `pi.registerMcpServer("pi-dashboard", {url, headers:{Authorization:"Bearer <token>"}, exposure:"deferred"})`; re-mint re-registers (replaces). `onSessionShutdown()` → `pi.unregisterMcpServer("pi-dashboard")`. Guard: missing/throwing `registerMcpServer` or delivery without `url` → one warn (session id) + one `plugin_pi_message` `mcp-server`/`mcp/registration-unavailable` `{reason:"api-missing"|"register-failed"|"no-url"}`. Token NEVER in `process.env` (no more `PI_DASHBOARD_MCP_TOKEN`), never logged/files/`pi.events`. Exports `DASHBOARD_MCP_SERVER_NAME`, `McpRegistrationApi`, `McpTokenMintedPayload`. See change: migrate-mcp-to-pi-builtin. `onSessionStart` also unregisters a standing registration (replacement session never inherits the previous bearer). See change: migrate-mcp-to-pi-builtin (review r1 B1). `register-failed` logs the fixed reason only (no exception text — pi may echo the config with the bearer).
