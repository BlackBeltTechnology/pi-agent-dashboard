# credential-guard.ts — index

Always-on agent credential guard (no switch, not a sandbox). `createCredentialGuard({env,homedir,log?,resolveEnv?,canonicalize?})` → `handler(event,ctx)` sync → `{block:true,reason:"credential_guard: …"}`; path rules (read/edit/write/ls/find/grep; canonical target via shared `tool-path-resolve`; sibling `<name>.*`; grep dir directly containing a protected file; missing/empty `path` on grep/find/ls = `ctx.cwd`) + text rules over command-bearing fields only (path-like refs, data-key service + keychain verb, `security dump-keychain`, `credentials decrypt`; never write/edit content fields). Fail closed per call; logs `[credential-guard] blocked tool=… match=<rule>` / `error tool=…`, never command text. `createCredentialGuardToolCallHandler(guard,isActive)` = what `bridge.ts` registers (before the path gate, not `safe()`-wrapped). Protected set also holds pi provider secrets (`PI_AGENT_SECRET_FILES`: `auth.json`, `mcp-auth.json`, `providers.json`, `system-one/auth.json`) of `~/.pi/agent` + `PI_CODING_AGENT_DIR`; text needles built explicitly (no `slice` index coupling). Tests: `__tests__/credential-guard*.test.ts`. See change: encrypt-credentials-at-rest; harden-agent-tool-guards. `PI_CODING_AGENT_DIR` is trimmed and a leading `~` expanded against the injected home (pi parity); text needles keep both the literal and the expanded spelling.
