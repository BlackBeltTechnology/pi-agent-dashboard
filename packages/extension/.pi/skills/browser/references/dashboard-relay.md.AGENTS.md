# browser/references/dashboard-relay.md — index

AUTHORED (not vendored). Preferred login-state recipe when the pi session runs on the dashboard host. Flow: `GET /api/browser/status` → `GET /api/browser/profiles` → `POST /api/browser/connect {profileDirectory}` → `agent-browser connect <cdpUrl>` → `web.md` workflow → `POST /api/browser/disconnect?instanceId=`. Branch table on 404 / `enabled:false` / `canOpenChrome:false` / 409 `not-installed` / 409 `busy` / 503 / 504 (token mismatch and no-allow are indistinguishable → one 504). Policy denials are LOUD: CDP error `-32000` `Denied by dashboard relay policy: <method>` (cookie verbs + `file:`/`javascript:`/`vbscript:`/`data:`/`blob:` and `allowedDomains` fence); `Browser.setDownloadBehavior` is ack-and-drop (`{}`, never forwarded, audit `dropped`). Documents the pi tools `browser_show_in_pane {instanceId, tabId?}` (5 s rate limit; errors `disabled`/`unknown-instance`/`unknown-tab`/`no-tab`/`rate-limited`) and `browser_await_human {instanceId, reason}` (blocks on a confirm the pane's Done answers; `done`/`cancelled`, `no-ui`). See change: add-browser-editor-pane-tab — report, never retry. One tab group per instance; one CDP client per instance (second closed `Another CDP client already connected`); DevTools takes a tab (`Target detached: devtools`); loopback-only endpoints. NEVER fall back to the bundled browser for a login-state task. Supersedes `own-browser.md` (legacy) on the dashboard host.
