# event-status-extraction.ts — index

Extract session status/tool/model stats from forwarded events. Exports `extractStatsFromEvents` (accumulate token/cost/context totals from `stats_update` batch), `extractSessionUpdates` (per-event `status`/`currentTool`/`model`/`thinkingLevel` deltas from `agent_start`/`agent_end`/`tool_execution_*`/`model_select`/`session_before_compact`/`session_compact`/`session_compact_failed`/`ui_prompt_start`/`ui_prompt_end`), `isActivityEvent` (narrow allowlist for `lastActivityAt` stamping), `isUnreadTrigger` (streaming→idle/active, `ask_user` flip, `agent_end` with error). Flows/architect events excluded (plugin-owned). `extractSessionUpdates(event, hasPendingPrompt = false)` gains the pure fold: when the event-derived update would leave `currentTool` empty and a prompt is pending, `"ask_user"` is written instead. A live tool always wins (`tool_execution_start{bash}` -> `bash`, registry not consulted); `currentTool` absent from the update (model_select) means unchanged, not empty. With `hasPendingPrompt:false` output is byte-identical to pre-change. Stays pure - no gateway, socket, or session manager; the CALLER decides when the flag applies (live events only). See change: restore-ask-user-tool-state-on-reconnect.

pi 0.84 event arms: `session_compact_failed` (pi >= 0.84.3) clears `compacting`, without which a failed/aborted compaction latches the flag and the reload dispatcher refuses every later reload. `ui_prompt_start`/`ui_prompt_end` (pi >= 0.84.4) bracket a BLOCKING `ctx.ui` prompt and write `currentTool: "ask_user"` / `null` -- reusing the input-requested surface (and, via `isUnreadTrigger` trigger 2, the unread stripe) instead of leaving the last tool name on screen. `status` deliberately untouched: a UI prompt is not a run boundary. The 0.85.1 lockstep floor guarantees both events, so the arms need no version gate (the former "inert below floor" framing was retired in change: update-pi-core-0-85-adopt-apis). Forwarded by `bridge.ts` `passThroughEventTypes`.

Adds exported pure `reconcileAgentLiveness(currentStatus, agentRunning): SessionUpdates | null` — reconciles stored session status against bridge-reported liveness, because `status:"streaming"` is otherwise a one-way latch (`agent_end` is the only path back to `idle`, so one dropped `agent_end` sticks the card on `Thinking…`). Deliberately NOT an arm of `extractSessionUpdates`: it needs the session's CURRENT status, and keeping it off the event path is what keeps unread/naming/retry anchored to real `agent_start`/`agent_end` (D2/D3). Table (D9): `streaming`+`false` → `{status:"idle", currentTool:null}`; `idle`/`active`+`true` → `{status:"streaming"}` (currentTool untouched — a running agent may be inside a tool); `ended` inert both ways (a beat racing teardown must not resurrect); every agreeing cell `null` (no churn per beat). See change: fix-stuck-streaming-status-latch.
