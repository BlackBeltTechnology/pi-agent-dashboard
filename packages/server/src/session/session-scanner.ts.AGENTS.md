# session-scanner.ts — index

Cold-start session scanner. Exports `ScanResult`, `scanAllSessions(sessionsDir)` — scans `~/.pi/agent/sessions/`, reads `.meta.json` sidecars, falls back to JSONL parsing writing fresh meta. Seeds `lastActivityAt` from events.jsonl mtime, probes `cwdMissing`, reconstructs worktree parentage. Also restores `kind`/`live`/`liveEpoch`/`closedReason`/`isGitRepo`/`tags` from meta so cold-start recovery classifies interrupted sessions, ended git-repo sessions keep the +Worktree button, and tagged sessions stay tagged. See changes: reopen-sessions-after-shutdown, gate-session-worktree-button-on-git, add-session-tags. `sessionFromMeta` restores `automationRun` beside `kind` so a restored run keeps its board visibility (the filter reads `automationRun.visibility`) and its `session-card-badge` slot re-arms. See change: fix-automation-identity-persistence.

Module-private `inferWorktreeFromCwd(cwd)` — heals persisted records whose parentage the removed-worktree race cleared. Fires in `sessionFromMeta` only when persisted `gitWorktree` is absent/implausible. Requires an ABSOLUTE cwd of the form `<X>/.worktrees/<name>[/<sub>...]` (split at the FIRST `.worktrees` segment, non-empty absolute `<X>`) where `<X>/.git` stats, reusing `isPlausibleWorktreeMainPath` for the one stat. Declines with NO stat for a relative or leading-`.worktrees` cwd (would resolve `.git` against the server cwd). Read-time only — never rewrites `.meta.json`. KNOWN LIMIT: nested `<X>/.worktrees/<A>/.worktrees/<B>` returns `<X>`/`<A>` (first segment wins); foreign layouts untouched. Tests: `__tests__/session-worktree-phantom-repair.test.ts` (E10–E19, X1, P1). See change: fix-worktree-grouping-lost-on-remove.

Module-private `isPlausibleWorktreeMainPath(mainPath)` — load-time repair of persisted phantom `gitWorktree.mainPath`. A phantom never expires on its own: an ended session never re-probes and `.meta.json` re-seeds at every boot. Plausible = no `.git` path SEGMENT (exact component) AND `statSync(<mainPath>/.git)` succeeds. One stat per record, zero subprocesses. The `.git`-entry condition is load-bearing: `--separate-git-dir` / bare phantoms are REAL existing unrelated dirs. Dropped on ANY stat failure, not only ENOENT. Never rewrites `.meta.json` (read-time filter — a revert just stops filtering). KNOWN LIMIT: a phantom landing on a real working tree survives (bare hub at `$HOME/bare.git` → `$HOME` dotfiles repo); shape, not identity. Tests: `__tests__/session-worktree-phantom-repair.test.ts`. See change: add-git-checkout-root-resolver.
