# session-file-reader.ts — index

Standalone JSONL session reader. Exports `SessionEntry`, `loadSessionEntries(filePath)` (leaf→root branch order via parentId), `parseSessionEntries(lines)` — the parse half over LINES, no file; a retained REMOTE transcript resolves the SAME branch the origin machine would (see change: serve-retained-remote-transcripts), `createBranchedSessionFile(sessionFilePath, targetEntryId)` for fork-from-message. Linear fallback when no tree structure. Exports `findSessionToolCallPayload(filePath, toolCallId)` → `{ content?, edits? } | null`: scans `message.content[]` for `{ type:"toolCall", id === toolCallId }` (nested id, not entry top-level), returns `arguments.content` (Write) / `arguments.edits` (Edit) from the on-disk JSONL — the FULL untruncated payload surviving the in-memory ~4 KB cap / >20-op collapse. SECURITY: takes only a transcript path + a toolCallId used for equality (no path input, no traversal); missing file / unknown id / unparseable → null, no path fallback. Backs `GET /api/session-change`. See change: opt-in-out-of-cwd-session-diffs. Exports `findSessionCustomEntry(filePath, entryId)` → `{ customType?, data? } | null`: scans for `type:"custom"` with `entry.id === entryId` on the active branch, returning the FULL untruncated payload (same rationale: the store caps strings at ~4 KB and drops arrays >20 at INGEST). SECURITY: session-addressed only; ID equality, never a path. Backs `GET /api/sessions/:sessionId/entry/:entryId`. See change: add-custom-entry-renderer-slot.

See change: offload-retained-transcript-replay — exports `splitTranscriptLines(raw) = raw.trim().split("\n")`, the ONE splitter shared by `loadSessionEntries` (file arm) and the session-load worker's `raw` arm, so identical bytes produce identical entries — and therefore identical events — by CONSTRUCTION rather than by assertion. This is also what closes the BOM divergence: the file arm's inline `.trim()` stripped a leading U+FEFF while the retained store's splitter kept it. The store's own `entries` split is deliberately NOT moved onto this helper (see `remote-transcript-store.ts`).
