# event-wiring.ts — index

Wires pi-gateway events → browser-gateway + session manager. Exports `wireEvents`, `EventWiringDeps`. Handles `event_forward` (store insert, broadcast, status/unread/activity/OpenSpec/stats extraction, gated `completedFirst`/`questionFirst` reordering, throttled `lastActivityAt`), `session_register` (replay mode, skip-wipe dedup via eventCount, three-tier headless link token→pid→cwd-FIFO, `decideDashboardSource` stamp, ghost cleanup, spawn-correlation, worktree/automation/initial-prompt arms (initial-prompt arm dispatches first `send_prompt`; see change: project-init-skill-and-profiles), goal-driver link via `linkGoalDriver` (PRIMARY: `headlessPidRegistry.getGoalId(sessionId)` token path AFTER `linkByToken`; FALLBACK: legacy goal cwd-FIFO; `replaceDriver` + clears OUTGOING driver's `goalId` for C2e; clears `inFlightSpawn`), `maybeRekeyOrder`, `isGitRepo` stamp + `.meta.json` persist), `replay_complete`, `queue_update`, `prompt_received`, `flows_list` debounce, `git_info_update` (`composeWorktreePayload`, `isGitRepo` refresh + persist). `onUnregister` fans session death to plugins via `dispatchPluginSessionEnded` (EventWiringDeps). See changes: finalize-automation-run-on-session-death, gate-session-worktree-button-on-git, add-goal-session-supervisor. On live events: `empty_actionable_surface` → `console.log(buildEmptyActionableLogLine)` (server.log, non-error); `agent_end` with terminal error → `console.error(buildModelErrorLogLine)` via `extractModelTurnError` (redacted). See change: fix-gemini-subagent-silent-tool-schema-failure. `git_info_update` merges `gitStatus` when present (omitted on inconclusive probe leaves last value). `git_commit_draft_result` → `commitDraftRelay.resolve`; `commitDraftRelay` dep added. See change: add-session-uncommitted-indicator-and-commit.
 On live events also captures lifecycle run-boundaries via `captureLifecycleTimestamp` (`agent_start`->`lastRunStartedAt`, normalized `agent_settled`->`lastSettledAt`; skipped in replay) feeding the disabled-by-default embed-lifecycle reaper; automation-run arm stamps `lifecyclePolicy:"ephemeral"` (mem+meta+broadcast). See change: add-embed-session-lifecycle. Derives `currentTool:"ask_user"` from the PromptBus registry via two mechanisms: M1 folds `browserGateway.hasPendingPromptRequests(sessionId)` into `extractSessionUpdates` at the ordinary call site for LIVE events only (never during replay; the `skipReplayInsert` fast path stays unfolded); M2 writes directly in the `prompt_request`/`prompt_dismiss`/`prompt_cancel` sibling branches, which sit outside the `event_forward` block and never reach the extractor. The `prompt_request` branch is trigger-complete - it evaluates the unread trigger and the `questionFirst` reorder itself (shared `stampUnreadIfTriggered` + `moveSessionToFrontAndBroadcast` helpers) so correctness does not depend on whether it or `tool_execution_start` wins the race. Both replay exits (`replay_complete`, now guarded by `if (replayingSessions.delete(sessionId))` like the 5s safety timeout already was) run reconcile -> recompute -> drain via `reconcileAndRecomputeOnReplayExit`, against the ephemeral per-replay `replayPromptIds` set; the recompute is registry-non-empty => `"ask_user"`, empty => leave the event-derived value alone. `onUnregister` clears both pending registries. See change: restore-ask-user-tool-state-on-reconnect.
 Splits notify out of the prompt path. The `prompt_request` branch keeps a PERMANENT skew guard: after the owner/`ended` check and BEFORE `trackPromptRequest`, `prompt.type === "notify"` early-outs through `handleNotify(fromLegacyPromptRequest(msg))` — an already-published bridge still sends the legacy shape, and everything downstream of the phantom "Needs you" flows from that one `trackPromptRequest` call. A sibling `msg.type === "notify"` branch handles the new shape: owner/`ended` guard, then `handleNotify` (append to the bounded notify log + `sendToSubscribers`) and return — no tracking, no `currentTool` write, no unread stamp, no `questionFirst` reorder, no `session_updated` broadcast. See change: split-notify-from-prompt-request.

`plugin_pi_message` dispatch now forwards the gateway's `sessionId` as a third argument to `dispatchPluginPiMessage(messageType, msg, sessionId)`. The id is the connection's registered session (`currentSessionId`), never `msg.sessionId` — the gateway now excludes `plugin_pi_message` from body-sessionId precedence — a plugin attributing a bridge message to a session (e.g. minting a session-scoped credential) depends on that being unspoofable. See change: add-dashboard-mcp-server.

Adds a `session_heartbeat` branch: when the beat carries `agentRunning` and the session is not replaying, `reconcileAgentLiveness(session.status, msg.agentRunning)` is applied via `sessionManager.update` + `broadcastSessionUpdated`, and logs `[reconcile] session <id>: <prev> -> <next>` on a correcting one (a heal is evidence a run-boundary event was lost). Deliberately does NOT call `stampUnreadIfTriggered` — the unread exemption is by CALL PATH, not by a flag. Honours the replay window (accumulated replay state is better truth than one beat) and the pending-prompt gate (a live `ask_user` keeps `currentTool`). See change: fix-stuck-streaming-status-latch (D3/D10). Every terminal `session_updated` broadcast carries `closedReason`, so a card watched live learns WHY it ended instead of only on the next full snapshot. `sessionManager.onEnded` writes liveness + `closedReason` eagerly on the exact terminal transition from BOTH seams (it replaced the unregister-only write, which missed `update()`-based endings — reload-spawn failure, zombie normalization, move). See change: stop-discarding-known-session-state.

`sessionManager.onEnded` also HEALS orphaned work: derives `findOpenToolCalls`/`findOpenSubagents` over `eventStore.getEvents(sessionId, 1)` (`session/open-tool-calls.ts`), inserts + broadcasts one `tool_execution_end{isError:true, result:"parent session ended", healedBy:"session_ended"}` per open call and one `subagent_failed` per non-terminal subagent, BEFORE the `session_updated{ended}` broadcast. Skips a session with `session.movedTo` set (relocation is not a death). Broadcast suppressed while `replayingSessions.has(sessionId)`; insert is not. Idempotent via the store — a second `onEnded` finds nothing open. See change: heal-orphaned-tool-cards-on-session-end.

Wires `piGateway.onDisconnect` -> invalidate the provider catalogue once no bridge session remains. See change: redesign-providers-settings-page (D5).

Carries the one-release `dispatch_extension_command` TOMBSTONE: on receipt it `console.warn`s once and persists + broadcasts `command_feedback {command, status:"error", message:"bridge outdated — reload the session"}` (persist FIRST — a broadcast-only terminal re-creates the stuck "in progress" pill on browser reattach). No keeper socket is written; a throwing `eventStore.insertEvent` is caught and logged so the WS handler never rejects. See change: retire-slash-dispatch-via-expand-prompt-templates (D4).
