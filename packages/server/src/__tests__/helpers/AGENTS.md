| `draining-ws.ts` | Timing-aware fake WebSocket for the broadcast load harness. `createDrainingWs({ drainRateBytesPerMs, readyState? })` models the send queue as a byte counter that fills on `send(frame)` and drains FIFO under a caller-owned virtual clock (`advance(ms)`, `drainFully()`, `now()`). Records `SentRecord[]` (`seq`, `enqueuedAt`, `bytesAtEnqueue`, `bytes`, best-effort `type`/`cwd`/`sessionId`) and exposes `timeToFlush(predicate)`, `flushTimes`, `bytesWhere`, `peakBufferedAmount`, `terminate()` + `terminatedCount()`, `close()`. Linear drain ignores TCP slow-start/Nagle/OS buffers — proves RELATIVE head-of-line effects deterministically, never absolute ms. Contrast the static `makeFakeWs` in `browser-gateway-broadcast-serialize-once.test.ts` (frozen `bufferedAmount: 0`). |

Probes: `aborted`, `promptsSeen`, `answers`, `openListeners`, `settled`, `interaction`. Module-level `totalOpenListenerCount()` / `resetFakeFlows()` account every fake's open prompt listeners (must return to 0 after pruning). Provider presets: `anthropicFlow`, `openrouterFlow`, `codexFlow`, `githubCopilotFlow`, `deviceCodeFlow({ expiresInSeconds? })`. See change: delegate-provider-oauth-to-pi-ai (D1, test-plan task 3.1). |
