# recovery-server.ts — index

Pure `node:http` recovery server. `startRecoveryServer({port, error})` spawned by `cli.ts` `runForeground` when top-level deps (fastify/toad-cache/etc) fail to resolve. Binds same port. Serves status HTML at `/`, `GET /api/health` returns `{mode:"recovery", error}`, `POST /api/recovery/retry` respawns dashboard via `process.execPath`, `POST /api/recovery/reinstall` runs `npm install` in detected layout. Zero third-party imports. `parseModuleNotFoundError(msg)` extracts missing specifier; `isModuleNotFoundError(err)` checks `ERR_MODULE_NOT_FOUND` / `MODULE_NOT_FOUND`; `detectInstallLayout(cwd)` returns `monorepo` / `npm-global` / `electron-bundled` / `unknown`; `detectPackageManager(repoRoot)` → `pnpm` when `pnpm-workspace.yaml`/`pnpm-lock.yaml` present, else `npm`; `suggestedReinstallCommand(layout, scriptPath?)` maps layout → shell cmd and for `monorepo` honours the repo's package manager (npm-installing a pnpm `nodeLinker: hoisted` workspace drifts the tree → nested wrong-version deps → pi fails to boot); `runReinstall` executes the same manager. See change: recovery-server-respect-package-manager; `buildRecoveryHtml({error, layout, cmd})` escapes XSS. Writes `~/.pi/dashboard/last-recovery.json` snapshot (timestamp, error, layout, cmd) on start. See change: add-startup-recovery-server.
