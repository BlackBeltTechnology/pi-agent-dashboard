# spawn-register-watchdog.ts — index

Arms per-spawn timer; fires `spawn_register_timeout` if pi never registers. byPid + byCwd + byToken maps. recentlyFired keyed by token when present, normalized cwd otherwise (one index per entry), evicted on a `RECOVERY_GRACE_MS` timer, emits at most one `spawn_register_recovered` per fire (never a `requestId` — `session_added` carries that). cwds normalized via `normalizeCwdKey` (realpath, raw-string fallback) at arm and every clear, so `/tmp` vs `/private/tmp` no longer misses. Every `clearBy*` returns whether it claimed the entry, so the pi-gateway cascade is tier-aware and registering one spawn no longer disarms a concurrent same-cwd spawn. Fire + recovery are logged, the persisted `REGISTER_TIMEOUT` names the per-entry effective timeout and carries `spawnToken`, and a recovery appends a `REGISTER_RECOVERED` companion joined by that token. `armSpawnWatchdog(cwd, mechanism, result, ws?, timeoutMs?)` returns the timeout it armed with, so callers derive every TTL from the same read. Firing also RECLAIMS the spawn — `findPidsBySpawnToken` → kill ladder — because a pi that never registers has no session record and is unreachable by shutdown/reap/idle-reclaim (measured: tmux panes stuck on pi's trust prompt, ~127 MB each). Never kills `process.pid`/`ppid`; kill runs BEFORE the `ws.readyState` early return; a cwd entry with its own token is not disarmed by a sibling spawn. Inject `WatchdogReclaimDeps` in tests. See change: spawn-failure-diagnostics, fix-tmux-session-shutdown-leak (D7), fix-spawn-correlation-ttl-coupling.
