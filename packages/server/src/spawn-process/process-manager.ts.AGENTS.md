# process-manager.ts — index

Spawns/kills pi sessions. Exports `spawnPiSession`, `buildSpawnEnv`, `buildHeadlessArgs`, `buildTmuxCommand` (argv `string[]`, not shell string), `spawnTmux`, `spawnWslTmux`,… → see `process-manager.ts.AGENTS.md`. See change: fix-tmux-cwd-command-injection.

Spawn pin: `buildSpawnEnv` sets `PI_DASHBOARD_URL=ws://localhost:<spawnDashboardPiPort>` AND, when this instance serves a socket at that port, `PI_DASHBOARD_SOCKET=<gateway-<piPort>.sock>`; any inherited `PI_DASHBOARD_SOCKET` is deleted first (it outranks our URL in the bridge ladder, so it would re-create the cross-instance capture the pin prevents). See change: add-pi-gateway-transport-identity (task 2.0f).

Scope env: `SessionOptions` gains `extensionConfig?: Record<name, Record<key, string | string[]>>` (structural superset of shared `SessionFlags`; populated by `pluginSpawnToSessionOptions`). `buildSpawnEnv(baseEnv, { extensionConfig })` projects each `extensionConfig[name][key]` → `PI_EXT_<NAME>_<KEY>`; name+key normalized via `normalizeEnvSegment` (camelCase boundary → `_`, then uppercase, then non-`[A-Z0-9_]`→`_`, so `allowedRoots`→`ALLOWED_ROOTS`, `api.key`→`API_KEY`). A scalar `string` value projects verbatim; a `string[]` projects as `JSON.stringify(value)` (lossless for path arrays, D8). Absent ⇒ env untouched (byte-identical). NUL-bearing value already dropped by the mapper. Only `spawnHeadless` passes `extensionConfig` (plugin spawns are headless-only); tmux/wt/wsl paths never project it. See change: add-plugin-spawn-scope.

Cwd policy funnel (Part B): `setCwdPolicyRegistry(registry)` wires the single `CwdPolicyRegistry` instance into `spawnPiSession`, which resolves the cwd policy and `mergeCwdPolicy`s it into `options` BEFORE building argv/env — for EVERY spawn (plugin or generic). No matching policy ⇒ merge returns options unchanged ⇒ byte-identical argv/env. See change: add-plugin-spawn-scope (Part B host-cwd-policy).

Session heap ceiling: `buildSpawnEnv` calls `stripDashboardHeapFlag(env)` so the SERVER's own `--max-old-space-size` stops reaching pi and, through `NODE_OPTIONS` inheritance, every vitest/tsc/vite an agent runs. Provenance-gated on `PI_DASHBOARD_HEAP_FLAG`; an operator pin is preserved verbatim. `sessionHeapArgs()` reads `loadConfig().sessionHeap` FRESH at spawn time, so the boundary is the next spawn (a reload is a kill + fresh `spawnPiSession`) with no server restart. `applySessionHeap(piCmd, rt, mechanism)` wraps `applyHeapArgsToPiArgv` and, on no runtime slot, logs a `[heap]` line AND calls `recordHeapArgvFallback` (surfaced at `/api/health` `sessionHeapFallback`). Per mechanism: headless puts the flags in the invocation handed to the keeper (so pi is capped and the SUPERVISING keeper is not — and the env fallback is deliberately NOT taken here, since the keeper re-passes its env to pi); `wt` uses argv and MAY take the env fallback; `buildTmuxCommand` gained a `heapNodeOptions` param delivering `-e NODE_OPTIONS=<subset>` per window for tmux + wsl-tmux, because a pane's env comes from the long-lived tmux server and `spawnWslTmux` keeps `["pi"]` literal for the guest namespace. Inside a pane descendants DO inherit the ceiling — the accepted cost of reaching the pane. See change: bound-session-heap-and-gc-telemetry.
