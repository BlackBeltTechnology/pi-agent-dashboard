# process-manager.ts — index

Spawns/kills pi sessions. Exports `spawnPiSession`, `buildSpawnEnv`, `buildHeadlessArgs`, `buildInteractivePiArgs`, `buildTmuxCommand`, `spawnTmux`, `spawnWslTmux`, `shellEscape`, `setResolver`/`resetResolver`, `setKeeperManager`/`getKeeperManager`, `SessionOptions`, `SpawnResult`. Supports tmux/headless/interactive/rpc-keeper strategies. `SpawnResult` carries `spawnToken`, `keeperSockPath`, `code` (`SpawnFailureCode`). `buildSpawnEnv` takes optional `argv0`/`electronDeps`; when `argv0` is the Electron binary (`electronAsNodeRequired`) re-adds `ELECTRON_RUN_AS_NODE=1` that `resolver.buildSpawnEnv` strips (absent argv0 ⇒ byte-identical). `buildTmuxCommand(cwd, sessionExists, options?, piInvocation=["pi"])` returns `string[]` argv (NOT a shell string): `cwd` travels as a literal `-c <cwd>` element and the redundant `cd <cwd> &&` prefix is dropped, so no dashboard-side shell interprets the workspace path (command-injection fix). `spawnWt`/`spawnHeadless` pass `piCmd[0]`; `spawnTmux`/`spawnWslTmux` (now exported) invoke via `buildSafeArgv` + `execFileSync` (`shell:false`), not `execSync(cmd)`. `spawnWslTmux` routes `wsl.exe --exec tmux …` (`.exe` bypasses the cmd.exe branch; `--exec` bypasses WSL's default shell) and passes `["pi"]` as `piInvocation` so `pi` resolves inside the WSL namespace. `shellEscape` is RETAINED for the pane command (tmux's own pane shell — layer 2 — remains by design). `buildTmuxCommand` passes the spawn token per-window with `tmux -e PI_DASHBOARD_SPAWN_TOKEN=...`: `execFileSync(argv,{env})` only sets the tmux CLIENT's env, so `new-window` inherited the tmux SERVER's and every window after the first carried the FIRST spawn's token (3 panes / 1 token, measured). See changes: spawn-correlation-token, add-rpc-stdin-dispatch-with-keeper-sidecar, spawn-failure-diagnostics, fix-nodescript-argv-electron-execpath-fallback, fix-tmux-session-shutdown-leak, fix-tmux-cwd-command-injection.
