# headless-pid-registry.ts — index

Registry mapping headless child processes → session IDs. Exports `createHeadlessPidRegistry`, `HeadlessPidRegistry`, `keeperOptsFromSpawnResult`, `KeeperRegisterOptions`, `KeeperWriter` (orphan discovery only — `writeRpc`/`writeRpcToSockPath` removed by change `retire-slash-dispatch-via-expand-prompt-templates`). Three-tier link (`linkByToken`/`linkByPid`/`linkSession`), keeper-mode `piPid` vs `keeperPid` split, `killBySessionId` (SIGTERM→2s→SIGKILL; kill pi first so keeper auto-exits), `cleanupOrphans`/`cleanupKeeperOrphans` (disk-persisted `spawnToken`/`piPid`/`keeperPid`/`keeperSockPath` survive restart). 7-day orphan max age. Test-guarded. `killByToken(spawnToken)` kills a spawned-but-unlinked entry (no sessionId) by stored token; shares the `killEntry` ladder with `killBySessionId`. `register(...,goalId?)` stamps an optional `goalId` on the entry (keyed to spawn token, round-trips restart); `getGoalId(sessionId)` resolves it after `linkByToken` — the PRIMARY goal-driver correlation (replaces goal cwd-FIFO). `listSessions()` enumerates every session-linked entry with its resolved pi PID + a `hasKeeper` flag — added so reload fan-outs can target a headless session whose bridge WS died (invisible to `getConnectedSessionIds()`, stamped `ended` in `sessionManager`). See changes: fix-out-of-band-reload, spawn-correlation-token, add-rpc-stdin-dispatch-with-keeper-sidecar, fix-keeper-kill-escalation, fix-automation-stop-zombie-runs, add-goal-session-supervisor.

`killEntry` keeper fallback (#912): 200 ms after the pi kill, `killProcessGroup(keeperPid,{timeoutMs:2000})` — gated on the keeper GROUP existing, not keeper liveness (pi is non-detached ⇒ shares keeper pgid; orphaned pi children stay in it). Replaces `isProcessAlive`+`killPidWithGroup(SIGTERM)`. See change: group-aware-kill-process.
