# cors-origin.ts — index

Pure CORS origin allow-decision extracted from the `@fastify/cors` callback in `server.ts` so it is unit-tested against real code (not a hand-mirrored copy). `isCorsOriginAllowed(origin, {configuredOrigins, trustedNetworks, getTunnelUrl})`: no-Origin→allow, `null`→DENY (preserved, opaque-iframe refusal), loopback→allow, active zrok URL→allow, `*.share.zrok.io` (v1) + `*.shares.zrok.io` (v2)→allow, `pi-dashboard.dev`→allow, configured→allow, host in `trustedNetworks` (via `isBypassedHost`, CIDR/wildcard/exact)→allow (LAN-to-LAN switching), else deny. CORS=read-authority, distinct from auth. See change: fix-remote-connect-cors-gates.

Also the ADMISSION decision (who may OPEN a socket / MUTATE state), sharing one code path with CORS so the two cannot drift. `isOriginAdmitted(origin, hostHeader, opts)` = `isCorsOriginAllowed` with two deltas: (1) Origin `host[:port]` equal to the request `Host` (URL-normalized both sides, origin's scheme applied to the Host so default ports elide) → admit — covers mDNS/plain-LAN pages that `isBypassedHost` (IP literals only) misses; (2) `allowZrokWildcard:false` — the `*.share(s).zrok.io` wildcard is CORS-only (default `true`), because a stranger zrok share is likely same-site to the victim's tunnel. Absent Origin→allow (non-browser clients send none); `""`, whitespace-padded, and malformed→deny. `isWsOriginTrusted(origin, host, scope, opts)` adds the `live`-scope `Origin: null` carve-out (sandboxed preview iframe, D3); `bridge` + unrouted `null` scope stay strict. `isMutationOriginTrusted` = `isOriginAdmitted`. `sanitizeHeaderForLog(value, max=256)` strips control chars + caps (attacker-controlled log fields, D5). See change: fix-ws-origin-cswsh.
