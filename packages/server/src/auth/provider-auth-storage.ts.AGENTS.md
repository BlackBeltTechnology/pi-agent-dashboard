# provider-auth-storage.ts — index

Reads/writes `~/.pi/agent/auth.json` for pi provider credentials via `proper-lockfile` + atomic write. Exports `ApiKeyCredential`, `OAuthCredential`, `AuthCredential`, `AuthData`, `getAuthStatus`, `getOAuthProvidersMeta`, `resolveAuthJsonKey`. OAuth rows from the `getOAuthRegistry()` runtime registry ∪ stored `{ type: "oauth" }` ids; API-key rows from `provider-catalogue-cache.ts`. Custom providers skipped (managed by LLM Providers settings). See change: replace-hardcoded-provider-lists.

Corrupt-content recovery: reads never fail on bad *content* — internal `readAuthJsonChecked()` returns `{ data, corrupt, quarantined }`, exported `readAuthJson()` is its tolerant `{}` wrapper. Unparseable bytes (empty/truncated/non-object) are COPY-quarantined (never renamed) to `auth.json.corrupt-<YYYYMMDDTHHMMSSsssZ>[-N]`, mode 0600, `wx` + `-N` suffix, SHA-256 content dedup (in-process, recorded only on a successful copy; a dedup hit reports `quarantined: true`). `ENOENT` stays `{}`; `EACCES` etc. still throw. `writeCredential`/`removeCredential` refuse (`corrupt && !quarantined`) under the lock; `withLock` placeholder create is mode 0600. See change: fix-corrupt-auth-json-500.

Async locking: `withLock`, `writeCredential` and `removeCredential` are ASYNC (BREAKING for any sync consumer — await them or the write stops being ordered). Acquisition is `proper-lockfile.lock()` (async, promise release), retried by our OWN loop over `err.code === "ELOCKED"` only, with awaited backoff summing under a 2 s budget — deliberately NOT the library's `retries` option, whose driver re-runs on ANY truthy error and would let `EACCES` eat the window. Lock options carried verbatim: `stale` (now 30 s — see below), `realpath: false` (async `lock()` defaults `realpath: true`, which would lock a DIFFERENT file on a symlinked home and drop mutual exclusion). `release()` is awaited in the `finally` — the old sync `try/catch` could not catch an unlock rejection. See change: fix-provider-auth-lock-contention.

`_buildAuthStatus` projects per-row-kind `configured` + `source` (D1 table); `writeCredential` throws `CredentialTypeConflictError` when the stored credential TYPE differs from the incoming one, `removeCredential` carries the same kind-mismatch refusal (same-type refresh is unaffected). Code: `provider_auth.credential_type_conflict`. See change: redesign-providers-settings-page (D1, D2).

`row.source` precedence: a STORED key wins outright — `hasStoredKey` forces `source: "stored"` before the catalogue's own `entry.source` is consulted. pi-ai reports `source: "environment"` whenever the env var is ALSO set, so an auth.json-backed row would otherwise be labelled `environment` while carrying a `maskedKey` and Edit/Remove, contradicting the status contract. See change: redesign-providers-settings-page (CodeRabbit PR #709).

`_buildAuthStatus(catalogue, authData, oauthEntries)` — pure, no I/O; takes the OAuth registry explicitly so tests inject fakes. OAuth-row id set = `oauthIdsFrom(entries, authData)` / `oauthIdSet(authData = readAuthJson())`: the registry's ids UNION every id already holding a stored `{ type: "oauth" }` credential, so a credential pi wrote for a provider with no dashboard flow stays visible and removable (`_buildAuthStatus`, `resolveAuthJsonKey` and the DELETE route's row-kind check all read ONE union). `expires` is `oauthRowExpires(cred)` → `cred.refresh ? cred.expires : null` — a permanent key obtained via an OAuth handshake (OpenRouter: `refresh: ""`) renders `null`, so the client needs one null-check, not provider knowledge. See change: delegate-provider-oauth-to-pi-ai (D1, D4).

pi lock coordination: `LOCK_OPTIONS` EXPORTED, single source, `{ stale: 30_000, realpath: false }` — coupled to pi 0.86.1 `auth-storage.js` `acquireLockAsync` (pi holds lock across OAuth refresh, mtime refresh every 15 s; proper-lockfile judges stale by ACQUIRER's `stale`, so 10 s stole pi's live lock). Pinned by `provider-auth-lock-coordination.test.ts` E1; its holder uses pi's literal options, never imports `LOCK_OPTIONS`. `withLock(fn, { budgetMs = 2_000, createIfMissing = true })` exported; `fn: () => T & NotPromise<T>` — async/promise callback = compile error (type test `provider-auth-withlock-types.test.ts`). Per-acquisition `onCompromised` cell: records error, logs one line with `err.code` only, never throws from timer; compromise seen before `fn` → throws recorded `ECOMPROMISED`, auth.json untouched; post-`fn` compromise → logged, result stands. Refresh path: `readCredentialLocked(provider)` → `ok`/`removed`/`replaced`/`corrupt` (never throws on content, quarantine unchanged); `writeRefreshedOAuth(provider, next, snapshot)` → CAS under lock, writes only when stored `isDeepStrictEqual` snapshot (every field) → `written`/`changed`/`removed`/`replaced`, corrupt → throws `AuthJsonCorruptError`. Both use `REFRESH_LOCK_BUDGET_MS` 20 s + `createIfMissing: false` (never create auth.json); `_setRefreshLockBudgetForTests(ms|null)` test seam. See change: harden-auth-json-lock-coordination.
Lock/checked-read/quarantine/atomic-write now delegate to `locked-json-file.ts` with `AUTH_PATH`; `LOCK_OPTIONS` re-exported, `withLock(fn,opts)` wraps `withLockedJsonFile` (logTag `provider-auth`); refresh-path budget + CAS helpers stay here; exports + behaviour unchanged; `_resetQuarantineDedupForTests` delegates. See change: expose-plugin-credential-and-oauth-seams.

`_buildAuthStatus`: OAuth rows carry registry `subscription` (absent for unknown stored ids); env api-key row gets `authLabel`; `authenticated` also true when env + `authLabel` + no stored key + no `envVar` + not `ambient`. `OAuthProviderMeta.subscription?`. See change: update-pi-core-1-0-adopt-apis.
