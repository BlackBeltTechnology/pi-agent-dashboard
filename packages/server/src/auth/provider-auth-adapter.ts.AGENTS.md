# provider-auth-adapter.ts — index

`AuthInteraction` adapter + in-memory flow store. `notify` sets sticky `authUrl` / `device_code` pending / `message`; `prompt` becomes a tagged `pending` resolved by `/flow/:flowId/input` (`secret` rejected). Flow-controller abort REJECTS the pending prompt so pi-ai's `finally` closes the callback listener. Exports `startFlow`, `getFlow`, `deleteFlow`, `flowStoreSize`, `cancelFlow`, `pruneFlows`, `abortAllFlows`, `pendingFlowsFor`, `toFlowStatus`, `startFlowPruneTimer`, `FLOW_START_TIMEOUT_MS`, `SUPERSEDE_SETTLE_TIMEOUT_MS`. TTL 10 min; device-code extends to `expiresInSeconds + 60 s`; `expired` derived from deadline, never message text; ids `crypto.randomUUID()`. See change: delegate-provider-oauth-to-pi-ai (D1, D2, D6, D7). Flows may be plugin-owned: `provider = plugin:<pluginId>:<key>`, `writeCredential` = the plugin's `persist` (credential passed untouched). Start robustness lives in `begin-flow.ts`. See change: expose-plugin-credential-and-oauth-seams. Input echo guard: `recordSubmitted` keeps secret-bearing fragments (every non-empty value + pasted-URL query/hash value (≥4 chars substring, shorter whole-token match), server-only `flow.submitted`, cleared at finish); `withholdEchoedInput` replaces an error quoting them with `WITHHELD_ERROR_MESSAGE`. See change: expose-plugin-credential-and-oauth-seams. `StartFlowParams.getDeviceId?`; `login(interaction, { getDeviceId })` defaults to pi `SettingsManager.getOrCreateDeviceId` pre-loaded by exported `loadPiDeviceId()`. See change: update-pi-core-1-0-adopt-apis.
