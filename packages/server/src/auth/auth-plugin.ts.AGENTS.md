# auth-plugin.ts — index

Fastify plugin registers OAuth routes + `onRequest` JWT gate. Exports `registerAuthPlugin`, `validateWsUpgrade`, `isBypassed`, `escapeHtml`. Mutates auth state via `_reloadAuth` for runtime config updates. Skips auth on loopback, `/auth/`, `/api/health`, `/v1/`, bypass prefixes, trusted hosts. Cookie `pi_dash_token`, 7-day expiry, httpOnly/`sameSite:lax`. `Secure` derives from `resolveRedirectBase().base` starting `https:` — NOT from `request.protocol`, which is always `http` behind a proxy because Fastify runs without `trustProxy` on purpose: `trustProxy` would rewrite `request.ip` from `X-Forwarded-For`, and `request.ip` is what BOTH bypasses read (`:288` here, `localhost-guard.ts:116`). Pinned by `__tests__/forwarded-ip-trust.test.ts` (S1/S2) — enabling `trustProxy` turns those red. Redirect URIs built with `authState.redirectBaseUrl` (config `auth.redirectBaseUrl`) threaded as `buildRedirectUri` override. Cookie validation sets `isAuthenticated` + additive `authVia: "session"` marker (operatorGuard reads it). See change: config-override-oauth-redirect-base (D14), mcp-legacy-clients-and-token-issuance.

`_reloadAuth(newAuth, fullConfig?)` merges `fullConfig.resolvedTrustedNetworks` (top-level `trustedNetworks` ∪ `auth.bypassHosts`) exactly as boot does — without the second argument every auth-carrying `PUT /api/config` silently dropped top-level trusted networks until restart (pre-existing defect, D15). `logResolvedRedirectBase` writes one `🔐 OAuth redirect base: <base> (source: <tier>)` line at register and at every reload, so `server.log` answers "which value won" with no HTTP (D10). See change: config-override-oauth-redirect-base.

`validateWsUpgrade` opts narrowed (add-browser-relay D1): `scope?: CoreWsRouteScope | null`, `consumeTicket?: (ticket, scope: CoreWsRouteScope) => boolean`. Plugin scopes never reach this gate (the upgrade handler returns before the auth branches), so tickets stay core-only at the type level too. See change: add-browser-relay.

`isBypassed` MOVED to the import-free leaf `bypass-urls.ts` and is RE-EXPORTED here, so this file's import surface (`auth-plugin.test.ts` imports it from `auth-plugin.js`) is unchanged. Reason: the universal network guard (change: add-universal-network-guard) needs the same `auth.bypassUrls` predicate, and importing it from this plugin would close a cycle (this plugin already imports `localhost-guard.ts`). One predicate, two callers — they MUST agree.
