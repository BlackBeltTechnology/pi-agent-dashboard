# verified-read.ts — index

Handle-verified byte serving for GRANT-admitted reads (design D14, task 2.8). `openVerifiedRegularFile` → `readFileVerified` / `readFileVerifiedUtf8` / `assertRegularFile`, plus `VerifiedReadRefused`. Closes the check→open window: `lstat` FIRST and require a regular file (`open(2)` on a FIFO BLOCKS a libuv worker, so refusing before any open is a liveness guard, not just correctness) → `open` with `O_NOFOLLOW`/`O_NONBLOCK` → `fstat` the HANDLE and require the same dev+ino the `lstat` described → the caller serves FROM that handle. Refusals are translated by callers into the site's EXISTING containment shape, so no new user-facing error string enters the surface. Layers ①/② keep their pre-existing (identical, untouched) window. Residuals are documented in the header: `O_NOFOLLOW` covers only the final component, and hardlinks defeat a realpath-based predicate. See change: add-access-grants-and-review.

`openVerifiedRegularFile` also `handleIsAlwaysRefused(handle)` after handle stat → `VerifiedReadRefused` reason `state-file` (hard link in granted tree to credential/token). See change: close-security-map-high-findings (D1).
