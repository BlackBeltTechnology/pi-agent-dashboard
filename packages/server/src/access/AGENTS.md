# DOX — packages/server/src/access

Files in this directory. One row per source file.

| File | Purpose |
|------|---------|
| `access-denials.ts` | Path-denial registry (design D20): `recordPathDenial`, `getPathDenial`, `__resetPathDenials`. A containment refusal records `{denialId, subject, site, session, ancestors, at}` so the remedy a grant binds to is one the OPERATOR saw, never a free-form path (design D12/D15). `denialId` is a `randomUUID`, returned only in the denial body and never by any read route. Bounded TTL + CAP (oldest evicted on record); an evicted or expired id resolves to `undefined`, so a grant against it is refused (409/410 class). Written ONLY by the denial path — no route creates an entry (task 9a.31/9c.6). See change: add-access-grants-and-review. |
| `access-grants.ts` | The path-grant store (design D2/D10/D11/D16/D17). `recordGrant` / `listGrants` / `revokeGrant` / `grantedSubjects` / `normalizeGrantSubject` / `__resetAccessGrants`. Subject = **realpath at grant time** (a retargeted symlink does not move the grant); non-directory subjects normalize onto their containing directory. Per-scope cap 200 with oldest-by-`grantedAt` eviction, never crossing scope. Atomic write (tmp+rename) → an interrupted write leaves old-or-new, never truncated. Load-once cache; `revokeGrant` invalidates it so revocation takes effect without a restart. A write failure returns `{ok:false}` and leaves the cache untouched, so the admitted set never widens on a failure (D11). **Forbidden backstop:** `isUngrantableSubject` is re-applied to the NORMALIZED subject, because normalizing a FILE subject onto its parent could otherwise store `$HOME` for a denial that named `$HOME/<file>` (design D15). Store path overridable via `PI_ACCESS_GRANTS_STORE`. See change: add-access-grants-and-review. |
| `ancestor-ladder.ts` | `offeredAncestorLadder(subject)` — the nearest-first rungs a denial remedy may also offer (task 7b.1a). Stops BELOW `$HOME` when there is no repository, and AT the checkout root inside one; never offers a symlink, never the filesystem root, and never a rung that SUBSUMES a forbidden subject (`/private` would admit `/private/etc` on macOS) or sits inside a secret store. Degrades to the no-repo boundary when `git` is unavailable. A ladder failure must never turn a denial into a 500 — `containment-gate` catches and falls back to no offer. See change: add-access-grants-and-review. |
| `canonical-subject.ts` | Volume-appropriate canonical form for access-subject comparison (task 2b.3a). `volumeCaseInsensitive` / `canonicalSubject` / `isSameSubject` / `isSubjectWithin`. Probes case sensitivity FROM THE VOLUME (flip an existing component's case, ask whether the flipped sibling exists; memoised per device) instead of assuming it from `process.platform` as the codebase-wide `samePath` does — which is wrong for a case-SENSITIVE volume on a case-insensitive host (APFS case-sensitive, a container bind mount, a network share), where two subjects differing only in case are different objects and folding them together silently widens a grant. NFC-normalises before folding. Containment is component-wise (`path.relative`), never a string prefix, so `/repo-secrets` is not inside `/repo`. An unresolvable path returns `null` and never matches. Deliberately does NOT modify `samePath`: that primitive's semantics are depended on across the server, so changing them here would alter shipped containment everywhere at once; the boundary is that a caller comparing an ACCESS SUBJECT uses this module. See change: add-access-grant-dialog (task 2b.3a). |
| `containment-gate.ts` | The ONE gate every body-emitting file-read site routes through; before it each of the ten sites inlined `isAllowed` and hand-rolled its own 403, which is why remedy fields could not be added consistently. `evaluateContainment(resolved, anchors, {site, session, allowGrant?, subjectKind?})` order is load-bearing (design D1/D9): ①/② `isAllowed` (untouched, still authoritative) → ③ the grant predicate ONLY on a miss → record the denial and return the ADDITIVE remedy (`reason`/`hint`/`subject`/`denialId`/`ancestors`), leaving every pre-existing status code and `error` string byte-identical (design D7). The remedy's subject comes from `remedySubject(resolved, subjectKind)`: `"file"` (default) = `grantableSubjectOf` (lexical dirname) because granting the containing directory is what unblocks a refused file; `"directory"` = the refused directory ITSELF, since naming its parent would offer every SIBLING tree in one click; `"auto"` = whichever the target actually is, for polymorphic sites (`/api/file`, `/api/file/exists`). `allowGrant:false` returns BEFORE any denial or remedy is created, so a grant-ineligible site (the two OS spawn routes) can never originate a grant it could not honour (task 4.5). A body-less site (`grep-routes`, `resolve-file-mention`) consumes grants but can never originate one. See change: add-access-grants-and-review. |
| `forbidden-subjects.ts` | Subjects that may never be granted, and why (design D15). `forbiddenGrantSubjects` / `isForbiddenGrantSubject` / `subsumesForbiddenGrantSubject` / `isUngrantableSubject`. Matching is deliberately SPLIT: `whole` (`/`, `$HOME`, platform system roots) matches EXACTLY, while `sensitive` (`~/.ssh`, `~/.pi`) matches exact-OR-descendant. A blanket descendant rule would forbid every project directory (they all live under `$HOME`) and macOS temp dirs under `/private/var`, making the feature unable to grant anything. `subsumes` rejects an ancestor RUNG that would admit a forbidden subject. Comparison is against realpaths, so `/etc` reached through the `/private/etc` alias is caught. Callers MUST pass the subject that will be PERSISTED, not a pre-normalization input. See change: add-access-grants-and-review. |
| `prompt-channel.ts` | Per-connection prompt capabilities (design D1/D1a/D2, tasks 3.1/3.3/3.4). `issuePromptChannel` / `resolvePromptChannel` / `releasePromptChannel` / `promptChannelCount` / `isPromptEligible` / `maySuspend` + `GRANT_CHANNEL_HEADER` (`x-pi-grant-channel`). The browser gateway issues each socket a 256-bit value, the browser echoes it, and a denial is prompt-eligible by resolving back to the issuing socket. Memory only, NEVER persisted (a restart issues fresh values); `releasePromptChannel` on socket close makes a capability die with its connection; comparison is `timingSafeEqual` over the whole scan with NO early `break`, so lookup cost does not depend on where the match is; absent, empty, wrong, and non-string all resolve to the SAME `null`, so a caller cannot distinguish "sent nothing" from "guessed wrong". Eligibility consults the capability and NOTHING ELSE — not auth, not the CORS decision, not `Sec-Fetch-*`, not an `Origin`/`Host` compare (the four recorded defeats). `maySuspend(request, mode)` additionally requires `enforce` and takes the mode as an ARGUMENT so it cannot mutate it; the caller resolves the live mode via `resolveHostGateMode` at the denial site. See change: add-access-grant-dialog. |
| `verified-read.ts` | Handle-verified byte serving for GRANT-admitted reads (design D14, task 2.8). `openVerifiedRegularFile` → `readFileVerified` / `readFileVerifiedUtf8` / `assertRegularFile`, plus `VerifiedReadRefused`. Closes the check→open window: `lstat` FIRST and require a regular file (`open(2)` on a FIFO BLOCKS a libuv worker, so refusing before any open is a liveness guard, not just correctness) → `open` with `O_NOFOLLOW`/`O_NONBLOCK` → `fstat` the HANDLE and require the same dev+ino the `lstat` described → the caller serves FROM that handle. Refusals are translated by callers into the site's EXISTING containment shape, so no new user-facing error string enters the surface. Layers ①/② keep their pre-existing (identical, untouched) window. Residuals are documented in the header: `O_NOFOLLOW` covers only the final component, and hardlinks defeat a realpath-based predicate. See change: add-access-grants-and-review. |
