# refusal-ledger.ts — index

The remembered-refusal ledger (tasks 2b.9, 8b.4a): the ONE piece of persisted state this change owns. `recordRefusal` / `isRefused` / `listRefusals` / `clearRefusal` / `refusalLedgerPath` / `__resetRefusalLedger`. An operator's EXPLICIT deny on a YOLO-eligible plane is recorded so a later YOLO session refuses that subject without prompting (refused-by-prior-refusal) instead of auto-allowing it. DURABLE (C4): survives restart, never self-expires, cleared only by the operator on the Access surface. An expiry is not a refusal. Grants nothing, so it is fail-safe across rollback. Store conventions mirror `access-grants.json`: config-dir default `access-refusals.json`, `PI_ACCESS_REFUSALS_STORE` override, atomic temp+rename, missing/malformed = empty, failed write leaves the cache unchanged.
