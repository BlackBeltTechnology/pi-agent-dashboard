# access-plane.ts — index

The plane registration seam (design D5/D2a/D3, tasks 5.1/5.5/2b.2/8b.1). `AccessPlane` = `HeldAccessPlane | DeferredAccessPlane`, `AccessPlaneRegistry`, `promptPrecondition`, `holdsRequest`, `persistVerdict`. A plane owns subject normalisation (`subjectOf`/`keyOf`), prompt copy (`describe`) and its OWN store write (`grant`). `yoloEligible` is typed `?: false` on a deferred plane (unrepresentable) and `register` REJECTS a cast `true` at runtime (#X9); duplicate id and unknown mode also throw. `mode` is a ceiling: `promptPrecondition` applies the ladder to every plane alike, in order: disabled/kill switch, then report-mode (every plane, D2), then the per-mode proof (D2a): HELD requires the REQUEST to hold a capability, DEFERRED requires a live operator channel and asks nothing of the request. `holdsRequest` is true only for a held plane whose precondition passed, so a deferred denial never suspends. `persistVerdict` writes ONLY on `allow-always`; `allow-once`/`deny` persist nothing. See change: add-access-grant-dialog. `isGrantPromptKilled(env)`: `PI_DASHBOARD_DISABLE_GRANT_PROMPT` engages ONLY on the exact value `1` and maps to the `disabled` rung, so it suppresses prompts while grants stay in force and denials are still recorded (task 9.1). `PlaneGrantResult` reason adds `unverifiable`.
