# containment-gate.ts — index

The ONE gate every body-emitting file-read site routes through; before it each of the ten sites inlined `isAllowed` and hand-rolled its own 403, which is why remedy fields could not be added consistently. `evaluateContainment(resolved, anchors, {site, session, allowGrant?, subjectKind?})` order is load-bearing (design D1/D9): ①/② `isAllowed` (untouched, still authoritative) → ③ the grant predicate ONLY on a miss → record the denial and return the ADDITIVE remedy (`reason`/`hint`/`subject`/`denialId`/`ancestors`), leaving every pre-existing status code and `error` string byte-identical (design D7). The remedy's subject comes from `remedySubject(resolved, subjectKind)`: `"file"` (default) = `grantableSubjectOf` (lexical dirname) because granting the containing directory is what unblocks a refused file; `"directory"` = the refused directory ITSELF, since naming its parent would offer every SIBLING tree in one click; `"auto"` = whichever the target actually is, for polymorphic sites (`/api/file`, `/api/file/exists`). `allowGrant:false` returns BEFORE any denial or remedy is created, so a grant-ineligible site (the two OS spawn routes) can never originate a grant it could not honour (task 4.5). A body-less site (`grep-routes`, `resolve-file-mention`) consumes grants but can never originate one. See change: add-access-grants-and-review. Takes an optional `hold: HoldTarget` (the live request/reply) so a site can SUSPEND a miss while the operator is asked; every miss is reported through `holdDenial` either way (no `hold` = recorded, answered at once). An allow verdict authorises a RE-EVALUATION, never a skip (`reEvaluate`): layers run again against the filesystem as it is NOW, so a subject swapped for a symlink after the verdict, a revoked grant, or a sibling outside the answered subject is still denied; `allow-always` must be admitted by the persisted grant, `allow-once` applies the answered subject as a transient real-path grant for this request only and never for a forbidden subject. The deny path is untouched, so every site's body is byte-identical. See change: add-access-grant-dialog (tasks 6.2/6.4/2b.5).
