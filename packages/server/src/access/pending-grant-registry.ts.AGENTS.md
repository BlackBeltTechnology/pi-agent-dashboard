# pending-grant-registry.ts — index

The pending access-request registry (design D4/D8/D9/D11, tasks 4.1-4.4 + 2b.6). `PendingGrantRegistry` with `record(input, precondition, now)` / `settle(response, now)` / `forget(promptId)` / `expire(now)` / `list` / `get` / `snapshotStats`, plus `formatTransition` and the `GRANT_*` constants (TTL 120 s, capacity 64, backoff 120 s, 5 prompts/plane/min, 2 concurrent dialogs, 12 entries + 1 dialog per channel, 1 prompt/plane/min per DEFERRED channel). Keyed `(plane, subject)`; subject arrives plane-normalised. Pure: no timers, `now` injected. Departs from `ResyncRequesterRegistry` twice ON PURPOSE: overflow REFUSES the new denial and never evicts a live entry (it may hold a suspended request), and expiry is reported through `onExpire`, never silent. Caller supplies the ladder `precondition` (ineligible / report-mode / disabled / no-audience) from the live request (D6); the registry owns only capacity, channel share, backoff, rates and dialog caps. Refusals (`capacity`, `channel-share`) create NO entry; floods (`backoff`, `plane-rate`, `channel-rate`, `concurrent-cap`, `channel-concurrent`) record an unprompted entry that stays answerable on the Access surface. Per-channel checks run before global ones so starvation is attributed to the requester (E23). A denial joining an unprompted entry re-evaluates it, so a key does not stay unprompted past its backoff. `settle` validates untrusted input: first well-formed answer wins; duplicate (remembered settled id) vs malformed vs unknown are counted separately; wrong plane and `allow-once` on a deferred plane are malformed; a subject that is neither the denied one nor an OFFERED rung is refused and the entry stays pending; `widenedFrom` is set when an offered rung is chosen. Log lines JSON-quote the subject (attacker-shaped CORS origins cannot forge a line). See change: add-access-grant-dialog. `GRANT_DEFERRED_MAX_ENTRIES`=16: deferred entries together capped, refusal `deferred-share` (counted in `flooded`), held keeps >=48 (D9 resolved, rotating sources). See change: surface-denial-remedy-in-previews — `PendingGrant.dialogChannel` owns the dialog (set on promote); join evaluates dialog-scoped `floodReason` against the JOINER; failure → `joined{reason}` + `flooded` transition + stats. `countChannelDialogs` public, reads `dialogChannel`. Exports `PreconditionReason`.
