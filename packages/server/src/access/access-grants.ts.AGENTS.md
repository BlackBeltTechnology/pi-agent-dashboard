# access-grants.ts — index

The path-grant store (design D2/D10/D11/D16/D17). `recordGrant` / `listGrants` / `revokeGrant` / `grantedSubjects` / `normalizeGrantSubject` / `__resetAccessGrants`. Subject = **realpath at grant time** (a retargeted symlink does not move the grant); non-directory subjects normalize onto their containing directory. Per-scope cap 200 with oldest-by-`grantedAt` eviction, never crossing scope. Atomic write (tmp+rename) → an interrupted write leaves old-or-new, never truncated. Load-once cache; `revokeGrant` invalidates it so revocation takes effect without a restart. A write failure returns `{ok:false}` and leaves the cache untouched, so the admitted set never widens on a failure (D11). **Forbidden backstop:** `isUngrantableSubject` is re-applied to the NORMALIZED subject, because normalizing a FILE subject onto its parent could otherwise store `$HOME` for a denial that named `$HOME/<file>` (design D15). Store path overridable via `PI_ACCESS_GRANTS_STORE`. See change: add-access-grants-and-review. `AccessGrant.via?: "prompt"` (+ `RecordGrantInput.via`) marks grants written by a prompt verdict; optional, additive, no migration (task 8.2). `setGrantsChangedListener` fires after persisted grant write/revoke. See change: mirror-dashboard-trust-to-pi. `via` is `GrantVia` (`prompt` | `agent-prompt` | `provision`). `recordGrant({evict:false})` refuses `{ok:false,error:"capacity"}` at the cap, nothing written. `enforceCap` returns boolean: skips `via:"provision"` victims on write (all-provisioned → refuse `capacity`), does NOT spare them at load (bound wins); every eviction logs `[access-grants] evicted subject=<json> via=`. See change: add-access-provisioning.

`setSessionGrantsChangedListener`: session record/revoke notify sync (persisted listener unchanged). See change: mirror-dashboard-trust-live-remote.

`AccessGrant.mode?:"write"` (absent = read; `GrantMode`). Load normalises fail-closed: only exact `"write"` kept, no rewrite on load, store stays `version:1`. `recordGrant({mode})` idempotent per `(subject,scope,mode)` — write grant = 2nd entry beside read; read stores no `mode` key. Cap counts entries. `grantedWriteSubjects()` = write predicate input; `grantedSubjects()` unchanged (write ⊃ read). `revokeGrant(subject,scope?,mode?)`: undefined = all entries; `"write"`/`"read"` = that mode only; any other value = no-op `false`. See change: fix-file-link-editor-routing.

harden-agent-tool-guards (D7): rows the build does not admit (now-forbidden, unrecognised, wrong scope) are kept as a raw side list and written back verbatim after the admitted grants by BOTH `recordGrant` and `revokeGrant`; the cap counts admitted grants only; one log line per now-forbidden subject per process. Whole-file states: invalid JSON / no `grants` / `version !== 1` → `recordGrant` moves the file to `<file>.corrupt-<UTC ts>` and writes a fresh v1 store (`revokeGrant` writes nothing, returns false); a file over `GRANT_STORE_MAX_BYTES` (1 048 576) is neither loaded nor rewritten (write fails, one log line).
