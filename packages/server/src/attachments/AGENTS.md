# attachments — index

Display-fit + originals handling for inline image attachments.

| File | Purpose |
|---|---|
| `display-fit.ts` | Pure fit primitive for inline image blocks. Exports `fitImageBlockForDisplay(block)`, `isAnimatedGif(bytes)`, `readImageDimensions(bytes)`, `DISPLAY_MAX_EDGE`=768, `DISPLAY_JPEG_QUALITY`=75, `DISPLAY_MAX_DECODE_PIXELS`=40M, `DISPLAY_MAX_INPUT_BYTES`=25M. PRE-DECODE GUARD: `readImageDimensions` parses declared w/h from the PNG/GIF/JPEG/WebP header (no pixel decode) and the fit refuses anything over 40 MP or 25 MB BEFORE `Jimp.read` — a decompression bomb (20000x20000 PNG = few KB on the wire, ~1.6 GB of RGBA bitmap) would otherwise OOM the process, since every other budget here measures OUTPUT. Fails CLOSED: an unparseable header returns `{failed:true}` rather than an unbounded decode. Resizes to a 768 px long edge via jimp; NEVER upscales and returns byte-identical input at/under the bound (no re-encode, no quality loss). PNG-in→PNG-out, else JPEG@q75. Animated GIFs exempt (D11) — `isAnimatedGif` counts Image Descriptor `0x2C` blocks, short-circuits at 2, so animation is never flattened to a still. Never throws: undecodable input returns `{failed:true}` so the caller can store the message row and render an honest failed state. Called from a worker so the measured 174–874 ms decode/encode stays off the event loop (D4). See change: fit-attachments-for-display. |
| `fit-worker.ts` | `worker_threads` entry for display fitting. Exports `fitBlocks(req)` (IS the worker body; imported directly by tests + the in-process fallback), `FitRequest`, `FitResponse`. Bootstrap block runs only when `!isMainThread`, mirroring `session-load-worker.ts`. Never rejects — a bad block returns `failed:true`. See change: fit-attachments-for-display. |
| `fit-worker-pool.ts` | Fixed-size worker pool for fitting. Exports `createFitWorkerPool(opts)`, `FitWorkerPool`. Modeled on `session-load-worker-pool.ts` MINUS cancellation (a fit is fire-and-forget; the row is already stored). Falls back in-process on spawn failure/crash/timeout so a fit can never lose a message. The in-process fallback is SEMAPHORE-CAPPED at the same `size` as the worker path — unbounded, a burst of pastes ran N simultaneous jimp decodes on the MAIN thread, the exact event-loop stall the pool exists to prevent; excess fits queue instead. Slot released in a `finally` so a throwing fit cannot leak the cap. Worker entry is a sibling `.ts` loaded via jiti inherited through `execArgv`. THIRD pool in the server — generic extraction deferred (task 9.3). See change: fit-attachments-for-display. |
| `image-mime.ts` | Single source of truth for which inline image mimes the pipeline TAKES OWNERSHIP of. Exports `isFittableImageMime(mime)` (case-insensitive, strips `;charset=…` params). Consumed by BOTH gates that must agree — `prepareEventForIngest` (what to strip into pending) and `fitImageBlockForDisplay` (what it can fit). They diverged once: ingest stripped ANY image block while the fit returned a non-allow-listed mime unchanged, so the resolution event carried the full-resolution bytes it was meant to replace, busted the per-event ceiling, truncated, and stranded the block on "pending" forever. A block rejected here is never PROMISED a resolution — it stays inline under the existing ceiling. `image/svg+xml` absent on purpose (script-bearing markup, not a re-encodable bitmap). Deliberately jimp-free: the ingest path runs on the event loop for every event. See change: fit-attachments-for-display. |
| `attachment-ingest.ts` | Two-phase ingest seam. Exports `prepareEventForIngest(event)` (strips inline image bytes to a bounded `{data:"",attachmentId,attachmentState:"pending"}` placeholder; returns the SAME event reference when there are no images; admits ONLY `isFittableImageMime` blocks — see `image-mime.ts`), `buildFittedEvent(input)`, `attachmentIdFor(base64)`, `ATTACHMENT_FITTED_EVENT`="attachment_fitted", `PendingAttachment`. Blocks are addressed by `attachmentId` = sha256 of the ORIGINAL bytes, NOT by seq — the client fold is append-only and never sees a seq, and the hash is the key the originals endpoint needs anyway (fitted derivatives are NOT cached — D10/D12). See change: fit-attachments-for-display. |
| `attachment-resolver.ts` | Phase-2 driver shared by BOTH paths that admit an image into the store: live `event_forward` (event-wiring) and session hydration (subscription-handler). Exports `createAttachmentResolver({eventStore,fitWorkerPool,emit})` → `resolve(sessionId, pending)`. Extracted rather than duplicated because the spec requires fitting on EVERY such path — an unfitted replayed image collapses to `{__truncated}` exactly like the original bug, so the two must not drift. Never rejects: a dead pool resolves every placeholder to `failed`. See change: fit-attachments-for-display. |
| `original-store.ts` | Recovery of FULL-RESOLUTION originals; trust boundary for the binary surface. Exports `findOriginalInTranscript(sessionFile, attachmentId)`, `isValidAttachmentId(id)` (strict `^[0-9a-f]{64}$` — uppercase REJECTED not normalised, so a cache key cannot split across two spellings), `isAllowedImageMime(m)`, `ALLOWED_IMAGE_MIME` (png/jpeg/jpg/gif/webp — `image/svg+xml` deliberately EXCLUDED, SVG is scriptable = XSS). `image/jpg` is an ALIAS of a format already served, added because the fit gate accepted it while this one did not: the thumbnail rendered fitted and the zoom-to-original 404'd. Serving stays STRICTER than fitting in general; the required invariant is only fittable ⊆ servable, asserted in `original-store.test.ts`. D7: transcript IS the record, no durable store added. Streams the JSONL line-by-line (peak memory bounded by the largest entry, not the file — P4) and depth-bounded-walks each entry for image blocks. Lookup is scoped to ONE session's transcript, so a valid digest from another session is simply not found — cross-session refusal WITHOUT an ownership table (X2). Never throws: missing file / absent hash / disallowed mime all resolve `null` → one clean 404. See change: fit-attachments-for-display. |
