# attachments — index

Display-fit + originals handling for inline image attachments.

| File | Purpose |
|---|---|
| `display-fit.ts` | Pure fit primitive for inline image blocks. Exports `fitImageBlockForDisplay(block)`, `isAnimatedGif(bytes)`, `DISPLAY_MAX_EDGE`=768, `DISPLAY_JPEG_QUALITY`=75. Resizes to a 768 px long edge via jimp; NEVER upscales and returns byte-identical input at/under the bound (no re-encode, no quality loss). PNG-in→PNG-out, else JPEG@q75. Animated GIFs exempt (D11) — `isAnimatedGif` counts Image Descriptor `0x2C` blocks, short-circuits at 2, so animation is never flattened to a still. Never throws: undecodable input returns `{failed:true}` so the caller can store the message row and render an honest failed state. Called from a worker so the measured 174–874 ms decode/encode stays off the event loop (D4). See change: fit-attachments-for-display. |
| `fit-worker.ts` | `worker_threads` entry for display fitting. Exports `fitBlocks(req)` (IS the worker body; imported directly by tests + the in-process fallback), `FitRequest`, `FitResponse`. Bootstrap block runs only when `!isMainThread`, mirroring `session-load-worker.ts`. Never rejects — a bad block returns `failed:true`. See change: fit-attachments-for-display. |
| `fit-worker-pool.ts` | Fixed-size worker pool for fitting. Exports `createFitWorkerPool(opts)`, `FitWorkerPool`. Modeled on `session-load-worker-pool.ts` MINUS cancellation (a fit is fire-and-forget; the row is already stored). Falls back in-process on spawn failure/crash/timeout so a fit can never lose a message. Worker entry is a sibling `.ts` loaded via jiti inherited through `execArgv`. THIRD pool in the server — generic extraction deferred (task 9.3). See change: fit-attachments-for-display. |
| `attachment-ingest.ts` | Two-phase ingest seam. Exports `prepareEventForIngest(event)` (strips inline image bytes to a bounded `{data:"",attachmentId,attachmentState:"pending"}` placeholder; returns the SAME event reference when there are no images), `buildFittedEvent(input)`, `attachmentIdFor(base64)`, `ATTACHMENT_FITTED_EVENT`="attachment_fitted", `PendingAttachment`. Blocks are addressed by `attachmentId` = sha256 of the ORIGINAL bytes, NOT by seq — the client fold is append-only and never sees a seq, and the hash is the key the originals endpoint + fitted cache need anyway (D10/D12). See change: fit-attachments-for-display. |
| `attachment-resolver.ts` | Phase-2 driver shared by BOTH paths that admit an image into the store: live `event_forward` (event-wiring) and session hydration (subscription-handler). Exports `createAttachmentResolver({eventStore,fitWorkerPool,emit})` → `resolve(sessionId, pending)`. Extracted rather than duplicated because the spec requires fitting on EVERY such path — an unfitted replayed image collapses to `{__truncated}` exactly like the original bug, so the two must not drift. Never rejects: a dead pool resolves every placeholder to `failed`. See change: fit-attachments-for-display. |
