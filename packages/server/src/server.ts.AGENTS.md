# server.ts — index

Dashboard HTTP + WebSocket server. Exports `ServerConfig`, `DashboardServer`, `createServer(config)`. Wires Fastify + CORS (origin callback delegates to `isCorsOriginAllowed` in `cors-origin.ts`; trusted-network origins allowed for LAN-to-LAN switching — change: fix-remote-connect-cors-gates) + compress + auth, registers all route modules, session/terminal/editor managers, pi/browser gateways, event forwarding, mDNS discovery, zrok tunnel, plugin runtime, OpenSpec polling. ~2190 lines. host provides cross-plugin service `host.knownFolderCwds` (live getter: session cwds ∪ pinned dirs) via pluginServiceRegistry; kb-plugin consumes for cwd validation. Trusted plugin ctx gains `abortSpawnedRun({sessionId?,spawnToken?,graceful?})` (RENAMED from `abortAutomationRun` — generic spawned-run kill, goal is a 2nd caller; gate priority<=100): graceful sends `{type:"shutdown"}` hint THEN `killBySessionId` (mirrors handleShutdown — hint dropped when WS not OPEN); hard kills by sessionId else falls back to `killByToken`. See change: add-kb-folder-slot, fix-automation-stop-zombie-runs, add-goal-session-supervisor. `pluginSessionEndSubs` + `dispatchPluginSessionEnded` fan `sessionManager.onUnregister` to `ctx.onSessionEnded` subscribers AND the main-server `goalSupervisor.onDriverDeath` (C2a). Builds `goalSupervisor` (createGoalSupervisor): `spawnGoalDriver` (headless-forced, token+goalId register, continue-mode resume / fresh reprime), boot reconcile deferred 30s. goal-routes `abortGoalSupervision` + budget guard on cumulative `totalTurnsUsed`. See change: finalize-automation-run-on-session-death, add-goal-session-supervisor. `worktree_init_subscribe`/`_unsubscribe` handlers accept `cwd` (registry.subscribeCwd/unsubscribeCwd) in addition to `requestId`. See change: friendlier-worktree-init. `sessionManager.onChange` debounced `.meta.json` save delegates to `sessionToMeta(session)` (full-overwrite enumeration; extracted for testability). See change: add-session-tags. Plugin ctx `registerBrowserHandler` wrapper routes `type==="plugin_action"` to `browserGateway.registerPluginActionHandler(plugin.manifest.id, ...)` (manifest-authoritative pluginId, not self-declared) so plugins fan out; other custom types stay single-owner via `registerHandler`. See change: fix-plugin-action-fanout-and-handlers. The `goalStore.subscribe` → `goals_update` broadcast now wraps `payload.goals` in `decorateGoalsWithSpend(...,sessionManager)` so the WS delivery path carries `totalSpendUsd` like the REST paths. See change: fix-goal-detail-turns-and-spend. Cold-start recovery now gates on the boot record: `stampBootStart(liveEpoch)` runs before classification, classification adds the `isRecoveryAllowed(resolveExitIntent(session.liveEpoch))` conjunct, the `ask` offer broadcast is DEFERRED until `RECOVERY_REATTACH_GRACE_MS` (shared `recovery-timing.ts`) closes and then fires once with the survivors, and `stop()` records `exitIntent:"idle"` INSTEAD of clearing each running session's `live` marker. New `flush()` method (metaPersistence + preferences) for the signal handler. See change: fix-recovery-exit-intent.

CORS `origin` callback + `networkGuard` read `liveCorsAllowedOrigins()` / `liveTrustedNetworks()` (mtime-gated `config-snapshot.ts`) on EVERY decision instead of closing over the boot config — a gateway origin or CIDR written at runtime applies with no restart (D15). `getReachableUrls` reads `resolvePublicBaseUrls(loadConfig())` (top-level `publicBaseUrls`, legacy `pairing.publicBaseUrls` fallback). See change: config-override-oauth-redirect-base.

`pluginPiHandlers` entries widened to `(msg, sessionId)` and `dispatchPluginPiMessage` passes the gateway-supplied `sessionId` through. Attribution source of truth for plugin bridge messages; see `event-wiring.ts`. See change: add-dashboard-mcp-server.

`start()` is now a thin wrapper: the startup body moved to `_startCore()` (new `DashboardServer` member, `@internal`) and `start(opts?)` runs it through `runBoundedStartup` (`lifecycle/bounded-startup.ts`). A step that throws or hangs after `piGateway.start()` tears down gateway → second fastify → fastify, then rethrows the ORIGINAL error; The deadline is OPT-IN (`start({deadlineMs})`): `cli.ts` passes `SERVER_STARTUP_DEADLINE_MS` for the standalone process, while in-process callers (tests, embedders) default to `null` = teardown-only, so a slow-but-fine boot is never killed on a wall clock. Stops the PID-78379 signature (gateway port held, dashboard port never bound, live loop). See change: fix-worktree-server-autostart-leak.

Plugin contexts gain `isPiExtensionInstalled` (design D2): one shared `createIsPiExtensionInstalled({listGlobal, listLocal})` hook (runtime `server/installed-probe.ts`) defined next to `packageManagerWrapper`, passed in every `createServerPluginContext` deps call. Union of global+local `packageManagerWrapper.listInstalled` scopes; ~30s success-only cache; scan failure rejects. See change: add-blackhole-session-pipeline.

Cross-site request gates (issue #625). One `corsOpts()` closure now builds the `CorsOriginOptions` for the CORS plugin, the WS upgrade gate and the mutating-REST gate — one live source, so admission and readability cannot drift. `fastify.server.on("upgrade")` calls `isWsOriginTrusted(headers.origin, headers.host, scope, corsOpts())` as the FIRST statement after `scope` (ahead of the `bridge` 400 early-return and the auth branches) → `403` + `socket.destroy()` + one sanitized `[ws-gate]` line; an untrusted Origin therefore never consumes a ticket and cannot distinguish a routed path from an unrouted one. `createMutationOriginGate(corsOpts)` is registered as an `onRequest` hook AFTER the CORS plugin. See change: fix-ws-origin-cswsh.
