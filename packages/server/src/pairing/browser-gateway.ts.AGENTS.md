# browser-gateway.ts — index

WebSocket gateway for browser clients. Exports `BrowserGateway` interface, `createBrowserGateway`, `buildOpenSpecConnectSnapshot`. Routes `BrowserToServerMessage` switch to `browser-handlers/*`. Manages subscriptions, replay suppression, headless `headlessPidRegistry`, `pendingResumeRegistry`, `viewedSessionTracker`, pending UI/prompt request replay, `broadcastEvent`/`broadcastSession*`/`broadcastOpenSpecUpdate` (pre-serialized payload fanout), plugin `registerHandler`/`registerDisconnectHandler`. Back-pressure guard via `MAX_WS_BUFFER`. Exports `getDroppedFrameStats()` (per-hop server→browser drop counters); `recordDroppedFrame` instruments each `MAX_WS_BUFFER` drop, surfaced on `/api/health#droppedFrames`. See change: fix-stuck-tool-card-on-dropped-event. Routes `role_remove` → `piGateway.sendToSession` (mirrors `role_set`/`role_preset_*` cases; without it custom-role removal was dropped server-side). See change: add-custom-roles-ui. Routes `subagent_resync_request` → `handleSubagentResyncRequest` → `piGateway.sendToSession`. See change: fix-subagent-live-detail-reliability (D2). Routes `set_session_tags` → `handleSetSessionTags`. See change: add-session-tags. Routes `remove_tag_globally` → `handleRemoveTagGlobally` (load-bearing switch case — unwired it falls through `default:`→`handlePiGatewayForward` and is misrouted to a bridge). See change: sidebar-tag-collapse-and-delete. `plugin_action` now fans out by pluginId: separate `pluginActionHandlers` Map<pluginId,Handler> + `registerPluginActionHandler(pluginId,handler)` gateway method (distinct from single-owner `customHandlers`); dispatch routes `plugin_action` to the owning plugin's handler, unknown pluginId → `plugin_action_error` sent to sender (never silent-drop), duplicate pluginId warns. See change: fix-plugin-action-fanout-and-handlers. Adds `hasPendingUiRequest(sessionId)` (unanswered `ask_user` tracked) - read by the embed-lifecycle reaper quiescence gate. See change: add-embed-session-lifecycle. Adds `hasPendingPromptRequests(sessionId)` (>=1 unanswered PromptBus request; read by the `currentTool` derivation and the reaper pending-ask union), `reconcilePromptRequests(sessionId, promptIds)` (snapshot setter - drops tracked prompts absent from the bridge's re-sent burst, recovering a `prompt_dismiss` lost across a socket drop), and `clearPendingRequestsForSession(sessionId)` (drops BOTH `pendingUiRequests` and `pendingPromptRequests` on session death; the pre-existing `pendingUiRequests` leak already made a dead session permanently unreapable). Accessors return ids/booleans, never prompt payloads. See change: restore-ask-user-tool-state-on-reconnect.
 Owns the bounded per-session notify log (`createNotifyLog`, cap 50, oldest-first). Adds `appendNotify(sessionId, entry)` (append + mirror onto `DashboardSession.notifyLog` so the debounced `.meta.json` save carries it across a restart) and `replayNotifyLog(ws, sessionId)` (sibling of `replayPendingUiRequests`, passed through `BrowserHandlerContext`; cold-hydrates from the restored session record when the in-memory log is empty). The log is deliberately NOT cleared in `clearPendingRequestsForSession` — an ended session keeps the rows it displayed while alive; reapability is protected by exclusion (no reaper signal reads it), not deletion. Exposes `getNotifyLogStats()` (cap evictions, `/api/health#notifyLog`). `hydrateNotifyLog(sessionId)` seeds the in-memory log from the restored record for BOTH `replayNotifyLog` and `appendNotify` — appending onto an empty in-memory list would mirror back a one-row array and wipe the persisted history. See change: split-notify-from-prompt-request.
 Adds the status-reconcile debt register: a shed `session_updated` is recorded, not lost. `broadcast()` derives `dirtyId = msg.type === "session_updated" ? msg.sessionId : undefined` and passes it to `fanout(serialized, stateKey, dirtyId)` — `fanout` sees only the serialized string and cannot recover type/sessionId without parsing, so the typed caller must supply it; every other caller (incl. `broadcastOpenSpecUpdateImpl`) passes `undefined`. Per-socket `statusDebt: Map<WebSocket, {ids:Set<string>, timer}>` holds IDS ONLY (no payload), so it cannot reach the pending-state byte ceiling nor move `stalledSocketsTerminated`. Own interval `STATUS_RECONCILE_INTERVAL_MS = 250` — NOT the pending-state timer, which exists only when a state frame defers and is never created by a purely-transcript flood. `flushStatusDebt` rebuilds the frame from `sessionManager.get(id)` (`{status, currentTool}`) under threshold; missing session → debt discarded, `statusReconcileSent` unchanged. Reconcile send carries `ctx.sessionId`, so a shed reconcile re-enters the debt at the drop site (eventually-delivered, idempotent `Set`). Settled-value only: an edge shed inside one window is not recovered. `dropStatusDebt` on close, on error, and on the `sendState` stalled-terminate path. Scope is `session_updated` alone — `session_added`/`session_removed`/`sessions_reordered` stay unrecovered. `DroppedFrameStats` gains `statusReconcileQueued`/`statusReconcileSent` (beside the drop counters, never folded in). New `getStatusReconcileInfo(ws)` (per-socket owed ids + timer liveness) and `getSocketBufferOccupancy()` → `SocketBufferOccupancy {max,p95,msAboveThreshold}` + `EMPTY_SOCKET_BUFFER_OCCUPANCY`; occupancy is sampled at the send-decision sites (which already read `bufferedAmount`) via `noteOccupancy`/`closeOccupancySpan`, NOT on a timer — a periodic sampler broke the "zero timers on an unsaturated socket" invariant (`browser-gateway-critical-frames` P3/E9). `setTestForceShed(enabled)` is a test-only shed injector, inert unless `PI_E2E_FORCE_SHED=1` at construction, surfaced as `POST /api/test/force-shed`. See change: fix-backpressure-status-and-subagent-frames.
