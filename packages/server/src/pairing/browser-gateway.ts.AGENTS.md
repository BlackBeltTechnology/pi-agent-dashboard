Manages subscriptions, replay suppression, headless `headlessPidRegistry`, `pendingResumeRegistry`, `viewedSessionTracker`, pending UI/prompt request replay, `broadcastEvent`/`broadcastSession*`/`broadcastOpenSpecUpdate` (pre-serialized payload fanout), plugin `registerHandler`/`registerDisconnectHandler`.  Adds the session-registry reconcile debt register: a shed registry frame is recorded, not lost. Registry kinds are `session_updated`, `session_added`, `session_removed`; `sessions_reordered` is now `state`-class (key `sessions_reordered:<cwd>`) — never shed, so it needs no debt. `broadcast()` derives delivery info (`id`, `kind`, `spawnRequestId`) via `deliveryInfoOf(msg)` and passes it to `fanout` — `fanout` sees only the serialized string and cannot recover type/sessionId without parsing. `session_added` carries its id at `msg.session.id` (NOT top-level `msg.sessionId`), so the shared derivation must not read `msg.sessionId` blindly. Per-socket `statusDebt: Map<WebSocket, {entries: Map<id, {kind:"updated"|"added"|"removed", spawnRequestId?, sawAdd}>, timer}>` holds identifiers + kind tag + one boolean + at most one short correlation id — zero payload bytes, so it cannot reach the pending-state byte ceiling nor move `stalledSocketsTerminated`. Kind precedence is LWW across `added`/`removed`; a newly recorded `updated` never downgrades a pending lifecycle kind. `sawAdd` is set when an `added` is recorded and survives a supersede by `removed` (the register's memory that the browser never received the creation); the shed `session_added`'s `spawnRequestId` survives that supersede too, so the sawAdd-branch reconcile can still clear the matching spawn placeholder instead of leaving it to the generic timeout. Own interval `STATUS_RECONCILE_INTERVAL_MS = 250` — NOT the pending-state timer, which exists only when a state frame defers and is never created by a purely-transcript flood. `flushStatusDebt` rebuilds from CURRENT server state under threshold, dispatch order: owed `removed` + no record → `session_removed`; owed `removed` + record `status !== "ended"` → re-registered, `session_added {reconciled:true}`; owed `removed` + ended + `sawAdd` → `session_added {reconciled:true, spawnRequestId?}` carrying the ended record; owed `removed` + ended + !`sawAdd` → `session_removed`; otherwise no record → `session_removed`; otherwise owed `added` → `session_added {reconciled:true, spawnRequestId?}`; otherwise `session_updated {status, currentTool, hostPressure}` (each `?? null` — an omitted key is dropped by `JSON.stringify` and the client merges `{...existing, ...updates}`, so it would PRESERVE the stale value; `hostPressure` is pushed on a TRANSITION only, so a shed recovery has NO successor frame and the badge would stay lit until a reconnect — see change: fix-false-unresponsive-badge). The status rule rests on the invariant `register()` is the only path to a non-ended record. A DELIVERED lifecycle frame (`session_added`/`session_removed`) clears that socket's debt for the id; a delivered `updated` is partial and does NOT clear. A shed reconcile re-records the SAME kind at the `sendTo` shed site (all three kinds) — self-healing. Settled-value only: an edge shed inside one window is not recovered. `dropStatusDebt` on close, on error, and on the `sendState` stalled-terminate path. Scope is the three registry kinds; `sessions_reordered` stays debt-free. `DroppedFrameStats.statusReconcileQueued`/`statusReconcileSent` count every registry kind (beside the drop counters, never folded in; no new field). New `getStatusReconcileInfo(ws)` (per-socket owed ids + `entries` carrying kind/`sawAdd`/`spawnRequestId` + timer liveness) and `getSocketBufferOccupancy()` → `SocketBufferOccupancy {max,p95,msAboveThreshold}` + `EMPTY_SOCKET_BUFFER_OCCUPANCY`; occupancy is sampled at the send-decision sites (which already read `bufferedAmount`) via `noteOccupancy`/`closeOccupancySpan`, NOT on a timer — a periodic sampler broke the "zero timers on an unsaturated socket" invariant (`browser-gateway-critical-frames` P3/E9). `setTestForceShed(enabled)` is a test-only shed injector, inert unless `PI_E2E_FORCE_SHED=1` at construction, surfaced as `POST /api/test/force-shed`. See change: fix-backpressure-status-and-subagent-frames.

Prompt-capability issuance (tasks 2b.1, 3.2). `setPromptCapabilityPolicy(policy | null)` installs the per-connection issuance decision AFTER construction (the policy needs `corsOpts`, which `server.ts` builds later). Unset = `null` = NO socket is ever issued a capability: fail-closed, so every existing embedder and test stays prompt-incapable. On `connection` each socket gets a local `grantSocketId` (`randomUUID`); if the policy returns `true` for `req.headers` (header-less `req` passes `{}`), the gateway sends `grant_channel {capability: issuePromptChannel(grantSocketId)}`. A throwing policy fails closed and does not break the connection. `ws.on("close")` calls `releasePromptChannel(grantSocketId)`, so a capability dies with its connection. `frameClassOf` classifies `grant_channel` as STATE (key `grant_channel`): the default arm is `transcript`, which is SHEDDABLE, and a shed capability would leave that browser prompt-less for the rest of its connection. Tests: `__tests__/browser-gateway-grant-channel.test.ts`. See change: add-access-grant-dialog.

`frameClassOf` classifies `grant_request` and `grant_dismiss` as STATE frames sharing the key `grant:<promptId>`: never shed (a shed prompt is a dialog that silently never appears), and a dismiss SUPERSEDES a still-queued request for the same prompt instead of racing it. `grant_response` reaches the coordinator through `registerHandler` (the `customHandlers` fallback). See change: add-access-grant-dialog.
