# pairing.ts — index

QR/copy-string pairing manager (D6/D12). `PairingManager({registry,getFingerprint,getReachableUrls,now?})`: `createPayload()` mints ~300s one-time code (`CODE_TTL_MS`; client countdown `GatewayPairQR.tsx` `PAIRING_CODE_TTL_MS` mirrors it) + payload `{v,id,code,urls[]}` (secure origins only, D14); `redeem(code)` creates ONE pending device + 8-digit confirm code (does NOT consume code); `approve(code,typedConfirmCode,label?)` compare-and-match then consumes code + mints bearer (rate-limit/lockout); `poll(pendingId)` one-shot token collect. `reachableUrls()` admits only https/wss (D14) EXCEPT a loopback http origin (`localhost`/`127.0.0.1`) when `PI_E2E_SEED=1` (`isTestLoopbackOrigin`; localhost is a browser secure context) so the Playwright/Docker harness runs the real handshake without TLS — never true in prod. Exports `PAIRING_PROTOCOL_VERSION`, `SUPPORTED_PAIRING_VERSIONS`. See change: add-server-keypair-pairing. See change: make-pairing-qr-camera-scannable.

`poll(pendingId, holder, channel)` marks the delivery channel via `registry.markDelivered`; `approve()` makes no exposure decision. See change: prove-vault-bridge-tls.

## add-pairing-approval-dialog

`redeem(code, meta?: RedeemMeta)` stores bounded untrusted redeemer metadata on the pending device (`userAgent` ≤256, `viaHost` ≤253, `remoteAddress` ≤64, `forwardedFor` = first XFF hop ≤64, `createdAt`) — display text only, never a decision, never logged (D4). `listPending(): PendingDeviceView[]` (live only: not approved/denied/locked; oldest first; `{pendingId, metadata, createdAt, expiresAt, attemptsLeft}`; NEVER code/confirmCode). `approvePending(pendingId, confirm, label?, tier?)` delegates to `approve()` (shared compare + lockout budget + expiry, D2). `deny(pendingId)` → `{ok}` | `no_pending` (live requests only — approved/denied/locked-out refused; a locked-out code stays re-redeemable); marks `rejected`, code dead (`redeem` → `invalid_code`), `poll` → `{status:"rejected"}` for 30s (D3). `approve` mismatch → `{error:"mismatch", attemptsLeft}` (post-increment); the 5th wrong returns `locked_out`. `onPendingChanged(cb)` fires AFTER commit on add/approve/deny/lockout/expire. Pushed expiry: per-entry `setTimeout(...).unref()` at `expiresAt+50ms` → `sweep()` emits + logs `expired` (D4b); cleared on approve/deny/lockout/overwrite; `dispose()` clears all timers + listeners. Logs `[pairing] pending|approved|denied|mismatch|locked_out|expired id=<pendingId[0..8]>` only (D7). `wirePendingHint(mgr, broadcast)` sends a fresh content-free `{type:"pair_pending_changed"}` per change (D1). See change: add-pairing-approval-dialog.
