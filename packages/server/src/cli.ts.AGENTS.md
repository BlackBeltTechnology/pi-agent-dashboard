# cli.ts — index

`pi-dashboard` CLI entry. Exports `parseArgs` (subcommand + flags), `buildConfig` (CLI+env+file merge → `ServerConfig`), `guardTempHomePort` + `PRODUCTION_DEFAULT_PORT` (8000), `cmdRestart` (delegates to `/api/restart` when dashboard running, else local stop/start), `parseNetstatListeners`, `findPortHolders` (back-compat re-exports). Subcommands `start`/`stop`/`restart`/`status`; default = foreground. `runForeground` does dynamic `./server.js` import → `startRecoveryServer` on `ERR_MODULE_NOT_FOUND`; asserts Node version + pi tool-registry resolution; legacy `~/.pi-dashboard` advisory. `installCrashSafetyNet` suppresses async faults. `runForeground` also installs idempotent SIGTERM/SIGINT handlers that `recordExitIntent("signal")` → `server.flush()` → `process.exit(0)`, so an OS shutdown is a recorded, recoverable exit instead of an untraced kill that also lost pending `.meta.json` writes. See change: fix-recovery-exit-intent. `buildConfig` runs the resolved port through `guardTempHomePort(port, os.homedir(), os.tmpdir())`: when HOME is under `os.tmpdir()` (a test/isolated/worktree run) an 8000 resolution is remapped to an ephemeral port (0) + warns — even on an explicit `--port 8000`. A faux-HOME server binding `127.0.0.1:8000` is MORE specific than the real server's `*:8000` and silently shadows the live dashboard for every localhost request (real dashboard appears to "lose" all sessions). See change: guard-temp-home-production-port. Subcommands also include `runtime` → `cmdRuntime(opts)` (sync print, exit 0): the PUBLISHED `runtime.resolved` block from raw config + a LIVE `resolveSpawnRuntime()` (piEntry null → canonical floor fallback, noted in output); injectable `configPath`/`resolve`/`out` for tests. At the END of successful startup `runForeground` calls `resolveLiveSpawnRuntime()` + `publishResolvedRuntime(rt)` — failure-tolerant (warn, never blocks startup). See change: unify-pi-runtime-identity (tasks 4.1/4.2). `--ephemeral` (FLAG ONLY — deliberately no env var, never inferred; D5) → `buildConfig.ephemeral`, arming the boot-parent watch; see change fix-autostart-discovery-precedence.

`main()` calls `migrateSubagentTickThrottle()` (config-api) right after `ensureConfig()` — the single boot-path site of the one-shot throttle-default migration. See change: heal-orphaned-tool-cards-on-session-end.

`buildConfig()` carries `push: fileConfig.push` into `ServerConfig`. See change: add-server-push-notifications.

- Identity plane: `cmdLogin(argv, {port}, deps)` = `pi-dashboard login --local` (D23 break-glass): POST `/api/identity/local-code` with the local token, prints `http://localhost:<port>/?pi_local=<code>` (single-use, ≤60 s). Dispatched in `main()` before the subcommand switch. See change: add-multi-user-identity-plane (18.24). `cmdStop(config,{force},injected?)` (exported) now takes the resolved `buildConfig` (so `--port`/`--pi-port` and the temp-HOME guard apply; `main()` passes a no-op `warn` for `stop`; ports <=0 never swept). Port sweep kills only listeners `lifecycle/stop-ownership.ts` proves this HOME owns (evidence gathered BEFORE the PID-file kill); foreign holders are reported with a `--force` hint (exit 0). `--force` (parsed for all subcommands, read only by `stop`; `restart` ignores it) kills every listener with a warning. `cmdRestart` fallback calls `stopFn(config)`. `buildConfig(flags, warn=console.warn)`. See change: fix-cli-stop-foreign-home-kill.

- `pi-dashboard service <verb>` dispatches to `services/cli-service.ts` `cmdService` with `localTokenHeader` + `localExecSecretsResolver` (exec resolves secrets locally, never via REST). See change: add-service-registry-core.

Local calls dial `localBase(config)` (`localDialHost(host)` literal) and send a per-request `X-Pi-Local-Proof` (`localCredentialHeaders`); the raw token is never sent. See change: loopback-credential-proof (D10).

`runForeground` calls `warnTsLoaderState()` once at boot (legacy `PI_DASHBOARD_TS_LOADER`, foreign jiti/tsx loader); `cmdStart` no longer catches `JitiNotFoundError` (class removed). See change: strip-only-native-ts-loader.

`cmdStart(config, injected?)` + `cmdStatus({port,piPort,host}, injected?)` are exported and share `lifecycle/classify-dashboard-port.ts`. `start`: classify first (owned→`already running (pid N)`, starting, unowned→`not owned by this HOME`, conflict, unresponsive→`running but not responding (pid N)` exit 1; only `free` launches); after readiness re-classify and print `started` ONLY when an owned dashboard reports the spawned child pid, else kill the unconfirmed child; every early child exit is re-classified (lost bind race → `already running`, exit 0). `status`: mDNS record kept only when `isLocal && port===config.port` (hostname hint); verdict from the classifier. `cmdStop` removes `server.pid` only when the pid is not alive after the kill. See change: harden-dashboard-start-detection.

`pi-dashboard pair list [--json] | approve [<id>] [--code d] [--name n] [--tier observe|control|operate] | deny <id>` (`cmdPair`, pre-switch dispatch like `token`/`service`/`login`). Existing routes only; token via `readLocalTokenIfPresent` (never created), `X-Pi-Local-Proof` per request, host-name `config.host` refused upfront (exit 1, nothing sent). Code from `--code` | TTY prompt | first stdin line; spaces/dashes stripped, non-8-digit refused locally (exit 2); never echoed. Exit: 2 usage/input, 1 credential/config, 3 server refused, 4 unreachable (5 s fetch timeout). `list` prints through `terminalSafe` (caps 64/120/64/64, pendingId full), never a code. `open --url <origin>`: `isLauncherOrigin` + http/https, no userinfo/query/fragment, path `/` at most, refused before `POST /api/local-proof`. Tests: `cli-pair.test.ts`, `cli-terminal-safe.test.ts`, `cli-open.test.ts`; QA `45-pair-cli.sh`. See change: fix-pairing-approval-credential.

`stop`: health-proven pid (`collectOwnership().healthProven`) is stopped by loopback `POST /api/shutdown` (no body, `localCredentialHeaders`; intent `shutdown`; bridges quiesce) then `waitForExit(pid,5000)`; error/refusal/survival → `killProcess` SIGTERM. New `StopDeps`: `collectOwnership`, `shutdownRequest`, `waitForExit`; `desktopAppNote` after a stop of an app-started server. `ownerSuffix(facts)` adds "(started by the pi-dashboard desktop app[, which is no longer running])" to `status` and the `owned` `portVerdict`. `cmdForeground(config,deps?)` = bare `pi-dashboard`: no probe on success; on any start failure classifies once, prints `portVerdict` lines or the generic message, `exit(1)` always. See change: fix-cli-control-electron-server.
