WebSocket server for bridge extension connections. Routes `ExtensionToServerMessage` → `SessionManager`; pings every `WS_PING_INTERVAL` (60s), heartbeat timeout `HEARTBEAT_TIMEOUT` (180s). See change: finalize-automation-run-on-session-death.
Enforces **one live bridge per session id**: the claim point is the first-message identity block (NOT the `session_register` dispatch), and the contention decision runs above every register side effect (watchdog clear, placeholder cleanup, `resetHeartbeat`, callbacks, `onEvent`). Contention resolved by a bounded two-factor probe (`CONTENTION_PROBE_WINDOW` 5s, override via `PiGatewayOptions.contentionProbeWindow`): pong → incumbent keeps; no pong but `_socket.writable` → busy, incumbent keeps; neither → terminate incumbent, accept newcomer. Same-pid reconnect and placeholder (`source:"unknown"`) incumbents skip the probe. Loser gets `register_rejected` before the close. Messages from a socket that does not own the id are dropped; per-socket message queue preserves order across the async decision. `ws.on("close")` cleanup guarded on `connections.get(id) === ws`; `stop()` terminates `wss.clients` (not `connections.values()`). Adds `contention` tracker + `findLiveSessionBySessionFile` (D5 resume guard). See change: fix-duplicate-bridge-registration.

The register-time watchdog clear is TIER-AWARE (`clearByToken` → `clearByPid` → `clearByCwd`, each short-circuiting on success): the former unconditional cascade let a token clear for spawn A go on to cancel a concurrent same-cwd spawn B, so B was never diagnosed and never reclaimed. `session_register.dashboardSpawned` is forwarded to `sessionManager.register` normalized to a strict boolean (`=== true`), alongside `hasUI`/`visibilityIntent`.
