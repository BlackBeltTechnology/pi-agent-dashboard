# resource-toggle-trust.ts — index

Project-trust gate for the resource-activation write. `resolveToggleTrust(cwd, agentDir, settingsManager)` → `proceed` | `refused` | `prompt`. Order: `ProjectTrustStore.getEntry(cwd)` — `true` proceeds; `false` recorded FOR THIS FOLDER refuses; an INHERITED ancestor `false` falls through to the prompt (pi's own dialog lets a nearer folder override). Nothing recorded → `SettingsManager.getDefaultProjectTrust()`: `always` proceeds WITHOUT recording (a user who chose `always` chose it to avoid prompts, not to enrol every folder), `never` refuses without prompting, `ask` prompts. Never mirrors pi's "no trust-requiring resources → trusted" shortcut: writing `.pi/settings.json` is itself what makes a folder trust-requiring. `hasTrustRequiringProjectResources(cwd)` is consulted only to EXPLAIN the prompt (`implicitlyTrusted`). `trustOptionsFor(cwd)` → dashboard-authored `trust`/`trust-parent`/`decline` (pi's `getProjectTrustOptions` is not reachable through the package `exports` map); `decline` carries `updates: []` so declining records nothing; no session-only option — the artefact written outlives any session. `persistTrustDecision(agentDir, updates)` writes through pi's own `ProjectTrustStore.setMany`. Exports `TrustUpdate`, `TrustOption`, `TrustGateResult`. See change: project-scope-disable-global-resources.
