# pi-resource-scanner.ts — index

Discovers extensions, skills, prompts, agents from local `.pi/`, global `~/.pi/agent/`, and installed `settings.json packages[]`. Agents from `agents/*.md` → `type:"agent"`; `parseFrontmatter` also reads `model` + `tools` (list `[a,b]`→`a,b` or scalar). Missing `agents/` → empty. Resolves package entries; local wins on dedup. Stamps `PiResource.enabled` from `pi-resource-activation.resolveActivation` (agents always true — pi has no agent activation dim; injectable via `ScanOptions.resolveActivation`; default true). Exports `scanPiResources`, `scanLocalResources`, `scanGlobalResources`, `parseFrontmatter`, `ScanOptions`, types from shared. `_resetNpmRootCache` test helper. Skills/prompts/themes now come from pi's own resolver (`ResolvedPaths`), not the walk: `metadata.scope` picks the local/global bucket (`temporary`→local), `metadata.origin=package` routes to the matching package row (unmatched `metadata.source` still reported, labelled raw via `PiResource.packageSource`), and pi's load gate drops any path with no non-empty frontmatter `description` (no name-based rule). `extensions`+`agents` stay scanner-discovered. `resolveActivation()` returning null/throwing/timing out, or returning empty while the walk finds resources, falls back to the walk and sets `PiResourcesResult.degraded`. `parseFrontmatter` strips YAML quoting off `description` so `""` reads empty. See change: folder-resource-activation-toggle, resources-card-tabs, fix-skill-discovery-parity.
