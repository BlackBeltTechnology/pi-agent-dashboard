# resource-entry-ownership.ts — index

Machine-local record of the plain settings entries THIS dashboard wrote, so a re-enable removes only its own. A user-authored entry is byte-identical to a dashboard-authored one, so ownership cannot be inferred from the file. Stored at `~/.pi/dashboard/resource-entry-ownership.json` (beside `worktree-init-trust.json`), atomic tmp+rename, shape `{ <resolved project path>: { skills|extensions|prompts|themes: string[] } }`. Deliberately NOT in `.pi/settings.json` (design D10): pi's `SettingsManager` has no writer for an unknown key, so recording there means two non-atomic writers per toggle, and it would put dashboard-private notation into a git-tracked file. Ownership is machine-local by nature — a collaborator's re-enable strips the exclusion and leaves the plain entry (inert residue, changes reported scope not activation). Exports `isOwnedEntry`, `recordOwnedEntry`, `clearOwnedEntry`, `OwnedArrayKey`. See change: project-scope-disable-global-resources.
