# resource-activation-toggle.ts — index

Writes the pi-standard settings form for a resource's ORIGIN, so pi enforces the result. `applyResourceToggle({scope,cwd?,type,filePath,enabled,packageSource?})`: `PackageManager.resolve()` locates the resource (404 if absent → also rejects `../` escapes; resolver throw → 500), `classifyFrom` picks the origin, then one of four writers. Forms: project-loose → `-<rel to .pi>`; `.agents`-loose → `-<rel to that base>`; package → project `{source, autoload:false, <type>:["-<rel to root>"]}` (global scope keeps in-place mutation — a second same-scope entry is dropped by pi's dedupe), matched by normalised identity; global-loose → own-FILE `~` entry + anchored glob `!**/<agentDirRelHome>/<rel>` (400 when the agent dir is not under `$HOME` — no portable form). Ambiguous relative pattern escalates to `!**/<baseLeaf>/<rel>`. Re-enable strips exclusions by exact spelling and writes NOTHING (never `+`); owned plain entries removed via `resource-entry-ownership.ts` AFTER a successful flush. Directional guard: global-scope toggle of a project resource → 400. Unparseable settings → 409 (pi would silently skip the write). Project scope passes `resolveToggleTrust` first — the single write choke point. pi's write is NOT JSONC-preserving (whole-file `JSON.parse`/`JSON.stringify`). Exports `settingsPathForScope`, `ToggleRequest`/`ToggleResult`/`ToggleFailure`/`ToggleScope`/`ToggleType`. See change: folder-resource-activation-toggle, project-scope-disable-global-resources.
