# resource-activation-routes.ts — index

pi-resource ACTIVATION routes (enable/disable), distinct from install/uninstall. Exports `registerResourceActivationRoutes({networkGuard,piGateway,sessionManager})`. `POST /api/resources/toggle` → `applyResourceToggle` (per-settings-file write mutex), returns `{affectedSessions}` (scope-governed running sessions). `POST /api/resources/reload` sends `/reload` to scope sessions (local=`findSessionsByCwd`, global=all), returns `{reloaded}`. `POST /api/resources/trust` persists a project-trust decision through pi's `ProjectTrustStore`: client names only an option id, server re-derives that option's updates AND requires an outstanding trust challenge raised by a real toggle (else 409), so a caller can pick neither the updates nor the path; trust-store write failure → 500, never a false success. A `403 trustRequired` toggle response carries `data.{trustRequired,trustOptions,implicitlyTrusted}` and registers the challenge. Exports `__resetTrustChallenges` (test seam). Auth via `networkGuard`. See changes: folder-resource-activation-toggle, project-scope-disable-global-resources.
Toggle trustRequired payload forwards `preselected`/`dashboardSource`. See change: mirror-dashboard-trust-to-pi.

Write mutex moved to `pi/settings-write-lock.ts` (`withSettingsWriteLock`), shared with the Add-ons hub toggle. See change: addons-hub-feature-catalog.

`routeAdmission` dep (default fail-closed). `POST /api/resources/toggle` admits a supplied `cwd` for both scopes before computing the settings path (403 `cwd_unknown` / 503); every trust challenge it registers is for an admitted cwd. No cwd = global scope. See change: core-file-cwd-admission.
