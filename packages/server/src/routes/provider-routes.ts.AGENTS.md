# provider-routes.ts — index

Custom LLM provider read/write to `~/.pi/agent/providers.json`. Exports `registerProviderRoutes`. Endpoints: `GET /api/providers` (redacted, folds in credential-free `health` from `provider-health-cache` WITHOUT re-probing), `PUT /api/providers` (merge, blank-name guard, recursion guard, `***` masked-sentinel preserve, ATOMIC tmp+rename write per change add-agent-role-model-tools Bug 7, then AWAITS `probeProvider` per saved provider → caches health), `POST /api/providers/test` (probe without saving; caches result when `name` present). Broadcasts `credentials_updated` + `refreshModelRegistry()` (re-runs custom-provider discovery). See change: surface-provider-health-in-settings.

Adds `PATCH`/`DELETE /api/providers/:name` — PATCH upserts, preserves EVERY non-`providers` top-level key (`roles`/`rolePresets`/`activePreset`), no `await` between read and tmp+rename, inherits the masked-sentinel + `RECURSIVE_PROXY` guards, probes only the touched provider and responds WITHOUT awaiting it, `retainProviderHealth` with the full remaining key list (DELETE drops only its own entry). `redactProviders` annotates `apiKeyResolved?: boolean` on a `$NAME` apiKey (`$NAME` passes through verbatim; resolution is a SERVER fact a browser cannot evaluate). See change: redesign-providers-settings-page (D1, D3).

A CORRUPT `providers.json` is quarantined and the WRITE REFUSED (409), never silently rebuilt — `readProvidersFileDataChecked()` returns `{}`+`corrupt` on an unparseable/non-object file, `quarantineCorruptProvidersFile()` saves a byte-exact `providers.json.corrupt-<stamp>` copy (sha256-deduped, `wx`, 0600, COPY never rename), and PATCH/DELETE/PUT refuse. Before this, a bare `catch { /* start fresh */ }` rebuilt the document from `{}` on a write and destroyed `roles`/`rolePresets`/`activePreset`. The GET path still TOLERATES corruption (an unparseable file must not 5xx the read). Mirrors `auth.json`. See change: redesign-providers-settings-page (D3).

The corruption check covers the `providers` VALUE, not just the top-level document: every route does `fileData.providers ?? {}` and writes through it, so an ARRAY took `existing[name] = entry` but `JSON.stringify` serialised it positionally and DROPPED the key — PATCH answered 200 having persisted nothing — and a STRING threw on that assignment and 500'd. Both now take the same quarantine+409 path. `providers: null`/absent keeps its "no providers yet" meaning. Both write paths go through `writeProvidersFileData()` (PUT no longer inlines its own tmp+rename) and create the tmp `mode: 0o600` plus an explicit `chmodSync`: `renameSync` gives the live file the TMP's inode, so the destination mode is NOT preserved, and `writeFileSync`'s `mode` applies only at CREATION — a tmp left by a crashed write would carry 0644 through the rename and publish API keys group/world-readable. Mirrors `auth.json`. See change: redesign-providers-settings-page (CodeRabbit PR #709).
