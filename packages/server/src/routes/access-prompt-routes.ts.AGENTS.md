# access-prompt-routes.ts — index

Access-prompt review API (add-access-grant-dialog 8.1-8.3, 8b.7a/b, 8b.8, 2b.9). `registerAccessPromptRoutes(fastify, {networkGuard, coordinator, planes, yolo, prompting, listRefusals, clearRefusal})`. `GET /api/access/prompts` -> `AccessPromptsView {prompting{enabled,killSwitch,hostGateMode,blockers report-mode|kill-switch|disabled}, pending PendingPromptView[] (no `channel`), verdicts (operator ring + YOLO log, `answeredBy`), yolo{available,durationsMinutes,session}, refusals}`. `POST /api/access/prompts/:promptId` -> `coordinator.settle` (answers unprompted entries too; statuses malformed 400/unoffered 403/unknown 404/duplicate 409/expired 410). `GET /api/access/yolo/roots?base=`, `POST /api/access/yolo` (activate or add root, report-mode 409), `DELETE /api/access/yolo`, `DELETE /api/access/refusals?plane=&subject=`. Mutations: global mutation-origin gate + `networkGuard` only (local, local token, trusted network, or authenticated), deliberately wider than `POST /api/access/grants` auth-or-loopback: a trusted-network browser already answers via the dialog WS, so the Access page matches it, YOLO included (user decision C). Module-private helpers `promptingBlockers`, `mergeVerdicts`, `parseYoloActivation`. Pending view carries `ttlMs` (remaining at response time) for skew-free client countdowns (review 9.5). Refusal clear route accepts `plane=agent-path` besides registered planes. See change: yolo-covers-agent-path-gate.
