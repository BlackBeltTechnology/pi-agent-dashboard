# access-routes.ts — index

The grant endpoint + Access review API (design D12/D15/D20). `POST /api/access/grants` is the ONE place a filesystem grant can be created, and it refuses to create one without a LIVE denial id the operator saw; the subject must be the denial's own subject or an offered ladder rung, compared in **canonical** form because `recordGrant` normalizes a non-directory onto its containing directory. The forbidden filter is applied to the **normalized** subject — checking only the raw one let a denial naming a FILE (`grantableSubjectOf` is a lexical dirname, so it is a regular file whenever the refused path had one extra component) pass the filter and then normalize into a grant for the whole of `$HOME`, or for `/`. `DELETE /api/access/grants` revokes for immediate effect, and the remaining routes revoke the other seven in-scope stores through each store's OWN write path (never writing pi's store directly). A successful grant is AUDITED (`[access-grant] granted …`, STRIDE: Repudiation), mirroring the network-trust accept path. Tier `operate`, behind `networkGuard` + the global mutation-origin gate.
