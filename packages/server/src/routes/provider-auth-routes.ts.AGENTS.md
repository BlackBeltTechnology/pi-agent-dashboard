# provider-auth-routes.ts — index

Provider OAuth (delegated to pi-ai) + API-key auth. Exports `registerProviderAuthRoutes`. Routes: `GET /api/provider-auth/providers|handlers|status|catalogue-ready`, `POST /api/provider-auth/start { provider, enterpriseDomain? }` (supersedes same-provider pending flow, starts `login()`, 200 `OAuthFlowStatus` on first user-facing step, 400 unknown, 500 pre-event rejection, 504 `Provider did not respond`), `GET|DELETE /api/provider-auth/flow/:flowId`, `POST /api/provider-auth/flow/:flowId/input { value }` (202 / 409 `No input pending for this flow` / 404), `PUT /api/provider-auth/api-key`, `DELETE /api/provider-auth/:provider`. Removed: `POST .../authorize`, `POST .../device-code`, `GET .../device-status/:flowId`.

The flow store lives in `provider-auth-adapter.ts` (TTL 10 min, prune per request + 60 s timer, `abortAllFlows()` on close). `/input` value may be a secret (auth code / redirect URL) — handed to the flow unchanged, never logged or echoed. Every provider-auth request awaits `registryReady`; production kicks the lazy registry build at route registration. Notifies bridges `credentials_updated` + eager-refreshes model registry. `GET .../status` keeps its BARE-ARRAY shape and answers 200 all-unauthenticated on corrupt `auth.json` content; `DELETE .../:provider` maps a write failure to `{ error }` matching `PUT` — lock-contention exhaustion included, passing the lock error's own message through rather than a generic phrase. Every credential write is AWAITED (`provider-auth-storage`'s writers are async). See changes: fix-provider-auth-lock-contention, delegate-provider-oauth-to-pi-ai.

`PUT /api/provider-auth/api-key` maps a credential-type conflict to 409 (`code` + `vars.storedType`); `DELETE /api/provider-auth/:provider` derives the addressed row kind via `oauthIdSet()` (registry ∪ stored oauth ids) and refuses a mismatch. `GET /api/provider-auth/catalogue-ready` -> `{ ready }`. See change: redesign-providers-settings-page (D2, D5).
