# openspec-routes.ts — index

REST routes: openspec-archive, pi-resources (cwd optional → falls back to `process.cwd()` for the global Settings resource pages; change: resources-card-tabs), pi-resource-file. Adds POST /api/openspec/config (core→CLI preset, expanded/custom→atomic JSON write, busts configCache), POST /api/openspec/update (per-cwd or all known cwds, records signature), GET /api/openspec/update-status (up-to-date|needs-update|unknown). knownCwds = union(session cwds, pinned dirs). GET /api/openspec/config reads via `configListOrAsync` (async, non-blocking). `currentGlobalSignature` async + computed ONCE per request (profile is global). GET /api/openspec/update-status + POST /api/openspec/update signature step no longer spawn `openspec config list` per-cwd — was ~11s blocking for 11 projects, starved concurrent config GET. See changes: add-openspec-profile-settings, fix-openspec-profile-load-race.

`GET /api/pi-resources`: stale-while-revalidate — serves a stale entry at once and starts one deduped background rescan (rejection swallowed, next request retries); cold miss / `refresh=true` await the scan. See change: optimize-polling-hot-paths.

Adds `POST /api/openspec/workflow-schema` (`control` tier): body `{cwd, action: enable|disable|update|adopt|pin|remove, ...}`. Gate order: shape → tracked-or-pinned (membership, no fs) → OpenSpec enabled → not opted out → fs (realpath + `<cwd>/openspec/`) → per-cwd lock (`inFlightInits`, keyed `realpathSync.native(cwd)`, shared with `POST /api/openspec/init`, 409 on contention). Allowed-state table + name/containment checks live in `runWorkflowSchemaAction`. Structured log `openspec.workflow-schema` (stampBefore/After). `POST /api/openspec/init` chains `enable` when `openspec/` was absent AND `workflowSchema.defaultForNewProjects`; failure reported as `workflowSchemaError`, never fails init. Deps: `getOpenSpecConfig` (live config), `spawnSemaphore`, `workflowSchemaDeps` (test seam); exports `OpenSpecGateConfig`. See change: add-pi-spec-driven-schema.

Legacy-artifact mirror (`LEGACY_CONFIG_FILES`, `LEGACY_COMMAND_DIRS`, `LEGACY_COMMAND_FILE_DIRS`) hoisted to module scope + exported so `__tests__/openspec-legacy-cleanup-parity.test.ts` (E19) reads it against the installed `@fission-ai/openspec` `dist/core/legacy-cleanup.js`. Mirrors 1.14.3: CoStrict `.cospec/openspec/commands` is a FILE dir now (cleanup is `openspec-*.md`-scoped); `.junie/commands` is a documented superset extra. See change: refresh-electron-bundled-components.

`GET`/`PUT /api/openspec/dependencies` (`observe`/`control`, `networkGuard`). Gate order: `invalid-request` 400 → `cwd-not-tracked` 403 → `openspec-disabled` 403 → `opted-out` 403 → `no-openspec-dir` 404 → `status-all-unsupported` 409 → `pending` 503 → `unknown-change` 404. PUT: whole-body validation first (≤64 KiB, names ≠ change, reasons ≤500, `expected` required), then `writeGuard` (`write-refused` 403), shared lock `inFlightInits` (`locked` 409), `dependencies-file.ts` write (`modified` 409). Log event `openspec.dependencies`. See change: add-openspec-change-dependencies.
Core cwd admission: 12 caller-`cwd` sites admit through `admitOpenSpecCwd` (`admitRouteCwd` + `admissionAllows`). Ungated sites (`config`, `update {cwd}`, `openspec-archive`, `pi-resources`, `pi-resources/commands`, `tasks`, `tasks/toggle`) → `admitUngatedCwd`: refuse/global-dir ⇒ 403 `cwd_unknown {reason,hint}`; indeterminate ⇒ 503. Gated sites (`init`, `workflow-schema`, dependencies via `depGates`) admit first, then KEEP exact `knownInitTargets` membership + opt-out (`isOptedOut`: raw AND canonical) + global-dir, with today's refusal bodies. Ops/keys keep the guarded RAW cwd. `change` segment: `isPortableProjectName` → 400 `invalid_name` (tasks, toggle; dependencies next to `KEBAB_ID_REGEX`). Server-chosen fallbacks and `update {all}` are not re-admitted. Deps `knownFolderCwds` (default `listKnownFolderCwds` of its own stores), `admitOptions`. See change: core-cwd-admission.
