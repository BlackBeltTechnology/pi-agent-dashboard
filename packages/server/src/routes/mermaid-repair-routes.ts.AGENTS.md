# mermaid-repair-routes.ts — index

`POST /api/mermaid/repair` `{code,error}` → `{success,data:{code,model}}`. Exports `registerMermaidRepairRoutes(fastify,{networkGuard,getConfig,getRegistry,getStreamSimple,log?})`; module-private `collectRepairText` (text deltas only), `extractDiagram`. One completion via `streamCompletion` (credentials server-side, no `apiKey` override), temperature 0, `maxTokens=min(ceil(maxChars/3),8192)`. Validation order: disabled 404 → bad_request 400 → too_large 413 (`code`>maxChars or `error`>2000) → busy 429 (one in-flight per server). Timeout via `setTimeout` abort → 504; client disconnect (`reply.raw` close) aborts the provider call, sends nothing, logs `aborted`. Provider throw/unknown model 502 `provider_error`; empty/oversize output 502 `unparseable` (never truncates). Error envelope `{success:false,error:<static text>,code}`. Logs one `[mermaid-repair] outcome= model= ms= chars=` line, never content. Output is untrusted: client renders + sanitizes. See change: add-mermaid-ai-repair.
