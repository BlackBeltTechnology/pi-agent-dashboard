# memory-event-store.ts — index

In-memory event store with LRU eviction; replaces SQLite-backed event-store. Exports `StoredEvent`, `EventStore`, `createMemoryEventStore(isSessionPinned, maxCachedSessions, maxEventsPerSession, maxStringFieldSize, maxEventDataSize)`, `exceedsSerializedSize(value, cap)`, `measureBytes(value, cap)`, `capString(s, maxSize)`, `reduceSubagentEvent(event, ceiling)`, `shrinkEntryToBudget(entry, B)`, `DEFAULT_MAX_CACHED_SESSIONS`, `DEFAULT_MAX_EVENTS_PER_SESSION`, `DEFAULT_MAX_EVENT_DATA_SIZE`. Per-session buffers, truncates large string fields, `findToolEndEvent` reverse-scans for `tool_execution_end`. Skips pinned sessions in eviction. Per-session trim preserves chat head: drops oldest NON-essential event first (tool/subagent/flow/reasoning noise), only drops oldest `message_start`/`message_end` under extreme pressure; `DEFAULT_MAX_EVENTS_PER_SESSION`=20000 (was 5000, subagent floods parent buffer). Per-event total-serialized-size ceiling (`DEFAULT_MAX_EVENT_DATA_SIZE`=20000, `0`=off): after per-field truncation, `exceedsSerializedSize` (bounded early-exit walk, never full-stringifies) gates replacing over-cap `event.data` with a `{__truncated}` placeholder — stops one oversized subagent event OOM-ing the broadcast `JSON.stringify`; `truncateStrings` depth>4 now truncates/collapses to `[truncated: deep]` (preserves image blocks) instead of returning raw. See change: bound-subagent-event-serialization. See change: preserve-chat-head-on-event-trim. `capString` skill-envelope-aware: `SKILL_ENVELOPE_RE` truncates BODY only, keeps `<skill>` header/closing tag/args intact so client `parseSkillBlock` survives. See change: bound-subagent-event-serialization (skill regression). Subagent-timeline head+tail: `locateSubagentTimeline` TYPE-scopes detection (`data.toolName==="Agent"` or `tool_execution_update`/`_end` + `details.agentId`, AND `entries[]` at `partialResult.details.entries`/`data.details.entries`); such over-ceiling events route to `reduceSubagentEvent` (detected BEFORE the generic pass so the >20-array clobber never hits `entries[]`) instead of `{__truncated}` — keeps first `K_HEAD`=1 + last `K_TAIL`=4 entries, elides the middle into a `{kind:"text","⋯ N steps hidden ⋯"}` sentinel (no new wire kind), caps `args.prompt`@2000/`details.description`@1500/`content[*]` text+image@1500, shrinks kept entries to a per-ENTRY byte budget via `shrinkEntryToBudget` (largest-leaf head+tail, floor 256), byte-accurate terminal proof, `{__truncated}` fallback when unreducible; returns a NEW event (never mutates the in-flight one). `capString` generic branch is now head+tail 50/50 (`…[N chars hidden]…`). Size walk is byte-accurate (`jsonStringByteSize`: UTF-8 width + JSON escapes; base64 image `data` counted at REAL size — no longer exempt — so image-bearing over-ceiling events correctly hit `{__truncated}`, closing a latent broadcast OOM); huge strings short-circuit via the code-unit lower bound (no scan, no stringify). `measureBytes` returns exact bytes when under cap else cap+1. See change: head-tail-truncate-subagent-event-timeline.
