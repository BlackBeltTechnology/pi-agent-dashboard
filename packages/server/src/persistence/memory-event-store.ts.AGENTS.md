# memory-event-store.ts — index

In-memory event store with LRU eviction; replaces SQLite-backed event-store. Exports `StoredEvent`, `EventStore`, `createMemoryEventStore(isSessionPinned, maxCachedSessions, maxEventsPerSession, maxStringFieldSize, maxEventDataSize)`, `exceedsSerializedSize(value, cap)`, `measureBytes(value, cap)`, `capString(s, maxSize)`, `reduceSubagentEvent(event, ceiling)`, `shrinkEntryToBudget(entry, B)`, `DEFAULT_MAX_CACHED_SESSIONS`, `DEFAULT_MAX_EVENTS_PER_SESSION`, `DEFAULT_MAX_EVENT_DATA_SIZE`. Per-session buffers, truncates large string fields, `findToolEndEvent` reverse-scans for `tool_execution_end`. Skips pinned sessions in eviction. Per-session trim preserves chat head: drops oldest NON-essential event first (tool/subagent/flow/reasoning noise), only drops oldest `message_start`/`message_end` under extreme pressure; `DEFAULT_MAX_EVENTS_PER_SESSION`=20000 (was 5000, subagent floods parent buffer). Per-event total-serialized-size ceiling (`DEFAULT_MAX_EVENT_DATA_SIZE`=262144 (256 KiB; couples to `DEFAULT_TRANSCRIPT_CAP_BYTES` 192 KiB per D9), `0`=off): after per-field truncation, `exceedsSerializedSize` (bounded early-exit walk, never full-stringifies) gates replacing over-cap `event.data` with a `{__truncated}` placeholder — stops one oversized subagent event OOM-ing the broadcast `JSON.stringify`; `truncateStrings` depth>4 now truncates/collapses to `[truncated: deep]` (preserves image blocks) instead of returning raw. See change: bound-subagent-event-serialization. See change: preserve-chat-head-on-event-trim. `capString` skill-envelope-aware: `SKILL_ENVELOPE_RE` truncates BODY only, keeps `<skill>` header/closing tag/args intact so client `parseSkillBlock` survives. See change: bound-subagent-event-serialization (skill regression). Subagent-timeline head+tail: `locateSubagentTimeline` TYPE-scopes detection (`data.toolName==="Agent"` or `tool_execution_update`/`_end` + `details.agentId`, AND `entries[]` at `partialResult.details.entries`/`data.details.entries`); such over-ceiling events route to `reduceSubagentEvent` (detected BEFORE the generic pass so the >20-array clobber never hits `entries[]`) instead of `{__truncated}` — keeps first `K_HEAD`=1 + last `K_TAIL`=4 entries, elides the middle into a `{kind:"text","⋯ N steps hidden ⋯"}` sentinel (no new wire kind), caps `args.prompt`@2000/`details.description`@1500/`content[*]` text+image@1500, shrinks kept entries to a per-ENTRY byte budget via `shrinkEntryToBudget` (largest-leaf head+tail, floor 256), byte-accurate terminal proof, `{__truncated}` fallback when unreducible; returns a NEW event (never mutates the in-flight one). `capString` generic branch is now head+tail 50/50 (`…[N chars hidden]…`). Size walk is byte-accurate (`jsonStringByteSize`: UTF-8 width + JSON escapes; base64 image `data` counted at REAL size — no longer exempt — so image-bearing over-ceiling events correctly hit `{__truncated}`, closing a latent broadcast OOM); huge strings short-circuit via the code-unit lower bound (no scan, no stringify). `measureBytes` returns exact bytes when under cap else cap+1. See change: head-tail-truncate-subagent-event-timeline. Store-shed telemetry: `trimBufferToLimit` returns `{dropped,toolEndDropped}` (counts `tool_execution_end` among drops in the same O(n) pass), `evictIfNeeded` returns evicted-buffer count; closure accumulates `trimmedEventsTotal`/`trimmedToolEndTotal`/`trimmedEventsBySession`(Map)/`evictedSessionsTotal`; `getTrimStats()` handle returns `TrimStats {trimmedEvents:{total,toolExecutionEnd,bySession},evictedSessions}` (global counters cumulative/never-reset; `bySession` lifecycle-scoped — entry dropped in `evictIfNeeded`/`deleteEventsForSession` when its buffer is removed, so the Map cannot accumulate stale sessions). See change: instrument-event-store-trim. `ESSENTIAL_CHAT_EVENT_TYPES` also includes `inline_terminal_open`/`inline_terminal_close` so the structurally-paired inline terminal lifecycle events survive per-session trim together (reducer replays the card at its original stream position). See change: preserve-inline-terminal-transcript. Also exports `DEFAULT_MAX_STRING_SIZE` (4000), consumed by `deriveTranscriptCapBytes`. See change: fit-attachments-for-display. Superseded-update collapse (D1/D5/D6/D7): `insertEvent` drops the previously-retained `tool_execution_update` per `toolCallId` when the incoming one SUBSUMES it, ordered AFTER `truncateEventData` and BEFORE trim/evict. Gate (`subsumes`) resolves details as `data.partialResult.details` ONLY (mirrors the reducer; a top-level `data.details` belongs to `tool_execution_end` and is NOT consulted) and requires: every predecessor key present with the SAME JS type (`readSubagentDetails` extracts type-conditionally, so a type-downgraded key is "absent" to the consumer), a non-empty `entries` not replaced by an empty one, and — if the predecessor sets the rendered `result` — the successor sets it too (`setsRenderedResult` covers BOTH sources: plain-string `partialResult` and structured `partialResult.content`). Neither carrying details ⇒ collapse unconditionally. Per-buffer index `Map<toolCallId,{creatingSeq,newestSeq}>` — TWO independent pointers: the first update carrying `details.agentId` is PINNED (the reducer's `type`/`description` are first-wins) and never collapsed, so a single-seq index would silently void the pin. Values are SEQS never array positions (`trimBufferToLimit` rebuilds the array wholesale). Lookup `findIndexBySeq` scans BACKWARD from the tail with an early break once below the target (a FORWARD scan — `getEvent`'s shape — would make collapse O(buffer length)); `dropIfSuperseded` VERIFIES the located entry is still a `tool_execution_update` with the same `toolCallId` before splicing, so a stale index is a no-op and a -1 can never reach `splice` (which would delete the max-seq event). Fail-open: an update with no `data.toolCallId` (incl. the `{__truncated}` placeholder) is retained and collapses nothing. The index rides on `SessionBuffer`, so it is released with the buffer on LRU evict / `deleteEventsForSession` (a process-wide map would leak an entry per `toolCallId` of every evicted session). `TrimStats` gains additive `collapsedUpdates`; `EMPTY_TRIM_STATS` is the explicitly-typed all-zero constant `/api/health` uses as its `??` fallback (an inline literal would typecheck while omitting a new required field, since `a ?? b` does not check `b` against `A`). `getCollapseProbe()` returns `{lastEntriesExamined,maxEntriesExamined,indexedToolCalls}` — TEST-ONLY find-cost instrumentation, deliberately distinct from the `collapsedUpdates` telemetry counter. See change: collapse-superseded-tool-execution-updates.
