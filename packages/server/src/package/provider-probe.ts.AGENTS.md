# provider-probe.ts — index

Provider probe — pings custom LLM provider base URL + API key to verify reachability/auth. Exports `buildProbeRequest`, `resolveProbeApiKey`, `probeProvider`, `listProviderModelIds` (full model-id list, not capped; reuses `buildProbeRequest`; [] on failure — used by server custom-provider discovery), `readProvidersFromDisk`, `ProbeApi` (`openai-completions`/`openai-responses`/`anthropic-messages`/`google-generative-ai`), `ProbeInput`, `ProbeResult`, `ProvidersReader`. Used by `POST /api/providers/test`. Responses scrubbed (never echo api key). See change: add-agent-role-model-tools.

`redactErrorText` scrubs credential SHAPES, not only the submitted key. The error is cached into `ProviderHealth`, which `provider-connection-test` requires to carry no credential material at ALL — and an upstream or intermediary routinely echoes a DIFFERENT secret (an `Authorization` header it received, a labelled `api_key`/`access_token`/`client_secret`, a vendor-prefixed `sk-`/`ghp-`/`xoxb-` key). Each pattern keeps the NAMING prefix and redacts only the value (`Bearer [REDACTED]`), so the error stays diagnosable; patterns are deliberately narrow (labelled secrets, not every high-entropy token) because over-broad redaction destroys the diagnostic value the body exists for. See change: redesign-providers-settings-page (CodeRabbit PR #709).

`readProvidersFromDisk()` resolves the `providers.json` path per call (`configPath()`), not at module load, so a changed HOME is honoured. See change: fix-provider-catalogue-first-run (D3).

Both probe `fetch` calls (`probeProvider`, `fetchProviderModelBody`) pass `redirect: "error"`: the credential header never follows a redirect. `probeProvider` maps the refused redirect (undici `cause` /redirect/) to `ok:false` with an error asking for the final URL; the model-list path returns `[]`. See change: triage-codeql-alert-debt (D3 #19).

Egress vet + secret binding (NET-04). `validateProbeBaseUrl` (non-URL → `Base URL is not a valid URL`, non-http(s) → `Base URL must use http or https`), `normalizeBaseUrl` (lower-case scheme/host, default port elided, ONE trailing `/` stripped, query/fragment dropped; userinfo + trailing-dot host kept → compare unequal; `null` on parse failure). `resolveProbeApiKey` gains OPTIONAL `requestBaseUrl` (only the Test route passes it): `***` → saved `baseUrl` must normalise equal (else `CHANGED_BASE_URL_ERROR`); request-supplied `$NAME` → some saved provider must hold exactly that ref at the same URL (else `ENV_KEY_BINDING_ERROR`, checked BEFORE the env lookup, never reveals whether the var is set). Absent `requestBaseUrl` = old behaviour (saved probes, discovery). `vetProbeTarget(baseUrl, signal?)` = `resolveAndVet(host, port, selfPort, lookup, "provider")`, lookup raced against the probe's 8 000 ms abort; called inside `probeProvider` and `fetchProviderModelBody` BEFORE `fetch` (Test, save/refresh probe, discovery). Refusal → `{ok:false,error}` (no `status`) / `null` + one host-only `console.warn`. `setProbeSelfPort(getter)` registered once by `server.ts` (unset → own-port rule off, metadata rule always on). `setProbeLookupAll(fn|null)` = test seam. Blocked set = webhook set (`169.254.0.0/16`, `fe80::/10`, `fd00:ec2::254`, IPv4-mapped); `100.100.100.200`/`192.0.0.192`/`fd00:ec2::23` named residual. See change: close-local-listener-and-egress-gaps.
