# provider-probe.ts — index

Provider probe — pings custom LLM provider base URL + API key to verify reachability/auth. Exports `buildProbeRequest`, `resolveProbeApiKey`, `probeProvider`, `listProviderModelIds` (full model-id list, not capped; reuses `buildProbeRequest`; [] on failure — used by server custom-provider discovery), `readProvidersFromDisk`, `ProbeApi` (`openai-completions`/`openai-responses`/`anthropic-messages`/`google-generative-ai`), `ProbeInput`, `ProbeResult`, `ProvidersReader`. Used by `POST /api/providers/test`. Responses scrubbed (never echo api key). See change: add-agent-role-model-tools.

`redactErrorText` scrubs credential SHAPES, not only the submitted key. The error is cached into `ProviderHealth`, which `provider-connection-test` requires to carry no credential material at ALL — and an upstream or intermediary routinely echoes a DIFFERENT secret (an `Authorization` header it received, a labelled `api_key`/`access_token`/`client_secret`, a vendor-prefixed `sk-`/`ghp-`/`xoxb-` key). Each pattern keeps the NAMING prefix and redacts only the value (`Bearer [REDACTED]`), so the error stays diagnosable; patterns are deliberately narrow (labelled secrets, not every high-entropy token) because over-broad redaction destroys the diagnostic value the body exists for. See change: redesign-providers-settings-page (CodeRabbit PR #709).
