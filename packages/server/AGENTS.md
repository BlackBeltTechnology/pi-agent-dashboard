| `bin/pi-dashboard.mjs` | `pi-dashboard` CLI shebang wrapper. Resolves jiti from `argv[1]`'s module graph and re-execs Node with `--import <jiti> src/cli.ts <args>` as a CHILD process; `--version`/`-v` short-circuits without jiti. FORWARDS `SIGTERM`/`SIGINT`/`SIGHUP` to that child — the wrapper owns `argv[1]`, so `kill <pid>`, a supervisor, and Ctrl-C all land on it; without forwarding the server child was orphaned and its exit-intent handler never ran. Re-raises the child's signal after dropping its own listener. Injects `--max-old-space-size=8192` into the child's `NODE_OPTIONS` (mirrors the bridge launcher `buildSpawnEnv`) unless the user already pinned a limit, so a bare `pi-dashboard` start gets the same 8 GB heap ceiling the bridge-launched server does — without it the standalone path runs at Node's default ~4 GB and the event store's worst-case per-session buffer can OOM-crash the server. No longer stamps `JITI_TSCONFIG_PATHS`: the browser plugin's vendored relay uses package-relative specifiers, so the flag has no remaining justification and a global resolution-semantics switch is not left alive for other plugins. See changes: replace-tsx-with-jiti, enable-standalone-npm-install, fix-recovery-exit-intent, standalone-heap-headroom, fix-browser-plugin-vendor-specifier-resolution. |
| `vitest.config.ts` | Vitest config for server package. `include` `src/**/__tests__/**/*.test.ts`, `environment` `node`, `pool` `forks`, `maxWorkers: PARALLEL_MAX_WORKERS`, `globalSetup` `setup-home.ts`. `setupFiles` resolves config-relative `setup-home-perfile.ts` so worktree-local source wins over hoisted node_modules. `resolve.alias` maps `@blackbelt-technology/pi-dashboard-shared` → `../shared/src` (worktree-local shared wins over hoisted symlink; mirrors client config) and `@blackbelt-technology/dashboard-plugin-runtime{,/server}`. `testTimeout` + `hookTimeout` 30_000 — full-server boots in tests and `beforeEach` hooks blew the 5s/10s defaults under fork contention. `exclude` spreads `REAL_PROCESS_TESTS` from `./vitest.real-process-files` — those run in their own phase after the parallel run. See change: `parallelize-test-suite`, fix-and-prefer-model-proxy-resolution, contention-harden-real-process-tests, isolate-real-process-tests. |
