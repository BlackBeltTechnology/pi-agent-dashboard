Retry surface — collapse while retrying, close once stopped

Session Stop already stops the retry (abortLatch.request → cachedCtx.abort(), re-armed for 2 s, plus abort-on-sight when the turn wakes). No new control is added anywhere. The one bug: ✕ deletes retryState, which unmounts that existing Stop.

1 · the three states

retrying · expanded — spinner, short status, chevron collapses
retrying · collapsed — one line (InlineMessage variant="compact")
stopped / settled — no spinner, real ✕ closes for good

Status text is short: Retry 3 · 12s while waiting, Retry 3 while in flight. No "attempt", no "next attempt in", no Copy word — the copy affordance is the icon alone, as everywhere else in the app.

The trailing control changes icon with its meaning. While retrying it is a chevron (mdiChevronUp, error-banner-collapse) because the action is collapse. An ✕ there would promise a close it does not perform. Once retrying stops it becomes a real ✕ (mdiClose, error-banner-dismiss) and does close the card.

2 · lifecycle — collapse only while retrying

✕ collapses only while a retry is pending. Once retrying stops, ✕ closes the card for good. A successful turn removes everything with no user action at all.
