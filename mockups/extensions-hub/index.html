What are extensions and plugins?

You use two programs: pi, the AI agent doing the work in each session, and this dashboard, the web app you are looking at. Add-ons can extend either one, or both.

⚙ extension Extension

Runs inside pi, in every session, also in the terminal

Changes what the AI agent can do.

  • new tools the AI can call (web search, browser, memory)
  • commands and behaviour during a session

✦ skills Skill

Read by pi when a task matches

Written know-how for the AI: step-by-step instructions for a kind of task. No code runs.

  • “how to review code”, “how to make a PDF”

◧ dashboard UI Dashboard plugin

Runs in this dashboard only

Changes what you see and control here.

  • new screens, settings pages, session-card sections
  • has no effect in terminal pi
📦 PackageWhat you install (from npm, git or a folder). One package can contain any mix of the above.

1 · One row per feature, not per packages[] entry: a dashboard plugin, its auto-registered bridge, and the pi package it requires fold into one row (e.g. Goal = goal plugin + bridge + @ricoyudog/pi-goal-hermes).
2 · The 9 …/src/bridge/index.ts rows disappear (they are dashboard-owned plumbing; visible only in a row's details).

4 · Plugins & Packages merge into one nav entry, Add-ons, the umbrella name. "Extension" keeps its narrow meaning (the agent-side part). Plugin settings pages collapse under "Plugin settings". Resources (Skills / Agents / Extensions / Prompts / Themes) STAYS: it is the per-file view and also lists loose files that are not in any package (e.g. ~/.pi/agent/extensions/pi-rtk-optimizer).

6 · Every row says who delivers it: pi-dashboard first-party, dashboard UI · ext by … dashboard UI on a community extension, community third party. Summary strip, filter, and "Group by who delivers it".
